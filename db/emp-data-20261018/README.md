> 用途:把 MES「职员」面板的档案数据打包成 Excel 随仓库同步到云端,**供同事拉取后直接打开/提取**,不必连库。

## 一、这份 Excel 是什么

| 项 | 口径 |
|---|---|
| 数据源 | 正式账套 `HSDZ_MES` · `dbo.bs_emp`(面板 `EMP`「职员」,基础档案,主键 `id`) |
| 行数 | **130 行**(`asp_user1='jdy-sync'` 金蝶同步 122 行 + `migration` 8 行演示档) |
| 列数 | 面板可见字段 13 个(页签「职员」)/ 表内物理列 52 个(页签「全字段」) |
| 导出时间 | 2026-10-18,由 `tools/archive/_emp-export-20261018/_export-emp-xlsx.mjs` 现取现写 |
| 排序 | 面板页签按 `yj_field.seq,id`(= 界面上的字段顺序),行按 `bs_emp.id` |

### 三个页签

1. **「职员」** — 只含面板可见字段,表头是界面显示名:
   `员工编码 / 员工名称 / 所属部门 / 证件号码 / 手机 / 停用 / 性别 / 部门编码 / 入职日期 / 离职日期 / 邮箱 / 生日 / 微信`
   (带自动筛选;这就是「职员」列表页看到的那份数据)。
2. **「全字段」** — `bs_emp` 全部 52 个物理列,表头 = 物理列名,值同「职员」页签(同为脱敏后),
   用于回导/比对(`备用1`…`备用20` 这 20 列当前全空,是表结构预留)。
3. **「字段说明」** — 列名 / 显示名 / 类型 / 非空行数 / 是否在面板 / 是否脱敏,自行解读用。

## 二、🔴 脱敏规则(推送前已按此处理)

`MyPanda-Hash/YINJIA` 是**公开仓库**(2026-10-18 核实:未登录访问首页 = HTTP 200),
所以联系方式一律脱敏后再入库,**原值不出本机**:

| 字段 | 规则 | 示例 |
|---|---|---|
| 手机 / 办公电话 | 只留前 3 后 4,中间 `****` | `134****9309`、`010****8001` |
| 证件号码 | 只留前 4 后 4,中间补 `*` | `1101**********1234` |
| 邮箱 | 账号名只留首字符 + `***`,域名保留 | `z***@example.com` |
| 微信 | 首字符 + `***` + 末字符 | `z***g` |

- **未脱敏**(按原样,因为它们是业务键/事实数据):员工编码、员工名称、所属部门、部门编码、性别、状态、停用、日期等。
- 导出脚本自带**残留扫描**:任一单元格出现 11 位手机号或 18 位身份证号即 `[FAIL]` 且不产出文件
  (金蝶 19 位雪花号 `外部数据ID` 已用数字边界排除,不会被误判)。
