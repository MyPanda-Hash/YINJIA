# ERP导入日志数据导出(2026-10-19)

> 用途:把 MES「ERP导入日志」面板的 9 个批次打包成 Excel 随仓库同步到云端,**供同事拉取后直接打开/提取**,不必连库。
> 起因(用户口径 2026-10-19):「erp导入日志的数据是否有推送到云端」→「推送到云端」→「写成 excel 表格推送到云端就行」。

## 一、这份 Excel 是什么

| 项 | 口径 |
|---|---|
| 数据源 | 正式账套 `HSDZ_MES` · `dbo.erp_imp_log`(9 行)+ `dbo.erp_imp_row`(45 行) |
| 面板 | `ERPLG`「ERP导入日志」/ `ERPLG_ROW`「ERP导入明细」(都**只读**:新增/保存/删除一律 403) |
| 行数 | **9 个批次 / 45 条明细**,批次合计 10,710 行数据 |
| 列数 | 面板可见字段:日志 11 个 / 明细 8 个(表头 = 界面显示名) |
| 导出时间 | 2026-10-19,由 `tools/archive/_erplg-export-20261019/_export-erplg-xlsx.mjs` 现取现写 |
| 排序 | 字段按 `yj_field.seq,id`(= 界面顺序);日志按 `id`,明细按 `(批次号, 行号)` |

### 四个页签

1. **「ERP导入日志」** — 面板可见字段(9 行,带自动筛选):
   `批次号 / 导入类型 / 文件名 / 总行数 / 成功数 / 失败数 / 跳过数 / 状态 / 操作人 / 导入时间 / 备注`
2. **「导入明细」** — 面板可见字段(45 行,带自动筛选):
   `批次号 / 行号 / 源单号 / 解析状态 / 错误信息 / 目标表 / 目标键 / 处理状态`
3. **「字段说明」** — 页签 / 列名 / 显示名 / 类型 / 非空行数 / 在面板 / 公开仓库外发,自行解读用。
4. **「说明」** — 这批数据的来龙去脉、云端现状、为什么不带原始报文。

## 二、🔴 推送口径(公开仓库)

`MyPanda-Hash/YINJIA` 是**公开仓库**(2026-10-19 复核:未登录访问 = HTTP 200),
所以 `erp_imp_row.原始JSON`(45 段金蝶原始报文,含客户/供应商名称、金额)**不导出**,
与 2026-10-18 职员档案「脱敏后推送」同一口径 —— 界面卡片上看得到的字段才进表。

- 导出脚本自带**红线扫描**:任一单元格出现原始报文特征串(`"bill_no":` / `"parent_id":` / `"bill_dis_amount":`)
  或手机号、身份证号即 `[FAIL]` 且不产出文件;本次 11 项全 `[PASS]`,`_export-summary.json` 里 `failed: []`。
- 需要在本地看原始报文:直接查 `erp_imp_row.原始JSON`,
  或 `node tools/archive/_erplg-export-20261019/_export-erplg-xlsx.mjs --with-json`(产物文件带「含原始JSON」后缀,
  **禁止入库/外发**,只能放仓库外目录)。

## 四、云端服务器上的 ERP导入日志现在还是 0 行

| 位置 | 现状(2026-10-19 实测) |
|---|---|
| 云端 `36.140.66.163:8090` | `ERPLG` 0 行 / `ERPLG_ROW` 0 行(关键字 `IMP-` 也是 0) |
| 本机 `HSDZ_MES` / `HSDZ_MES_TEST` | 各 9 批 / 45 明细 |

原因:这批数据是**本机脚本直写库**,不在迁移链(`tools/db-migrations.txt`)里;而数据上服务器只有部署一条通道
(全量恢复备份 / 增量迁移),并且代码里**没有把导入日志往外推的逻辑** —— `转ERP`(`KingdeePushService`)
只推业务单据,`ERPLG`/`ERPLG_ROW` 在 `PanelPermissionService.READONLY_PANELS` 里是只读。

⇒ 本轮按用户口径**只出 Excel 上云**;要真正让云端面板也有这 9 行,得走部署(迁移链补一条幂等补录脚本,
或全量恢复时一并带上去)。需要时再单开一个任务。
