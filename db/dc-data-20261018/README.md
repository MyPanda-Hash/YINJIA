4. **「采集点」** — 设备下的采集变量:编码/名称/数据类型/单位/采集频率/上下限。
5. **「数采规则」** — 定时采集 / 变化上报 / 越限报警(含表达式与参数)。
6. **「采集流水」** — 853 条,设备与采集点已从 id 翻译成编码/名称,含数值、文本值(条码)、质量码、采集时间。

8. **「在线状态日志」** — 当前 0 行(占位显示「暂无数据」)。
9. **「数据说明」** — 数据源、安全口径、真实性说明、导出时间。

## 二、🔴 安全与可见性

- **网关接入密钥 `api_key` 一律没有导出**。它是硬件上报的凭据(`POST /api/dc/ingest` 的 `X-DC-Key` 必须等于它),而 `MyPanda-Hash/YINJIA` 是**公开仓库** —— 密钥一旦进 git 历史就无法撤回,谁拿到都能伪造设备上报。表里只给一列「密钥已设置 = 是/否」。生成器的自检会**全表扫描**真实密钥值,出现一处即 `[FAIL]` 不产出。
- **设备 IP(`192.168.x.x` 内网)与序列号按原样保留**。设备台账就是给人看"怎么配的",打码后失去参考价值;但**含内网设备地址,请不要对外再分发**。
- **采集流水里的文本值可能是条码**(如 `M-001-20261018-063` = 物料编码 + 批号),属业务数据,原样保留。
- 本表**不含任何人员姓名/联系方式**。

## 三、数据真实性

- 数采平台的口径是「没有硬件上报就没有数据」:流水与报警**全部来自真实/测试设备的 HTTP 上报**,不是编造的演示数字。
- 当前台账里 `GW-SIM 测试网关`、`SIM-SCALE-01 测试电子秤`、`FX-001 扫码枪` 都是**测试/联调设备**(见各表「备注」列),不是生产现场的真实硬件。真实硬件接入前,「已接入」状态只代表联调脚本在推数据。
- 数值是导出时刻的快照;要看最新数据请直接开系统「数采平台 → 数据监控 / 状态统计」。

## 四、怎么复跑

```powershell
# 仓库根;需本机 SQL Server(正式账套 HSDZ_MES)可用
node tools/archive/_dc-export-20261018/_export-dc-xlsx.mjs
# 可选:--db HSDZ_MES_TEST  --out D:/tmp/dc/
```

脚本是**只读**的:`SELECT` + 写文件,不碰库、不改任何业务数据。
