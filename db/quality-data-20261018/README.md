# 「我的桌面」质量模块数据导出(2026-10-18)

> 用途:把 MES「我的桌面 → 质量」看到的那份数据打包成 Excel 随仓库同步到云端,供同事拉取后直接打开/核对,不必连库。

## 一、这份 Excel 是什么

| 项 | 口径 |
|---|---|
| 数据源 | MES 后端 `GET /api/dashboard/stats?from&to` 的 `quality` 段(=「我的桌面」质量卡与「质量」页签渲染的**同一份数据**) |
| 区间 | **2026-09-19 ~ 2026-10-18**(近 30 天,与「我的桌面」默认区间一致) |
| 统计粒度 | `day`(按天;区间变长时后端会自动切 week/month) |
| 导出时间 | 2026-10-18,由 `tools/archive/_quality-export-20261018/_export-quality-xlsx.py` 现取现写 |
| 生成时自检 | 5 项(页签齐全 / 概览三项与接口一致 / 趋势点数一致),`_export-summary.json` 里 `failed: []` |

### 五个页签

1. **「质量概览」** — 送检数量 758500 / 合格 732165 / 非合格 26335 / 合格率 97%,每行带口径说明。
2. **「检验结果分布」** — 合格 732165 / 不合格 26335。
3. **「送检合格趋势」** — 30 天逐日「送检 / 合格 / 差额」,**合格率列是 Excel 公式**(`=IFERROR(合格/送检,"")`),打开即可自行核对,不是写死的数字。
4. **「不合格物料TOP」** — 7 条,按不合格数量降序(英克瑞斯酸洗炭 13055、雅可比CS(80-200) 6770 …)。
5. **「数据说明」** — 数据来源、与界面的对应关系、导出时间、隐私说明。

## 二、口径要点(别看错)

- **非合格数量 ≠ 送检 − 合格**。三个数取自检验单明细的不同列(送检数量 / 合格数量 / 不合格数量),不同源时一减会出负数,所以本表直接给「不合格数量」的合计,并单列趋势里的「差额」供对照。
- **合格率** = 合格数量 / 送检数量,后端已算好(97%);趋势页签的合格率是逐日公式,两者口径相同但窗口不同,不要混着引用。
- **数值是导出时刻的快照**。要看最新数据请直接开系统,不要拿本表当实时依据。

## 三、隐私与可见性

- 本表**不含任何人员姓名、手机、证件号**——只有数量与**物料/供应商名称**(业务事实数据,按原样保留)。
- `MyPanda-Hash/YINJIA` 是**公开仓库**(2026-10-18 核实:未登录访问首页 HTTP 200)。若以后要导含人员的质量数据(如检验员下的明细),必须先脱敏,参照 `db/emp-data-20261018/README.md` 的规则。

## 四、怎么复跑

```powershell
# 仓库根;需 8090 在跑 + 管理员账号(口令走环境变量,不写进脚本/仓库)
$env:YINJIA_MES_USER='admin'; $env:YINJIA_MES_PASS='<口令>'
python tools/archive/_quality-export-20261018/_export-quality-xlsx.py
# 可选:--base http://127.0.0.1:8090 --from 2026-09-19 --to 2026-10-18 --out db/quality-data-20261018
```

脚本是**只读**的:只调查询接口 + 写文件,不碰库、不改任何业务数据。
