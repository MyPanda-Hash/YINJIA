## 模块一: 二维码体系（基础层,其余模块依赖）

### 1.1 编码规则（V1.2 已确认）

| 类型 | 编码 | 示例 |
|---|---|---|
| 材料二维码 | `物料编码 + 批号` | `M-001-20260910001` |
| 工单二维码 | `工单号(MANU_ORDER.合同号)` | `2026-09-10` (date类型列) |
| 产品二维码 | `产品编码 + 生产批号` | `T382-20260910B001` |
| 批号规则 | `入库日期(yyyymmdd) + 3位流水` | `20260910001` |

### 1.2 数据模型

```sql
-- 批号注册表(全系统统一批号生成,幂等)
CREATE TABLE qr_batch_registry (
    id INT IDENTITY PRIMARY KEY,
    batch_no NVARCHAR(50) NOT NULL UNIQUE,  -- 20260910001
    biz_date DATE NOT NULL,                 -- 入库/生产日期
    seq INT NOT NULL,                       -- 3位流水
    item_code NVARCHAR(50),                 -- 关联物料/产品编码
    source_type NVARCHAR(20),               -- PURCHASE_IN / WO_REPORT / FINISH_IN
    source_no NVARCHAR(100),                -- 来源单据号
    created_by NVARCHAR(50),
    created_at DATETIME2 DEFAULT GETDATE()
);
```

### 1.3 前端

- 新建 `QrPrintDialog.vue`: 输入编码列表 → 生成二维码图片(用 `qrcode` npm包) → 浏览器打印
- 挂载点: 采购入库单/工单/产品入库单的工具栏按钮「打印二维码」
- 扫码端(PDA/手机): 后续模块五统一设计

### 1.4 依赖的现有基础

- `bs_inv.存货编码` → 材料编码来源
- `MANU_ORDER.合同号` → 工单号来源
- `bs_bom.父件编码` → 产品编码来源

## 模块二: 品检自动分流 + 采购链自动化

### 2.1 物料检验标志（V1.2 基础数据层已确认）

```sql
-- bs_inv 加两列(已有基础数据层草案)
ALTER TABLE bs_inv ADD [是否检验] BIT DEFAULT 0;
ALTER TABLE bs_inv ADD [检验方式] NVARCHAR(10) DEFAULT N'全检'; -- 全检/抽检
```

### 2.2 自动分流逻辑

```
采购入库流程:
  用户选物料 → 查 bs_inv.是否检验
    ├─ 否(免检) → 直接生成 PURCHASE_IN 行 → 扫码入库
    └─ 是(检验) → 自动生成 QC_RECV(暂收单) → QC_INSP(来料检验)
         ├─ 合格数量 → PURCHASE_IN(采购入库) → 材料仓
         └─ 不合格数量 → QC_RETURN(暂收退回)
```

**实现**: 在 `PURCHASE_IN` 保存时,按子件物料编码查 `bs_inv.是否检验`:
- 免检: 正常保存
- 检验: 后端自动创建 QC_RECV + QC_INSP 草稿,数量拆分(合格/不合格)

### 2.3 采购单 ERP 自动导入

- 扩展 jdy-sync: 加 `sync-purchase.mjs`
- API: `/jdy/v2/scm/pur_order` → 直写 `PU_ORDER + PU_ORDER_DETAIL`
- 幂等: 外部数据ID(`external_id` 列,已有迁移)

## 模块三: 生管层(工单自动生成 + 排产增强)

### 3.1 ERP 销售订单审核 → 自动生成工单

```
触发: jdy-sync 拉到已审核(C状态)销售订单
  → 检查 SO_ORDER 是否已有关联工单
  → 无 → 按 BOM 展开自动生成 MANU_ORDER(草稿)
  → 有 → 跳过(幂等)
```

**实现**: jdy-sync 的 `sync.mjs` 在插入 SO_ORDER 后调用内部函数 `generateManuOrder()`:
```javascript
// 伪代码
async function generateManuOrder(so) {
    // 1. 查该销售订单是否已生成工单(外部ID幂等)
    // 2. 查 BOM(T382 的 29 种子件)
    // 3. 创建 MANU_ORDER + MANU_ORDER_DETAIL(数量=订单数)
    // 4. 状态=草稿,待生管确认排产
}
```

### 3.2 排产增强(产能/齐套/拆单)

在现有 WO_SCHEDULE 面板扩展:
- **产能设置**: 新增 `pd_capacity` 表(产线/设备/日产能)
- **齐套表**: 按工单子件查 `kucun` 现存量,不足标红
- **拆单**: MANU_ORDER 支持按数量拆分为多个工单(父子关联)
- **产能柱状图**: ECharts 甘特/柱状图(Vue端)

## 模块四: 五道工序生产过程模型

### 4.1 核心设计: 一张工单 × 五道工序 × 扫码报工

```
MANU_ORDER(工单)
  ├─ Stage 1: 混料(领料→报工)          — 自制物料车间
  ├─ Stage 2: 成型(领料→报工→产品二维码)  — 成型车间
  ├─ Stage 3: 切炭(报工,双出口)          — 切炭车间
  │    ├─ 合格品(直销) → FINISH_IN(自动入成品仓)
  │    └─ 合格品(组装) → 继续到 Stage 4
  ├─ Stage 4: 组装(领料→报工)           — 组装车间
  └─ Stage 5: 装箱(封箱确认→成品入库)     — 装箱车间
```

### 4.2 数据模型

```sql
-- 工序报工表(五道工序共用一张表,stage 区分)
CREATE TABLE wo_stage_report (
    id INT IDENTITY PRIMARY KEY,
    manu_order_no NVARCHAR(50) NOT NULL,   -- 工单号
    stage NVARCHAR(20) NOT NULL,           -- 混料/成型/切炭/组装/装箱
    report_date DATE NOT NULL,
    shift NVARCHAR(10),                    -- 白班/夜班
    worker NVARCHAR(50),                   -- 操作工
    plan_qty DECIMAL(18,4),               -- 计划数量
    actual_qty DECIMAL(18,4),             -- 实际完成数量
    defect_qty DECIMAL(18,4) DEFAULT 0,   -- 不良数量
    dual_out_qty DECIMAL(18,4),           -- 切炭:直销数量(双出口)
    batch_no NVARCHAR(50),                -- 产品批号(成型/切炭阶段)
    qr_code NVARCHAR(100),                -- 扫码内容
    device_no NVARCHAR(50),               -- 设备编号
    notes NVARCHAR(500),
    asp_user1 NVARCHAR(50),
    asp_time1 DATETIME2 DEFAULT GETDATE(),
    asp_cancel CHAR(1) DEFAULT 'N'
);

-- 工序领料表
CREATE TABLE wo_material_pick (
    id INT IDENTITY PRIMARY KEY,
    manu_order_no NVARCHAR(50) NOT NULL,
    stage NVARCHAR(20) NOT NULL,           -- 领料工序
    item_code NVARCHAR(50) NOT NULL,       -- 物料编码
    item_name NVARCHAR(100),
    batch_no NVARCHAR(50),                 -- 材料批号(扫码)
    qty DECIMAL(18,4) NOT NULL,
    picker NVARCHAR(50),
    pick_time DATETIME2 DEFAULT GETDATE(),
    qr_code NVARCHAR(100),                -- 扫码内容
    asp_cancel CHAR(1) DEFAULT 'N'
);

-- 线边库存(工序间在制品)
CREATE TABLE wo_line_stock (
    id INT IDENTITY PRIMARY KEY,
    manu_order_no NVARCHAR(50) NOT NULL,
    stage NVARCHAR(20) NOT NULL,           -- 当前所在工序
    item_code NVARCHAR(50),
    batch_no NVARCHAR(50),
    qty DECIMAL(18,4) NOT NULL,
    warehouse NVARCHAR(20) DEFAULT 'LINE', -- 线边仓
    asp_cancel CHAR(1) DEFAULT 'N'
);
```

### 4.3 切炭双出口逻辑

```
切炭报工(actual_qty=1000, dual_out_qty=200):
  ├─ 200(直销) → INSERT FINISH_IN(成品入库,仓=成品仓,批号=切炭批号)
  └─ 800(继续组装) → INSERT/UPDATE wo_line_stock(stage='组装', qty=800)
```

### 4.4 PDA/手机报工界面

- 新建 `MobileReport.vue`(移动端H5,复用 Vue3 + Element Plus 移动组件)
- 功能: 扫码(工单二维码/材料二维码) → 选择工序 → 输入数量 → 提交
- 路由: `/m/report`(不需要完整桌面布局,独立移动端入口)
- 认证: JWT token(复用现有,移动端登录页)

按工序分组,用 RecordSheetPanels 配置驱动(1:1 复刻):

| 成型 | 5 | 同上 |

| 追溯 | 1 | LOT_TRACE 扩展 |

## 模块五: 品质层增强(隔离仓 + 追溯)

### 5.1 仓别扩展

```sql
-- bs_wh 追加隔离仓(已有 5 仓: CK01-CK05)
INSERT INTO bs_wh ([仓库编码],[仓库名称],[状态]) VALUES
(N'CK06', N'隔离仓', N'启用'),
(N'CK07', N'不良品仓', N'启用');
```

### 5.2 隔离流程

```
任何工序发现不良品 → MOVE 到 CK06(隔离仓)
  → QC_DISPOSAL(品质处置单)
     ├─ 返工 → 退回原工序线边
     ├─ 报废 → MOVE 到 CK07(不良品仓) → 物料报废单
     └─ 让步接收 → MOVE 回成品/材料仓
```

### 5.3 品质追溯增强

扩展现有 LOT_TRACE: 按批号串联全链路
```
材料批号 → 混料投料 → 成型报工 → 切炭批号 → 组装 → 装箱 → 成品批号 → 销售订单
```

## 模块七: 成本核算(最低优先级)

### 7.1 设计原则(V1.2: MES 主要处理成本核算)

- 按工单归集: 材料(领料成本) + 人工(报工工资) + 制造费用
- 数据来源: wo_material_pick(材料) + wo_stage_report(人工) + 费率表
- 输出: 工单成本汇总表 + 产品单位成本

### 7.2 数据模型(骨架)

```sql
CREATE TABLE cost_wo_summary (
    id INT IDENTITY PRIMARY KEY,
    manu_order_no NVARCHAR(50) NOT NULL,
    material_cost DECIMAL(18,4) DEFAULT 0,
    labor_cost DECIMAL(18,4) DEFAULT 0,
    overhead_cost DECIMAL(18,4) DEFAULT 0,
    total_qty DECIMAL(18,4) DEFAULT 0,
    unit_cost DECIMAL(18,6) DEFAULT 0,
    period NVARCHAR(10),                  -- 2026-09
    asp_cancel CHAR(1) DEFAULT 'N'
);
```
