| 依据 | 总流程图 §1 采购支线 + §3 #3/#4;现有 PURCHASE_IN(采购入库单)/QC_ITEM/QC_PLAN 面板复用 |

## 0. 流程定位

```
采购单(已审核,金蝶同步,bl_pu_order 行) 
  → 供应商送货
  → 分流依据: bs_inv.是否检验
     ├─ 免检(=0): 直接扫码入库 → 采购入库单(PURCHASE_IN 已有)
     └─ 检验(=1): 送料暂收单 → 来料检验单
                    ├─ 合格数量 → 采购入库单(实收数量=合格数量)
                    └─ 不合格数量 → 暂收退回单
```

## 1. 三张新单(doc 模式,参照 rd_* 迁移范式,单据编号前缀区分)

### 送料暂收单(qc_recv / qc_recv_detail,前缀 ZS)

头:单据编号/单据日期/采购订单号(参照 PU_ORDER)/供应商/供应商编码/到货日期/经手人/
   备注/单据状态/审核人/审核时间/审批人/审批时间 + asp_*
行:物料编码(参照 INV)/物料名称/规格型号/单位/采购数量(带出)/暂收数量(手填)/
   批号(扫码带入或 yj_lot_seq 取号)/仓库(参照 WH)/备注

### 来料检验单(qc_insp / qc_insp_detail,前缀 IJ)

头:单据编号/单据日期/暂收单号(参照 ZS 单)/供应商/检验员/检验日期/
   检验方案(参照 QC_PLAN,可空)/总结论(下拉:合格/不合格/让步接收)/
   备注/单据状态/审核人/审核时间 + asp_*
行:物料编码/物料名称/规格型号/单位/送检数量(带出=暂收数量)/合格数量/不合格数量(自动=送检-合格)/
   处置方式(下拉:入库/退货/让步入库)/批号/备注

### 暂收退回单(qc_return / qc_return_detail,前缀 TH)

头:单据编号/单据日期/检验单号(参照 IJ 单)/供应商/退货原因/经手人/
   备注/单据状态/审核人/审核时间 + asp_*
行:物料编码/物料名称/规格型号/单位/退货数量(带出=不合格数量且处置=退货)/批号/备注

## 2. 与现有件的接缝

- **采购入库单(PURCHASE_IN)已有**:bd_purchase_in.采购订单号 + bl_purchase_in.实收数量——
  检验合格后建采购入库单,来源单据链:暂收单号/检验单号 写入 bd_purchase_in.外部单据号 或 备注?
  → 建议: bd_purchase_in 已有"外部单据号"列(通用),检验流转来的单写检验单号
- **检验方案/项目档案已有**:qc_insp.检验方案 参照 QC_PLAN(方案含检验方式/抽检比例)
- **批号**:yj_lot_seq 取号(入库日期+3位流水);暂收时物料批号可扫码(供应商标签)或留空
- **yj_doc_status 状态机**:三单都走 doc 模式既有审批流(草稿→已审核),零新造轮子
- **多语言**:三面板 + 全部字段的 yj_translation(en 必做,AGENTS.md 强制)

## 3. 决策点(需拍板)

1. **检验单粒度**:流程图只有 合格数量/不合格数量(简单式);
   但 bs_qc_item(检验项目:检验内容/标准/上下限/判定规则)档案已存在。
   - 方案A(推荐):一期简单式——行级合格/不合格数量 + 检验方案引用;项目明细二期挂
   - 方案B:一步到位——qc_insp_detail 再挂 qc_insp_item 子表(每检验项一条判定)
2. **单据生成方式**:
   - 方案A(推荐):暂收单审核后,行操作"生成检验单"(带出送检行);检验单审核后,
     合格行"生成采购入库单"、不合格行"生成退回单"——参照已有 RefPick/生成模式
   - 方案B:纯手动新建+参照选择(少开发,但录员多一步)

## 4. 明确不在本模块

- 材料二维码打印(#3 前半)——独立模块,下一草案
- 库存台账记账规则(入库审核→仓库台账)——随"材料仓库存账"模块设计
- 隔离仓流转(检验不合格先进隔离仓)——品质层 #11
