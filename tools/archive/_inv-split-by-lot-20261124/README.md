## 三、顺带修复的线上隐患:出库审批「预警闸门」二次扣减

`StockWarnService.checkOutbound` 由 `StockFlowService.post` 调用,而 `post` 在
`StockLedgerService.apply` **扣完 kucun 之后**才执行 ⇒ 读到的余额已是「出库后」,
原代码再减一次本单已出量 = 扣两遍。判据:该批次出完还剩一点、但剩余 < 本行数量 ⇒ 误报
「出库后余额 -N」。拆行后每行只出自己的批,几乎必踩(实测 LL-2026-11-0047 首次审核被拦:
`出库后余额 -200 低于预警数量 0(当前余额 200,本单该批次已出 400)`)。
现改为直接比出库后余额;库存不会变负 —— `applyOutAggregated` 自己的「现存量不足」守卫仍在。
