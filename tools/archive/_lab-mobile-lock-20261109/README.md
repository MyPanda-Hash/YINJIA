# _lab-mobile-lock-20261109 —— 手机端两道状态闸门

> 用户口径(2026-11-09):「还有手机点击保存草稿的单据,就不能修改设备名称。
> 还有审批通过后的单据连新增修改都不可以。」

## 规则(与电脑端"单据身份"口径一致)

| 闸门 | 条件 | 结果 |
|---|---|---|
| ① 标识字段锁 | **单据已保存**(有单据编号) | 表头里"这张单是什么"的字段只读:设备名称 / 仪器名称/型号 / 测试项目(= 面板 `titleField`)+ 其它 `dataType=标准库` 的表头字段;字段标签旁显示「已锁定」 |
| ② 整单只读 | 状态 ∈ 已审核 / 已归档 / 审批通过 / 已作废 | 表头全字段、明细字段、「加一行」、「保存草稿」、「拍照/上传附件」、「附件 ✕」全部禁用;顶部提示 `🔒 这张单已是「已归档」,只能查看;要改请在电脑端按流程处理` |

草稿(以及审批中)不受 ② 影响 —— 仍然可以改;「删除行」「清空重填」维持第三轮口径(只有草稿能删)。

纯函数在 `business/labMobile.js`:`canEditDoc(status)` / `isDocReadOnly(status)` /
`lockedHeaderKeys(headerFields, {saved, titleField})`;页面只做绑定。
**写入口在逻辑层也各挡一道**(save/addRow/addRowFiles/removeRowPhoto 先判 `readOnly` 并提示),
不只靠按钮 disabled —— 手机长按、脚本、回车都可能绕过 UI。

## 验证(5173 源码版)

| 场景 | 证据 | 结果 |
|---|---|---|
| 新单(未保存) | `ego/02-新单可编辑.png` | 设备名称可编辑(还没有单据编号) |
| 已保存的单(审批中 EU-2026-11-0001,正式库) | `ego/01-非草稿只读.png` | **设备名称已锁定**;备注/单据日期仍可改;删除行禁用 |
| 审批通过后(测试库:把 EU-2026-11-0001 审批通过 → 已归档) | `ego/03-审批通过只读.png` | 顶部只读提示;单据编号/单据日期/设备名称/备注/使用日期/测试项目**全部禁用**,加一行/保存草稿/拍照全禁用 |

复跑:`ego/round-01.mjs`(新单 vs 审批中)、`ego/round-02.mjs`(测试库审批通过后再打开)。
第二支脚本会在**测试库**把 `EU-2026-11-0001` 从「审批中」推到「已归档」,只影响测试库。

契约单测:`src/views/mobile/mobileLabRecordLock.test.js` 4 条(只读判定走 canEditDoc、标识字段走
lockedHeaderKeys、四个写入口都判 readOnly、按钮 disabled 跟着 readOnly);`node --test` **1628/1628**。
