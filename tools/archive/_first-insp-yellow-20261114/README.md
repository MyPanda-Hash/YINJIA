## 一、用户口径（2026-11-14，随《炭棒成型车间首件检验记录表》原图一起给）

> 「将当前的首件检验单格式修改为图中所示，也就是**没有黄色的格子就打上斜杠，不可填写**，
>  其余的不用修改，就还需要把**对应的表格修改为黄色**。」

⇒ 可填范围回到纸面：**黄格 = 要填（铺 `#FFF3CA`）**，白格 = 打 `/` 不可填；
除「可填/不可填 + 黄色」外，列集、勾选项、相关要求、抬头、表尾、打印/导出入口一律不动。
标准行的表观/脱粉两格按纸面改**灰底 `#D9D9D9` + `/`（只读）**。

## 五、遗留风险 / 需 Lead 知晓

1. **兜底是按"分组"不是按"原列身份"**：契约口径如此 —— 若把「挤压强度」改名成认不出的列名、而分组仍留在
   「强度」，兜底会落 5#/6#（而非纸面的 7#/8#）。默认 10 列不受影响（列名能认）。
2. **浊度NTU 是系统比纸面多的一列**：用户口径「其余的不用修改」⇒ 不清列，按契约随「浊度及压降」组记 7#/8#。
3. **Excel 导出对非可填格一律写 `/`**（含历史值）—— 与契约 §二「非可填格写 `/`」一致；
   「老单据已填值原样只读显示、不吞数据」只落在**屏幕**（`cellText(sample,c) || '/'`），xlsx 不落历史值。
   若将来要求导出也吃历史数据，需先改契约。
4. **标准行表观/脱粉改只读后**：默认标准就是 `/`；万一历史数据里那两格有非 `/` 内容，屏幕只读照原样显示（不吞）。
5. **静态产物 `backend/src/main/resources/static` 未同步**（任务明确不碰）。按仓规纯前端改动还要
   `npm run build` → 同步 static → 单独一个 `chore: 前端静态产物同步(...)` 提交，留给 Lead 统一处理。
6. **服务端报表**（`QcFirstInspReportSupport.java` / `qc_first_insp.jrxml`）由另一队友改，矩阵以契约文档为准；
   本回合前端未跑后端冒烟，最终应由 Lead 做三处同口径核对（前端矩阵 / 导出 / 报表 PDF）。
7. 契约 §四 的验证表里「30 个黄格」与 §一 的「可填 20 格」口径不一致（前者像是原图 blob 数），
   本任务按 §一（20 格）实现，建议 Lead 在契约里统一措辞，免得验证者数错。
