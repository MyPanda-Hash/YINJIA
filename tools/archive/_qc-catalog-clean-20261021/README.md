## 二、判定规则

保留集 = `qc_insp`（`asp_cancel≠Y`）⋈ `qc_insp_detail`（`asp_cancel≠Y`），按 `(单据编号, 物料编码)`。

- **目录行**：`检验单号` 必须命中上述保留集，否则删除（含无关联的手工行）。
- **记录**：`来料检验单号 + 物料编码` 必须命中保留集；同一记录单号若有多行，只在**有效行**里保留
  `id` 最小的一条（去重不把有效行拖下水，见脚本内注释）。
- 删除记录的连带清理：`qc_insp_rec_detail`、`yj_doc_status`、`yj_form_approval`、
  `form_flow_link`、`yj_attachment`、`yj_doc_annotation`；`qc_tc_in.检验数据记录单号`
  指向已删记录的统一置 `NULL`（只断链，不删特采单）。
- 保留行按检验单明细**回正**：`数量/计量单位/批次号/物料名称/检测物料类别`。
- 补齐缺失：`IJ-2026-09-0152`（真实链路单，暂收 `SL-2026-09-0189`）当时没有生成目录/记录 ⇒
  补 1 行目录 + 1 条记录（`JYSJ-2026-10-0089`，单号走号池 `s_allno`）。

## 七、来料检验单草稿审批（2026-10-21 第三轮）

用户口径：

> 「处理当前来料检验单的草稿单据，但是审核人都需要是冯敏。」
> 追问确认：3 张草稿走完审批、审核人=冯敏；已审核/已归档的不动；10-0001/10-0200 的合格数量
> **先按送检数量补齐再审核**。

处理对象：`IJ-2026-09-0152`、`IJ-2026-10-0001`、`IJ-2026-10-0200`（当时仅剩的 3 张草稿）。

| 步骤 | 动作 | 结果 |
|---|---|---|
| ① 补数 | `qc_insp_detail.合格数量 = 送检数量`（只补空/0） | 0001 补 1 行、0200 补 2 行；0152 原就是 100 |
| ② 提交 | admin 点「提交审批」 | 3 张 → 审批中 |
| ③ 审核 | **fm**（质量审核角色 1039，`real_name=冯敏`）点「审批通过」 | QC_INSP 是**单节点审批**，一级通过即「已审核」 |
| ④ 落章 | `qc_insp.审核人` + `yj_doc_status.shr` 统一 = **冯敏**；时间用中国本地时间 | 列表审核人显示「冯敏」 |

> ⚠ 时间坑：SQL Server 跑在 UTC 容器里，`GETDATE()` 比本地慢 8 小时。纸面 `审核时间` 与
> `yj_doc_status.shsj` 必须用 `SYSDATETIMEOFFSET() AT TIME ZONE 'China Standard Time'`，
> 否则列表会显示 08:20（实际 16:20）。
>
> 审批留痕 `yj_form_approval.operator` 记录的是操作账号 `fm`（不是姓名）；纸面/列表的「审核人」
> 取 `shr`，已统一为「冯敏」。

结果：3 张全部「已审核」，`QC_INSP` **草稿剩余 = 0**；已审核 2 张（0003/0005）与已归档 1 张（0004）未动。

|---|---|---|
| IJ-2026-09-0152 | PI-2026-10-0024 | 1 |
| IJ-2026-10-0001 | PI-2026-10-0025 | 1 |
| IJ-2026-10-0200 | PI-2026-10-0026 | 2 |

三张入库单都是草稿，供应商/采购订单号/批次号/单价/实收数量已随链带入；**仓库为空**是因为来源
`sl_recv_detail.仓库` 本来就是空（不是审核丢的），需仓库补填后再审核。
