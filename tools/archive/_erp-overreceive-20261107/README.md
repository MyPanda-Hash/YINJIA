# 转ERP「不允许超量入库」取证(2026-11-07 客户服务器)

> 报障原文:`服务异常:转ERP失败:金蝶接口失败:请求接口返回失败 [采购入库单(CGRK-20261107-03645),
> 商品分录第1行]反写[采购订单(YJ-20261027-05),商品分录第1行]不允许超量入库`
>
> 结论:**不是接口/凭证/网络故障,是数量超了订单 —— 入库 454 支 vs 采购订单 400 支(超 54 支 / 13.5%)**。
> 金蝶按「收货上限 = 订单数量(超收比例=0)」反写拦截;而 MES 侧的「收料超送比例 = 20%」放行了 454
> (400×1.2=480)。**两端口径不一致**,超送量必然卡在转ERP。

## 一、两端实测数据(均为只读取证)

| 项目 | 金蝶真实账套(tf.jdy.com,clientId 359797) | MES 生产服务器(36.140.66.163:8090) |
|---|---|---|
| 采购订单 `YJ-20261027-05` 分录 1 | 折叠棉 `YJ-YCYX-012`,单位 支,**qty=400**、`in_qty=0`(已入库 0)、`un_out_qty=400`、base_qty=400、单价 2.4、金额 960;单据 已审核、`bill_close_state=C`、`io_status=A` | 数量 **400**、单价 2.4、金额 960;单据状态 已审核 |
| 采购入库单 `PI-2026-11-0018` | 金蝶侧 **不存在**:`CGRK-20261107-03645` 查无此单(保存被回滚) | 实收数量 **454 支**、批次 20261107、采购订单行号 1、存货 `YJ-YCYX-012`;单据 已审核、**未转ERP**(可直接重试) |
| 差额 | **454 − 400 = 54 支(13.5%)** | 同一口径 |

链路:采购订单 400 → 送料暂收单(1 张,454 支,批次 20261107,已审核)→ 采购入库单 454 支(无来料检验,
QC_INSP 查 0 张,属暂收免检直达)→ 转ERP 推 `pur_inbound`,`src_bill_no=YJ-20261027-05`、`src_seq=1`
→ 金蝶反写订单时按订单数量校验 → 拒绝。

> ⚠ 金蝶订单行里 `inv_qty=290` 是**库存数量(现存量)**,不是已入库量(`in_qty=0`);别据此误判"已收过 290"。
> 该订单在 MES/金蝶两侧都只有这 1 张入库单(`PURCHASE_IN` 按采购订单号查 totalSize=1),不存在重复推送/累计超收。

## 二、MES 为什么会放过 454

- 系统参数 `yj_app_setting.receive_over_ratio` = **0.2**(服务器实测:生单弹窗元数据 `overRatio=0.2`,20%)。
- 可送上限 = 订单数量 ×(1+超送比例)= 400×1.2 = **480**,454 ≤ 480 ⇒ 送料暂收/入库 都放行。
- 金蝶侧超收比例为 0(未开「按比例控制超收」/订单行未开「控制收货上限」)⇒ 收货上限 = 400 ⇒ 反写拒绝。
- **即使不经过 MES,只要入库数量 > 订单数量,金蝶默认就是这句「不允许超量入库」**;所以这不是偶发故障,
  而是「MES 允许超送、金蝶不允许超收」这一口径差在超送单上的必然结果。

## 三、怎么处理这张单(三选一,业务拍板)

1. **业务确实多送 54 支**:金蝶把该采购订单数量改为 454(或补一张 54 支的订单/订单行)→ 回 MES 重转。
2. **金蝶开超收**:系统参数 → 采购参数 → 勾「按比例控制超收」;商品档案维护「采购订单超收比例」;
   采购订单分录列打开「控制收货上限 / 超收比例(%) / 收货上限」。比例需 ≥13.5%,建议与 MES 的 20% 对齐,
   然后重转。依据:[【云星辰】超收超发管控](http://www.tjyxk.com/article-item-222.html)。
3. **数量录错**:MES 弃审 → 改 454→400 → 重审 → 转ERP(弃审会清 ERP 标记,本单本来就是未转,无副作用)。

不建议把 54 支拆成"其他入库单":那会脱离采购订单来源,应付/成本口径与采购链不一致。

## 四、根治建议(口径统一)

- **首选**:把 MES「收料超送比例」调到 0(或与金蝶允许比例一致),让超量在收料/生单阶段就被拦住,
  而不是到转ERP 才失败(现在用户看到的只有金蝶原文,不知道该改哪张单)。
- 若业务确需超送:MES 20% ↔ 金蝶 20% 必须同时设,且金蝶要在**商品档案/订单行**上真正落下去
  (只开系统参数、商品比例为 0 仍会拒绝)。
- 可选:MES 转ERP 前加预检(本单 + 历史已转 vs 订单数量),直接给出「超出订单 54 支」的可读提示。

## 四之二、金蝶侧到底能不能"设"?(2026-11-07 追加核实)

**能设**,参数是 **「允许入库数量大于订单数量」**(账套级开关):

- 金蝶云·星辰官方 FAQ(旗舰版)明确:「若修改收料通知单要大于采购订单数量,**系统参数里需勾选
  "允许入库数量大于订单数量"**」——见 [采购入库的数量是否支持大于收料通知的数量?](https://vip.kingdee.com/knowledge/713195554595044864?productLineId=35&isKnowledge=2&lang=zh-CN),
  文中另链《如何设置采购订单是否能超额入库?》。
- 入口按星辰口径是 **系统设置 → 系统参数 → 采购参数**(该页同时有「按比例控制超收」等开关;
  路径依据 [【云星辰】超收超发管控](http://www.tjyxk.com/article-item-222.html))。不同版本菜单文案可能略有差异,
  以账套里实际显示为准。
- 另一个「允许入库数量大于**收料通知单**数量」是**另一条参数**,只管「收料通知单→采购入库」链路;
  本例 MES 是把入库单直接挂**采购订单**(`src_bill_no`),不看那一条。

勾上之后会发生什么(必须先跟客户说清):

1. **账套级放开**:所有商品、所有订单的采购入库都可以超订单数量,金蝶不再兜底 —— 等于把超收管控
   完全交给 MES 的 20% 比例。若不希望这样,应改用「按比例控制超收」+ 商品档案「采购订单超收比例」
   (订单行「控制收货上限 / 超收比例(%) / 收货上限」),比例设到 ≥13.5%(建议与 MES 的 20% 对齐)。
2. 只勾总开关、商品超收比例仍为 0 时,若同时启用了「按比例控制超收」,收货上限仍按 0% 算 → 继续被拒。
3. **比例不必逐个商品设**:系统参数只是**开关**,数值挂在商品档案上;星辰支持「商品类别 → 通用属性」一次统设
   (整个类别继承)或「商品列表勾选 → 批量修改」,也可只在**采购订单行**上按单维护(不动档案/参数)。
   建议只给真正会超收的类别(如棉材)设,其余保持 0 —— 不要全盘放宽。
   (口径来源同上[【云星辰】超收超发管控]:「商品列表支持批量修改」「商品类别通用属性也支持统一维护」)
4. 改参数属于账套管理动作,需要客户的金蝶管理员/服务商在**金蝶端**操作;MES 侧不用改代码,
   重转这张单即可(单据仍为「未转ERP」,无重复风险)。
