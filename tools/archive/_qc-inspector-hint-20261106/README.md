# 取证:检验报告「检验人」为什么会显示「账号登录人自动生成」(2026-11-06)

## 报障

用户截图:检验数据记录(空白草稿)签名行 `检验人 | 账号登录人自动生成 | 审核人 | 冯敏`,问「为什么出现这个检验人」,
追问「这个账号登录人自动生成是在保存后生成真正的填表人的吗」。

## 结论(逐层有据)

| 环节 | 会不会写「检验人」 | 依据 |
|---|---|---|
| **新增那一刻** | ✅ 写入**当前登录账号的显示名**(`realName`,取不到就是账号) | `frontend/src/core/panel/docDefaults.js` 的 `LOCKED_PERSON.QC_INSP_REC = '检验人'`,只在 `isNew=true` 时执行 |
| **保存** | ❌ 不改、也不剥离;前端带什么落什么 | `ButtonService.save` 只剥离「编制格」名单里的键(`body.remove(prepCol)`),而 `QC_DOC_PREPARER` 里没有 `QC_INSP_REC` |
| **提交审批 / 审核** | ❌ 不碰它 | 「编制=提交人」的回写只覆盖 `QC_TC_IN / QC_LYB / QC_SCY / QC_BHG / QC_BHC / QC_BHZ / QC_JJF / QC_SCP / QC_OQC_REPORT` |

所以这格记的是**建这张单的人**(点「新增」时的登录账号),**不是**最后一次保存的人、也不是现场检验人;
生成后谁再改这张单都不会变(该格 `yj_field.editable=0`,前端只读、后端不回写)。

纸面那串字是**空值说明**,不是数据:`QcInspRecSheet.vue` 的 `signText()` 取不到值时回落显示文案。
所以看到它 = 这张单的「检验人」是空的。

为什么会空:前端只在「新增那一刻」写。已保存过的草稿(`saved='Y'`)、非新增建出的单(生单/后台建)、
新增后没保存就断了 —— `isNew` 都不成立,于是永远空;而后端也没给这张面板兜底 ⇒ **保存也补不上**。

## 数据侧印证(本地正式库)

```
68 张检验数据记录,其中 20 张「检验人」为空;
最近 6 张(JYSJ-2026-10-0087 ~ 0092)全是 NULL;
有值的写的是登录账号 admin(不是真实姓名 系统管理员)——10-15 那批是同一秒批量造数,不代表 UI 行为。
```

「审核人」有名字是因为 `表单审核人=冯敏` 属**普通默认值**(任何空值都补),与「检验人」这种**锁定字段**机制不同。

## 用户决定(2026-11-06)

选 **C**:行为不改,**只把说明文字说清**。

## 改动

- `QcInspRecSheet.vue`:`signText()` 空值文案 `账号登录人自动生成` → **`新增时按登录人生成`**;
  新增 `signHint()` 给该签名格加 `title`:
  - 空值时:`这格在「新增」那一刻按登录账号填入,之后不再随保存/编辑变更;不是从新增建出的草稿会一直为空`
  - 有值时:`新增时按登录账号填入,之后不再随保存变更`
- 注释写清完整规则(避免下次又有人以为是"保存时生成真正的填表人")。
- `en.js` / `zh-TW.js` 补 4 条词条。

## 验证

- `node --test`:**1540 / 1540 全绿**;
- 8090(重建 jar 后)实机:有值的那格 `title` = 「新增时按登录账号填入,之后不再随保存变更」✅(证明新代码在跑);
- 构建产物与 jar 内均含新文案(`grep '新增时按登录人生成'` → `PanelxList-*.js` + en/zh-TW 语言包各命中);
- ⚠ 空值分支没能在 8090 界面上直接取到证据:本地空「检验人」的那几张草稿不在列表首屏,
  `?docNo=` 也没把面板切到它们(默认查询条件先行)。该分支就是同一函数里的三目,文案已在构建产物/jar 中核对。

## 已知遗留(本次按 C 未处理)
