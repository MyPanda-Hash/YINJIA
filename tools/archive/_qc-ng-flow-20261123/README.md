# _qc-ng-flow-20261123 —— 出货检验(功能/表观)判不合格 → 转到哪(2026-11-23,只读核查)

用户口径:「检查当前出货检验（功能）和（表观）选择不合格时转向什么页面」

## 结论

**两张单都转到同一张「不合格品处理单(制程)」QC_BHC**(菜单:品质管理 → 质量单据 → 不合格品处理单(制程)),
不是在检验页面里换到别的检验单,也不是自动跳转 —— 是纸面上的一个**显式按钮**:

| 环节 | 事实 | 真源 |
|---|---|---|
| 按钮文字 | `⧉ 去开不合格处理单` | `frontend/src/core/qc/shipInspNg.js`(NG_DISPOSITION_ACTION) |
| 出现条件 | 面板 ∈ {QC_PROC_INSP, QC_ASM_INSP} **且表头「总结论」= 不合格**(与草稿/已审核无关,已审核单也能补开) | `canOpenNgDisposition()` |
| 位置 | 纸面「检验明细」区块带右侧(与 新增检验项 / 带入检验项目 / 添加批次 同一排,`no-print` 不进打印) | `QcProcInspSheet.vue` `.qr-band-ng` |
| 点击后 | 先静默保存脏单 → `POST /api/qc/shipInsp/ng` → 关当前页签 → 开 `/panelx/list/QC_BHC?docNo=<新单号>`(定位到那张单) | `PanelxList.openNgDisposition()` |
| 服务端 | 目标 `QC_BHC`(表 `qc_bhc`)；复核 总结论=不合格(否则 422)；同一检验单**幂等**只留一张存活处理单(按 `qc_bhc.出货检验单号`)；需同时有来源单 + QC_BHC 的查看权 | `QcShipInspNgController` |
| 带过去的数据 | 单据日期=今天、出货检验单号、工单号、客户名称、产品编码、产品名称、产品规格、生产量(=检验数量,空则抽检总量)、不合格品数量(=明细合计:功能读「不良数量」/表观读「不合格数量」)、不合格品比例；明细留空、**建成草稿不自动提交** | 同上 |
| 目标页纸面 | 《不合格品处理单（制程）》YJ-QR-59,含「出货检验单号 / 工单号 / 不合格报告单号」三格 | `docSheetConfigs.QC_BHC` |

## 数据现状(两账套一致,`q*.sql`)

- 出货检验单里**一张「不合格」都没有**:功能 421 合格 / 28 空;表观 2 合格 / 401 空(测试库 420/29、1/401)。
- `qc_bhc` 里**没有**任何带「出货检验单号」的行(正式 1 张、测试 3 张都是空号)→ 这条链路至今未被真实点到过。
- 但表观有一行**逐行判了不合格**:`ZJ-2026-10-0006` 的「成品检验」= 不合格,而**表头总结论仍是空** ⇒
  纸面不会出按钮(见下「已知差异」)。

## 已知差异 / 可改进点(供决定要不要改)

1. **只认表头「总结论=不合格」**:明细里逐行判「不合格」但没把总结论改成不合格时(实测 ZJ-2026-10-0006),
   不出按钮 ⇒ 现场可能"判了不合格却不知道去哪开单"。
2. **表观单落到「出货检验单号」格**,但该格的参照源只登记了 `QC_PROC_INSP`(功能单)⇒ 值能显示(纸面直接印存值),
   但点参照重选时候选里只有 ZC- 开头的功能单,搜不到 ZJ- 的表观单。
3. 两张单转的是**同一张** QC_BHC(靠「出货检验单号」区分来源),没有"表观专用"处理单;
   自制物料那张是另一张单 `QC_BHZ`,不在这条链路上。
4. 处理单建成草稿、明细空,需要人工补填写再提交审批(不自动建明细/不自动提交)。
