## 一、先修掉「产成品入库单一张都没生成」的 3 个 bug

|---|---|---|---|
| ① | 报工行 `WHERE s.sc_no = 报工单号` | 报工单号写在 `scjl.[报工单号]`（WO_REPORT 面板 group_col），`sc_no` 全空 | 查出 0 行，静默 return |

## 二、多批次模型（本轮核心）
- **批次号 = 报工完工日**（`scjl.wgsj` 本地日期 `yyyyMMdd`，缺则 `sc_date`）；
- **入库数量 = 该工单行该完工日、最后一道工序的已审报工量合计**（只取最后一道，不跨工序相加）；
- **一张未提交的产成品入库单承载多个批次**：每个批次一条明细行（批号 + 实收数量）；
- 之前的入库单一旦**提交审批 / 已审核（锁定）**，新批次就**新建**一张入库单承接；锁定单不再改动（同批次差额也进新单）；
- 幂等：同工单行同批次重复触发只更新数量，不重复加行；
- 触发：最后一道工序报工审核/审批通过（`runWoAuditHooks`）+ 运维补生成接口 `POST /px/scheduleBoard/finishInBackfill {加工单号, 行id}`（权限与「排产」同口径，用于存量补偿）。
- 单号/单据日期：新单沿用 FINISH_IN 号池（FI-yyyy-MM-nnnn），单据日期=首个批次完工日；表头批次号=最早批次（仅作参照，明细行才是一批一行）。

## 三、门禁放宽
[`assertFinishInInspLink`](../../../backend/src/main/java/com/yinjia/mes/service/ButtonService.java) 现在只校验：
1. 表头「出货检验功能单号」「出货检验表观单号」必填；
2. 两张检验单都必须**已审核**（`yj_doc_status.shr` 非空、未作废）；
3. **不再**要求本单批次出现在检验单明细「内部批次」里、**不再**要求该批次每行判「合格」；
4. 金蝶导入历史单（外部单据号非空）不追溯；保存草稿不拦，只在提交审批/审批通过/审核时校验。

## 六·再补：出货检验**表观**没自动关联（2026-11-13 用户报障，已修）
**现象**：产成品入库单 FI-2026-11-0002 的「出货检验功能单号」自动带出了 ZC-2026-11-0006，但「出货检验表观单号」一直空着（截图：请选择）。
**根因**：入库草稿生成/补生成时只匹配**已审核**检验单；而表观单 ZJ-2026-11-0009 是在入库草稿生成之后（17:38）才审核的，且当时没有任何「检验单审核 → 回写入库单」的钩子 ⇒ 草稿永远拿不到表观号。
**修法**：
1. 新增 `latestInsp`：优先取**已审核**检验单，没有则回退**最新未作废**单（草稿也先关联上，提交时再校验已审核）；
   入库草稿生成/补生成、提交时自动带号都改用它；
2. 新增 `syncFinishInInspNos`：`QC_PROC_INSP` / `QC_ASM_INSP` **审核/审批通过**时，把单号回写到同工单行**未提交**的产成品入库单（只补空、不覆盖、不动已提交单）；
   挂在 `runWoAuditHooks`（审核、一级/二级审批通过三条路共用）。
**正式库复验（8090 最新 jar）**：
- FI-2026-11-0002 → 功能单 `ZC-2026-11-0006`（已审核）、表观单 **`ZJ-2026-11-0009`（已审核）** ⇒ 门禁已满足，可直接提交；
- FI-2026-11-0003 → 功能单 `ZC-2026-11-0007`、表观单 `ZJ-2026-11-0010` 已自动关联（两张当前是草稿，需品质审核后提交；
  审核那一刻 `syncFinishInInspNos` 还会再同步一次，不会退回去）。
- 重新调用补生成接口两次均成功（新建 0、更新明细 1），未影响已锁定/已审核单据。
