# 产成品入库单「加工单号」补齐 —— 分析、脚本与实测（2026-10-22）

> 用户口径：「写个脚本可以补齐成产品入库的加工单号。按照有的补齐。要合理，符合时间。」

## 1. 结论先说

| 项 | 结果 |
|---|---|
| 脚本 | `tools/migrate-finish-in-wo-backfill-20261022.sql`（只填空值，可回滚） |
| 只读报告 | `tools/verify/finish-in-wo-backfill-report.sql`（先看要改哪些单） |
| 回滚 | `tools/rollback-finish-in-wo-backfill-20261022.sql`（按留痕还原） |
| 正式库实测 | 231 张空单中 **补上 31 张**（strict）；剩 **113 张只对得上部分产品** + **87 张产品在工单里完全查不到** |
| 测试库 | `plang` **0 行** ⇒ 跑出来是 `RESULT: FINISH-IN-WO-NOOP`（幂等，不改任何数据） |
| 回滚实测 | 31 → 231（全部还原）→ 再跑 → 31（同一批，确定性） |

## 2. 「加工单号」到底是什么

不是金蝶的号，而是 **生产工单号 `plang.pl_no`**（形如 `GD-2026-10-0117`）。三处现役代码同口径：

- `WorkOrderPickingService`：「加工单号 = 工单号」+「工单行号 = plang.pl_xc」；
- `ButtonService` 出单：`head.put("加工单号", wo)`（wo = 工单号）；
- 工单追溯 / 工单结案 / 工单拆分：一律 `WHERE bd_finish_in.加工单号 = ? (+ 工单行号)`。

⇒ 只能填库里**真实存在**的工单号，编一个号会让追溯查到空气。

## 4. 判定规则（strict / lenient）

对每张 `加工单号` 为空的产成品入库单：

1. **候选** = `plang` 里含本单产品的工单号（`bl_finish_in.产品编码 = plang.dm`，去首尾空格）；
2. **时间闸门（用户要的"符合时间"）**：该工单的**最晚一行工单日期 ≤ 入库单日期**（工单不可能晚于入库），
   且距今 ≤ `@MaxDays`（默认 180 天）；
3. **一张单只落一个工单号**：排序取 `覆盖产品数 desc → 时间差 asc（离得最近）→ 数量差 asc → 单号 desc`；
4. **strict（默认）**：只有"该工单含本单**全部**产品"才填 —— 本单与工单对得上，填了才是事实；
   **lenient**：允许"只对上部分产品"也填，并把覆盖率写进留痕供复核；
5. 单产品单顺带填 `工单行号`（`plang.pl_xc` 里对该产品的那一行）；多产品单**不填**工单行号
   （一行对不上多个产品；留空 = 占整单，语义才对）；
6. **只填空值**，已有值（含金蝶导入的真号）一行不碰；每改一张单写一条 `yj_usage_log` 留痕。

## 5. 为什么补不全（这是数据事实，不是脚本能力）

| 分类 | 单数 | 说明 |
|---|---|---|
| ② 全覆盖（已补） | **31** | 工单的产品集恰好覆盖本单全部产品，且工单日期在入库日之前 |
| ④ 部分覆盖（strict 不填） | 113 | 本单 3~7 个产品里只有 1~3 个能在某个工单找到 ⇒ 落一个号会把其余产品"赖到"该工单头上，工单追溯就错了 |
| ③ 无候选 | 87 | 本单产品在 `plang` 里根本没有工单（66 个产品完全没有工单，但都在商品档案里） |

> 想放宽：把迁移脚本顶部 `DECLARE @Mode nvarchar(20) = N'strict';` 改成 `N'lenient'` 再跑，
> 会**再**补 113 张（已补的 31 张不会被动），留痕里会写 `(覆盖1/6/lenient)` 便于逐条复核。

## 7. 复核建议

1. `applied-HSDZ_MES.txt` 里逐单看：`相差天` 应 ≥ 0（本批 0~20 天），`入库产品` 应全部出现在该工单行明细里；
2. 抽查工单追溯：`GD-2026-10-0117` 现在挂着 3 张入库单（`CPRK-20260922-00007 / 20260926-00004 / 20261009-00007`），
   产品都是它的两行 `C-84-01 / C-84-02` —— 说得通；
3. 若某张单补错了：`rollback-finish-in-wo-backfill-20261022.sql` 一次全撤（或先手工把该单加工单号改掉，回滚脚本会跳过它，不动新值）。
