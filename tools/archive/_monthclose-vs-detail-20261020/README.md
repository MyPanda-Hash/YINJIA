# _monthclose-vs-detail-20261020 — 库存明细「月结单据明细」为什么有些行有、有些行没有

用户 2026-10-20 提问:「库存明细的月结单据单据为什么有些数据有有些无」。

## 复现方式
`Q_run.java <库> <脚本.sql>`(只读探针,UTF-8 读文件;`GO` 分批)。

## 取证结论(正式库 HSDZ_MES,期间 2026-09 已月结)

| 事实 | 数字 |
|---|---|
| 月结行表 `bl_stock_close` (物料,仓库,批号) 键 | 2389(含 117 个结存=0) |
| 结转行 `inh` JZ-202609 | 2272 = 恰好「非零结存」的键(**结存=0 按口径不写结转行**) |
| 缺结转行的 117 个键 | **全部** 结存=0,无一异常 |
| 库存明细(kucun) 键 | 2475:有结转行 2429 / 无 46(其余 29 个是上月零余额但保留预警的) |
| kucun 里有、`bl_stock_close` 里没有 | 182(本月新批次;其中 42 个物料+仓库连结转行都没有) |
| 上月非零结存但今天明细里缺失 | 0(数据没有丢) |

## 根因(展开区取数口径)
`StockMonthCloseService.detail()` 原先:上月「已月结」时**只取结转行**。于是两类行必然空:

1. **上月期末结存 = 0 的(批号,物料,仓库)**:月结按用户口径「0 就不写结转行」⇒ 该批没有月结单据
   (比如 9 月进完发完、10 月补货再发的批次)。
2. **本月才出现的新批次**:上月没有这个批号,当然没有它的结转行。

按旧口径统计:2429/2475 行有、46 行整段空(另外 42 个物料+仓库 只有当月单据、无月结行)。

## 修复(2026-10-20)
上月这段改为 **结转行(已月结时)+ 上月原始单据** 合并,按「单据编号+批号」去重:
- 已月结:月结行打头,后面是上月(**9 月**)的原始出入库单据,余额来源不再断;
- 未月结/已取消:仍只陈列原始单据(保持第三轮口径)。

⚠ 口径变化:以前已在 9 月被结转「吃掉」的原始单据现在也会列出来,组内 `余额`/`当月合计` 会把上月动过的量
再算一遍 ⇒ 想余额精确请用外层报表「现存量」。这是「让每行都能看到余额来源」付出的代价,
改口径要用户点头,别擅自再改回去。
