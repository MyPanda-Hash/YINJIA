> 迁移脚本尚未编写;本文件是续做入口。

> **⚠ 本文件是动工前的计划;实施中有 4 处口径改了(2026-09-21 落地后补记)。**
> 权威口径以 `tools/migrate-inv-report-fields.sql` 头部注释 + `InvCostService.java` 类注释 + `db-migrations.txt` 登记项为准:
> 1. **成本没做成存储过程**:yinjia 非 db_owner,dbo 架构下的对象既不能 EXECUTE 也无权 GRANT →
>    改由后端 `InvCostService` 直接跑递归 SQL(审核/弃审钩子 + 启动自检 + 面板「重算成本」按钮)。
>    故下文第 3、9 行的 `sp_recalc_inv_cost` 作废。
> 2. **批号不进成本分区、也不进 GROUP BY**:批次级 225 个分区里 114 个「只出无进」(实测),
>    出库成本会恒为 0;批号只作台账明细列。故下文第 ② 行作废。
> 3. **新字段只落台账**:往来单位/经手人/含税/税额在汇总表会变成 MAX 出来的混合值、在状况表无对应语义
>    → 仅 STOCK_LEDGER 加 6 列(含新增「发出单据金额」,避免售价信息被成本口径顶掉)。故下文第 ③、7 行范围收窄。
> 4. **原始单价列未加**:由 `ISNULL(金额, 单价×数量)` 兜底吸收。
> 实测结果:成本覆盖 235/235,累计出库成本 1,097,266.09,结存金额 3,099,936.64,勾稽不符 0。

- 结存金额三种口径:**售价口径 −205,981.28**(现状,列名「结存金额」) / **累计入库加权平均 2,268,221.49** / **真·移动加权平均 3,092,184.28**。
  两法相差 **823,962.79(27%)**,单分区差异最大 447,014 → 不可当近似互换。

  采购侧 distinct(存货,仓库) 64 组、销售侧 60 组、**交集仅 33** → 一半分区"只出无进",必然负数。

## 三、硬约束(改变了实现方式)

1. **递归 CTE 可以建视图,但视图不能写 `OPTION (MAXRECURSION)`**,走默认上限 **100 行**。台账 235 行 → 实测报「完成执行语句前已用完最大递归 100」。
   → 真·移动加权平均**不可能**在实时视图里实现;**存储过程可以**用 `OPTION (MAXRECURSION 0)`。这就是选物化方案的技术原因。
2. **只有 `bl_purchase_in` / `bl_sale_out` 有 `仓库编码` 列**;其余 6 张行表只有 `仓库` 名称。
   → 那 6 类只能走名称查 bs_wh 兜底(它们 0 行,无数据损失);视图里必须对它们传 NULL 而不是引用不存在的列。
3. `批号` 列 8 张行表**都有**;`id` 均为 `int`。
4. `bd_other_in` / `bd_material_out` 没有 `经手人`/`部门`/`供应商编码`/`客户编码`。
   → 这 6 类头表的 `往来单位编码`/`经手人`一律传 NULL(0 行,且避免引用未验证列)。
5. bs_wh 6 行、编码与名称各 6 个 distinct → 按编码 join 不扩行。

## 四、拟建结构(一个迁移脚本内完成)

```
tools/migrate-inv-report-fields.sql

1) 新视图 v_stock_movement —— 8 类单据 UNION **只此一处**(消掉现在 balance/ledger 各复制一份的重复)
     列: src, rid, 单据日期, 单据类型, 单据编号, 业务类型,
         仓库键, 仓库编码, 仓库(显示名), 存货编码, 存货, 规格型号, 计量单位,
         收入数量, 发出数量, 收入金额, 发出售价金额, 含税金额, 税额,
         往来单位, 往来单位编码, 经手人, 批号
2) 新表 inv_cost_ledger(PK (src, rid),每行表行只出现一次,故 PK 稳定)
     列: 仓库键, 存货编码, 批号, 单据日期, 收入数量, 发出数量, 收入金额,
         结存数量, 移动加权单价, 结存金额, 发出成本金额
3) 新存储过程 sp_recalc_inv_cost @仓库键=NULL, @存货编码=NULL(NULL=全量,否则只重算该分区链)
     递归 CTE + OPTION (MAXRECURSION 0);DELETE 范围行 → INSERT;幂等
     单价规则:结存数量<>0 时 结存金额/结存数量,否则 0
4) 重建 v_stock_ledger —— 基于 v_stock_movement,LEFT JOIN inv_cost_ledger 取成本
     **必须保留这些列名**(QueryService/ButtonService 依赖):仓库, 存货, 单据日期,
       收入数量, 发出数量, 收入金额, 发出金额
     分区:PARTITION BY 仓库键, 存货编码, 批号;期初 LAG / 期末累计
5) 重建 v_stock_summary —— 基于 v_stock_ledger,GROUP BY 加 批号;删掉死列「辅单位」(源数据 计量单位2 仅 2 行)
6) 重建 v_stock_balance —— 基于 v_stock_movement,GROUP BY 加 批号;成本取 inv_cost_ledger
7) yj_field:三面板加 批号(detail)、往来单位编码、经手人、含税金额、税额;摘要表删「辅单位」
8) yj_translation:新字段 en 译名
9) 后端 ButtonService 审核通过 → 调 sp_recalc_inv_cost(仓库键,存货编码);另加「重算成本」按钮
10) tools/db-migrations.txt 登记
```

### 注意事项
- QueryService 的台账三段式(期初/期末合成行)SQL 是 `收入金额 - 发出金额`,发出金额改成本后**自动一致**,无需改 Java。
- QueryService 的期初/期末合成行是**存货级**总计;明细行是**批次级**。两者相加相等(批次结存之和=存货总),但呈现上要说明。
- 批号暂时只作 detail 列(不进查询区),避免与存货级合成行的口径不一致。
- **原始单价列不加**:`单价` 已被 ⑤ 的 `ISNULL(金额, 单价×数量)` 吸收,单列会重复(有意偏离原建议)。
- 41 行负现存量属**数据/仓库填写问题**,成本口径修不了;需单独确认是否测试数据随机分仓。
