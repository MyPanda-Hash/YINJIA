与 `SL-2026-11-0144`(11-24,本行 150,即本单来源)。

## 三、MES 为什么还放它送 150

- MES 生单只看自己 `form_flow_link` 的已生单量:该行 1000 + 150 = 1150;
  系统参数 `receive_over_ratio` = 0.2 ⇒ 可送上限 1000×1.2 = **1200** ⇒ 放行。
- 金蝶侧实际已入库 1125(见 §二),收货上限按订单量 1000 算 ⇒ 再收 150 就是超 275 ⇒ 拒绝。
- 两端**没有任何自动同步**:同步任务只拉采购订单 + 档案 + 库存,不拉采购入库单(见
  `deploy/采购订单未完成数量-MES与金蝶口径差-20261123.md` §一)。

## 四、报错链路(代码,已核对)

1. `ButtonService#pushToErp` → 包一层「转ERP失败:」
2. `KingdeePushService#pushDocument` → `doPushDocument`([[KingdeePushService.java:207](file:///D:/YINJIA-main/backend/src/main/java/com/yinjia/mes/service/KingdeePushService.java)])
3. 表头「采购订单号」是合单串 ⇒ 逐行用行级「源单编号」解析(`resolveLinePoRef` → `resolvePoRefs`),
   解析到就带整组 `src_bill_no` + `src_bill_type_id=pur_bill_order` + `src_inter_id` + `src_seq` + `src_entry_id`
   ([[KingdeePushService.java:688-726](file:///D:/YINJIA-main/backend/src/main/java/com/yinjia/mes/service/KingdeePushService.java)])
4. 带 `src_bill_type_id` 后金蝶**按下推校验源单分录**:该分录可关联量已为 0/负 ⇒ 报本文这句;
   `errcode!=0` 时把金蝶原文抛给前端([[:767-770](file:///D:/YINJIA-main/backend/src/main/java/com/yinjia/mes/service/KingdeePushService.java)])
5. `resolvePoRefs()` 目前只取 `id` / `seq`(推 `src_*` 用),**没读** `close_state / in_qty / un_out_qty`
   ⇒ 所有"金蝶侧已收满/已超收/已关闭"的情况,现场只能看到金蝶原文。

## 五、处置(业务拍板,三选一)

1. **这 150 个不该再入库**(最可能,1125 已超收 125):
   弃审本单 → 把第 4 行(YJ-GL-001 150,源 `YJ-20260924-04` 行 6)删掉/改小 → 重审 → 转ERP。
   其余 3 行(150 / 300 / 180)都还有额度,不受影响。
2. **确实又到了 150 个**:
   先在金蝶把该订单行的量改大(或补一张订单/订单行),使未执行 ≥ 150,再回 MES 重转。
   注意该订单已审核,金蝶侧要反审核才改得动;不建议靠"反关闭分录"——那会改成报「不允许超量入库」
   (同 2026-11-07 的 `PI-2026-11-0018`,见 `tools/archive/_erp-overreceive-20261107/README.md`)。
3. **不挂源单硬推**(仅应急):清空该行的「源单编号」再转 ⇒ 代码按无来源单的普通入库单推送
   (会 `log.warn` 提示);代价是这 150 不再计入订单执行、金蝶该行仍未闭环 —— 只作临时手段。

> 不建议把超收量拆成"其他入库单":会脱离采购订单来源,应付/成本口径与采购链不一致。

## 六、代码可改进(未实施,待确认 —— 与 11-07 / 11-11 两次建议合并)

1. **转ERP 推前预检(最高性价比)**:`resolvePoRefs()` 已经在拉订单详情,
   顺带读 `material_entity[].{close_state, in_qty, un_out_qty}`,逐行比对本次实收数量:
   - 命中「未执行 ≤ 0」或「实收 > 未执行」或「close_state=0」⇒ 直接抛人话:
     「第 4 行 YJ-GL-001 挂的采购订单 YJ-20260924-04 第 6 行已入库 1125/1000(超收 125),没有可关联数量;
     请减少本行数量或先在该订单加量」;
   - 不再把金蝶原文甩给用户,也不必让现场去猜哪一行。
2. **超送口径统一**:MES「收料超送比例」20% ↔ 金蝶超收控制(默认 0)必须一致;
   或在转ERP 时按「金蝶未入库量」截断(不截断就必然在金蝶制造负数未执行行)。
3. **反向同步(治本)**:定时拉金蝶采购入库单回写「订单行 × 已入库量」,
   生单阶段就按金蝶未入库量约束 —— 否则"一边在 MES 生单、一边在金蝶手工收货"会一直复现。
