# _print-station-20261104 — 自动打印改「按电脑 + 按打印类型」的取证与验收

任务:2026-11-04 用户口径

> 「现在的自动打印有问题,我是想要设置的电脑开启自动打印,没有设置的电脑就不开启,
>   但是在服务器上开启是固定的。能不能在自动打印的面版加个参数来限定电脑。
>   还有我想加个勾选打印类型的。现在自动打印只有生产领料单。但如果后面也有多个电脑
>   每个电脑又不同打印要求,需要面版能够勾选打印的需求报表。」

## 一、改前的问题(为什么"不设的电脑也会打")

旧实现:一个**全局**开关 `print.auto_enabled` + 一条**共享**队列。
任何一台电脑只要在轮询(打印代理或页面),就取走队列里的任务 —— 谁先轮到谁打;
而且只能"全打/全不打",表达不了"这台只打领料单、那台只打报工单"。

## 二、改后的口径

- **站点 = 一台打印电脑**,键是**站点名称**(打印代理的 `-Station`,代理每 4 秒
  `/pending?station=<站点名>` 自己拉任务;面板上看到的就是这个表单里的名字)。
- 配置存 `yj_app_setting`:`print.station.<站点名>.enabled` / `.types` ——
  代理在跑、页面可能没开,只存 localStorage 的话服务端一重启就丢。
- **没配置过的站点默认关闭**(用户要的"没设置的不开");服务端总闸固定常开。
- 派单 = 类型匹配 + 开关打开 + 90 秒内有心跳;多个站点都符合 ⇒ 都打(各自一张)。
- 迁移脚本 `tools/migrate-print-station-20261104.sql` 按旧参数 `print.station_name`
  给现网那台电脑补「开 + 生产领料单」,升级后不用先配一次。

## 三、验收证据(2026-11-05,本机 5173 / 8090,vite+jar 同源)

| 场景 | 结果 |
|---|---|
| 代理刚起来、站点未配置 | 清单里出现「打印电脑-01」(`source=agent`)、`enabled=false`、`types=[]` |
| 未配置时手机发单 | `queued:false`、`reason:no-subscriber`、提示"…没有可用的打印电脑:请…把该电脑的开关打开并勾上「生产领料单」" |
| 面板给该电脑开开关 + 勾「生产领料单」 | `enabled=true`、`types=[PICK_SLIP]`(库:`print.station.打印电脑-01.*`) |
| 再发一单 | `queued:true`、`targets:["打印电脑-01"]`、`message:已发送到打印电脑「打印电脑-01」` |
| 代理(每 4 秒轮询)取任务 | 4 秒内出纸:`deploy/print-agent/print-out/GD-AGENT-1_L1_20261105-102107-914.pdf`;回执后 `queueSize=0`、最近出纸「已出纸」 |
| `/pending` 无 station | 不注册、不派单(没有"无名站点") |
| 旧全局开关 `print.auto_enabled` | 已不参与分发,remark 标记【已停用】 |

`print-agent.ps1 -Port 18778 -Mode Pdf -Server http://127.0.0.1:8090 -User admin -Pass 123456 -Factory YJ_TEST -Station 打印电脑-01`。

## 四、顺带修掉的纸面缺陷(同一片代码)

`queueToPrintStation` 只转发了「标题/二维码/工单号/产品/规格」—— **把后端算好的
`领料单号 / 打印日期 / 明细` 丢了**。后端 `printPayload` 和打印代理的绘制逻辑都靠这几个字段
(2026-11-02 用户要的"纸质领料单"七列表格),少了它们打出来就是一张空表头的纸。

修法:按原样透传(见 `frontend/src/business/printStation.js`)。证据 = 同一台代理、同一个模式:

| 任务 | 载荷 | 产出 PDF |
|---|---|---|
| `GD-AGENT-1` / `GD-AGENT-2`(修复前,无明细) | 抬头 + 二维码 | 121,788 / 122,183 字节 |
| `GD-2026-11-0016 #1`(修复后,单据页点「打印二维码」) | 抬头 + 领料单号 + 2 行明细 | **133,667 字节**,`print-out/GD-2026-11-0016_L1_20261105-102835-226.pdf` |
