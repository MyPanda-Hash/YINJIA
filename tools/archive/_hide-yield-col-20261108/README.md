## 为什么隐藏

- 算法(行级,2026-10-30 起)= `本工单行需求 xq_sl − 本工单行订单占用`(form_flow_link 里
  `target_panel_code='PLANG'`、`target_line_key=工单号#工单行号`、`link_status='ACTIVE'` 的
  `linked_quantity` 合计),不足 0 记 0。取数:`WorkOrderListController.ROW_YL` /
  `ScheduleBoardService.ROW_YL`(同式两份)。
- 2026-10-31 起 `xq_sl = pl_sl = 本次转单量`,占用链也写同一个数 ⇒ **正式库 399 张有效工单行里
  397 行恒为 0**;唯一非零 1 行是 2026-10-20 切单未拆账留下的假余量
  (`GD-2026-10-0226-1` 显示 10,而该订单行实际已 100/100 转满);另 1 行父单占用 100 > 需求 90 被压成 0。
- 列名叫「余量」但**不含工序/换算率/报工/入库**,与"当前工序还剩多少未生产"无关,极易误读。
- 要看"还剩多少":生产工单页「工序进度」(当前工序完工量/计划量)、工单排产页「未交量」(排产−入库)。
