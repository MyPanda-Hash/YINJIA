# _scan-multi-20261105 — 扫码按纸面顺序 + 多选(一次扫多张工单)

用户 2026-11-05 第三轮口径:

> 「下边的提示框能不能实现,按照图片中的顺序来对应的。生成工单领料和退料单这个界面的
>   扫码能不能支持多选。可以多个订单生成一对一的领料单。」

## 一、按纸面顺序排列(原生 ScanActivity)

- 排序键 = 条码中心点的 `(bufferX 升序, bufferY 降序)`。
  竖屏 + `setDisplayOrientation(90)` 时 buffer(x,y) → 屏幕 `(H-1-y, x)`,
  所以"屏幕行"随 x 增大、屏幕列随 y 增大而左移;这样列表顺序 = 纸上从上到下的序号;
- 中心点取 `Result.getResultPoints()` 的均值(QR 是 3 个定位点,1D 是两个端点);
- 同一行(Δx < 24px)内按 y 降序(右→左),再按文本兜底,避免位置抖动导致顺序乱跳。

## 二、多选扫码

| 层 | 改动 |
|---|---|
| 原生桥 | `MainActivity.Bridge.scanMulti()` → 以 `multi` 模式打开扫码页;结果走 `window.__yjScanResultMulti([...])`(数组按纸面顺序) |
| 扫码页 | 多选模式下每行可勾选(**默认全选**),底部按钮:`全选/全不选`、`生成(N)`、`重扫`、`取消` |
| 网页 | 「生成工单领料/退料单」页多一个 **扫多张** 按钮(仅新版 APK 显示);回传的码逐个 `parseWorkOrderCode` → 待生成队列(重复跳过并报数) → 点「批量生成」 |

为什么不"扫一张就自动生成一张":现场是一沓单子,先把队列看全、再一次性生成,
中途发现扫错了可以直接删行(队列每行有「删除」)。

## 三、验收

- 网页侧(用注入的假 `YjNative` 桥验证,不需要真机):
  `round-54.mjs` → 按钮出现「扫多张」;喂 4 个码(其中 1 个重复)→
  队列 3 行、提示「已加入 3 张工单 · 跳过 1」、按钮变「批量生成 (3)」,
  截图 `create-scan-multi.png`。
- APK:`aapt2 / javac / d8 / zipalign / apksigner` 全绿;dex 内含
  `scanMulti`、`multiAll`、`multiPick`、「按纸面顺序排列」「已选 」。
- ⚠ 真机未验(本机无设备):排序方向按 90° 传感器的标准映射实现;若某机型方向相反,
  列表会整体上下颠倒 —— 把 `ScanActivity.sortedCodes()` 里 x 的比较取反即可。
