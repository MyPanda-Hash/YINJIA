## 三、🔴 最大隐患:计量单位不参与结存(克 g vs 千克 kg)

- `bs_inv`:这些物料 `是否多单位=1`、主计量 `g`、辅助单位 `kg`、**换算率1 = 1000**(1 kg = 1000 g);
- 期初 `INIT-20260831` 的 14 行按 **g** 记:合计 **3,013,900**(占期初总量 5,660,746 的 53%);
- 而 MES 材料出库单据按 **kg** 记(如 `SCLL-20260915-00004` HP-08 75 kg);
- `kucun` / `inh` / `outh` **没有单位列**,三键只有 (物料,仓库,批号) ⇒ 两种单位直接相减。

实例 `XH-SX80250SX / YCL-01`:

```
期初 1,039,000 (g) − 出库 925 (kg) = 台账 1,038,075
真实 1,039 kg − 925 kg = 114 kg
⇒ 台账虚高约 1,037,000(每次出库只扣掉 1/1000 的量)
```

同类 13 个 (仓库,存货) 键、26 行在 `v_stock_balance` 里被「主计量」拆成两行(一正一负):
`HP-08`(YCL-01 与 CK00006 各一条)、`HS-150 / HS-2040 / SD-000 / SIT-Q4 / SSC-Q3 / XC-2040 / XC-4080 /
XH-SX80250SX / YJ-044` 为 g/kg;`YJ-JPL-033` 为 kg/米;`YJ-SX-031` 为 PCS/个。
另有 2 个键因「规格型号」不同被拆(`C-78-31` 空 vs 'Z049'、`CL002` 'A00' vs 空)。
合计 **15 键 / 30 行**(`_q18` 实测)。

⇒ **现存量合计里 57% 是克(g)**,首页「现存量 TOP」跨仓库按存货 SUM,等于把 g 和 kg 相加。

## 四、其余四条会"影响判断"的口径问题

- **R2 预警数量三种口径**:设过阈值的行 = 0。门户口径 `ISNULL(NULLIF(预警数量,0),50)` ⇒ **691 条**低库存告警;
  看板/库存状况表口径 `预警数量>0` ⇒ **0 条**;出库闸门按 0 ⇒ 等价"不许负结存"。
- **R3 "现存量提取"只取前 500 行**:`engine.js:447` 调 `STOCK_STATUS`(kucun,2,138 行)`pageSize:500`,
  服务端上限 1,000 ⇒ 只看得到 id 最大的 500 行。复算:1,431 个键里 **984 个完全取不到(回填 0)**、
  119 个只取到一部分 ⇒ 1,103 个键(77%)显示的现存量是错的。
- **R4 库存状况表按 主计量/规格型号 拆行**:15 个键被拆成 30 行,同一 (仓库,存货) 会出现一正一负两行
  (例:`C-78-31` −502 / +10;`CL002` −391 / +248)。
- **R5 单据行「现存量」是过期快照**:后端零引用(`grep 现存量` 仅命中注释与 8 处守卫文案),
  界面上的负数/陈旧值纯属 2026-09~10 导入时的历史值。
