# 修「生成工单领料时只打组装领料单、混料领料单不出纸」— 2026-11-17

> 用户报障:「生成工单领料扫码的时候,只由组装领料由自动打印,混料领料没有打印出来。」

## 一、根因(两处,缺一不可)

一个工单行现在会出**两张**单:组装领料 + 混料领料(2026-11-18 口径)。打印链路断在两处:

| # | 位置 | 问题 |
|---|---|---|
| ① | `frontend/src/views/mobile/MobilePickCreate.vue` → `autoPrintAll()` | 只读**顶层** `r.打印`(后端把组装那张的载荷放在顶层),`单据[i].打印` 里的混料载荷从来没被送进打印队列 ⇒ 只出组装一张 |
| ② | `backend/.../MobilePickController.java` → `existingResult()` | **重复扫码**(该工单行已开过单)走这条路径时,`单据[]` 里每张单**没有** `打印` 载荷 ⇒ 就算前端改成逐张打,重打时混料那张还是打不出来 |

后端**新建**路径(`createPickDoc`)本来就逐张给了载荷 —— 实测:组装「明细 2 行」、混料「明细 6 行、标题=混料领料单」,所以问题只在前端取数与重复路径。

## 二、改了什么

1. **前端纯逻辑**(可单测):`frontend/src/business/mobilePick.js` 新增 `printJobsOf(result)`
   —— 有 `单据` 数组就**逐张**取各自 `打印`;没有(老结构/单张)退回顶层 `打印`;
   按领料单号去重(重复扫码会把同一张单列两遍);载荷为 null(关掉自动打印)则不打。
2. **前端页面**:`MobilePickCreate.vue` 的 `autoPrintAll()` 改为遍历 `printJobsOf(r)` 逐张入队
   (`queueToPrintStation` → 没订阅/离线则退回本机 `printWoQr`)。
3. **后端**:`existingResult()` 给 `单据[i]` 逐个补 `打印`(标题/领料类型/明细各按自己那张单取)。
4. **单测**:`frontend/src/business/mobilePick.test.js` 加 4 条
   (两张单都打 / 无单据数组退回顶层 / 重复单号去重 / 载荷为空不打)。
