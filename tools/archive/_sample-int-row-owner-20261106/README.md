# 内部样品单 = 数据记录表：行级归属 + 改他人行 + 纸面 20 行分页（2026-11-06 第三轮）

## 用户口径（原话）

> 「内部的这个样品开发单去掉审批，不需要审批，性质是一个数据记录表，但是样式不变，可以新增行数进行填写，
> 多了就切页，20行就切，谁填写的申请人就是谁，每个人只能改自己作为申请人的行数据，点击保存之后申请人
> 就不能改了，只能由有更改权限的人来改，这个权限写进组织架构对应面板里面，未点保存点击草稿，申请人还是
> 可以改的，每一行数据就像一张独立的单据一样，保存修改状态是不互通的」

## 实现

| 点 | 做法 |
|---|---|
| 无审批 | 仍在审批按钮组名单之外；保存只落库定稿，不送审 |
| 样式不变 | 纸张表格（模板 13 列）保留 |
| + 新增行 | 底部「＋ 新增样品」，新行自动带 `申请人 = 当前登录人`（未保存前可改） |
| 20 行切页 | `config.grid.pageSize = 20`；DocSheet 表内分页条「◀ 1/2 ▶ 每页 20 行 · 共 25 行」，保存仍提交整表 |
| 行级归属 | `ButtonService.applySampleIntRowRules`：新行强制 `申请人=当前用户`；已保存行**申请人锁回库值**；别人已保存行**内容原样回写**且**不因缺席被软删**（`upsertLineRows` 新增 `protectIds`） |
| 改他人行权限 | 新权限词 `edit_others`：`SysAdminController` 给 `RD_SAMPLE_INT` 专属动作集 → 组织架构·角色与面板权限矩阵多一列「改他人行」；`PanelPermissionService.PERM_LABEL` 同源文案；`AuthController` 下发 `user.editOtherRowsPanels`；前端据此解锁 |
| 权限落点 | `migrate-sample-int-row-owner-20261106.sql`：**按角色能力**（该面板 can_approve='Y'）授予，不写死 role_id —— 正式库实测角色 id 是 1/1025/1026（本地曾是 1/3/4），写死会在正式库只命中 1 个 |

## 实测

- 本地（sampler=打样员 普通用户 / admin=系统管理员）：
  - 25 行时纸面出现分页条「1/2 · 每页 20 行 · 共 25 行」；
  - sampler 视角：别人已保存行 = `RO:` 只读文本；新增行自动带「打样员」；
  - sampler 只提交自己那行保存 → admin 的行(系统管理员)保持存活且内容未被改；sampler 自己的旧行按缺席删除。
- 生产：
  - `GET /api/sys/role/1/panels` 里 `RD_SAMPLE_INT` 动作列已含 **「改他人行」**（14 列）；
  - `yj_role_panel`：管理员(1)/文件负责人(1025)/研发审核(1026) 均带 `edit_others`，普通用户(2) 不带；
  - 台账 760 → **761**（测试 635 → **636**）。
