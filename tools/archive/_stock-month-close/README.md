# 库存月结(2026-10-15)

> 用户口径:「每月 1 号自动月结上个月的」+「上月月结 / 取消上月月结 / 重新月结」三按钮 +
> 按 (物料编码, 仓库编码, 批号) 汇总上月入库(含上月结转来的量)+ 用上月入库数据循环运算逐笔统计出库汇总 +
> 写进 `inh` 生成结转单据 + 出入库三步(统计本月合计 → kucun 有则改无则增 → 改余量)+
> 报表左侧做成「采购入库单选单同款、按仓库选择」。

## 1. 两个定了才敢动数据的口径(用户 2026-10-15 拍板)

| # | 口径 | 取值 | 为什么 |
|---|---|---|---|
| A | 结转行写进 `inh` 后,**累计口径**怎么不翻倍 | 结转行 `src=0` + `单据类型='月结结转'` + `单号 JZ-YYYYMM` + `日期=次月1号`;**`v_stock_movement` 按 `单据类型<>'月结结转'` 排除它** | 三张报表与成本引擎都是「全部历史求和」;若把结转行算进去,8月末结存 X 会被 9 月再记一遍 ⇒ **库存逐月翻倍** |
| B | kucun 的「有则改无则增」 | **幂等重算**:`rkl/ckl` = 截至期末累计、`yl` = 累计入 − 累计出 | kucun 已由审核/弃审钩子**实时维护**;若按「本月入−本月出」累加就是**双计**。重算还有个附带好处:542 行负现存量那类偏差会按流水回正 |

**结转行为什么落次月 1 号**(而不是被结月份的月末):用户口径是「汇总上月的入库数量(**包含上月结转过来的数据**)」——
落在次月 1 号,次月的「本期入库」就天然含上月结转来的量;落在被结月月末则次月求和会漏掉它。

### 计算顺序(有依赖,别调换)

```
① 汇总 期初/本期入/本期出   ② FIFO 分摊(顺带回写缺批号出库行的批号)
③ 用分摊结果覆盖每键出库量   ④ 写结转行(inh)  ⑤ kucun 幂等重算  ⑥ 月结头/行表
```
②必须在⑤之前:回写批号改变了流水侧的键归集,⑤要按回写后的结果重算,才能与⑥的行快照对得上。

### FIFO 循环运算(用户口径③的实现)

- 队列 = **期间开始前的结存**(按期初日合成一行,保证排在期间入库之前)+ 本期间入库行,按 (单据日期, id) 升序;
- 出库行按 (单据日期, id) 升序逐笔取用:带批号的只吃自己那一批(取空记「超发」,不阻断);
  **不带批号的在整组内先进先出,整笔恰好落在单一批次时回写 `outh.批号`**(跨批的行不回写,单行拆不成两条批号);
- 产出每批的**分摊出库量**与**最晚出库日期**;分摊不掉的余量留在原键上(不隐藏、不吞掉)。

## 3. 真跑结果(2026-10-15,两账套都跑了 2026-09)

> 为什么跑 2026-09 而不是当前月:数据里真正的「上月」是 2026-09(1271 条入库),2026-10 才过半;
> 按钮默认口径本来就是「上月」。

| 项 | HSDZ_MES_TEST | HSDZ_MES |
|---|---|---|
| 期间的键数 / 结转行数 | 2443 / 2143 | 2445 / 2145 |
| 入库合计 / 出库合计 | 2,393,738.50 / 2,562,781.626 | 2,393,939.50 / 2,562,781.626 |
| **结存合计(写进结转行)** | **4,663,156.77** | **4,663,357.77** |
| kucun 新增 / 更新 | 224 / 2203 | 226 / 2203 |
| FIFO:缺批号出库行 / 回写 / 跨批未回写 / 超发 | 661 / 197 / 18 / 767 | 661 / 197 / 18 / 767 |
| kucun Σ现存量(月结前 → 后) | 4,455,288.07 → 4,707,806.77 | 4,287,547.564 → 4,751,133.77 |
| kucun 行数(前 → 后) | 2281 → 2505 | 2281 → 2507 |
| kucun 负值行(前 → 后) | 264 → 381 | **542 → 381** |

**两条硬验证**(`q-03-monthclose-effects.sql`):

1. **三张报表口径一字未变**:正式账套 `v_stock_balance` 月结前后都是 **1634 行 / Σ现存量 4,493,375.07**;
   今日写入 `inh` 的行**只有** `月结结转` 2145 行(+ 另一条线的 `期初结存` 1888 行),`outh` **0 新增**、
   只有 197 行被回写批号。
2. **排除生效证明**:视图净额 4,493,375.07 + 结转行 4,663,357.77 = 含结转净额 **9,156,732.84** ——
   正好差一份结转行。若不做这个排除,累计口径就会凭空多出一整份库存(逐月翻倍)。

**一致性交叉验证**:2026-09 月结算出的期末 4,663,357.77,与独立空跑出来的「2026-10 期初」完全相等 ⇒
「期末 = 次月期初」这条账理成立。

⚠ **kucun 的变化是幂等重算的结果**(用户口径 B):Σ现存量 +46 万、行数 +226、负值行 542→381 ——
即「流水里有、kucun 里没有」的键被补上,偏差按流水回正。若认为不该动 kucun,**取消月结不会回滚它**
(设计如此:回滚反而会把它改错);要退回月结前的数值,得用月结前备份(`bd_stock_close` 里记了合计)。

## 6. 踩坑留档(本任务实测,别重犯)

| # | 坑 | 现象与根因 |
|---|---|---|
| 1 | `单据日期` 是 **datetime** 不是 date | `String.valueOf(Timestamp)` → `"2026-09-30 10:20:30.0"`,直接喂 `java.sql.Date.valueOf` 抛 `IllegalArgumentException: null`(**消息为空** ⇒ 全局异常处理器只回一个 `code:400/500`,没有线索)。两处都得上 `toDate()` 截前 10 位 |
| 2 | NULL 被拼成字面量 `"null"` | `String.valueOf(null)` = `"null"`,同样会喂给 `Date.valueOf` 炸掉;判空必须在取值处 |
| 3 | 全局异常处理器吞堆栈 | `GlobalExceptionHandler` 把异常归一成 code+message,**不打日志**。为此给月结加了运维直调入口 `POST /api/stock/monthClose/run`(返回异常类名 + 消息 + 前 8 帧),后续排查先打它 |
| 4 | `rebuild-prod.ps1` 的 fat jar 自检 | 脚本用 `jar tf`,而 `jar` 不在 PATH(`$JAVA_HOME\bin` 没进 PATH)⇒ 打包成功后卡在自检、**没重启服务**。自检要显式用 `"$env:JAVA_HOME\bin\jar.exe"` |
| 5 | 停服才能 repackage | 后端跑着 `target\*.jar` 时 `mvn package` 报 `Unable to rename ... .jar.original`;必须 `start-prod.ps1 -Stop` 后再打包 |
| 6 | **改了后端必须重打 jar 才生效** | 8090 跑的是 jar 里的 class:我先改了 `QueryService._whCodes` 却在旧 jar 上验前端 ⇒ 勾选仓库**看着像前端没生效**(条数纹丝不动),其实是后端不认这个条件键。判据:同一个接口用 curl 直接带 `_whCodes` 试一次,能区分「前端没送」还是「后端没认」 |
| 7 | 改带中文的 `.ps1` 会丢 BOM | 编辑工具写回的是无 BOM UTF-8,PowerShell 5.1 按 GBK 解码 ⇒ 语法报错。改完 `.ps1` 要**补回 BOM**(本仓库既有脚本都是带 BOM 的) |
