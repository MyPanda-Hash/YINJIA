## 二、逐流程测了什么(全部真实接口,证据 JSON 在本目录)

### 1. 生成工单领料/退料单(扫工单 → 批量生单)—— `10-createbatch.ps1`
- `GET /create/woStatus` → 204 行工单行、26 行未开单(当时口径);
- `POST /create/batch` 扫 `GD-2026-11-0010#3` + `GD-2026-11-0009#1` → **成功 2、失败 0,每张工单行各出「组装 + 混料」两张单**;
- 再扫同一批 → **不重复建单**(全部 `重复=true`)。

### 2. 生产领料(扫工单定位 → 扫物料 → 填数量 → 提交)—— `20-pick.ps1`
- `GET /locate?woNo=GD-2026-11-0010&line=3` → 命中 **两张单**(组装 `LL-2026-11-0029` / 混料 `LL-2026-11-0030`);
- 单据明细 3 行:半成品 `A-48-16**TB`(标 `半成品·免领`)+ PE袋 + 无纺布;
- **扫半成品码被拒**:「物料 A-48-16**TB 是半成品(编码含 \*\*TB),本厂不入库、不需要领料」;
- 扫物料返回可用上限(PE袋 1977 / 无纺布 4000)、`setQty` 后 `可以提交=true`;
- `POST /submit` → **出库行数 2,单号 LL-2026-11-0031**,状态转「已完成」、`出库已审批=false`(等仓管审批,没扣库存);
- 混料单侧:扫 `YJ-YKRS-001` 可用上限 0,填 1 → **被库存闸门拦**:「库存不足…请减少数量或先补货」。

### 3. 生产退料(扫已审领料单 → 扫物料 → 退料)—— `30-return.ps1`

- 超退(999999)被拒:「可退只剩 9(已领 10 − 已退 1)」。

### 4. 其他领料 / 其他退料(只扫物料码,扫完提交)—— `40-other.ps1`

### 5. 扫码混料(扫工单 → 物料清单 → 逐项取秤 → 整单保存 → 补打印)—— `50-mix.ps1`

## 四、发现的问题(按严重度)

1. **工序报工页面进页面不自动聚焦扫码框**(界面)。`scanFocus` 口径要求「刚进入光标就在扫码栏」,
   该页 `document.activeElement` 停在 BODY;同页其它 6 个扫码页都正常。
2. **扫码混料只认完整工单码**(`公司代码@工单号@1000+行号`);输入裸工单号 `GD-2026-11-0010` 会提示
   「不是工单码(工单码格式:公司代码@工单号@行号)」。现场扫纸面二维码没问题,但**手输/调试必须带公司代码段**,
   且页面上没有"按工单号查询"的兜底(生产领料页有)。建议给扫码混料补一条「裸工单号也接受」或明确提示。
3. **其他出库单空清单提交后端不拦**:`/px/callButton(OTHER_OUT, 提交, 明细=[])` 返回 200 并生成
   `OO-…0010`(0 明细的草稿单)。前端会拦,后端没拦 —— 与「扫完才提交」的口径不一致,建议后端补一条空明细校验。
4. **混料单目前仍提交不了**:补齐配方里有 7 个物料(椰壳炭 `YJ-YKRS-001`、`YJ-YPS-001`、`M4-D YJ-ZX-001`、
   `PS-2`、`Sr-35200`、`AGC-80250`、`KG-AJE-A01`)在测试库**没有库存**,生单时仓库预填为空、
   填数量会被「库存不足」拦。要跑通「混料单 → 提交 → 仓管审批」还得先给这几个料做期初/入库。
5. (上一轮已修)两账套缺 `wo_bom` 导致生成领料单一律 500 —— 已补跑 `migrate-wo-bom-20261113.sql`。
