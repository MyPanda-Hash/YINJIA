# _other-slip-print-20261116 — 其他领料 / 其他退料 / 生产退料 的纸面报表

任务用户口径(2026-11-16,两轮合并):

> 「其他领料,其他退料和生产退料。都要可以打印报表。(这3个都是在提交的时候打印的,可以补打印。
>  其他领料和其他退料要有对应关系的二维码,方便手机扫码后补打印,或查询补打印)。
>  打印格式和生产领料一样,只是名称不同」

## 三种报表 → 面板 / 打印类型 / 纸面标题

| kind | 落库面板 | 打印类型(派单键) | 纸面标题 | 单号示例 |
|---|---|---|---|---|
| `OTHER_PICK` | `OTHER_OUT` 其他出库单 | `OTHER_PICK_SLIP` | 其他领料单 | `OO-2026-11-0005` |
| `OTHER_RET` | `MATERIAL_RET` 生产退料单 | `OTHER_RET_SLIP` | 其他退料单 | `TL-2026-11-0007` |
| `MAT_RET` | `MATERIAL_RET` 生产退料单 | `MAT_RET_SLIP` | 生产退料单 | `TL-2026-11-0008` |

⚠ 其他退料 与 生产退料 **落同一张面板**,只能靠 kind 区分标题与打印类型 ⇒ kind 必须跟着二维码走。

## 二维码 = 对应关系

内容 `YJSLIP:{KIND}:{单号}`,例如 `YJSLIP:OTHER_PICK:OO-2026-11-0005`。

- 印在纸面右上角(与生产领料单同一位置);
- 手机端**扫码框**扫到它 → 直接补打印同一张单(主扫框与「补打印」框都认);
- 与工单码(`0@工单号@1001`)、物料码(`存货编码|批号`)用**不同前缀**,解析分支互不干扰
  (单测里钉死:这两种码都不许被当单据码)。

## 补打印的三条入口

1. 提交成功 → 自动打一次(`queueToPrintStation`,没有电脑在线则浏览器打印层);
2. 手机扫码框扫**纸上的二维码** → 补打印(不用再找单号);
3. 页面底部「补打印」区手输单号 → 补打印;
4. (生产退料)领料单页抬头「退料单号」旁的「补打印」按钮 → 打最近一张退料单。

# 第二轮(同日):显示历史单据,扫码 = 查询

用户口径:

> 「显示历史单据,扫码相当于查询,和生产领料一样。」

## 改成什么样

页面结构照「生产领料」列表页:

```
[扫物料码 → 加清单 → 提交]        ← 开单区(不变)
────────────────────────────
查询单据          刷新
[扫单据二维码、输入单号或关键字] [查询]
扫码 = 查询:扫纸上的二维码可直接定位那张单，再点「补打印」
▼ 待审核 2
   OO-2026-11-0006   草稿
   2026-11-16  行数 1 · 数量 1
   —  admin 2026-11-16 11:44
   [补打印] [查看明细]      ← 展开后逐行显示物料/规格/数量
▼ 已作废 0
```

- **历史单据只列本页自己开的单**:后端按**备注前缀**筛(`扫码其他领料` / `扫码其他退料`)。
  不筛的话其他出库单里还有 ERP 同步来的 `QTCK-*`,而其他退料与生产退料又落在同一张
  `MATERIAL_RET` 上,现场会翻半天找不到自己刚提交的那张。
- **扫码不再是"扫了就出纸"**:扫到 `YJSLIP:` 码 = 按单号精确查询 + 高亮定位 + 自动展开所在分组,
  出纸要点该行的「补打印」。理由:纸放在桌上被扫到会白吐一张、还会把队列里真要打的那张挤掉。

## 后端新增

`POST /api/px/slip/list` `{面板, 备注前缀?, 关键字?, 上限?}` →
`{list:[{单据编号,单据日期,部门,创建人,创建时间,行数,数量合计,单据状态}], 条数}`

单据状态口径:`已作废` → `已审核`(有审核人) → `待审核`(pending='Y') → `草稿`。
⚠ 手机端「提交」走的是 `callButton 保存→提交`,落库后是 `saved='Y' / pending='N'`,
所以列表里显示为**草稿**(与「材料出库单草稿,请到材料出库单里审核」同一口径),
前端把它归进「待审核」组(仓管审核后才会变「已审核」)。
