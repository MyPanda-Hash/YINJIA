# 生产退料扫码 + 版面与生产领料对齐 + 扫工单码弹窗选组装/混料 — 2026-11-18

> 用户口径:
> 「生产退料也要可以扫码退料而且前端页面要和生产领料对齐,两个界面有差距,其他的扫码也要和领料对齐。」
> 「如果领料退料扫的是工单码,就要弹窗选择是混料还是组装。如果是领料单上的二维码就直接跳转。」

## 一、做了什么

| # | 改动 | 位置 |
|---|---|---|
| ① | **生产退料可扫码**:顶部加「扫码定位」行(扫领料单码 / 工单号 → 打开单据),扫到可退单直接进「退料作业」;不能退(未提交/未审核)给一句人话提示 | `MobileReturnList.vue` |
| ② | **版面与生产领料对齐**:同一套 48px 顶栏(标题 / 接口地址 / 说明 / 刷新)+ 灰底 + 「查询单据」卡(关键词查询 + 扫码定位 + 说明)+ 卡片式列表;物料行、按钮、命中区(≥44px)、等宽数字全部同口径 | `MobileReturnList.vue` |
| ③ | **扫工单码 → 弹窗选组装/混料**:新增 `PickKindDialog.vue`(大按钮列表,显示类型/单号/工单行/状态/物料项数);扫**领料单纸面二维码**(带 `@A`/`@M`)则**直接跳转**不弹窗 | `PickKindDialog.vue`、`MobilePickList.vue`、`MobileReturnList.vue` |
| ④ | **其他扫码页顶栏统一**:其他领料 / 其他退料 / 扫码混料 的页头改成与生产领料同一套(标题 + 接口地址 + 说明 + 灰底 + 卡片观感);工序报工本来就是这套,未改 | `MobileOtherScan.vue`、`MobileMixScan.vue` |
| ⑤ | keep-alive 回来也把光标放回扫码框(与"刚进入光标在扫码栏"同一口径) | `MobilePickList.vue`、`MobileReturnList.vue` |
| ⑥ | 新增文案补英文译名(选择要打开的单据 / 扫领料单码… 等 13 条) | `i18n/locales/en.js` |

新增纯逻辑:`business/mobilePick.js` 的 `locateQueryOf(raw)`(码 → 工单号/行号/领料标记,带单测)。

## 二、实测(ego 浏览器,5173 源码版,测试库 YJ_TEST)

| 场景 | 结果 |
|---|---|
| 生产领料:扫**工单码** `0@GD-2026-11-0010@1003` | **弹窗**「选择要打开的单据」,两条:组装 `LL-2026-11-0047`(物料项数 2)、混料 `LL-2026-11-0048`(5) |
| 弹窗里点「混料」 | 打开 `#/panelx/list/MOBILE_PICK/doc?id=857`(**混料单**) |
| 生产领料:扫**领料单纸面码** `…@1003@M` | 直接打开 id=857(混料),**不弹窗** |
| 生产退料:版面 | 顶栏「生产退料 查询单据 → 扫码定位 → 扫物料码 → 提交退料 刷新」+ 查询单据卡 + 可退单据卡,与领料同构 |
| 生产退料:扫 `0@GD-2026-10-0217@1010@A`(可退单 `LL-2026-11-0006`) | **直接选中该单**,退料作业区出现(可退项数 3) |
| 生产退料:扫一张未审核的单 | 提示「这张单还不能退:需要先完成领料、且材料出库单被仓管审核」 |
| 其他领料 / 其他退料 / 扫码混料 / 工序报工 / 生产领料 / 生产退料 | 六页顶栏结构一致(截图 `round-03-*.png`) |

前端单测 **2021 项全过**。
