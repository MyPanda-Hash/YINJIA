# 送料暂收单 / 来料检验单「验收造数」批次清理（2026-11-26）

> 用户口径：「又一批之前 10 月份系统生成的暂收单和检验单等单据（为了过验收的），占用了采购订单的生单，
> 但是实际并没用采购入库，我现在要在服务器上把它们删除掉」；补充：「还有 9 月份的，当时是有 Excel 表的，
> 不用删采购入库单」。

## 一、批次判定（怎么认出来的，可复算）

| # | 判据 | 实测 |
|---|---|---|
| ① | **审核时间恰为 `12:00:00`** —— 脚本批量审核的指纹（人工点审核不会整秒落 12:00:00） | 9 月 245 张、10 月 39 张，共 **284** 张 |
| ② | **暂收数量 = 采购订单行全量**（一张单吃满一整行） | 284/284 全量 |
| ③ | **下游没有任何采购入库单** | 0 张有 `采购入库单`（`来源单号 = SL-…` 命中 0） |
| ④ | 对照：10 月另有 13 张暂收单是**人工**录的 | 审核时间参差（11:41/14:44/23:02…）、数量多为部分量、其中 2 张已生成采购入库并转 ERP ⇒ **未动** |

两种账期对不上也印证了 ①：9 月 250 张里 245 张带指纹、另 5 张（`SL-2026-09-0001`~`0005`）是手工草稿，
10 月 52 张里 39 张带指纹、13 张人工 —— 指纹边界与人工边界完全吻合。

单号本身也是连续脚本号：`SL-2026-10-0083`~`0090` 一次生成，而 `SL-2026-10-0129/0130` 序号排在
10-12/10-13 那批之后，单据日期却回填成 10-05 / 10-13（**倒填日期**）。

## 二、执行通道（为什么只能这么做）

| 通道 | 状态 |
|---|---|
| `8090`（应用 HTTP API） | ✅ 通 |
| `5985/5986`（WinRM，部署脚本用） | ❌ 超时 |
| `1433`（SQL 直连） | ❌ 超时 |
| `3389`（RDP） | ✅ 通（未用） |

⇒ 只能走系统自己的按钮链：**弃审 → 删除**（`POST /api/px/callButton` 弃审、`POST /api/px/deleteForms` 删除）。
这条链正是业务口径：弃审会冲回库存台账/成本、级联处理下游；删除会把 `yj_doc_status.canceled='Y'`
并 `form_flow_link` 置 `RELEASED`（占用才能真正还给采购订单），同时把单据从列表里隐藏。
**这不是物理删表**：行还在库里（`asp_cancel`/`canceled` 标记），要物理清表得在服务器本机跑 SQL。

## 三、执行步骤

1. **先回弹检验目录**：8 张批次检验单挂在「检验数据记录明细表」`qc_catalog_detail` 上且状态是
   `已完成检验`，此时 `QcCatalogService.assertLinkedRowNotCompleted` 会挡住弃审。
   → `node reopen.mjs`（调 `callButton(QC_CATALOG, 修改, {编号:JYML-2026-10-0001, id})`），共回弹 **10 行**。
2. `node exec.mjs run cleanup-list.json`：逐张 `弃审`（已审核的）→ 删关联检验单 → `删除` 暂收单；
   草稿单直接 `删除`（不占库存、无下游）。
3. 逐张核对：`exec-log.txt` / `exec-result.json`。

> 弃审暂收单会**级联弃审**它生成的来料检验单（`ButtonService.slUnauditCascade`），这是名单里检验单
> 一并变成草稿的原因；随后再调 `deleteForms` 把检验单也作废。

## 五、刻意**没动**的（都写清原因）

| 对象 | 为什么不动 |
|---|---|
| **采购入库单 449 张** | 用户明确「不用删采购入库单」；10 月 83 张全部 `是否已转ERP=是`，动它会与金蝶脱链 |
| **暂收退回单 `TH-2026-10-0003 / 0005 / 0006`** | 这 3 张由批次检验单（不合格）自动生成、**已转ERP=是**（金蝶侧有真实退货单）。它们反过来挡住 3 张暂收单弃审 ⇒ 连带 `SL-2026-10-0121 / 0125 / 0127` 与 `IJ-2026-10-0205 / 0207 / 0208` **一并保留**。要清必须先到金蝶删退货单、再弃审转ERP |
| **检验数据记录 `JYSJ-2026-10-00xx`** | 用户只点到「暂收单/检验单」；记录单属实验室数据，未授权删除 |
| **10 月 13 张人工暂收单** | 人工录入、部分有采购入库并转ERP（`PI-2026-10-0034` / `PI-2026-10-0048`） |
| **5 张手工草稿 `SL-2026-09-0001`~`0005`** | 非批次（无 12:00:00 指纹、无明细），草稿不占订单 |

## 七、回滚

删除 = 软删（`yj_doc_status.canceled='Y'`），单据行仍在 `sl_recv` / `sl_recv_detail` / `qc_insp` /
`qc_insp_detail`。回滚不是「复原」而是「重做」：清掉 `canceled` 再逐张重新审核（库存/占用会按当时数据重算）。
弃审同时清了 `shr/shsj`，故不能只清 `canceled` 了事：

```sql
-- 仅示意，需在服务器本机执行（1433 对外不通）
UPDATE yj_doc_status SET canceled=NULL, cancel_by=NULL, cancel_at=NULL WHERE panel_code='QC_RECV' AND doc_no IN (...);
-- 随后在界面逐张「审核」回去（会重新写库存台账 + form_flow_link ACTIVE）
```

被删清单（单号/日期/状态/采购订单/物料/数量/批次/关联检验单）见 `deleted-docs.csv`（284 行）；
清理前的完整面板快照见 `QC_RECV.json` / `QC_INSP.json`。

> 注：弃审时 `form_flow_link` 是置 `RELEASED` 而不是删除行，所以占用链的历史仍可反查；
> 但为了让剩余量回到「未占用」，只清 `canceled` 不够 —— 必须重新审核一次让链路重新 ACTIVE。
