二、三处「在别处能跑、在本机必炸」的脚本修复(均实测复现后再改)
  · migrate-align-qc-col-fix-20260924.sql:
    ① qc_return_detail 本机只有 规格型号、没有 型号 ⇒ 直写 [型号] 让**整批编译失败**
       (SQL Server 对已存在表的缺列在编译期即报「列名 '型号' 无效」,同批合法语句一起不执行)
       → 改动态 SQL + COL_LENGTH 守卫;
    ② qc_insp_detail.[不良数量] 是**计算列** = ([不合格数量]) ⇒ 「不良数量 ← 不合格数量」必报
       「不能修改列…因为它是计算列」,反向则是死语句(两账套实测 0 行)→ 该批不再搬这两列。
  · migrate-qcreturn-srcfix.sql:数量列名按**血统二择一**(本机是「退货数量」,远端是「数量」),
    与 ButtonService.inspAutoReturn「按目标面板注册择一写入」同款口径;硬写任一名字都会在另一
    血统上编译失败。
  · migrate-spec-testlib-replace.sql:去掉**裸 `USE HSDZ_MES;`**,改 `IF DB_NAME() = N'master' USE …`
    守卫形式(DbSync 明令拦截裸 USE:连测试库跑时会静默把会话切到正式库,改错库且不报错)。

    (实测 HSDZ_MES 遗留 inh 仅 1 行、outh 0 行;CSV 见 archive/_legacy-*-backup-HSDZ_MES.csv)。
