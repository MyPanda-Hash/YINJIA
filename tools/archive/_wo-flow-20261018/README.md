# 生产工单「全流程推进」数据作业(2026-10-18)

## 用户口径(两轮确认后锁定)

> 「对当前的生产工单数据进行流转……**近 3 个自然日不处理**,其余工单**全部推进到结案**。」

- 近 3 个自然日 = `pl_date >= 今天-3`(执行当日为 `2026-10-15` 及以后)——**一行都不动**;
- 其余工单(`pl_date < 2026-10-15`)——**跑完全流程到已结案**;
- 两个账套**都执行**(`HSDZ_MES` 正式 / `HSDZ_MES_TEST` 测试)。

| 环节 | 落点 | 口径 |
|---|---|---|
| 排产 | `plang.scx`(末道组装线)+ `plang_pc` 镜像行(1:1,`plang_id` 锚点) | 报工 `gd_id` 的唯一身份 = 工单行 |
| 报工 | `scjl` × 3(成型/切炭/组装),`wgzt='Y'`,`[报工单号]=BG-ym-####` | 一道工序一张报工单;`gxdm` 存**工序名称**;`yj_doc_status` 写 `shr` 审核留痕 |
| 工序任务 | `wo_progress` × 3,`完成数量=计划数量`,`状态='已完工'` | 与 `scjl` 事实一致,排产看板「已报工」不再恒 0 |
| 检验 | `qc_asm_insp_head` × 1(带 **工单行号**+批次号+`合格数量=排产`)+ `qc_asm_insp_detail` × 2 | 结案判据要求它**已审核**(`yj_doc_status.shr` 非空) |
| 入库 | `bd_finish_in` + `bl_finish_in`,`加工单号=工单号`、`工单行号=工单行号`、`实收合计=排产`、`单据状态='已审核'` | 结案要求 `rk_sl ≥ pl_sl` |
| 结案 | `plang`: `rk_sl=pl_sl`、`rk_no=FI 单号`、`完工状态='生产完工'`、`当前工序='组装'`、`ja='Y'` | `PlangClose` 判据 = `ja∈(T,Y)` 且 `入库≥排产` ⇒ 列表显示「已结案」**且**「结案异常=N」 |

  但没有生成库存流水);如需库存同步,另跑 `tools/migrate-kucun-recalc-to-now-20261016.sql` 一类重算工具;
- **材料出库/领料**:结案不要求领料,保持原样;
- **`yj_usage_log` 留痕**:未刷「排产/结案」动作记录,工单追溯时间线仍只显示创建;
- 不改任何表结构、不改面板/字段/多语言(纯数据作业,无 i18n 交付项)。

## 用法

```powershell
cd tools
node archive/_wo-flow-20261018/_seed-wo-flow.mjs --db HSDZ_MES            # 预演(只打印计划)
node archive/_wo-flow-20261018/_seed-wo-flow.mjs --db HSDZ_MES --apply    # 执行
node archive/_wo-flow-20261018/_seed-wo-flow.mjs --db HSDZ_MES --verify   # 只读体检
node archive/_wo-flow-20261018/_seed-wo-flow.mjs --db HSDZ_MES --cleanup --apply   # 回滚
```

- 幂等:重复执行会因「已有本批标记」直接跳过;要重跑先 `--cleanup --apply`;
- 所有新建行 `asp_user1='wo-flow-20261018'`,回滚脚本 `rollback-<DB>.sql` 由脚本在落库前生成
  (逐行复位 `plang` 原值 + 按标记删单),已随本目录提交;
- 时区:`mssql` 默认 `useUTC=true`,本脚本显式 `useUTC:false` + 用 `CONVERT(varchar(10), pl_date)` 取日期,
  否则 22:00 的 `pl_date` 会漂到次日(报工日期/批次号跟着错一天)。

## 后续补丁:领料数据(2026-10-18 第二轮,用户报「一个个都没有领料数据」)

`_seed-wo-picking.mjs` 对**已结案**工单行补一张**已审核**的材料出库单(领料单):

| 项 | 落点 / 口径 |
|---|---|
| 单头 | `bd_material_out`:`加工单号=工单号`、`工单行号=plang.pl_xc`、业务类型=材料出库、出库类别=直接领料、仓库=A仓(原料辅料仓)、单据状态=已审核、前缀 **CL** |

## 后续补丁:首件/制程检验单(2026-10-18 第三轮,用户报「只有组装成品检验单」)

### ⚠ 明细必须按纸面模型写(2026-10-18 第四轮返工)

第一版只写了「检验项目」,漏了**报表矩阵的行键** ⇒ 打开首件检验单,纸面上每个样品格都是 `/`
(用户报障:「当前表格都没数据」)。两种纸面的真实模型(前端单一真源,别自创):

| | 首件检验单(`firstInspCols.js` / `QcFirstInspSheet.vue`) | 制程检验单(`QcProcInspSheet.vue`) |
|---|---|---|
| 形状 | **长表**:一行 = 行类型 × 样品序号 × 检验列 | **纵向表**:一行 = 一个检验项目 |
| 必填行键 | `行类型`(标准/样品)、`样品序号`(标准 / 1#..8#)、`检验列`(列键)、`项目分组` | `检验项目`、`检验要求`、`检验方法`、`产线常规功能性结果`、`结果判断` |
| 列集合 | 10 列:`表观及脱粉`(炭棒表观状态/脱粉) · `尺寸及重量`(外径/内径/长度/重量) · `强度`(跌落/挤压强度) · `浊度及压降`(浊度NTU/压降kPa) | 外观 / 尺寸-外径 / 尺寸-长度 / 重量 / 成型压力 / 成型温度 |
| 勾选列 | 表观、脱粉只填 **1#/2#**(`CHECK_SAMPLE_ROWS`) | — |
| 每张行数 | 10 × (1 标准 + 8 样品) = **90** | **6** |

修复脚本(按 单据编号 删明细后重铺,头/审核/单号不动,两账套各跑一次):
