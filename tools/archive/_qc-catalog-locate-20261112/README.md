# 待检验目录:查询 = 数据定位(2026-11-12)

> 用户口径:「待检目录查询有问题,应该做的是数据定位,因为他的所有数据都在一张单据里」

## 问题

`QC_CATALOG` 是 **singleDoc**(全部行都在同一张目录单 `qc_catalog_detail` 里),
而右侧「① 查找」给的是**单据级**三件套(查询单据 / 模糊搜索 / 单据预览)——
它们干的都是"在单据之间找单据",这里恒等于同一张单、完全没用。
顶部/右侧的「查询」弹窗提交后走 `search()` → 服务端按**表头**字段过滤 ——
而目录的行字段(检测物料类别/物料名称/批次号/检验状态/是否合格/单号)全在**明细行**上,
所以那个查询等于没查(用户看到的就是"查询没反应")。

## 改法

| 层 | 改动 |
|---|---|
| `QcCatalogSheet.vue` | 新增**行定位**:`applyLocate(conds)` 按各条件(包含、忽略大小写、AND)筛行 → 只留命中行 + 自动滚到第一行 + 闪一下(1.6s);纸头上加一条**定位条**(`数据定位 · 条件… · 匹配 N 行 · 清除定位 ✕`);空结果时的提示改成"没有匹配的行,点清除定位看全部";`clearLocate()` 复位 |
| `PanelxList.vue` | 新增 `isRowLocatePanel`(现役 = QC_CATALOG):①右侧 ① 查找 只留**「查询定位」**(点开同一个条件弹窗),隐藏 查询单据/模糊搜索/单据预览;②`applyHeaderQuery` 对这类面板**不再 `search()`**,而是把条件交给纸面定位并等命中数,提示「已定位 N 行」/「没有匹配的行…」;③`search()`(刷新/重置)顺手清定位与条件,回到全部待检验行;④顶部「查询」按钮的 tooltip 改成"按物料/批次等条件在本单的行里定位" |
| 多语言 | 新增 10 条文案(查询定位 / 数据定位 / 匹配 / 清除定位 / 已定位 / 两种"没有匹配的行"提示 …),10 语言静态包齐 |

匹配口径:**包含**(忽略大小写)+ 多条件 AND,空条件忽略 —— 与查询弹窗"留空即不限"一致;
全程**纯前端**,不重新取数(服务端本来就只会返回同一张目录单)。

## 取证(ego,测试库)

| 轮次 | 结论 |
|---|---|
| round-11 | 右侧 ① 查找 只剩「查询定位」;填 `批次号=20260922` 提交 → 表格只剩 1 行(白色无纺布100g/YJ-XWR-032/20260922),定位条「数据定位 批次号: 20260922 匹配 1 行」;点「清除定位」→ 回到 43 行 |
| round-12 | 填 `物料名称=折叠棉` → 5 行,提示「**已定位 5 行**」 |
| round-15 | 整页刷新后同一条流程:`匹配 5 行`、`is-hit` 高亮行 = 第一条命中(P 折叠棉/YJ-YCYX-020)、toast「已定位 5 行」 |

> 踩坑:第一版 `applyLocate` 是 async,`applyHeaderQuery` 里没 await ⇒ 拿到的是 Promise,
> 命中数恒判为 0、永远弹"没有匹配的行"(round-11 实测)。已改成 `await`(见
> `applyHeaderQueryAsync` 注释)。
