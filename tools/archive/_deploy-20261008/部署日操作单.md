## 2. 定 to-run 口径(本次唯一需要你拍板的点)

**口径 A(默认,推荐)= 全量 11 条**:什么都不用做。

**口径 B(保服务器现状、四单 3 条另议)= 只上仓位 8 条**:

```
copy /y to-run-20261008-whloc-only.txt to-run-20261008.txt
copy /y tools\db-migrations-whloc8.txt tools\db-migrations.txt
```

两个文件**必须一起换**:GO 第 4c 步的裸 sync 按 `tools\db-migrations.txt` 执行,只换 to-run 的话,
清单里有、台账没记的那 3 条四单照样会被裸 sync 补跑。改回口径 A = 把包再解压一次覆盖这两个文件。

**为什么要拍板**:开发机只读探针实测,**服务器四单与开发机不同代** ——
QC_INSP 的 `业务员` 在服务器是**文本**(基线是参照)、表头用 `单号` 而非 `单据编号`;
采购入库单还带着一批宽版字段登记(合同号/项目/外部单据号/资金批次/采购类型… 含 `供应商id`/`经手人id` 这类 id 列)。
这批登记出自链上种子脚本 `_doc_part2_meta.sql`(本机 2026-09-02 跑过),**开发机在 10-08 四单回正时删掉了它们**,
服务器还停在宽版。回正脚本对多出的行是 `DELETE` 后按基线重建 ⇒ 执行下去服务器那批列会消失。

按文档口径(唯一基线 = `docs/development/采购链四单字段与显示字段.md`)**应该对齐** ⇒ 默认 A;
服务器自己的列注释写着那批列「历史遗留、本表该列全空、无面板字段引用」,所以删错影响面小,
且**可逆**(pre-deploy 备份 + 重跑 `_doc_part2_meta.sql` 都能复原)⇒ 选 A 的代价可控。
选 B 则本包主功能(jar + 仓位体系)照样完整上线,四单留待后续单独处理。

## 3. GO(停机 1~3 分钟)

```
deploy-incremental.bat GO
```

预期 7 个 RESULT 依次出现:
`APP-STOPPED` → `BACKUP-GATE-PASSED` → `MIGRATIONS-OK` → `NEW-JAR-IN-PLACE` → `APP-STARTED` → `LOGIN-OK` → `ALL-OK`

自动顺序:停应用 → 备份库(`C:\yinjia\backup\pre-deploy-<时间戳>.bak`,失败硬停) → 按包内 to-run 逐条强制迁移
→ baseline 刷哈希 → 裸 sync 复核 → 换 jar(旧 jar 归档) → 起应用 → 登录探针。
任何一步不过即打 `RESULT: FAIL-*` 停止;详细输出在 `logs\deploy-<时间戳>.log`。

## 4. 复核(部署后)

```
cd /d C:\yj-deploy\tools
java -Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 -cp lib\mssql-jdbc.jar DbSync.java
java -Dstdout.encoding=UTF-8 -cp lib\mssql-jdbc.jar verify\FourDocAudit.java HSDZ_MES
sqlcmd -S localhost -d HSDZ_MES -E -h -1 -W -Q "SET NOCOUNT ON; SELECT COUNT(*) FROM bs_wh_loc WHERE ISNULL(asp_cancel,'')<>'Y'"
sqlcmd -S localhost -d HSDZ_MES -E -h -1 -W -Q "SET NOCOUNT ON; SELECT COUNT(*) FROM sys.columns WHERE object_id=OBJECT_ID('bs_wh_loc')"
certutil -hashfile C:\yinjia\app.jar SHA256
```

预期:DbaSync `执行 0, 失败 0, 跳过 429`（口径 B 下是「跳过 426」）;FourDocAudit `[PASS]`;
仓位 679;列数 38;certutil 等于包内 `SHA256SUMS.txt` 里 app.jar 那行(`ca386364…`)。

> 口径 B 提示:上面第一条裸 sync 按**已换过的清单**走,所以不会补跑四单 3 条(这正是要一起换
> `tools\db-migrations.txt` 的原因)。若你只换了 to-run 没换清单,裸 sync 会显示 `执行 3` 并跑掉四单批 —— 
> 那就不是口径 B 了;此时立即停手,用 pre-deploy 备份回滚库(或接受并对齐)。
