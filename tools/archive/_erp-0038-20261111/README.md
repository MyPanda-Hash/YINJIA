# 转ERP「单据已关闭不允许下推或商品需检验,请先生成收料通知」排查(2026-11-11)

## 现场(用户截图)

```
服务异常：转ERP失败: 金蝶接口失败: 请求接口返回失败:
不符合条件: 单据已关闭不允许下推或商品需检验,请先生成收料通知。
```

面板:采购入库单 `PURCHASE_IN`。用户口头指的是 `PI-2026-11-0038`(列表第 1 行高亮),
但**截图里真正打开的是 `PI-2026-11-0019`**(表头单据编号 + 页脚「第 13/331 张」+ 明细行
`YJ-HKB-001 黑卡载银炭粉 1000kg` 都是 0019 的)。

## 一、结论(三条,都有实测)

### 1. `PI-2026-11-0038` 其实**已经转成功了**,不可能再报这句

| 项 | 值 |
|---|---|
| MES `是否已转ERP` / `ERP单号` / 操作人 / 时间 | 是 / `CGRK-20261111-03675` / jxg / **2026-11-11 13:52:43** |
| 金蝶 `CGRK-20261111-03675` `create_time` | **2026-11-11 13:52:43**(秒级对上) |
| 金蝶 `remark` | `[MES:PI-2026-11-0038]`(MES 推送必带) |
| 金蝶行 | `YJ-YCYX-020 折叠棉 5057 支`,`src_bill_no=YJ-20261103-07`,`src_seq=1` |

**现场实测(只读、无副作用)**:对 0038 再点一次「转ERP」,服务端命中「已转」守卫**直接返回**,
根本没有打金蝶(`out-already-probe.txt`):

```json
{"code":200,"data":{"是否已转ERP":"是","already":true,
 "ERP单号":"CGRK-20261111-03675","转ERP操作人":"jxg","转ERP时间":"2026-11-11 13:52:43",
 "message":"该单据已转入ERP（ERP单号 CGRK-20261111-03675），不可重复转入；如需重新转ERP，请先「弃审」再「审核」"}}
```

⇒ 线上跑的版本**已含 11-09 的 `already` 守卫**(8090 前端引用 `erpOutcome-J4Iz2G1o.js`、
`PanelxList` 里有 `.already` 分支),所以「已转的单」点转ERP **永远拿不到金蝶报错**。
**那句报错不是 0038 产生的。**

### 2. 真正待转、且是截图里那张的是 `PI-2026-11-0019`,它的订单行**没关闭**

- MES:`PI-2026-11-0019`|2026-11-07|北京黑卡博 `YJ-HKB`|订单 `YJ-20261102-02`|来源 `SL-2026-11-0014`|
  行 `YJ-HKB-001 黑卡载银炭粉 1000kg`|`是否已转ERP` 空(**未转**)。
- 金蝶 `YJ-20261102-02`:头 `bill_status=C`、`bill_close_state=C`、`io_status=A`;
  第 1 行 `qty=1000 / in_qty=0 / un_out_qty=1000 / close_state=1`(**未关闭**)。

⇒ 「单据已关闭」那一半**对不上**(订单行是开的,也没被收过),所以只剩另一半:**商品需检验**。

### 3. 「商品需检验」= 金蝶商品档案勾了「来料检验」⇒ 必须先做「收料通知单」

金蝶云星辰的规则(官方/服务商文档口径):
**商品档案勾「来料检验」→ 采购订单必须先流转生成「收料通知单」→ 来料检验单 → 才能生成采购入库单**;
商品免检/无需质检才能由采购订单直接下推入库([来料入库质检介绍](https://help.njkingdee.com/docs/ye-wu-cao-zuo-7fRc)、
[采购订单下推入库为何提示该句](https://vip.kingdee.com/knowledge/649777516349109248?productLineId=35&isKnowledge=2&lang=zh-CN))。

账套实测旁证:

| 证据 | 值 | 含义 |
|---|---|---|
| `GET /jdy/v2/scm/pur_mat_rec_notice`(收料通知单) | `count=0`(**全账套一张都没有**) | 客户从来没走过「收料通知→检验→入库」这条链 |
| 商品 `YJ-HKB-001` 与这次转成功的 `YJ-YCYX-020` 档案差异 | 只有单位/分类/`is_batch`(HKB 是批次管理)等,**没有任何"检验"字段** | 星辰开放接口**不暴露**「来料检验」勾选框(质检模块字段),只能到金蝶界面看 |

⚠ MES 里的「是否来料检验=否」**只是 MES 自己的字段**,取自金蝶的**自定义字段**
`custom_field__1__62tvoyr1j4fa`(实测这两个商品该字段都是空值),**不参与金蝶的校验** ——
所以"MES 说免检、金蝶说需检验"是两边两套口径,不是矛盾,是没打通。
另:0019 这行 MES 的「送检数量」= **1000**(暂收单带来的),却同时标「来料检验=否」,口径本身就不一致。

## 二、要用户在金蝶界面确认的一步(接口读不到)

打开 金蝶 → 基础资料 → 商品 → `YJ-HKB-001 黑卡载银炭粉` → 看 **「来料检验」是否被勾上**
(同一位置还有「产品检验方式」)。勾了就是本例原因。

处置二选一:

1. **取消该商品的「来料检验」勾选**(与 MES 的"否"口径对齐)→ MES 直接再转 0019 即可;
2. **保留检验**:按金蝶流程先在金蝶做「收料通知单 → 来料检验单」,再出采购入库单;MES 侧这条链
   目前**没有**收料通知/检验单接口实现(`deploy/doc-endpoints.json` 未授权,`KingdeePushService`
   也没有 pur_mat_rec_notice 通道),要支持得单独开发。

`PI-2026-11-0038` **不要再点转ERP**(已在金蝶 `CGRK-20261111-03675`,去金蝶审核即可)。

## 三、顺带查清的另一件事:0038 把订单行"收满并关闭"了(超收 57 支)

| 金蝶 `YJ-20261103-07` 第 1 行 | 值 |
|---|---|
| 订单数量 `qty` | **5000 支** |
| 已入库 `in_qty` | **5057 支**(= MES 这张单 5057,超收 **57 支 / 1.14%**) |
| 未执行 `un_out_qty` | **-57** |
| `close_state` | **0 = 已关闭** |

MES 侧:采购订单行 5000 支 ↔ 送料暂收单 `SL-2026-11-0032` 5057 支(超送比例 20% 放行);
金蝶这次也放行了(写入成功),但随即把该行**自动关闭**。
⇒ 以后再往这一行下推(同一订单行出第二张入库单),金蝶就会回「单据已关闭不允许下推」——
**这是第三种"同一句报错"的来源**(11-11 上午 `PI-2026-11-0036` 是同一族:订单行 11-05 已收满)。

## 四、可改进(未实施,待确认)

1. **转ERP 推前预检**:`resolvePoRefs()` 已经拿到订单详情,顺带读 `close_state / in_qty / un_out_qty`,
   命中已关闭行直接给人话提示(「订单 X 第 N 行已入库 5057/5000 并关闭」),而不是把金蝶原文甩给用户;
2. **来料检验口径打通**:把金蝶「来料检验」勾选同步进 MES(现在那个自定义字段是空的),
   生单阶段就能提示"该商品金蝶要求走收料通知";
3. **并发闸门**:前端动作按钮全部没有 `:loading`,后端「是否已转ERP」守卫是推送前读库 ⇒
   连点两下会出现两个并发推送(第二发必然被金蝶按"源单已关闭/已下推"拒)。建议按单据号加锁或先占位。
   本次不是这个原因(0038 只有一次成功推送、金蝶只建了一张单),但闸门仍该补。
