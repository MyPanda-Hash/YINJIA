# 其他领料/其他退料「单据明细页」照「生产领料」补齐字段(2026-11-18)

> 用户口径:「还有其他领料和其他退料的单据和明细的显示信息(就是物料编码,名称,规格型号等字段)
> 要和生产领料一样,现在的单据表头和各行明细的信息太少了。仿照生产领料来写。」

## 一、改前 vs 改后

| | 改前(MobileOtherDoc) | 改后(照 MobilePickDoc) |
|---|---|---|
| 抬头 | 单据编号 / 状态 / 日期 / 部门(或领用人) / 创建人 / 数量合计 —— **6 行** | 单据编号 / 状态 / 日期 / **业务类型** / 部门(退料=领用人) / **经手人** / (仓库·工单号·来源单号,有才显示) / **审核人** / 创建人 / **创建时间** / **行数** / 数量合计 / **金额合计** / **备注** |
| 明细每行 | 「名称 · 编码·批号 / 规格·单位 / 仓库 / 数量」**挤成 4 列** | 名称 + **逐项成行**:物料编码 / 规格型号 / 计量单位 / 批号 / 仓库 / 明细备注;右侧「数量 + 单位」,有金额再加一行金额 —— 与生产领料明细行**同一个 `dl/dt/dd` 版式** |

## 二、改了什么

### 1. 后端 `OtherSlipController`(`POST /api/px/slip/rows`)

同一份取数**同时**给两种键,谁也不用猜对方的字段名:

- **纸面键**(打印代理读的,一个都没动):`材料名称 / 规格 / 单位 / 请领数量 / 实发数量 / 备注`;
- **页面键**(本次新增):明细 `物料编码 / 名称 / 规格型号 / 计量单位 / 批号 / 仓库 / 数量 /
  单价 / 金额 / 明细备注 / 序号`;抬头 `业务类型 / 经手人 / 审核人 / 行数 / 金额合计 / 备注`,
  退料再加 `仓库 / 来源单号`(空值前端隐藏)。

抬头取数补了列(都是这两张单据本来就有的):`业务类型 / 经手人 / 备注 / 审核人`(其他出库)、
`业务类型 / 仓库 / 来源单号 / 备注 / 审核人`(生产退料)。
**审核人优先取 `yj_doc_status.shr`**(本系统里谁审的),没有才回落到单据头那列(金蝶同步来的)。

### 2. 前端 `MobileOtherDoc.vue`

- 顶栏照生产领料:返回 + 单号/业务类型(副标题) + 状态胶囊 + 「打印」;
- 抬头卡片用 `.mod-kv`(标签 76px + 值),缺值一律显示 `—`(不省略行);
- 明细行 `.mod-line` + `.mod-line-fields`(grid 68px + 1fr),右侧 `.mod-line-qty` =
  「数量 + 单位」/「金额」;字段键**新旧都认**(`数量` 缺了就退回 `实发数量`,`规格型号` 缺了退回 `规格`);
- 打印逻辑一行没改(仍是 `printSlip` → 打印站点/本机打印兜底)。

### 3. 顺带

- `android/build.ps1`:`1.0.20` → **`1.0.21`(versionCode 22)**,整站前端重打 —— 手机上要看到本页改版必须换包;
- 静态产物与 jar 已同步(8090 现在的静态就是新版)。

## 五、注意

- **手机要看新页面必须换 APK**:`android/dist/yinjia-mes-1.0.21.apk`(同 debug 签名、versionCode 22,
  可直接覆盖安装)。网页端(5173 / 8090)刷新即可。
- 这两张单据是金蝶键集克隆的,**没加列、没改面板元数据** —— 只是把表里已有的字段显示出来,
  所以不涉及数据库迁移,也不影响「采购链四单」基线。
- 明细里的 `请领数量` 仍恒为 0(不挂工单,没有"该领多少"),纸面那一列保持空白,与本页的「数量」不是一回事。
