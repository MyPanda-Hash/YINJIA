# 采购入库单「多仓库入库」取证包(2026-11-17,最终版)

## 一、客户口径(原话,三轮定稿)

> 第一轮:「采购入库单在草稿状态下要可以实现一个明细划分多个仓库来存放」
> 第二轮:「不要设置成这样,可以在仓库选择时多个按钮,实现多选仓库弹窗」
> 第三轮(定稿):「写法还是改成有个多仓库入库按钮(在顶部)。点击后和生单一样的界面。
>   然后每行明细的头部有个下拉扩展的倒三角,点一下就多出一行明细来。但是总数量不超过最大数量。」
> 全程附加:「来源采购订单行号和上游的行号不变」。

前两轮的做法(① 操作列拆分图标 + 拆分弹窗 ② 仓库格子多选弹窗)都已按用户口径**删除**,
现在只有一条路:工具栏「多仓库入库」。

## 三、验证(测试库 HSDZ_MES_TEST,ego 浏览器)

单据 **PI-2026-11-0008**(草稿,2 行 YJ-XH-002 各 30:恒亿仓 / 成品B仓):

1. 打开单据 → 工具栏出现 **多仓库入库**;
2. 点开 → 整单明细表(和生单同款),每行前面有 ▾;
3. 第 1 行点 ▾ → 多出一行子行(默认带原仓库 + 整行数量);把数量改成 20;
4. 再点一次 ▾ → 第二行子行(仓库空),选「成品B仓」、数量 10;
5. 行尾显示 `已分配 30 / 剩余 0`,底部 `要拆分的行: 1 · 拆出来: 2 行`,确定可点;
6. 确定 ⇒ 服务端拆行,明细变成 3 行,DB 核对:
   `1252 恒亿仓 20` / `1270 成品B仓 30`(原第 2 行未动)/ `1271 成品B仓 10`;
   三行 `批次号 20261113`、`批号 20261113002` 完全一致。

**校验实测**:第二行子行没选仓库时,底部红字「第 2 个仓库子行还没填仓库或数量」+ 确定置灰;
合计超过可入库数量时提示「该行各仓库数量合计不能超过可入库数量」;
只填一个仓库子行时提示「同一行要拆至少两个仓库:再点一次 ▾」。
