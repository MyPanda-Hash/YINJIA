# 「生产车间」统一成标准库 mold.workshop（2026-11-06）

## 用户口径

> 「把烧结工艺清单的生产车间换成和X烧结工艺清单的生产车间的内容一样，
> 再把这两个做成标准库可以更新维护，标准库是可以增加，删除的」

## 改前 / 改后

| 位置 | 改前 | 改后 |
|---|---|---|
| 烧结工艺清单 · 工艺清单页 `RD_MOLD_PROC.生产车间` | 参照 **DEPT**（部门档案：烧结车间/组装车间…） | 标准库 `mold.workshop`（1#~7#） |
| 烧结工艺清单 · 成型配方页 `RD_MOLD_FORMULA.生产车间` | 参照 DEPT | 同上（**同一张单的两个页签，必须一起改**，否则切页签看到两种下拉） |
| X烧结工艺清单 `RD_X_SINTER.生产车间` | 下拉框，dict_sql 里写死内联 `VALUES ('1#'..'7#')`（内容对但不可维护） | 标准库 `mold.workshop` |

- 标准库条目：`yj_std_lib` 里 `lib_code='mold.workshop'`，7 条（`item_code='默认'`，`content` = `1#`…`7#`），
  与 `asm.form`/`prod.form` 同构 —— 前端因此自动出现下拉 + 「⧉ 标准库维护」入口。
- 维护能力（StdLibManager，生产实测 `标准库维护 · mold.workshop` 弹窗）：**加入标准库 / 编辑 / 停用 / 恢复启用 /
  关闭** —— 增删改都不碰元数据、不发版。
- 数据：两张头表的 生产车间 实测为空/NULL，无需回填；历史值（如某单上的 `D05`）按原文本保留并照常显示
  （下拉是 filterable + allow-create，不会把旧值冲掉）。
