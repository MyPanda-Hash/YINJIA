# 组装物料清单:产品编码改手输 + 工序移出表头(2026-11-04 晚)

一次性取证目录。对应需求(用户 2026-11-04 18:34 截图,两处红框):

> 「这个产品编码要可以自己编辑,且当前的工序都为组装的 bom 不需要设定工序了。」

## 问题

上一轮(同日下午)把 ASM_BOM 表头做成可维护时,给两处做了「更聪明」的默认,但现场不要:

1. **产品编码**登记成「参照存货档案(INV)」—— 只能弹窗/下拉选,不能直接敲编码;
   而现场有些产品编码不在存货档案里,或手输更快 ⇒ 用户要求「可以自己编辑」。
2. **工序**是表头必填下拉(组装/成型/切炭) —— 但现有 236 张 BOM 全部是「组装」,
   新建也只会是组装 ⇒ 用户要求「不需要设定工序了」。

## 修复(纯元数据 + 一行脏数据回填;**零 DDL、零代码改动**)

迁移脚本:`tools/migrate-asm-bom-product-manual-20261104.sql`(两账套已执行,`[OK] 10 batches`)

| # | 改什么 | 改成 |
|---|---|---|
| §1 | `yj_field.产品编码` | `data_type` 参照 → **文本**;`ref_panel/ref_field/display_field` 清空;保留 `editable=1 / required=1`(手输但必填) |
| §2 | `yj_field.工序` | `place` `query,header` → **`query`**(从表头网格移除,**保留查询条件**);`editable 1→0`、`required 1→0` |
| §3 | `yj_panel.config.headDefaults` | 增加 `"工序":"组装"`(与原有 `"状态":"启用"` 合并)⇒ **新建 BOM 自动写 工序=组装** |
| §4 | `bs_asm_bom.工序` 空值行 | 回填为 `组装`(正式库 2 行,均为「新增」产生的空草稿占位行) |

为什么用「place 只留 query」而不是 `hidden=1`:前者从表头网格与前端必填校验里自然消失,
但「查询」弹窗仍能按工序筛选(将来成型/切炭同表追加时有用);后者会把查询条件一起隐藏。

⚠ **迁移顺序**:本脚本必须排在 `migrate-asm-bom-maintainable-20261104.sql` 之后。
整链重放按清单顺序自然收敛到当前设计;但**不要单独重跑 maintainable 那条** ——
它会把产品编码改回参照、把工序加回表头。
