# 采购订单打印:送货单改名 + 有金额版签章框带入/弹窗选需方联系人(2026-11-11)

> 用户原话(2026-11-11):
> 「1.打印无金额的采购订单报表名字改为送货单。送货单下方不需要写供方和需方。
>  2.打印有金额的采购订单,下面的供方单位名称带入供应商名称。还有需方的联系人和联系方式改为打印前先弹窗。
>  下拉选择名字和联系方式。可以新增」

## 一次做完了什么

| 需求 | 落地 |
|---|---|
| 无金额版报表名 → **送货单** | 纸面 `<h1>送货单</h1>`(原「银嘉采购订单」),打印层文档名也改成 `送货单-<单号>` |
| 送货单下方**不写**供方/需方 | 整块 `.sign` 签章框不产出(不是隐藏,是没有这段 HTML) |
| 有金额版**供方单位名称带入供应商名称** | `供方 · 单位名称：<本单供应商>`(以前恒留空手填) |
| 需方**联系人/联系方式**改**打印前弹窗** | 有金额打印弹窗顶部加两个下拉(`需方联系人` / `联系方式`),选名字自动带出电话 |
| **可以新增** | 填了名单外的名字/电话 ⇒ 点「确定并打印」时自动存进系统参数,下次打开下拉里就有 |

## 关键设计

1. **候选名单存哪**:系统参数 `yj_app_setting.pu_order.buyer_contacts`,格式 `姓名|联系方式;姓名|联系方式`。
   不建表、不建面板 —— 它只是"打印时填哪个人"的候选,改一处全公司生效;参数表本来就承载这类运行期小配置。
   库里没有该参数时,代码**回落**到历史默认值(孙郝聪 / 13718162430),老纸不变。
2. **为什么弹窗而不是纸面手写**:用户要"打印前先弹窗、下拉选择、可新增" ⇒ 值必须在**出纸前**定下来,
   而报表打印又不落单(没有"需方联系人"这种单据字段可存)。所以走"弹窗选值 → 传给出纸函数"这条路,
   名单单独存参数,纸面纯粹按传进来的值印。
3. **送货单不印签章框**:用户口径是"不需要写供方和需方" ⇒ 直接不生成该块(连 CSS 都不落地),
   避免"打了但内容空着"这种半吊子形态。
4. **纸面标题不进翻译表**:`送货单` / `银嘉采购订单` 是**单据模板抬头**(与既有「银嘉采购订单」同口径),
   属固定中文,不随界面语言变(ADR-0001 的分层:数据/模板不翻,只为界面词条翻)。
   弹窗里的「需方联系人」「联系方式」等**字段标签**按规范补了 `yj_translation` 10 语言。

## 踩坑记录

- 取证脚本第一版按"caret 菜单里点「打印采购订单」"找，结果下拉里只有 `预览/导出/打印订单无金额/打印材料码` ——
