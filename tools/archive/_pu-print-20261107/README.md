## 打印记录口径(与材料码的区别)

| | 材料码(`bd_pu_label`/`bl_pu_label`) | 报表打印记录(`bd_pu_print`/`bl_pu_print`) |
|---|---|---|
| 一张单代表 | 一个批次号 | 一次打印(哪几行 × 各自数量) |
| 是否占用订单量 | **预约**,作废释放 | **不占用**,作废只软删这张纸 |
| 重打 | 打印次数 +1 | 同 |
| 面板 | 不建(弹窗反查) | 不建(弹窗反查) |
| 单号前缀 | `MQ-yyyy-MM-nnnn` | `MP-yyyy-MM-nnnn` |

小计口径:数量**没改** ⇒ 沿用订单原金额(折扣/整单分摊不会被打印抹掉);改了 ⇒ `单价 × 本次数量`(4 位小数)。
落纸「备注」列取订单行备注(该字段此前未进 `yj_field`,纸面恒空;现在随快照带上)。

## 打印数量按超送封顶(2026-11-09 用户口径)

> 「打印的时候没有和材料码一样考虑到超送问题」→ 补完后用户再要求:「和材料码一样,这些都要有」
> (截图圈出材料码弹窗的 `订单数量 / 已送 / 已打印 / 剩余可打 / 本次打印数量`)

材料码弹窗的「剩余可打」带超送;采购订单打印弹窗原来对「本次打印数量」**没有任何上限**。现与材料码**完全同口径**:

| 项 | 口径 |
|---|---|
| 剩余可打 | `订单数量 + floor(订单数量 × 超送比例, 单位精度) − 已送 + 已退回 − 已打印`,负数归 0 |
| 已送 / 已退回 | `BatchService.sentByLineKey / returnedByOrderLine` —— 与材料码弹窗同源 |
| 已打印 | 本订单该行**存活打印记录**的打印数量合计(`bl_pu_print` 作废不算);等价于材料码的「已打印预约」—— 打过的量已划走,要原样再出一张用「重打」 |
| 超送量取整 | 按该行**计量单位精度向下取整**(个/卷=整数、kg/米=3 位),与材料码/生单同一个 `BatchService.overAllowance(..., decimals)` |
| 前端 | 弹窗列:订单数量 / **已送** / **已打印** / **剩余可打** / 本次打印数量;默认填 **剩余可打**;输入框 `max=剩余可打`、精度=单位小数位,改完向下取整并夹到上限;「按剩余可打填充」按钮一键复位 |
| 后端 | `GET /px/puPrint/quotas?orderNo=` 下发每行(已送/已退回/已打印/剩余可打/小数位数/超送比例);`puPrint/print` **强制校验** `数量 ≤ 剩余可打`,超出报「第 N 行:本次打印 X 超出剩余可打 Y(订单数量 Q ×(1+超送比例 R%)− 已送 S + 已退回 T − 已打印 P…)」 |
| 供应商面板 | 同一弹窗同一口径;`SupplierPortalGuardFilter` 放行 `/api/px/puPrint/quotas`(仍按逐单归属校验) |

实测:

- `YJ-20261105-01`(超送 20%):`2000 → 剩余可打 2400`、`3500 → 4200`,弹窗默认填 2400/4200;超送改成 15% 时接口给 `2300 / 4025`(与用户截图一致,两边同读 `receive_over_ratio`);
- 直连接口超上限 → `400 本次打印 X 超出剩余可打 Y(订单数量 Q ×(1+超送比例 R%)− 已送 …)`,不落打印记录;
- 证据:`ego/round-48/49/50`、`round-50-print-quota-cols.png`。

## 超送量按计量单位取整(2026-11-09 用户口径)

> 「超送要去整」→「要根据单位确定超送是否需要小数,如果需要小数要确定位数」

原实现直接 `数量 × (1 + 比例)` 算浮点数:24 个 × 1.2 − 24 = **4.799999999999997**、12 个 → 2.3999999999999986,
计件单位出现"半个"上限,还带浮点尾数。现改为:

| 步骤 | 口径 |
|---|---|
| 精度来源 | ① `bs_uom.[小数位数]`(金蝶同步:个/卷/张/支/PCS = **0**,kg/米 = **3**);② 取不到时按单位名兜底:计件单位(个/只/张/条/支/片/卷/套/台/件/包/箱/桶/瓶/盒/根/份/次/PCS…)= **0**,计量单位(kg/g/吨/L/ml/米/cm/mm/㎡/m³…)= **3**,都不认识 = **2** |
| 取整方向 | **向下取整**(上限只少不多):24 个 ×20% ⇒ 超送 **4** 个(收 5 个就是 20.8%,已超比例) |
| 落地位置 | 后端 `BatchService.overAllowance(..., decimals)`;`PushGenerateHandler.batchRows`(可送上限)、`VoucherFlowService.sources`(选单)、`PuLabelService`(打印材料码「剩余可打」「可补打」+ 打印校验)、前端 `overAllowance`(分批送料弹窗即时预览)—— 四处**同一函数口径** |
| 显示/输入 | 服务端逐行下发 `小数位数`;弹窗输入框精度跟单位(计件不能填 0.5 个);已送/已打印等**实际数量**用四舍五入(`roundTo`),上限/剩余可打用向下取整(`floorTo`) |

实测(订单 `YJ-20261012-11`,单位=卷,订单 24/12 已全送):

- 修复前:剩余可打 **4.799999999999997** / **2.3999999999999986**;
- 修复后:剩余可打 **4** / **2**,本次打印数量输入框也只能填整数;
- kg 行(`bs_uom` 精度 3):`YJ-20261012-01` 304.6kg 返回 `小数位数=3`,上限与剩余可打都按 3 位;
- 后端接口 `batchFlow/lines` 同样返回 `可送上限 4.0 / 2.0` 与 `小数位数 0`。

## 口径说明(为什么打印不写回订单)

「打印材料码」弹窗要**落库**(批次号权威登记 + 预约数量);采购订单报表只是把已保存的订单打出来,
勾选与数量若写回会绕过保存/审核链路。故打印记录只存**快照**(以后重打按快照原样出纸),
订单上一个字段都不动 —— 弹窗顶部那句话就是口径本身:
「勾选要打印的明细行，并填写本次打印数量；只影响这张报表，不改动订单数据」。
