## 该单究竟多出来哪一行(生产库实测)

## 根因

「自定义检验要求」页签在 2026-10-04 随面板拆分下线(`tools/migrate-qc-insp-req-drop-custom-tab.sql`):

但这 4 行是 **2026-10-14 21:43:53** 由 `admin` 落进来的(晚于下线),类别仍写着已下线的值,因而留在了现役 17 个页签之外:

| id | 物料编号 | 物料类别 | 现役页签命中 |
|---|---|---|---|
| 89 | YJ-XH-001 | 自定义检验要求 | 另有 1 行(另有炭粉可显示) |
| 90 | YJ-XH-002 | 自定义检验要求 | 0 行 → 弹窗显示「该物料未维护来料检验要求」 |
| 91 | YJ-YKRS-009 | 自定义检验要求 | 同上 |
| 92 | YJ-YKRS-014 | 自定义检验要求 | 同上 |

本地正式库(HSDZ_MES)同 id 同样存在,另有 1 行同类已作废行,合计 5 行。

## 影响

1. 弹窗**看不到**这行;**维护面板(来料检验要求)也永远看不到**(没有页签承载它);
2. 但「带入检验要求」**会**把它带进报告 —— `qcInspReqCarry.js` 对归类外的组走 `fallbackColsOf()`,
   按行自身字段名当检验项 ⇒ 报告里会冒出「外径=按图纸」「内径=按图纸」等 9 条,
   形成"弹窗看不见、报告带得进来"的不一致;
3. 只命中这一行的物料(YJ-XH-002 / YJ-YKRS-009 / YJ-YKRS-014),弹窗直接说「该物料未维护来料检验要求」,
   比这条黄色提示更误导(行其实在库里)。

# 追加需求(2026-11-06 同日第二轮):弹窗里也要能「带入检验要求」

用户原话:

> 还有检验数据记录根据物料带入的数据,只有再草稿的时候才可以带入。

## 口径落地

- 「保存后」在这套系统里**仍是草稿状态**(`yj_doc_status`:`saved='Y'`、`shr/pending` 为空 ⇒ 单据状态=草稿),
  所以判定统一成 **可带入 = 本单可编辑**(`editable` = 草稿 / 修改中),不另立一套状态表 ——
  与表头那个「⧉ 带入检验要求」**同一真源**(PanelxList 的 `draftEditable`)。
- 提交审批(审批中/待二级审批/会签中)、已审核/已归档、已作废/中止:按钮**置灰**并给出原因;
  弃审退回草稿后自动恢复可点(不需要刷新、不需要改配置)。
- 弹窗页脚新增 `⧉ 带入检验要求`(+ 关闭),真带进来了才关弹窗,让用户直接看到表体。

## 改动

  页脚按钮 `:disabled="!canCarry"`,不可用时旁边显示原因。
- `QcInspRecSheet.vue`:把弹窗接上 `:can-carry="editable"` + `@carry="onDialogCarry"`;
  新增 `carryBlockedHint`(按 `单据状态` 给具体原因:审批中→请先驳回或弃审、已审核→请先点「弃审」、

## 8090(本地打包实例)为什么看不到按钮 —— 已修并验证

用户 2026-11-06 报「带入按钮在哪,我在本地也没找到」,截图地址是 **127.0.0.1:8090**。

- 根因:**8090 的前端在 jar 里**(`BOOT-INF/classes/static`),只在打包/换 jar 时变化;
  当时 jar 的 `index.html` 指向 `assets/index-BAMtJVFY.js`(旧),而新构建是 `index-BErWVBjm.js`。
  上一轮我只把前端同步进仓库(并提交 `backend/src/main/resources/static`),没有换 jar、没重启,
  所以 8090 上自然没有按钮 —— **5173 上一直是新的**。
- 处理:`npm run build` → 同步 static → `start-prod.ps1 -Stop` → `jar uf target\yinjia-mes-backend-0.1.0.jar
  -C <stage> BOOT-INF` → `start-prod.ps1` 重启。现入口 = `index-BErWVBjm.js`。
- 验证(round-20.mjs + round-20-8090.png,ego 浏览器直连 8090 并登录正式库):
  草稿单 JYSJ-2026-10-0077 弹窗页脚出现「⧉ 带入检验要求」(可点),与 5173 一致。
- ⚠ 浏览器缓存:换 jar 后旧 `index.html` 可能还在缓存里,要 **Ctrl+F5** 强制刷新才看得到。
- ⚠ 启动日志里 `[ERROR] DB sync failed` 是既存的 2026-11-02 清理脚本闸门(见上文「环境现状」),
  与本次改动无关,不阻断启动。

⚠ 顺带确认(不是 bug):草稿单**打开时**若表体为空,`物料编码` 变化会触发 600ms 去抖的**自动带入**
(2026-10-04 口径,只补缺失项) —— 所以很多单"打开就已经有检验项了",弹窗里的按钮主要用于
"要求表后来补了项,在已保存的单上再补一次"。
