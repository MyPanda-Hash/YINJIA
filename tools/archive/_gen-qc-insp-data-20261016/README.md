# 造一批「来料检验单」，让质检看板不再是假的 100%(2026-10-16)

用户口径:「质检方面的模块看板……原公司没有上传检验单据，所以这些只能自己写一些，现在 **100 的合格率太假了**」
→ 选定 **近 30 天、约 90 张、合格率 ~97%、两个账套都写**。

## 现状(为什么是 100%)

`DashboardStatsService.quality()` 取 `qc_insp_detail` 的 `送检数量 / 合格数量 / 不合格数量` 求和。
导入的公司数据里 `qc_insp` 只有 11 张、明细只有 **1 行填了数量**(IJ-2026-09-0152 送检 100 / 合格 100 / 不良 0)
⇒ 看板恒 100%;其余 5 行三列全空、11 张单的 `总结论` 也全空。
另外项目口径:`暂收单→检验单` 的生单只对 `bs_inv.来料检验='是'` 的 **9 个物料**生效,
且 118 张已审核暂收单里 115 张已被检验链占用 ⇒ **造数只能「新增」检验单**,不能靠生单批量产出。

## 口径(怎么造的)

| 项 | 取值 |
|---|---|
| 单据 | 90 张/账套,单据日期铺在最近 30 天(2026-09-16 ~ 10-15) |
| 明细 | 1~3 行/单,物料取 `bs_inv.来料检验='是'` 那 9 个真实物料,数量 500~12,000(与真实暂收单同量级) |
| 供应商 | 取自真实暂收单(`sl_recv`),30 家 |
| 检验员 | 真实账号姓名(彭于晏/陈秀丽/刘磊/柴善银/冯敏) |
| 不良分布 | 约 1/3 的单有零星不良(1%~15%),处置方式 挑用/让步接收/退货/特采/降级使用,**整体合格率收敛到 97.00%**(含存量口径) |
| 表头 | 单据日期 / 供应商(+代码) / 检验员 / 检验日期 / 检验方案 / 执行标准 GB/T 2828.1-2012 / 检验类型=来料检验 / 总结论 / 备注 |

**走平台接口**(`新增` → `保存`),所以单号来自号池、字段走面板校验,与手录完全一致 ——
不是裸写库(裸写会像导库那样绕过应用副作用,见 `../_kingdee-reimport-20261016/README.md`)。

> ⚠ **有意不审核**:检验单审核会按既有链路**自动生成采购入库单草稿**(`ButtonService.inspAutoPurchaseIn`),
> 90 张检验单会凭空多出 ~90 张采购入库单草稿、把刚核对好的 `PURCHASE_IN` 计数搅乱。
> 看板按明细行统计、不看单据状态,保持草稿即可达到目的。要审核:跑 `--audit`(自担上述副作用)。

## 踩到的四个坑(别再踩)

1. **保存必须带 `编号`**:`新增` 返回的键是 `编号`,只传 `单据编号` 时保存会**另起一张单** ——
   第一版就这样留下 90 个空壳头(见 `cleanup-empty-qc-heads-20261016.sql`)。
2. **`新增` 会给骨架行写一条 `yj_doc_status` 留痕**(saved='Y')⇒ 清理时**不能**拿「没有留痕」当守卫。
3. **同号遮挡**:骨架行与已存在单据同号时,「按单号 `NOT EXISTS(明细)`」判不出空壳
   (明细按单号关联)⇒ 判据要用「**总结论与检验员都空**」。
4. **号池落后于导库数据**:`FormNoService.next()` 只看 `s_allno` 自身 + `inh`,`exists()` 不查业务表 ⇒
   本地 IJ 池末号是 0100 而库里已有 0011~0020 时,`新增` 会**连发重号**(实测第一版连撞 10 个)。
   修法见 `../_kingdee-reimport-20261016/backfill-formno-pool-imported.sql`(把导入单据号回登号池)。

## 本次没做的两件事(要就说)

- **检验数据记录(`QC_INSP_REC`)与检验项目目录(`QC_INSP_REQ`)没造**:质检看板不读它们;
  要给这批单补,可参考 `tools/archive/_fill-qc-insp-1014.mjs` 的写法(它只覆盖写死的 8 张单)。
- **检验单保持草稿**:要变成「已审核」需连审核一起做,副作用见上(会生成 ~90 张采购入库单草稿)。
