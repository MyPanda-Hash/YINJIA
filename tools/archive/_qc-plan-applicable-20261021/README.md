# 检验标准库按单据分套 + 组装成品单置顶「外观、尺寸、重量」（2026-10-21）

## 用户口径

> 「当前组装检验单的各个单据的检验项目高度雷同需要对这个进行差异化修改，并且增加几条检验项目中的
> 检验标准库，最顶上填写一条检验项目为外观，尺寸，重量的标准库项目。」

用户拍板：**标准库按单据分套**；置顶那条 = **一个方案，下挂 外观 / 尺寸 / 重量 三个项目**。

## 落地

1. `bs_qc_plan` 新增 `适用单据`（逗号分隔面板代号 `QC_FIRST_INSP` / `QC_PROC_INSP` / `QC_ASM_INSP`；
   空 = 未归档，默认不混进任一单据）。`migrate-qc-plan-applicable-doc-20261021.sql`。
2. 四套方案 / 18 条项目种子：
   - `QP-ASM-00` 组装成品检验方案（外观、尺寸、重量）—— 编码升序置顶，下挂 外观/尺寸/重量 3 条；
   - `QP-ASM-01` 组装成品性能（抗压强度/初始流速/压降/余氯去除率）；
   - `QP-FIRST-01` 首件（外观/尺寸/重量/抗压强度/浊度）；
   - `QP-PROC-01` 制程（外观/尺寸/重量/初始流速/压降/余氯去除率）。
   - 旧 `QP-CAS18` / `QP-YCAS23` 不删、不填适用单据，只在「显示全部单据」里维护。
3. 后端 `/api/qc/inspPlan/plans` 支持 `panelCode` + `docScope=all`；`planSave` 保存 `适用单据`。
4. 弹窗默认只列本单适用方案；新增「显示全部单据的方案」开关、「适用单据」列与多选表单。
5. 带入明细时**项目自己的「检验内容」优先于方案合并类型** —— 否则置顶方案三条会被
   `normInspType` 全部归一成「外观」。

## 验证

- 两账套（HSDZ_MES / HSDZ_MES_TEST）`DbSync run` 均 `[OK] 8 batches`，复跑幂等。
- 正式/测试库 `QP-ASM-00` 均 3 条项目，`检验类型 = 外观、尺寸、重量`。
- 临时后端 8091（测试库）+ 临时 Vite 5174 的 CDP 探针 **8/8**：
  - 组装单弹窗只剩 2 套组装方案（QP-ASM-00 / QP-ASM-01），首行 QP-ASM-00；
  - 方案表「适用单据」列显示「组装成品检验单」；
  - 勾「显示全部单据的方案」后 7 套（测试库含 QP-CARBON-ROD）；
  - 项目表 3 条 = 外观 / 尺寸 / 重量；
  - 无未捕获运行时异常。
- `mvn -DskipTests compile`、`npm run build`、前端单测 6/6 通过。

## 约定

- 检验单明细是**文本快照**：改标准库不会改动已录入单据；存量 `ZJ-*` 单里雷同的「目数」行
  未做批量替换（按产品猜项目改库等于造假数据），需要换项目的单据由品质在单上重新「带入明细」。
- 方案「适用单据」为空 = 未归档，默认不显示；维护时勾「显示全部单据的方案」。
