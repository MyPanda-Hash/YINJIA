# 角色字段视图（`yj_field_view`）— 实现与验证归档（2026-11-13）

## 一、用户口径（本次唯一的验收标准）

> ① 「不同的角色可以同一面版可以自己调整单据的字段……每个角色都可以独立看到不同的字段」
> ② 「两层就够了，从系统到角色的定制，不用在角色下单独区分账号，同一角色看的是一样的」
> ③ 「没有保密的诉求」
> ④ 「要保留原来表格调整的功能不变，并且确保现在做的调整不会回退。然后定制的表格调整是在原来表格调整的基础上，再做修改的显示或者隐藏」

因此：**系统整体（`yj_field`，原「表格调整/表头调整」照写不误）→ 角色（`yj_field_view`，只存显隐）**，
同一角色所有账号共用一套，不做个人层，不做字段级权限。

## 五、实现要点（踩过的坑）

0. **打包版与源码版的差距**：13:56 有人重打过一版 `app.jar`，那一版里 `enabled` 判据还是错的（见下条），
   8090 于是"有功能但对谁都查不到角色"。用 `tools/scripts/rebuild-prod.ps1 -SkipFrontend` 重打包重启后，
   `jar` 内 class 与 8090 接口均恢复正常（`_smoke-8090.mjs`：`roleCode=admin / roleName=管理员 / 24 表头行 / 49 明细行`）。
   ⇒ **改完后端之后，别只看源码实例，拿 jar 里的 class 复核一遍**。

1. **`yj_user.enabled` 是 `'1'/'0'`，不是 `'Y'/'N'`** —— 第一版按 `='Y'` 写，所有账号都查不到角色，
   界面表现是「角色列恒空、保存报未分配角色」。已改成 `ISNULL(enabled,'1') <> '0'`。
2. **只改渲染真正读的那个位**：表头看 `hidden`、明细列看 `visible`。明细里存在
   「`hidden=1` 但 `visible=1`」的字段（纸张不印、表格要显示），两个位一起写会把这类字段从表格里误删。
3. **必填字段不可隐藏**：写入侧静默跳过并回报标签，合并侧再兜一次（历史脏行 / 整体后改为必填）。
   界面上该行勾选框直接置灰。
4. **与整体相同即删行**：保存时把"和整体一样"的项删掉而不是存冗余行，因此整体以后改了，角色自动跟上；
   对话框里也能准确显示"已定制"。
5. **`PanelRegistry` 的 30 秒快照不掺角色数据**：合并发生在 `buildConfig` 的入参，注册表保持全员一致。

## 六、边界（刻意不做，写清楚免得被当 bug）

- **只存显隐**：顺序（`seq`）与栏名（`alias`）仍由系统整体决定，角色作用域下这三项交互被禁用。
- **查询条件（`place=query`）不参与**：本次只做表头与明细两层。
- **纸张/报表模板独立**：角色隐藏只影响界面/列集，不影响打印模板里显式写死的格子（隐藏是在"字段级"生效）。
- **不是权限**：隐藏 ≠ 看不到数据（无保密诉求）。真要挡数据必须做字段级权限（后端列剔除 + 导出/报表剔除）。

# 第二轮（2026-11-13 当日追加）：序号排序 + 角色模板

> ①「只存显隐，也可调整位置，并且这个字段排序，可以用序号来调整位置，**只有勾选的字段了才有序号**」
> ②「角色模板：**从整体一键复制 / 套用到另一个角色**」

| 后端 | 合并按"角色序号"排；保存带 `seq`；新增 `copyFromSystem` / `copyToRole` / `roleList`；控制器 `copyRoleFieldViewFromSystem`、`copyRoleFieldViewToRole`、`fieldViewRoles` |

## 3. 排序规则（写进代码注释，别凭印象推）

- 勾选的字段按 `seq` 1..n 排列（保存时**压成连续序号**，不会留空号）；
- **没勾选的字段没有序号**（`seq = NULL`），对话框里排在末尾；
- 覆盖表里**没有行的字段**（整体后来新增的）按系统整体顺序**追加在已编号字段之后** —— 新字段不会因为角色没编号而消失。

## 4. 两个必须记住的坑（都是实跑踩出来的）

1. **隐藏字段必须留一行 `shown=0`**：第一版保存时把"没勾选"的当"跟随整体"删掉了 ⇒ 删行=继承整体(整体是显示) ⇒ 隐藏完 `单价` 它照旧冒出来。
   现在只有"整行没提交"才删。
2. **`ORDER BY r.id` 必须同时 `GROUP BY r.id`**：SQL Server 会报"列无效"，异常被兜住 ⇒ 「套用到其他角色」的下拉**静默为空**（界面看着像没数据，日志里才有一行 WARN）。

## 6. 边界（第二轮新增）

- **角色一旦定制，就以自己那份为准**：保存会写全这套字段的行，所以整体以后改显隐不会自动同步到该角色（新字段仍会继承并排在末尾）。想回到跟随整体 → 「恢复继承」。
- **「套用到其他角色」只有管理员**（后端按 `is_admin` 拦，前端按钮也对非管理员隐藏）。
