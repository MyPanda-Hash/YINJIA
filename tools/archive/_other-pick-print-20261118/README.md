# 其他领料 / 其他退料「提交即打印」失败 —— 定位与修复(2026-11-18)

> 用户报障:「其他领料和其他退料要在提交生成单据时,自动打印一次。」
> 随后贴「自动打印 → 最近出纸」截图:**3 条全是「失败」,单号一栏是「—」**。

## 一、结论先说(不是前端没写自动打印,是打印代理打不出来)

「提交即打印」的代码 2026-11-16 就有了(`MobileOtherScan.submit` → `printSlip`,
见 `frontend/src/business/slipPrintFlow.js`),单据也确实入队了
(`yj_print_task` 里 2026-11-18 09:17/09:18/09:21 三条 OTHER_PICK_SLIP / OTHER_RET_SLIP)。
坏在**打印电脑上跑的那份代理**(`deploy/print-agent/print-agent.ps1`,v1.1.0)有两处不认这几张单:

| # | 原因 | 现场表现 |
|---|---|---|
| ① | 这几张扫码单**纸上不打二维码**(用户口径「二维码也不用打了」),服务器入队时把 `二维码内容/二维码图` 清空;它们**又不挂工单号** ⇒ 老代理在 `Invoke-PrintJob` 里直接 `throw '缺少打印内容(二维码内容与工单号都为空)'` | **其他领料/其他退料/生产退料** 100% 打不出来 |
| ② | 混料单带 `纸面`(《成型配料记录》A4 横),老代理**没有这段绘制分支**(该功能只写在 `tools/printing/print-agent.ps1` 源版,没发布到 `deploy/` 那份) | 混料单同样失败(id=15) |
| ③ | 失败时**代理不把原因回执给服务器**(`ack` 只带 `ok:false`) | 面板只有「失败」两字,`yj_print_task.fail_reason` 空,查不出原因 |

代理日志(`deploy/print-agent/agent.log`)是铁证:

```

2026-11-18 09:18:11 [轮询] 本机打印失败(id=17): 远程服务器返回错误: (500) 内部服务器错误。
```

## 二、改了什么

### 1. 打印代理(v1.1.0 → **v1.2.0**)

`deploy/print-agent/print-agent.ps1`(客户电脑实际跑的那份)与
`tools/printing/print-agent.ps1`(源版)同步改:

- **无码也能出纸**:没有二维码就照常打(版式/明细/抬头一个都不变),不再 throw;
  码框只在真有二维码时才画(留个空框现场会当成"码没打出来")。
- **认混料单专用纸表**:任务带 `纸面` ⇒ 走《成型配料记录》横板 A4(`Send-MixSheetToPrinter`,
  与源版逐行一致;选打印机/落 PDF 换成这份代理既有的做法:`Resolve-PrinterName` + Win7 的 `Get-PdfPrinterName`)。
- **失败原因回传**:`/ack` 带 `error`(含本机 `/print` 返回的 JSON `error`)+ `领料单号`/`类型`。
- 日志认单:没有工单号时用**单号**记(`[打印] TL-2026-11-0012 -> Kyocera …`)。
- `deploy/print-agent/说明.md` 追加 §十四:客户电脑怎么换新版、怎么验收(`/health` 的 `version=1.2.0`)。

> ⚠ 两份代理脚本**已经分叉**(2026-11-10 的 Win7/针式打印机/守护任务改造只落在 `deploy/`,
> 纸张/混料纸表/无码只落在 `tools/`)。本次两边都改,但**没有做合并** ——
> 下次谁再动代理,先决定哪一份是唯一真源,否则同样的坑会再踩一次。

### 2. 服务器(查看面 / 回执落库)

- `PrintStationController.ack`:把回执里的 `领料单号` 记进「最近出纸」,并把 `error` 作为
  失败原因带出去(以前这俩都是空值,所以那一栏永远是「—」)。
- `PrintCacheService.list()`:列表里带上 **FAILED** —— 失败的单子以前只落在库里、面板看不见,
  也就没有失败原因、更没法在修好打印机后点【补打】。
- `PrintStation.vue`:「最近出纸」显示**单号**(`领料单号 || 工单号`)+ 标题 + 失败原因;
  「打印缓存」里失败单的标签显示 **打印失败**(红底),仍可【补打】/【删除】。
