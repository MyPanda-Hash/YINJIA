## 每一步的判定

| 步骤 | 期望 | 实测 |
|---|---|---|
| 新增模版 → 输入名字 → 创建并设计 | 设计器打开，**6 列**，每列都绑在已登记字段上 | 6 列：测试日期·日期 / 项目名称 / 测试装置 / 测试工位 / 配水量（L）/ 配置用水；`6 / 15` |
| 加一列 → 新建自定义列「探针试剂X」 → 加入 | 新行标「自定义列（保存时登记）」 | 第 7 行出现该标记，计数 `7 / 15` |
| 保存 | 先 `/px/extField/add`（绑备用1）再 `/stdlib/add`；toast + 清单出现新模版 | toast「已保存，选中该条目的单据会用这套表头」；清单 4 条、新模版 7 列 |
| 打开单据「测试项目」下拉 | 新模版立刻在候选里（存库后重拉面板配置） | 4 个候选，末项 `ZZ-测试模版-20261106` |
| 选中新模版 | 纸面表头换成这套 7 列 | 表头：测试日期 / 项目名称 / 测试装置 / 测试工位 / 配水量 / 配置用水 / 探针试剂X |
| 设计（改列名）→ 保存 | `/stdlib/update` **带 id** 成功；改列名不动数据键 | 成功；库里 `key=探针试剂X`、`label=探针试剂X-改` |
| 删除（×）→ 确认 | `/stdlib/destroy`；清单与下拉都不再有它 | 清单回到 3 条，toast「已删除」 |

## 与上一版（已被本轮替换）的差异

上一版「编辑表格结构」按钮的三处致命问题：
① 保存发 `{lib,item,content}`，后端只认 `{id,content}` ⇒ 一律回「id 无效」，改完存不进去；
② 「新增模版」只清空列、不建条目 ⇒ 没法为"很多种项目"加表；
③ 改列名顺手改 key ⇒ 以后录这一列的值落进不存在的字段（静默丢数据）。
本轮三处都已修，并有源码契约单测钉住：`frontend/src/core/views/spikeWaterTemplateEditor.test.js`。
