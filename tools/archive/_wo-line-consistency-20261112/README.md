# 工单排产看板「本线任务量」口径统一（2026-11-12）

> 用户报障（原话）：
> 「目前左侧边栏显示的数量和当前的生产线排产数量（本线排产数量）和当前工序报工数量没有任何关联，
> 这个工作流的进行没处理完成吧」
> 截图：选中「生产线：装箱2(新厂)」，右侧明细合计 5421（本线排产）/ 1100（当前工序完工量），
> 顶部「本线排产数量 5421 | 未完工量 5000」，而左侧该线数字是 **0**。

## 一、根因（三件事叠在一起）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 左栏数字与右侧/顶部**完全无关** | 左栏数字是**成品口径** `未交量 = 排产 − 入库`（`linesSummary` 自带口径，2026-10-07 定），对后道线（装箱/组装，历史行入库早就 = 排产）几乎恒为 0；右侧明细是**工序口径**（工单行 × 该线工序的台账计划量/已审报工）。两套口径从来没有交集。 |
| 2 | 右侧多出一行**早已完工**的行 | 台账 `wo_process_line` 里 2026-10-10（「行级锚定」修好之前）建的 3 行把工单号存错了：`工单行id=123` 指向 GD-2026-09-0049 行5（生产完工、入库=排产=996），却存 `工单号=GD-2026-10-0003`；而代码/迁移一律按 `工单号=?` 找台账 ⇒ 这 3 行永远匹配不上、状态被冻在「已落实」，看板就把它们当成「等装箱的活」（421/996）。 |
| 3 | 顶部合计跟着虚高 | 顶部「未完工量」当时取 Σ`未交量`（成品口径），与本页「本线排产数量」「当前工序完工量」不是一家人；加上第 2 条的幽灵行，出现 5421 / 5000 这种读不懂的组合。 |

## 二、改了什么

### 后端 `ScheduleBoardService`

- **表达式收口**：新增 `ledgerOfRow(p,w)` / `curOpExpr()` / `reportedQtyExpr(op)` / `planQtyExpr(op)` 四个方法，
  `scheduled()`、`today()`、`linesSummary()` 全部改调它们（原来 `curOp`/`qtyOf` 是 `scheduled()` 里的局部字符串，
  另两处各抄了一份 ⇒ 口径必然漂移）。
- **台账权威键 = 工单行id**：`ledgerOfRow` = `w.工单行id = p.id OR (w.工单行id IS NULL AND w.工单号 = p.pl_no)`
  （老数据才回落工单号）。`当前工序`/`当前工序计划量`/`计划线`/`当前工序序` 全部走它。
- **`linesSummary` 新增 3 个字段**（每个产线一行）：
  `本线排产数量` / `本线已报完工量` / `本线未完工量`（+ `本线行数`），
  口径 = 选中该线后 `scheduled(line,'未完工')` 那批行的合计：
  - A 类：`plang_pc.scx = 该线` 的未结案未完工行（与 `scheduled` 主查询同过滤）；
  - B 类：台账归该线、工单当前线不在该线的「本线工序任务」（与 `lineProcessRows` 同过滤、同去重）；
  - `本线未完工量 = Σ max(本线计划 − 本线已报, 0)`（**逐行**截断，不让超报行抵掉别行缺口）。
- **`lineProcessRows` 补「整张工单行已完工/已结案」过滤**（仅未完工/全部页签）：
  做完了的行不该再挂成"等我的活"（与 2026-10-16 用户口径「完工后组装内没有当前生产工单」同一原则）；
  同时把硬编码的 `生产状态=N'未完工'` 换成 `ST_EXPR`（在产/未完工与页签同源）。

### 后端 `ProcessFlow` / `ProcessTaskService`（台账读取收口）

- `ProcessFlow.ledgerPlanQty`、`ProcessTaskService.applyNextProcess` 的台账查询统一改为
  `(工单行id=? OR (工单行id IS NULL AND 工单号=?))` —— 台账唯一权威键 = 工单行id，
  否则第 2 条的历史行永远不会被重算（状态永冻）。

### 迁移 `tools/migrate-wo-ledger-rowid-align-20261112.sql`（零 DDL / 幂等 / 两账套已执行）

1. 工单号回正：按 `工单行id → plang.pl_no`（正式库 18 行）；
2. 按行id + `ProcessFlow` 同口径重算整行台账的 状态 / 实际生产线 / 落实时间（正式库 11 行）；
3. 自检：工单号漂移 = 0、状态漂移 = 0，否则 `RAISERROR` 中止（DbSync 判 FAIL，不写 `yj_schema_log`）。
   - 正式库 `HSDZ_MES`：① 18 行 / ② 11 行 / 漂移 0·0；`执行 1, 跳过 742, 失败 0`；第二遍 `执行 0, 跳过 743, 失败 0`
   - 测试库 `HSDZ_MES_TEST`：0 行变更（旧快照）同样登记进链；第二遍 `执行 0, 跳过 743, 失败 0`

### 前端 `WorkOrderBoard.vue` + `en.js`

- 左栏主数字 = `本线排产数量`（字段缺失回退 `未交量`，不空白/NaN），下方新增 11px 次行
  `已报 X · 未完工 Y`（`本线已报完工量` / `本线未完工量`），工具提示写清口径；
  原有「今日已排/日产能」小标签未动。
- 顶部统计改为 `本线排产数量 X ｜ 已报完工量 Y ｜ 未完工量 Z`，三项都是工序口径、与本页明细同源；
  tooltip 里保留成品口径的 `Σ未交量` 供对账。
- 新增 8 条 `tt()` 中文 key 的 en 译名（至少 en；其它语言回退中文/机翻）。
