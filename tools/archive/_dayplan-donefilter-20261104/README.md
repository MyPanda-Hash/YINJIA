# 今日已排 / 每日已排 排除「已完工 + 已结案」行(2026-11-04)

## 1. 用户报障

> 「当前服务器存在这个问题，就是按你的说法左侧的未完工量已经为 0 了，今日派产量却还有这个数量是什么原因呢？」
> 截图为「工单排产」页：左侧 `装箱2(新厂)` **未交量 = 0**，右侧却显示 **今日已排 3046 / 日产能 15000**；
> 该线右侧排产明细「未完工」页签是**空的**（排产数量 0 / 未完工量 0）。

## 2. 根因（两套口径自相矛盾）

左边两个数由不同口径算出来：

| 数字 | 代码 | 过滤条件 |
|---|---|---|
| 未交量（左大数） | `ScheduleBoardService.linesSummary` | 作废 + **未结案** + **未完工** |
| 今日已排（右小数） | `ScheduleBoardService.dayPlanTodayByLine`（左侧骨架/顶部超载）<br>`WorkOrderDayPlanService.lineDailyPlan`（日期列表头「已排/日产能」） | 作废 + 空线 —— **没有**排除完工/结案 |

`dayPlanTodayByLine` / `lineDailyPlan` 会把该线**全部在册行**（不分页签）的日计划按 `DayPlanSpread`
摊到当天求和。而日计划是派生值，摊分规则有三条会让**早已完工的行**继续往今天出数：

1. 开工日为空 ⇒ 从**今天**起摊（`DayPlanSpread.of`：`s = start == null ? today : start`）；
2. 交期晚于今天 ⇒ 今天仍在摊分区间内（完工了但交期写在未来，常见于整单排期很宽）；
3. 交期早于今天 ⇒ 逾期，整笔压到开工日那天（开工日为空即今天）。

所以完工/结案的单不会被「未交量」计数，却仍被「今日已排」计数 ⇒ 左侧同一条线两个数打架。
用户环境中该线的 3046 全部来自这类行（本地库可复现其中一份：完工厂单 `GD-2026-09-0164`
排产 5000 / 入库 5000 / 完工+结案，但 `cp_date = 2026-11-30` ⇒ 今天仍摊 82）。

## 3. 修法（口径对齐，不动任何业务数据）

两处、共 4 条查询补上与未交量相同的过滤（复用 `PlangClose.notClosed("p")` / `PlangDone.done("p")`）：

- `backend/.../service/ScheduleBoardService.java`
  - `dayPlanTodayByLine()`：人工指定查询、在册行查询
- `backend/.../service/WorkOrderDayPlanService.java`
  - `lineDailyPlan()`：人工指定查询、在册行查询

效果：**完工/结案的行不再参与「今日已排 / 每日已排 / 今日超载」**；未完工行的数一分不动。

用本目录 `probe.mjs` 打两个实例：

## 5. 影响面 / 不变量

- 只改「产能/负荷」的显示口径：排产数量、日计划、未交量、格子数字、排单计划报表**均不变**。
- 已完成明细仍在「已完工」页签可见；结案/完工判定口径未改（`PlangClose` / `PlangDone` 只读复用）。
- 顶部「今日超载 N 条线 / 合计超 M」与左侧「今日已排」同源，一并修正（不再被已完工单虚增）。
- 取舍（已与用户确认）：改完后**今天刚完工的行当天即从「今日已排」消失** —— 这个数表示
  「线上还剩多少活」，不是「今天计划排了多少」；若要后者应另立标签，不能靠回加过滤。
