# 排产数量口径 A 方案：本线排产数量（2026-11-11）

## 背景（用户口径）

`工单排产 / 快速排产②已排产` 的一行 = **一张工单行 + 当前产线 + 当前工序**。
用户口径：「排产数量不是应该是当前产线需要排产的数量才对？」「排产数量应该为根据工序换算率换算过的数量实现」。

结论：`plang.pl_sl`（排产数量）是**成品口径**的排产确认量（结转时就写成转单数量），
不是本线量；本线量一直在 `wo_process_line.计划数量`（= 排产数量 × 该道换算率）。
本次只把**显示**改成本线量（A 方案），不动 `pl_sl`、不动台账、不写库。

## 改动

| 位置 | 改动 |
|---|---|
| `backend/.../ScheduleBoardService.java` `scheduled()` | 查询后补只读别名字段 `本线排产数量` = 既有 `当前工序计划量`（台账计划数量优先、缺失回落 pl_sl×换算率）——零新增查询、不写库 |
