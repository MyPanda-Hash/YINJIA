# 来料检验单「合格数量」必填 —— 2026-11-17

## 1. 问题

用户问:「来料检验单的合格数量是不是必填的，要设置为必填」。

**先说结论:`yj_field.required` 本来就是 1**(正式库/测试库都是,四单基线文档第 374 行也登记为「必填 ✔」),
但**后端两层都没兜住**,实际可以空着存、空着审 —— 所以体感上"不是必填"。

## 2. 修前实测(测试库,`_probe-before-fix-20261117.mjs`)

| 场景 | 「保存」 | 「保存为草稿」 | 「审核」 |
|---|---|---|---|
| 明细行**带** `合格数量 = null` | 409「明细第 1 行合格数量不能为空」 | 200(草稿豁免) | **200 通过** ← 洞 |
| 明细行**没有** `合格数量` 这个键 | **200 通过** ← 洞 | 200 | **200 通过** ← 洞 |

**为什么漏**

1. 保存路径的通用明细必填 `ButtonService.ensureDetailRequiredFilled` 按「载荷里带了这个键」判,
   缺键视为选单/局部提交而**跳过**(2026-09-20 为避开选单误报定的口径)。
2. 而库里为 NULL 的列,在 `getFormDescriptor` 导出的明细行里**根本没有这个键**
   —— 实测 `IJ-2026-11-0002` 的明细行只有 9 个键,`合格数量` 不在其中
   ⇒ 界面上"从库里载入 → 原样提交"这条路,后端必填形同虚设。
3. 「审核」这一环完全不查必填(只有保存查),草稿(允许存一半)可被直接审核成已审核。

**业务后果**:来料检验单审核后会按 `合格数量` 生成采购入库单、按 `不合格数量` 生成暂收退回单,
合格数量为空 ⇒ 生成 0 数量入库 / 空退料,采购链在这里断掉。

## 3. 修法(`ButtonService.java`)

| 方法 | 位置 | 作用 |
|---|---|---|
| `ensureInspOkQtyPresent(items)` | `if (markSaved)` 分支内(保存/提交路径) | 来料检验单**缺键按空算**:每行「合格数量」必须非空;「保存为草稿」按用户口径豁免 |
| `ensureInspOkQtyFilledForAudit(def, no)` | `audit()` 状态闸门之后 | 审核前**按库里的行**复核(`qc_insp_detail`,**排除 `asp_cancel='Y'` 软删行**),空则拒绝 |

> 软删行那条踩到了:保存会"软删旧行 + 插新行",不过滤 `asp_cancel` 的话,旧行(合格数量 NULL)
> 会先撞闸门 —— 首版实测"补了合格数量还是审不过",已修。

前端不用改:`PanelxList.validateInlineDraft` 早就拦(实测见下面第 4 节界面证据),它和高亮定位一起工作。

## 9. 「提交审批 / 审批通过」原来一处必填校验都没有

`ButtonService` 里必填只在两处:保存(`ensureRequiredFilled` / `ensureDetailRequiredFilled`,而且看**载荷**)与

# 第三轮(同日):「审核时合格数量会不会自动填 0」

## 13. 用户问

> 「现在看来料检验单会不会出现点审核或者提交审核出现合格数量自动填为0的情况。
>  只有不合格数量可以出现这个情况。」

## 14. 先查「谁会把 0 写进去」

| 可能的来源 | 结论 |
|---|---|
| 后端 `审核 / 审批通过 / 生单` 写 `合格数量` | **不会**。全仓 grep:后端对 `合格数量` 只读不写(只有注释/派生口径说明);`syncFromRecv` 明确"检验单自有字段(合格数量/不良数量/抽样方案)不动" |
| 送料暂收单「生单」→ 来料检验单 | 不带这个键,库里就是 NULL(实测 `IJ-2026-11-0004/0005` 的行) |
| 「选单」映射 | 只映射 `detailMap` 里声明的列,`合格数量` 不在其中 ⇒ NULL |
| **界面「新增数据」造的新行** | **这里**:`PanelxList.newDetailRow` / `PanelxForm.addDetailRow`(含子表)/ `NewVoucherDialog` / `DetailMaintainDialog` 都把 `小数/整数` 一律 `defaultValue ?? 0` ⇒ 新行的 `合格数量` 是 **0** |

于是真实链路是:新增一行(合格数量=0)→ 填送检数量 → 点「审核 / 提交审批」→ 前端静默保存把 **0** 落库
(0 算"已填",必填拦不住)→ 审核按「合格数量 > 0 分流入库」一行都不生成 ⇒ 采购链断在这里。
**这不是"审核动作把值改成 0",而是"新行先生成 0,再被审核原样存下去"。**

## 15. 修法:新行默认值收口到一处

新增 `@core/panel/detailRows.blankRowOf(fields)`(**新行默认值的唯一出处**):

```
小数/整数 → defaultValue ?? (isRequired ? '' : 0)   // 必填留空,非必填才预填 0
是否      → defaultValue ?? false
其余      → defaultValue ?? ''
```

四个新行构造点全部改走它;`DetailMaintainDialog` 因为整数默认是行序号,只改小数那一支。

界面实测(5173 + 正式库草稿 `IJ-2026-10-0020`,**只新增行不保存**,单据在库里仍是 1 行):

| 列 | 新增行(勾选后) | 结果 |
|---|---|---|
| 合格数量(必填) | `∅` 空 | ✅ 不再自动 0 |
| 不合格数量(非必填) | `0` | ✅ 保持自动 0(用户明确允许) |
| 送检数量 / 单价 / 损耗 / 损耗率 | `0` | 非必填,照旧 |
| 物料编码 / 批次号 … | `∅` | 文本照旧空串 |

"四处新行构造点都不许再自己写 `defaultValue ?? 0`");`npm test` **1993 项全绿**。
