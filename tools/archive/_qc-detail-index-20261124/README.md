# 检验数据记录明细表「单号直索引」+ 索引跳空表的原因说明（2026-11-24）

用户报障（两张截图：「检验数据记录明细表」+「待检验目录」）：

> 「索引无法查找到对应的单据，当前转跳为空表。并且明细表也可以直接索引」

## 一、复现与根因（生产 36.140.66.163:8090 实测）

`round-03/04` → 在「待检验目录」点第 1 行的 **↗ 跳转到该检验单**（单号 `IJ-2026-11-0002`）：
落到「来料检验单」面板，**0 张单**，提示「未找到该单据（可能已作废或没有查看权限）」。

`round-06/07/08` → 直打接口定位：

| 取证 | 结果 |
|---|---|
| `queryFormDataList{QC_INSP, _docNo=IJ-2026-11-0002}` | `totalSize = 0` |
| `queryFormDataList{QC_INSP, 单据编号=IJ-2026-11-0002}` | `totalSize = 0` |
| `getFormDescriptor{QC_INSP, IJ-2026-11-0002}` | **200，单据状态 = 已作废**（抬头完整） |
| 全量比对（检验单列表 vs 检验数据记录引用） | 只有 `IJ-2026-11-0002` 这一张是悬空引用；其余引用都能定位 |

⇒ **不是索引坏了，是那张检验单已被作废**：作废只写 `yj_doc_status.canceled='Y'`，单据行还在库里，
而列表按口径把它过滤掉，于是深链 0 行、落在空表上；旧提示把「已作废 / 已删除 / 无权限」混成一句，
用户看不出到底为什么。

（数据侧遗留：该检验单作废后，「检验数据记录明细表」里它的行与待检验目录行仍在，
所以从这两张表点过去一定会撞到这张作废单 —— 本次只改**提示**，不动业务口径。）

## 二、改动

1. **`frontend/src/core/views/PanelxList.vue`**
   - 报表(flat)面板新增「单号直索引」分支：登记过的面板/列 → 单号渲染成 `.doc-no-link`，
     **点号直接** `router.push('/panelx/list/<目标面板>?docNo=<单号>')`（不弹窗、不加图标）。
     映射真源 = `core/qc/qcInspRecDetail.js` 的 `QC_REC_DETAIL_LINKS`
     （检验数据记录单号 → `QC_INSP_REC`、来料检验单号 → `QC_INSP`）。该常量此前**没有任何渲染方**，
     明细表上一直是纯文本。
     跳转前过 `canViewPanel`（报表不能当跳板绕过授权）。
   - `loadDocNoTarget()` 落空时改调新增的 `missingDocHint(no)`：回查一次抬头，
     状态含「作废」⇒「单据 X 该单据已作废,作废单不进入列表」；有业务字段的其它状态 ⇒ 带出真实状态；
     抬头只是「空壳」（接口对不存在的单号会合成一张新单默认抬头，实测 `IJ-2099-01-9999` 返回「草稿」）
     ⇒ 不采信，走通用兜底文案 + 单号。列表照旧恢复，**不落空表**。
2. **`frontend/src/i18n/locales/en.js`**：补 2 条词条（AGENTS §2.1）。
3. **测试**：新增 `core/qc/qcInspRecDetail.test.js`（6 条，含"常量必须真接到渲染方"的源码闸）；
   同步更新 `core/views/panelxDocNoJump.test.js` 的提示断言。

## 六、追加：行内「取消完成」按钮（2026-11-24 第二轮，用户口径）

> 「检验数据记录明细表可以加上这个按钮，这个取消完成后重新在待检验中看到」

实现**不是新写**：这段渲染与动作 2026-11-11 就交付过（commit `6cf9aea6c`），但在
**merge `9e8e5db2c`（2026-11-13「合并 origin/main(LF 云端) 到本地分支」）里被整段丢掉**
（该次合并后 `PanelxList.vue` 里 `qcRecDetailReopen` / `qcRecLinkPanel` 命中数为 0；
`git rev-list --first-parent` 二分定位，`git log -S` 只在引入提交命中 —— 典型"合并整文件覆盖"，
与 AGENTS §5⑦ 记录的事故同源）。常量 `qcInspRecDetail.js`、en 词条一直都在，丢的只是渲染与动作，
所以本次按原实现**原样恢复**（含会话/提示文案，未新增词条）。

行为：面板按 `yj_panel.config.statusGate` 只放行「已完成检验」的行 ⇒ 行内只对这些行出「取消完成」；
点了走 `QC_CATALOG` 的「修改」按钮（取参 = 目录单号 + 目录行 id），后端把目录行回弹成「正在检验中」
并写一条 `yj_doc_modify_log`；该行随即离开本表并重新出现在「待检验目录」。
