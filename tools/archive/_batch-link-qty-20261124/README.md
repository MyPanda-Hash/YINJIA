# 分批送料「占用不回写」修复（2026-11-24）

客户报障原文：

> 「为什么生单数量是 4000，这里只有 200」

截图：`分批送料 · YJ-20261103-06` 对话框行 6（`YJ-GL-012` 二十寸纸箱）显示
`数量 4000 / 已送 4000 / 剩余 0 / 可送上限 2000 / 本次 0`，而送料暂收单
`SL-2026-11-0028`（2026-11-11）明细行只有 **200**，采购入库单 `PI-2026-11-0034` 同样 **200**。

## 一、根因（生产接口取数核实，非推测）

| 取证 | 结果 |
|---|---|
| `/px/batchFlow/lines`（订单 YJ-20261103-06 行6） | `数量 4000 / 已送 4000 / 已退回 0 / 剩余 0 / 可送上限 2000` |
| `/px/batchFlow/batch?batchNo=20261111` | `batchQty 4000`、首单 `SL-2026-11-0028`、末端 `PI-2026-11-0034` |
| `getFormDescriptor(QC_RECV, SL-2026-11-0028)` | 1 行，`YJ-GL-012` 数量 **200** |
| `getFormDescriptor(PURCHASE_IN, PI-2026-11-0034)` | 1 行，实收 **200**、送检 **200** |
| 单据头时间 | 审核 `11:15:58`，**创建时间 `16:42:28` 更晚** ⇒ 审核后又被保存过一次 |

结论：「已送 4000」是 `form_flow_link.linked_quantity` 的**占用**，不是单据数量。
占用与批次台账 `yj_doc_batch.batch_qty` 只在**生单那一刻**写一次
（`VoucherFlowService.linkBatch` → `linked_quantity = 本次送料量`），
全仓库**没有任何**「保存/审核暂收单时回写占用」的路径 ⇒ 生单 4000 之后把单据行改成 200，
占用仍停在 4000，于是 剩余=0、客户看到 4000 vs 200（差 3800 的幽灵占用）。

## 二、修复

1. **代码（堵漏）**：`BatchService.syncReceiptLinks(docNo, user)`
   - 每次保存**送料暂收单**后（`ButtonService.save` 里 `syncBatchNo` 之后）跑一遍，幂等：
     · 每条 ACTIVE 占用 → 行还在：`linked_quantity` = 行当前「数量」；
     · 行已软删/不存在 → 占用置 `RELEASED`（额度还给订单行）；
     · 涉及的批次台账 `batch_qty` 重算 = 该批次 ACTIVE 占用对应行数量合计。
   - 只碰 `target_panel_code='QC_RECV'`（采购订单→暂收单）；
     **不动**「检验→采购入库/暂收退回」的占用（那是合格/不合格数量语义）。
2. **修数（清存量）**：`tools/migrate-batch-link-qty-sync-20261124.sql`（幂等，含改前/改后与末尾自检），
   已登记进 `tools/db-migrations.txt`；两账套均已执行并登记 `yj_schema_log`。
3. **体检（防复发）**：`tools/verify/BatchLinkQtyAudit.java`（只读，exit 1 = 有漂移），
   查三类：① 占用指向已失效行 ② 占用数量 ≠ 行数量 ③ 批次台账 ≠ 实际送料量。

## 三、验收（本地 8090 + 正式账套库，逐条实测）

| 场景 | 结果 |
|---|---|
| 代码路径：把草稿暂收单 `SL-2026-11-0002` 行 552 数量 8000 → **7000** 后点保存（走真实 `/px/callButton` 保存） | 行数量 7000，**占用自动变 7000**，批次台账 19900 → **18900** ✅ |
| 复原：同一行改回 8000 再保存 | 占用 8000、台账 19900，全部回到原值 ✅ |
| 人为制造漂移（占用写 9000、单据 8000；台账写 21900） | 稽核 `[FAIL] 发现 2 处漂移`（② `占用 9000 / 实际 8000 (差 1000)`、③ `台账 21900 / 实际 19900`）✅ |
| 跑修数脚本后再稽核 | `①0 ②0 ③0` → `[PASS]` ✅ |
| 两账套终检 | `HSDZ_MES` / `HSDZ_MES_TEST` 均 `[PASS]` ✅ |
| **生单侧联动**（`round-41.mjs`）：订单 `YJ-20261110-03` ↔ 草稿暂收单 `SL-2026-11-0002` 行552，把数量 8000 → **6000** 保存后直接调 `/px/batchFlow/lines` | 改前 `已送 8000 / 剩余 0 / 可送上限 1600` → 改后 **`已送 6000 / 剩余 2000 / 可送上限 3600`**，改回 8000 又变回原值 ✅（说明分批送料对话框的已送/剩余/上限就是按占用算的，现在已经跟单据同步） |

脚本与日志：`round-38.mjs`（改数量保存）、`round-39.mjs`（复原）、`round-40.mjs`（rebase 后复验）、
`round-41.mjs`（生单侧联动）、`q30~q40.sql`（取证）、`rebuild2.log` / `rebuild3.log`（打包+重启）。

**生效边界**（回答「改了暂收单，生单那边会跟着改吗」）：① 只在**保存**时回写，改完不保存不算；
② 只对**送料暂收单**生效（检验单的合格数量属另一条链，语义是合格/不合格）；
③ 已审核单需先弃审才能改；④ 分批送料对话框是**打开时取数**，已开着的要关掉重开。
