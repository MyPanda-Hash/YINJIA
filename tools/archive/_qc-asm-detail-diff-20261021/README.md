`目数(+20目)` / `目数(-325目)`。

## 脚本

`migrate-asm-insp-detail-diff-20261021.sql`

- 默认 **干跑**：`#cfg.apply = 0`，只打印计划，不写库。
- 默认只改当前单：`#cfg.docNo = N'ZJ-2026-10-0135'`。
- 改全部含「目数」行的单：把 `docNo` 改成 `NULL`。
- 真正写库：把 `apply` 改成 `1`。

每张目标单：

1. 原「目数%」行 **软删**（`asp_cancel='Y'`，`asp_user2` 留痕，历史可查）；
2. 写入 4 行：
   - 外观（标准库 `QP-ASM-00` / `ASM-APPEARANCE`）
   - 尺寸（`ASM-DIMENSION`），测量值 1/2/3 = 外径/内径/长度（按产品规格 `a*b*c` 解析）
   - 出货重量（`ASM-WEIGHT`）
   - 性能项（`QP-ASM-01` 按 `head.id % 4` 轮换：抗压强度/初始流速/压降/余氯去除率），
     测量值 1 按单据 id 生成一个落在标准内的值；
3. 检验结果 / 结果判断 = 合格，不合格数量 = 0，合格数量沿用表头。

## 其它单怎么处理

先干跑全部：

```sql
-- 把脚本里 #cfg 改成：
INSERT INTO #cfg (apply, docNo, mark) VALUES (0, NULL, N'qc-asm-detail-diff-20261021');
```

确认计划行数（当前 384 张单 × 4 = 1536 行）后再把 `apply` 改成 1；脚本按「仍有存活目数行」判目标，
已改写的单不会重复处理，可重复执行。

## 注意

- 这是**业务数据整形**脚本，不是结构迁移，**故意不登记 `tools/db-migrations.txt`**（避免部署时自动重跑）。
- 改的是已审核单的明细；旧行只软删、不物理删，可回滚（把旧行 `asp_cancel` 改回 `N`、删新增行）。
- 性能项测量值是演示用的确定性数值（按 id），不是真实检测结果；正式质量数据请以实际检测为准。
