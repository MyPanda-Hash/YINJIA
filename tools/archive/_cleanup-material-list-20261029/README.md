# 服务器物料清单数据清理(2026-10-29)

## 要做什么

清空**服务器** `36.140.66.163` 上「研发管理 / 产品文件 → 物料清单」面板的全部数据。

- 用户口径:「把服务器上的物料清单的数据全部清理掉」
- 用户确认:**全部删除、不需要备份**

## 清理对象(只有一张表)

`yj_panel` 里 WLBOM(物料清单)是**单表式面板**:

| panel_code | head_table | line_table | mode |
|---|---|---|---|
| WLBOM | NULL | **mate** | doc |

⇒ 头与明细都在 `mate` 一张表里(旧行表,一行 = 一个「产品 + 子件」),
**没有独立的 _head/_detail 附表**。清 `mate` 即清空面板全部数据。

样例数据(2026-10-29 只读取证):

```
物料编码      | 物料名称      | 单据日期    | 单据状态
1000056562   | 1000056562   | 2025-05-30 | 草稿
1000056557   | 1000056557   | 2025-05-30 | 草稿
```

抽样 1200 行:**物料名称 ≡ 物料编码、明细全空、全部草稿** ⇒ 批量导入的占位数据。

## 怎么执行

服务器只开放 3389(RDP) 与 8090(HTTP),1433 不对外 ⇒ 无法从开发机直连,
需在服务器上用 SSMS 手动执行。

1. RDP 连 `36.140.66.163:3389`,登录 `Administrator`
2. 打开 SSMS,`localhost` + **Windows 身份验证**
3. 打开本目录 `cleanup-material-list-server.sql`,**整个文件**执行(F5)
4. 看消息窗口,应出现:

```
[OK] 已删除 mate 行数: 6655
[PASS] mate 已清空(0 行),物料清单面板现在应该是空的
[PASS] WLBOM 面板元数据仍在(物料清单入口保留,可继续录真实 BOM)
cleanup-material-list-server-20261029.sql 完成
```

## 脚本做了什么

| 步骤 | 动作 |
|---|---|
| ① | 删除前打印 mate 现状(总行数/不同产品/日期区间 + 3 行样例) |
| ② | `DELETE FROM dbo.mate` 并打印删除行数 |
| ③ | 自检:残留必须为 0,否则 RAISERROR 中止 |
| ④ | 自检:WLBOM 面板元数据仍在(脚本不碰 yj_panel) |

**不删表、不改元数据。** 面板入口保留,以后可以继续录真实 BOM。

## ⚠ 清理后注意

`ButtonService.syncProdBomToMaterialList` 会在**产品信息表归档时自动把 BOM 写回 mate**
(2026-10-29 新增,用户口径「产品信息表归档之后同时保存到物料清单」)。

⇒ 清空后如果你**重新归档**任何一张产品信息表,对应的 BOM 会被自动写回物料清单。
这不是 bug;若要保持物料清单为空,别重新归档产品信息表。
