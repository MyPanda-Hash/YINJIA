# _finish-in-insp-link-20261112 —— 产成品入库单关联两张出货检验单(阶段 1 取证)

> 用户口径(2026-11-12):「修改当前的产成品入库，让他需要关联当前的出货检验功能记录表和出货检验表观，
> 当这两个完成后按照每天的批次实现对这个产成品入库单的入库数量进行填写和创建。」
> 追问确认:表头两个参照字段 / 数量按该批次报工量带出可改 / 两单都已审核且该批次双合格才可入库 /
> **一张入库单 = 一个日期批次** / 最后一道工序报工自动生成草稿 或 选单选生产工单人工控制批次。

## 本阶段(阶段 1)做了什么
- `tools/migrate-finish-in-insp-link-20261112.sql`(两账套执行 `[OK] 5 batches`、复跑幂等):
  - `bd_finish_in` +`出货检验功能单号`/`出货检验表观单号` nvarchar(60) + 列注明;
  - `yj_field`(FINISH_IN)两条**参照**字段:header/seq 66·68,ref_panel=`QC_PROC_INSP` / `QC_ASM_INSP`,
    ref_field=display_field=`单据编号`(与既有「制程检验单号」同款);
  - `yj_translation`(scope='field')两条标签 × 10 语种。
- 零业务门禁:只让单据能选、能存;不改变任何既有单据、审批与库存行为。

## 阶段 2(待做,方案见 docs/design/出货检验功能记录表-表样改造.md §八)
1. 保存/提交/审核门禁:两单号必填、两张单都「已审核」、本单批次在两张单明细「内部批次」里都存在且都判「合格」。
2. 数量:按 `(工单号, 工单行号, 批次号)` 汇总**已审核报工**(scjl)→ 实收数量默认值,可改;保存校验不超报工量。
3. 自动生成:最后一道工序报工审核后按「一个日期批次一张」生成产成品入库单草稿(幂等)。
4. 人工创建:沿用「选单(选生产工单)」,按批次带出产品/批次/数量,再选两张检验单。
