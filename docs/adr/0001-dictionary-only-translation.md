# ADR-0001: 多语言翻译边界——字典翻、事实不翻

| 属性 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-08-30 |
| 背景 | 多国语言切换功能设计拷问会话(grill-with-docs) |

## 背景

YINJIA-MES 需要多国语言切换(简体中文 + 英语),要求"所有字段、所有设置、所有数据显示"
切换语言。数据库数据分两类:

- **字典/配置类**:仓库(原料仓)、工序(检验人员)、面板字段标签——系统词汇,量小、封闭集合
- **业务事实类**:客户法定名称(广东胜蓝新能源科技有限公司)、单据编号、用户录入备注、物料规格——外部事实,量大、持续新增

## 决策

**字典/配置类数据提供译名并随语言切换;业务事实类数据永远保持原文,不接机器翻译。**

理由:
1. 客户法定名称、规格型号(如 C5191H-0D20X11D5-AE)的机器译文不可控,错译直接造成业务事故
2. 字典集合封闭(22 仓库、186 工序、面板标签数百条),人工维护译名成本可控
3. 单据编号、日期、金额等本身语言无关

## 后果

- 正面:翻译质量可控;新增语言只需补字典译名与语言包;接口协议稳定(label + label_en)
- 负面:新增字典条目时需同步维护译名(提供维护界面降低成本);若未来某客户法定名
  确需显示英文名,以"客户备注英文名"字段单独解决,不推翻本边界
- 若要推翻本决策:需重设计字典表结构、面板配置接口与维护界面,并回答机器翻译质量兜底问题
