# ADR-0004: 配方计算器采用「面板按钮 + 弹窗」,公式写死只持久化参数

- 状态：已接受（2026-09-20）
- 背景：炭棒配方有 12 步计算(成型长度→体积→干重→折算炭粉量→脱模重量→最终比例→含水分添加量),
  目前靠一张会算的 Excel 与一个独立演示程序《炭棒工艺配方设计器》(PyInstaller 打包的 exe)在算,
  算完的值靠人手抄进「成型工艺清单」单据(页 1 灌料三值/脱模长度与重量/理论水分,页 2 配方表两列)。
  `docs/design/研发管理-新面板设计与改动方案.md` §12「配方计算器(已定:落地)」原定的落点是
  **成型工艺清单的第 3 个页签**;本次重新拷问后推翻该落点,理由如下。
  另有三条约束必须先明确:① 单支物料含量要作为**订单物料需求的数据源**,计算口径不能各处一套;
  ② 成型工艺清单是**受控文书**(归档 + 两级审批 + 四文件编辑门禁),纸面版式被改坏过两次,代价很高;
  ③ 弹窗里的一切几/折算比/公差/漂移系数是**工艺参数**,每次重敲不现实,但落成单据字段又会把
  受控文书变成草稿本。
- 决策：
  1. **形态 = 面板按钮 + 弹窗**,不占页签:入口在「成型工艺清单」(RD_MOLD_PROC)面板上,
     弹窗内的一切几/折算比/公差/漂移系数/含水率**不落库、不打印**,只有回填进单据字段的值随单据保存
     (打印沿用既有"一次只打当前页签"行为,页 1/页 2 两张纸的输出完全不变)。
  2. **公式写死在代码里**,唯一实现 = `frontend/src/core/mold/recipeEngine.js`,逐条对齐 exe 的
     `app.domain.engine.compute`(ENGINE_VERSION 1.0.0);验收口径是**与 exe 逐位一致**,
     期望值由 `tools/archive/_gen-recipe-golden.py` 从 exe 真引擎产出并固化为 fixture。
     **否决"公式表达式可编辑并存库"**:那会打破唯一实现,单支物料含量作为订单需求数据源时口径不再受控。
  3. **只持久化可调参数**(一切几/折算比/成型长度公差上下限/脱模漂移系数):粒度 = 系统默认 +
     **按产品编号覆盖**,落点复用**标准库** `yj_std_lib`(条目名=产品编号,空条目=系统默认),
     维护界面复用现成的 `StdLibManager.vue` —— 不新建表、不新建维护界面。
  4. **配方的唯一真源 = 单据页 2「成型配方」的配方表**:弹窗读当前单据该表的行(物料种类定料位分组、
     序号定料位、设计添加量作设计值、物料编号反查含水率),算完把 `实际添加比例`/`单支物料含量`
     写回**同一行**,页 1 的灌料三值/理论水分/脱模长度与重量/密度上下限另写。
  5. **物料含水率**落 `bs_inv`(商品/存货档案)的 `水分含量` 列;弹窗尺寸先读单据现有格,
     60 行「烧结尺寸表」(`rd_sinter_tolerance`)作为紧随的独立任务(它同时服务页 1 检验要求四格)。
- 后果：
  - 页 1/页 2 的**受控纸面一个字都不动**(不加页签、不改版式),公式与参数的变化因此完全不进入
    文书审批链路;代价是弹窗的输入不随单据留存 —— 换一个人打开同一张单,看到的只有结果值,
    看不出"当时用的一切几/折算比是多少"。**这是本决策的主要代价**,接受它是因为这几个参数已按产品
    持久化(第 3 条),需要时能查回来。
  - 计算口径只有一个实现,但**只在浏览器里**跑:小程序/服务端要算同一套,得再搬一次或加接口;
    本期不做,理由是落库后的 `单支物料含量` 已足够支撑订单物料需求,不需要重算。
  - 引擎与 exe 的**逐位一致**是硬约束:任何公式/次序改动都必须重跑黄金向量;
    生成期望值的 Python 版本也被钉住(3.10 —— 3.12 起 `sum()` 改补偿求和,会差最后一两个 ulp)。
  - 被放弃的替代方案:
    ① **§12 的第 3 个页签**(输入随单据存、可复算,但把"计算器"塞进受控文书 —— 页签版式会被
       当成纸面来维护,且归档后要改参数得走修改申请,工序上不划算);
    ② **公式表达式可编辑并持久化**(最灵活,但唯一实现被打破、需表达式求值器 + 校验 + 版本 +
       多语言 + 打印留痕,收益与成本不成比例);
    ③ **弹窗自带 10 料位、与单据配方表并存**(贴近演示程序的手感,但同一份配方两处可改,
       必然出现"弹窗算的和单据上写的不一致")。
