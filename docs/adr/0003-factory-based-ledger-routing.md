# ADR-0003: 登录工厂即账套切换(一系统两账套)

- 状态：已接受（2026-09-12）
- 背景：登录页原本有「登录工厂」选择，但后端写死只返回一家工厂（YJ），数据层无任何工厂维度——
  纯展示壳。需要区分"真实工厂使用"与"测试演练"两套账，且要求**一个系统、登录时选工厂即切换**。
- 决策：
  1. **单实例 + 数据源路由**：不跑双实例双端口。登录时所选工厂写入 JWT 工厂声明（YJ / YJ_TEST）；
     `JwtAuthFilter` 按声明用 ThreadLocal 切换 `AbstractRoutingDataSource` 的查找键，把该请求
     路由到对应库：YJ → HSDZ_MES（正式）/ YJ_TEST → HSDZ_MES_TEST（测试）。
  2. **每账套独立 Hikari 连接池**（各 10 连接）；无工厂上下文的线程（启动播种/定时任务/无令牌调用）
     一律落正式库（安全默认）。过滤器 finally 清理 ThreadLocal，防容器线程复用串库。
  3. **登录验密按所选账套**：login 接口先路由再查 yj_user——两个账套各自有独立的用户与角色数据。
  4. 测试库由 `tools/scripts/make-test-db.ps1` 备份还原制备（yinjia 为 db_owner），可随时重跑刷新。
- 后果：
  - 切换账套 = 重新登录选另一个工厂（工厂绑定在令牌里）；两个工厂的令牌可并存使用。
  - 旧令牌/无声明的 API 直连默认正式库——测试库数据不会因漏带参数而泄入正式账。
  - 迁移脚本需两库都执行（先正式后测试）；jdy-sync 定时任务只写正式库。
  - 附件文件目录两账套共享（上传文件名带随机串，DB 行隔离，冲突概率可忽略）。
  - 被放弃的替代方案：双实例双端口（运维/入口割裂，已建后拆除 application-test.yml 与 start-test.ps1）、
    业务表加工厂字段的行级隔离（侵入面大，单工厂现状不划算）。
