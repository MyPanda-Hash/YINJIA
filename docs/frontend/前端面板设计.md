# YINJIA-MES 前端面板设计

| 属性 | 内容 |
|---|---|
| 文档类型 | 前端设计 |
| 适用场景 | 前端面板设计 |
| 维护状态 | 生效 |
| 规范来源 | light-mes 前端面板设计(2026-08-27)适配 + YINJIA-MES 通用设置(v0.5) |

本文定义 YINJIA-MES 的前端面板结构和交互。渲染器与 light-mes core 完全同源;面板与字段以 HSDZ_MES 元数据(yj_panel/yj_field)为准。

## 1. 运行链路与职责

```text
路由 /panelx/list/:panelCode 或 /panelx/form/:panelCode
  -> core/views 通用渲染器(经 panel-runtime 注入,不直接依赖业务层)
  -> business/engine.js 适配器(SQL 接口、参照展平、按钮名映射)
  -> /api/*
  -> Spring Boot + SQL Server HSDZ_MES
```

| 位置 | 职责 | 禁止事项 |
|---|---|---|
| `frontend/src/core/` | 通用列表、表单、参照、选单、扫描填单和导入组件 | 写死某个业务面板的字段或种子数据;直接 import business 层 |
| `frontend/src/business/engine.js` | SQL 接口适配、参照展平、按钮名兼容、现存量回填 | 保存前端配置副本或演示行 |
| `frontend/src/business/menus.js` | 菜单和面板入口 | 绕过角色可见面板过滤 |
| `frontend/src/views/` | 门户、Dashboard | 复制通用面板渲染逻辑 |

## 2. 页面形态

| 形态 | 入口 | 数据来源 | 用途 |
|---|---|---|---|
| 单据列表/表单 | `/panelx/list/:code` | yj_panel(mode=doc) | 查询、单据翻页、明细维护、审核 |
| 单单据档案 | 同一组通用路由 | yj_panel(mode=archive) | 一张虚拟单承载整份基础档案 |
| 报表/平表 | 通用列表 | yj_panel(mode=flat) | 只读查询(库存状况等) |

单据列表从上到下固定为:工具栏(buttonGroups 分组)→ 查询区(queryFields)→ 明细区(gridTabs)→ 表尾。

## 3. 配置映射

运行时配置唯一来源是 `PanelConfigService` 按 yj_panel/yj_field 实时生成的 light-mes 契约 JSON;前端不维护配置副本。

| 配置路径 | 页面用途 | 生成规则 |
|---|---|---|
| `metadata.panelName` | 页签与标题 | yj_panel.panel_name |
| `metadata.panelCategory` | 单据/基础档案/报表 | yj_panel.category |
| `metadata.singleDoc` | 单单据档案模式 | mode=archive 时 true |
| `metadata.panelState` | 状态字段与选项 | 档案:状态(启用/已作废);单据:单据状态(草稿/已审核/审批中/已中止/已作废) |
| `metadata.uniqueKeys` | 档案唯一键(同码不允许重复) | `yj_panel.config` 的 `"uniqueKeys"` 原样下发(仅声明了才下发);形如 `[["工序编码"]]`(单列)或 `[["仓库","仓位编码"]]`(组合键)。前端保存前对已载入的全量行查重,后端 `ButtonService.saveArchive` 同一份声明做落库前预检,数据库侧另有过滤唯一索引兜底 —— 见 §4.9 |
| `metadata.buttonGroups[]` | 工具栏分组 | 见 §6 |
| `tablePages[0].queryFields` | 查询字段 | place 含 query 的字段(**档案面板恒为空,规范 §4**) |
| `tablePages[0].gridTabs` | 明细列 | 见 §7(列自定义);单据面板第二项为汇总页签 `{label:汇总, summary:true}`(PANDA 对齐) |
| `gridTabs[1].summary` | 汇总页签开关 | true 时明细区出现 明细\|汇总 页签切换:按 存货/产品/材料 分组,度量列合计,尾行总计 |
| `detail.tabs[].summaryItems` | 汇总字段 | `[{label:"数量合计", field:"数量"},...]`——数量/金额类数值列自动推导;驱动汇总页签合计列全集与表单「明细汇总」子页签 |
| `dataSchema.fields` | 表头字段 | 单据=header 字段;**档案仅"备注"** |
| `detail.tabs[]` | 明细页签 | 档案=全部字段(业务键如 khda);单据=items |
| `gridTabs[0].columnAliases` | 列头别名映射 | yj_field.alias(非空时 `{原标签: 别名}`) |
| `gridTabs[0].displayToKey` | 显示名→数据键 | `{别名: 原标签}`(与 columnAliases 互逆) |

`detail.tabs[].key` 必须与接口返回的 `detail.<key>` 完全一致(yj_panel.detail_key)。

## 4. 单单据档案(基础资料)

基础资料(KHDA/GFDA/YWYDA/CKDA/ZDGL)取消多单据痕迹,严格采用 light-mes §八 单单据结构:

1. `queryFields = []` —— 单据行顶层无业务字段,参照/查找在展平后的明细行上前端过滤。
2. `dataSchema.fields` 仅"备注" —— 全部业务字段位于明细页签。
3. `detail.tabs = [{key: 业务键(如 khda), label: 面板名+"明细", fields: 全部字段}]`。
4. `gridTabs = [{label: 面板名+"明细", rowSource: "rows", columns: 全部字段}]`。
5. 列表页内联编辑:新增/修改直接在明细行填写;保存=全量明细 upsert(缺席行=已删除);删除=勾选行后保存。
6. 参照来源:engine.queryRefRows 按 `metadata.singleDoc` 拉取单据并展平首个明细页签,filter/keyword 在前端应用。
7. 档案行软删(asp_cancel='Y')与旧系统一致。
8. 单单据面板隐藏单据切换按钮(◁◀ 第X/Y张 ▶▷),仅保留单据名与状态标识(PanelxList singleDocMode)。
9. **同码不允许重复(唯一键声明,2026-10-16)**:`yj_panel.config` 写 `{"uniqueKeys":["工序编码"]}`
   (组合键写 `[["仓库","仓位编码"]]`)即声明"这几列的取值在同一张档案里不得重复",三层各管一段:
   - **元数据**:只加一行 config —— 换面板/加一列都不改代码(与"加面板=插行"同一条规矩);
   - **后端** `ButtonService.ensureArchiveUniqueKeys`:保存前查"提交行之间"与"与库里其它存活行"两处,
     命中即 400 + 业务话术(排除本次作废行;整档提交时"缺席即删除"的行不算已存在;空值不参与);
   - **前端** `PanelxList.validateArchiveUniqueKeys`:保存前在**已载入的全量行**里查重,即时提示行号,
     且**不受"保存为草稿跳过必填校验"影响**(数据正确性 ≠ 填没填全);
   - **数据库**:过滤唯一索引(存活行唯一,`WHERE [asp_cancel]='N'`)是最后一道闸 ——
     脚本直插也拦得住,而**作废行不占码**,故"作废 → 重建同码"照常可用。
   样板:`bs_op` 工序档案(`ux_bs_op_code` + `migrate-op-code-unique-20261016.sql`)。

## 5. 字段与参照

| 数据类型 | 默认控件 | yj_field 映射 |
|---|---|---|
| 文本/整数/小数/日期 | 输入框/数字/日期 | data_type |
| 多行文本 | 多行输入框(autosize,1~6 行,**仅明细网格**) | data_type |
| 下拉框 | 选择器 | dict_sql(执行取首列选项) |
| 参照 | 弹窗 或 下拉(见 §5.1) | ref_panel + ref_field + display_field |

业务字段能对应基础档案时必须用参照定义;选项来自 dm_gx 字典(dict_sql),禁止前端硬编码。

**「多行文本」取舍**(2026-10-15,工序检验单三面板首用):

- 字面就是「这个字段的内容会超长、要折行显示」——**由 `data_type` 决定,不写面板/字段名单**,
  哪个面板哪个字段要多行就在库里改这一格;要恢复单行改回 `文本` 即可。
- **只在明细网格生效**:`place='header,detail'` 的字段是同一行 `yj_field` 同时供表头与明细,
  表头若也渲染多行框,4 列网格会被 6 行高的框撑开、下面整排字段被推下去留大块空白。
  口径来源:用户只说「明细行文字过长时可以多行显示」。
- 别把**短列**(如 检验单的 表区/行号/数量)也配成该类型 —— 上一版按"面板"放行就是这样
  把整面板的文本列一起变多行的,当场被撤回。

**怎么回滚**(2026-10-15 实测走通,两个方向都验过):

- 因为渲染认的是 `data_type`,**关掉只需要一条 UPDATE**:
  `tools/migrate-field-multiline-text-rollback-20261015.sql`(手动执行,**有意不进迁移链** ——
  一登记 DbSync 就会在链尾自动把功能关掉;判定口径见 `DbNormAudit` 检查 12 的 `allowOffChain`)。
- **不用重新打包、不用重启**:`PanelRegistry` 的元数据缓存是**按账套 30s TTL**,
  改完库里 ≤30 秒界面即切换(实测:同一份前端产物下,正式账套仍是多行、刚回滚的测试账套已回到单行并横向滚动)。
- 再开回来:重跑 `tools/migrate-field-multiline-text-20261015.sql`(幂等 UPDATE)即可。

### 5.1 参照字段双模(面板开发通用设置)

参照字段根据引用面板的数据行数**动态切换**交互模式:

| 引用面板行数 | 交互模式 | 实现 |
|---|---|---|
| **≤ 20 行** | 弹窗(RefPickDialog) | 点击字段 → 弹窗展示全量行,勾选导入 |
| **> 20 行** | 下拉(el-select) | 可输入搜索、远程过滤,直接选择 |

规则:
1. 判定时机:面板配置加载时(`loadCrg`),对全部参照字段并行调用 `engine.refRowCount(field)` 获取行数。
2. 缓存:判定结果存入 `refModeMap[fieldKey]`(dialog/select),面板生命周期内不再重复判定。
3. 下拉模式:`el-select` + `filterable` + `remote` + `remote-method`,选项由 `engine.refSelectOptions(field, keyword)` 远程获取。
4. 键映射:`refField`/`displayField` 必须用**中文标签**(引用面板的字段标签,非列名),与数据行键一致(后端 `refLabelOf()` 自动转换)。
5. `allow-create`:下拉模式允许输入不在列表中的值。
6. 新增参照面板数据导致行数跨越 20 条阈值时,刷新面板后自动切换模式。

## 6. 工具栏与状态

- 分组结构 `{name, actions}`;**首个动作=主按钮点击行为**,其余进 ▼ 下拉。
- 单据面板:**PANDA 一比一按钮组**(`PanelConfigService.PANDA_BUTTONS` 按面板注册,含组名/顺序/动作;仅收录前后端可执行的动作)。常见组:新增/选单/修改/保存(保存,保存新增,保存为草稿)/删除(删除,删除单据)/审核+审批(前端归一为一个审批组)/打印(打印,预览,导出)/查找(查找,刷新)/导入/更多(复制**主按钮**,放弃,草稿,中止类,表格调整,刷新)。
- 基础档案:新增/修改/保存/删除/查找/打印/导入/更多(维持 light-mes 形态)。
- 报表(明细/统计):查询(查询,刷新)/打印(打印,预览,导出)/更多(发送邮件,表格调整,退出)。
- 查询方案保留:前端 `toolbarGroups` 剥除 查询/查找 动作并与工具栏左侧独立「查询」按钮(查询方案弹窗)去重。
- 表单底部(`formPages[0].bottomOperationBarBtn`):PANDA 一比一 = 保存,删除,审核,弃审,(整单中止|中止执行,草稿),放弃。
- 未收录的 PANDA 动作(生单/转换/联查/设置/附件/消息/常用单据/打印模板等)因无后端实现不输出——规范要求按钮必须可点;`PanelActionHandler` 扩展后可加回。
- 状态机:草稿→提交审批→审批中→审批通过→已审核→弃审→草稿;审批驳回→草稿;已中止⇄已审核(整单中止/中止执行/草稿);已作废不可再保存。

### 6.2 未保存离开守卫(2026-09-01 规范)

**触发**:单据面板草稿态内联编辑存在未保存修改(表头/明细任一控件 @change 置脏,或与已保存基线快照不一致),**或当前单为「新增创建且尚未成功保存」的单据(`freshAdded` 标记持久化到 localStorage,刷新/重进后仍生效,零修改也算未保存),或「空白草稿」(草稿态且明细所有数值列全为 0/空——含单表式面板的占位行;单单据档案面板与无数值列面板不适用)**时,以下任一离开/切换动作:
- **离开本面板页**(`onBeforeRouteLeave`:菜单切换/页签关闭/浏览器后退)
- **面板内切换单据**:翻页 ◁◀▶▷/首页/末页(含跨页)、主表点行——统一经 `guardDocSwitch`/`guardPageAction` 拦截
- **工具栏「新增」与快捷入口「新增单据」(?new=1)**:经 `guardPageAction` 拦截,避免静默丢弃上一张未保存草稿
- **刷新/关闭浏览器**:`beforeunload` 原生确认兜底

**弹窗三态**(`leaveVisible` 模板弹窗;问句按状态区分:新建未保存/空白草稿=「当前草稿尚未保存,是否保存?(不保存将撤回该单)」,有修改的=「当前单据有未保存的修改,是否保存?」):

| 选择 | 行为 |
|---|---|
| 保存 | 走「保存」按钮路径(`saveInlineDraft('保存')`),成功后放行;失败留在本页 |
| 不保存 | **新建未保存过的**(freshAdded 标记命中)与**空白草稿**(已保存基线的明细数值列全 0/空)→ 撤回整单:走「删除」按钮路径,按开发规范留痕(`yj_doc_status.canceled='Y'` + `cancel_by/cancel_at`,并释放 `form_flow_link` 占用);**修改既有草稿的** → 仅放弃修改,保留单据(撤回判定取已保存基线,避免误删已填写内容) |
| 取消(关闭弹窗) | 留在本页(若页签已被关闭则自动补回) |

**脏检测双通道**:变更钩子置脏(表头 5 类控件/明细全部控件 @change、表头参照带回、新增明细行)+ 基线快照对比(载入/保存成功后 `markSavedSnapshot`)。保存成功与重新载入均清脏。

### 6.1 审批流按钮状态

| 动作 | 可用条件 | 前端拦截 |
|---|---|---|
| 提交审批 | 当前单据=草稿 | isDisabled 检查 |
| 审批通过/驳回 | 当前单据=审批中 + 用户有审批权限 | APPROVE_ACTIONS + user.approvePanels |
| 弃审 | 当前单据=已审核 | isDisabled 检查 |
| 审核(直接) | 当前单据=草稿 **且用户在直审名单里且是管理员** | isDisabled + `canDirectAuditHere` |

**直接「审核」入口怎么开(2026-10-17 制程检验单先例)**:2026-09-22「直审收权」后,侧栏审批组
(`hasApprovalBtns`:标准流文书 / QC_INSP_REC / RD_DOM_TEST)只给「提交审批 → 审批通过」,
不再有直审按钮;后端 `ButtonService.audit()` 也硬拒非管理员(「仅管理员可直接审核,其他角色请走提交审批」),
且**走两级审批的质量单据**(`ADMIN_L2_PANELS` = QC_DOC_PREPARER 那 8 张)连管理员都不给直审。

工序检验单一族(制程/成型/切炭/组装/首件)既不在那 8 张里、也没有审批流 ⇒ 直审是它们唯一的出口。
前端在 `PanelxList.vue` 里单开一个名单:

```js
const DIRECT_AUDIT_PANELS = ['QC_PROC_INSP']     // 要放开哪张单就加哪个面板码
const canDirectAuditHere = computed(() => DIRECT_AUDIT_PANELS.includes(String(panelCode.value)) && user.isAdmin)
```

侧栏渲染「审核 / 弃审」两个 `.as-side-btn`(位置在审批组之后、删除组附近),置灰交给
`isDisabled('审核'|'弃审')`(草稿才可审、已审核才可弃审)—— **权限只在前端显隐,后端仍会再校验一次**,
所以名单与后端口径必须一致,否则非管理员点了只会拿到 403。
⚠ 验证:**界面只读断言**(CDP 探针,绝不点审核 —— 页面可能连着正式账套),
真正的审核/弃审落库往返在**测试账套**上跑 `node tools/archive/_qc-proc/_api-proc-audit.mjs`
(新增 → 保存 → 审核(带审核意见) → 审核后保存被拒 → **审核留痕断言** → 弃审 → 清理,13 项)。

**审核记录(审批情况)—— 直审也必须留痕(2026-10-17 用户口径「审核还有审核记录之类的功能在研发管理模块内实现很多」)**:
全系统的审批留痕只有**一张表** `yj_form_approval`(action/result/node_no/operator/opinion/create_time),
服务端 `recordApproval(...)`,读取走 `/px/getApprovalHistory`,前端弹窗 `ApprovalHistoryDialog.vue`(侧栏「审批情况」)。
研发管理那套动作(提交/通过/驳回/会签/中止/撤销/弃审…)**每一个都留痕**,唯独直接 `audit()` 只写
`yj_doc_status.shr/shsj` ⇒ 制程检验单只有直审一条路,**审完在「审批情况」里什么都看不到**。修法三件套:

1. `ButtonService.audit()` 在**竞态守卫之后**补 `recordApproval(def.code(), no, "AUDIT", "APPROVED", auditOpinionOf(formData))`
   —— 位置在守卫之后,被守卫挡下的那次不留痕;`auditOpinionOf` 是新增的小工具:前端直审弹窗填的是
   **「审核意见」**,而老的 `opinionOf` 只认「审批意见」,直接复用会"动作有了、意见丢了"。
2. `queryApprovalHistory` 排序由 `id ASC` 改成 **`create_time ASC, id ASC`**:历史补录是后插的行,
   按 id 排会把时间倒挂(补录行的 id 比当时的弃审行大)。
3. 历史补录迁移 `tools/migrate-qc-proc-insp-audit-trail-20261017.sql` —— 本改动**之前**已直审过的单据,
   按其 `yj_doc_status(shr/shsj)` 补一行 `AUDIT/APPROVED`,意见注明「（历史补录：直接审核）」,不冒充真实意见;
   只针对 QC_PROC_INSP(其它面板走 提交审批→审批通过,本就有 APPROVE 行,补录会重复)。幂等 + 自检。
4. 弹窗侧:`actionLabel/tagType` 加 `AUDIT`(标签走 `tt('审核')`);弃审行的 `result` 后端存的是 `PENDING`,
   直映会显示「审批中」与动作矛盾 ⇒ 弃审行按动作显示 **「已弃审」**(新词条由 `_i18n-proc-cols.mjs` 落 10 语言)。
5. 侧栏:直审名单面板额外给一个 **「审批情况」** 只读入口(不限单据状态、谁都能看)。
   取证:`node tools/archive/_qc-proc/_api-approval-history.mjs http://127.0.0.1:8090 QC_PROC_INSP <单号>`
   (只读打印审批记录),界面断言在 `_cdp-proc-cols.mjs` 第 ⑦ 段。

⚠ **打包顺序(踩过的坑)**:`mvn package` 必须在**停掉 8090 之后**跑 ——
实例占着 `target\yinjia-mes-backend-0.1.0.jar` 时 repackage 改名失败,磁盘上会留下**瘦 jar**
(无 `BOOT-INF/lib`,699 条目),此后 `start-prod.ps1` 起的进程**秒退**。
判据:`[IO.Compression.ZipFile]::OpenRead(jar)` 看有没有 `BOOT-INF/lib/*.jar`。
救法:`start-prod.ps1 -Stop` → `mvn -o package -DskipTests` → `start-prod.ps1`。

**审批动作前的落库与失败归因(2026-10-17 用户报障「未保存可以直接审核,出现错误」)**:
点「审核 / 提交审批 / 提交会签」时,若当前单据是可编辑草稿(`draftEditable`),前端会**先静默保存一次**
(审批必须基于库里的数据,否则状态刷新后看到的是库里旧数据)。问题出在保存**没通过**时:
此前只弹一句保存侧的校验文案(实测就是「请至少添加一行明细」),用户根本不知道自己点的是审核、
也不知道要先补什么,看起来就像"审核报了个莫名其妙的错"。
修法:`saveInlineDraft(..., { reason })` —— 审批路径把动作名传进去,失败提示统一变成
**「{a}前需先保存：<原因>」**(例:「审核前需先保存：请至少添加一行明细」),且**只有保存成功才继续审核**;
保存失败的三种来源(唯一键查重 / 必填校验 / 后端保存报错)都走同一前缀。新增词条 `'{a}前需先保存：'`
由 `tools/gen/_i18n-proc-cols.mjs` 落进 10 个语言文件。
验收:`node tools/archive/_qc-proc/_cdp-audit-unsaved.mjs`(测试账套真点,13 项:空单点审核只提示不误审、
未保存内容点审核自动落库并审核成功、弃审回草稿、无 JS 异常、结束自清探针单)。

## 7. 表格列自定义(面板开发通用设置)

所有面板的表格列支持三种自定义,入口在"更多 ▼"→"表格调整":

| 功能 | 操作 | 存储 |
|---|---|---|
| **列排序** | 拖拽(⋮⋮ 拖动)或箭头(▲▼) | yj_field.seq |
| **栏名修改** | 文本框输入别名(留空=原标签) | yj_field.alias |
| **显示/隐藏** | 勾选框 | yj_field.visible |

规则:
1. **数据键不变**:列排序和改名仅影响显示,数据行的键始终为原标签(yj_field.label)。列头显示名通过 `gridTabs[0].columnAliases` 映射:`显示名 = columnAliases[原标签] || 原标签`。
2. **不可见列**:yj_field.visible=0 的字段不出现在 gridTabs[0].columns 中,后端直接排除。
3. **保存**:调用 `POST /api/px/saveColumnPrefs` `{panelCode, columns: [{label, alias, visible}]}`,更新 yj_field 后自动刷新面板(清空 cfgCache → 重载配置与数据)。
4. **恢复默认**:对话框内"恢复默认"按钮清空全部 alias 并设 visible=true,需点"保存"生效。
5. **所有面板类型生效**:单据明细、基础档案明细、报表表格均可使用。

### 7.1 合计行的位数口径(2026-10-03 用户口径:合计与明细一致)

用户报「现在的单据明细与合计的小数点后位数有差距,要合计保持与明细一致」——
明细列在库里绝大多数是 `decimal(18,4)`(HSDZ_MES 实测 scale=4 共 291 列、scale=2 仅 11 列、scale=6 共 8 列),
而合计原先一律 `Math.round(sum * 100) / 100`(恒 2 位)⇒ 明细显示 `0.132`,合计却显示 `0.13`。

**唯一口径:合计的小数位数 = 该列明细值里最多的小数位数**(整数就 0 位),末位做一次十进制四舍五入;
没有任何可加项时返回 null(由调用方决定显示 `''` 还是 `0`)。实现是
`frontend/src/core/panel/sumTotals.js` 的 `sumKeepScale(values)` / `sumColumn(rows, key)`(有单测)。

规则:

1. **禁止再写 `Math.round(x * 100) / 100` 当合计** —— 等于把 decimal(18,4) 的明细砍成 2 位。
2. 走同一助手的四处(改合计只改这里,别各写各的):`PanelxList.sumMethod`(明细页脚合计行)、
   `PanelxList.archSumsMap`(档案分页全量合计)、`PanelxList.summaryRows`(汇总页签分组小计 + 尾行总计)、
   `PanelxForm.summarize/summaryRows`(单据表单明细合计 + 明细汇总子页签)。
3. 顺带治浮点尾差:分组小计原先裸加,`1.1 + 2.2` 会显示 `3.3000000000000003`,合计行却是 `3.3`。
4. 纸面打印的「总　计」同口径(`business/print-formats.js` 的 `printPuOrder`/`printPuOrderNoAmount`)。
5. 只治**显示口径**:落库值仍由后端 `CalcRuleService` 的规则 round 决定(见 `core/panel/calcRules.js`)。
   带位数上限的输入类合计(送料/打印量弹窗的「本次合计」)保持 2 位,因为它必须与后端 round2 的校验一致。
6. 验收:`node tools/archive/_verify-total-decimals.mjs <面板> <单据号> [summary|form]`
   (CDP 无头 Edge,读真实明细单元格与合计行,逐列比位数与数值)。

### 7.3 纸面表 → Excel 导出(制程检验单先例,2026-10-17)

## 8. 列头点击筛选(面板开发通用设置)

所有表格的列头支持点击后输入文字实时筛选该列数据:

| 操作 | 效果 |
|---|---|
| **点击列头** | 列头出现内联筛选输入框(自动聚焦),原文字变为蓝色加粗 |
| **输入文字** | 该列数据实时过滤(包含匹配,不区分大小写) |
| **多列同时筛选** | 多列条件 AND 关系 |
| **点 [关键词 ×] 标签** | 清除该列筛选 |
| **按 Esc** | 关闭筛选输入并清除 |
| **正常状态** | 列头右侧显示灰色 🔍 图标 |
| **筛选中状态** | 🔍 变为蓝色标签 `[关键词 ×]` |

实现:
1. 前端状态:`colFilterText`(各列筛选文本 Map) + `filterColProp`(当前激活列)。
2. 渲染:`el-table-column` 的 `#header` 插槽渲染列名+图标/标签+输入框;`#default` 不变。
3. 数据过滤:`blockRows(b)` 返回前调用 `applyColFilters(rows, cols)`,逐列检查 `colFilterText[col.prop]` 非空时 `includes` 过滤。
4. 适用范围:明细区块(blockRows)、BOM 主表(mainRows)、报表表格(reportColumns)。
5. **纯前端过滤**:不对后端发起请求,筛选范围=当前已加载的数据。
