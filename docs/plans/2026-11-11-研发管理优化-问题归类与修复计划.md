### 1.3 代码事实（决定改法，不是我想怎么写）

1. **「只看自己的单」是服务端硬闸门**：`QueryService.OWN_DOCS_PANELS = {RD_SAMPLE_EXT, RD_SAMPLE_INT}`，
   `queryDocs` 里对非管理员强制 `AND asp_user1 = <当前账号>`；`loadOneDoc` 还单独校验单据归属。
   **这是 R4-1 / R5-1 的直接原因**——刘磊不是管理员，所以他只能看到自己创建的外部样品单。
2. **内部单已无审批**：`hasApprovalBtns` 不含 `RD_SAMPLE_INT`，`rd_sample_int_detail` 有 `申请人/样品状态`
   等 13 列，行级归属由 `ButtonService.applySampleIntRowRules` 实现（`edit_others` 词控制能否改他人行）。
   → R6 的「新增即增行 / 不做审批 / 草稿可改归档不可改 / 每账号只能改自己行 / 管理员可改所有」**已实现**。
   R6 里**未实现**的是：归档列表入口、汇总进度表、点编号跳转。
3. **内部单的行归属是「行」级，但可见范围是「单」级**：`OWN_DOCS_PANELS` 按 `rd_sample_int_head.asp_user1`
   过滤 ⇒ 即使同一张单里有 25 行属于我，只要单头不是我就整单看不到。**这是 R5-1 的真正机制**：
   内部单的实际模型是「一张单 = 多条独立行」，用单级归属去管必然错。
4. **外部单没有「进度描述」字段**：`rd_sample_ext_head` 列 = 单据编号/单据日期/客户名称/费用/期望交期/
   产品整体规格/炭棒规格/样品数量/组装要求/产品功能/背景/性能要求/配方及工艺要求/申请/审核/确认/备注。
   全库无任何「进度/状态描述」列。R3 需要新增字段（头表 1 列，或独立明细表）。
5. **一级审批回填弹窗只白名单 3 列**：`ButtonService.applyL1Backfill` 的
   `allowed = {配方及工艺要求, 组装要求, 性能要求}`。二级审批**没有任何回填入口**（`openSampleL1` 只在
   `单据状态=审批中` 且 panels ∈ {RD_PROD_INFO, RD_SAMPLE_EXT} 且一级节点时触发）。→ R2 根因。
6. **样品单不属于 `DOC_ARCHIVE_PANELS`**：所以既没有「保存即送审」，也**没有归档按钮**，
   更没有「归档列表」。单据状态来自 `yj_doc_status`（pending/archived/modify_state）。
   → R6「设置归档列表选项」= 需要新做一个归档动作 + 列表筛选，不是改现有按钮。
7. **「选型号」下拉挂在数据格上**：`recordSheetConfigs.js` 里 `{ key: '外径mm', span: 2, moldPick: true }`
   位于**标签行之下的数据行**，所以截图里下拉出现在「炭棒外径mm」列内。R1 要求移到「炭棒尺寸」标签单元格下方，
   且 `.no-print` 要覆盖到它（当前 `rs-mold-pick` 无 `no-print` 类，打印会印出来）。
   ⚠ 同一段配置被 **RD_MOLD_PROC 与 RD_X_SINTER 共用**（`cfg.sections` 同一份），改一处两张单一起变。

### B 类：可见范围（R4-1 / R5-1）—— 这是本次最需要拍板的一条

**现状机制**：`OWN_DOCS_PANELS` 一律按 `head.asp_user1 = 当前账号` 过滤，非管理员严格执行。
这满足了旧口径「只能看自己填的」，但**刘磊要「看到全部外部样品单」就必然冲突**。

建议改成**「按权限词决定可见范围」**，与项目里 `edit_others` 同一套做法：

```
新增权限词 view_all（可见全部单据），仅对 RD_SAMPLE_EXT / RD_SAMPLE_INT 生效：
  · 勾了 view_all 的角色 → 不追加 asp_user1 过滤（看到全部）
  · 未勾 → 现状（只看自己的）
  · 管理员恒放行（已是现状）
配置：文件负责人(1025) 勾上 ⇒ 刘磊立刻能看到全部外部样品单（R4-1 达成）
```

理由（为什么不用「角色白名单硬编码」）：项目里 `edit_others` 已经是「面板权限 + 组织架构勾选」的模式
（`SysAdminController.SAMPLE_INT_ACTIONS` + `PanelPermissionService.PERM_LABEL`），再自造第二套会让两个词
的配置界面不一致；且 R7 明确要求「做成面板权限，把个人角色的权限配好」。

**内部单（R5-1）要单独处理**：内部单是「一单多行、行各归其主」，用单级 `asp_user1` 过滤必然是错的。
建议按行判断：
```
RD_SAMPLE_INT 的可见性 = 该单下存在 申请人=我 且未作废的明细行
   ∨ 我有 view_all
   ∨ 我是管理员
```
但这会让「单据列表」出现只含我几行的单，**与「一张单=多条独立行」的模型一致**（用户原话：
「每一行数据就像一张独立的单据一样」）。⚠ 代价：单头字段（单据编号/日期/备注）对非创建人可见，
需确认这是否可接受。

| 项 | 内容 |
|---|---|
| 改法 | ① `SysAdminController` 为样品两面板加 `view_all` 动作（label「可见全部单据」）；<br>② `PanelPermissionService.PERM_LABEL` 加词；<br>③ `QueryService`：`OWN_DOCS_PANELS` 分支改为「无 view_all 才过滤」；内部单再叠加行级 OR 条件；<br>④ `AuthController` 下发 `viewAllPanels`，前端 `stores/user.js` 白名单加键；<br>⑤ 迁移脚本给 1025/1026 授权（幂等，按角色名而非 id）。 |
| 验收 | 用 `liulei` 登录（生产）：外部样品单列表条数 = 全表条数（非 1）；用 `sampler` 登录：仍只见自己的；管理员：全部。 |
| 待确认 | ① `view_all` 是否只给**文件负责人**，还是同时给研发审核？② 内部单按行可见（能看别人单头）是否可接受？ |

  （不是「配方信息」），对应权限词就是现有 `edit_others`。**已实现**，缺的是可见范围（P3）。
