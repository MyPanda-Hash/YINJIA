# 采购订单「打印材料码」批次号方案（供应商自行打码场景）

| 属性 | 内容 |
|---|---|
| 文档类型 | 实施计划（**待拍板，尚未实现**） |
| 适用场景 | 采购订单打印材料码时确定批次号，并把它带进「生成送料暂收单」对话框 |
| 维护状态 | 草案（2026-10-04 提出） |
| 相关 | `tools/migrate-batch-no-on-generate.sql`（现行批次号口径）· `docs/development/数据库规范.md` §1/§2 · `docs/development/代码规范与防臃肿.md` |

**目标：** 让「供应商自己打码」这条链在**打印材料码的那一刻**就能定下批次号（按既有格式预填、可改），
把这张码上印的批次号**记住**并**预约**对应的订单行数量，随后在「生成送料暂收单」对话框里
**按这批已打印数据直接生单或组合生单**，且预约量从余量里扣减。

**一句话本质：** 批次号从「生单时产生」**前移**到「打印时登记」——打印记录成为批次号在该订单上的**权威登记处**，
生单只是**消费**这份登记，不再重新取号。

## 一、现状（已核查，带出处）

| # | 事实 | 出处 |
|---|---|---|
| 1 | 采购订单「打印材料码」= 取当前单据明细 → `printProductCards`（75×100mm 产品标识卡，一行一卡）；**`批次` 与 `生产日期` 传空**，纸面留横线手填；二维码 = `公司代码@物料编码`（**无批号段**） | `PanelxList.vue` 6109-6140；`print-formats.js` 355-399 |
| 2 | 批次号现行口径 = **供应商编码去掉 `YJ-` 前缀 + `-` + 生单当天 yyyyMMdd**（如 `YJ-TX` ⇒ `TX-20260910`），**在生单那一刻写入**，下游逐站继承 | `BatchService.buildBatchNo` / `PushGenerateHandler.generateBatch` |
| 3 | 批次号目前挂在**单头**（一张暂收单 = 一个号），明细行随单头（`syncBatchNo` 每次保存/审核覆盖写） | `BatchService.syncBatchNo` |
| 4 | 余量口径：`剩余 = 订单数量 − Σ form_flow_link.linked_quantity(ACTIVE) + 已退回`；**打印完全不参与占用** | `PushGenerateHandler.batchLines` / `overAllowance` |
| 5 | 下游单作废/删除 → `form_flow_link.link_status='RELEASED'`，来源行重新可选；生单时 link 的 `batch_no` 已写入 | `VoucherFlowService.release` / `PushGenerateHandler.generateBatch` |
| 6 | 超送比例系统参数 `receive_over_ratio = 0.05`（5%，上限硬钳 50%） | `yj_app_setting`；`BatchService.overRatio` |
| 7 | `bl_pu_order.批次号` 列**存在但 4456 行全空**，且 `yj_field` 里是 `hidden=1/visible=0` 的隐藏同步字段 —— **不能当打印批次号用** | 实测 `sys.columns` / `yj_field` |
| 8 | `qr_batch_registry` + `QrBatchService`（批号 = `yyyyMMdd`+3位流水）是 V2.0 设计遗留：**表 0 行、前端零引用**，且取号规则与现行口径**冲突** | `QrBatchService.java`；`ShellController` `/qr/*`；前端 grep 0 命中 |

**结论：** 现状下打印阶段**确实没有号**，且没有任何地方能记住"这张纸上印的是哪个号"——
这正是本条需求的根源，也说明**必须新增一份持久化的打印记录**，靠现成表补不出来。

## 二、你提的方案评估

你的方案（打印弹窗填批次号 + 勾行号与数量 → 生单弹窗多一行已打印数据 → 直接生单或组合生单 →
在余量里扣减）**方向是对的**，下面是需要补钉的四件事，否则实现出来会出漏子。

### 2.1 必须承认"批次号前移"这个新状态（最关键）

批次号一旦印在标签上贴到实物，它就是**物理事实**，系统只能服从。所以：

> **打印时登记的批次号 = 权威。生单时必须用它，绝不能按公式重算。**

推论（三条硬规则）：
1. 生单时若来源订单已有「已打印未生单」的预约，**批次号取自预约**，忽略公式；
2. **一张暂收单只能装同一个批次号的预约行**（因为暂收单只有一个单头号）；
3. 对话框里若勾了已打印行，**顶部的批次号输入框必须锁定为该批次号**（否则会出现"标签是 A、系统里写成 B"）。

### 2.2 打印即占用，就必须有"释放"出口

你说"在余量里面扣减" ⇒ 打印 = **预约**。那打错了、货不来了怎么办？
必须同时给：**打印记录作废/释放**（软删 + 释放预约量），否则余量被永久吃掉，后续再也送不了料。

### 2.3 组合生单要按批次号**分组**，而不是"凑一张"

"组合生单要按照打印的批次号来"——不同批次号的已打印行**不可能**合成一张暂收单（一单一号）。
建议不要报错拦人，而是**按批次号自动分组，一次点击生成 N 张暂收单**（每组一张），
并在确认前明确提示"将生成 2 张：A 组 3 行 / B 组 1 行"。

### 2.4 一个订单行可以分多次打印（1:N）

同一行先打 100、下月再打 50 —— 所以打印记录**必须是订单行的子表**，
不能往 `bl_pu_order` 加一列（第 7 条已实测那列也确实是空的历史遗留）。

## 三、数据模型（按《数据库规范》）

新增**一对**头行表（规范 §1.1 硬规矩 3：单据必须 `bd_` 头 + `bl_` 行成对，禁止单表承载头行）。

> **语义：一次打印 = 一张「材料码打印单」，带一个批次号；行 = 该次打印覆盖的订单行与数量。**
> 头存批次号（一批次号一张头，重复打印复用同一张），行存每行的打印量与订单行锚点。

```sql
-- 头：材料码打印单（一批次号一张；重复打印复用，不新增占用）
CREATE TABLE bd_pu_label (
  id            bigint identity PRIMARY KEY,
  单据编号      nvarchar(40)  NOT NULL,              -- 前缀 MQ，如 MQ-2026-10-0001（FormNoService）
  单据日期      date          NOT NULL,
  采购订单号    nvarchar(200) NOT NULL,              -- 锚：bd_pu_order.单据编号
  供应商编码    nvarchar(100) NULL,                  -- 打印时快照（订单编码可能被改）
  批次号        nvarchar(100) NOT NULL,              -- ★ 本方案的核心：打印时定稿的批次号
  打印人        nvarchar(50)  NULL,
  打印时间      datetime2     NULL,
  打印次数      int           NOT NULL DEFAULT 0,    -- 重打累加，便于追溯
  备注          nvarchar(500) NULL,
  asp_user1 nvarchar(50) NULL, asp_time1 datetime2 NULL,
  asp_user2 nvarchar(50) NULL, asp_time2 datetime2 NULL,
  asp_cancel nvarchar(1) NOT NULL DEFAULT 'N'        -- 软删；作废即释放预约
);
CREATE UNIQUE INDEX uq_bd_pu_label ON bd_pu_label (采购订单号, 批次号) WHERE asp_cancel = 'N';

-- 行：本批次号下，每个订单行打印了多少
CREATE TABLE bl_pu_label (
  id            bigint identity PRIMARY KEY,
  单据编号      nvarchar(40)  NOT NULL,              -- → bd_pu_label.单据编号
  采购订单行号  nvarchar(50)  NULL,                  -- 展示用（bl_pu_order.行号）
  采购订单行id  int           NULL,                  -- ★ 锚：与 form_flow_link.source_line_key 的「#id」同源
  物料编码      nvarchar(100) NULL,
  物料名称      nvarchar(200) NULL,
  规格型号      nvarchar(200) NULL,
  计量单位      nvarchar(50)  NULL,
  打印数量      decimal(18,4) NOT NULL DEFAULT 0,    -- 本次（=本批次号下）打印量
  备注          nvarchar(500) NULL,
  asp_user1 nvarchar(50) NULL, asp_time1 datetime2 NULL,
  asp_user2 nvarchar(50) NULL, asp_time2 datetime2 NULL,
  asp_cancel nvarchar(1) NOT NULL DEFAULT 'N'
);
CREATE UNIQUE INDEX uq_bl_pu_label ON bl_pu_label (单据编号, 采购订单行id) WHERE asp_cancel = 'N';
```

**落库要求（规范硬规矩，缺一即任务未完成）**
- 同脚本写 `MS_Description` 表/列中文注明（幂等写法见 `tools/migrate-table-comments.sql`）；
- 新表登记进 `tools/db-inuse-tables.txt`（在册台账）与 `docs/development/数据库表清单.md`；
- 迁移脚本登记进 `tools/db-migrations.txt`，**两个账套都执行**，`DbSync` 跑到「执行 0、失败 0」；
- 表结构变更后重跑表清单末尾两条命令。

**不新增"已生单数量"列**（重要设计选择，见 §五）。

## 四、打印弹窗设计（`MaterialLabelDialog.vue`，新组件）

现在的「打印材料码」是一次性动作（无弹窗）。改为弹窗，弹窗内**所见即所打**。

### 4.1 主界面与规则

```
┌─ 打印材料码 · 采购订单 YJ-20260916-03 ───────────────────────────────┐
│ 批次号 [ KBL-20261004              ]  ← 按公式预填、可改           │
│         (供应商编码 KBL ← 去 YJ- 前缀 + 当天 20261004)              │
│                                                                      │
│ ☑ 行号 物料编码    物料名称   规格    订单数量 已送 已打印 剩余可打 本次打印 │
│ ☑ 1    YJ-HDN-001  XX材料     ...     400      0    0      420      100   │
│ ☐ 2    YJ-HDN-002  YY材料     ...     200     50    0      160        0   │
│ 合计本次打印: 100                                                     │
│ 提示: 打印上限 = 订单数量×(1+超送比例 5%) − 已送 + 已退回 − 未生单预约  │
│                                  [取消]  [作废选中打印记录] [确定并打印] │
└──────────────────────────────────────────────────────────────────────┘
```

**字段与规则**

| 项 | 规则 |
|---|---|
| 批次号 | 默认 `buildBatchNo(供应商编码, 当天)`（同现行公式，**复用后端同一实现**，不重写一份）；可人工改；长度 ≤ 100（列宽） |
| 勾选列 | 行级勾选；勾选即参与本次打印 |
| 本次打印数量 | 默认 = 该行「剩余可打」；可改小；`0 < 本次 ≤ 剩余可打` |
| 剩余可打 | `订单数量×(1+超送比例) − 已送 + 已退回 − 未作废的打印量`（与「可送上限」同口径，超送 5% 现设） |
| 确定并打印 | ① 写 `bd_pu_label`/`bl_pu_label`（同订单+同批次号则复用头、行就地改量）→ ② 出纸 |
| 作废选中打印记录 | 软删该批次号下的行/头 → **立即释放预约**（余量回来） |
| 重打 | 同一(订单,批次号)复用同一张头：`打印次数+1`，**不重复占用** |
| 纸面 | `批次` 填批次号（不再是横线）；二维码带上批号段 |

**二维码内容（跟随采购入库单标识卡口径）**

- 打印时带批次号 ⇒ `公司代码@物料编码@批次号`（如 `0@XH-SX80250SX@KBL-20261004`）；
- 现有实现是 `公司代码@物料编码`（`productCardQrText` 天然支持三段，只要把 `批次` 传进去即可）；
- ⚠ 于是同一物料会同时存在**带号**（新打）与**不带号**（历史标签）两种码，**扫码解析端要两种都认**。

### 4.2 已有打印记录列表（**取代"查询面板"，零新增面板**）

用户明确不要新加面板（2026-10-04），所以**反查入口就放在这张弹窗里**：打开弹窗时，
在明细表下方并列显示**该采购订单已登记的打印记录**：

```
┌─ 已打印记录（本订单） ───────────────────────────────────────────────┐
│ 批次号          打印量  已生单  未生单  行数  打印单号        打印时间  次数 │
│ KBL-20261004    100     0       100     1     MQ-2026-10-0001 10-04 09:12  2 │
│ [作废]  ← 软删该记录，预约量立即释放回余量                            │
└──────────────────────────────────────────────────────────────────────┘
```

- 列表数据由 `/px/puLabel/lines` 一并返回（见 §七），**不新增面板、不新增菜单、不配权限**；
- 「作废」= §四 的释放出口，放在这里最顺手（看得见"这批还压着多少余量"再决定废不废）；
- 台账登记仍照做（`tools/db-inuse-tables.txt` / `数据库表清单.md` 是**表级**登记，与面板无关）。

## 五、余量口径与"已生单量"的派生（建议的核心取巧点）

### 5.1 公式

| 量 | 公式 |
|---|---|
| 已送 | `Σ form_flow_link.linked_quantity WHERE source_line_key=? AND link_status='ACTIVE'` |
| 已退回 | 现有 `returnedByOrderLine`（已审核未作废的退回单） |
| **已打印量** | `Σ bl_pu_label.打印数量 WHERE 采购订单行id=? AND 未作废`（跨该订单所有批次号） |
| **未生单预约** | `Σ (bl_pu_label.打印数量 − 已生单量)` ⚠ 见 5.2 |
| 可打印上限 | `数量×(1+超送比例) − 已送 + 已退回 − 未生单预约` |
| **剩余可送** | `数量 − 已送 + 已退回 − 未生单预约`（**打印预约吃余量**） |

### 5.2 「已生单量」不建列，从 `form_flow_link` 派生

> `已生单量(订单行 × 批次号) = Σ form_flow_link.linked_quantity`
> `WHERE source_line_key = 该行 AND batch_no = 该批次号 AND link_status='ACTIVE'`

好处（这也是我建议不建计数器列的原因）：

- **作废/删除下游单时自动回落**：`VoucherFlowService.release` 把 link 置 `RELEASED`，
  预约自动回到"未生单"，**零额外回滚代码**、不会与既有释放逻辑分叉；
- 与余量口径**同一真源**，不会出现"预约说已生单、link 说没生"的两套账。

**前置条件（已于上一轮做完）**：生单时把批次号写到 link ——
`PushGenerateHandler.generateBatch` 现在会 `UPDATE form_flow_link SET batch_no=? WHERE batch_id=? AND ISNULL(batch_no,'')=''`。
**老数据**里 batch_no 为 NULL 的 link 不参与按号统计，所以"打印前的历史送料"不会被误计入某个新批次号。

### 5.3 边界情形（需要在实现时明确）

| 情形 | 建议口径 |
|---|---|
| 打印量 > 订单剩余 | 拒绝，提示上限（含超送额度） |
| 本次生单量 < 预约量（少送） | 允许；差额仍留在预约里，可下次再送 |
| 本次生单量 > 预约量（多送） | 允许，但**多出的部分属于未打印量** → 生单后提示"本次有 N 未打印标签，是否补打？"（P1） |
| 已打印行与未打印行混在一张暂收单 | 允许（整单同一个号）——但要提示"其中未打印 X" |
| 已打印行来自**不同批次号** | 不允许合成一张；按批次号**分组拆成多张**（§2.3） |
| 暂收单被作废/删除 | 预约自动恢复（§5.2）；批次号仍不回收（现行口径：会跳号不重号） |
| 打印记录作废后重打 | 新建/复用头与行，重新占用 |
| 历史订单（无打印记录） | 完全不受影响：生单仍按公式取号（打印弹窗可跳过） |

## 六、生单弹窗对接（`BatchSendDialog.vue`）

### 6.1 数据来源

`POST /px/batchFlow/lines` 的返回里，每行**追加**该行的打印预约明细：

```jsonc
{
  "lines": [{
    "lineKey": "YJ-20260916-03#12", "行号": "1", "数量": 400, "已送数量": 0,
    "已退回数量": 0, "剩余数量": 400, "可送上限": 420,
    // ★ 新增：该行的已打印预约（按批次号）
    "打印预约": [
      { "批次号": "KBL-20261004", "打印数量": 100, "已生单量": 0, "未生单量": 100,
        "打印单号": "MQ-2026-10-0001", "打印时间": "2026-10-04 09:12" }
    ],
    "未生单预约合计": 100
  }]
}
```

### 6.2 界面

- 主表保持现状（行号/物料/数量/已送/已退回/剩余/可送上限/本次送料数量），**"剩余数量"改为已扣预约**；
- 主表下方新增一张只读小表 **「已打印待生单」**：`批次号 | 行号 | 物料 | 打印数量 | 已生单 | 未生单 | 打印单号`，
  带勾选列 —— **勾选即"按这一行生单"**；
- 勾选规则：
  - 勾 1 个批次号下的若干行 ⇒ 生成 **1 张**暂收单（组合生单）；
  - 勾到**多个批次号** ⇒ 提示并**按号拆成 N 张**；
- 勾选已打印行后，顶部**批次号输入框锁定**为该号并显示"已按打印批次号锁定"；
  未勾任何已打印行时保持上一轮做的"可改、默认按公式预填"；
- 已打印行的「本次送料数量」默认 = 未生单量，可改小（少送）。

### 6.3 后端生单校验（`generateBatch`）

在既有的批次号覆盖逻辑上再加一层（**只加校验，不改变已有分支语义**）：

```
若本次目标批次号 T 与「被勾选的已打印行」的批次号不一致 → 拒绝，报错列出冲突行
若 T 无对应打印记录（纯未打印生单）→ 维持现状：用对话框传入的号或按公式取号
```

## 七、接口清单（拟新增/改动）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/px/puLabel/lines?orderNo=` | 打印弹窗取数：订单行 + 已送/已打印/剩余可打 + **预填批次号**（服务端算，复用 `buildBatchNo`）+ **本订单已有打印记录**（§4.2，取代查询面板） |
| POST | `/px/puLabel/print` | 登记打印：`{ 采购订单号, 批次号, lines:[{采购订单行id, 打印数量}] }` → 返回打印单号与行；幂等（同订单+号复用头） |
| POST | `/px/puLabel/void` | 作废打印记录（软删 + 释放预约）：`{ 单据编号 }` 或 `{ 采购订单号, 批次号, 行ids }` |

## 十、已拍板（2026-10-04，用户口径：前五条按推荐、第六条不新增面板）

| # | 问题 | **定稿** |
|---|---|---|
| 1 | 打印弹窗里能否改批次号 | **可改**（人工优先）；同一订单 + 同一批次号**复用同一张打印头**，重打不重复占用 |
| 2 | 打印是否立即占用余量 | **立即占用**；必须同时提供「作废选中打印记录」入口来接释放 |
| 3 | 勾到多个批次号 | **按批次号自动拆成多张暂收单**（不报错拦人），生成前提示将拆成几张 |
| 4 | 已打印行 + 未打印行能否混在一张暂收单 | **允许**（整单同一个号），但对话框明确标注"其中未打印 X"；生单后可选补打 |
| 5 | 打印数量上限 | `订单数量×(1+超送比例) − 已送 + 已退回 − 未生单预约`（与「可送上限」同口径；现设超送 5%） |
| 6 | 单据号 vs 查询面板 | **拆开处理**：<br>· **单据号 `MQ-yyyy-MM-nnnn`：采纳** —— 走 `FormNoService.next(prefix,user)`，号池是 `s_allno`（按 `lb=前缀` 取号），**不需要任何面板注册**，零面板成本；<br>· **查询面板：取消** —— 那确实要往 `yj_panel`/`yj_field` 插行（新面板 = 新菜单项 + 权限 + 多语言全套），用户明确不要；反查改由打印弹窗内联列表承担（§4.2） |

**由此产生的两处口径（实现时必须照此）**

- `bd_pu_label`/`bl_pu_label` **只建表、不建面板**：不插 `yj_panel`/`yj_field`、不进菜单、不配权限；
  仅登记进 `tools/db-inuse-tables.txt` 与 `docs/development/数据库表清单.md`（在册台账是表级别的，与面板无关）。
- 打印记录的**唯一查看入口 = 打印材料码弹窗**（打开时即列出该订单已有记录）。

## 附：与现有口径的冲突点提醒

1. **批次号权威性**：本方案落地后，`buildBatchNo`（公式）只在**没有打印记录**时才用；
   有打印记录时一律以记录为准。文档与代码注释都要写清这条优先级，否则后来人会以为公式是唯一来源。
2. **一单一号的约束不会因为本需求松动**：组合生单是"按号分组各出一张"，不是"一张多个号"。
3. **历史订单零影响**：没有打印记录的订单，走的是现有路径（对话框可改号 / 公式取号）。
