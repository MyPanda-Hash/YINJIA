## 一、当前仓位是怎么实现的（先回答这个问题）

**一句话：仓位没有专属代码，它是"一张表 + 通用档案引擎"跑出来的一个普通基础档案面板。**

| 层 | 落点 | 内容 |
|---|---|---|
| **表** | `bs_wh_loc` | **唯一一张**。`id / 仓库 / 仓位编码 / 仓位地址 / 停用 / 备注 / asp_cancel / asp_user1-2 / asp_time1-2 / 仓库编码 / 备用1-20`（32 列，**5 行试录数据**） |
| **元数据** | `yj_panel` | `WHLOC / 仓位 / category=基础档案 / mode=archive / line_table=bs_wh_loc / pk_col=id / detail_key=locations / page_size=50` |
| **元数据** | `yj_field` | 6 行：`仓库`(参照 WH.仓库名称) · `仓库编码` · `仓位编码` · `仓位地址` · `停用` · `备注` |
| **元数据** | `yj_role_panel` / `yj_translation` | 全角色 `view,query`；面板名 + 字段名 ×9 语言译名 |
| **后端** | `PanelConfigService` 第 107–110 / 194–203 行 | 注入 `qrLabel` / `qrLabelKey=仓位编码` / `qrLabelScopeKey=仓库` / `qrLabelKind=whloc`。**除这 2 处外，仓位没有任何后端代码** |
| **前端** | `menus.js:389` · `PanelxList.vue:3753-3789, 6386-6406` · `print-formats.js:366-410` | 菜单项 + 通用档案列表 + 二维码标签勾选分支 + 75×100mm 标识卡 |

**CRUD 全部复用通用引擎，一行仓位专属 Service 都没有：**
- 查询：`QueryService.queryArchive` — **全量返回**，上限 `ARCH_LOAD_CAP = 50_000` 行
- 保存：`ButtonService.saveArchive` — 全量 upsert，**缺席行 = 已删除**（有"带筛选保存"误删护栏）

**所以当前实现的本质是：** 仓位 = 一段可打印的自由文本 + 一个二维码标签。
它**能建档、能打标签**，但（a）表达不了 Excel 的层次，（b）与库存链路零引用，（c）与单据侧的 30 处仓位列完全不通。

## 二、目标：仓位编码体系（照文档）

### 2.1 编码取值 = 文档原样

| 厂区 | 库区 | 文档写法 | 拆成的仓位编码 |
|---|---|---|---|
| 老厂区 | 成品B仓 B1–B4 | `B1-01-1/2` | `B1-01-1`、`B1-01-2` |
| 老厂区 | 成品C仓 C1/C2 | `C2-16-1/2/3` | `C2-16-1`、`C2-16-2`、`C2-16-3` |
| 老厂区 | A仓炭粉/胶粉/纸箱/端盖 | `A1-09-1/2/3`、`A1-1-1/2/3`、`A2-2-1/2/3/4/5` | 同名 |
| 老厂区 | 货架区/无纺布/网套/标签 `AH*` | `AH5-1/2/3-1...` | **待补全**（22 处） |
| 新厂区 | 成品 D 仓 | `D1-01-1/2` | 同名（`D2-D7`、`D8-D11` 按继承复制） |
| 新厂区 | 炭粉/胶粉/纸箱/端盖/PP棉/折叠棉/网套 | `炭1区1-36`、`1-14`、`1-12`… | **待定规则**（468 条） |
| 新厂区 | 货架区 | `H1-1/2/3/4` | `H1-1`…`H11-4` |

**规模：已可解析 987 条，实际约 1,100+。**

### 2.2 仓位编码的构成（供生成器用）

```
仓位编码 = <库区>-<排号>-<位号>       例：B1-01-1 、D8-03-2
           └┬┘  └┬┘  └┬┘
            │    │    └─ 位号 1..5（一排货架的格/侧）
            │    └────── 排号 01..24（两位补零）
            └─────────── 库区码（仓字母+区号，或 AH / H / 炭N区）
AH 系列（三层）= AH5-<位>-<层>        例：AH5-1-1（排-位-层）
```

### 2.3 二维码：**保持三段不变**（用户口径）

```
仓库编码 @ 仓位地址 @ 仓位编码
   CK03  @ 成品B仓1区01排1位 @ B1-01-1
```

**唯一要求：`仓位地址` 不能再是随手写的自由文本** —— 否则同一个仓位改一次描述，已打印的码就"漂"了。
做法：`仓位地址` **由层次列派生**（`厂区+仓+库区+排+位` 拼装，如"成品B仓1区01排1位"），
既是人话、又稳定、还让中段永远非空（避免出现 `CK03@@B1-01-1`）。
`locationCardQrText` **一行都不用改**。

## 三、主数据改造：`bs_wh_loc` 加列（仍是这张表）

> 层次化**不需要新机制**：引擎已支持**自参照**（`data_type='参照'` + `ref_panel=自己`），
> `DEPT` / `FIN_ACC` / `FIN_EXP` / `REGION` **4 处先例**，`bs_dept` 就是一张表装完整棵树。

| 新增列 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `仓位名称` | nvarchar(120) | 现场叫法（"成品B仓1区01排1位"） | 生成 |
| **`上级仓位`** | nvarchar(60) | **参照 WHLOC.仓位编码，display=仓位名称** ← 照抄 `DEPT.上级部门` | 生成 |
| `上级仓位id` / `上级编码` | bigint / nvarchar(60) | 与 `bs_dept` 同款冗余 | 生成 |
| `级次` | nvarchar(10) | 1厂区 2仓 3库区 4排 5位 | 生成 |
| `长编码` | nvarchar(200) | 路径码（子树查询免递归） | 生成 |
| `是否叶子节点` | bit | 位=1，其余=0 | 生成 |
| `厂区` | nvarchar(20) | 老厂区 / 新厂区 | 文档 |
| `库区` | nvarchar(30) | `B1`…`D11` / `AH` / `H` / `炭1区` | 文档 |
| `排号` / `位号` / `层号` | nvarchar(10) | 见 §2.2 | 文档 |
| `仓位类型` | nvarchar(30) | 货架位/地面/纸箱区/端盖区/PP棉/折叠棉/网套/标签/炭粉/胶粉/不良品/呆滞/设备/柱 | 文档列头 |
| `存储类别` | nvarchar(200) | 允许存放的物料大类（多值） | 文档列头 |
| `是否可拣货` | bit | 默认 1 | 新 |

**既有列处置：**
- `仓库编码` —— **升级为主关联**（`仓库` 名称列保留兼容，新逻辑只认编码）
- `仓位编码` —— 加 **唯一索引**
- `仓位地址` —— 改为**派生字段**（§2.3），语义从"随手描述"变"层次拼装"
- `停用` / `备注` / `asp_*` / `备用1-20` —— 不动

**⚠ 级联做不到**：引擎 `ref_filter` 只支持常量 `k=v`，无动态变量。
所以 `厂区/仓库/库区/排号/位号` 做**普通列**（数据本就批量生成），只 `上级仓位` 与 `仓库` 做参照。

## 五、操作处理方式（表多怎么安全地做）

### 5.1 三条原则

1. **不动物理列，只动元数据。**
   30 列全部保留原样（改列名会牵动金蝶接口、ERP 血统、面板字段、审计四件套）。
   接通一个仓位字段 = `UPDATE yj_field` 一行，**不需要改后端代码**（参照是引擎通用能力）。
2. **元数据驱动 ⇒ 可分批、可回滚、幂等。** 每批一个独立迁移脚本，`IF NOT EXISTS` / 窄条件 `UPDATE` + 行数守卫。
3. **两个账套都跑**（先 `HSDZ_MES` 后 `HSDZ_MES_TEST`），`DbSync` 跑到「执行 0、失败 0」。

### 5.2 分批顺序（每批可独立上线、独立回滚）

| 批 | 内容 | 依赖 | 风险 |
|---|---|---|---|
| **① 主数据** | `bs_wh_loc` 加 12 列 + 唯一索引 + 派生字段 + 照抄 `DEPT` 那行注册 `上级仓位` 参照 + 9 语言译名 + 中文注明 | 无 | 低 |
| **② 数据导入** | 迁移脚本按规则生成 987 条（区间/继承/多值拆分）→ 22 处截断与 468 条新厂区编码**待业务补全后补录** | ① 完成 + 业务确认编码规则 | 低 |
| **③ 生成器** | 面板「仓位批量生成」按钮（预览 → 幂等生成），供以后新增货架 | ① ② | 低 |
| **④ 单据接通** | A 档 8 列挂参照 + 正名 + 放开可见；同步修 §4.3 过时注释 | ① ②（要有仓位数据可选） | **中 —— 见 5.3** |
| **⑤ 二维码** | 无需改代码（三段保持不变）；仅确认 `仓位地址` 已按 §2.3 派生 | ② | 低 |
| **⑥ 遗留登记** | B 档 22 列写入 `tools/db-legacy-whitelist.txt` 冻结 | ④ | 低 |

### 5.3 🔴 第 ④ 批的硬约束：**采购链四单基线**

改 `PURCHASE_IN` 任何字段 = 触发 `AGENTS.md`「采购链四单字段与显示字段基线」规范，**不可豁免**：

3. 同批重跑 `node tools/archive/_gen-fourdoc-restore.mjs` 刷新 ①回正脚本 ②`tools/fourdoc-baseline.tsv`
4. 跑回归闸：`cd tools && java -cp lib\mssql-jdbc.jar verify\FourDocAudit.java HSDZ_MES` → 必须 `[PASS]` 全 0
5. `§四 顺序核验汇总` 必须 12/12 全 ✅
6. **单独一个 commit**

> ⚠ **协调提示**：当前工作区已有**未提交**的四单基线回正改动
> （`migrate-fourdoc-baseline-restore-20261008.sql` / `migrate-fourdoc-bloodline-cols-20261008.sql` /

### 5.4 其它护栏

- **新增列/表必须同脚本写 `MS_Description`**（AGENTS.md 硬规矩）；查注明按 `class=1` 过滤（索引级会撞号）
