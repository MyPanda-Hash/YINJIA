# 排单计划打印「日期窗口」四个方案（2026-11-04）

> 背景：用户口径「**当前的排单计划打印的日期形式每天打印都是根据当天的打印，不会打出以往排单计划的日期，
> 这种需要修改吗?还是如何处理这个日期的形式问题**」。本文件把四个备选方案写全，供拍板；打印功能本轮**不动**。

> **用户已拍板（2026-11-04）**：采用 **C 的收敛版** —— 日期列 = **勾选行「最前日期 → 最后日期」**
> （连续、含中间空列；不锚定今天），已按纯前端实现并提交。实现与取证见
> `tools/archive/_plan-sheet-range-20261104/README.md`；A / B / D 三个方案保留备查。

## 0. 现状机制（已实测，不是推测）

| 环节 | 现状 | 位置 |
|---|---|---|
| 取数 | `POST /api/px/scheduleBoard/planSheet` 返回 `{日期[], 今天, 行[]}`；`日期` = 各行日计划/日报工出现过的日期 ∪ 各工序「计划开工~完工」区间 | `WorkOrderDayPlanService.planSheet()` / `buildDates()` |
| 日期列表 | **后端其实已包含过去日期**（只要那天有计划或有已审报工）。实测 2号车间：22 个日期列 `2026-10-29 … 2026-11-19`，且每行 `日计划` 里带 `10-29:2000 / 10-30:2000 / 10-31:2000` 等历史值 | 同上 |
| 出纸前裁剪 | 前端 `planSheetDates(dates, today, 5)`：**只保留 >= 今天的日期，再取前 5 个**；今天以后一个都没有时，退化为"最后 5 个" | `frontend/src/business/print-formats.js:597-604` |
| 窗口来源 | `today` 取后端 `今天`（= 服务器当天），与页面左上「开工日期」**无关**；`/planSheet` 接口根本不收它 | `WorkOrderBoard.vue#printPlanSheet` |
| 纸面 | 页头**只有标题**（2026-10-21 口径：不印打印日期/制单人/线体）；排单计划打印**不留痕**（`printStamp` 只服务「打印工单」） | `schedPlanSheetHtml()` |
| 版式 | A4 横向 6mm；固定列合计 73%、二维码 5%，日期列宽 = `max(4, 27/n)%` ⇒ **n>6 就挤到不可读** | `schedPlanSheetHtml()` |

**结论：**现状下"打印当天起 5 天"是**前端一层 5 行代码**决定的，后端数据一直都有历史日期。
后果：过期/历史计划打不出来（例：0227 的 6000 在 10-29~10-31，今天 11-04 打印时整段被切掉、日期格全空，
但"未完成总数 6000"照旧）；同一张计划隔天打印，两张纸只有日期列不同、无法归档辨认。

## 1. 方案 A：打印前弹窗选「起始日期 + 天数」〔推荐〕

**① 目标与流程**
点「排单计划（N）」→ 弹小窗（起始日期 / 天数）→ 点「打印」→ 出纸。起始日期默认 = 页面左上「开工日期」
（没选就今天），天数默认 5；窗口内**没有计划的日期也保留空列**。要补打上周的计划，把起始日期改成上周即可。

**② 改动点**
- `frontend/src/views/modules/plan/WorkOrderBoard.vue`：`printPlanSheet()` 拆成「开弹窗」→「确认打印」；
  新增 `psDialog/psStart/psDays` 状态 + `el-dialog`（`el-date-picker` value-format=YYYY-MM-DD、`el-input-number` 1~10）；
  确认后仍走原 `/planSheet` 取数、`pickPlanSheetRows` 过滤勾选行，只多传窗口参数。
- `frontend/src/business/print-formats.js`：
  - 新增 `planSheetWindow(start, days)`——纯日期算术生成 `['YYYY-MM-DD', ...]`（跨月/闰年安全，别用 `toISOString` 直接切片）；
  - `planSheetDates(dates, today, days)` 保持原签名（内部实现改为调 `planSheetWindow`），保证旧调用不破；
  - `schedPlanSheetHtml(rows, dates, opts)` 支持 `opts.start/opts.periodText`：日期列直接取窗口（窗外后端多给的日期不用），
    表头右上加一行小字「计划期间：10月29日~11月2日」（可选加「打印时间」，见④）。
- `frontend/src/i18n/locales/*.js`（至少 en）：新增弹窗文案（起始日期/天数/计划期间…），显示层用 `tt()`（ADR-0001：纸面事实文案不进翻译）。
- 后端 **0 改动**（`/planSheet` 现有返回已够）。

**③ 数据与接口**：无新接口、无落表。参数只在请求响应内部传递。

**④ 口径与边界**
- 起始日期为空 ⇒ 今天；天数限制 1~10（>6 列已不可读，10 是硬上限，建议 5 默认）；
- 起始日期早于/晚于数据范围 ⇒ 照常出空列（不报错，避免"以为没数据"；可取到 0 行时给 toast「窗口内无计划」）；
- 逾期行的量摊在开工日（可能远早于窗口）⇒ 窗口选过去才看得到，属正确行为；
- 已完工行默认不在打印范围（勾选来自未完工页签）；若在「已完工/全部」页签打印，窗口同样可选过去；
- 多行区间不同 ⇒ 各取各的日计划，窗口只是公共坐标轴（与现状同一渲染逻辑）；
- 留痕：仍不落表；纸面是否加「打印时间」需单独确认——**2026-10-21 曾定"不印打印日期"**，
  建议只印「计划期间」（这是计划事实，不是打印元数据），打印时间暂不印。
- 权限：沿用「打印」动作词，不新增。

**⑤ 验收**
- 单测（`frontend/src/business/print-formats.test.js`，现有 12 条上加/改）：
  1) `planSheetWindow('2026-10-29', 5)` ⇒ `['2026-10-29'..'2026-11-02']`（跨月）；
  2) 起始早于所有数据 ⇒ 仍返回 5 个日期、HTML 日期列头齐全；
  3) `schedPlanSheetHtml(rows, dates, {start:'2026-10-29', days:5})` ⇒ 含 `10月29日`，且 0227 行的 2000 出现；
  4) 不传 `start` 时输出与旧版逐字一致（防回归）。
- 实测：起 5173（源码态）→ 勾 2 行 → 起始 10-29、天数 5 → `window.print` 一次、打印层日期列 = 10月29日~11月2日、
  0227 三格 2000 在位；再点默认（今天）⇒ 与现状一致。
- 前后端 `npm run build` 通过；静态产物同步（若同时要 8090 生效，见 §5）。

**⑥ 工作量**：前端 2~3h + 单测/实测 1.5~2h ≈ **4h/0.5 人日**；不动后端 jar（纯静态资源更新）。

**⑦ 风险/回滚**：低。只动出纸选择交互与纯函数；回滚 = 还原两个前端文件（或 `git revert`）。
不改数据、不影响既有打印通道（`printInPage` 不变）。

**⑧ 优缺点**：能补打任意历史窗口、列宽自动可控、改动最小；代价是多一步弹窗（可默认值直接回车）。
**适用**：车间日报/补打、需要"按某个日期段出纸"的日常场景。

## 2. 方案 B：直接把页面「开工日期」当窗口起点〔最小改〕

**① 流程**：改左上「开工日期」→ 点「排单计划」→ 日期列 = 开工日期起 5 天。默认开工日期=今天，故默认行为不变。

**② 改动点**：只改 `WorkOrderBoard.vue#printPlanSheet`：把 `today: d['今天']` 换成 `today: day.value || d['今天']`；
`print-formats.js` 零改动；按钮 tooltip 改文案「按左上开工日期起 5 天打印」。
**③ 接口/数据**：无变化。**④ 边界**：天数固定 5；开工日期为空/非法 ⇒ 回落今天；其余同 A。
**⑤ 验收**：`npm run build` + 页面实测：开工日期改 10-28 ⇒ 打印列 10月28日~11月1日；默认 ⇒ 与现状一致。无新增单测（或 1 条）。
**⑥ 工作量**：**0.5~1h**。**⑦ 风险**：最低，但语义借用（开工日期本来只是左侧汇总的回显参数）。
**⑧ 优缺点**：最快；缺点是不直观（用户得知道"先改日期再打印"）、天数写死、没法一次看两个窗口。
**适用**：只偶尔补打、且能接受"先改日期"的操作习惯。

## 3. 方案 C：日期列改成"按数据实际"（不锚定今天）

**① 流程**：不做选择，打印时自动取这批行的**全部实际计划日期**（含过去），一格不多一格不少。

**② 改动点**：`print-formats.js#planSheetDates` 改为 `planSheetDatesFromData(dates, rows, maxCols)`：
候选 = 后端 `日期` 中"有任一行日计划/日报工非零"的日期（可再并上各行 计划开工~完工 区间中点）；
加 `maxCols` 上限（比如 10），超了截断并在表头标注"共 N 天，仅印前 M 天"。
**③ 接口/数据**：零改动（后端已返回全部日期与日计划）。
**④ 边界**：这批数据实测并集 **10-29~11-07 共 10 列**（跨两行区间），列宽 `max(4,27/10)=4%` ⇒ 日期列合计 40%、
总宽 118% ⇒ 表格必然断行/缩小；22 列时更糟。跨月/多行区间差异无解，除非改版式（多页、每行一张、或缩到 5 天硬截断）。
**⑤ 验收**：单测 2~3 条（并集/截断/空集）；实测 2号车间打印件版式（`tools/archive/_plan-sheet-20261031/render-sheet.mjs` 可离线渲染成图片检查）。
**⑥ 工作量**：2~4h（含版式调参）。
**⑦ 风险**：中高——**纸面可读性/版式**是最难的部分，且"打印结果随数据变"（没有稳定窗口，审核/复核时不好对照）。
**⑧ 优缺点**：不用选日期、天然含历史；但宽表挤、无统一坐标轴，"每行各打各的"与原纸表形态冲突。
**适用**：只在"只需要 3~5 天且各行区间基本一致"的车间；本厂当前数据不满足（10+ 列）。

## 4. 方案 D：打印快照落表，支持"原样重打历史打印件"

**① 流程**：点「排单计划」→（选窗口，同 A）→ 系统**先存档再出纸**：纸面右上印「打印编号 PS20261104001」；
另给「历史打印件」入口：列表（编号/时间/人/产线/窗口/张数）→ 选中 → 按**存档快照**重打（日期、数量与当时一致）。

**② 改动点**
- 后端：`ScheduleBoardController` 新 3 个端点（`/planSheet/archive` 保存、`/planSheet/archive/list` 列表、
  `/planSheet/archive/get` 取快照）；`WorkOrderDayPlanService` 复用现有取数 + 保存；权限沿用「打印」+「查询」。
- 数据库（新表，须按《数据库规范》走）：`wo_plan_sheet_print`（打印id/打印编号/打印时间/打印人/生产线/页签/
  窗口起/窗口天数/行数/asp_user1-4/asp_time1-4）+ `wo_plan_sheet_print_cell`（打印id/工单行id/日期/数量）；
  或明细只存一行 JSON（省表，但不利于按日查）。**必须**：`MS_Description` 中文注明、登记 `tools/db-inuse-tables.txt`、
  进 `tools/db-migrations.txt`、两账套各执行一遍、`DbNormAudit` 通过。
- 前端：`WorkOrderBoard.vue` 加「历史打印件」按钮/下拉 + 列表弹窗；`print-formats.js` 的渲染函数接受
  "快照形态"的行（与实时行同构，额外带 `打印编号/打印时间` 表头字段）。
- 迁移脚本：`tools/migrate-wo-plan-sheet-print-20261104.sql`（幂等）。

**③ 数据结构**：新增 2 张表；新增 3 个接口；不动物料/生产数据。
**④ 边界**：重打用快照、**不重算**（这正是目的）；窗口外/空窗口照 A 规则；快照保留策略（默认永久或按 N 年）需拍板；
已完工行同样可存档；打印时间/打印人**必然上纸**（与 2026-10-21 口径冲突，需用户明确同意）。
**⑤ 验收**：接口断言（存档后 list 能查到、get 与出纸数据一致）；页面实测（打一次 → 改数据 → 重打旧件，
日期/数量仍是当时的）；两账套迁移 + `DbNormAudit`；出纸版面截图。
**⑥ 工作量**：**8~12h**（后端 4~6h、前端 2~3h、迁移/双账套/文档 2h、验收 1~2h）；需**重建 jar + DB 迁移 + 部署**。
**⑦ 风险**：最高——生产库加表/改权限、部署窗口、留痕语义（谁打的、打几次）要定；回滚要回滚表 + jar。
**⑧ 优缺点**：唯一能"原样重打历史打印件"、可审计；但对当前诉求（只是想打出以往日期）明显过重。
**适用**：有审计/对账要求（客户投诉、计划变更追溯）时再上。

## 5. 四方案对比

| 维度 | A 选窗口 | B 用开工日期 | C 按数据实际 | D 快照落表 |
|---|---|---|---|---|
| 能打出以往计划的日期 | ✅ 任意窗口 | ✅（先改日期） | ✅ 但列数爆炸 | ✅ 且可原样重打 |
| 能否选天数 | ✅ 1~10 | ❌ 固定 5 | ❌ | ✅ |
| 列宽可控 | ✅ | ✅ | ❌（10~22 列挤爆） | ✅ |
| 是否动后端/部署 | 否（仅前端静态） | 否 | 否 | **是**（jar+DB 迁移） |
| 纸面是否留痕 | 仍无（可选加"计划期间"） | 同左 | 同左 | ✅ 打印编号/时间/人 |
| 工作量 | ~4h | 0.5~1h | 2~4h | 8~12h |
| 风险 | 低 | 最低 | 中高（版式） | 最高 |
| 建议 | **首选** | 应急/顺手 | 不建议单独用 | 后续按需 |

## 6. 推荐

**先上 A**：它用最小改动解决"打不出以往排单计划"的核心诉求，列宽可控，且为将来 D 的窗口选择打基础。
实施时可顺手把「计划期间」印到表头（不加打印时间，守住 2026-10-21 口径）；
如果现场觉得弹窗麻烦，可把 A 的默认值做成"起始=开工日期、天数=5"，直接回车即出纸（体验接近 B）。
若后续出现审计/对账需求，再上 D（A 的窗口参数可直接复用）。
