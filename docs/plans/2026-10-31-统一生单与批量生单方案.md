## 一、用户口径(原话)

> 「在**生单**下多写一个**批量生单**的功能。如采购订单中增加左侧边栏中增加勾选出来,勾选多个采购单后
> 打开一个新的界面为勾选的各个单据的明细行,再进行选择,来实现这个的转单的处理。
> 并且**生单**也要变成可以勾选的和选择数量的(现在只有采购订单的生单做了特殊处理,但是别的编辑和打印旧不用了)。
> **非定制化的生单只要可以勾选和选择数量就可以**。」

拆成三条需求:
1. 左栏(单据选择栏)每行一个**勾选框**,可跨页勾多张来源单;
2. 「生单」下拉里多一项「批量生单」:打开对话框列出**勾选单据的明细行**,再挑行/填量转单;
3. 「生单」本身也要能**勾行 + 填数量**;编辑/打印不动。

> **第二轮口径(同日,把上面的"非定制化"限定取消)**:「**所有单据只要有生单和批量生单这个按钮的,都要实现 ——
> 送料暂收就不能批量,而且生单也没有勾选**」。
> 于是第一版里"定制化动作保持原样直接调后端"的送料暂收单也接进了对话框
> (按商品档案逐行分流到 检验/入库,落库逻辑仍由 `QcRecvGenerateHandler` 接管)。
>
> **第三轮口径(同日,回退两条)**:「**销售订单 → 生产工单、生产工单 → 产成品入库单 这两个保持原来的不变**」。
> 这两条**不进统一生单对话框、也不出「批量生单」**:
> 生成生产工单仍走原来的 `callButton → ManuScheduleHandler`(按订单行 1:1 落 plang,工艺路线由服务端决定);
> 生成产成品入库单仍是原来的一键整单(`generateBatch` 按剩余量整单送出,批次号继承)。
> 前端登记在 `PanelxList.GENERATE_KEEP_ORIGINAL`,后端相应分支已撤掉。
>
> **第四轮口径(同日,两处收口)**:
> ① 「**除了采购订单,别的生单没有超送比例**」—— 对话框里的「超送比例」输入框只对 `PU_ORDER`
>    (含其供应商打印副本 `SUPPLIER_PU_ORDER`)出现;其余链路(暂收→检验/入库、销售订单→销售出库单)
>    一律**不显示,且本次比例恒 0**(上限 = 剩余量,后端 `generateBatch` 按 0 校验,不再有 1.2 倍额度);
> ② 「**销售订单只用生销售出库单,不用生成生产工单**」—— 销售订单生单组里隐藏「生成生产工单」
>    (`PanelxList.GENERATE_HIDDEN`),主按钮因此变成「生成销售出库单」,下拉只剩「批量生单」;
>    后端 `PUSH_TARGETS` 与 `ManuScheduleHandler` **保留不动**(订单结转/选单等入口仍在用这条链路)。

## 二、哪些生单改、哪些不改(改动面收口的依据)

| 来源面板 \ 动作 | 目标面板 | 后端归属 | 本次行为 |
|---|---|---|---|
| `PU_ORDER \| 生成送料暂收单` | `QC_RECV`(分批) | `PushGenerateHandler.generateBatch` | **生单**:仍是原「分批送料」对话框(材料码隔离行/超送比例/批次号那一套口径一字不动)<br>**批量生单**:走新对话框(每张单一段明细,同样带批次号与隔离行;**超送比例只在这里**) |
| `SO_ORDER \| 生成销售出库单` | `SALE_OUT` | 通用推式生单 | **销售订单的生单主按钮就是它**(生产工单已从工具栏隐藏);**生单 / 批量生单**都走新对话框,无超送比例 |
| `QC_RECV \| 生成检验或入库单` | `QC_INSP` + `PURCHASE_IN` | `QcRecvGenerateHandler.generateSelected` | **生单 / 批量生单**都走新对话框;按商品档案「来料检验」分组各出一张;无超送比例 |
| `SO_ORDER \| 生成生产工单` | `MANU_ORDER` | `ManuScheduleHandler` / `QuickScheduleService` | **保持原来的不变**(工具栏隐藏、不进对话框、不出批量生单) |
| `MANU_ORDER \| 生成产成品入库单` | `FINISH_IN`(分批) | `generateBatch` | **保持原来的不变**(一键整单,批次号继承) |

**分层**:前端 `GENERATE_KEEP_ORIGINAL` 把最后两条挡在对话框之外(`GENERATE_HIDDEN` 再把生产工单从
销售订单的工具栏藏掉),其余动作一律先开对话框;后端 `PxController.generateByAction` 只对送料暂收单做
动作级分派(它要按商品档案分流),其余走 `PushGenerateHandler.generateOne`(内部再分分批/普通)。

## 三、交互流程

```
列表页(采购订单 / 送料暂收单 / 销售订单 / 生产工单 …)
 ├─ 左栏「XX选择」每行 ☑(表头全选本页 / 摘要「已勾选 N 张 + 清空」)
 ├─ 工具栏「生单」(主按钮)                        ← 单张(当前单据)
 └─ 工具栏「生单 ▼ → 批量生单」                    ← 多张(未勾选时先提示,不弹空窗)
        ↓   · 勾选里混了草稿 → 跳过并提示「已跳过 N 张非已审核单据」(生单只认已审核)
        ↓   · 有多条生单链路的(销售订单:生产工单 / 销售出库单)→ 下拉里各一项「批量生单·<动作>」
 统一生单对话框 GenerateLinesDialog
   · 每张来源单一段:单号 / 审核状态 / 日期·往来单位 /(分批)批次号 / 全选·取消全选·已选 N 行
   · 行表:行号·物料编码·物料名称·规格型号·单位·(分批)批次号·数量·已生单·剩余·可生单·**本次数量**·(分批)状态
   · 默认勾选:有剩余的**订单行**(已打印隔离行必须显式勾 —— 与原分批对话框同口径)
   · 底栏:已选 N 行 · 本次合计 / 按剩余量填充 / 清空 / 取消 / 确定生单
        ↓
 POST /px/push/generate(逐张、独立事务)
   · 只生成 1 张 → 关源页签、开目标面板页签(与推式生单同款);生产工单跳独立路由 /prod/plan/workOrderList
   · 生成多张(批量,或"一条动作两个去向"如 暂收单→检验单+入库单)→ 留在来源列表刷新,勾选清零
```

## 四、接口契约

### 4.1 `POST /api/px/push/lines`

```jsonc
{ "panelCode": "PU_ORDER", "action": "生成送料暂收单", "sourceNos": ["YJ-20261012-01", "YJ-20261012-02"] }
```

返回(分批链路与普通推式生单**同一份行契约**):

```jsonc
{
  "targetPanel": "QC_RECV", "targetName": "送料暂收单", "batchFlow": true, "overRatio": 0.2,
  "docs": [{
    "sourceNo": "YJ-20261012-01", "status": "已审核", "header": { /* 单头(中文标签键) */ },
    "nextBatchNo": "20261031", "batchInherited": false, "batches": [],
    "lines": [{
      "lineKey": "YJ-20261012-01#4825", "id": 4825, "rowKind": "order",
      "行号": null, "物料编码": "A-32-01", "物料名称": "S阻垢炭棒/滤芯", "规格型号": null, "计量单位": "支",
      "数量": 20.0, "已送数量": 0.0, "已退回数量": 0.0, "剩余数量": 20.0, "可送上限": 24.0
    }]
  }]
}
```

- 行键 `{来源单号}#{来源明细行id}` 与选单/分批**同一约定**;已打印隔离行为 `{单号}#{行id}@{打印行id}`;
- `rowKind`: `order` | `printed`(材料码打印出去的隔离行,自带批次号);
- `可送上限`:订单行 = `数量×(1+超送比例)−已送+已退回`;隔离行 = 未生单量(印在标签上的量不可超)。

### 4.2 `POST /api/px/push/generate`

```jsonc
{ "panelCode": "PU_ORDER", "action": "生成送料暂收单", "overRatio": 0.2,
  "docs": [{ "sourceNo": "YJ-20261012-01", "batchNo": "20261031",
             "lines": [{ "lineKey": "YJ-20261012-01#4825", "qty": 20 }] }] }
```

返回 `{ targetPanel, 生成: [{ sourceNo, 编号, 面板, 批次号 }], 失败: [{ sourceNo, 原因 }] }`。

- **逐张独立事务**(`PushGenerateHandler.generateOne` 每张一次 `@Transactional`):
  某张失败(被别人送满/状态变了)不回滚已生成的那几张,失败原因逐条回给界面;
- 权限:`perm.requirePanelView(来源)` + `perm.requireButton(目标, "保存")`(与 `/batchFlow/generate` 同门);
- 前端用 `unwrapStrict` 解包:权限拒绝是 **HTTP 200 + body 403**,普通 `unwrap` 会让对话框空着、看不出原因;
- 来源单已被别人删除/作废(列表是几秒前的快照)时,`loadOneDoc` 只回 `{编号, 单据状态}` 的空壳 ⇒
  `PushGenerateHandler.looksEmptyDoc` 判为不存在,直接报「来源单据不存在或已被删除:<单号>」,
  不在对话框里摆一段空明细、也不让它误导成"状态不对"。

## 五、占用与剩余量口径(为什么"可以选数量")

| 链路 | 占用写入 | 剩余量来源 |
|---|---|---|
| 分批链路 | 既有 `linkBatch(..., batchId, links)` + 批次台账 | `BatchService.sentByLineKey` / `returnedByOrderLine`(与分批送料同源) |
| 普通推式生单(本次新) | `voucherFlow.linkBatch(source, no, target, newNo, null, null, links)` —— **按行、按本次量** | 同上(`form_flow_link.source_line_key` 求和) |

与旧「整单推式生单」(`PushGenerateHandler.handle`,仍保留给程序化调用)的差别只有两点:
① 只映射勾选的行;② 占用记本次量而非整行量 —— 于是**先送一部分、剩下以后再生**成立。
`handle` 那条老路径仍写整行量,所以它生成的单与本次路径**在账上互相看得见**(同一 `sentByLineKey`)。

## 六、多语言(AGENTS 红线)

- 对话框全部显示文案走 `tt()`;`en.js` 已补本批词条(`批量生单 / 目标单据 / 已勾选 / 本次数量 / 可生单 …`);
- **面板名也走 `tt()`**(`targetName` 经 `yj_translation` scope=panel,英文界面显示 `Sales issue`),
  否则英文界面会出现「Target document: 销售出库单」这种半截中文;
- 生单动作名补了三条显示译名(`生成销售出库单 / 生成产成品入库单 / 生成检验或入库单`)——
  `buttonName` 数据键仍是中文(ADR-0001);
- 守卫测试 `frontend/src/core/views/generateLinesDialog.test.js`:模板里不许出现未走 `tt()` 的中文、
  en.js 必须含全部新词条、`批量生单` 必须在生单组下拉里。

## 八、已知边界

1. **`MANU_ORDER` 没有左栏**(`DOC_RAIL_PANELS` 未登记)⇒ 不显示「批量生单」;
   要支持得先给它配左栏(中间列按实测有值率挑),不在本次范围。
2. **报表/文书面板**不出现勾选列(只在有左栏且存在生单链路时出现)。
3. **表单页(PanelxForm)的选单生单**仍走 `callButton` 老路径,本次只改列表页;
   `PushGenerateHandler.handle`(整单映射)因此保留。
4. 超送比例在对话框里是**本次生效**(随请求带给后端),不写系统参数 ——
   写 `yj_app_setting.receive_over_ratio` 的仍是「分批送料」对话框(那一处有权限门 `PU_ORDER|修改`)。
5. **批量生单只送已审核的单据**(前端按列表行的 `单据状态` 过滤 + 提示跳过张数;后端 `generateSelected`/
   `generateOne` 再兜一道)。
6. **销售订单 → 生产工单按用户口径保持原样**,因此它原有的"工艺路线必须已审核"约束也原样保留:
   `QuickScheduleService.generateFromOrder` 走 4 参重载(route=null),而 2026-10-16 的闸门不接受空路线
   ⇒ 从列表页点这条路会报「未选择工艺路线，不能转工单」。**这是既有行为,本次未改**,要修请单独提。

## 九、回滚

- 前端:`PanelxList.vue` 去掉 `toolbarGroups` 里的「批量生单」追加与 `onButton` 的拦截即可回到旧行为
  (`GenerateLinesDialog` 与 `engine.pushFlow*` 保留不用);`GENERATE_KEEP_ORIGINAL` 是"保持原样"清单,
  想新增例外往这里加面板|动作即可。
- 后端:两个端点无调用方即失效,`PushGenerateHandler` 新增方法不影响既有 `handle`/`generateBatch`;
  `QcRecvGenerateHandler.handle` 仍保留整单模式(传 null 即为旧行为);`QuickScheduleService` 与
  销售订单/生产工单那条链一行未改。
