# 排产「快速调整」弹窗方案（2026-10-31）

> 用户口径（原话）：
> 「排产呢，就那几个动作。然后，他们那个表出来以后，你可以考虑一下点那个或者双击那个数字啊，可以修改。
> 嗯，开工的日期啊，预定完成日期啊，还有可以调线，就是说。开展这几个功能，可以都集中到一个小的页面上，
> 双击那个数量弹出来，他可以在那儿修改，就基本上满足他上一次提的需求了。
> 就是当前的数量可能也要能够修改，但是我不知道怎么修改，给我一个方案实现。」

**结论**：双击日期格（格内那个计划数量）弹出「排产快速调整」小弹窗，一个页面里集中 4 个动作：
**改当天数量 / 改计划开工日 / 改预定完成日期 / 调线**。其中「当天数量」用
**人工指定 + 剩余量重摊**的守恒模型 —— 这是本文档要解决的核心设计（自动均摊怎么容得下人工改一格）。

---

## 1. 现状（基线，别推翻）

| 项 | 现状 |
|---|---|
| 日计划 | 2026-10-31 起**系统自动均摊**（`DayPlanSpread`：工序计划量 ÷ 开工日→交期），日期格只读、不落表 |
| 排产日期/交期 | `plang.st_date` / `plang.cp_date`；`plang_pc` 是它的镜像（`WorkOrderScheduleRecord.sync` 同步，实测两处一致） |
| 调线 | `POST /px/scheduleBoard/transfer`（`WorkOrderTransferService`）：写 `plang.scx`+`plang_pc.scx`、写 `wo_transfer_log` 轨迹、可 `transferRevoke` 撤回；守卫=停用线拒/已结案拒/未排产拒/**只能调到当前工序的产线** |
| 调线候选 | `POST /px/scheduleBoard/transferTargets`（同一处口径，前端只展示） |
| 权限词 | 改数量=`dayplan`、改日期=`assign`（排产）、调线=`transfer`（调拨） |

## 2. 核心设计：自动均摊 + 人工指定一格

### 2.1 存储：`wo_day_plan` 改当「人工指定覆盖表」

表结构不用动，语义变一下（这也顺便让那张表继续有用，不用删）：

| 情境 | `wo_day_plan` 行 |
|---|---|
| 某天被人工改成 X（X>0） | `asp_cancel='N'`、`计划数量=X` ⇒ **这天以人工值为准** |
| 恢复自动 | 该行软删（`asp_cancel='Y'`）⇒ 回到自动均摊 |
| 从没人工改过 | 没有行 ⇒ 自动 |

> ⚠ 先**不做**"显式 0（这天不做）"这个语义 —— 0 一律按「恢复自动」处理，避免"0 = 不做"和"0 = 没指定"
> 两义混淆（要用再说，加一列或约定一个哨兵值即可）。

### 2.2 算法：守恒重摊（T → S → R → n′）

对每个 `(工单行, 工序)`：

```
T  = 工序计划量            = 排产数量 × 换算率
M  = 人工指定集合 { 日期 → 数量 }
S  = ΣM
R  = T − S                 （剩余要摊的量）
D  = 自动区间              = [max(开工日, 今天)?… 交期]（沿用 DayPlanSpread 现有规则）
D′ = D 中**未被人工指定**的天
n′ = |D′|
```

- `n′ > 0 && R > 0` ⇒ 把 `R` 按现有规则摊到 `D′`（整数件取整 + 余数逐天摊开；不整除按 4 位小数）；
- `n′ == 0` 或 `R ≤ 0` ⇒ 不再自动摊（R<0 = **超分配**，界面红字提示 X，但仍允许保存，沿用「不堵死录入」口径）；
- 最终 `日计划[d] = M[d] ?? 自动摊值`。

**关键性质**：`Σ日计划 = T`（不超分配时），所以
`计划合计 / 7天已排 / 15天已排 / 产线今日已排 / 今日超载` 全部继续自洽 —— 不需要再改那些地方，
它们读的还是"合并后的日计划"。

### 2.3 显示

- 人工指定过的格子：数量右上角一个 `手` 角标（或数字加粗 + 浅黄底），tooltip「已人工指定，双击可改/恢复自动」；
- 弹窗里那格旁边有「恢复自动」按钮；
- 行汇总口径不变（不新增"未分配量"列）。

### 2.4 为什么选这个模型（不选另两个）

| 备选 | 为什么不选 |
|---|---|
| A. 只改那天、总数允许不守恒 | 要重新引入"未分配量/已分"列，且 `7天已排` 与格子对不上 → 就是今天上午踩过的坑 |
| B. 改数量 = 改排产数量 | 语义变成"整单加/减量"，会牵动需求数量校验、领料、入库，太重 |
| **C. 人工指定 + 剩余重摊（本文档）** | 现场最直观："这天多做 200，剩下几天自动少摊"，总量仍守恒，不用新列 |

## 3. 交互：双击日期格 → 「排产快速调整」小弹窗

```
┌───────────────────────────────────────────────┐
│ 排产快速调整                                   │
│ GD-2026-10-0226-1 / 行1   客户:张莉            │  ← 只读头
│ 成型 · 1号机 · 排产 10 · 已完工 0 · 计划量 10   │
├───────────────────────────────────────────────┤
│ ① 当天数量(2026-11-05)  [    3    ] [恢复自动]  │  ← 双击进来的那天
│    说明:改完其余天按剩余量自动重摊              │
├───────────────────────────────────────────────┤
│ ② 日期   计划开工日 [2026-10-31 ▾]              │
│          预定完成日 [2026-11-05 ▾]              │
├───────────────────────────────────────────────┤
│ ③ 调线   车间 [成型 ▾]  产线 [1号机 ▾]          │
│          原因 [____________]  (仅调线时必填)    │
├───────────────────────────────────────────────┤
│                          [取消]  [保存]        │
└───────────────────────────────────────────────┘
```

- 入口：两页（生产工单 `WorkOrderList` / 工单排产 `WorkOrderBoard`）日期格 `@dblclick`；
- 只保存**改动过的块**：三块各自调自己的接口，互不牵连（哪块没权限就置灰 + 提示）；
- 保存成功 → 关弹窗 → 重新拉 `dayPlan/data`（日计划会被重算），并行刷新看板/统计；
- 弹窗复用一份组件：`frontend/src/views/modules/plan/ScheduleQuickEditDialog.vue`（两页各自传 row + 日期）。

## 4. 后端改造

### 4.1 读：`WorkOrderDayPlanService.data()` 合并人工指定

- `derivedPlans()` 改成 `mergePlans()`：先按 `DayPlanSpread` 摊 `R` 到 `D′`，再叠加 `M`；
- 人工指定从 `wo_day_plan` 读（`asp_cancel='N'` 的行），一次 `IN (行id...)` 批量查，别 N+1；
- 行上新增两个字段供弹窗/角标用：`人工指定` = `{日期:数量}`、`超分配` = `S − T`(>0 才有意义)；
- `每日已排`（产线列头）与 `ScheduleBoardService.dayPlanLoads`（今日已排/超载）同样走合并后的口径
  （`lineDailyPlan` 里也要读该线各行的人工指定）。

### 4.2 写：新增 2 个接口，复用 1 个

| 动作 | 接口 | 说明 |
|---|---|---|
| 改当天数量 / 恢复自动 | `POST /px/scheduleBoard/dayPlan/override` | `{工单行id, 工序, 生产线, 计划日期, 计划数量}`；数量 **null/0 = 恢复自动**（软删 `wo_day_plan` 行）；>0 = 指定。**复用现有 `save()` 实现**，只是语义文档化 + 权限词 `dayplan` |
| 改开工日/预定完成日 | `POST /px/scheduleBoard/rowDates`（新增） | `{行id, 计划开工日期?, 交期?}`；守卫：已结案拒 / 完工不早于开工 / 已作废拒；写 `plang.st_date/cp_date` 后调 `WorkOrderScheduleRecord.sync` 同步 `plang_pc`（保持单轨）；权限词 `assign`；留痕 `yj_usage_log`(动作"改排产日期") |
| 调线 | `POST /px/scheduleBoard/transfer`（**复用，不新写**） | 走既有轨迹/撤回/守卫；候选来自 `/transferTargets`；权限词 `transfer` |

> 改日期**不新增"改日期专用词"**，直接挂 `assign`（排产）——否则要在权限体系里再加一格，运维配权限时容易漏。

### 4.3 校验与边界

- 工序计划量 `T` 需要 op/route/rate 才能算 → 弹窗打开时后端随 `dayPlan/data` 已返回 `工序计划量`，前端只读展示；
- 改日期后区间变 → 日计划整体重算（`M` 里超出新区间的指定仍保留并显示，但会算进 `S`，可能触发「超分配」提示）；
- 调线后该行的 `生产线` 变 → 列头「已排」与左侧树随之变（现有逻辑已按 `plang.scx` 汇总）。

## 6. 验收

1. 双击 `GD-2026-10-0226-1` 的 11-05 格 → 弹窗打开，默认聚焦「当天数量」；
2. 把 3 改成 5 → 保存 → 该天 5，其余 5 天从 (2,2,2,2,1) 重摊为 (1,1,1,1,1)，**计划合计仍 10**；
3. 点「恢复自动」→ 回到 2,2,2,2,1,1；
4. 改「预定完成日」到 11-07 → 日期列自动多出 11-06/11-07 两列，计划自动重摊；改到早于开工日 → 前端拦 + 后端拒；
5. 调线到 `2号车间` → 行从左树 `1号机` 消失、出现在 `2号车间`；`/transferRevoke` 能撤回；
6. 三块的权限分别生效（只授 `dayplan` 时，日期/调线块置灰且不提交）；
7. 超分配（人工合计 > 工序计划量）→ 弹窗红字提示，仍允许保存；
8. `node --test`、后端编译、`SpreadTest` 全绿。

## 8. 需要你拍板的 4 件事

1. **人工改数量要不要守恒**（推荐：守恒 —— 改这天，其余天自动重摊；总数不变）？
2. 双击的是**日期格**（计划数量）—— 那"当前的数量"我按**当天这一格**理解，对吗？还是也要能改
   **排产数量（整单）**（那要走 `assign` 的排产数量校验，影响更大，建议单独做）？
3. 弹窗里三块**分开保存**（哪块改了保存哪块），还是一个大「保存」一次提交（推荐：分块，权限也能分开判）？
4. 改日期/调线后**日计划整体重算**（人工指定保留）—— 可接受吗？

## 10. 无弹窗版：直接在表格里改（2026-10-31 用户口径「当前实际不需要弹窗，只要看下如何实现那些功能即可」）

> **弹窗方案作废（暂不做）**。下面是把同样几个动作**就地做在表格里**的实现方式。
> §2 的「守恒重摊」模型不变 —— 仍然要解决"自动算的格子怎么被人工改一次"。

### 10.1 一张表看清落点

| 功能 | 交互（就地） | 前端落点 | 后端 | 需要新增 |
|---|---|---|---|---|
| **改当天数量**（双击那个数字） | 双击计划数字 → 格子变输入框 → 回车/失焦保存；**清空 = 恢复自动** | 两页日期格：`<span class="dp-plan">` ↔ `el-input-number` 条件渲染 | **复用** `/px/scheduleBoard/dayPlan/save`；`data()` 要合并人工指定 | 后端合并逻辑 + 放宽守卫；前端加回 `saveDayPlan` |
| **改开工日** | 双击「开工日期」格 → `el-date-picker` 就地选 | 工单排产页**已有**该列（`开工日期`）；生产工单页**没有**，需加一列 | 新增 `POST /px/scheduleBoard/rowDates` | 是 |

### 10.2 改当天数量（核心，也是你问"怎么改"的那条）

**数据**：`wo_day_plan` 当「人工指定覆盖表」——只存人工改过的格子（`计划数量>0`、`asp_cancel='N'`）；
恢复自动 = 软删该行。从没改过的天没有行 = 自动。
**算法**：`T=工序计划量`、`S=Σ人工`、`R=T−S`，把 `R` 摊到"区间内未被人工指定的天"，`日计划[d]=人工值 ?? 自动值`
⇒ 改一格，其余天自动让位，**合计仍 = T**（§2.2 原样搬过来）。

**后端 3 处改动**（都在 `WorkOrderDayPlanService` / `ScheduleBoardService`）：
1. `derivedPlans(...)` → `mergePlans(...)`：`SELECT 工单行id,工序,计划日期,计划数量 FROM wo_day_plan WHERE 工单行id IN (...) AND asp_cancel='N'`
   批量读一次，先扣 `S` 再把 `R` 摊到剩余天；行上多返回 `人工指定`、`超分配`、`计划开工日期`；
2. `lineDailyPlan(...)`（列头「已排/日产能」）与 `ScheduleBoardService.dayPlanLoads(...)`（今日已排/超载）
   同样叠加人工指定 —— 否则改完数量，产能数和格子对不上；
3. 🔴 **放宽 `save()` 的守卫**：现在是「Σ计划 ≤ 排产数量×换算率，超了整笔回滚」，
   那是"全量手填"时代的闸；人工指定只占一部分 ⇒ 改成 **`S ≤ 工序计划量` 的软校验**
   （超了给 `超分配` 提示、自动部分不摊，但**不整笔回滚**，沿用「不堵死录入」口径）。

**前端**（两页日期格，各约 20 行）：
```vue
<template #default="{ row }">
  <el-input-number v-if="editingKey === key(row, d)" v-model="draft" size="small" :controls="false"
                   :min="0" class="dp-input" autofocus

  <span v-else class="dp-plan" :title="tt('双击可改当天数量;清空恢复自动')" @dblclick="startEdit(row, d)">
    {{ qtyText((row.日计划 || {})[d]) }}
    <span v-if="(row.人工指定 || {})[d] != null" class="dp-hand" :title="tt('人工指定')">{{ tt('手') }}</span>
  </span>
  <div v-if="(row.日报工 || {})[d]" class="dp-act" :title="tt('当天已审核报工量')">…</div>
</template>
```
- `commitQty`：数量 >0 → `saveDayPlan([{工单行id, 工序:row.工序日, 生产线, 计划日期:d, 计划数量:v}])`；
  空/0 → 同样调一次（后端按"软删"处理 = 恢复自动）；
