# 预排全程线 + 转序派线 —— 方案评估(2026-10-07 · 第二版:人工先选)

> 需求口径(用户原文):
> ①「在快速排产内进行排产,可实现一开始对当前工单的工序路线进行**全部的排产**,当前工单实现工序路线
>    **排好几个工序的生产线**,**完成一个工序就进入到下一个工序的生产线**,先这样实现。」
> ②(本版修正)「预排线应该是**在排产前就人工选择**,而不是先自动再人工;也就是**和当前选择排线的方式一样**,
>    **一开始就选择好**。」

---

## 0. 一句话结论

**可行**。做法 = 在快速排产的「排产」动作里加一个**「工序路线排线」弹窗**:把该工单工艺路线的每道工序列出来,
**每道由人工选一条生产线**(下拉与现在顶部选线同款:按该工序的生产车间过滤、显示今日负荷/日产能/超载),
**一次选好整条路线**再提交 → 首道的线写入工单级排产(`plang.scx`+`plang_pc`,与现在完全一致),
其余各道写入**预排台账 `wo_process_line`** → 报工审核后**自动转序**:完成一道就切到下一道的线。

> ⚠️ 历史提醒:同一功能(`预排全程线 + 转序`)2026-10-05 实现过、2026-10-06 以「**不应该预排产**」为由回退
> (`d2c44599`/`078dddec`)。本次为**有意改口径**,且与旧实现的差别是:**线由人工先选**(旧实现是系统按"最闲线"自动排)。

## 2. 交互设计(和现在选排线的方式一致)

### 2.1 入口

快速排产 ① 待排产池(工单行)勾选一条 → 点 **「排产」**(现在的「批量排入勾选」按钮位置)→
弹出**「工序路线排线」**弹窗(替代现有的"顶部选线 → 批量排入")。

> 顶部那几个参数保留但**不再是排产来源**:`工序/工艺/产线分组/生产线` 继续当**筛选/参考**用
> (选中工序时收敛候选线);`排产班组/预开工日/预完工日/排产数量` 移入弹窗按需使用。

### 2.2 弹窗内容(每道工序一行,人工选线)

```
工单 MO-2026-09-0007 行2 · 批次 20260928        工艺路线:GY-CB-STD(成型→切炭→组装)
┌────┬────────┬──────────┬───────────────────────────┬──────────┬────────────┐
│序  │工序    │生产车间  │生产线(人工选)              │计划数量  │计划完工日期│
├────┼────────┼──────────┼───────────────────────────┼──────────┼────────────┤
│ 1  │成型    │成型      │[成型1线 · 负荷200/产能1000 ▾]│ 210      │ 2026-10-12 │
│ 2  │切炭    │切炭      │[切炭2(自动) · 负荷200/产能0 ▾]│ 70      │ 2026-10-15 │
│ 3  │组装    │组装      │[组装线 · 负荷0/产能0       ▾]│ 70       │ 2026-10-18 │
└────┴────────┴──────────┴───────────────────────────┴──────────┴────────────┘
[排产]  [取消]      提示:首道的线 = 工单排产线;其余道为预排计划线,报工完工后自动转序
```

- **生产线下拉** = 与现在顶部同款(该工序的**生产车间**下的启用线,标签带 今日负荷/日产能,超载标 ⚠)
- **计划数量** = 按工艺路线换算率预填(`processPlanQty`),可改
- **计划完工日期** = 默认取工单交期,可改
- 未选线 / 未绑定工艺路线 → 提交时拦截并提示

### 2.3 提交后发生什么

1. **排产(按行)**:`plang.scx = 首道的线`(**只写被排的那一工单行**,`WHERE id=?`)、`plang_pc` 按 `plang_id` 写薄记录、留痕
   → 报工闸门、看板、负荷、调拨口径都不变
2. **预排台账**:`wo_process_line` 写 N 行(首道状态=已落实/实际线=首道线;其余状态=计划),**带 工单行id**
3. **回执**:「排产 1 张;预排 N 道:(成型→成型1线)(切炭→切炭2)(组装→组装线)」

### 2.4 报工完工 → 自动进下一道

> **唯一键 = 工单号 + 工单行号**(2026-10-07 用户口径):转序只切**被报工的那一行**的线,同工单其它行原样不动。
> 报工落点先按报工单的**批次号**锚到该批次的排产行(plang_pc),再经 `scjl.gd_id → plang_pc.plang_id` 定到行;
> 报工单不带批次号时退回 FIFO(老口径兼容)。

报工**审核**时按台账找**该行**状态=计划的第一道:
- **转序条件**:前一道已完工(该行已审核报工量 ≥ 该道计划量)**且**本道尚未开工
- 命中且计划线 ≠ 当前线 → `plang.scx = 计划线`(仅该行)+ `plang_pc.scx`(该行镜像)+ 台账置「已落实」
  + 写 `wo_transfer_log`(原因「转序自动派线」,带 `plang_id`)
- 计划线为空 → 只提示「下一道未预排线,请人工派线」

### 2.4.1 计划数量口径(2026-10-07 修正)

`计划数量(工序 i) = 所排工单行排产数量 × **该工序自己的换算率**`(各道**分开算,不累乘**)。
弹窗内列有「换算率」列便于核对;已存台账由 `migrate-wo-process-line-qty-recalc.sql` 按此口径校正。

### 2.4.2 **两把尺子**(2026-10-07 定死,所有页面与公式都必须遵守)

| 尺子 | 覆盖的量 | 说明 |
|---|---|---|
| **成品口径** | 订单结转数量、需求数量、排产数量、**入库数量**、**未交量**、未入库数 | 客户要的是成品 ⇒ 结转**不乘**换算率 |
| **工序口径** | 各工序**计划量**、**报工量/完工量**、转序判据、工序进度 | 各道按**自己那道**的换算率折算:计划量 = 本行排产数量 × 该道率 |

- ✅ 工序进度 = 该道完工量 ÷ **该道计划量**(工序÷工序)
- ✅ 未交量 = 排产数量 − 入库数量(成品−成品,不足 0 记 0)
- ❌ **禁止工序口径与成品口径相减/相除**:实测踩坑 —— 未交量 = 排产 8000 − 报工合计 56000 = **-48000**
  (根因:「报工合计」把各道报工量相加后拿去减成品排产;2026-10-07 已修)
- 明细列 = `当前工序` / `当前工序计划量` / `当前工序完工量`(工序口径)+ `未交量`(成品口径);
  原「已报工」列(跨工序报工合计)已删除
- 报工单审核时的**封顶判据已对齐**(2026-10-07):口径 = **该工单行该道工序的计划量**
  (= 本行排产数量 × 该道换算率),已报量也按该行统计;只在"超计划量 10 倍"时拦(允许超产)。
  拿不到行/路线时兜底用旧的 `processPlanQty`(历史数据兼容)
- 实测(测试库):行排产 500、成型换算率 3 ⇒ 该行该道计划量 1500;
  报 1500 通过并自动转序到切炭线;报 75000 被拦,提示「本行批次…工序[成型]计划量 1500.0,已报 1500.0」

### 2.5 改线 / 撤销 / 可见性

- 快速排产「已排产」列表新增 **「计划线(各工序)」** 列(`成型:成型1线 → 切炭:切炭2 → 组装:组装线`)与 **行id**
- 重新打开「工序产线排线」弹窗即可**改线**(带行id;首道=该行排产线,换线需先撤销该行排产)
- **撤销排产 = 按行**(勾哪一行撤哪一行:清该行 `plang.scx`/`plang_pc`,并作废该行预排台账;同工单其它行不动)
- 追溯弹窗恢复 **「工序产线计划」** 块(计划线/实际线/状态/计划数量)

## 5. 依赖与风险

**已具备(不用改)**
- `plang.工艺路线` + `bs_route` 明细(工序/加工顺序/生产车间/换算率)
- `processPlanQty()`(换算后工序计划量)
- 报工侧校验:工序必须在路线内 + 不得跳序 + 按换算量封顶(正好是转序的前置条件)
- 工单级排产 `assign` / 撤销 / 调拨 / 看板 / 闸门

**风险点**
1. **口径反复**:同一功能曾以"不应该预排产"回退,实施前请确认改口径(本版假设已确认)
2. 转序会**自动改 `plang.scx`**,与人工调拨共用 `wo_transfer_log`:需确认「转序轨迹是否也可撤回」(建议:可撤回,回退到原线)
3. 首道线 = 工单排产线 ⇒ 若后续要改首道线,仍走"撤销排产 + 重排"(现有守卫,不改)
4. 台账与工单级排产的一致性:撤销排产时应**同时清台账**(否则残留计划线);建议纳入第一步

**回滚路径**:`DROP TABLE wo_process_line` + 摘掉弹窗入口与转序钩子(与上次回退同路径)
