# 检验单生成门禁(成型完成)—— 方案评估(2026-10-19)

> 需求口径(用户原文):
> 「当前首件检验单、制程检验单、组装成品检验单都需要实现当前完成了进行,**成型完成后的生产工单才能生成**
> 这个首件检验单,**当前实现的所有生产工单都能生成检验单据**,修改当前的实现逻辑,先去 GitHub 查询
> 这类实现方式,再进行编写实现方案。」
> 追加口径(本轮)「当前还有没有其他实现方案,帮我再查找一下」⇒ 本文 §3 把可选路径**全部摊开**(六组),
> §4 给推荐组合;另:门禁落点已定「**前端过滤 + 后端硬校验**」,存量单据「**不动,只约束新单**」。

---

## 0. 一句话结论

**现状**:三张单据的「能不能开」**完全不看工序进度** ——
制程/首件的手工「选生产工单」弹窗把**全部未作废未结案工单行**都列出来(本机正式库 424 行),
首件检验单更是**第一张报工(哪怕报的是「混料」)审核后就自动出单**。

**推荐**:抽一个深模块 **`WoInspGate`**(唯一判据 + 唯一话术),门禁加在**后端建单前**,
判据用**报工记录/工序进度**(不用「数量达标」),第一版口径 =「**成型有已审核报工**」,
配 **系统选项开关** + **无报工历史兜底** + **管理员强制放行(留痕)** + **手工补单通道**。
理由:SMT/ERP 行业口径都指向「后端报工入口校验 + 可配置 + 默认宽松兜底」,
而本机库数据极薄(424 行工单里只有 1 行有成型报工)⇒ 用「达标」当闸会让现场一张单都开不出来,反被绕过。

## 1. 现状取证(代码 + 库实测)

### 1.1 三个生单入口,一个都不看工序

🔴 **锚定坑(必须写进实现)**:本机正式库 `plang_pc` 只有 2 行,`plang_id` = 1127/1128,
而 `plang` 最大 id = 429 ⇒ **`gd_id → plang_pc.plang_id` 这一级锚定在本库取不到行**。

而现役 `ProcessTaskService.reportedQty`(:998)只有「pc.plang_id」和「gd_id=0 时按批次」两级,
**在这条数据上同样取不到** ⇒ 门禁判据必须做**三级锚定**:`scjl.[工单行号]` → `pc.plang_id(且该 plang 存在)` → `批次号`。

🔴 **上线风险(量化)**:正式库 424 行里 423 行**从来没有成型报工**。若第一版就用「成型达标」硬拦,
现场几乎所有工单都开不出检验单 —— 行业调研里的反例正是这个([SMT MES 首件实践](https://www.cnblogs.com/mesinvestigator/articles/23310396):
「卡太死 ⇒ 班组私下走线下流程,系统里的记录反倒成了摆设」)。

### 1.3 与《银嘉MES总流程V1.2》品质泳道的对照(2026-10-19 用户提供流程图)

流程图(泳道:研发|采购|仓库|生管|混料|成型|组装|**品质**|销售|财务|备注)品质泳道共四个节点,
规则是 **「工序质检数据随报工产生」**:

| 流程图节点 | 本系统对应 | 现状判定 | 依据 |
|---|---|---|---|
| 混料报工 → **混料质检数据** | 无载体 | ❌ 未实现 | 现役标准路线 `GY-CB-STD` 只有 3 道(成型→切炭→组装),**连「混料」工序都没有**;无面板、无表 |
| 成型报工 → **成型质检数据** | **首件检验单 `QC_FIRST_INSP`** 承接(成型检验单 `QC_MOLD_INSP` 已按 2026-10-16 用户口径下架) | ⚠️ **触发点与流程图不符** | 现行 `firstInspGenerate` 判的是「本批**第一张报工**」,**与工序无关** ⇒ 一旦路线里补上混料,混料报工就会出错单;流程图要求的是**成型报工**才产生成型质检数据 |
| 组装报工 → **组装质检数据** | 组装成品检验单 `QC_ASM_INSP` | ✅ 时机一致(组装报工审核自动出单) | `ButtonService.woInspGenerate`(WO_INSP_PANEL: 组装→QC_ASM_INSP) |
| 组装质检数据 → **合格品自动入库** → 成品仓库 | `asmInspToStock`(检验单审核 → 合格数量转产成品入库单) | ⚠️ 机制在,数据为 0 | 依赖单头「合格数量」填写;`bd_finish_in` 实测 0 张 |
| **品质追溯** | 独立面板 2026-10-09 下架,现役只剩「工单追溯」弹窗 | ➖ 有替代 | `ScheduleBoardService` 追溯段 |
| **隔离仓 / 不良品仓** | 不良品处理单 `QC_DISPOSAL` 2026-10-09 整组下架,不合格数只留在检验单明细 | ❌ 未实现 | 仓库档案已有「成品不良品区/原料不良品仓」两个仓,但无流转 |

> **制程检验单 `QC_PROC_INSP` 不在流程图的品质泳道里**(流程图只画了混料/成型/组装三块质检数据),
> 它是按《生产相关品质检验.xlsx》第 3 步人工开单的。它同样应由「成型报工完成」兜住门槛(见 §4)。

**结论**:流程图口径 = **「哪一道报工完成,就产生哪一道的质检数据」**。用户要求的「成型完成后的工单才能生成」
与流程图完全一致,落点就是把三张单的触发/准入从「本批第一张报工」「所有工单行」改成
**「对应工序已报工完成」**。另外要留意:现行 `GY-CB-STD` 3 道路线里成型是**首道**,
所以今天"成型报工"恰好等于"第一张报工";但流程图要求补上「混料/装箱」后这个巧合就没了 ⇒
门禁必须**显式按工序名判**,不能继续依赖"第一张报工"这个隐含口径。

**🔴 开源里没有、必须自研的部分**(直接决定本方案的形态):

1. **「工序报工完成 → 自动生成该工序检验单」这条因果链没有先例** —— Carbon 是"打开检验工序时懒创建"、
   ERPNext 是"完工/入库时**反向**门禁",**没有一家是"报工审核后自动建检验单"**。
   ⇒ **时点定义(首件 = 首笔报工?还是整批报工完成?)必须我们自己定** —— 这正是 §9 待拍板的第 1 项。
2. **首件检验的类型枚举 + 触发规则**(每班/换模/换批/首件合格才放行批量)零先例,要自研。
3. **三张检验单的检验项目内容体系**(混料/成型/组装的特性、公差、抽样方案)属业务知识;开源只有 AQL 抽样算法可参考。

**对本方案的 3 条修正(重要)**:

- ✅ **稽核一条现状**:本项目现在是「三张单各自一套面板 + 一套 `qc_*_insp_head/_detail` 表」,
  与开源"一张通用表 + 工序来源字段"**不同**。但本项目是**面板元数据驱动**(`yj_panel`/`yj_field`/中文数据键),
  为三张单改通用表会牵动面板/字段/多语言/打印版式全部重做 —— **不建议照搬**;
  改用 **D2 深模块 `WoInspGate`** 把「判据 + 话术 + 幂等键」收敛到一处,同样达到"三处不漂移"的目的。
- ✅ **要照搬的两点**:①幂等唯一键(源报工行 + 检验类型)防重复建单(Carbon 的部分唯一索引思路);
  ②入库方向保持"**检验单当门禁**"(本项目 `asmInspToStock` 已是这个方向,且已有 `form_flow_link` 幂等),
  **不要把入库单做成反向查检验单**。
- 🟡 **留给后续(不在本次范围)**:混料质检数据无载体、品质追溯面板已下架、隔离仓靠"库存状态字段 + 默认库位映射"
  而非另开仓 —— 这三条属流程图 #10/#11 的其它节点,建议另立任务,别塞进本次门禁改造。

## 3. 可选实现方案(六组,可自由组合)

### 3.1 门禁方向

| 选项 | 做法 | 代价/风险 |
|---|---|---|
| **A 后向(卡开单)** ← 用户原始诉求 | 条件不满足 ⇒ 生成检验单被拒(前端置灰 + 后端 422) | 不改报工节奏;但现场可能"手工补单"绕过 → 需留豁免/强制通道 |
| **B 前向(卡流转)** | 成型未完成 ⇒ **不允许下道报工**(把 WoReportService:169 的「不跳序」从"前道有已审报工"升级为"前道已完工") | 现场最容易感知、行业标准做法;但会直接卡产线,阻力最大 |
| **C 双向** | 先 A,后续按需加 B | 分期落地 |

### 3.2 「成型完成」的判据口径(核心分歧点,5 选 1 或分档)

| # | 口径 | 取数 | 现场语义 | 实测命中(正式库) | 风险 |
|---|---|---|---|---|---|
| **1** | **成型已有已审核报工**(完工量 > 0) | `scjl` where 工序=成型 and `wgzt='Y'` | 「首批已成型/已脱模」—— **与 C-95「脱模后立马首件检验」一致** | 1/424 行 | 只要报 1 件就放行,粒度较松 |
| **2** | **成型达标完工**(完工量 ≥ 该道计划量) | 上式 + 计划量 = 本行 `pl_sl` × `bs_route.换算率`(或取 `wo_process_line.计划数量`) | 「整批成型做完」 | **0/424**(161 < 500) | 排产数量常是整批、实际分批生产 ⇒ **极易全库封死**(最大风险) |
| **3** | **台账已落实** | `wo_process_line` 里该行成型行 `状态='已落实'` | 「成型这道已在预排台账上落实」 | 有台账的工单可为真 | 台账按 `工单行id` 锚定,本库**同样是悬空 id**(1127/1128)⇒ 只能用「工单号+工序」兜底;没预排线的工单没有台账 |
| **4** | **工单状态列** | `plang.[当前工序]` 序 ≥ 成型,或 `[完工状态] ∈ {在制, 生产完工}` | 「工单已经走到成型之后」 | 本库该行两列**都为空**(`syncWorkOrderState` 没跑过) | 依赖重算时机;空值语义要先定义(空 = 未开工还是未知?) |
| **5** | **转序轨迹** | `wo_transfer_log` 有从成型线自动派线的记录 | 「成型做完并已转到下一道」 | 本库无 | 等价于口径 2(达标才转序)⇒ 同样封死 |
| **1′** | **口径 1 + 维度化**(金蝶口径) | 维度 = 报工日期(每天)/批次/班组/人员,任一维度首次即算首件 | 「今天这个班组的第一次成型 = 首件」 | — | 更贴现场,但需要新增维度配置,工作量 +1 期 |

### 3.4 门禁强度与兜底

> **「门禁强度」= 条件不满足时,系统到底怎么办**(不是数学概念)。举例:工单 `GD-2026-10-0010` 行1
> 成型还没报工,品质点「选生产工单」时 ——
> **拦截**:该行灰掉、点确定弹「该工单行成型尚未报工,暂不能生成检验单」,直接调接口也被拒(422);
> **提示**:照样能开单,只弹确认框「该工单成型尚未报工,确认仍要生成?」并留痕;
> **开关**:上面两种行为由管理员在系统选项里选(关闭 / 只提示 / 拦截),改口径不用改代码重发版。

| 选项 | 做法 | 评价 |
|---|---|---|
| C1 硬拦截 | 后端 422 + 前端置灰(用户已选此层) | ✅ 采纳 |
| C2 软提示 | 放行但写留痕 + 生成品质待办 | 🟡 可作为「无报工历史」老工单的过渡 |
| C3 **系统选项开关** | `关 / 提示 / 拦截` 三档,存 `yj_panel.config` 或新表 `yj_sys_option` | ✅ 推荐(畅捷通就是这么做的);默认档位建议**拦截**,但可按账套/灰度先「提示」 |
| C4 豁免与强制 | ① 未绑路线 / 路线无「成型」工序的行 → 免门禁(不然这些工单永远开不了);② 无任何报工历史的存量工单 → 提示放行;③ 管理员「强制开单」按钮:必须填原因,写 `yj_usage_log` 留痕 | ✅ 推荐 |
| C5 白名单 | 指定客户/产品/工单行豁免(如试制单) | 🟡 一期可不做 |

## 6. 边界与例外

1. **未绑工艺路线 / 路线里没有「成型」工序** ⇒ 免门禁(否则这些工单永远开不出单);`woLines` 标「免门禁」。
2. **首件的时间语义**:口径 1 才不违背 C-95「脱模后立马首件检验」;口径 2 会把首件推到整批成型之后。
3. **弃审回退**:报工弃审后成型量回退 ⇒ 已经存在的检验单**不自动作废**(存量不动口径),
   但「弃审后不能再开新单」；首件/组装两张现有随报工弃审作废的链路保持不变(`woInspUnauditCascade`:3243)。
4. **老工单**:无任何报工历史的行,建议按 C4-② 提示放行(否则 423 行全部开不出单)。
5. **多行工单/跨批次**:一律按「工单号 + 工单行号」判,不看整单(与 2026-10-15 行级口径一致)。
6. **强制放行**:必须填原因 + 写 `yj_usage_log`,并在单上加注释(留痕可审)。
7. **无工艺路线的工单行(实测:正式库 0 行 / 测试库 0 行,全部绑了 `GY-CB-STD`)**:
   现行 `WoReportService`:172 明写「工单未关联路线时**不校验**」⇒ 报什么工序就是什么工序(工序自由);
   但代价是**工序 → 生产车间 → 候选产线**这条链断了:`快速排产的「工序路线排线」会直接拒绝`
   (「该工单未绑定工艺路线(或路线无明细),不能排线」),既排不了全程线、也转不了序,
   现场只能在排产时人工随便挑一条线。⇒ 门禁本身不受影响
   (`ProcessTaskService.PROCESS_ORDER` 已有「混料→成型→切炭→组装→装箱」标准五步兜底,无路线行按它判),
   但**「没有对应产线」是数据面问题,不是门禁能解决的** —— 建议按数据问题补路线,门禁一期按已定口径
   「豁免 + 在弹窗标 `免门禁`」。
8. **生产线(scx)现状**:正式库 **424/424 行 scx 为空**(排产尚未做)、测试库 26/38 为空
   ⇒ **门禁判据绝不能依赖产线**;要判「成型是否在成型车间/成型线上完成」得先把排产补起来。

## 附录 B:口径 1 的判据 SQL 草案(三级锚定,可直接进 `WoInspGate`)

```sql
-- 该工单行的「成型已审核报工量」( @wo 工单号, @xc 工单行号, @rowId plang.id, @batch 批次号 )
SELECT ISNULL(SUM(ISNULL(s.sl,0)),0) AS 成型完工量
FROM dbo.scjl s
LEFT JOIN dbo.plang_pc pc ON pc.id = s.gd_id
WHERE s.gldh = @wo AND s.gxdm = N'成型'
  AND ISNULL(s.asp_cancel,'N')<>'Y' AND ISNULL(s.wgzt,'N')='Y'
  AND ( ISNULL(s.[工单行号],0) = @xc AND @xc > 0                 -- ① 行号(审核时写定,最可靠)
     OR ( @rowId > 0 AND pc.plang_id = @rowId                    -- ② gd_id 锚定(仅当该 plang 存在)
          AND EXISTS (SELECT 1 FROM dbo.plang p WHERE p.id = @rowId) )
     OR ( ISNULL(s.gd_id,0) = 0 AND @batch <> N''                 -- ③ 批次兜底(空批次不比)
          AND ISNULL(s.[批次号],N'') = @batch ) );
```
