# YINJIA-MES 后端逻辑设计

| 属性 | 内容 |
|---|---|
| 文档类型 | 后端设计 |
| 适用场景 | 后端逻辑设计 |
| 维护状态 | 生效 |
| 规范来源 | light-mes 后端逻辑设计(2026-08-27)适配 |

## 1. 总体结构

```text
浏览器 /api/*
  -> SecurityConfig + JwtAuthFilter
  -> Controller(PxController 仅依赖 PanelRuntimeService 契约)
  -> PxRuntimeService —— PanelActionRegistry(领域动作) / ButtonService(通用生命周期)
  -> PanelRegistry/PanelConfigService/QueryService/FormNoService
  -> JdbcTemplate -> SQL Server HSDZ_MES
```

| 层 | 主要实现 | 职责 |
|---|---|---|
| 配置与安全 | `config/` | JWT、Security、CORS、异常归一化 |
| 接口 | `controller/` | 协议转换;统一 ApiResult(code=200 成功) |
| 运行时 | `panel/` + `PxRuntimeService` | PanelRuntimeService 契约 + PanelActionHandler 领域动作插拔 |
| 业务 | `service/` | 元数据、配置生成、查询映射、按钮状态机、编号、OCR、通知 |
| 数据 | HSDZ_MES | yj_* 元数据 + 旧业务表(直读直写) |

| `yj_user` | 登录用户(id/username/password_hash/is_admin/dept_id/role_id/enabled) |
| `yj_dept` | 组织架构(公司真实层级) |
| `yj_role` / `yj_role_panel` | 角色 + 11 项操作权限(view/query/add/edit/delete/export/print/audit/price/review/adjust) |

## 4. 面板配置生成与查询映射

- `PanelConfigService.buildConfig`:archive→严格单单据结构(§前端 4);doc→单据结构;flat→报表结构。
- `QueryService`:
  - doc:按 group_col 分组,一单一行;单表式头字段取首行,头行式(order_bt+order_bs)分别查头表/行表。
  - archive:一张虚拟单,detail.<detail_key>=全量记录(≤2000 行,保证"缺席=已删除"语义安全)。
  - flat:一行一记录直接返回。
- 条件/关键词:中文标签→列名映射,SQL Server LIKE / EXISTS 行级匹配。

## 5. 状态与审批(照搬 light-mes)

**9 态状态机**(真源 `ButtonService.docStatusOf` / `QueryService.docStatus`,两处同一优先级链):

```text
【优先级链】已作废 > 已中止 > 删除申请中 > 修改申请中 > 审批中 > 修改中 > 已归档 > 已审核 > 草稿
            (canceled) (stopped)  (deleting)   (modify_state=R) (pending) (modify_state=Y)(archived)(shr≠NULL)

【通用单据:草稿 ⇄ 已审核 + 审批流】
草稿 --审核--> 已审核 --弃审--> 草稿                       (审核/弃审需审批权,见下)
草稿 --提交审批--> 审批中 --审批通过--> 已审核
                     +--审批驳回--> 草稿(意见必填,可修改后重新提交)
已审核 --中止(整单中止/中止执行)--> 已中止 --取消中止(草稿按钮)--> 已审核(shr 留痕保留)
任意 --删除--> 已作废(仅草稿可删;已审核请先弃审)
基础档案单=启用(虚拟),行级删除走 asp_cancel

【文书归档面板(DOC_ARCHIVE_PANELS 21 面):保存即归档 + 归档后修改闭环】
草稿 --管理员保存--> 已归档(不经审批,markArchived)
草稿 --普通用户保存--> 审批中 --审批通过--> 已归档 / --审批驳回--> 草稿
已归档 --申请修改--> 修改申请中 --修改审批通过--> 修改中(可编辑,保存不自动归档)
                       +--修改审批驳回--> 已归档
修改中 --提交审批--> 审批中 --审批通过--> finalizeModify 收尾(写修改记录)后 已归档
已归档/已审核 --删除申请--> 删除申请中 --删除审批通过--> 已作废 / --删除审批驳回--> 已归档
删除申请中/修改申请中 --撤回申请--> 已归档(发起人本人或审批人,卡死单据出口)

【标志位】
archived='Y'  归档(archived_at 仅首次归档写入,CASE 保首次——查询时间区间口径)
deleting='Y'  删除申请中(附 delete_req_by/delete_req_at)
modify_state  'R'=修改申请中(附 modify_req_by/at) / 'Y'=修改中(附 modify_appr_by/at);收尾置 NULL
saved         'Y'=该单存过一次 / 'N'=新增未保存或保存为草稿(directAdd 占位='N');
              前端 isFreshAddedDoc() 靠 'N' 界定"本次新增"窗口,**不表示审核状态**
shr/shsj      审核人/审核时间;**保存即归档不写 shr**(归档单纸面审核人栏为空是既定行为)
```

- 审批留痕:`yj_form_approval`(SUBMIT/APPROVE/REJECT/UNAUDIT/STOP/UNSTOP/MODIFY_REQ/MODIFY_APPROVE/MODIFY_REJECT/DELETE_APPROVE/DELETE_REJECT/DELETE_WITHDRAW/MODIFY_WITHDRAW,含 operator/opinion/node_no,结构对齐 light-mes form_approval);提交/通过/驳回/弃审/中止/恢复/删除审批/撤回全记录。
- 防伪校验:`requirePendingSubmission` —— 审批通过/驳回必须紧跟一次有效 SUBMIT/PENDING,防止仅改状态伪造审批结果。
- 权限:**审批类动作(审批通过/驳回、审核、弃审)需审批权 = 管理员(`yj_user.is_admin='Y'`)**∪ **角色对该面板勾了 `yj_role_panel.can_approve='Y'`**(`ButtonService.requireApprover`/`canApprove`,对应 light-mes 角色 can_approve);删除审批/修改审批同口径,撤回申请额外放行申请发起人本人(`delete_req_by`/`modify_req_by`);前端 `approvePanels` 同步控制按钮显隐。
- 守护:审批中不可保存/删除;已审核不可保存;已中止不可保存/审核(须先恢复);已作废不可审核;仅草稿可删除;所有状态变化后端再校验。
- 状态推导:见上方优先级链;列表行附 提交人/提交时间(审批中)与 审核人/审核时间(已审核,`shr≠NULL` 才附 `审批状态='已通过'`)。
- 中止类按钮按面板配置(SO_ORDER 整单中止;MANU_ORDER 中止执行+草稿[恢复]),前端 engine.callButton 归一为 中止/取消中止。

## 6. 保存与编号

- 保存(提交):无编号=新建(头行式写头表占位,单表式写一行占位);有编号=行 upsert(有 id 更新/无 id 插入回填自增/缺席行软删)。
- 基础档案=全量明细 upsert;调用方必须先取全量再提交。
- 编号:`FormNoService` 沿用 s_allno 号池(前缀-yyyy-MM-4 位序,如 PG-2026-09-0001),按 前缀+月份 续号,写号留痕与旧系统一致;面板前缀取 `yj_panel.prefix`(对齐历史单据家族,见 tools/migrate-formno-style.sql)。**单号单调递增、`s_allno` 从不回收**(删除单据不释放单号,不存在"释放后可重发");`yj_doc_status` 里出现"库里没有这张单"的孤儿状态行,成因是**历史清理脚本把业务表头行物理删掉**(2026-09-11 更正),"新建时状态行被清掉"的兜底见 `clearStaleDocStatus`。
- `saved` 标志(2026-09-11 起真生效):`save()` 的 `markSaved` 参数在**写入成功后**落库——`保存/提交/保存新增`→`'Y'`(该单存过一次),`保存为草稿/新增/新增流程`→`'N'`;空草稿占位(directAdd)=`'N'`。`saved` **只表示"存过一次",与审核状态无关**;前端 `isFreshAddedDoc()` 靠 `'N'` 界定"本次新增"窗口(锁定字段默认值/离开守卫撤回整单)。

## 7. 领域动作扩展(PanelActionHandler)

通用生命周期之外的动作(生单、跨单据流转)实现 `PanelActionHandler.supports/handle`,注册为 Spring Bean 即被 `PanelActionRegistry` 分发;与既有生命周期冲突(多处理器)直接报错。

### 7.1 推式生单(PushGenerateHandler,2026-09-01)

`生成XX` 动作:来源单整单映射为目标面板草稿并写占用,返回 `{编号, 单据状态:草稿, gotoPanel}` 由前端跳转。与选单(拉式)**共用** `SELECT_FLOWS` 链路图与 `buildSelectConfig` 头/行映射(同一份映射双向使用),生单后 `VoucherFlowService.link` 写 `form_flow_link`(ACTIVE),来源行不再出现在选单列表;删除下游草稿自动释放(RELEASED)。

- 守护:来源必须已审核;同一(来源,目标)已有 ACTIVE 占用时拒绝重复生单;空明细拒绝。
- 新建兜底:单据日期缺省当天(对齐 PANDA insertGenerated)。
- 首批链路:采购链(请购单→采购订单→采购入库单)、销售生产链(销售订单→生产加工单→产成品入库单/销售出库单)。
- 头映射同义词按链路键控(`FLOW_HEAD_SYNONYMS`):建议供应商→供应商、单据编号→采购订单号/销售订单号、合同号→加工单号;行映射同义词含 物料↔存货 双向口径。

## 8. OCR 与通知

- OCR:图片校验(格式/尺寸/比例)→ 用户级限流 → 云网关 → `OcrFormMapper` 按面板配置白名单映射表头/明细表格;凭据未配置返回明确 503。
- 通知:todo=yj_doc_status 待处理单据;message=s_log 操作日志;alarm=kucun 低库存(<100)。

## 9. 身份、权限与错误

- 除登录/工厂列表外全部需 JWT;BCrypt;无 Session。
- 业务异常:IllegalArgument→HTTP 400,IllegalState→HTTP 409,其余→500;OCR/上传/权限类走 body-code(403/429/503),避免 403 触发前端登出。
- 日志与异常消息不得输出密码、Token 或完整连接串;生产密钥经环境变量(YINJIA_JWT_SECRET / ALIBABA_CLOUD_* / 数据源)。
