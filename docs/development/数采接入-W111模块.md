# 数采接入:天翊电子秤 + W111 无线透传模块

> 适用设备:计价电子秤 **DZ-06**(天翊 / JIANKUN,100kg/10g,蚌埠鸿海工业科技,出厂 2026-09-30,产品编号 JC6120103677)
> + **W111** 串口转 WiFi 透传模块。MES 侧台账设备编码 `DZ-001`,采集点 `W01 重量(kg)`。
> 建立时间 2026-10-19;现场实测记录随接线进度更新。

## 1. 链路

```
电子秤 RS232 ──串口线──> W111 模块 ──WiFi──> 本机接收端(8099) ──HTTP──> MES /api/dc/ingest ──> 数采流水
                                    (W111 只能原样转发串口字节,拼不出 MES 要求的 JSON + X-DC-Key)
```

MES 侧已就绪:网关 `GW-DZ-01`(接入密钥 `scale-demo-2026`)、设备 `DZ-001`(已绑网关/数采工程/组态)、
采集点 `W01 重量`(kg,量程 0–200)、规则「稳定值上报」「超量程报警」。第一次真实上报会自动补上「数据调试」,配置度 100%。

## 2. W111 模块配置(浏览器操作)

1. 电脑连模块的 AP:`W111`,密码 `12345678`(APSTA 模式,模块自己也连现场路由器)。
2. 浏览器打开 `http://192.168.4.1`,账号/密码都是 `admin`。
3. **系统**页:路由器 SSID / 密码 = 现场 WiFi(⚠ 必须与运行接收端的这台电脑同一网段);
   LAN IP 保持 `192.168.4.1`;网页账号保持 admin。改完点**保存并重启**才生效。
4. **端口1** 页:串口参数 `9600 8 N 1`(说明书口径:默认 9600 不用改;恢复出厂后要改回 9600);
   传输模式选 **http**;填服务器地址 = 本机 IP(现阶段 `192.168.23.109`)、端口 `8099`、
   请求方式 `POST`(或 GET,两种接收端都吃)、URL `/scale`。
5. 高级选项里的「搜索关键字 userdata / 搜索端口 8168」:接收端已在 8168 做自动发现应答,
   若模块自己广播找服务器,会收到含本机 IP 的回复。

## 3. 本机接收端

```powershell

node tools/archive/_dc-scale-live-20261019/_w111-receiver.cjs --dry

# 2) 报文能解析出重量后,去掉 --dry 正式上报
node tools/archive/_dc-scale-live-20261019/_w111-receiver.cjs
```

- 端口 `8099`(HTTP)+ `8168`(UDP 自动发现),设备 `DZ-001` / 采集点 `W01` / 密钥 `scale-demo-2026` 都可命令行覆盖。
- 收到什么打什么:方法、路径、查询串、请求头、正文原样打印;抽到重量就上报,抽不到只记录。
- 串口直连(不经 W111)时用同目录 `_scale-bridge.ps1`,支持 `-Sniff` 嗅探与 `-Simulate` 链路自测。

## 4. 防火墙与网络

- Windows 防火墙 Private/Public 都开;`node.exe` 已有入站放行规则(程序级),故 8099 一般可直接被访问。
- 若模块连不上,用管理员 PowerShell 显式放行:
  ```powershell
  New-NetFirewallRule -DisplayName 'YINJIA DC W111 8099' -Direction Inbound -Protocol TCP -LocalPort 8099 -Action Allow
  ```
- 本机 IP 是 DHCP 分配(WLAN `192.168.23.109`,网关 `192.168.23.1`),换网/重连会变;
  IP 变了就把模块里的服务器地址改成新 IP(或在路由器给这台机器做静态绑定)。

## 5. 排障对照

| 现象 | 先查什么 |
|---|---|
| 接收端一个请求都没收到 | 模块与电脑是否同一网段(模块状态页看是否拿到 IP);端口 8099 是否被防火墙挡;服务器地址是否写成公网/旧 IP |
| 收到请求但抽不到重量 | 打开 dry 打印看正文;秤可能不是连续输出(按秤的「功能」键切连续);波特率可能 4800/2400 |
| 重量全 0 | 秤未放物或未去皮;模块缓冲区/帧拼接问题(看请求里是否半截帧) |
| 上报 401/400 | 网关密钥与 `GW-DZ-01` 不符,或设备没绑网关(`scale-demo-2026`) |
| 数据监控显示「数据过期」 | 超过心跳窗口(60s×3)没有新上报 —— 正常,说明没数据在流 |

## 6. 现场实测结果(2026-10-19,已打通)

| 项 | 实测值 |
|---|---|
| 模块 IP | `192.168.23.120`(MAC `EC:C9:FF:17:F8:20`,APSTA 连 `agplus会议室`,DHCP) |
| 模块配置 | `uart1 = 9600 8N1 NFC`、`sock1a = TCPS 8010 max8`(客户端连 8010 收串口数据) |
| 秤 | 天翊/JIANKUN DZ-06 计价秤,`100kg/10g`,编号 `JC6120103677` |
| 操作 | **放物品 → 按秤上的 `*` 键** = 发送一帧(不是连续输出) |
| 帧格式 | `+000.39000.00kg
` = 净重 `+000.39` + 皮重 `000.00` + 单位 `kg` + CRLF(17 字节,中间无分隔符) |

## 7. 方案 C(已落地):W111 直接 HTTP 推到 MES —— 不需要电脑常开

**模块配置(端口1)**,现场实测可用(固件 V1.0.2):

| 字段 | 值 | 说明 |
|---|---|---|
| 模式 | `HTTP Client(SSL)`(HTPC) | 原 TCPS 模式不再使用 |
| 请求方式 | `POST` | 正文 = 串口帧原文 |
| 服务器地址 / 端口 | MES 主机 / `8090` | 部署到服务器后改成服务器 IP |
| URL | `/api/dc/ingest/text?device=DZ-001` | **≤64 字符**,设备号走查询串 |
| 协议头 | `X-DC-Key: scale-demo-2026\|Content-Type: text/plain` | ≤64 字符,多个头用 `\|` 分隔 |
| 包头过滤 / 超时 | `OFF` / `6` | |

保存后**必须重启模块**(`/cgi-bin/ctrl?ops=reboot`)。

**MES 侧文本上报口**:`GET|POST /api/dc/ingest/text`
- 取重量顺序:查询串 `data`/`v`/`value` → POST 正文 → 查询串整体 → 请求 URI;
- 设备号:`device` 或 `deviceCode` 查询参数,或请求头 `X-DC-Device`(缺省 `DZ-001`);
- 鉴权:`X-DC-Key` 必须等于该设备所绑网关的 `api_key`(与 JSON 口同一套);
- 解析口径与现场一致:先「净重+皮重+kg」(`+000.41000.00kg`),再退回通用数值规则。

**实测(2026-10-19 14:25)**:秤按 `*` → 模块 `HTTP` 上行 34 字节(两帧)→ MES 返回 1126 字节 →
`DZ-001` 在线、`W01 = 0.41 kg` 状态正常,**本机没有任何中转脚本在跑**。

一键配置/回滚:

```powershell
# 切到 HTTP 直推(参数:模块地址 / MES 主机 / MES 端口)
node toolsrchive\_dc-scale-live-20261019\_configure-w111-http.cjs 192.168.23.120 192.168.23.109 8090
# 回滚成 TCP 服务端模式(仍用本机监听脚本)
node toolsrchive\_dc-scale-live-20261019\_configure-w111-http.cjs --restore
```

**部署到服务器时只改一处**:模块「服务器地址/端口」改成服务器 IP 与端口(如 `10.0.0.5:8090`),
MES 端不用改;车间不需要留任何电脑。
