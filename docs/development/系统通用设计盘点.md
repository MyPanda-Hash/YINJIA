## A2. 选单占用/生单技术差异(细节)

| 维度 | light-mes(E 盘) | YINJIA-MES |
|---|---|---|
| 占用存储 | **无占用表**:`reservedQuantity()` 遍历**全部 FormData 单据**,按明细行「来源面板/来源单号/来源行号」反查累加执行数量 | **`form_flow_link` 持久化**(source/target 面板+单号+行键+数量+`link_status ACTIVE/RELEASED`+释放时间) |
| 性能 | 每次校验全库扫描 O(全部单据×明细) | SQL 索引查询占用,行级可算剩余数量 |
| 释放 | 无显式状态,靠「下游已中止排除」软过滤;不写回 | 删除/取消下游草稿时 `UPDATE ... RELEASED`(留痕 release_time) |
| 生单映射 | **每对面板硬编码方法**(PxService 内 ~20 个 `generateXxx`(SO→MO、MO→PROCESS_REPORT、PU_REQ→PU_ORDER…),头/行字段逐个手写 | **`PushGenerateHandler` + `VoucherFlowService`**:与选单共用 `SELECT_FLOWS` 链路图与头/行映射(同一份映射双向复用),面板对(动作→目标)可配置;`supports()` 按 `pushTarget` 判定 |
| 数据存储 | 统一 `FormData`(panelCode/formNo/status/detailData JSON 一张表) | 业务化 bd_/bl_ 业务表 + `yj_doc_status` 状态表 |
| 选单来源 | `buildSelectConfig` 按 source 面板生成,已有状态过滤(已审核) | `voucherFlow/sources` 已审核 + 占用过滤(剩余数量),分页 |

## 评审锚点(对照着找遗漏)

1. 新面板上线全流程是否都走"元数据插行"而不用改前端?(A1/A6/A7)
2. 列头能改名/排序/显隐、列头筛选、查询方案?(B1/B2)
3. 切换语言:静态包→机翻→落库→重渲,字段/面板/按钮全覆盖?(C 全)
4. 单据状态/审批/生单/占用/删除释放链路是否统一?(D 全)
5. 权限:角色×面板×11 操作;审计:登录/操作留痕?(E 全)
6. 无实现按钮灰态、未知动作安全降级?(A4)
7. 导入/导出/打印/预览/扫描填单是否随面板自动具备?(B/F)
