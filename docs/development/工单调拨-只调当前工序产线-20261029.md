# 工单调拨：只能调拨到「当前工序」的产线（2026-10-29）

> 用户口径（原话）：「修改当前工单排产的调拨逻辑需要实现当前的调拨只能调拨到当前工序的产线中」
>
> 落点：工单排产页 `WORK_ORDER_BOARD`（`frontend/src/views/modules/plan/WorkOrderBoard.vue`）的
> **调拨**按钮 → `POST /api/px/scheduleBoard/transfer`。**不动数据库结构**（纯逻辑 + 一个新读接口）。

## 1. 改前是什么样（为什么要改）

旧调拨弹窗的「目标车间 / 目标生产线」两个下拉是**前端拿整条产线档案拼的**
（`/px/scheduleBoard/workshops` + `linesSummary`），服务端只校验三件事：
目标线存在、未停用、属于所填车间（而车间本身也是前端随便填的）。

⇒ 现场能把**切炭工序**的工单调到**成型线**、把**组装**单调到**切炭线**，轨迹照样写、
看板照样显示「已调拨」，直到报工/检验环节才暴露工序与产线对不上。

## 2. 现在的口径（唯一一处，三处复用）

| 概念 | 唯一出处 | 说明 |
|---|---|---|
| **当前工序** | `ProcessTaskService.currentProcess(plNo, rowId)` | 与看板「当前工序」列 / 生产工单列表**同一口径**：`wo_process_line` 里**最后一道「已落实」**（工序序倒序）优先；台账缺失回落**本行** `plang.[当前工序]` |
| **这道工序能去哪些线** | `ProcessTaskService.lineScope(op, routeShop)` | 复用既有的工序↔产线**软判据**（`ProcessShop` + `ProcessTaskService.requiredShop`，与派工/预排线/转序同源）：成型/切炭/组装/装箱 且该车间**真有启用线**才限定；判不出（新工序、该车间没建线、工序为空）⇒ 全部启用线，**不猜也不拦**（2026-10-28 口径不变） |
| **目标产线是否合法** | `WorkOrderTransferService.transfer(...)` 内逐行守卫 | **服务端硬校验**，不信任前端；非法即整行拒绝并给出「当前工序 X 只能调到 Y 车间（候选线…）」 |

### 2.1 弹窗候选（新接口）

`POST /api/px/scheduleBoard/transferTargets`（权限 = 页面可见 + 「调拨」动作词）

请求：`{ rows: [{ 工单号, 行id, 工单行号, 批次号 }] }`（与 `/transfer` 同格式）

响应：

```json
{
  "逐行": [{ "工单号": "GD-…", "行id": 2172, "工单行号": 1, "当前工序": "成型",
             "应进车间": "成型", "当前产线": "2号车间", "候选数": 19 }],
  "工序": ["成型"],              // 选中行当前工序去重
  "车间": ["成型"],              // 候选线所属车间去重(下拉用)
  "产线": [{ "生产线": "成型1线", "生产车间": "成型", "日产能": 0 }],
  "可调拨": true,                // 产线为空 ⇒ false(前端禁用「确认调拨」)
  "提示": ""                     // 不可调拨原因(中文业务话术,前端原样显示)
}
```

**多行勾选 = 取交集**：每个选中行都允许的线才会列出；不同工序的工单没有共同合法目标时
返回 `可调拨=false` + 「所选工单当前工序不同（成型 / 组装）…请按工序分行调拨」，
不给一个点了就被服务端驳回的选项。

**剔除原线**：所有选中行都在同一条线时，候选里剔掉它（调到原线没有意义，服务端也会拒）。

### 2.2 旧入口 `/reassign` 一并收口

`POST /px/scheduleBoard/reassign`（批量调线，前端已无调用方）原本**只改线、不写轨迹、不校验工序**，
等于给新规则留了个绕过口。现在它直接转调 `WorkOrderTransferService.transfer(...)`：
同一套工序守卫 + 轨迹 + 可撤回 ⇒ **改线只剩一条路径**，历史调用方行为只会更严（多出轨迹，可撤回）。

## 5. 边界与遗留

1. **判不出当前工序**（无台账且 `plang.当前工序` 为空）⇒ **不设限**（全部启用线可选），
   与仓库既有软判据一致（不猜也不拦）；若后续要求"判不出就禁止调拨"，改 `lineScope` 的 `null` 分支即可。
2. 历史跨车间数据（17 行）不自动纠正：老工单已在错误线上，新规则只约束**之后的调拨**；
   要纠偏请用「撤销排产 → 重新排线」或正常调拨回本工序线。
3. 调拨**不会**重写 `wo_process_line.计划生产线`（轨迹只记产线变化；台账计划线仍按预排产时的选择），
   与旧行为一致 —— 若要求"调拨同时改计划线"，需另开需求（会影响转序自动派线）。
4. 手机端/外部程序若直写 `plang.scx`，不经本守卫（与既有的"外部直写库"边界一致）；
   MES 侧所有改线入口（`/transfer`、`/reassign`）都已收口。
