# 库存表清单

> 系统里的「库存」不是一张表，而是**三套并行记录 + 一组档案**。看库存数字之前，先确认你看的是哪一套。
>
> - 本文只登记**对象与口径**；逐表的中文名/列数/关联面板见 [数据库表清单](数据库表清单.md)，建表改表的硬规矩见 [数据库规范](数据库规范.md)。
> - 采集自 2026-09-30 的 HSDZ_MES 正式库 + 代码；数字会变，**结论口径跟着代码走**。

## 1. 三套库存记录（先认清这个）

| 套 | 载体 | 语义 | 谁写 | 谁读 |
|---|---|---|---|---|
| **A. 余量台账** | `kucun`（库存资料，**拼音遗留表**） | 一行 = (物料 `wzdm`, 仓库 `ckdm`, 批号 `lot_no`)，`rkl` 累计入库 / `ckl` 累计出库 / **`yl` 现存量** | 单据**审核时过账**、弃审对称冲回（`StockLedgerService`）；不良品处理（`QcDisposalService`）；手工「新增库存」（`ButtonService:1805`） | 面板「库存状况」`STOCK_STATUS`（`QueryService:156`）、桌面「现存量 TOP」（`DashboardStatsService:276`）、低库存预警（`PortalNotificationService:142`） |
| **B. 凭证式台账** | 4 个视图 + 1 张物化表（见 §2） | 一行 = 一条**已审核**出入库明细；余量与金额由聚合/递归算出 | 视图本身不写；源头是 8 组出入库单据（只认 `单据状态='已审核'`） | 面板「库存台账」`STOCK_LEDGER`、「库存状况表」`STOCK_BALANCE`、「收发存汇总表」`STOCK_SUMMARY`；成本表由 `InvCostService` 重算 |
| **C. 遗留进销存** | `inh`(进货单 115 列)/`outh`(出货单 126 列) | 经典 HSDZ 的进/出物理表 | 历史遗留，MES 侧不写 | **桌面统计**（`DashboardStatsService:20` 自述「库存 = inh/outh 两物理表」） |

> ⚠️ A 与 B **不是同一口径**：A 是「审核即改余量」的实时账，B 是「按已审核明细重算」的凭证账。两边不一致时不要急着判谁错 —— 先看是不是拿 A 的数去对 B 的表。

## 2. 逐个对象

### 2.1 库存量（B 套）

| 对象 | 类型 | 作用 | 依赖 |
|---|---|---|---|
| `v_stock_movement` | 视图 | **库存移动明细**：8 种单据 `UNION ALL`，`src` 1..8 标来源、`收入数量/发出数量/收入金额` 逐行铺开 | `bd/bl_` 8 组头行表 + `bs_wh`（仓库名兜底成编码） |
| `inv_cost_ledger` | 表（物化） | **移动加权成本**：`PK(src,rid)` 对应 movement 一行，存 `结存数量/结存金额/移动加权单价/发出成本金额` | 由 `InvCostService` 递归重算 |
| `v_stock_ledger` | 视图 | **库存台账**：movement 左连成本表，逐行给出期初/收入/发出/期末 | movement + inv_cost_ledger |
| `v_stock_balance` | 视图 | **库存状况表**：按 (仓库键,仓库编码,仓库,存货编码,存货,规格型号,计量单位) 聚合出 `现存量/结存单价/结存金额` | movement + inv_cost_ledger |
| `v_stock_summary` | 视图 | **收发存汇总**：按 (仓库,存货,期次=年月) 窗口累计出期初/本期入出/期末 | v_stock_ledger |

**`v_stock_movement` 的 8 段**（`src` 即段号，段内已过滤 `asp_cancel<>'Y'` 且 `单据状态='已审核'`）：

| src | 单据 | 方向 | 头/行表 |
|---|---|---|---|
| 1 | 采购入库单 | 入 + | `bd_purchase_in` / `bl_purchase_in` |
| 2 | 产成品入库单 | 入 + | `bd_finish_in` / `bl_finish_in` |
| 3 | 其他入库单 | 入 + | `bd_other_in` / `bl_other_in` |
| 4 | 委外入库单 | 入 + | `bd_outsource_in` / `bl_outsource_in` |
| 5 | 销售出库单 | 出 − | `bd_sale_out` / `bl_sale_out` |
| 6 | 材料出库单（领料） | 出 − | `bd_material_out` / `bl_material_out` |
| 7 | 其他出库单 | 出 − | `bd_other_out` / `bl_other_out` |
| 8 | 委外发料单 | 出 − | `bd_outsource_issue` / `bl_outsource_issue` |

**两个容易踩的口径**：

- **仓库键** = 单据自身仓库编码 → 退 `bs_wh` 按名称查编码 → 再退 `'#'+仓库名称`。兜底是必需的：不兜底同一仓库会被拆成 92 个分区，兜底后 78 个（与按名称分组一致）。见 `v_stock_movement` 末段注释。
- **采购入库/销售出库额外认 `单据状态2='C'`**（金蝶手动关闭也计入），其余 6 种只认 `单据状态='已审核'`。

### 2.2 成本（B 套）

`inv_cost_ledger` —— **为什么是物化表而不是视图**（`InvCostService.java:12-34` 原文，值得完整保留）：

- 真·移动加权平均本质是**递归**（无闭式解）。递归 CTE 可以建视图，但**视图不能带 `OPTION (MAXRECURSION)`**，走默认 100 行上限 ⇒ 台账 235 行就报「已用完最大递归 100」。
- 退而用「累计入库加权平均」虽是闭式、可进视图，但**口径不同**：实测 2,268,221.49 vs 真值 3,092,184.28（**差 27%**），不可当近似互换。
- 也不用存储过程：迁移以 `yinjia` 执行，它只有 `db_ddladmin/db_datareader/db_datawriter`（非 `db_owner`），在 dbo 下建的对象归 dbo ⇒ 既不能 EXECUTE 也无权 GRANT EXECUTE，运行期审核钩子会直接报权限错。**Java 侧直跑这段 SQL 反而没权限问题**（`OPTION (MAXRECURSION 0)` 只是语句一部分）。
- **分区口径 = (仓库键, 存货编码)，不含批号**：批号进分区键会让分区数 78 → 225，其中 **114 个（51%）「只出无进」** ⇒ 出库成本恒 0、结存数量为负，报表不可用。根因不是"销售批号为空"（空批号销售仅 13 行，其中只剩 1 行的存货本有入库），而是**同一批号值在采购侧与销售侧挂到了不同 (仓库,存货) 组合**上。故批号只作台账**明细列**，不做成本分区、不进 balance/summary 的 GROUP BY。
- 重算触发点：审核/弃审钩子 + 启动自检 + 面板「重算成本」。
- 与 `tools/migrate-inv-report-fields.sql` 的**分工**：迁移建视图与物化表（不预填），运行期由 `InvCostService` 重算；**二者口径必须一致，改动要同步该文件头部注释**。

### 2.3 档案

| 表 | 中文名 | 列/行(2026-09-30) | 在库存链路里的角色 |
|---|---|---|---|
| `bs_inv` | 存货档案 | 145 列 / 114 行 | 物料/产品主数据（含是否检验标志）；`kucun.wzdm` 与视图的存货编码都指向它 |
| `bs_wh` | 仓库档案 | 52 列 / 18 行 | **仓库编码 ↔ 名称的真源**：过账守卫「仓库档案必须存在」查它；movement 的仓库键兜底也查它 |
| `bs_wh_loc` | 库位档案 | 32 列 / **0 行** | 仓库内货位（一仓多库位）；库位二维码 = `仓库@库位地址@库位编码`。**尚未启用** |
| `bs_inv_price` | 存货价格本 | 52 列 / 30 行 | 面板 `INV_PRICE`（archive 模式）在用 |
| `dm_ck` | 仓库代码 | 42 列 / 22 行 | ⚠️ **遗留拼音表**，与 `bs_wh` 并存；新代码一律用 `bs_wh` |

### 2.4 出入库单据（写盘点/写成本都靠它们）

16 张头行表见 §2.1 的 8 段表。**现状**（2026-09-30 正式库）：`bd_*` 头表全部 **0 行**，`bl_*` 行表各 1 行（演示数据）——**即这张链路在正式库里还没真正跑过业务**。

### 2.5 遗留旁路

`inh`(进货单) / `outh`(出货单)：经典 HSDZ 物理表，**MES 侧只读不写**，被桌面统计用（`DashboardStatsService`）。它们**不参与** A/B 两套库存的计算。

## 3. 数据流

```
                     ┌──────────────────────────── 8 组出入库单据(bd_/bl_) ────────────────────────────┐
                     │  采购入库 / 产成品入库 / 其他入库 / 委外入库        销售出库 / 材料出库 / 其他出库 / 委外发料  │
                     └───────────────┬───────────────────────────────────────────────┬─────────────────┘
                                     │ 审核(postIn)                                   │ 弃审(unpostIn)
                                     ▼                                                ▼
        ┌────────────────────────────────────────┐                    ┌──────────────────────────────┐
        │ A. 过账 kucun                          │                    │ 对称冲回:rkl/ckl 回退、yl 反向   │
        │   (物料,仓库,批号) 一行:               │                    │ 守卫:冲回为负则拒绝、整笔回滚     │
        │   rkl += 入库量, yl += 入库量          │◀───────────────────┤ StockLedgerService.unpostIn    │
        │   ckl += 出库量, yl -= 出库量          │                    └──────────────────────────────┘
        │   守卫:仓库档案须存在 / 出库不得超现存量  │
        └────────────────┬───────────────────────┘
                         │ 读
                         ▼
        库存状况(STOCK_STATUS) / 桌面现存量TOP / 低库存预警

        ┌────────────────────────────────────────┐
        │ B. 视图链路(只认「已审核」,不改任何表)   │
        │   v_stock_movement  ← 8 段 UNION ALL    │
        │        │                                │
        │        ├─► InvCostService 递归重算 ──► inv_cost_ledger (成本物化)
        │        │                                │
        │        ├─► v_stock_ledger   (台账:逐行期初/收入/发出/期末)
        │        │        └─► v_stock_summary (收发存:按月窗口累计)
        │        └─► v_stock_balance  (状况表:按仓库×存货聚合出现存量/结存金额)
        └────────────────────────────────────────┘
```

**A、B 谁先谁后**：互不依赖。A 在**单据审核的同一个事务里**改 `kucun`；B 是**查询时才算**（视图）+ 成本表在审核/弃审钩子里重算。所以：

- 审核失败会整笔回滚（A 与 B 都不会留下半截）；
- 但**弃审时 A 有兜底跳过**（`StockLedgerService.java:53-60`：无明细行或仓库三列全空 ⇒ 跳过冲回、不阻断弃审），B 那边就没有这层 —— 历史单弃审后两边可能不一致。

## 4. 口径、守卫与已知坑

| # | 事项 | 说明与出处 |
|---|---|---|
| 1 | **过账顺序：先确认批次号，再库存过账** | `ButtonService.java:1118` —— 否则 `kucun.lot_no` 落的是确认前的批号 |
| 2 | **批号口径变更的冲回兜底** | `StockLedgerService.java:65-70`：采购入库批号改成「批次号优先、批号兜底」后，历史单按旧口径记的账要用**备选批号**再冲一次（备选"存在但为空"也算），否则"账在、批号口径变了、冲回静默跳过"⇒ 库存虚挂 |
| 3 | **出库必须扫码带批号，且台账行必须已存在** | `StockLedgerService.java:14` |
| 4 | **现存量不足 / 冲回为负 ⇒ 拒绝** | 同上 `:15`（整笔回滚） |
| 5 | **仓库三列全空才算"缺失"** | `StockLedgerService.java:54-58`（2026-09-23 口径：行仓库/头仓库/行仓库名称/行仓库编码/头仓库编码 全空） |
| 6 | **成本分区不含批号** | 见 §2.2：含批号会产生 51% 的"只出无进"分区 |
| 7 | **`kucun` 是拼音遗留表，但仍是 A 套的真源** | 列名 `wzdm/ckdm/rkl/ckl/yl` 等；**中文注明是后补的**（`sys.extended_properties` 有全套）。`备用1` 的注明写着「库存状况面板排序分页键」——改它之前先读那条注明 |
| 8 | **当前 `kucun` 31 行的批号全是 `INIT-*`** | 即由**期初初始化**灌入，不是单据过账跑出来的（对应 §2.4：`bd_*` 全 0 行）。**别拿它当"过账链路已验证"的证据** |
| 9 | `inv_cost_ledger` 当前 **0 行** | 成本尚未算过（或算过又清空）；面板上的"结存金额/单价"会全 0 —— 先点「重算成本」再判断 |

## 5. 要改库存时先看这里

- **加一种出入库单据**：要同时动三处 —— ① `v_stock_movement` 加一段（`src` 取下一个号）② `StockLedgerService.postsStock()` 登记面板码 ③ `tools/migrate-inv-report-fields.sql` 头部口径注释同步。漏了 ①，该单据不进任何库存视图；漏了 ②，审核不过账 `kucun`。
- **改成本算法**：改 `InvCostService` 时必须同步 `tools/migrate-inv-report-fields.sql` 的注释（它俩是同一口径的两半）。
- **改仓库口径**：`bs_wh` 是编码↔名称真源；`dm_ck` 是遗留，**不要新引用**。
- **库存对不上时的排查顺序**：① 先确认问的是 A 还是 B（§1）② B 的话看单据是不是「已审核」③ 成本列全 0 就先重算成本 ④ A 的话看 `kucun` 那三键（物料/仓库/批号）与单据是否同口径（坑 #2）。

## 6. 刷新本清单

```powershell
# 1) 表/视图清单与行数(在 tools 目录)
sqlcmd -S localhost -d HSDZ_MES -U yinjia -P <pwd> -W -s "|" -h -1 -f 65001 -Q "SET NOCOUNT ON; SELECT t.name+' | '+ISNULL(CAST(ep.value AS nvarchar(200)),'') FROM sys.tables t LEFT JOIN sys.extended_properties ep ON ep.major_id=t.object_id AND ep.minor_id=0 AND ep.name='MS_Description' WHERE t.name LIKE '%stock%' OR t.name LIKE '%inv%' OR t.name LIKE '%_wh%' ORDER BY t.name;"
# 2) 视图定义(含中文列名,请用 JDBC 而不是 sqlcmd —— sqlcmd 的 -W 与 -y/-h 互斥,取全文本会报错)
#    参考 tools/archive/_req/ 下同款 JDBC 探针写法
```
