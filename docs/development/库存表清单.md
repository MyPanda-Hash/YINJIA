# 库存表清单

> **现行结构（2026-09-30 起）：三张表。** 库存明细（流水）与结存分开存，**流水是唯一真源**，`kucun` 只是结存缓存。
>
> | 表 | 角色 | 一行是什么 |
> |---|---|---|
> | `inh` | **入库流水** | 一张已审核入库单据的一行（采购入库 / 产成品入库 / 其他入库 / 委外入库 / 期初结存） |
> | `outh` | **出库流水** | 一张已审核出库单据的一行（销售出库 / 材料出库 / 其他出库 / 委外发料） |
> | `kucun` | **结存缓存** | 一个 `(物料编码, 仓库编码, 批号)` 的 `rkl` 累计入 / `ckl` 累计出 / `yl` 现存量 |
>
> 报表（库存台账 / 库存状况表 / 收发存汇总）读的是**流水**；启动自检核对 `结存 == Σ流水`，不一致即报警。
>
> 本文只登记**对象与口径**；逐表的中文名/列数/关联面板见 [数据库表清单](数据库表清单.md)，建表改表的硬规矩见 [数据库规范](数据库规范.md)。

## 1. 三张表

### 1.1 `inh` 入库流水 / `outh` 出库流水

| 项 | 说明 |
|---|---|
| 来源 | 8 类出入库单据**审核时**由 `StockLedgerService` → `StockFlowService` 在**同一事务**内写入；弃审红冲（`asp_cancel='Y'` 软删），重新审核**复活**并刷新单据侧字段 |
| 幂等键 | `(src, rid)` **过滤唯一索引**（`WHERE rid IS NOT NULL`）—— `rid` = 来源单据行 `bl_*.id` |
| `src` 段号 | 1 采购入库 / 2 产成品入库 / 3 其他入库 / 4 委外入库 / **0 期初结存** / 5 销售出库 / 6 材料出库 / 7 其他出库 / 8 委外发料 |
| 关键列 | `单据编号` `单据类型` `单据日期` `物料编码` `仓库编码`（**解析后的档案编码**，与 `kucun.ckdm` 同源）`仓库名称` `批号` `数量` |
| 仅 `inh` 有 | `单价` `金额` `含税金额` `税额` |
| 仅 `outh` 有 | `单据金额`（售价，不参与成本）`成本单价` `成本金额`（由 `inv_cost_ledger` 回填） |
| 历史 | 由遗留纺织表 `inh`/`outh`（115/126 列、数量单位"米/公斤"）**清空重建**而来；老数据备份为 `tools/archive/_stock-flow-backup-20260930.csv` |

**期初**：`src=0`、`rid=NULL`、`单据日期 = 1900-01-01`（**哨兵值，不是业务时点**）。取远古日期是为了移动加权成本的顺序：成本按 `(仓库编码, 存货编码)` 分区、按 `(单据日期, src, rid)` 递归滚 —— **若期初定在"昨天"，任何补录的历史单据都会排到它前面**，变成"先出库后入库" ⇒ 出库成本算 0、结存为负。

### 1.2 `kucun` 结存缓存

| 项 | 说明 |
|---|---|
| 粒度 | `(wzdm 物料编码, ckdm 仓库编码, lot_no 批号)` |
| 真正被写的列 | `rkl` 入库量 / `ckl` 出库量 / `yl` 现存量（外加 `lot_no`、`in_date`、`price`、`预警数量`） |
| 谁写 | `StockLedgerService`（单据过账/冲回）与 `QcDisposalService`（不良品处理，**不走统一过账**，见坑 4） |
| 谁读 | 工单齐套 `v_wo_kit`（直接 `SUM(k.yl)`）、采购申请、低库存预警、桌面现存量 TOP、「库存状况」面板（`STOCK_STATUS`，**已从菜单下线但配置保留、表不能动**） |
| ⚠ 遗留列 | `rkl2`/`ckl2`/`yl2`（匹数）、`kucun_no`、`khdm`、`total_je` **当前代码零引用** —— 别照名字猜用途 |
| `asp_user1` | 写入来源标记：`stock:<user>` / `qc:<user>` / `migration` |

## 2. 库存视图与成本

| 对象 | 类型 | 作用 |
|---|---|---|
| `v_stock_movement` | 视图（23 列） | **库存移动明细**：读 `inh`/`outh` 两张流水表。仓库键三级兜底：自身编码 → 退 `bs_wh` 按名称查 → `'#'+名称` |
| `inv_cost_ledger` | 物化表（PK `(src,rid)`） | **移动加权成本**。分区 = `(仓库键, 存货编码)`，**不含批号** |
| `v_stock_ledger` | 视图 | 库存台账：流水 + 期初/期末（取自成本表） |
| `v_stock_balance` | 视图 | 库存状况表：按 `(仓库键,存货…)` 聚合 `现存量/结存单价/结存金额` |
| `v_stock_summary` | 视图 | 收发存汇总：按 `(仓库,存货,期次)` 窗口累计 |

**成本为什么必须物化**（`InvCostService` 头部注释，勿删）：
- 真·移动加权平均是**递归**（无闭式解）。递归 CTE 可以建视图，但**视图不能带 `OPTION (MAXRECURSION)`**，走默认 100 行上限 ⇒ 台账 235 行就报「已用完最大递归 100」。
- 「累计入库加权平均」虽是闭式，但**口径不同**：实测 2,268,221.49 vs 真值 3,092,184.28（**差 27%**），不可当近似互换。
- 也不用存储过程：迁移以 `yinjia` 执行（非 `db_owner`），dbo 下建的对象既不能 EXECUTE 也无权 GRANT。**Java 直跑这段 SQL 反而没权限问题**。
- **分区不含批号**：批号进分区键会让分区 78 → 225，其中 **114 个（51%）「只出无进」** ⇒ 出库成本恒 0、结存为负。

**重算触发点**：审核/弃审钩子（全量）· 启动自检（双指纹比对，不一致才重算，失败不阻断启动）· 面板「重算成本」。

**性能**：这 4 张报表必须带 `OPTION (RECOMPILE)`（缓存计划 65,021 ms vs 42 ms，前端 axios 15s 超时）。**视图本身不能带 hint**，故只能加在取数 SQL 上（`QueryService` 的 `recompileOnRead`）。

## 3. 档案

| 表 | 中文名 | 在库存链路里的角色 |
|---|---|---|
| `bs_inv` | 存货档案 | 物料/产品主数据；`inh.物料编码` 与 `kucun.wzdm` 都指向它 |
| `bs_wh` | 仓库档案 | **仓库编码 ↔ 名称的真源**：过账守卫「仓库档案必须存在」+ 视图仓库键兜底都查它 |
| `bs_wh_loc` | 库位档案（0 行） | 仓库内货位。**库存链路零引用**，尚未启用 |
| `bs_inv_price` | 存货价格本 | 面板在用，但**库存链路零引用** —— `kucun.price` 与流水的金额都来自**单据行**，不读价格本 |
| `dm_ck` | 仓库代码（遗留） | 旧码（101/102/L201…），与 `bs_wh` 的 `CK01..CK05/WH-CL` **零交集**；仅遗留视图引用。**新代码一律用 `bs_wh`** |

## 4. 出入库单据（8 组 16 张）

`bd_purchase_in`/`bl_purchase_in` · `bd_finish_in`/`bl_finish_in` · `bd_other_in`/`bl_other_in` · `bd_outsource_in`/`bl_outsource_in` · `bd_sale_out`/`bl_sale_out` · `bd_material_out`/`bl_material_out` · `bd_other_out`/`bl_other_out` · `bd_outsource_issue`/`bl_outsource_issue`。

**它们是流水的唯一业务来源**：审核动作触发过账（写流水 + 改结存），`提交审批 → 审批通过` 同口径。

## 5. 数据流

```
     8 组出入库单据（bd_/bl_）
              │  审核 / 审批通过（同一事务）；弃审 = 对称冲回
              ▼
   ┌──────────────────────────────┐
   │ inh / outh（流水，唯一真源）    │
   │ kucun（结存缓存，同事务更新）   │
   └──────────────┬───────────────┘
                  │
        v_stock_movement（读流水）
                  ├─► InvCostService 递归重算 ──► inv_cost_ledger
                  ├─► v_stock_ledger ──► v_stock_summary
                  └─► v_stock_balance
                  │
        启动自检：结存 == Σ流水，不一致即 WARN 并列出差异三键
```

## 6. 口径与已知坑

| # | 事项 | 说明 |
|---|---|---|
| 1 | **过账顺序：先确认批次号，再库存过账** | `ButtonService` —— 否则 `kucun.lot_no` 落的是确认前的批号 |
| 2 | **弃审与审核不对称** | 无明细行 / 仓库三列全空 ⇒ **静默跳过**冲回（`StockLedgerService`）：单据弃审了但结存仍留着那笔。**流水侧天然一致**（跳过发生在写流水之前） |
| 3 | **批号口径换过，冲回要带备选批号** | 采购链批号改为「批次号优先、批号兜底」后，历史账要用备选批号再冲一次，否则「账在、批号口径变了、冲回静默跳过」⇒ 库存虚挂 |
| 4 | **不良品处理（`QC_DISPOSAL`）不在统一过账集合里** | 它经 `QcDisposalService` 直接改 `kucun`（原仓出 + 目标仓入两笔）⇒ **移仓/报废在流水与三张报表里不可见**，也不触发成本重算 |
| 5 | **无批号不许出库；台账无该批行不许出库** | `StockLedgerService` |
| 6 | **`bs_wh` 有重复行** | 18 行只有 11 个不同名称（原料仓/辅料仓/成品仓/半成品仓各 2 行、不良品仓 3 行）⇒ **任何按仓库名 join 的地方都会翻倍**。相关脚本一律用 `OUTER APPLY (SELECT TOP 1 … ORDER BY id)` |
| 7 | **`inh`/`outh` 有过滤索引 ⇒ DML 必须 `SET QUOTED_IDENTIFIER ON`** | `sqlcmd` 默认 OFF ⇒ `DELETE FROM inh` 报 `1934`；命令行加 `-I`。走 JDBC 的代码不受影响 |
| 8 | **列级注明会被索引级扩展属性「撞号」** | `sys.extended_properties` 按 class 混装（`kucun` 就有过：索引 `index_id=34` 撞上 `备用1` 的 `column_id=34`，注明静默丢失）⇒ 查注明**必须按 `class=1` 过滤** |
| 9 | **成本必须物化、分区不含批号** | 见 §2 |
| 10 | **视图定义里的 `-- 注释` 会进 `sys.sql_modules.definition`** | 用 `LIKE` 做自检时**必须先剥行注释**，否则注释里的字面量会造成假 FAIL |
| 11 | **报表必须 `OPTION (RECOMPILE)`** | 见 §2 |
| 12 | **期初只在 `inh`（`src=0`）**，`kucun` 的余量是它的对侧 | 两者由启动自检核对；**期初日期 1900-01-01 是哨兵值**，别当业务日期读 |
| 13 | **演示数据生成器曾被迁移链重跑，摧毁基础档案** | `migrate-rebuild-inventory.sql` 开头自述：该脚本先硬 `DELETE` 再随机生成，登记进迁移链后每次内容变化重跑都会清掉 `bs_inv`/`kucun`/`bs_inv_price`；现已中性化为只打印跳过 |
| 14 | **遗留 `inh`/`outh` 的重建与老数据** | 2026-09-30 清空重建（老结构是纺织表）；老数据在 `tools/archive/_stock-flow-backup-20260930.csv`（inh 145 行 / outh 30 行）；面板 `RKD`/`CKD` 与 36 个纺织遗留视图**仍在库里且已失效**（引用旧列名），属**待清理项** |

## 8. 刷新本清单

```powershell
# 表/视图清单与中文注明(注意 class=1 过滤 —— 坑 8)
sqlcmd -S localhost -d HSDZ_MES -U yinjia -P <pwd> -W -s "|" -h -1 -f 65001 -Q "SET NOCOUNT ON; SELECT t.name+' | '+ISNULL(CAST(ep.value AS nvarchar(200)),'') FROM sys.tables t LEFT JOIN sys.extended_properties ep ON ep.major_id=t.object_id AND ep.minor_id=0 AND ep.class=1 AND ep.name='MS_Description' WHERE t.name IN ('inh','outh','kucun') OR t.name LIKE '%stock%' ORDER BY t.name;"
# 视图定义(含中文列名 ⇒ 必须走 JDBC;sqlcmd 的 -W 与 -y/-h 互斥,取全文本会直接报错)
#   java -cp tools\lib\mssql-jdbc.jar tools\archive\_dump-stock-view-defs.java
```
