## 二、缺口基线(为什么要同步)

摘自 [MES与金蝶出入库对照.md](MES与金蝶出入库对照.md)(2026-11-13 取证,D1/D6):

| 单据 | 金蝶(已审核) | MES 存量 | 覆盖率 | 现状 |
|---|---|---|---|---|
| 销售出库单 | **5,475**(本次实测 5,487 全量) | 455 | 8.3% | 2026-10-14 之后 MES 侧几乎空转(11 月 0 张) |

⇒ MES 的销售出库单从来不是"全量台账"(它只是 **MES 自己发起并转ERP 的那部分**),
而金蝶里真正在开单。**没有同步就没有数据可打** —— 这是本次两件事必须一起做的原因。

## 三、方案(三个已定的选择)

| 选择 | 结论 | 理由 |
|---|---|---|
| 数据落位 | **写进现役面板表**(`bd_sale_out` / `bl_sale_out`),不另建镜像表 | 用户口径;面板里能直接看到、直接打印;代价(进流水口径)已在 §六 记录 |
| 同步范围 | **整单增量**(最新 + 历史回灌) | 金蝶 5,475 张;给一次性回灌命令(§五.2) |
| 打印入口 | 销售出库单面板「打印」下拉 + 一颗「出货单」 | 与「预览/导出/生成出厂检验报告」并列,一张单一份 |

## 四、同步实现(`deploy/sync-core.mjs` 的 `SALE_OUT` 条目)

### 4.1 接口与锚点

| 项 | 值 |
|---|---|
| 列表 | `GET /jdy/v2/scm/sal_out_bound`(`bill_status=C` + `modify_start_time/end_time` 窗口) |
| 详情 | `GET /jdy/v2/scm/sal_out_bound_detail?id=<id>` |
| 头表 / 行表 | `bd_sale_out` / `bl_sale_out` |
| 同步锚点 | 头表 **`外部数据ID`(金蝶 id)+ `外部指纹`** —— 本次新增,见 `tools/migrate-saleout-sync-cols-20261128.sql` |
| 行键 | 金蝶分录 `seq` → `bl_sale_out.行号`(`upsertLines` 按「单据编号 + 行号」UPDATE,**保住行 identity id**) |

### 4.2 指纹与"每天重取一次明细"

金蝶**列表**只回 18 个表头键(实测:`id/bill_no/bill_date/bill_status/settle_status/delivery_status/
customer_name/number/total_amount/material_qty/material_group/ivc_status…`),**没有明细、没有修改时间**。
金蝶侧改批号/改数量**不改变列表级指纹** ⇒ 沿用订单那套「**明细每日复核日戳**」
(`orderDailyStampOnly`):增量模式下,窗口内每张单每天至少重取一次详情,最坏延迟 1 天。
要立刻补某一张:`node sync.mjs --types=SALE_OUT --refresh-bill=<单号>`。

### 4.3 字段映射(只列"业务列";其余走 `kingdee-extra-fields.mjs` 的自动并集)

**表头**(`mapHead`):

| MES 列(数据键) | 金蝶键 | 备注 |
|---|---|---|
| 单据编号 | `bill_no` | ⚠ **必须是第一个键**:`upsertDoc` 用 `@p0` 收编「外部数据ID 为空 + 同编号」的 MES 老单 |
| 单据日期 | `bill_date` | |
| 客户 / 客户编码 | `customer_name` / `customer_number` | |
| 结算客户 | `settle_customer_name` | |
| 经手人 / 部门 | `emp_name` / `dept_name` | |
| 单据状态 | `bill_status` | `C` → 已审核,否则草稿 |
| 审核人 / 审核时间 | `auditor_name` / `audit_time` | |
| 出库类别 | `trans_type` | `2` → 普通销售(实测真实账套一律 2,与 MES 转ERP 推送口径一致);其它值**留空**不猜 |
| 是否已转ERP / ERP单号 | 常量 `是` / `bill_no` | **关键**:不打这个标,现场点「转ERP」会再造一张金蝶单(见 §六.2) |

**明细**(`mapLines`):`存货编码/存货名称/规格型号/计量单位/数量/批号(金蝶 batch_no)/仓库/售价/含税售价/
销售金额/含税销售金额/税率%/现存量/源单编号(src_bill_no=销售订单号)/源单行号(src_seq)/备注`。
其余列(`税额/成本/折扣族/客户单号/未开票数量…`)由自动并集表补齐。

### 4.4 写库前的"物理列白名单"(本次新增的通用防护)

`kingdee-extra-fields.mjs` 是「接口键 → 面板字段**标签**」生成的,而**标签 ≠ 物理列名**:
实测 `bl_sale_out` 被自动映射了一个**不存在的列「仓库名称」**(真列叫 `仓库名称_sp_name`)。
这类列一旦进 INSERT/UPDATE,整张单写入报「列名无效」⇒ **整类同步 0 行 + 每张单一条报错**,而源码与面板两头看都对。

⇒ `sync-core.mjs` 新增 `tableColumns()`(按表缓存 `sys.columns`)+ `keepKnownCols()`,
写库前过滤,丢弃的列**逐类型告警一次**:

```
⚠ 【销售出库单】自动映射里有 1 个列在表上不存在,已跳过(不影响其余字段):仓库名称 —— 见本文档
```

## 五、怎么跑

### 5.1 日常(计划任务,无需改参数)

`deploy/sync.mjs`(服务器计划任务 `JdySalOrderSync`,每 5 分钟)已经会跑它 —— **前提是服务器
`config.json` 的 `sync.types` 里加了 `SALE_OUT`**(该文件不入库,模板见 `deploy/config.example.json`):

```json
"types": ["SO_ORDER", "PU_ORDER", "SALE_OUT"]
```

⚠ 不加这一项 = 计划任务永远不跑销售出库单,而且**不会报错**(类型过滤是静默的)。

### 5.2 历史回灌(一次性)

```bash
cd deploy
node sync.mjs --types=SALE_OUT --window-days=1200 --yes          # 约 5,475 张,每张 1 次详情调用 ≈ 11 分钟
node sync.mjs --types=SALE_OUT --window-days=1200 --dry-run      # 先看会写多少
```

`--types` / `--window-days` 是本次新增的命令行覆盖(改 `runCore` 的 `types` / `windowDays`),
用途就是"服务器 config.json 还没登记新类型时的一次性补拉",不必先改配置。

### 5.3 上线三步(服务器)

1. `git push` 后 `deploy/winrm/deploy_src.py --ref <已推送 SHA>` 换包(前端+后端都在 jar 里);
2. 迁移:`tools/migrate-saleout-sync-cols-20261128.sql`(已登记 `tools/db-migrations.txt`)。
   🔴 **本机实测 `DbSync sync` 会在更早的 `migrate-qc-proc-insp-batch-table-20261111.sql` 自检失败处中止
   (「出货检验功能记录表(批次矩阵)迁移自检失败」),后续脚本整链不执行** ⇒ 服务器若同样卡住,用
   `tools/DbSync.java run migrate-saleout-sync-cols-20261128.sql` 强制单跑(会记账,幂等);
3. 回灌:`node sync.mjs --types=SALE_OUT --window-days=1200 --yes`,再把 `SALE_OUT` 写进服务器 `config.json`。

## 六、已知边界与风险(必须知道)

1. **不动库存**。本同步直接写单据表、**不经过审核动作** ⇒ `kucun` 一列都不碰,库存数量真源仍是金蝶现存量覆盖。
2. **挡住二次转ERP**。同步写入 `是否已转ERP='是' + ERP单号=单据编号` —— 这些单据本来就在金蝶里,
   不标记的话 `KingdeePushService` 开头的「是否已转ERP」守卫(行 276)拦不住,现场点一次转ERP = 金蝶多一张出库单。
   `转ERP操作人/转ERP时间` **不映射**(保留 MES 当年推送时的事实;为空的表示"金蝶侧建单/同步而来")。
3. **收编老单**(2026-10-14 前 MES 自己开的 455 张):单号与金蝶同一套(`XSCK-…`),`upsertDoc` 按
   「外部数据ID 为空 + 同编号」UPDATE 收编 —— 实测 `XSCK-20261014-00001/00002` 收编后
   `转ERP操作人/转ERP时间` 原值保留,明细行 id 不变(`167-169`)。
4. **流水口径会变大**。`v_stock_flow` / `v_stock_balance`(库存状况表、首页现存量TOP、流程看板)是**流水口径**,
   它直接读 `bl_sale_out` ⇒ 导入历史出库单后这批数字会变(与"金蝶为准"的 `kucun` 不同源)。对账时别混用。
   要区分"谁发起的":`外部数据ID` 非空 = 经本同步写入/收编;`转ERP操作人` 非空 = 当年由 MES 推送。
5. **金蝶批号基本是占位值**。「无批次管理」的商品金蝶一律写 `PC0000`(真实账套 61.7% 商品 `is_batch=true`,
   但有值的批号极少)⇒ 同步进来的行大量是 `PC0000`/空。**出货单备注列过滤 `PC0000`**(见 §七.3),
   所以这些单的备注是空的 —— 这是事实,不是漏印。
6. **`仓库名称` 列被跳过**(见 §4.4),不影响其余字段;要真想落这列，得先建列再重跑同步。

## 七、出货单打印(`frontend/src/business/shipNote.js`)

### 7.1 入口与取数

- 入口:销售出库单面板 →「打印」下拉 → **出货单**(后端 `PanelConfigService` 在 `SALE_OUT` 的打印组追加该动作,
  与「生成出厂检验报告」同一处;动作名=中文数据键,ADR-0001 永不翻译)。
- 前端:`PanelxList.vue` 的动作分发里新增 `action === '出货单'` 分支 ⇒ `engine.getFormDescriptor()`
  取**已保存的最新**头+明细(与本文件其它「打印XX」先例同源),交给 `printShipNote(doc, lines)`。
- 出纸:全系统唯一通道 `printInPage`(`frontend/src/core/panel/printChannel.js`),**不开子窗口**。
- 明细需要用到隐藏列 `源单编号`(= 销售订单号):描述符按 `yj_field.label` 返回**全部**登记字段(含隐藏),
  所以取得到(前端表格不显示它,但数据在)。

### 7.2 合并口径(用户口径的核心)

| 列 | 取数 |
|---|---|
| 序号 | 合并后的行序 |
| 订单编号 | 行级 **`源单编号`**(金蝶 `src_bill_no` = 销售订单号);行上没有才退回表头 `销售订单号`;一行里多张订单 → 逗号拼接 |
| 产品编码 | `存货编码` |
| 产品种类 | `存货名称` |
| 产品整体规格 | `规格型号`(如 `L: 275±0.5mm`) |
| 数量 | **同一物料求和**(`sumKeepScale`,保留原始小数位) |
| 单位 | `计量单位` |
| 备注 | 该物料**全部批号**:去重、去占位(`PC0000`)、保持出现顺序、逗号分隔 |

**合并键 = `存货编码 + 计量单位`**:
只用存货编码不够(同一物料偶尔两种单位并存,数量直接相加会算错);编码为空的行(占位空行)跳过;
只有名称没有编码的行仍出一行(按名称当键)。

### 7.3 版面

A4 纵向、`@page margin:12mm 10mm`;公司抬头 + `出货单`(字距 14px)+ 客户编码/客户名称/出货日期 +
8 列固定宽表(`6/15/12/23/15/8/6/15 %`)+ 合计行(跨前 5 列,数量右对齐)+ 说明条款 +
签字行 + 五联说明。**明细有几行印几行,不铺空行**(用户纸样只有 2 行,空行会让合计离明细太远、像漏填)。

版式常量集中在文件头:`SHIP_NOTE_HEAD`(抬头/电话/传真)、`SHIP_NOTE_NOTE`(说明条款)、
`SHIP_NOTE_COPIES`(五联)、`PLACEHOLDER_BATCHES`(占位批号)、`SHIP_NOTE_SIGNERS`(签字行,含手签横线长度 `w`)。
⚠ 签字行的人名(**仓管 蒋小刚 / 财务 叶健乐 / 品质 冯敏**)是用户纸样上预印的,换人只改 `SHIP_NOTE_SIGNERS` 一处。

**页脚手签横线(v1.1 修 / v1.2 补)**:`物流：____` / `客户：____` 原来写成
`display:inline-block; width:70px; height:1px; vertical-align:middle` —— 实测(Edge 打印预览,4 倍放大)
**线浮在文字中间、不像下划线**,而且「客户」那格留白太大。改法:
`height:1em + vertical-align:baseline`(线正好压在文字基线上)+ 长度按格给(数据在 `SHIP_NOTE_SIGNERS[].w`);
同时页脚三段(说明/签字行/五联)各留 8~12px 间距,不再挤成一坨。

**五格都有线(v1.2,2026-11-28 用户二次口径「这3个也有横线」)**:原来只有 物流/客户 有手签线,
仓管/财务/品质 只印预印人名。现在**五格统一** = `标签：` + (可选)粗体人名 + 手签横线
(`物流 92 / 仓管·财务·品质 76 / 客户 120`),人名在线左边、横线给本人手签。
⚠ 改这段别再动回 `height:1px`——那条线会跑到字中间(用户 2026-11-28 正是按这个报的「这个横线有问题」)。

## 九、回滚

```sql
-- ① 把同步进来的单据整批撤掉(只删「有外部数据ID」且不是 MES 转ERP 的单;删前先备份)
--    ⚠ 先确认这几张不是 MES 自己开的单:转ERP操作人 IS NULL
DELETE l FROM bl_sale_out l JOIN bd_sale_out h ON h.单据编号 = l.单据编号
  WHERE h.外部数据ID IN (SELECT 外部数据ID FROM bd_sale_out
                          WHERE 外部数据ID IS NOT NULL AND ISNULL(转ERP操作人,'') = '' AND 单据日期 >= '2026-10-15');
DELETE s FROM yj_doc_status s WHERE s.panel_code = N'SALE_OUT' AND s.doc_no IN (SELECT 单据编号 FROM bd_sale_out WHERE 外部数据ID IS NOT NULL AND ISNULL(转ERP操作人,'') = '' AND 单据日期 >= '2026-10-15');
DELETE h FROM bd_sale_out h WHERE h.外部数据ID IS NOT NULL AND ISNULL(转ERP操作人,'') = '' AND 单据日期 >= '2026-10-15';

-- ② 停同步:服务器 config.json 的 sync.types 里去掉 SALE_OUT(不必回滚表结构;
--    外部数据ID/外部指纹 两列留着不写就是 NULL,对面板无影响)
```
