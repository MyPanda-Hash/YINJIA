# 审批与「本人自审」权限

> 状态：现役（2026-10-28 起）。涉及：`ButtonService`（审批闸门）、`PanelPermissionService` /
> `SysAdminController`（权限词表）、`AuthController`（下发前端）、`yj_form_approval`（自审留痕）。

## 1. 原来的规矩（2026-09-12 起，默认保留）

**编制与审批分离**：提交人不能审批自己提交的单。两处拦截（管理员豁免）：

| 动作 | 位置 | 拦截话术 |
|---|---|---|
| 直接「审核」 | `ButtonService.audit()` | 审核人不能与制单人相同（编制与审批分离） |
| 「审批通过」一级节点 | `ButtonService.approveApproval()` | 审批人不能与提交人相同（编制与审批分离）：本单由 X 提交，请由他人完成一级审批 |

另外：**直审仅管理员**（2026-09-22）；二级审批人也不能选提交人本人。

## 2. 2026-10-28 新增：「本人自审」

用户口径：

> 「本人可以提出审核后自己审核确认，增加一个这个权限设置，保留原来的本人提交审核后不能本人自己审核的逻辑。」

### 2.1 权限词

- 词：`selfaudit`，中文标签 **本人自审**
- 位置：组织架构 →「角色与面板权限」→ 每个面板的独立一列（与「审批」并列）
- 存储：`yj_role_panel.perms` 的 csv（如 `view,query,add,audit,selfaudit`），**无需改表**
- 管理员：恒有（`selfAuditPanels = ["*"]`，与 `approvePanels` 同口径）

### 2.2 判定（一句话）

> **有该面板审批权 + （勾了「本人自审」 **或** 该面板除你之外没有别的启用审批人） + 单子是自己提交的
> ⇒ 允许一级审批通过，并记为「自审」。**

两条来源（`ButtonService.canSelfAudit`，任一成立即可）：

| 来源 | 条件 | 说明 |
|---|---|---|
| 显式授权 | 角色在该面板勾了 `selfaudit` | 适用于「有两个以上审批人，但业务上就允许自审」 |
| **单人审批兜底** | 该面板**除我之外没有其他启用（未停用/未作废）的非管理员审批人** | 2026-10-28 用户口径「我既然拥有审批权限我就应该能审批，而不是提交了还要其他账户给我批」。这与既有「管理员豁免」是同一个理由：只有一个审批人时，不放开就是死路 |

- 兜底**不含两级面板**（`RD_PROD_INFO` + 8 张质量单据）：它们本来就有确定的第二级，不存在死路；
- 「本人自审」**不等于**审批权：`requireApprover()` 仍在自审判定之前；
- 只管**一级审批通过**；二级审批人仍不能是提交人；
- 直审仍仅管理员；
- **默认没有该词、且面板还有别的审批人 = 原逻辑一字不动**（拒绝）。

### 2.2.1 为什么要有兜底（2026-10-28 实测）

正式库 68 张单据面板里，**非管理员审批人「只有 1 个」的有 14 张**（生产日报表、投料确认单、
物料混合记录、造粒记录、无黑处理登记、封箱确认、工序报工单、设备点检、保养计划、委外加工单…），
「0 个」的 10 张，≥2 个的 44 张。也就是说：**日常那些生产记录单据，审批人就只有一个人**——
他自己提交就必然卡住，只能找管理员。兜底正是为这批面板而设。

### 2.3 留痕

审批通过写入 `yj_form_approval.self_audit = 'Y'`（迁移
`tools/migrate-form-approval-self-audit-20261028.sql`，两账套已执行，带中文注明）。

前端「审批情况」在该条动作后加一个橙色 `自审` 标签 —— 编制人 = 审批人的单据必须一眼可辨，
不能和正常他人审批长得一样。审批通过按钮旁也会提前提示「本单由你提交；本面板已授『本人自审』，
通过后会记为自审」。

### 2.4 前端数据流

`AuthController` 登录/`/api/auth/perms` 下发 `user.selfAuditPanels`（管理员 `["*"]`）→
`stores/user.js` → `PanelxList.vue`：

- `canSelfAuditHere()` 判本面板是否授了自审；
- 授了 ⇒ `iAmCurSubmitter` 不再成立（「审批通过」不再对提交人置灰）；
- `selfAuditNow` 用于按钮旁提示。

展示层只是便利，**最终裁决在服务端**（`ButtonService.canSelfAudit`，同词同口径）。

## 3. 怎么给某个人开

> 先看一条：**如果这个面板只有他一个审批人，不勾也已经能自审**（单人审批兜底）。
> 兜底不生效 = 面板上还有别的审批人，这时才需要显式授权。

1. 组织架构 → 角色 → 选该人的角色 → 面板权限；
2. 找到对应面板，勾上 **本人自审**（同时确认「审批」列也勾着，否则没有审批按钮）；
3. 保存 → 该人重新登录（或顶栏刷新权限）后生效；
4. 只给一个人开：新建一个角色只放这个人，避免整组人都获得自审权。

## 4. 边界与注意

- **不要**给财务/库存过账类单据随手开自审：编制与审批分离是内控，自审等于单点完成"编 + 审"；
- 二级审批（`RD_PROD_INFO` 立项 / `QC_TC_IN` 特采）**没有**放开自审：一级自审通过后仍要另一个人做二级；
- 弃审、驳回不受该权限影响（谁提的谁撤，按原规则）；
- 审计口径：查「谁自审过」=

  ```sql
  SELECT * FROM yj_form_approval WHERE self_audit = 'Y' ORDER BY create_time DESC;
  ```
