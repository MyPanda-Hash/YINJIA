# 品质流程监控（QC_FLOW）—— 实现与验证

> 2026-11-12 立；同日第二轮扩到**不合格分支 + 已转ERP 隐藏**。
> 一句话：**一条来料批次（送料暂收单的一行物料）在「送料 → 检验 →（不合格）退回 →（让步）特采 → 入库」
> 这几张单上走到哪一步**，点节点跳对应单据；**没有该面板查看权限时不可跳转**；**末尾单据已转 ERP 的默认隐藏、勾一下就能显示回来并照常点开**。
> 本页只读，不改任何业务数据。

## 一、用户口径（原文）

第一轮（2026-11-12）：

> 「流程监控：从送料->检验单->入库。为品质做一个流程监控的面版，可以知道每个单据的状态，和跳转，
> 如果没有对应面版的权限就无法跳转过去。这种看板类似，而且参考检验目录，主要要显示物料批号和物料编码。」

第二轮（同日，补不合格线 + 隐藏规则）：

> 「还有检验单到退货，或者退货到特采到采购入库的呢。入库单转erp后就隐藏了。已经入库后就隐藏。
> 隐藏后的单据是可以重新打开的」

复述确认（三问已答）：**只隐藏「已转ERP」的**（已审核但没转 ERP 的仍显示）；不合格分支**在一行内分叉**
且退回/特采节点照样带状态可跳；「重新打开」= **开关把隐藏行显示回来 + 点节点打开那张单**。

拆成六条硬要求：

| # | 要求 | 落地 |
|---|---|---|
| ① | 从送料 → 检验单 → 入库，一条链看完 | 一行 = 送料暂收单的一条物料行，右侧主链三节点 |
| ② | 知道**每个单据**的状态 | 每个节点自带状态徽标（已审核/草稿/审批中/已作废/未生成） |
| ③ | 能跳转到该单据 | 点节点 → `/panelx/list/<面板>?docNo=<单号>` 定位那张单 |
| ④ | 没有面板权限就**不能**跳 | 前端 `canViewPanel` 判定，无权限只提示不发路由；节点右上角带锁标记 |
| ⑤ | 参考检验目录，突出**物料批号 + 物料编码** | 第一列就是「物料批号 / 物料编码」（批号醒目、编码显式带标签） |
| ⑥ | 不合格线：检验 → 退货 →（特采）→ 入库 | 主链下方第二条泳道「不合格：暂收退回单 → 特采单」，同样带状态与跳转 |
| ⑦ | 已转 ERP 后隐藏，但可重新打开 | 默认过滤 `已隐藏=1`；勾「显示已隐藏 (N)」原样显示回来，节点照常可点 |

## 三、页面与权限

- **入口**：品质管理 → 来料品质 → **品质流程监控**（排在「来料检验单」之前），地址 `/qc/flowMonitor`。
- **面板码**：`QC_FLOW`（**页面级虚拟面板**，不往 `yj_panel` 插行 —— 插了会污染选单/字段配置等
  `registry.all()` 下游，沿用 `WORK_ORDER_PROGRESS` / `PROJECT_FLOW` 先例）。
- **动作集**：只有 `view`（可见）+ `query`（查询）—— 本页不写任何业务数据。
- **授权**：`tools/migrate-qc-flow-monitor-20261112.sql` 按「已授 `QC_INSP` 或 `QC_RECV` 可见」的角色
  等价补授 `view,query`（∪ 管理员）。不补授会让老账号上线后菜单消失/接口 403 而管理员不知道怎么勾。
- **三道闸门**（缺一不可）：
  1. 菜单/路由：菜单项带 `panelCode`，路由 `meta.panelCode` 由 `router.beforeEach` 拦手输地址；
  2. **看板跳转**：点节点时 `jumpTarget()` 再判一次目标面板（无权限只提示）；
  3. 目标面板自己的后端 `requirePanelView`（跳过去也读不到数据）。

## 四、一行是什么（粒度）

**一行 = 送料暂收单（`sl_recv_detail`）的一条物料行 = 一个来料批次**，与「待检验目录」（`qc_catalog_detail`）
同粒度 —— 这正是用户要的「物料批号 + 物料编码」那一层。同一张暂收单多行物料就是多行，
不会把不同物料/批次串到一行（`OUTER APPLY … TOP 1` 逐级取，绝不做笛卡尔膨胀）。

## 五、数据口径

### 5.1 单据状态：真源是 `yj_doc_status`，不是单头列

五张单（送料/检验/退回/特采/入库）的「状态」按 `ButtonService.docStatusOf` 的同一优先级折叠成 5 档：
**已作废 > 已中止 > 审批中 > 已审核 > 草稿**。

`yj_doc_status` 没有行时（旧系统导入 / 金蝶同步进来的单）按以下顺序兜底：

1. **审核时间**有值 → 已审核；
2. 单头「单据状态」列有值 → 用它；
3. 都没有 → 草稿。

> ⚠ 顺序不能反：正式库 320 张送料暂收单的单头「单据状态」**全部停在「草稿」**，
> 其中 290 张审核时间有值 —— 先读那一列会把已审核的批次全显示成草稿（本次开发实测）。

该环节**还没有单据**时状态给 `NULL`（不是「草稿」），前端据此显示「未生成」/「免检」。

### 5.2 链路怎么连（三级，全部标出来源）

| 级 | 关联 | 说明 |
|---|---|---|
| 送料 → 检验 | `qc_insp.暂收单号 = sl_recv.单据编号` **且** 检验行 `物料编码` 相同 | 同批次优先，再取最新一张 |
| 检验 → 退回 | `qc_return.检验单号 = 检验单号`；取不到再按「批次号 + 退回行物料编码」兜 | 现网 38 张退回单大多没填检验单号，只能这样兜 |
| 检验 → 特采 | `qc_tc_in.检验单号 = 检验单号`；取不到再按「批次号 + 产品名称=物料名称」兜 | 现网 25 张特采单，一部分有检验单号 |
| 检验/送料 → 入库 ① | 检验行 `qc_insp_detail.入库单号` | 最硬：检验单上直接记了入库单号（`匹配方式=检验单行`） |
| … → 入库 ② | `bd_purchase_in.来源单号` ∈ {检验单号, 暂收单号, **退回单号**, **特采单号**} | MES 内生成的入库单都带来源（`匹配方式=来源单号`） |
| … → 入库 ③ | 入库行 `批次号/批号` = 送料行 `批次号` 且 `存货编码` 相同 | **推定**（`匹配方式=批号推定`），界面上要在 title 里标出来 |

> 退回/特采与批次的关联在现网数据里主要靠「批次号 + 物料」兜底（多数退回/特采单没填检验单号），
> 一张批次级退回单可能同时挂到同批次的多个送料行上 —— 这是**数据现状**，不是看板算错；
> 它们各自带状态（作废的显示红色「已作废」），但**不计入「异常」计数**（见 5.4）。

### 5.3 需检验 / 免检（决定「当前环节」跳不跳检验）

真源 `bs_inv.来料检验 = '是'`（正式库 13 个物料需检验，其余 3967 个免检）。

- 需检验：送料审核后必须有一张**已审核**的检验单，否则环节 = `检验`；
- 免检：送料审核后直接进 `入库`（界面上检验节点显示灰色「免检」，而不是「未生成」）。

> 不按这条跳，整块看板会把 400+ 条免检批次全标成「卡在检验」—— 那是假卡点。

### 5.4 当前环节、异常与停留天数

```
送料未审核                                          → 送料
需检验 且（无检验单 或 检验单未审核）                    → 检验
有特采单 且 特采状态 ∈ {草稿, 审批中}                   → 特采
无特采单 且 有退回单 且 退回状态 ∈ {草稿, 审批中}         → 退货
检验不合格 且 无退回/特采单 且 无入库单                  → 退货（待开退回单）
有入库单 且 入库未审核                                → 入库
无入库单 且 退回单已审核（纯退回供应商）                  → 完成
无入库单                                            → 入库
否则                                               → 完成
```

- **已作废/已中止的退回/特采单不参与环节判定**（作废 = 这条路走不通，批次回主链继续）——
  否则一张作废退回单会把一批批次永远钉在「待退货」（实测 25 行 → 修正后 1 行）。
- **异常** 只看主链三单（送料/检验/入库）的作废·中止 + 检验全不合格；退回/特采**不计入**异常
  —— 它们与批次按批次号兜底匹配，计进来会把异常数虚高（实测 11 → 35）。
- 异常单不参与「未完成」计数（未完成 = 还在走且没异常），单列一档，卡在哪仍看得见。

检验结论分三档（避免误报）：`合格数量 > 0 且 不合格数量 > 0` = **部分不合格**（橙，要人看）；
`合格数量 = 0 且 不合格数量 > 0` = **不合格**（红，同时计入异常）；只有合格 = **合格**（绿）；
两者都没填 = 空（不猜）。

停留天数 = 从**当前环节那张单的日期**算到今天（缺单则逐级退回上一张单）；已完成给 0。
超过 7 天在界面上标红。

### 5.5 隐藏（已转 ERP）与重新打开

用户口径：「入库单转erp后就隐藏了……隐藏后的单据是可以重新打开的」，并确认**只隐藏「已转ERP」**
（已审核但没转 ERP 的仍显示）。

| 项 | 口径 |
|---|---|
| 判定 | **末尾单据已转 ERP**：有入库单 → 看 `bd_purchase_in.是否已转ERP`；没有入库单（纯退回）→ 看 `qc_return.是否已转ERP` |
| 默认 | 不返回这些行（`AND 已隐藏 = 0`），但单独数一个 `汇总.已隐藏`，界面显示「显示已隐藏 (N)」 |
| 重新打开 | 勾上开关 → 按 `含已隐藏=true` 原样返回（含 `已隐藏=1` 标记，界面打「已转ERP」小标），**节点照常可点、可跳到那张单据** |
| 不是删除 | 隐藏纯粹是查询过滤，**不动任何单据、不写库**；取消勾选即恢复 |

> 现网正式库：375 张采购入库单里 318 张已转 ERP ⇒ 默认视图少 36 行（都是已完成的批次）；
> 另外 9 行「已入库但没转 ERP」照常显示 —— 正好拿来盯「还差转 ERP」。

### 5.6 汇总条

`批次行数 / 未完成 / 已完成 / 需检验 / 待检验 / 待退货 / 待特采 / 待入库 / 异常 / 已隐藏`，
只统计**本次返回的行**（与界面所见一致，不做另一套"全库口径"）；`已隐藏` 由后端单独数。

## 八、已知限制（写清楚，免得被当成 bug）

1. **金蝶导入的采购入库单对不上送料批次**（无来源单号 + 批次号编码规则不同）⇒ 入库节点可能显示「未生成」；
   界面上「批号推定」命中会标出来，未命中不猜。
2. 送料 → 检验按 `暂收单号 + 物料编码` 关联：检验单若没填暂收单号（例如直接从检验单面板手工建），不会串到本行。
3. **退回/特采单多数没填检验单号**（现网退回单 38 张、特采单 25 张，多数还是草稿且无检验单号）⇒ 只能按
   「批次号 + 物料」兜底关联，一张批次级退回单可能同时挂到同批次的多个送料行上（故它们不计入「异常」）。
4. 退回/特采的**数量是整张单的合计**（按物料行汇总），不是本行的分摊量。
5. 停留天数按**单据日期**算，不按状态变更时间（`yj_doc_status.update_at` 跨单据口径不一致，且含审批/弃审抖动）。
6. 汇总只统计本次返回的行；界面一次取 800 行（正式库整条链约 502 行，全量铺开不截断）。
7. 隐藏只认「末尾单据已转 ERP」这一个信号；**已审核未转 ERP 的照常显示**（这是用户明确要的口径）。
