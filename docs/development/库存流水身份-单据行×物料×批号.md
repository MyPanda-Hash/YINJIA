# 库存流水的「身份」:单据行 × 物料 × 批号

> **日期**:2026-10-20(起因 2026-10-20 用户报障)
> **改动**:`tools/migrate-stock-flow-src-rid-grain-20261020.sql`(两账套已执行)+ `StockFlowService.post`
> **一句话**:流水行的身份由 `(src, rid)` 放细到 `(src, rid, 物料编码, 批号)`;
> 一个工单可以领多种物料,同一单据行同一物料重复审核仍然只记一次。

---

## 1. 现场

用户(2026-10-20,原话):

> 「你们限定了一个工单只能领一次料,换没领过料的工单就可以了,应该是把你们设定的哪个唯一性拿掉,就彻底解决了」
> 「我们有个扫码领料的小程序,扫码领料有出现限制,一个工单是可以扫多个物料的,一个工单因为有多个物料组合」

现场报错:

```text
消息 2601,级别 14,状态 1,第 1 行
不能在具有唯一索引"UX_outh_src_rid"的对象"dbo.outh"中插入重复键的行。重复键值为 (6, 1711)。
```

`src=6` 是**材料出库**(生产领料)段号,`rid=1711` 是来源行 id。

## 2. 机理:两套 rid 语义撞在同一个唯一键上

| 写入方 | rid 取什么 | 一个 rid 几行 |
|---|---|---|
| MES(转领料单 → 补材料 → 审核,`StockFlowService`) | `bl_material_out.id`(单据**明细行**) | 1 行(一行一个物料) |
| 扫码领料小程序(直连库写 `outh`) | 工单 / 工单行 id(这次报障的那套) | **N 行**(一个工单 N 种物料) |

MES 自己的写法天然满足「一行一物料」,所以 `(src, rid)` 唯一键从 2026-09-30 建表起一直没暴露问题;
小程序按**工单**写 rid,扫第二件物料时必然撞键 —— 表现出来的就是「一个工单只能领一次料」。

## 3. 改法:放细,不是删掉

唯一索引是「**结存 == Σ流水**」的最后一道保险(`StockFlowService` 头注)。整条删掉,
`post` 的存在性判断哪天出 bug 就是**静默重复扣账**,而且再也查不出来。所以只把粒度放细:

| 位置 | 旧 | 新 |
|---|---|---|
| `outh` 唯一索引 `UX_outh_src_rid` | `(src, rid)` | `(src, rid, 物料编码, 批号) WHERE rid IS NOT NULL` |
| `inh` 唯一索引 `UX_inh_src_rid` | `(src, rid)` | 同上(对称,防下一个同款报障) |
| `inv_cost_ledger` 主键 `PK_inv_cost_ledger` | `(src, rid)` 聚簇 | `(src, rid, 存货编码, 批号)` **非聚簇** |
| `v_stock_ledger` / `v_stock_balance` 的 JOIN | `c.src=m.src AND c.rid=m.rid` | 再补 `存货编码`、`批号` |
| 代码 `StockFlowService.post`(存在性判断 / 弃审 / 复活) | `(src, rid)` | `(src, rid, 物料编码)` |

结果:

| 场景 | 结果 |
|---|---|
| 一个工单领 5 种物料 | 5 行,不撞键 ✅ |
| 同一条单据行重复审核(幂等) | 仍 1 行 ✅ |
| 同一物料同批号重复扫码 | 仍被 2601 拦下 ✅ |
| `rid IS NULL`(期初、月结转) | 过滤索引排除,可任意多行 ✅(2026-09-30 口径不变) |

> **为什么 `inv_cost_ledger` 必须跟着改**:同一 `(src, rid)` 多行时,成本重算的
> `INSERT INTO inv_cost_ledger ... SELECT ... FROM #rec` 直接撞主键。
> 2026-10-20 在测试账套实测:往 `outh` 塞一条 `(src=6, rid=9, 另一物料)` 再点「重算成本」→
> `HTTP 500 违反了 PRIMARY KEY 约束"PK_inv_cost_ledger"…重复键值为 (6, 9)`。改完 → 200。
> ⚠ 键长:存货编码 `nvarchar(400)`(800B)+ 批号 `nvarchar(120)`(240B)+ src/rid(8B)≈ **1048B**,
> 超过聚簇索引键上限 **900B** ⇒ 主键只能做**非聚簇**(上限 1700B),表随之从聚簇表退化为堆
> (全表 ~6500 行,查询走 PK / `IX_inv_cost_ledger_part` 都不受影响)。

> **为什么两个报表视图必须跟着改**:JOIN 只按 `(src, rid)` 时,一条流水匹配到 N 行成本行 ⇒
> **行数翻倍、成本金额被重复计入**。改完实测三处行数一致(正式库 6408 / 6408 / 6408)。

## 4. 踩坑:代码不能按「批号」精确定位(重要)

第一版代码把存在性判断/弃审/复活改成了 `(src, rid, 物料编码, 批号)` 四键精确匹配,
测试账套当场复现事故:

- 2026-10-15 起「无批次物料统一补默认批号 `PC0000`」⇒ 10-14 之前落库的流水 `批号 = NULL`,
  而单据行今天解析出来是 `PC0000`;
- 弃审按 `批号=PC0000` 找不到自己那行 ⇒ **什么都没冲**;重审按同样条件也找不到 ⇒ **再插一行**;
- 结果 `SCLL-20260902-00011` 由 11 行变 **22 行**(两套都 `asp_cancel='N'`)⇒ 同一单据双倍扣账。

**结论**:索引按 4 键放开(给别家写入方留空间);**代码只按 `(src, rid, 物料编码)` 定位**(容得下批号漂移),
复活时把批号**刷新**成单据行当前值。代码里 `ROW_KEY_SQL` 上方的注释写明了这段经过。

> 这个坑反过来也说明:**批号是会变的元数据,不能当幂等键**。物料同理,但物料的变动概率低得多;
> 真出现「单据审核后改物料」,旧行为也是留下两条(一条作废一条有效),`Σ流水` 仍然正确。

## 6. 给小程序侧的口径(写 `outh` / `inh` 时)

1. **`rid` 用「工单行」级别的稳定 id 就好**(这次就是这么用的),不必为了绕唯一键去造号;
2. **必须写 `物料编码`** —— 它是放细后身份的一部分,空物料会让同一物料的两行仍然撞键;
3. `批号` 有就写、没有就写 NULL(或补默认批号),不要写空串以外的占位符;
4. `src` 按段号填(材料出库 = 6),`asp_cancel` 弃审用 `'Y'`(软删,别物理删);
5. ⚠ **同一件物料同批号请只写一行**(重复扫码请改写那一行的数量),否则会被 2601 拦下 ——
   这是故意保留的「防重复扣账」保险。

