## 一、分工口径(先定清楚，别各做一半)

| 谁持有什么 | 具体对象 | 方向 |
|---|---|---|
| **金蝶(主数据)** | ① 仓库档案「启用仓位管理」(`is_allow_freight`) ② 仓位档案(sp，仓库下级) | 金蝶 → MES：每 5 分钟同步进 `bs_wh.启用仓位管理` |
| **MES(单据来源)** | 出入库单据行上的 `仓位编码` | MES → 金蝶：转ERP 时行级推 `sp_id` / `sp_number` |
| **两边都不是** | 库存数量 | 金蝶为准(`kucun` 每轮被金蝶现存量覆盖) |

因此「仓位」是**单据留痕**，不进库存记账键（`kucun`/`inh`/`outh` 的键是
`(物料, 仓库, 批号)`）—— 填了仓位也不会多出"按仓位看库存"的能力。

## 三、本次改动清单

### 代码(3 处)

1. **`deploy/sync-core.mjs`** — `BD_STORE` 指纹补 `is_allow_freight`、`allow_negative`。
   *为什么必须*：指纹里没有开关字段 ⇒ 在金蝶勾了「启用仓位管理」，列表行指纹不变，同步**永远判"无变化跳过"**，
   MES 永远停在 0。
2. **`KingdeePushService`** — 转ERP 行级推仓位：`sp_number` 恒带、`sp_id` 由
   `spIdOf()` 反查（①本行 `仓位id` 列 ②从已同步的金蝶单据 `仓位编码 → 仓位id` 反查 + 进程内缓存）。
   *为什么反查*：保存接口只认 `*_id`（2026-10-04 实测 `stock_number` 被静默忽略），而仓位档案无开放接口。
   取不到 id 时**只带 sp_number 并 warn**，绝不因此阻断转ERP。
3. **`ButtonService.ensureBinRequiredFilled`** — 必填校验同时认「仓位」「仓位编码」两种标签。
   *为什么*：采购/暂收/检验的字段叫「仓位」，材料出库/销售出库/销售退货/生产退料叫「仓位编码」；
   只认一个 ⇒ 那四张单的"逐仓必填"开关**永远不生效**。

### 迁移 `tools/migrate-bin-fields-20261201.sql`(两账套已执行)

| 动作 | 对象 |
|---|---|
| 补 3 列(`仓位编码`/`仓位id`/`仓位名称`) | `bl_finish_in`、`bl_other_in`、`bl_other_out`（类型对齐 `bl_purchase_in`：500/500/200）+ 中文注明 |
| 登记明细「仓位」字段(参照 `WHLOC.仓位编码`，级联 `仓库=$仓库`) | `FINISH_IN`(seq 125)、`OTHER_IN`(110)、`OTHER_OUT`(100) |
| 隐藏 → 可见参照(标签/物理列不动) | `MATERIAL_OUT`、`SALE_OUT`、`SALE_IN`、`MATERIAL_RET` 的「仓位编码」 |
| 不动 | 采购入库 / 送料暂收 / 来料检验 / 暂收退回（**四单基线**，改动另有流程） |

脚本末尾带**三态自检**：缺列/缺面板 ⇒ 提示跳过；列在但字段没登记或没转参照 ⇒ `RAISERROR`；全绿 ⇒ `PRINT`。

## 五、金蝶侧需要做什么(用户/实施顾问)

1. **仓库**：基础资料 → 仓库 → 选目标仓 → 勾「**启用仓位管理**」→ 保存。仓库用过也能开（官方：
   [仓库使用后如何开启仓位?](https://vip.kingdee.com/knowledge/609551736360820224?productLineId=35&isKnowledge=2&lang=zh-CN)）。
2. **仓位**：基础资料 → 仓位 → 在该仓下新增（可批量），编码**必须与 MES 的 `仓位编码` 逐字一致**
   （MES 推的是编码 → 金蝶按编码反查 id；不同仓允许同码，仓内唯一）。
3. **只在这 6 个仓上开**：MES 的 A/C/D/辅料仓在金蝶**不存在**，那 679 个仓位推不上去。
4. **存量库存归位**：该仓现有库存没有仓位，开完要做一次仓位初始化/调整，否则进出与现存量口径打架。
5. 开完通知我跑 `node sync.mjs --refresh=BD_STORE`（或等下一轮），MES 的 `启用仓位管理` 会变 1，
   之后单据才会真正校验/预填/推送仓位。

## 六、已知限制 / 下一步

| 项 | 说明 |
|---|---|
| `QC_RETURN`(暂收退料) 没补仓位列 | 属四单基线，改动要连带重跑基线生成器，本轮不动；金蝶侧该仓若开仓位管理，退料单会缺仓位 |
| 仓位档案无开放接口 | `sp_id` 靠"已同步单据反查"；金蝶侧**至少要有一张带仓位的单据**（人工录一张即可）才能反查出 id，否则只带 `sp_number` |
| 仓位不进库存 | `kucun` 无仓位维度；"某仓位有什么货/上架拣货"是二期 |
| 新代码尚未上到 8090 | 代码改动需 `停 8090 → mvn package → 起`（或走增量部署）；本轮只做了 `compile` 与元数据生效 |
