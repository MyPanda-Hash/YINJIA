## 一、通用口径(三单共用,动字段前必读)

### 1.1 位置(place):决定字段出现在哪、按什么排序

| `place` 取值 | 出现处 | 排序 |
|---|---|---|
| `header` | 单据表单页(表头) | `seq` 升序 |
| `query` | 列表页查询条 **+ 表单页表头(同一字段出现两次)** | `seq` 升序 |
| `query,header` | 表单页表头 + 查询条 | `seq` 升序 |
| `detail` | 明细页签 | `seq` 升序 |
| `query,detail` | 查询条 + 明细列 | `seq` 升序 |

> 🔴 **表单页表头顺序 = `place` 含 `header`,或 `place` 恰为 `query` 的全部字段,合并后按 `seq` 升序。**
> 只按 `header` 算会少一排字段(单号/单据日期/业务类型…全在 `query` 位上);
> 而 `query,detail` 的字段只进查询条与明细,**不进表单页表头**。
> 列表页顶部宽表的明细列顺序 = `place` 含 `detail` 且可见的字段按 `seq` 升序。

### 1.2 排序真源与并列规则

| 优先 | 键 |
|---|---|
| 1 | `yj_field.seq` 升序 |
| 2(并列时) | `yj_field.id` 升序(= 该字段行的登记先后) |

> `seq` 允许并列,并列时后端按 `id` 排。要精确控制顺序,请把 `seq` 写成不重复的值。

### 1.3 四个显示开关

| 列 | 语义 | 后果 |
|---|---|---|
| `visible` | 是否作为**表格列**出现 | `0` ⇒ 表格不显示该列(明细**表单**里仍可录入) |
| `hidden` | 是否隐藏 | `1` ⇒ 表格与表单都不显示(值仍存、仍参与链路映射) |
| `editable` | 是否可编辑 | `0` ⇒ 只读(同步/生单带下来的字段靠它锁死) |
| `required` | 是否必填 | `1` ⇒ 表单校验拦截保存 |

### 1.4 字段 vs 显示字段(ADR-0001:数据键永远中文)

| 概念 | 落在哪 | 说明 |
|---|---|---|
| **字段(数据键)** | `yj_field.label` | 也是前后端 API 的 `dataName`;**永远中文、不随语言变** |
| **物理列** | `yj_field.col_name` | 落库列名,**可与字段名不同** |
| **显示名(译名)** | `yj_translation(scope='field', ref_key=中文标签, locale)` | 切语言后**只换显示名**,字段名与顺序都不变 |

### 1.5 参照字段的显示来源

参照型字段(`dataType=参照`)按 `ref_panel` 的 `ref_field` 匹配,选中后把 `display_field` 回填本字段。

## 六、红线(改字段时不可违反)

1. **数据键永远中文**(ADR-0001):`label` 不随语言变,只改 `yj_translation` 的显示名。
2. **`place` 决定出现处**:把 `header` 字段改成 `detail` 会让它从表单页消失;`query,detail` 不会进表头。
3. **金蝶必填项不能空**:其他入库/其他出库的 **业务类型id**(`trans_type_id`)**保存接口必需**(真实账套 其他入库=12 / 其他出库=13);
   产品入库单的 `qty` 等数值**必须传字符串**(protobuf 校验,否则报 `invalid value for string type`)。
4. **检验方式(全检/抽检)是 MES 本地字段**:金蝶保存接口对检验类键**静默忽略**,不得指望它随转ERP 落金蝶。
5. **改参照源**必须带窄条件 + 行数守卫 + 越界自检(见《采购链四单字段与显示字段》§5.3 事故)。
