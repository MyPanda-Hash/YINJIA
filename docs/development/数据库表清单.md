## 0. 表命名与归属规范（强制）

| 前缀 / 形态 | 含义 | 归属模块 | 建表要求 |
|---|---|---|---|
| `yj_` | 面板引擎元数据与运行时（面板/字段/翻译/状态/权限/日志） | 系统 | 只由引擎读写，业务代码禁止直连 |
| `bs_` | 基础档案（主数据） | 基础设置 | 必须走**单单据结构**（`archive` 模式）；保存必须全量提交 |
| `bd_` / `bl_` | 业务单据 **头表** / **行表**（成对） | 订单/生产/仓库管理 | 必须齐备 `asp_user1/2`+`asp_time1/2` 审计列；删除=软删 |
| `rd_` | 研发管理模块单据 | 研发管理 | `*_head`+`*_detail` 成对；无后缀的旧单表只读保留 |
| `qc_` | 品质管理单据 | 品质管理 | 头行成对 |
| `wo_` | 生产执行（工单/报工/进度） | 生产管理 | 头行成对 |
| `dm_` / `s_` / 拼音缩写 | **经典 HSDZ 遗留**，非 MES 自有结构 | 遗留 | 新功能**禁止**使用；面板仍在用的（见下表「关联面板」）改动前须评估 |
| `RENAME_` / `*_bak_*` / `tmp_*` / `t1` / `t2` | 备份与临时 | **已清零（2026-09-29）** | 禁止引用；体检 10 项棘轮基线已收到 0（再出现即 FAIL） |

### 0.1 在册表登记（「确定下来的后台表」）

**在册台账 = [`tools/db-inuse-tables.txt`](../../tools/db-inuse-tables.txt)**（222 张在册 + 3 张例外保留 = 225 张；2026-09-29 四源审计定册 206+3,其后 bs_wh_loc、9.29 生产批次①②④、材料码两表、qc_insp_req_series 等陆续补登,2026-10-07 补登研发两对表,见维护记录 v3.1）。
判定口径 = 四源并集（① `yj_panel` 绑定且面板在运营 ② 在运营视图依赖 ③ `backend/src/main/java` + `frontend/src` 运行期 SQL 引用 ④ 业务数据行），
逐表证据与探针在 `tools/archive/_table-audit/`（objects/panels/deps/refs/granted/classify/drop-risk）。

- **不在册 = 脏数据**：新表必须先在 `db-inuse-tables.txt` 登记，再进 `db-migrations.txt`，并写 `MS_Description`。
- 2026-09-29 已按该口径物理删除 **244 张未用表**（`pr_*` 已下架面板表、无引用遗留表、空表、备份/临时表），
  并回收 29 个已下架面板的 `yj_panel`/`yj_field`/`yj_role_panel` 行与仅它们使用的译名词条；
  迁移脚本 `tools/migrate-drop-unused-tables.sql`，执行前有全库备份（`deploy/HSDZ_MES_pre_drop_*.bak`）。
- 在用业务表 **全部备有 `备用1..备用20`（nvarchar(500)）**语义化冗余列池，承载「字段管理」动态字段（零 DDL）；
  补齐脚本 `tools/migrate-spare-columns-biz.sql`，设计见 [动态字段扩展-备用列池](../design/动态字段扩展-备用列池-V1.0.md)。

**通用硬约束**（表清单之外的「列级」规范见 [代码规范与防臃肿](代码规范与防臃肿.md) §C3 与 [开发与质量](开发与质量.md) §3「列名安全规范」）：

- 列名**禁止含 `.`**；含 `%`/空格等特殊字符的列，SQL 中必须写 `t.[列名]`。
- 一切写入经 `asp_user1/2` + `asp_time1/2` 留痕；删除=软删（`canceled` 状态）。
- 库变更**禁止手工改库**：一律写幂等迁移脚本进 `tools/db-migrations.txt`（§代码规范 E2）。
- 表的中文说明写进 `MS_Description` 扩展属性——本文档的中文名就是从这里读的。
