## 2. 关键口径(实测踩坑后才定下来的,后续维护别再猜)

### 2.1 「批次号」的真相(2026-10-29 实测)

- `plang.lot_no` **全库 470 行全 NULL** —— 它不是生产批次号,别拿它当批次;
- 真实生产批次号在 `plang.[批次号]`(433 行有值,2026-10-19 之前的老单)/`plang_pc.[批次号]`/`scjl.[批次号]`;
- 该号由 `ProcessTaskService.assignProductionBatch` 在该工单行**首次「生产完工」**(全部工序报工完工)时写入 = **完工当天日期**;
- ⇒ **录入照片阶段多数工单行还没有批次号**,卡头先按工单日期推定(`批次来源='工单日期'`),服务端在读到真实批次号后自动同步(`批次来源='生产批次'`)。卡号/小批次号不含批次号,同步不影响身份。

解析优先级(服务端 SQL):
`plang.[批次号]` → `plang_pc.[批次号]` → `scjl.[批次号]` → `CONVERT(varchar(8), plang.pl_date, 112)`。

### 2.2 工序行与完成量

- 工序行**只读**工序台账 `wo_process_line`(按工艺路线生成,口径=订单结转所选路线 → 产品档案 → `GY-CB-STD`);
  台账缺行时调既有 `ProcessTaskService.ensureLedgerForWorkOrder` 补齐后再读,**不重算路线、不写台账**;
- 完成量口径与 `WorkReportController` 的工序台账段**逐条一致**:
  行锚 = `scjl.gd_id → plang_pc.plang_id`,草稿期 `gd_id=0` 时按 `批次号` 兜底;`wgzt='Y'`=已报工,其余=待审核;
- `wo_proc_card_detail` **不存完成量/状态/完成时间**(只存工艺快照:工序序/工序/计划数量/计划生产线/实际生产线/车间/备注),避免与报工两账不合一。

### 2.3 卡状态

`录入中`(默认)→ `已完成`(人工「确认完成」;前置=**全部工序已完工** 且 **每道工序至少 1 张照片**,服务端强校验)。
回退 `录入中` 清空确认人/时间。无审核/弃审流(卡是记录表,不是单据)。

### 2.4 照片

- 复用 `yj_attachment`:`panel_code='PROC_FLOW_CARD'`,`doc_no=卡号`,`field_key='工序照片-<工序序>'`;
- 上传/删除/下载走既有 `/api/attachment/{upload,delete,{id}/download}`(不新造文件服务);
- ⚠ 同批给 `AttachmentService.syncHeadField` 加了容错:面板不在 `yj_panel`(页面级虚拟面板)时直接返回,
  原先 `queryForMap` 查不到面板会抛异常 ⇒ 上传 500。既有面板行为一字不动。

## 6. 附带修复:工单追溯 / 成型报工审核指向已下架表(既有生产故障,2026-10-29 实测复现并修)

- **现象**:`POST /api/px/scheduleBoard/trace` 对**任何工单**返回 500「对象名 'dbo.qc_mold_insp_head' 无效」⇒
  生产工单 / 工单排产页的「工单详情 · 追溯」全挂;`QcInspAutoService` 成型报工审核钩子同样指向该表 ⇒
  成型报工审核整笔回滚(现场表现为「报工提交不了」)。
- **根因**:`qc_mold_insp_head` 早在 2026-10-16 随「成型检验单 QC_MOLD_INSP」整体下架,而 2026-10-21 的
  提交 `12866177` 把四处代码改指向它。实测现库:qc_first_insp_head(425 行)/ qc_proc_insp_head(434 行)/
  qc_asm_insp_head(435 行)三张单都在用,`yj_panel` 里 QC_FIRST_INSP / QC_PROC_INSP / QC_ASM_INSP 在册。
- **修法**:`ScheduleBoardService.INSP_HEAD`、`QcInspAutoService.OP_PANELS/HEAD_TABLE/head()`、
  `ButtonService.WO_INSP_HEAD` + 弃审级联、`FirstInspBackfill.HEAD` 一并恢复为
  成型 = 首件 + 制程、组装 = 组装成品(明细不合格列:首件/组装 = `不合格数量`,制程 = `不良数量`)。
- **验证**:trace 接口 200 且质检段有数据(首件/制程/组装成品各 1 张已审核);`/api/procCard/trace` 的
  `工单追溯` 不再是降级错误;生产工单页追溯弹窗质检段 3 行、无「对象名无效」;
  静态核对:三个 head 方法组装的键在 38/36/35 列里**全部是真实列**。
  活体验证(在测试账套实际报工审核)**未做** —— 避免在生产库造业务数据,列为待补。

## 7. 已知边界与非目标

- 不打印纸质卡(后续可复用既有纸张组件,本版不做);
- 卡的修改只留 `asp_user2/asp_time2`,无逐条修改历史;
- 照片在 `uploads/attachments` 磁盘,删卡/删照片只删登记行与文件(见回滚脚本说明);
- 未做材料/来料批次追溯(仍走采购链四单);
- 中间体与成品共用同一套工序口径,按工艺路线走完即「完成」;
- 照片上传沿用全局 `/api/attachment/upload`(该接口没有面板动作词闸门,平台级既有行为,见设计文档 §9)。
