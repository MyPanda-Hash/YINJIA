## 四、如果以后要接推单,还差什么

1. **调拨单**:等金蝶开放的 v2 保存接口(或拿到 v1 的 access_token);字段按 §3.1 映射即可。
2. **盘点单**:需要 MES 侧先有「盘点任务」(`check_task_id`)的概念 ——
   金蝶的盘点单必须挂在盘点任务下(任务=某仓库某一批货物的盘点范围)。
   可行做法:MES 新建盘点单时同时建金蝶盘点任务,或复用固定任务。
3. **仓位**:金蝶调拨/盘点的仓位字段是 `sp_*`,MES 已有 `仓位编码`,映射 `sp_number` 即可 ——
   但金蝶侧 `stock_is_allow_freight` 决定是否校验,需先确认目标仓是否启用仓位管理。
4. 盘盈/盘亏由金蝶"盈亏处理"生成,MES 不需要单独推。

### 为什么盘点类是 0 张

金蝶里最近的盘点单是 **PDD-20260106-00008(2026-01-06)**,盘盈/盘亏单最新也是同一天;
2026-09-01 之后确实没有盘点作业。这不是导出失败 —— `_probe-kd-prod-tfmove.mjs` 实测全量 36/43/45 张都在。

### ⚠ 日期过滤的一个坑

这几个列表接口**不吃任何日期过滤参数**:`start_date` / `begin_time` / `start_time`(时间戳)/
`bill_date_start` / `modify_time_start` 五种写法返回的条数**完全相同**(`_probe-kd-datefilter.mjs` 实测)。
所以日期只能在客户端按 `bill_date` 筛 —— 脚本里就是这么做的,别改成传参数,否则会静默全量返回。
