## 一、这两张单解决什么问题

库存核算里其余出入库单都有"业务对象":采购入库对着供应商、销售出库对着客户、材料出库对着生产工单。
但有两类**纯仓库作业**没有往来单位,只有"货在仓库之间怎么动"和"账上说的和实际数差多少":

| 场景 | 没有这两张单会怎样 | 有了之后 |
|---|---|---|
| 原料从主仓挪到车间仓、成品从成品仓挪到不良品区 | 只能先做"其他出库"再做"其他入库"两张单,一旦漏做一张,两个仓的账就永久歪了 | **一张调拨单一次审核**,两腿同事务,做不成就是整笔不做 |
| 月末盘库,账上 100 实际 92 | 手工改 `kucun` 或做红蓝对冲,改了什么没人留痕 | **一张盘点单**:填实盘数,审核自动算差异并调平,差异留档可追 |

一句话:**调拨管"货挪位",盘点管"账对实"**。两者都是直接改 `kucun` 的单据。

## 二、调拨单(TRANSFER)

### 2.1 用法

1. 库存管理 → 库存核算 → 单据 → **调拨单** → 新增;
2. 点工具栏 **选单** → 弹出「选库存」→ 勾出要挪的货(物料/批号/调出仓/现存量一目了然)→ 确定;
   明细自动带上 **存货 / 规格 / 批号 / 调出仓库 / 单价**,数量与调入仓库**留空由人填**;
3. 逐行填 **调入仓库** 和 **数量**;
4. 保存 → 审核。

### 2.2 审核做了什么

一条明细 **两腿过账**,同一个事务里:

```
调出仓: applyOut(数量)   →  kucun.ckl += N, kucun.yl -= N   (出库流水 src=10)
调入仓: applyIn (数量)   →  kucun.rkl += N, kucun.yl += N   (入库流水 src=9)
```

- **公司总库存不变**,只是从 A 仓挪到 B 仓 —— 这也是验收口径:调拨前后 `Σ kucun.yl` 必须逐字相等;
- 任一条腿失败(仓库档案不存在、调出仓存量不足、…)**整笔回滚**,不会出现"出了没进";
- **弃审 = 两腿对称反做**,按行上数量冲回,不按"当时余额"重算,所以调拨之后又发生了别的出入库也不会冲错。

### 2.3 业务守卫

| 守卫 | 行为 |
|---|---|
| 调出仓 = 调入仓 | **拒绝审核**,提示「同仓调拨没有意义,请改成一个不同的调入仓库」 |
| 数量为空 / 0 | **拒绝审核**(选单带入后忘填数量是常见操作,静默跳过会让人以为"审过了却没动库存") |
| 调出仓现存量不足 | 拒绝(出库后余额转负) |
| 库存低于该批次「预警数量」 | 拒绝(与其他出库单同一道闸门,`StockWarnService`) |
| 仓库档案不存在/停用 | 拒绝,提示先在基础档案-仓库中建立 |

## 三、盘点单(STOCKTAKE)

### 3.1 用法

1. 库存管理 → 库存核算 → 单据 → **盘点单** → 新增;
2. 点 **选单** → 「选库存」→ 勾出要盘的货 → 确定;明细自动带 **存货/规格/仓库/批号/账面数量(=当前现存量)**;
3. 把实际数填进 **实盘数量**(这是**唯一**需要人填的数字);
4. 保存 → 审核。

### 3.2 审核做了什么

```
差异 = 实盘数量 − 账面数量(审核时刻的 kucun.yl)
差异 > 0 → 盘盈:applyIn       (入库流水 src=11)
差异 < 0 → 盘亏:applyOut(|差异|) (出库流水 src=12)
差异 = 0 → 账实相符,不产生任何流水
```

并把 **账面数量 / 差异数量 回写到明细行留档**(界面这两列是只读的,手填会被覆盖)。

- 结果恒等式:**盘点后该行库存 == 实盘数量**,与盘前是多少无关;
- **弃审**:按行上留档的差异对称反做,然后把这两列清空(它们是由审核派生的值,留着会让草稿显示过期数字)。

### 3.3 为什么不卡「预警数量」

盘亏是把账调到实盘,**按定义不该被"低于预警数量"挡住**,否则盘点单永远审不了。
现存量非负守卫仍在(不会盘成负库存),只是不额外卡预警线。

## 四、库位(仓位)

### 4.1 字段与关联

| 单据 | 字段 | 物理列 | 参照 | 级联条件 |
|---|---|---|---|---|
| 调拨单 | **调出仓位** | `调出仓位编码` | 仓位档案 `WHLOC`.`仓位编码` | `仓库 = $调出仓库` |
| 调拨单 | **调入仓位** | `调入仓位编码` | 仓位档案 `WHLOC`.`仓位编码` | `仓库 = $调入仓库` |
| 盘点单 | **仓位** | `仓位编码` | 仓位档案 `WHLOC`.`仓位编码` | `仓库 = $仓库` |

这套配置**与采购入库单的「仓位」字段逐字同款**:选仓位前必须先选该行仓库,弹窗只列**该仓**的仓位
(`ref_filter` 里的 `$字段` 由参照弹窗从当前行取,没填仓库会提示「请先选择『仓库』」)。

### 4.2 审核时的校验(`StockLedgerService.ensureBinValid`)

| 情形 | 结果 |
|---|---|
| 填了仓位,但不属于该仓库(拿 B 仓的仓位填 A 仓) | **拒绝**:「…不属于仓库「A仓」,或该仓位已作废 —— 请重新选择」 |
| 填了仓位,但该仓位在档案里「停用」 | **拒绝**:「…已停用,不能使用」 |
| 该仓库**已维护仓位档案**或 `bs_wh.启用仓位管理=1`,却没填 | **拒绝**:「…的[调入仓位]不能为空:仓库「A仓」已维护仓位档案/已启用仓位管理,必须指定库位」 |
| 该仓库既无仓位档案、也没启用仓位管理 | 允许留空(系统现状:恒亿仓 867 行库存、仓位档案 0 条) |

> 为什么"有档案就必填"比只看 `启用仓位管理` 更严:某个仓一旦维护了仓位,业务上就是要按位管理,
> 空着等于让库位字段形同虚设;而没维护仓位的仓强行要求选一个不存在的位,只会把单子堵死。

### 4.3 ⚠ 口径边界:仓位**不参与**库存结存

`kucun` 与流水表 `inh`/`outh` 的粒度是 **(物料, 仓库, 批号) 三键 + 仓库**,**没有仓位维度**。
所以:

- 仓位**只落在单据上**,是留痕/追溯信息,不影响 `kucun.yl`、不影响台账/收发存/成本;
- 这与**采购入库单/销售出库单完全同口径** —— 实测 `bl_purchase_in` 964 行,填过仓位的 **0 行**;
- 要让仓位成为**库存维度**(按位结存、按位盘点、按位预警),需要给 `kucun` + 收发流水加维度,
  并改所有收发单的过账逻辑 —— 那是独立的一期改造,不在本次范围。
