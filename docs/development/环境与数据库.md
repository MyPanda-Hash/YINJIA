# 环境与数据库（一系统两账套：登录工厂即切换）

> ADR-0003：单一系统、单实例（8090），登录页「登录工厂」选择即切换账套。
> YJ = 正式库 HSDZ_MES；YJ_TEST = 测试库 HSDZ_MES_TEST。令牌(JWT)携带工厂声明，
> 后端按声明把请求线程路由到对应库（每账套独立 Hikari 连接池，各 10 连接）。
>
> **全库表清单（437 表 + 101 视图逐张登记：表名/中文名/列数/关联面板/归属模块）见 [数据库表清单](数据库表清单.md)**；
> 新增表必须带 `MS_Description` 中文注明并刷新该清单（AGENTS.md「数据库注明」规范）。

## 使用

| 登录工厂选择 | 数据库 | 顶栏/登录页显示 |
|------|--------|------|
| YINJIA-MES | `HSDZ_MES`（正式） | YINJIA-MES |
| YINJIA-MES·测试库 | `HSDZ_MES_TEST`（测试） | YINJIA-MES·测试库 |

- 切换账套 = 退出后重新登录选另一个工厂（令牌在签发时绑定工厂，改选必须重登）。
- 两个工厂的令牌可以并存（不同浏览器/标签页各登各的），互不影响。
- 无工厂声明的旧令牌/API 直连默认落**正式库**（安全默认）。

## 测试库制备/刷新

```powershell
powershell -ExecutionPolicy Bypass -File tools/scripts/make-test-db.ps1
```
- 做法：`BACKUP DATABASE HSDZ_MES` → `RESTORE ... WITH MOVE` 为 `HSDZ_MES_TEST`（存在则覆盖），
  并把 `yinjia` 授为测试库 `db_owner`。需 **Windows 管理员身份**运行。
- 测试库被玩坏后重跑一遍即恢复到与正式库一致。

## 日常约定

1. **演示/试用/批量造数 → 登录工厂选「测试库」**；正式库只录真实业务。
2. **迁移脚本**（tools/migrate-*.sql）两个账套都要执行：先正式、后测试（脚本均幂等）。
   - 执行方式二选一：`tools/SqlRunner.java <jdbcUrl> yinjia env <脚本.sql>`，或在 tools 目录下
     `YINJIA_SQL_DB=HSDZ_MES_TEST java -cp lib/mssql-jdbc.jar DbSync.java`。
   - 🔴 **脚本里写无条件 `USE HSDZ_MES;` 会把会话切回正式库**（2026-09-21 实测：连测试库执行后
     `DB_NAME()` 变成 `HSDZ_MES`）——"给测试账套补迁移"实际改的是生产库、测试库一条没补，且**不报错**。
     一律用守卫形式 `IF DB_NAME() = N'master' USE HSDZ_MES;`（只在未选定库时才切）；**不要直接删该行**，
     `yinjia` 登录的默认库是 `master`，删了会在 master 里建表。DbSync 已加拦截（exit 3）防复发。
3. **jdy-sync 定时任务只写正式库**（每 5 分钟同步星辰销售订单）；测试库销售订单需自造。
4. 启停：`tools/scripts/start-prod.ps1`（`-Stop` 停止）。OCR 密钥走环境变量，脚本不落密钥。

## 开发机环境:必须 JDK 25(2026-09-22 核实)

后端硬要求 JDK 25:`backend/pom.xml` 里 `<java.version>25</java.version>`,
打出来的 class 是 **major 69**(= Java 25)。用 21/24 编译会直接报
`错误: 不支持发行版本 25`;用低版本 JDK 跑 jar 会报 `UnsupportedClassVersionError`。

**本机实际情况**(2026-09-22 实查,换机器先照此核对):

| 项 | 值 |
|---|---|
| PATH 里的 `java` | `C:\Program Files\Common Files\Oracle\Java\javapath\java.exe` → **Oracle JDK 24**(系统装的,`C:\Program Files\Java\jdk-24`) |
| JDK 25 实际位置 | `C:\Users\x1787\.jdk\jdk-25\jdk-25.0.2`(Microsoft build 25.0.2,IDE 下载的,**不在系统 PATH**) |
| 处置 | 已设**用户级 `JAVA_HOME`** 指向 JDK 25(不需要管理员) |

**为什么必须设 `JAVA_HOME`**:Windows 的 PATH 解析是「系统 PATH 在前、用户 PATH 在后」,
所以往用户 PATH 里加 JDK 25 **覆盖不了** Machine 级 javapath 里的 java(24)。
而 `mvn` 与仓库所有脚本都**优先取 `JAVA_HOME`** —— 设它就够了:

```powershell
# 一次性(用户级,新开终端即生效;无需管理员)
[Environment]::SetEnvironmentVariable('JAVA_HOME', "$env:USERPROFILE\.jdk\jdk-25\jdk-25.0.2", 'User')
# 验证:应该是 Java version: 25.0.2
& C:\INCER\YINJIA-MES\tools\apache-maven-3.9.9\bin\mvn.cmd -version
```

- 仓库脚本(`build-appjar.ps1` / `build-hot-update.ps1` / `start-project.bat` / `backend\build.bat` /
  `tools\scripts\start-backend.bat` / `tools\pull-sync.bat`)的探测顺序**一致**:
  `JAVA_HOME` → `C:\Program Files\Java\jdk-25` → `D:\Program Files\Java\jdk-25` → `%USERPROFILE%\.jdk\jdk-25\jdk-25.0.2`,
  都找不到才报错。**新写脚本请沿用这段探测,不要把 JDK 路径写死**(2026-09-22 刚从两处硬编码
  `jdk-24` 改成探测式:硬编码在换版本/换机器后必挂)。
- ⚠ 裸 `java -version` 仍会显示 **24**(Machine javapath 优先)。要让**系统默认 java** 也变 25,
  需管理员权限二选一:① 改 Machine 级 `PATH`(把 JDK 25 的 `bin` 放到 javapath 之前)
  或 Machine 级 `JAVA_HOME`;② 用 `deploy\jdk25.msi` 安装到 `C:\Program Files`(会一并写 JAVA_HOME)。
  不改也不影响构建与运行 —— 构建链已全走 `JAVA_HOME`。
- 服务器侧要求与安装步骤见 `deploy/部署说明.md` §4 与 `docs/deploy/服务器部署.md`(均为 JDK 25)。
