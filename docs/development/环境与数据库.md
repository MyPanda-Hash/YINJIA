# 环境与数据库（测试库 / 正式库）

> 2026-09-12 起系统按「一库正式 + 一库测试」运行（ADR-0002 同期决策，见 ADR-0002 复审记录所属会话）。
> 两个环境 = 同一台 SQL Server 上的两个库 + 两个后端实例（端口不同）。

## 环境一览

| 环境 | 数据库 | 端口 | 启动方式 | 工厂名显示 |
|------|--------|------|----------|------------|
| **正式**（真实工厂使用） | `HSDZ_MES` | 8090 | `tools/scripts/start-prod.ps1` | YINJIA-MES |
| **测试**（演示/E2E/随便造） | `HSDZ_MES_TEST` | 8091 | `tools/scripts/start-test.ps1` | YINJIA-MES·测试库 |

- 登录页/顶栏的工厂名来自后端 `/api/base/factory/list`，由 `yinjia.factory-name` 配置——测试实例带「·测试库」标识，防止把测试账当正式账。
- 停止实例：`start-prod.ps1 -Stop` / `start-test.ps1 -Stop`。
- OCR 密钥走环境变量（`ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET`），脚本不落密钥。

## 制备/刷新测试库

```powershell
powershell -ExecutionPolicy Bypass -File tools/scripts/make-test-db.ps1
```
- 做法：`BACKUP DATABASE HSDZ_MES` → `RESTORE ... WITH MOVE` 为 `HSDZ_MES_TEST`（存在则覆盖），
  并把 `yinjia` 授为测试库 `db_owner`。
- 需 **Windows 管理员身份**运行（集成认证连本机实例；`yinjia` 账号无 CREATE DATABASE 权限）。
- 随时可重跑：测试库被玩坏后重跑一遍即恢复到与正式库一致。

## 日常约定

1. **开发/测试一律打 8091**（E2E 脚本把 BASE 指到 `http://127.0.0.1:8091`）；
   8090 只跑验证性冒烟，不批量造数。
2. **迁移脚本**（tools/migrate-*.sql）两条链都要执行：先正式库、后测试库（脚本均幂等）。
3. **jdy-sync 定时任务只写正式库**（HSDZ_MES，每 5 分钟同步星辰销售订单）——测试库没有实时同步，
   需要销售订单测试数据时手动从正式库查或自造。
