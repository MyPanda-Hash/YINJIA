# 仓库·仓位 四层结构与编码规则

> **唯一基线**：仓位的层次与编码一律以本文为准。改结构或改编码规则 = 改本文 + 重跑生成器。
> 现状（2026-10-08）：`bs_wh` 53 列 / `bs_wh_loc` 38 列；**679 个仓位**（新厂区原料区/辅料及配件区待重做）。

---

## 一、四层结构

```
第1层 厂区      老厂区 | 新厂区
第2层 仓        A仓 | B仓 | C仓 | D仓
第3层 大区      原料区 | 辅料及配件区 | 成品仓区
第4层 分区      炭粉区 | 胶粉区 | 货架区 | 纸箱区 | 端盖区 | PP棉区 | …
                  └ 分区内再用 区码 / 排 / 位 / 层 定位
```

### 全景

| 厂区 | 仓 | 大区 | 分区 |
|---|---|---|---|
| 老厂区 | **A仓** | 原料区 | 炭粉区 · 胶粉区 · 货架区 |
| 老厂区 | **A仓** | 辅料及配件区 | 纸箱区 · 端盖区 · PP棉区 · 无纺布区 · 网套区 · 标签区 |
| 老厂区 | **B仓** | —（本身即成品仓，**不再分区**） | — |
| 老厂区 | **C仓** | —（同上） | — |
| 新厂区 | **D仓** | 成品仓区 | —（成品不再细分） |
| 新厂区 | **D仓** | 原料区 | 炭粉区 · 胶粉区 |
| 新厂区 | **D仓** | 辅料及配件区 | 纸箱区 · 端盖区 · PP棉区 · 折叠棉 · 网套&布区 · 货架区 |

> D仓 就是整个新厂区（两者并列），所以**厂区的区别靠"仓"就能看出来**，不必在仓位表里重复存厂区。

## 二、两张表如何承载这四层

**原则：第 1、2 层是"仓"的属性 → 落 `bs_wh`；第 3、4 层是"仓位"的属性 → 落 `bs_wh_loc`。仓位表不冗余厂区/仓名，查询时 JOIN 取。**

### `bs_wh`（仓库档案）— 承载 **第1层 + 第2层**

| 列 | 承载 | 取值 |
|---|---|---|
| `厂区` | **第1层** | 老厂区 / 新厂区 |
| `仓库编码` | 第2层 主键 | `CK-A` / `CP-02` / `CK-C` / `CK-D` |
| `仓库名称` | **第2层** | `A仓` / `B仓` / `C仓` / `D仓` |
| `仓库类型`·`仓库分类`·`停用`… | 属性 | 见库内注释 |

### `bs_wh_loc`（仓位档案）— 承载 **第3层 + 第4层 + 坐标**

| 列 | 承载 | 说明 |
|---|---|---|
| `仓库编码` | 外键 → `bs_wh` | 关联第1、2层；**厂区从这里取** |
| `仓库` | 第2层名称快照 | 仅显示用（改仓名时随 `bs_wh` 同步刷） |
| **`大区`** | **第3层** | `原料区` / `辅料及配件区` / `成品仓区`；B仓/C仓 不分区 ⇒ 空 |
| **`存储分区`** | **第4层** | `炭粉区` / `纸箱区` / … ；不细分的 ⇒ 空 |
| `区码` | 第4层内的区段标识 | 见 §三 区码分配表 |
| `排号` | 坐标 | 2 位补零 |
| `位号` | 坐标 | 该排的第几格 |
| `层号` | 坐标（选填） | 货架层，地面位为空 |
| **`仓位编码`** | **唯一键** | = §三 规则拼成，扫码/参照用它 |
| `仓位地址` | 人读串 | 派生显示：`大区+存储分区+区码[+排]位[+层]` |
| `停用`·`备注`·`asp_*`·`备用1-20` | — | 常规 |

### 为什么这样分

| 选择 | 理由 |
|---|---|
| 厂区/仓 **不放**仓位表 | 厂区由仓唯一决定（D仓=新厂区），存两份必然漂移；用户口径「厂区应该在仓库表而不是仓位表」 |
| `仓位编码` 为**唯一键**，不能由 `区码/排/位` 反推 | 源文档（《仓库库位信息表》）本身有两种写法（区域族 `B1-01-1`、货架族 `AH5-1-1`），编码是**原文事实**；坐标列是**便于筛选的分解** |
| B仓/C仓 的 `大区`/`存储分区` 留空 | 用户口径「B仓一个成品仓、C仓一个成品仓，不再分区」——它的"仓"就是"成品仓" |
| 不做树、不加父节点 | 四层里第 3、4 层已经是列，筛选/汇总直接 GROUP BY；树形 UI 由面板的查询条件承担（引擎无 treeGrid） |

## 三、编码规则

### 唯一一条

```
仓位编码 = <区码>-<排号>-<位号>[-<层号>]

  区码  必填   第4层"分区"在该仓内的短标识（一仓内不重复）
  排号  必填   2 位补零：01…99
  位号  必填   该排的第几格：1…9
  层号  选填   货架层：1…9；地面位不写
```

**依据**：源文档表头原句 —— `B1-01-1/2 = B仓1区 - 01排 - 1#位/2#位`。

### 区码分配表（一仓内唯一）

| 仓 | 分区 | 区码 | 编码示例 |
|---|---|---|---|
| A仓 | 炭粉区 | `A1` | `A1-09-1` = A仓1区-09排-1位 |
| A仓 | 胶粉区 | `A1` | `A1-21-1` |
| A仓 | 纸箱区 | `A1` | `A1-01-1` |
| A仓 | 端盖区 | `A2` | `A2-02-1` |
| A仓 | 货架区 | `AH` | `AH-05-1-1` |
| A仓 | 无纺布区 / 网套区 / 标签区 | `AH` | `AH-01-1-1` |
| B仓 | （成品，不分区） | `B1`~`B4` | `B1-01-1` |
| C仓 | （成品，不分区） | `C1` `C2` | `C2-16-3` |
| D仓 | 成品仓区 | `D1`~`D11` | `D1-01-1` |
| D仓 | 炭粉区 | `T1`~`T6` | `T1-01-1`（待定，见 §四） |
| D仓 | 胶粉区 | `G1`~`G5` | `G1-01-1`（待定） |
| D仓 | 纸箱区 / 端盖区 / PP棉区 / 折叠棉 / 网套&布区 | `ZX` `DG` `PP` `ZD` `WT` | `ZX-01-1`（待定） |
| D仓 | 货架区 | `H` | `H-01-1` |

> **同一区码可承载多个分区**：老厂区 A仓 的 `A1` 同时是 炭粉区(排09–20) 与 胶粉区(排21–24) 与 纸箱区(排01–08)，
> 靠**排号区间**划分用途 —— 这正是源文档的真实结构（`A1` 是物理区，用途是按排段切的标签）。

### 编码 → 四层 的还原

| 编码 | 厂区 | 仓 | 大区 | 分区 | 区码/排/位/层 |
|---|---|---|---|---|---|
| `A1-09-1` | 老厂区 | A仓 | 原料区 | 炭粉区 | A1 / 09 / 1 / — |
| `A1-01-1` | 老厂区 | A仓 | 辅料及配件区 | 纸箱区 | A1 / 01 / 1 / — |
| `AH-05-1-2` | 老厂区 | A仓 | 原料区 | 货架区 | AH / 05 / 1 / 2 |
| `B1-18-3` | 老厂区 | B仓 | — | — | B1 / 18 / 3 / — |
| `D1-01-2` | 新厂区 | D仓 | 成品仓区 | — | D1 / 01 / 2 / — |

## 四、需要拍板的两处（现状与规则不一致，须归一）

### ① 货架族：`AH5-1-1` / `H1-1` 的"区码+排号"是连写的

源文档写 `AH5-1/2/3-1...`、`H1-1/2/3/4` —— 区码与排号之间**没有横线**，与 `B1-01-1` 的写法不一致。

| 方案 | 编码 | 影响 |
|---|---|---|
| **甲：归一为三段**（推荐） | `AH-05-1-1`、`H-01-1` | 与规则完全统一；**需改 108 个老厂区货架码**（`AH5-1-1`→`AH-05-1-1`） |
| 乙：货架族保留连写 | `AH5-1-1`、`H1-1` | 不动存量；但规则变成"两种写法"，与用户口径的单一规则不符 |

### ② 新厂区序号区：原文只有一段数字（`炭1区1-36` / `1-7` / `1-12` / `1-24`）

按三段式规则，这一段数字必须落到 **排** 或 **位**：

| 方案 | 炭粉1区（36 个） | 纸箱区（14 个） | 货架区 | 说明 |
|---|---|---|---|---|
| **甲：数字当"位"、排统一 01**（推荐） | `T1-01-1` … `T1-01-36` | `ZX-01-1` … `ZX-01-14` | `H-01-1` … `H-11-4` | 语义：一个排里 36/14 个位 |
| 乙：数字当"排"、位统一 1 | `T1-01-1` … `T1-36-1` | `ZX-01-1` … `ZX-14-1` | `H-01-1` … `H-11-4` | 语义：36/14 个排各 1 位 |

> 这两处一旦定下，新厂区 原料区(504) + 辅料及配件区(118) 即可按规则重生成；
> 上一批用「两段式」（`炭1区-36` / `纸箱区-14`）生成的 622 个**已删除**（`migrate-whloc-newplant-drop-20261008.sql`）。

## 五、落地方式

- **生成器优先**：每个批次的仓位由 Python 脚本从《仓库库位信息表》原文生成（`tools/archive/_whloc-req/gen-*.py`）→ 产出显式 INSERT 的迁移脚本 → 走 `DbSync` 两账套执行。规则变了改生成器重跑，不手改数据。
- **不新增表、不新增层级**：四层全靠 `bs_wh.厂区` + `bs_wh_loc.大区/存储分区` 三列承载。
- **`区码/排号/位号/层号` 是分解列**，供筛选与批量生成；`仓位编码` 才是唯一真源。
