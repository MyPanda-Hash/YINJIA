系统 = 元数据驱动的低代码 MES:Vue3 面板引擎 + Spring Boot + SQL Server(HSDZ_MES / HSDZ_MES_TEST 双账套),前后端数据键为中文。回归风险集中在五类:

## 3. 分层策略:每层防什么、不防什么

| 层 | 防 | 不防(交给谁) |
|---|---|---|
| L1 前端单测 | 纯逻辑回归(配置推导/键映射/正则/i18n 词条/导出计算) | 渲染与交互 → L2 UI + 真服务走查(AGENTS.md「验证与收尾」) |
| L2 e2e API | 契约与业务事实:统一响应/409/审批防伪/生单占用/编号/记账,断言到 DB 只读核对 | 样式像素 → 人工/截图 |
| L2 e2e UI | 交互可达(登录/离开守卫/参照双模/面板冒烟) | 业务事实(**UI 只断言交互可达,事实以 API/DB 为准**,沿用 e2e README §6) |
| L4 面板回归 | 元数据可查询性(视图/列缺失/参照字段映射) | 业务逻辑 → L2 |
| L5 审计 | 基线漂移/规范体检/部署前置 | 业务逻辑 → L2 |
| L7 部署闸 | 包完整性/备份/恢复/登录可达 | 部署后业务抽验 → 外网终验(入口 `index-*.js` + 面板 totalSize 逐面板对表) |

原则:**能进 L1 的纯逻辑不进 L2**(快、稳、不污染数据);**DB 集成路径由 L2 e2e 承担,后端测试不重复连库集成**(见 G-5,避开测试账套陈旧陷阱)。

## 4. 环境与数据纪律(红线)

1. 🔴 **自动化写入只允许本机**(8090 / 5173 / 1433 容器);**禁止指向生产 36.140.66.163**。`tests/e2e/.env` 不入库;提交前 `git grep` 扫一次不含生产地址/真实凭据。
2. 🔴 **两账套**:迁移与审计类验证必须正式 + 测试双账套都跑(先正式后测试);测试账套陈旧不逐表补迁移,直接 `make-test-db.ps1` 重建(AGENTS.md 两账套纪律)。
3. **e2e 造数规范**:统一 `AUTO_` 前缀 + `.tracked.jsonl` 台账;**清理走 API 不直写库**(草稿→作废;已审→弃审+作废;已中止→恢复+弃审+作废;档案行全量重存剔除);每个用例 `reg` fixture 结束自动清理,`node scripts/cleanup-autodata.mjs` 兜底;已知不可回收留痕清单见 e2e README §4。
4. **DB 只读断言**用专用只读账号 `e2e_ro`(建号脚本 `scripts/create-readonly-login.sql`);db fixture 代码层拦截写关键字 + 表名白名单。
5. 本地 HSDZ_MES 数据按 2026-10-14 口径 = 可随时重拉的测试数据(不产备份文件);但**部署打包前照常跑 `RdAreaEmptyAudit`**(研发区闸门独立于 e2e 残留)。
6. 正式上线当天的库存批次追溯验收(重新导期初 / 出库必填批号 / 先出库按批核销)按 `上线前必验-库存批次追溯.md` §五执行;验收期「忽略批次」的权宜写法必须留 `// 【上线前改写】` 痕。

## 7. 缺口与补齐路线图

盘点缺口:① e2e 套件未入库,单机资产有丢失风险 ② 后端 0 测试(无 test 依赖、无 src/test)③ 无 CI/门禁自动化 ④ livedb 混在默认单测入口(默认绿不了)⑤ 无统一测试入口 ⑥ 无覆盖率度量 ⑦ 组件级(挂载/交互)0 覆盖 ⑦ 审计工具结果无汇总落盘。

### P0(零新依赖,先决与止血)

1. **G-0 e2e 套件入库决策(需拍板)**:`tests/` 目前整体 gitignore。建议解除忽略、把 `tests/e2e` 入库(`.env`/`node_modules`/`report`/`test-results`/`.tracked.jsonl` 仍忽略),作为正式资产维护;若维持不入库,至少定期把 `tests/e2e` 打包备份到仓库外。
2. **G-1 livedb 分离**:把 livedb 文件移出默认发现范围(如 `frontend/test-livedb/`),`"test": "node --test src"`、`"test:livedb": "node --test test-livedb"`——默认 `npm test` 全绿,需真库时手动跑 `test:livedb`。
3. **G-2 统一入口** `tools/scripts/run-checks.ps1`:按 `-Frontend / -Api / -Panels / -Db / -All` 分组聚合**现有**命令,失败即停、末尾汇总 PASS/FAIL 清单(只聚合不新造测试)。
4. **G-3 e2e 绿色基线**:本机起服务(8090+5173)后跑一次全量,结果记入 §8,作为后续回归参照;顺手把 `.env` 切到 `e2e_ro` 只读账号。

### P1(低风险增强)

5. **G-4 后端纯逻辑单测地基**:引入 `spring-boot-starter-test`(JUnit5),只测**不连库的纯逻辑**(编号格式、单据状态推导、翻译分层、口令哈希、参照解析);DB 集成继续由 e2e API 层承担——后端测试**不**直接连两账套,避开「测试账套陈旧同名对象不同源」陷阱。
6. **G-5 门禁自动化**:优先**本机计划任务**夜间跑(前端单测 → e2e api 组 → FourDocAudit/DbNormAudit,结果落 `tools/reports/`,失败留报告);GitHub Actions 作可选(e2e README §5 有现成示例),因 GitHub 连接不稳不作第一选择。
7. **G-6 修复并发取号竞态**(e2e PX-A-043 实证):`FormNoService.next()` 改 UPDLOCK/HOLDLOCK 或加唯一约束,修后移除 fixme 转正用例。

### P2(按需,暂缓)

8. 覆盖率度量(`node --test --experimental-test-coverage`)。
9. 组件级测试(vitest + @vue/test-utils)**暂不引入**:交互层已有 e2e UI + CDP 冒烟兜底,防臃肿;待面板引擎重构需求出现再评估。

每项动工仍按「单任务单提交」+ 提交前四查执行。
