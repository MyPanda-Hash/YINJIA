## 2. 「回填到各自的面版」是怎么成立的

**手机端不另建表、不另建面板**:三张手机页的面板码就是研发管理里那三张 PC 面板
(`RD_SPIKE_WATER` / `RD_EQUIP_USE` / `RD_INSTR_USE`),数据键与落库表完全同一份:

```
手机页(RD_EQUIP_USE)
  GET  /px/getNewFormPermMatrix?panelCode=…   → meta(表头字段) + detail(明细页签) + data(默认值)
  GET  /px/getFormDescriptor?panelCode&code   → data + detailData(明细行,带 id)
  POST /px/queryFormDataList                  → 列表 + 模糊查询(keyword 同时匹配表头与明细)
  POST /px/callButton {buttonName:'保存为草稿'} → 单据头/明细落 rd_*_head / rd_*_detail
```

⇒ 手机存下的单,电脑端打开同一个面板就是**同一张单**(状态=草稿),
审核/归档照电脑端原流程(`提交审批` → `审批通过`),手机端不替用户送审。

为什么用「保存为草稿」而不是「保存」:这两张 PC 面板属文书式(DOC_ARCHIVE_PANELS),
`保存` 会直接置 `审批中`(送审),草稿态才可以继续补照片/改错字。必填校验在前端做一层
(后端 `ensureRequiredFilled` 只对「保存」生效,草稿口子靠前端把关)。

## 3. 照片:一个字段,两处看

- 每张记录表新增**一个表头字段** `手机照片`(`data_type='附件'`、`place=header`、`seq=50`)。
- 手机端选/拍的照片走既有附件服务:`POST /attachment/upload`(multipart: file + panelCode + docNo + field=`手机照片`)。
  - **新单没有单号** ⇒ 先本地预览排队(界面上标「待上传」),保存拿到后端发的号后自动补传;
  - 已有单号 ⇒ 选完即传。
- `AttachmentService.syncHeadField` 会把原文件名串(「、」分隔)同步写回 head 表的 `[手机照片]` 列,
  列表/打印/导出看到的都是这串文件名。
- 电脑端查看入口两处:
  1. `RecordSheetPanels` 纸面**上方**的「附件/照片条」—— 只显示「配置没消费、但元数据里有」的附件字段
     (这三张是 plain 登记表版式,纸面没有通用 key-value 区);已在 `recordSheetConfigs` 里声明成
     `{type:'file'}` 的字段(如产品信息表·客户图纸)照旧走原格子,不会重复渲染。该条 `no-print`。
  2. 具备通用表头附件条的页面(`PanelxList` 的 attach-strip / `PanelxForm` / `DocSheet`)同样可见。
