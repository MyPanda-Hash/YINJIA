## 2. 「回填到各自的面版」是怎么成立的

**手机端不另建表、不另建面板**:三张手机页的面板码就是研发管理里那三张 PC 面板
(`RD_SPIKE_WATER` / `RD_EQUIP_USE` / `RD_INSTR_USE`),数据键与落库表完全同一份:

```
手机页(RD_EQUIP_USE)
  GET  /px/getNewFormPermMatrix?panelCode=…   → meta(表头字段) + detail(明细页签) + data(默认值)
  GET  /px/getFormDescriptor?panelCode&code   → data + detailData(明细行,带 id)
  POST /px/queryFormDataList                  → 列表 + 模糊查询(keyword 同时匹配表头与明细)
  POST /px/callButton {buttonName:'保存为草稿'} → 单据头/明细落 rd_*_head / rd_*_detail
```

⇒ 手机存下的单,电脑端打开同一个面板就是**同一张单**(状态=草稿),
审核/归档照电脑端原流程(`提交审批` → `审批通过`),手机端不替用户送审。

为什么用「保存为草稿」而不是「保存」:这两张 PC 面板属文书式(DOC_ARCHIVE_PANELS),
`保存` 会直接置 `审批中`(送审),草稿态才可以继续补照片/改错字。必填校验在前端做一层
(后端 `ensureRequiredFilled` 只对「保存」生效,草稿口子靠前端把关)。

## 3. 照片:一个字段(按行),两处看

- 每张记录表的**明细表**新增一列 `手机照片`(`yj_field.data_type='附件'`、`place='detail'`)。
- 手机端选/拍的照片走既有附件服务:`POST /attachment/upload`(multipart: file + panelCode + docNo + field=`手机照片-<行id>`)。
  - 行已有 id(既有单的行 / 已保存过的行)⇒ 选完即传;
  - **新行还没有 id** ⇒ 先本地排队(标「待上传」),保存拿到 id 后自动补传(见 `mergeRowIds`);
  - 每一行各自一份附件,**显示成文件列表**(📎 名字 + 大小),点名字=下载;按用户口径**不提供预览**
    (`FileAttachCell` 新增 `downloadOnly` 开关,手机端与纸面逐行附件格都用它)。
- `AttachmentService.syncHeadField` 会把该行原文件名串(「、」分隔)同步写回 `rd_*_detail.[手机照片]`,
  纸面/打印/导出看到的都是这串文件名;其余面板(采购订单 附件1..6 等)仍走原来的头表同步,行为一字未动。
- 电脑端查看/上传入口:`RecordSheetPanels` 在**数据表格末尾自动补一列**「手机照片」——
  该列由明细字段元数据发现(`dataType='附件'` 且在 `detailFields` 里),不在三份 `recordSheetConfigs` 里写死
  (加标水那种"列集由标准库模版决定"的表格因此也带得上)。表头那条「附件/照片条」按用户要求撤掉。
