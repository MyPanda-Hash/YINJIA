# 数采(数据采集)后台表清单

> 建立时间 2026-10-19;口径:凡是「数据抓取保存」落库的地方都在这 7 张表里,全部是 `bs_dc_*` 前缀
> (表前缀与命名规则见 `docs/development/数据库规范.md`;建表脚本 `tools/migrate-dc-platform-20261018.sql`)。
> 快照数据取自 2026-10-19 15:08 的正式账套 HSDZ_MES。

## 1. 总表(一页看完)

| # | 表名 | 中文名 | 存什么 | 谁写 | 增长/保留 |
|---|---|---|---|---|---|
| 1 | `bs_dc_gateway` | 数采网关 | 网关台账:协议、IP/端口、在线状态、接入密钥 `api_key` | 界面(设备配置管理)/`/gateway/save` | 台账,几条 |
| 2 | `bs_dc_device` | 数采设备 | 电子秤/扫码枪/看板/PLC 台账 + 绑定的网关 + 在线状态 `status`、最近上报 `last_seen_at` | 界面/`/device/save`;**硬件上报时刷新在线** | 台账,几条 |
| 3 | `bs_dc_point` | 采集点 | 设备下的变量:编码、名称、类型、单位、量程上下限、采集周期 | 界面/`/point/save` | 台账,几条 |
| 4 | `bs_dc_rule` | 数采规则 | 定时采集/变化上报/阈值报警规则 | 界面/`/rule/save` | 台账,几条 |
| 5 | **`bs_dc_sample`** | **采集流水** | **每次抓到的值**:`value_num`(数值)/`value_text`(文本)、`quality`、`collect_at` | **硬件上报** `/api/dc/ingest`(JSON)与 `/api/dc/ingest/text`(原始串) | **每秒一条;每 5 分钟清理,每点只留 10 条** |
| 6 | `bs_dc_alarm` | 报警记录 | 超限报警:级别、内容、触发值、发生时间、处理留痕 | 上报时自动产生;`/alarm/handle` 写处理结果 | 只增,不清理 |
| 7 | `bs_dc_status_log` | 在线状态日志 | 设备 在线↔离线 状态变更(在线率统计的唯一依据) | 硬件上报/心跳触发状态变化时写 | 只增,不清理 |

**一句话**:台账 4 张(gateway/device/point/rule)+ 数据 3 张(sample/alarm/status_log)。

## 2. 数据怎么流进来的

```
电子秤/扫码枪/PLC
   │ 串口(RS232 9600-8-N-1) 或 网络
   ▼
W111 透传模块 / 网关
   │ ① JSON 口  POST /api/dc/ingest        {deviceCode, values:[{pointCode, value|text, at}]}
   │ ② 文本口  POST /api/dc/ingest/text   正文=串口帧原文(如 +000.41000.00kg)
   │ ③ 心跳    POST /api/dc/heartbeat     {deviceCode}
   ▼
MES(DcController → DcService)
   ├─ 写 bs_dc_sample            一条采集流水(value_num / value_text + collect_at)
   ├─ 刷 bs_dc_device            改 status=online / last_seen_at / last_debug_at
   ├─ 状态变化时写 bs_dc_status_log
   └─ 越过采集点上下限时写 bs_dc_alarm(level=预警,state=未处理)
```

文本口的两道闸(2026-10-19 用户口径):**空重量(≤5g)不写流水但刷在线心跳**;**同一设备 1 秒最多写一条**。

## 3. 逐表关键列

### 3.1 `bs_dc_sample`(数据抓取主表)

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint 自增 | 主键;流水只增不改 |
| `device_id` / `point_id` | int | 哪台设备的哪个采集点 |
| `value_num` | decimal(18,4) | 数值型采集值(重量/读码率…) |
| `value_text` | nvarchar(200) | 文本型采集值(条码内容…) |
| `quality` | char(1) | 质量位,默认 `G` |
| `collect_at` | datetime2 | 采集时刻(**不是入库时刻**,回放历史数据时用 `at` 指定) |
| `asp_*` | — | 审计五件套;`asp_user1` 记录来源(`ingest`) |

索引:`PK_bs_dc_sample`(id)、`IX_bs_dc_sample_point_at`(point_id, collect_at DESC)。

### 3.2 `bs_dc_device`

关键列:`code`(唯一)、`device_type`、`gateway_id`、`status`、`last_seen_at`、`last_debug_at`、
`heartbeat_seconds`(离线判定 = 该值 ×3)、`project_code`/`scada_drawn`(五连检查用)。

### 3.3 `bs_dc_point`

关键列:`device_id`、`code`(上报时用它)、`name`、`data_type`、`unit`、`freq_seconds`、
`low_limit`/`high_limit`(越限才报警)、`enabled`。

### 3.4 `bs_dc_gateway`

关键列:`code`(唯一)、`protocol`、`host`/`port`、`status`、`api_key`
(**硬件上报的唯一凭据**:请求头 `X-DC-Key` 必须等于该网关的 `api_key`)。

### 3.5 `bs_dc_alarm`

关键列:`device_id`/`point_id`、`level`(预警…)、`message`、`value_text`、`occur_at`、
`state`(未处理/已处理)、`handled_by`/`handled_at`/`handled_note`。

### 3.6 `bs_dc_status_log`

关键列:`device_id`、`status`(online/offline)、`changed_at`、`reason`。
状态统计页的在线率/在线时长都是从这张表折叠出来的,没有日志就算「未接入」,不再按窗口硬算离线。

## 4. 保留与清理

| 表 | 保留策略 | 配置项 |
|---|---|---|
| `bs_dc_sample` | **每个采集点只保留最新 10 条**,每 5 分钟清理一次(`DcSampleCleanupScheduler`, cron `0 */5 * * * *`) | `yinjia.dc.sample.retain`(默认 10,≤0 关闭)、`yinjia.dc.sample.cleanup-cron` |
| 其他 6 张 | 不自动清理(台账 + 报警 + 状态日志都是业务凭据) | — |

清理只删流水表,**不动**报警、状态日志、台账;因此状态统计/在线率不受影响。
