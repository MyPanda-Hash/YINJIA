# 检验报告表尾:按模板两行两对 + 处理意见标准库 + 三处必填(2026-11-11)

## 一、用户口径

> 「红框四项修改成这个图片上的排列形式,处理意见做成标准库的形式。
> 还有检验结论和处理意见是必填。单项判定也是必填。」

模板(YJ-QR-96 检验结果区底部)是**两行两对**;原来代码是「检验结论」「处理意见」各占整行、
签名行单独一行(共三行)。

## 二、改了什么

| 项 | 改前 | 改后 |
|---|---|---|
| 表尾版式 | 检验结论(整宽) / 处理意见(整宽) / 检验人·审核人(一行) —— 三行 | **检验人 \| 值 \| 检验结论 \| 值** / **审核人 \| 值 \| 处理意见 \| 值** —— 两行两对 |
| 处理意见 | 文本输入框 | **标准库下拉**(`qc.insp_disposal`,带「⧉ 标准库维护」,也可直接敲新词) |
| 检验结论 | 选填 | **必填**(★,服务端拦) |
| 处理意见 | 选填 | **必填**(★) |
| 单项判定 | 选填 | **必填**(★,逐行拦) |

落点:

- 版式真源:`frontend/src/core/qc/qcInspRecColumns.js` 的 **`QC_INSP_REC_FOOT_ROWS`**
  (两行 × [签名, 结论];原来拆成 `FOOT_FULL` + `SIGN_ROW` 两份,现在合成一份);
- 组件:`frontend/src/core/views/QcInspRecSheet.vue` —— 表尾按 `FOOT_ROWS` 渲染,
  `处理意见` 走 `el-select`(选项来自字段 `options`,即后端按 `data_type=标准库` 下发的 yj_std_lib 条目),
  两个标准库各自可维护(`openStdLib(lib, title)` 参数化,检验项 = `qc.insp_item`,处理意见 = `qc.insp_disposal`);
- 必填标记:`isRequired(key)` 读面板配置里的 `isRequired`(= `yj_field.required`),显示红色 ★;
- 必填"拦得住"的关键:`ButtonService.ensureDetailRequiredFilled` **只校验载荷里带了该键的行**
  ⇒ 新增行原来是空对象 `{}`,整行会被跳过。现在 `blankRow()` / 带入的行都把
  `检验项 / 检测标准 / 单项判定` 建成了空串键,空值才会被服务端拦下;
- 元数据:`tools/migrate-qc-insp-rec-foot-required-20261111.sql`(两账套已执行,幂等)
  · `处理意见` → `data_type=标准库` / `dict_sql=qc.insp_disposal`
  · `yj_std_lib` 播种 7 条:同意入库 / 让步接收 / 挑选使用 / 退货处理 / 返工重检 / 报废处理 / 待品质部评审
  · `required=1`:检验结论(header)、处理意见(header)、单项判定(detail)。

## 四、维护方式

- 改处理意见候选:纸面「处理意见」标签旁的 **⧉ 标准库维护**,或 `yj_std_lib` 里
  `lib_code='qc.insp_disposal'` 的行(停用= `enabled=0`,删除= `asp_cancel='Y'`);
- 改必填:字段管理里把 `required` 开关拨掉即可(服务端同一份 `yj_field.required`);
- 版式若还要调(例如把「处理意见」也做整宽),改 `QC_INSP_REC_FOOT_ROWS` 一处即可,
  纸面、打印、导出都跟着变。
