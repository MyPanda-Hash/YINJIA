# 原有排产表数量为零修复

## 根因与口径

`ScheduleBoardService.assign` 和切单继承排产原只向 `plang_pc` 插入产线等少量字段,漏掉原有 `pl_sl` 等数量列,默认成为0。页面从 `plang` 取数掩盖了此问题。

- 沿用 `plang` 工单行与 `plang_pc` 排产记录结构,不新增表列。
- 明确传入排产量时使用该量;省略时优先沿用工单行已有正排产量,否则使用需求量。零/负数/非有限数拒绝。
- `yl=需求数量-排产数量`,不与工序报工数量混算。
- 新排产携带原有数量、产品、单位等共同业务字段。客户代码两表长度不同,不新增客户代码复制;历史来源订单号不同长度,同步时不覆盖原值。
- 切单与撤回同步父数量;子单继承排产量。修正切单 INSERT 中工艺路线与审计列的错位。
- 入库结案重算/领料回写同步现有单条排产记录;只UPDATE,保留 `scjl.gd_id` 引用的排产ID。
- 历史同一 `plang_id` 多条有效排产记录不能按主行全量覆盖,同步跳过;存量迁移仅补唯一有效排产行的零量,歧义行输出供单独核实。
