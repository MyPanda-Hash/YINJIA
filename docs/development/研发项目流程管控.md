# 研发「项目流程管控」

> 面向:**填了立项申请、想知道单子走到哪一步的人**(申请人 / 对接人 / 项目责任人 / 审批人)。
> 入口:研发管理 → 项目管理 → **项目流程管控**(`/#/rd/projectFlow`,面板码 `PROJECT_FLOW`)。
> 建立日期:2026-10-20(用户口径见下)。

## 一、为什么有这一页

用户原话:

> 我填写立项申请之后提交审批,但是我不知道我这个文件到底到哪个流程了,现在是只有到项目实施计划填写
> 审批归档之后才会在项目进度查询里面看到,但是中间可能会卡住却不知道 ……
> 看这个编号对应的流程走到哪里了,哪个环节还没有审批,哪个单据审批了下一张单内容还没有开始填写。

**改前**:链路中间的环节(定级分发 / 确认责任人 / 责任人确认收到 / 实施计划建了但没填)在界面上
没有统一出口 —— 只有等实施计划归档进了「项目进度查询」才看得见,卡在中间只能靠逐个面板翻。

**改后**:一个只读页,输入立项单号(支持片段)→ 10 个环节逐条给结论:
已完成 / 进行中(带时间与操作人)/ 未开始,并算出**当前卡在哪一步、该谁动手、停留几天**。

## 二、10 个环节与判定口径(唯一真源 = `frontend/src/core/rd/flowStages.js`)

| # | 环节 | 判据(全部取现役真实字段) |
|---|---|---|
| 1 | 立项申请填写 | `rd_approval` 有该单据行 |
| 2 | 立项申请提交审批 | `yj_form_approval` 有 `RD_APPROVAL/SUBMIT` 留痕,或 `yj_doc_status.pending='Y'`,或已审批通过 |
| 3 | 立项申请审批通过 | `yj_doc_status.shr` 非空 / `archived='Y'`,或 `RD_APPROVAL/APPROVE` 留痕 |
| 4 | 定级分发(等级 + 对接人) | `rd_approval.项目等级` 与 `备用1`(对接人)**都非空**(2026-10-19 起两事一个按钮) |
| 5 | 确认项目责任人 | `rd_approval.备用2` 非空(由对接人签核选人) |
| 6 | 责任人确认收到 | `rd_approval.备用3/备用4` 非空,**或** `RD_APPROVAL/OWNER_ACK` 留痕 |
| 7 | 填写项目实施计划 | `rd_plan.文档编号 = 立项单号` 且**至少一个阶段有计划内容**;只建单不填仍算"没开始填" |
| 8 | 实施计划提交审批 | `RD_PLAN/SUBMIT` 留痕,或 `pending='Y'`,或已审批/归档 |
| 9 | 实施计划审批通过并归档 | `yj_doc_status.shr` 非空 / `archived='Y'`(该类面板审批通过即归档) |
| 10 | 进入项目进度查询 | `rd_progress_detail.[说明] = 计划文档编号`(= 立项单号)且有未作废的进度单 |

**待办人**(该谁动手):

- 2 → 申请立项人;3 / 9 → 「审批人」(具体人要按角色审批权判,不写死)
- 4 → 本单审批人(`shr`)· 5 → 对接人(`备用1`)· 6 / 7 / 8 → 项目责任人(`备用2`)
- 10 → 管理员(超时没自动同步时点「同步进度」)

**停留天数** = 现在 − **最后一次动作时间**(取已完成的各环节时间最大值);
完成的项目不显示停留天数;≥7 天在页面上标红,并计入「超 7 天没动」KPI。

## 三、两种非正常情形(实测会遇到,已按数据真实呈现)

1. **状态没落库、后序已完成**
   例:`HSDZ_MES` 的 `LXA-2026-10-0011` —— 实施计划已归档、进度查询已有行,但立项上
   `责任人确认收到` 的备用3 是空的(老代码路径只写了留痕)。此时该环节显示「进行中」+ 红色
   **状态待核** 标签,detail 末尾注明「后序环节已完成，此处状态未落库」,避免用户以为流程没走到这。
2. **弃审回退**
   弃审会清 `项目等级 / 备用1~4`,但审批留痕与进度行可能还在 ⇒ 页面如实显示"卡在定级分发"且
   5~7 步未开始,由用户按弃审后的真实状态重走流程。

## 四、代码位置与边界

| 层 | 位置 | 说明 |
|---|---|---|
| 取数 | `backend/.../service/RdProjectFlowService.java` | **只取事实**(立项/计划/两处 doc_status/进度行/留痕/账号姓名),不判环节 |
| 接口 | `PxController` `GET /api/px/rdFlow?keyword=` | 闸门 `perm.requirePanelView("PROJECT_FLOW")` |
| 判环节 | `frontend/src/core/rd/flowStages.js` | 纯函数 `buildFlow(project, names, now)`,15 条单测钉边界 |
| 页面 | `frontend/src/views/rd/ProjectFlow.vue` | 表格 + 展开 10 步时间轴;窄屏(≤768)只留 4 列防横向溢出 |
| 接口封装 | `frontend/src/business/rdApi` → `rdFlowApi.js` | `apiQueryRdFlow(keyword)` |
| 权限 | `PagePanelRegistry.PROJECT_FLOW`(模块=研发管理,动作 view/query) | 页面级虚拟面板:**不往 `yj_panel` 插行** |
| 授权/译名 | `tools/migrate-rd-project-flow-20261020.sql` | 现有全部角色 `view,query` + 面板名 en 译名 |

**本页不写任何单据** —— 要补审批 / 定级分发 / 确认收到 / 填计划,都回原面板操作。
没有新增表、没有视图,`tools/db-inuse-tables.txt` 与《数据库表清单》无需变更。
