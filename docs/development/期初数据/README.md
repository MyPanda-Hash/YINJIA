## 三、两种口径为什么不同

| | 方案A(采用) | 方案B(未采用) |
|---|---|---|
| 算法 | 金蝶 `point_date=2026-08-31` 直取 | 金蝶当前现存量 − 金蝶 9/1 后真实收发净额 |
| 行数 / 合计 | 1,345 / **5,660,746.23** | 1,925 / 4,730,170.33 |
| 负值行 | **0** | 263 |
| 期末(=期初 + MES 9/1后净额 −338,846.83) | 5,321,899.41 | 4,391,323.51 |
| 与金蝶当前现存量(4,434,487.26)差 | −887,412(多) | −43,164(少) |

**A/B 逐键一致仅 865 / 2,714**,差额绝对值合计 271.7 万 —— 因为 MES **缺拉调拨单 `SCTL`**、
采购退货 `CGTH` 等单据(9/1 后金蝶净额 −295,683 vs MES 已记账 −338,847,差 43,164)。

> ⇒ 方案A 的期初**本身是对的**(它是金蝶官方时点库存),差异来自 9/1 后的单据缺口,
> 不在期初。要真正对上金蝶,还须补拉调拨单等单据(见可行性核查文档 §六)。

## 四、正式库导入前必须确认

1. 本目录的 Excel 与 `_out/opening-A-0831.json` 是否仍是你想要的**当期**口径
   —— 若离上线日已远,应改用 `point_date=<上线日前一天>` 重取,不要直接复用 8/31 这份;
2. 确认后执行(先 dry-run,dry-run 全绿再加 `--write`):
   ```powershell
   cd D:\YINJIA-main
   node tools\archive\_kd-opening-probe\_import-opening.mjs --db HSDZ_MES
   node tools\archive\_kd-opening-probe\_import-opening.mjs --db HSDZ_MES --write
   ```
3. 导入后重启 8090(启动自检 `InvCostService.reconcileOnStartup` 会重算成本物化表),
   或点「库存报表 → 重算成本」;
4. **上线当天的批次追溯口径另有一整套要求**,见 [上线前必验-库存批次追溯.md](../上线前必验-库存批次追溯.md)。
