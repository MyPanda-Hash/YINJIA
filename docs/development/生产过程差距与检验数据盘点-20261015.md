## 三、当前生产「是否产生检验数据」——代码机制 + 实际结果

### 3.1 机制(报工审核后副作用,`ButtonService.runWoAuditHooks`)

```
WO_REPORT 报工单「审核」或「审批通过」(两条路共用同一钩子,2026-10-15 修)
  │
  ├─ woReport.post            记账:写 wgzt/wgsj、补工单行号、镜像排产到 scjl
  ├─ processTask.onReport     工序任务回写 + 工单行状态重算
  ├─ applyNextProcess         转序:前道完工 → 切下一道预排线
  ├─ woInspGenerate ★         成型→QC_MOLD_INSP / 切炭→QC_CUT_INSP / 组装→QC_ASM_INSP
  │      └ firstInspGenerate ★  本(工单,批次,工单行)第一张报工 → QC_FIRST_INSP
  ├─ asmInspToStock           组装成品检验审核 → 合格数转产成品入库单草稿
  ├─ dualOutFinishIn          切炭直销数量 → 自动成品入库并审核入账
  ├─ manuWriteback            工单回填 rk_sl/rk_no/ll_no2
  └─ syncCloseAfterAsmInsp    结案重算
```

★ 两处就是「生产产生检验数据」的全部落点。关键代码事实:

## 五、差距清单(按影响排序)

### P0 —— 影响「生产产生检验数据」这个命题本身

1. **自动出单 ≠ 有检验数据**:`woInspGenerate` 按 2026-10-15 口径「明细行不填入」,
   自动生成的检验单永远是空草稿。若不改口径,系统**不会**因为生产而产生检验数据。
   → 建议:至少把《成型工艺清单》/检验方案(`bs_qc_plan`,现 0 行)的检验项目**预铺成明细行**
   (像首件检验单那样),让品质"填值"而不是"从零建表"。
2. **首件检验单自动出单路径从未被验证**:功能上线(10-15)晚于最后一张报工(10-14)。
   → 建议:在测试库造一张报工、走一遍审核,确认 `WO_REPORT→QC_FIRST_INSP` 流转链与
   5 项预铺真的落库(顺带确认 27 张手工空壳是不是"新增即落库、未保存明细"的正常现象)。
3. **检验基础档案为空**(`bs_qc_item`/`bs_qc_plan` 0 行),检验单没有可参照的标准。
   → 先把基础档案铺起来,预铺明细才有内容。

### P1 —— 流程断点

4. **没有领料**(`bd_material_out` 0 行)、**没有成品入库**(`bd_finish_in` 0 行):
   报工之后链路空转。装箱→入库改由组装检验驱动,但组装检验也没填数 ⇒ 入库永远为 0。
5. **标准路线 `GY-CB-STD` 只有 3 道(成型→切炭→组装)**,流程图要求的混料、装箱不在路线里。
   → 混料报工/装箱报工"无路线可依";若按流程图走五道工序,需先建含混料/装箱的路线。
6. **打印产品二维码入口不可达**:唯一登记点挂在已下线的 `WO_ORDER` 面板,且 `genProductLot()`
   只认 `MANU_ORDER`(0 行)—— 与 `plang` 单轨不兼容。
7. **齐套表已下架**(`WO_KIT`/`bs_bom`/`v_wo_kit` 2026-10-14 整体删除),流程图明确要求"要能看齐套表"。

9. 线边库存(只有 i18n 词条,无任何实现)

## 六、一句话回答原问题

> **当前系统在生产报工审核时会自动"开出"成型/切炭/组装三张检验单(以及首件检验单),
> 但这些单子都是空壳:明细不预铺、实测数值 0 行、检验数量与总结论全空 ——
> 即「生产会自动产生检验单,但不产生检验数据」;全库真正填了检验数值的只有 1 张手工建的
> 制程检验单(ZC-2026-10-0001)。首件检验单的自动出单路径至今一次都没被真实报工触发过。**
