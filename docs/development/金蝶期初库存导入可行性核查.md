# 金蝶期初库存导入 MES —— 接口可行性核查(2026-10-19)

> **用户口径**:「需要 9 月 1 号之前所有库存的现存量作为 MES 库存;9/1 之后的单据我们已经拉下来了;
> 希望 MES 库存与金蝶实际库存能对应上,符合实际,能直接投入使用。」
> **背景**:MES 只有 9/1 之后的出入库单据,库存经常为负。
>
> 本文全部结论出自对**真实账套**(clientId=359797,惠州市银嘉环保,outerInstanceId=580147507460444160)的
> **只读**接口实测。探针:`tools/archive/_kd-opening-probe/`。

---

## 一、结论速览

| 问题 | 结论 |
|---|---|
| 金蝶能直接给出「2026-08-31 的库存」吗? | **能** ✅ 用 `/jdy/v2/scm/inventory` 的 **`point_date`** 参数,一行代码、无推导误差 |
| 这个接口可信吗? | **可信** ✅ `point_date=今天` 与现存量接口逐键比对 **1374/1374 完全一致** |
| 导入后 MES 能对上金蝶吗? | **不能自动对上** ⚠ 另有 **2 个与期初无关的真实缺口**(见 §五) |
| 能直接投入使用吗? | **口径上可以,但有前提** —— 必须同时修批号口径 + 补拉缺失单据(见 §六) |

**一句话**:期初本身没问题,金蝶给得出、给得准;**卡住 MES 与金蝶对不上的是「批号口径」和「单据没拉全」**,这两个不修,导什么期初都对不上。

## 三、核心接口:`point_date` 历史时点库存

### 3.1 接口形态

```
GET /jdy/v2/scm/inventory?page=1&page_size=100&point_date=2026-08-31
```

返回行字段(实测):`material_id` `material_number` `material_name` `material_model`
`stock_id` `stock_name` `stock_number` `batch_no` `qty` `qty_package` `aux_qty` 等。

### 3.2 自洽性验证(**这是可信度的关键**)

| 时点 | 行数 | 数量合计 |
|---|---:|---:|
| `point_date=今天(2026-10-19)` | 1374 | 4,434,487.26 |
| 现存量接口 `inv_inventory_ims`(当前) | 1374 | 4,434,487.26 |
| **逐键比对** | — | **一致 1374 / 不同 0 / 仅一边有 0** ✅ |

⇒ `point_date` 与"当前库存"在同一口径下**完全吻合**,说明它给的就是真实的时点结存。

### 3.3 各时点取值(证明真的在按日期切片)

| point_date | 行数 |
|---|---:|
| 2026-06-30 | 1351 |
| 2026-08-01 | 1285 |
| **2026-08-31** | **1346** |
| 2026-09-01 | 1318 |
| 2026-10-19(今天) | 1374 |

⇒ 不同日期返回不同结果,**不是把当前值原样返回**。

### 3.4 2026-08-31 期初实测结果

- **1346 行**,其中非零 **1345 行**
- 数量合计 **5,660,746.23**
- **负值 0 行** ✅(期初本身干净,不含负库存)

## 四、两个"看似可用其实有坑"的接口

### 4.1 `inv_inventory_ims` 的 `filter_date` 是**摆设**

| 参数 | count | Σqty |
|---|---:|---:|
| 无 `filter_date` | 1374 | 206,039.70 |
| `filter_date=2026-08-31` | 1374 | 206,039.70 |
| `filter_date=2026-09-30` | 1374 | 206,039.70 |

⇒ **完全不生效**。官方文档虽有 `filter_date` 参数,但实测被忽略。想取历史只能用 `scm/inventory` 的 `point_date`。

### 4.2 `inv_detail`(收发明细)做期初累加:能算但很危险

实测踩到 4 个坑,记录在此以免后人重踩:

| # | 坑 | 实测现象 |
|---|---|---|
| 1 | **日期跨度上限约 1 年** | `2015-01-01~2026-08-31` → **静默返回 0 条**;`2026-01-01~08-31` → 30040 条 |
| 2 | **每页固定只回 100 行** | `page_size=2000` 也只回 100(首页例外)→ 必须按 100 翻页 |
| 3 | **期间汇总行混在明细里** | 约 1/3 的行 `bill_no` 为空、`stock_number` 为空、带 `remain_base_qty` ⇒ 累加时**必须排除**,否则双计 |
| 4 | **单日窗口返回快照** | `start=end=当天` 恒返回 369 条,不能累加 |

按正确口径(按月窗口 + 只取有单据号的行)算出的期初:**

| 口径 | 键数 | 期初数量合计 | 为负 |
|---|---:|---:|---:|
| A 正向累加(2025-01 ~ 2026-08) | 4684 | 1,452,600 | 404 |
| B 倒挤(现存量 − 9/1后净额) | 1963 | 4,728,339 | — |
| **C `point_date` 直接取** | **1346** | **5,660,746** | **0** |

⇒ **三种口径互相打架**(A 与 B 逐键仅 500 个一致),说明**用单据反推期初不可靠**;
`point_date` 是唯一"金蝶自己说了算"的口径,**应当以它为准**。

## 五、MES 导入期初后的闭环缺口(如实报告)

把 `point_date(2026-08-31)` 当期初、MES 已有的 9/1 后流水当发生额,比对金蝶当前现存量:

```
期初(8/31) 5,660,746.23  +  MES 9/1后流水 −338,844.83  =  5,321,901.41
金蝶当前现存量                                              4,434,487.26
                                                        差  887,414.15
```

按三种粒度逐键比对:

| 粒度 | 键数 | 一致 | 不一致 | \|差额\|合计 |
|---|---:|---:|---:|---:|
| 物料 + 仓库 + 批号(kucun 原生) | 3145 | 746 | 2399 | 8,245,843 |
| 物料 + 仓库 | 1586 | **1189** | 397 | **2,805,025** |
| 物料 | 1392 | **1056** | 336 | **2,569,059** |

**缺口由三块构成**(已逐项取证):

### 缺口① MES 少拉了一类单据:调拨单 `SCTL`(最大头)

金蝶 9-10 月单据净额 vs MES 已拉单据净额:

| 单据类型 | 金蝶净额 | MES 状态 |
|---|---:|---|
| SCLL 生产领料 | −2,666,208 | ✅ 已拉 |
| CGRK 采购入库 | +2,307,638 | ✅ 已拉 |
| XSCK 销售出库 | −1,284,233 | ✅ 已拉 |
| CPRK 产品入库 | +1,183,651 | ✅ 已拉 |
| **SCTL 调拨单** | **+164,592** | ❌ **未拉**(MES 无调拨面板) |
| QTRK 其他入库 | +56,872 | ✅ 已拉 |
| **CGTH 采购退货** | **−30,361** | ❌ **未拉** |
| QTCK 其他出库 | −27,780 | ✅ 已拉 |
| XSTH 销售退货 | +146 | ❌ 未拉(MES 只有零星 1 单) |
| YCD 租入 | 0 | — |

### 缺口② MES 存在"只出无进"的批次:批号口径不一致(**这是负库存的真正根因**)

以 `YJ-SX-043 \| CK00006` 为例(实测流水):

| 单据 | 批号 | 数量 |
|---|---|---:|
| 采购入库 CGRK-20260901-03107 | `SX-20260901` | +5,000 |
| 采购入库 CGRK-20260902-03122 | `SX-20260902` | +5,000 |
| …共 26 个不同批号… | `SX-…` | … |
| **材料出库 SCLL-20260902-00012** | **`PC0000`** | **−5,000** |
| **材料出库 SCLL-20260903-00007** | **`PC0000`** | **−5,000** |
| … | **`PC0000`** | … |

⇒ 入库落在 `SX-2026090x` 等批号,出库却一律扣 `PC0000` ⇒ **`PC0000` 这一行只出不进,结存 −143,620**;
而同物料同仓的其它批号合计仍有 +8,000。

**kucun 现有 470 行负结存,其中 187 行是 `PC0000`**;按物料合计后只剩 **7 个物料**真的为负。
⇒ 负库存的**大部分不是"缺期初",而是"批号错配"造成的假象**。

### 缺口③ 少量单据时间差

金蝶 9-10 月有、MES 里没有的单号 **235 张**(净额合计 +74,704),多为月末刚发生、尚未同步。

## 六、建议方案(按性价比排序)

### 🔴 前置:先修批号口径,否则期初白导

期初导入解决的是"9/1 之前的账",但 `PC0000` 问题会让**9/1 之后**继续产生负库存。
最小修法(二选一,需业务确认):

- **方案甲(推荐,改动小)**:材料出库不再强制写 `PC0000`,改为**按实际领用批次**扣减
  (`StockLedgerService.applyOut` 已有 `HIST_BACKFILL` 分支,可复用到"按 FIFO 自动选批");
- **方案乙(口径统一)**:让采购入库也统一记 `PC0000`(牺牲批次追溯能力,不推荐)。

### 步骤 1 —— 导入 2026-08-31 期初(核心交付)

```JavaScript
GET /jdy/v2/scm/inventory?page_size=100&point_date=2026-08-31   // 1346 行
```

落库口径(**必须同时写两处,否则启动自检 `结存 == Σ流水` 会报警**):

1. `inh` 插期初行:`src=0` / `rid=NULL` / `单据编号='INIT-20260831'` / `单据类型='期初结存'`
   / `单据日期='1900-01-01'`(哨兵,必须早于一切业务)/ 经手人 `='migration'`
   —— 与既有 `INIT-20261014` 那批期初行**同形**;
2. `kucun` 按 `(wzdm, ckdm, lot_no)` 有则改、无则增,`yl=期初数量`、`rkl=ckl=0`。

⚠ **必须先清理现有的 3 批旧期初**,否则会与新期初双计:

| 现有期初 | 行数 | 数量 | 处置 |
|---|---:|---:|---|
| `INIT-20261003` | 1 | 10 | 删除 |
| `INIT-20261014`(金蝶现存量倒挤) | 1888 | 4,816,716.90 | **删除**,由新期初取代 |
| `JZ-202609` 月结结转 | 2272 | 4,663,357.77 | **删除**后重做月结 |
| `kucun.asp_user1='期初导入'` | 331 | −234,892.26 | 整表重建 |

### 步骤 2 —— 补拉缺口单据(让闭环真正对上)

| 缺口 | 补法 |
|---|---|
| 调拨单 SCTL | `deploy/sync-core.mjs` 增 `TRANSFER` 类型;MES 需建"调拨单"面板(一进一出)或**按单据类型折成两行流水** |
| 采购退货 CGTH | 已有 `bd_purchase_in` 面板,补 `src` 段(出库方向) |
| 销售退货 XSTH | 补拉 |
| 235 张缺失单号 | 重跑同步 |

### 步骤 3 —— 验收标准

```
每键:期初(8/31) + MES 9/1后流水  ==  金蝶 point_date(今天)
```
按 **物料+仓库** 粒度,一致率应从当前 **1189/1586(75%)** 提升到 **100%**;
按 **物料+仓库+批号** 粒度,需批号口径修好后才能达标。
