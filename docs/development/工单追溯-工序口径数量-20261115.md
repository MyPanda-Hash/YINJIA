# 生产工单追溯·完工数据的「工序口径」数量(2026-11-15)

> 用户口径(2026-11-15):「这种对于工序实现的数据应该是选择对应的实现,应该是换算后的数量,
> 因为当前的工单工序存在换算机制。」
> 现场截图:`GD-2026-11-0028` 行1(排产 50、成型换算率 0.5)的追溯弹窗——
> 完工数据 成型 `计划数量 50` / `完成数量 1`,看上去"只做了一点点",而上方的工序进度却是
> 成型 `1/25`(换算后工序口径)。同一个弹窗里两种口径对着摆,用户看到的就是"计划数量不对"。

## 1. 根因(为什么 50 是错的)

| 位置 | 原实现 | 问题 |
|---|---|---|
| 完工数据·`计划数量` | `MAX(scjl.pl_sl)` | `scjl.pl_sl` 是**报工单上的计划数量 = 成品口径**(成型率 0.5 的报工单也写 50),而同一行的 `完成数量` 是 **Σscjl.sl = 工序口径** ⇒ 计划与完成**不是同一个单位**;整单口径下还有 `MAX` 跨行取最大(GD-2026-11-0017 行1 30/行2 715 → 显示 715,实际应为 745) |
| 完工数据·`完成数量` | `SUM(sl)`(不过滤 `wgzt`) | 把**草稿报工**也算成完成;`单据状态` 只要有一条已审就写"已审核" ⇒ 数字含草稿、状态却说已审核(实测 `GD-2026-10-0226-1` 组装:完成 10/已审核,而同弹窗工序进度 0/待审 10) |
| 完工数据·`报工人`/`报工时间` | 两个独立的 `MAX()` | 多张报工单时会显示 **A 的人名 + B 的时间** |
| 工序进度·`产出/未完成合计/进度` | `产出 = 末道已审完工量(工序口径)` ÷ `计划合计(成品口径)` | **同段混口径**:`GD-2026-11-0028` 行3209 表头 2%,而步骤条 成型 1/25 = 4%,差 1/换算率 倍;换算率>1 的道(切炭 3.0)还能算出 >100% |

## 2. 修法(改完的口径)

统一规则:**工序这一级的数据一律是换算后的数量,换算公式只有一条 ——
`工序计划量 = 本行排产数量 × 该道自己的换算率`(各道独立折算、不累乘)**。
这条式子与看板、工序进度、报工封顶(`ProcessTaskService.stepsSummary` / `WorkFlow` 的"折成品"、
`WoReportService` 的报工上限)同源。

1. **`ScheduleBoardService.trace()` 完工数据段**(`fillDonePlanQty`)
   - `计划数量` = 本行排产数量 × 该道换算率;整单口径按**各行分别折算后累加**(每行用自己那行的路线取率),
     ❌ 不是"整单合计 × 一次换算率";路线里查不到该工序按率 1(与 `routeLines` 的兜底一致);
   - 新增 `换算率` 字段(各行/各道率一致才给值,不一致给空串 ⇒ 界面显示 `-`)。
2. **完成/待审拆开**:`完成数量` 只算已审(`wgzt='Y'`)、`待审数量` = 草稿;`单据状态` 三态
   `含草稿 / 已审核 / 草稿` —— 与工序进度"完工量 / 待审量"同源。
3. **报工人+报工时间取同一条**(最近一张报工单,`ROW_NUMBER()` 分区在工序上)。
4. **工序进度段折成品**:`产出 = 末道已审完工量 ÷ 该道换算率`(成品口径)后才与 `计划合计` 比;
   另回 `产出工序口径` 供探针核对。`进度 = 折成品产出 / 排产数量`。
5. **前端** `WorkOrderTraceDialog.vue`:完工数据表新增 `换算率`、`待审数量` 两列;表尾一行口径说明
   (`计划数量 = 排产数量 × 换算率 ｜ 完成数量 = 已审核 ｜ 待审数量 = 草稿`);`单据状态` 值走 `tt()`;
   排产数据段的标题胶囊改读后端 `分段口径`(原来硬写"整单",与按行收敛的数据自相矛盾)。
   10 个语言包补 `待审数量` / `含草稿` 两条译名。

## 3. 为什么**不**读工序台账 `wo_process_line.计划数量`(决策记录,别再改回去)

台账是排产/切单时按同一算式算好的**存量快照**,健康数据与算式逐行相等。但存量里有
**9 行**是历史脏值(旧 bug 串行的成品量,典型 `GD-2026-09-0049` 行1 排产 1100 / 成型台账 **56000**)。
如果完工数据优先读台账,就会出现「完工数据 计划 56000 / 同一弹窗工序进度 1100」的新矛盾
——修一处又造一处。故本段与工序进度**同用算式**;台账脏值订正、以及看板
`planQtyExpr`(当前工序计划量)**仍是台账优先**的收口,属另开的存量任务(见 §5)。

## 6. 同日追加:工单排产看板「需交付 / 未交量」(2026-11-15 第二轮)

用户口径(带 4号车间 `GD-2026-11-0028` 截图):「**需交付**这里原来也应该是**工序计划量**,
而**未交量**应该是当前整个工单剩余的**成品数量**」。

### 6.1 需交付三桶 = 工序计划量(改)

- 位置:`WorkOrderDayPlanService.data()`(生产工单页与工单排产页**共用**这一个接口)。
- 原实现:`7天/15天/大于15天需交付` 取 `RowRef.demand` = **需求数量**(成品口径)。
  实测 `GD-2026-11-0028` 行3209(成型 0.5):需交付 **50** 而 已排 25 ⇒ 同一行两个单位,
  "需交付永远大于已排";1号车间 `GD-2026-11-0012` 更明显:需交付 **5000** / 已排 1900(工序计划量 2500)。
- 现实现:按交期落桶的额度改成 **工序计划量 = 排产数量 × 该道换算率**(= `opCaps`,
  与日计划总额/保存守卫/工序进度同一算式)。同一行变成 需交付 25 / 已排 25(同口径可比)。
  `需求数量`/`排产数量` 字段仍按成品口径原样下发(订单口径列,别改)。
- 表头 tooltip(两页都加):`需交付 = 工序计划量(排产数量 × 该道换算率),按交期落桶;与「已排」三桶同一口径`。

### 6.2 未交量 = 整单剩余成品(不改,只写清)

- 现实现(`scheduled()` / `lineProcessRows()` / `linesSummary()`):`未交量 = 排产数量 − 入库数量`(不足 0 记 0),
  **成品口径、按工单行**;工单行=「工单号+工单行号」即现场说的"当前整个工单" ⇒ 本次样本 50 = 50 − 0 ✓。
- 2026-11-15 复核:全库抽查 8 条产线/19 行,`未交量` 与 `max(排产−入库,0)` **逐行相等**;
  与工序口径无关(报工多少不影响它),这正是用户要的"剩余成品"。
- **未改**;只给看板列加了 tooltip:`未交量 = 排产数量 − 入库数量(成品口径,整单剩余;不折工序)`。
  ⚠ 若日后要的是「需求数量 − 入库」(把未转单部分也算欠),那是另一个口径 —— 现在不是。

## 7. 同日第三轮:两张纸的「数量」也换成工序口径(2026-11-15 第三轮)

用户口径(带两张纸的截图):

### 7.1 成型车间排单计划 —— 「生产计划数量」

- 位置:`frontend/src/business/print-formats.js` 的 `PLAN_SHEET_BASE_COLS`。
- 原来取 `r['排产数量']`(成品口径)⇒ 成型 0.5 的单印 **50**;右邻「实际完成数量」却是工序口径(当前工序完工量)。
- 现取 **`r['当前工序计划量']`**(= 台账该道计划数量 = 排产数量 × 该道换算率;2026-11-15 首版取 `工序计划量`,
  2026-11-18 收口),老接口缺该键时逐级回落 `工序计划量 → 本线排产数量 → 排产数量`。
  同一行 ⇒ 生产计划 25 / 实际完成 0。
  - 🔴 **2026-11-18 为什么要收口到「当前工序」**:`工序计划量` 由日计划接口按 `plang.[当前工序]` 取换算率,
    而看板「当前工序」是台账里**最前面的已落实道**;两者漂移时(实测 GD-2026-11-0032:plang 停在`成型`、
    台账已到`组装装箱`)会打出「计划 240(成型)/ 完成 280(装箱)」这种跨道的纸。
- ⚠「未完成总数」**没改**:仍取 `未交量`(成品口径)= 50 —— 和你要的「未交量=整单剩余成品」一致;
  若这一列也要按工序口径(= 工序计划量 − 已完工),说一声再改。
  - 🔁 **2026-11-18 已按用户新口径改掉**:该列改名「**工序未报工量**」= **当前工序计划量 − 当前工序报工数量**
    (不足 0 记 0),见 `print-formats.js#planSheetUnreportedQty`;原「未完成总数(未交量)」不再印在排单计划上。
    实测 GD-2026-11-0032(4号车间,当前工序=组装装箱 480、已报 280)⇒ 纸面 480 / 280 / **200**,
    与追溯弹窗「未完成合计 200」同数。

### 7.2 打印工单「成型生产任务单」—— 「成型折算后数量」

- 两个打印入口(生产工单页 `WorkOrderList.vue` / 工单排产页 `WorkOrderBoard.vue`)的算法**收口到一个纯函数**
  `print-formats.moldPlanQty(row, detail)`:
  ① 有 `/px/processTask/detail` 的工序步骤 ⇒ `排产数量 × (成型计划量 ÷ 计划合计)`;
  ② 取不到 detail 且当前工序就是成型 ⇒ 用「当前工序计划量」;③ 都没有 ⇒ 退回排产数量(与旧版一致)。
- 原因:工单排产页原来直接印 `排产数量`(成品 50);生产工单页内联算因子、两处各写一套。
  现在两页同一实现 ⇒ 成型 0.5 的行都印 **25**。
