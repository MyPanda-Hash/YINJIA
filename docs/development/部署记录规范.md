# 部署记录规范（Markdown）

> 适用范围：**所有**对服务器执行的部署（增量 `deploy-production.bat GO`、只换 jar `GO APP`、
> 只跑库 `GO DB`、例外路线全量恢复 `deploy-all.bat GO CONFIRM-FULL-REPLACE`）。
> 目的只有一个：**任何人（含未来的 AI 会话）不读聊天记录、不猜，也能确认「服务器现在是哪一版」以及怎么退回去。**

---

## 一、三份文档的分工（不要重复、不要互相替代）

| 文档 | 是什么 | 谁维护 |
|---|---|---|
| `deploy/部署说明.md` | **执行手册**：怎么打包、怎么 CHECK/GO、失败怎么处置、历史实录 §A2~A9 | 部署流程变化时更新 |
| `deploy/部署台账.md` | **事实台账（append-only）**：每次部署的指纹、迁移条数、验收证据、回滚点 | **每次部署必须追加** |
| 本文件 | **书写规范**：字段口径、格式、写入时机、禁止事项 | 规范变化时更新 |

> 结论：`部署台账.md` 是「部署到哪了」的**唯一答案**；本文件只规定「那本台账怎么写」。

## 二、写入时机（三步，缺一不可）

1. **打包完成、尚未上线** → 在台账 §1 追加一行，`结果` 列填 `待执行`，其余按包内容填满
   （包名/指纹/迁移条数/部署前指纹）。**先登记再上线**，避免"部署完忘了记"。
2. **GO 返回终态**（`RESULT: ALL-OK` 或 `RESULT: FAIL-*`）→ **回填**该行的 `部署后` 指纹、
   `台账 前→后`、`面板 前→后`、`结果`、`回滚点`；同时在 §2 追加一节详细记录。
3. **发生回滚** → 不改原行，**另起一行**记录回滚（`类型=回滚`，`部署后` 写回滚到的版本，
   `回滚点` 指向被还原的备份），并在 §2 写明原因。

## 三、必填字段与取值口径

| 字段 | 含义 | 取值口径（必须可独立核对） | 示例 |
|---|---|---|---|
| 部署日 | 实际执行日 | `YYYY-MM-DD`（本地时区） | `2026-11-01` |
| 包 | 部署包 | 目录名 + zip SHA256 **前 8 位** | `pkg-incr-20261101` / `048ae9dc…` |
| 类型 | 做了什么 | `增量（库+jar）` / `仅 jar` / `仅库` / `全量恢复` / `回滚` | `增量（库+jar）` |
| 迁移条数 | 本次实际 `to-run` 条数 | 包内 `to-run.txt` 非注释行数；只换 jar 填 `0` | `65` |
| 部署前（入口 / jar） | 部署前服务器版本 | 入口 chunk 全名 / jar SHA256 前 8 位 | `index-D-F6Ph3B.js` / `d7f0938c…` |
| 部署后（入口 / jar） | 部署后服务器版本 | 同上 | `index-CzB9czVk.js` / `fad130df…` |
| 台账 前→后 | `yj_schema_log` 行数 | `sqlcmd … SELECT COUNT(*) FROM yj_schema_log` | `656 → 721` |
| 面板 前→后 | `yj_panel` 行数 | 同上，换表名 | `146 → 150` |
| 结果 | 终态 | 以日志末行 `RESULT:` 为准，不允许凭印象写 | `ALL-OK` / `FAIL-MIGRATIONS` |
| 回滚点 | 库 + jar | 备份文件**全名**（含时间戳） | `pre-deploy-20261101-220512.bak` |
| 执行人 | 谁做的 | 姓名或账号；AI 代执行写「AI(会话) + 用户确认」 | `vigna12` |

### 「三条指纹」的定义（判定版本的标准方法）

1. **app.jar SHA256** — 代码版本，`certutil -hashfile C:\yinjia\app.jar SHA256`；
2. **前端入口 chunk** — 前端版本（`assets/index-<hash>.js`），登录页源码里就能看到，且**外网可查**
   （`curl http://36.140.66.163:8090/ | findstr index-`），无需登录服务器；
3. **yj_schema_log 行数** — 库版本，判断库与代码是否同步。

> 只报"部署成功了"不算记录；**必须给出可复核的数字或指纹**。

## 四、Markdown 书写规范

1. **台账表头固定**，列序不得调整（脚本/人按列读）；新增信息加列时，必须同时更新本文件 §三。
2. **数字不写约数**：`236` 而不是「两百多」；未知写 `—`，不要留空、不要编。
3. **时间格式统一** `YYYY-MM-DD`（表格内）与 `YYYY-MM-DD HH:mm`（正文叙述）。
4. **指纹一律取前 8 位 + `…`**，完整值放正文的代码块里（表格里塞 64 位会撑爆阅读）。
5. **备份文件名必须完整**（含时间戳），它就是回滚指令里要粘贴的东西。
6. **命令块标语言**：`cmd` / `powershell` / `sql` / `bash`；命令用相对路径或 `C:\yinjia`、
   `C:\yj-deploy` 这类**服务器真实路径**，不要写开发机路径。
7. **文档间用相对链接**（`[部署说明](部署说明.md)`），不写绝对路径、不写 `file:///`。
8. **一节只记一次部署**，标题格式 `### YYYY-MM-DD · <包名>（<一句话主题>）`。
9. 详细记录里允许贴 **≤20 行**的关键输出（如 `RESULT:` 块），**整段日志不入库**，指向日志文件路径即可。

## 五、禁止事项（红线）

- ❌ **禁止改历史行**（台账是 append-only）；写错了另起一行更正，并注明「更正上一行」。
- ❌ **禁止写密码/连接串/AK**：管理员口令、`sa` 密码、金蝶凭证一律不落文档。
- ❌ **禁止把 `deploy/pkg-*`、`.bak`、`app.jar` 提交进仓库**（已在 `.gitignore`；台账只写指纹）。
- ❌ **禁止用「部署完成」代替结果**：必须有 `RESULT:` 值与验收证据。
- ❌ **禁止只写"已执行 N 条"不写剔除项**：凡是**有意剔除**的脚本，必须在详细记录里点名并写理由
  （否则下一个人会以为漏了）。
- ❌ **禁止把"预期值"当"实测值"**：未实际查的格子写 `⚠待回填`，回填后再删标记。

## 六、模板（复制即用）

### 6.1 台账行（§1）

```markdown
| 2 | 2026-11-01 | `pkg-incr-20261101`<br>SHA256 `048ae9dc…` | 增量（库+jar） | 65 | `index-D-F6Ph3B.js` / `d7f0938c…` | `index-CzB9czVk.js` / `fad130df…` | 656 → 721 | 146 → 150 | **ALL-OK** | `C:\yinjia\backup\pre-deploy-20261101-220512.bak` + `app-20261101-220512.jar` |
```

### 6.2 详细记录（§2）

```markdown
### YYYY-MM-DD · <包名>（<一句话主题>）

**背景**：服务器当时停在 <版本指纹>，本次要解决 <问题/需求>。

**包**

| 项 | 值 |
|---|---|
| 包文件 | `<路径>`，<字节> B，`SHA256 <64位>` |
| 包内校验 | `CHECKED=<n> MISSING=0 BAD=0` → `PACKAGE-OK` |
| app.jar | `<64位>`（内嵌前端 `<index-xxx.js>`） |
| 源码基线 | 仓库 HEAD `<commit>` |
| to-run | **<n> 条** = <组成说明> |
| 主动剔除 | `<脚本>`：<理由>（无则写「无」） |
| 打包前闸门 | 演练 `<账套> <x/y 通过>`；字节变更 <n> 条（<脚本>，已过三查） |

**部署方式**：`<路径>` 下 `deploy-production.bat` → `GO`。

**验收证据（实测）**

| 判据 | 期望 | 实测 |
|---|---|---|
| 首页入口 | `<index-xxx.js>` | ✅/❌ |
| 台账 / 面板 / 字段 | a / b / c | ✅/❌ |
| <业务抽查项> | <期望> | ✅/❌ |

**已知偏差（预期内）**：<逐条；无则写「无」>

**回滚**

（此处贴两行 cmd：还原旧 jar + 重启任务计划）
```

## 七、提交前自检（4 条，全过才算完成）

1. 台账新行里 **10 个字段全都不是空的**（未知写 `—` 或 `⚠待回填`）；
2. `结果` 与日志末行 `RESULT:` **逐字一致**；
3. `回滚点` 里的备份文件名在服务器 `C:\yinjia\backup` 下**真实存在**；
4. 详细记录里点名了**所有被剔除的脚本**与**所有预期内偏差**。

> 对应 AGENTS.md「Git 提交规范」：部署记录与部署动作**同一个提交**（`docs:` 或 `db:` 前缀），
> 单任务单提交，不与其它改动混在一起。
