## 一、根因(两条,都在 `frontend/src/core/qc/QcProcInspSheet.vue`)

一张纸由 QC_PROC_INSP(功能)与 QC_ASM_INSP(表观)共用,故一处修两张单同时生效。

### 1. 只读态批次号彻底消失(确定性缺陷)

表头「批次号」格原来只有**可编辑分支**:

```html
<div class="qr-batch-edit">
  <el-input v-if="editable" ... />     <!-- 改名输入框 -->
  <span v-if="editable && batches.length > 1" class="qr-batch-del">×</span>
</div>
```

批号本身只存在这个输入框里(不在每一行重复印,设计见设计契约 §三)。
⇒ `editable=false`(提交审批 / 审核通过 / 归档 / 无编辑权限)时,整列只剩「批次号」三个字,
**批号 `20281117` 在纸面上无处可查**;而 Excel 导出的表头(`qcProcInspExport.js`)却还印着
「批次号：20281117」—— 屏幕与导出两张纸对不上。

实测取证(改前,已审核态):`batchHeads=[{ text:'批次号', hasInput:false }]`。

### 2. 同一张纸四套对齐口径(「各行的格式还不一样」)

| 列 | 录入态 | 只读态 | 行高 |
|---|---|---|---|
| 检验项目 | 居中 | 居中 | 18px |
| 检验方法 / 检验要求 | **左对齐** | **左对齐** | **17px** |
| 批次号列体(录入结果) | **左对齐** | **居中** | 18px / normal |
| 本批结果判断 | 居中 | 居中 | 20px / normal |

⇒ 同一个格「填写时靠左、填写完成后居中」,同一行里各列基线与行高也不一致,
用户看到的就是「各行的格式还不一样」。

## 二、修法

1. **只读态必须印出批号**:批号格改为
   `v-if="editable"` 输入框 / `v-else` `<span class="qr-batch-value">{{ b }}</span>`,
   标签「批次号」在两种状态都保留(与可编辑态同位置、同字号)。
2. **五个数据列一套口径**:`c-item / c-mtd / c-req / c-batchtext / c-result`
   统一 `text-align: center` + `line-height: 18px` + `vertical-align: top`;
   录入态 `.qr-cell-wrap` 的 textarea 与只读态 `.qr-cell-text` 同为中心/18px;
   判定下拉的选中值也居中。顶对齐保留(2026-11-23 定的,免得单行格看着掉到下一行)。
3. **手工换行两种状态都留得住**:textarea(Enter)→ 落库 `\n` → 只读态 `.qr-cell-text`
   `white-space: pre-wrap`;本次只统一行高/对齐,未改换行链路(实测 `\n` 在库里与只读态都在)。
4. 抬头/表尾(客户名/检验人/结论等)保持左对齐 —— 本次只动「检验明细」矩阵。

守卫:`frontend/src/core/qc/qcProcInspSheetLayout.test.js`(5 条钉子:只读批号分支、
批号样式 pre-wrap、五列一套口径、录入/只读同对齐、抬头表尾不动)。
