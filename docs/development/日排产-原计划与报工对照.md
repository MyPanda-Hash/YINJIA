# 日排产「原计划 / 报工」与未完成提示口径（2026-11-13 基线）

> 适用页面：**工单排产**（`WorkOrderBoard.vue` / 页面面板 `WORK_ORDER_BOARD`）与
> **生产工单**（`WorkOrderList.vue` / 页面面板 `WORK_ORDER_LIST`）的**日期列**。
> 改这两页的日期格、顶部汇总，或改后端 `WorkOrderDayPlanService.data` 的 `原计划` 字段之前，先读这里。

## 1. 需求与用户口径（原文）

用户（2026-11-13，附两张截图，红框标在日期列上）：

> 「在这里增加一个原计划量/报工数，当天结束后未完成会进行提示。这种形式，图片中也说明了」

> 「报工后显示在当前位置和原计划量/实际报工量，未达到数量进行提示，
>   未达到计划数量的向后序数量进行处理」

逐项拍板（`ask_user_question`，2026-11-13）：
1. 日期格显示：**一格两数「原计划/报工」**（如 `715/15`），未达计划标红；
2. 未完成提示：**格子标红 + 页面顶部一行红色汇总提示**（「历史未完成 3 处 · 合计欠产 985」，悬停看明细），
   不弹窗、不打断操作；
3. 适用页面：**工单排产 + 生产工单两页都改**（两页共用同一份日排产算法）。

## 2. 两本账：原计划（基线） vs 日计划（剩余）

| 账 | 来源 | 是否扣报工 | 含历史日期 | 用途 |
|---|---|---|---|---|
| **原计划**（2026-11-13 新增） | `DayPlanSpread.merge(工序计划量, 开工日, 交期, 今天, 人工指定)` | **不扣** | **含** | 格内对照 + 历史欠产判定（「那天本来打算做多少」） |
| 日计划（2026-10-31 起） | `DayPlanSpread.mergeReported(工序计划量, 已审报工合计, 开工日, 交期, 今天, 人工指定)` | 扣（剩余量重摊） | 不含（只从今天起） | 今天起还要做多少 / 计划合计 / 7天·15天已排 |
| 日报工 | `scjl` 已审（`wgzt='Y'`），日期 `sc_date → wgsj → asp_time1` 回落 | — | — | 当天实际做多少（含手机端吸收） |

- 原计划是**派生值，不落表**：工序计划量 / 开工日 / 交期 / 人工指定（`wo_day_plan`）任一变化，下次刷新自然变。
- 后端落点：`WorkOrderDayPlanService.data(...)` 每行输出 `原计划`（`日期 → 数量`，日期升序，含历史）。
- 前端落点：`frontend/src/business/dayPlan.js` 的 `dayCellView()` / `historyShortfalls()` / `shortfallTotals()`。

## 3. 格内显示规则（`dayCellView`）

| 情形 | 显示 | 颜色 |
|---|---|---|
| 当天有已审报工 | `原计划/报工`（例 `715/15`） | 绿色（沿用「有实际值」标色） |
| 当天没报工（今天及以后） | 计划（= 日计划，今天起还要做多少） | 深色（沿用） |
| 日期 < 今天、原计划 > 0、一笔没报 | `原计划/0` | **红色**（欠产） |
| 日期 < 今天、报了但 < 原计划 | `原计划/报工` | **红色**（欠产） |
| 日期 < 今天、报工 ≥ 原计划 | `原计划/报工` | 绿色 |
| 后端未升级 / 该日期无原计划 | 退回旧单数显示（有报工显示报工，否则显示计划） | 沿用旧色 |

- **今天不判未完成**（`past = 日期 < 今天`）：当天还没结束，白天的正常进度不标红。
- 格内 tooltip 给出完整口径与欠产量；空格只留编辑提示。
- 列头 tooltip：`格内:原计划/报工;原计划 = 工序计划量按 开工日→交期 均摊(不扣报工、历史也保留);标红 = 当天已结束未达成`。

## 4. 未完成提示（当天结束后）

- **判定**：`日期 < 今天` 且 `报工 < 原计划`（容差 `1e-6`；原计划 ≤ 0 的日子不算，那是没排/已重摊走）。
  欠产 `short = 原计划 − 报工`。
- **格**：标红加粗（`.dp-plan.short`），tooltip 写明 `当天未完成 · 原计划 X · 报工数 Y · 欠产 Z · 未完成量已并入后续日期重排`。
- **页面顶部汇总条**（仅当有欠产时出现）：
  `历史未完成 N 处 · 合计欠产 M` + 灰字 `标红格 = 当天已结束但报工未达原计划(汇总含未显示为列的日期)`；
  悬停显示明细（每行 `工单号#行号 · 日期 · 原计划 X / 报工数 Y · 欠产 Z`，最多 15 行 + `… 共 N 处`）。
- **统计范围**：
  - 工单排产页 = 当前选中产线、当前页签（未完工/已完工/全部）下的明细行；
  - 生产工单页 = 当前筛选后的行集 `filtered`（与「未完工/已完工」页签、产线筛选一致；
    不是滚动渲染的那 50 行），滚动加载时汇总数不跳动。
- **汇总处数可能大于屏幕上的红格数（已知、不是 bug）**：日期列由后端 `buildDates` 按「日计划 /
  已审报工 / 工序台账区间」生成 —— 有些历史欠产日期（典型：老工单没有 `wo_process_line` 台账、
  历史也没报工）**没有对应的日期列**，那些欠产只体现在顶部汇总 + 悬停明细里，屏幕上看不到红格。
  2026-11-13 实测：`2号车间` 汇总 25 处/10235，其中只有 1 处（11-05）落在日期列上。
  若用户要求这些历史日期也出列：在 `buildDates` 里加「原计划窗口（开工日→交期）的过去日期」即可，
  但会复活 2026-10-30 用户报障的「别的行的历史日期也长成一列」问题 ⇒ **先与用户确认再动**。
- **已知口径（不是 bug）**：按**天**比较，不按累计 —— 前一天没做完、第二天补报，前一天仍会显示「未完成」；
  这是用户要的「当天结束后未完成要提示」。若要改成「累计口径（截至某天累计应做 vs 累计已做）」，
  先与用户确认再改。
- 跨工序不可加：不同工序计量单位不同（换算式见 `工单排产看板-本线任务量口径.md` §3.4），
  汇总只在同工序/同车间内看。

## 5. 「未达到计划数量的向后序数量进行处理」怎么落

这句用户口径**已由既有实现覆盖**，本次不新增逻辑，但显示上要能看出来：

1. **本道没报完的量不丢、向后堆**：`DayPlanSpread.mergeReported` 的 `剩余 = 工序计划量 − 已审报工`，
   从今天起重摊到「开工日/今天 → 交期」窗口 ⇒ 历史欠产的量全部压到后续日期，保证后面排得完、且不会
   出现「6000 变 12000」的重复计数（2026-11-05 事故口径，见 `DayPlanSpread.mergeReported` 注释）。
2. **下道工序只认上道实际**：`ProcessFlow` 的「可加工量 = 上一道已审报工（按换算率折到本道）」，
   本道**没做出来的量不会流到下一道**；工单排产/生产工单两个明细表都有
   `上道完工量 / 可加工量 / 待报量 / 待流入量` 四列可直接对照（2026-11-12 上线）。
3. 下道的「计划量」本身不因上道少做而改写（计划是计划、流转是流转），但 `待流入量 = 本工序计划量 − 可加工量`
   会显示缺口 —— 现场据此调整排产或补报。

## 8. 边界与兼容

- **后端未升级**（5173 连旧 8090 的过渡态）：接口没有 `原计划` ⇒ 前端退回单数显示、汇总条不出现，不报错、不造数。
- **开工日为空**：基线按 `DayPlanSpread` 口径从**今天**起摊（与日计划一致），因此该行历史日期没有「原计划」对照，
  历史格只显示报工数（不判欠产）。
- **日期列不在窗口内**：`原计划` 覆盖整段「开工日→交期」，但界面上只渲染后端 `日期` 列；
  汇总条不受列窗口限制（按 `原计划` 全量日期算），确保"没显示出来的那一列"欠产也能提示。
- **老数据 1900-01-01 哨兵**：视同为空（`isOutOfPlanRange` 同口径）。
- **已完工/已结案行**：历史日的欠产仍按事实标红（用于回看），不因整单完工而清零。
