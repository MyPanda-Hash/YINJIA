## 四、四条跨项目注意事项

### 1. 中文数据键:结构性不可移植

239 处 SQL 全是中文表名/字段名。**换库、换项目一行都用不了。**

取舍必须写清楚(依据 [ADR-0001](adr/0001-dictionary-only-translation.md)):

| 换来 | 付出 |
|---|---|
| 业务人员直接读懂数据结构与界面配置 | 跨库不可移植 |
| 界面语言切换不影响数据契约 | 工具链全程防编码事故(PowerShell 组) |
| — | `NCHAR(65533)` best-fit 等 SQL Server 行为坑 |

### 2. 两账套纪律(每个库变更两条)

一切库变更**两个账套都执行**:先 `HSDZ_MES`,后 `HSDZ_MES_TEST`,以 `DbSync` 跑到「执行 0、失败 0」为准。

- 迁移脚本**禁止**无条件 `USE HSDZ_MES;` —— 会打穿测试账套隔离(本仓 98/238 脚本曾如此)。用 `IF DB_NAME() = N'master' USE HSDZ_MES;`
- ⚠ **不能直接删** `USE`:登录默认库是 master,删了会在 master 建表。
- `DbSync` 按内容哈希判断重跑 ⇒ **改动任何 `tools/*.sql` 字节都会触发重跑**。

### 3. `yj_field.place` 是逗号复合值

取值形如 `query,header` / `header,detail` / `query,header,detail`。写单值 `place='header'` 会**漏 282 个字段**(曾一轮误报 15/20 面板)。

### 4. 保留键勿占用

`save()` 把载荷里的 `编号` 当单据标识取走(`body.remove("编号")`)⇒ 同名列表头字段**永远无法落库**。

保留键:`编号` / `单据编号` / `单据状态` / `detail`

## 五、验收方式(每步都得有)

| 步骤 | 验证动作 | 通过判据 |
|---|---|---|
| 注册表 | 注册两个 `supports` 命中的 handler | 抛 `IllegalStateException("面板动作存在多个处理器：…")` |
| 元数据表 | 改一行元数据新增按钮 | 不改代码、重启后按钮出现 |
| 装配器 | 只插 `yj_panel`/`yj_field` 两行 | 新面板在列表页出现 |
| 权限闸门 | 未登记按钮 + 直连 `callButton` 提交缺必填单据 | 服务端拒绝;权限不足回 **200 + body-code 而非 403**(403 会触发前端登出) |
| 生单引擎 | 新增带「批次号」字段的面板,不登记任何名单 | 自动识别为批次目标 |
| 前端视图 | 四个互斥顶层 `v-if` | 消失,由元数据选布局 |
| 多账套 | 切工厂后查 `DB_NAME()` | 随之变化,无需重启 |
