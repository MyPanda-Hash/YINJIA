# 移动端扫码领料(`/m/pick`)

> **日期**:2026-10-20
> **触发**:用户决定放弃小程序的扫码领料(它是**直连数据库写 `outh`**),改用 MES 自己的手机网页领料
> **入口**:http://<主机>:8090/#/m/pick(独立移动页,不套桌面布局)
> **代码**:[MobilePick.vue](frontend/src/views/mobile/MobilePick.vue) · [scanPick.js](frontend/src/business/scanPick.js)

## 1. 为什么要换掉小程序的那条路

小程序的扫码领料直接 `INSERT INTO outh`,只落了「库存流水」这一半:

| 缺什么 | 后果 |
|---|---|
| 没有材料出库单(`bd_/bl_material_out`) | 单据列表/统计/打印/审批全空;**金蝶「生产领料单」推不上去** |
| 不动 `kucun` 结存 | 现存量、批号级可用量、出库闸门都看不见这笔出库 |
| 没有工单键(加工单号+工单行号) | 工单追溯「领料数据」段看不到、`plang.ll_no2` 回写不亮、切单守卫误判 |

改成 MES 自己的页面后走同一条链:**扫工单 → 扫物料 → 填数量 → 生成材料出库单草稿 → 审核 → 写流水**,
库存与单据同时正确(唯一过账入口仍在 `StockLedgerService` / `StockFlowService`)。

## 2. 交互流程

```
① 扫工单码/输入工单号  → 工单卡(工单号·行号 / 产品 / 规格 / 产线 / 排产数量 / 已开领料单)
② 扫物料码/输入物料编码 → 该物料(物料+仓库)可用量
③ 填领用数量           → 立刻显示「按批号日期先进先出」的分配预览(可多行)
④ 加入清单             → 可连续扫多种物料;同一(物料,批号,仓库)自动合并数量
⑤ 生成材料出库单       → 落**草稿**(单据号由后端号池生成),再到材料出库单里审核
```

- 工单行**必须已排产**(`排产数量 > 0`),否则当场拦下并提示先去快速排产;
- 单据头写 **`加工单号` + `工单行号`**,明细写 材料/批号/仓库/仓位/数量 —— 追溯与回写靠这两列。

## 3. 三条业务口径(用户 2026-10-20 明确)

| 口径 | 规则 |
|---|---|
| **批号(先进先出)** | 按**批号里的日期**排序:日期在前先扣;一批不够就扣下一个日期的批次,**生成多条明细**。取不到日期时退化到 `入库日期`,再退化到批号字典序 —— **不猜** |
| **可用量** | 只看 **物料 + 仓库**(同物料多个批次相加),不看批号 |
| **互斥/预占** | 同批号**不互斥、不预占**;真正的拦截在**审核**那一刻(`StockLedgerService.applyOut` 现存量不足直接抛错,整笔回滚) |
| **仓位** | 库存账只有 物料+仓库+批号 三级,**没有仓位**;仓位按**仓库的默认仓位**(`bs_wh_loc.是否默认=1`)带出,仅作单据留痕,不参与扣减 |

> 为什么"仓位随批号变"只做到"仓库随批号变":库存表 `kucun` 里没有仓位列,批次与仓位之间**没有事实数据**;
> 硬造一个映射会把"账"变成"猜"。等库存真正按仓位管理(上架/库位台账)后,再让这条联动落数据。

## 4. 页面规范落地(按仓库里既有的规范)

来源:`docs/design/补充设计-V2.0.md` §4.4(移动端 H5 独立入口)+ `docs/frontend/前端面板设计.md` §10(视觉与可用性)。

| 规范 | 落地 |
|---|---|
| 独立移动入口 | `/m/pick` 是**顶级路由**,不套 `PortalLayout`(无 tab 栏/侧栏) |
| 不横向滚动 | 375×900 实测 `scrollWidth == innerWidth == 375` |
| 命中区 | 输入框/按钮 `min-height: 44px`,吸底按钮 46px |
| 字号 | 输入框 16px(低于 16px iOS 会自动放大) |
| 数量 | 等宽数字、右对齐(`font-variant-numeric: tabular-nums`) |
| 文案 | **全部走 `tt()`**,译名进 [en.js](frontend/src/i18n/locales/en.js);禁止裸中文 |
| 视觉 | 安静、密集、可扫描;无装饰动画、无卡通文案;错误用内联中性文案 + toast |
| 安全区 | 吸底栏 `padding-bottom: env(safe-area-inset-bottom)` |

## 5. 本期"手动输入"的边界

- 摄像头扫码要 **HTTPS 安全上下文**(`getUserMedia` 在 `http://IP:8090` 下不可用),本期先不做;
- 输入框已按「**回车即提交**」设计:USB/蓝牙扫码枪(键盘态)扫完自动回车 = 直接走完整流程,**不用改任何代码**;
- 域名 + 证书上线后,再在页面里加一个「摄像头扫码」按钮(`BarcodeDetector` / `zxing-wasm`),
  扫码结果仍喂给同一个输入框,业务逻辑零改动。

## 7. 已知限制与下一步

1. **摄像头扫码**待 HTTPS 域名(见 §5);
2. **不做预占**:多张草稿同时领同一批次时,谁先审核谁先扣,后审核的会被"现存量不足"拦下 —— 用户口径如此;
3. **批号日期靠批号本身**:批号里没有日期、`入库日期` 又为空时,只能按批号字典序(当前正式库多数批次 `lot_no` 为空,退化路径很常见);
4. **仓位只是单据留痕**,库存按仓位管理后需要再补一段;
5. 未做"按工单行汇总已领数量 vs 排产数量"的超出校验 —— 审核时靠库存闸门兜底,后续可加软提示。
