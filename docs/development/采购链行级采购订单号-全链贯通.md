# 采购链「行级采购订单号」全链贯通（2026-11-13）

> 用户口径（原文）：
> 「从采购订单->送料暂收->来料检验单->退货退料->特采->采购入库，明细行都要带采购订单号
> （不能只有表头有）。值要传递过来。还有考虑一下转erp的时候是通过明细转单号的还是表头。
> 如果表头有多个单号会不会影响转erp」

## 一、每张单上，订单号落在哪一列

| 站点 | 面板 / 表 | 行级订单号列 | 显示名 | 谁写 |
|---|---|---|---|---|
| 采购订单 | `PU_ORDER` / `bl_pu_order` | 本身没有"上游订单号"；`仓库`/`仓位` 同层 | — | — |
| 送料暂收 | `QC_RECV` / `sl_recv_detail` | **采购单号** | 采购单号 | 生单（单张/批量/合单）时按**来源订单号**逐行写 |
| 来料检验 | `QC_INSP` / `qc_insp_detail` | **采购单号** | 采购单号 | 暂收→检验 由链路同义词带入（`FLOW_DETAIL_SYNONYMS 采购单号→采购单号`） |
| 暂收退回（退货退料） | `QC_RETURN` / `qc_return_detail` | **采购单号** | 采购单号 | 检验审核自动生退回行时带（`inspAutoReturn`） |
| 特采 | `QC_TC_IN` / **只有表头** | 表头 **采购单号** | 采购单号 | 退料单勾「特采」审核 → 生特采单时带，**行级优先**（合单后表头可能是多单串） |
| 采购入库 | `PURCHASE_IN` / `bl_purchase_in` | **源单编号**（= 金蝶 `src_bill_no` 同名） | 源单编号 | 检验审核（合格品）/ 特采审核 / 暂收免检直达 三条路都写 |

第二列「采购订单行号」自始至终是**合单前**的订单行号（`行号` → `采购订单行号` 映射），逐站下传。

## 二、合单前后，两种行号别混

- **合单前**：`采购单号`（订单号）+ `采购订单行号`（订单行号）——识别"这行原来属于哪张订单的哪一行"；
- **合单后**：暂收单自己的行 id、`form_flow_link.source_line_key`（`暂收单号#行id`）——占用、按量核销、反查下游一律走它。

## 三、转ERP 走明细还是表头？

**采购入库单：走明细行。** `KingdeePushService` 逐行解析：

1. 行上取 `源单编号`（兼容旧列的 `采购单号`）；取不到才退回表头；
2. 每行按自己的订单号解析 `src_inter_id/src_entry_id`（含「MES 单号 → 金蝶 ERP 单号」兜底），
   这样一张入库单跨多张采购订单时，每行的 `src_bill_no` / `src_seq` 都挂到对的订单上；
3. 表头是多单串（含 `、` 或 `,`）时**显式跳过表头解析**，只逐行挂；单订单的历史单据仍按表头（与改造前一致）。

采购订单、销售出库等其它可转ERP 的单据不涉及"采购订单号"（订单自己就是源头；销售链走销售订单号）。

## 四、表头有多个单号，会影响什么？

| 位置 | 影响 | 处置 |
|---|---|---|
| 转ERP（采购入库） | 无影响：已改为**逐行**取 `源单编号`，并显式忽略多单串表头 | 本轮已改；点击验证见下 |
| **退货回冲额度**（暂收退回 → 订单行「已退回数量」） | 原先按 `qc_return.采购订单号 = 订单号` 等值匹配，合单后表头是"订单1、订单2"⇒ **一条都匹配不上**，退货额度放不回去（可送上限虚低） | 本轮改成**行级 `采购单号` 优先 + 表头兜底** |
| 界面查询（暂收/检验/入库的「采购订单号」查询条） | **无影响**（2026-11-13 点击实测）：查询走 `LIKE %值%` 子串匹配，合并单表头"订单1、订单2"用其中任一订单号都能查到 | 无需改动 |
| 转ERP 的提示文案 | 以前会对多单串报"金蝶账套内未找到采购订单[…]"（误导） | 本轮跳过该提示，改记日志说明"按行级源单编号挂" |

## 六、代码落点

- `PushGenerateHandler`：`rowHasPoNo` + `isOrderSource()`（头一跳写行级采购单号；下游只继承，不覆盖）；
  `generateMerged` 合单同样逐行写。
- `ButtonService`：`inspAutoPurchaseIn`/`inspAutoReturn` 逐行带；`returnAutoSpecialAccept`（特采头）与
  `tcInApprovedGenerate`（特采→入库）行级优先，入库行落 `源单编号`。
- `KingdeePushService`：逐行 `resolveLinePoRef`；表头多单串跳过并记日志。
- `BatchService.returnedByOrderLine`：行级 `采购单号` 优先 + 表头兜底。
