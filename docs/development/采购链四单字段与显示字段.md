## 一、通用口径(四单共用,动字段前必读)

### 1.1 位置(place):决定字段出现在哪、按什么排序

| `place` 取值 | 出现处 | 排序 |
|---|---|---|
| `header` | 单据表单页(表头) | `seq` 升序 |
| `query` | 列表页查询条 **+ 表单页表头(同一字段出现两次)** | `seq` 升序 |
| `header,query` | 表单页表头 + 查询条 | `seq` 升序 |
| `detail` | 明细页签 | `seq` 升序 |
| `query,detail` | 查询条 + 明细列 | `seq` 升序 |

> 🔴 **表单页表头顺序 = `place` 含 `header`,或 `place` 恰为 `query` 的全部字段,合并后按 `seq` 升序。**
> 只按 `header` 算会少一排字段(单号/单据日期/供应商…全在 `query` 位上),这是"顺序对不上"的头号原因;
> 而 `query,detail` 的字段(如 物料编码/条码)**只进查询条与明细,不进表单页表头** —— 这是第二个坑。
> 列表页顶部宽表的明细列顺序 = `place` 含 `detail` 且可见的字段按 `seq` 升序。

### 1.2 排序真源与并列规则

| 优先 | 键 |
|---|---|
| 1 | `yj_field.seq` 升序 |
| 2(并列时) | `yj_field.id` 升序(= 该字段行的登记先后) |

> `seq` 允许并列(四单现有多处并列:`QC_RECV` 单据日期/物料编码、`QC_INSP` 总结论/条码、`QC_RETURN` 单据状态/不良原因、`PURCHASE_IN` 存货编码/单据日期)。
> 并列时后端按 `id` 排,**不是按字段名**。要精确控制顺序,请把 `seq` 写成不重复的值,别依赖并列。

### 1.3 四个显示开关

| 列 | 语义 | 后果 |
|---|---|---|
| `visible` | 是否作为**表格列**出现 | `0` ⇒ 表格不显示该列(明细**表单**里仍可录入) |
| `hidden` | 是否隐藏 | `1` ⇒ 表格与表单都不显示(值仍存、仍参与链路映射) |
| `editable` | 是否可编辑 | `0` ⇒ 只读(生单带下来的字段靠它锁死) |
| `required` | 是否必填 | `1` ⇒ 表单校验拦截保存 |

> 表格列 = `visible=1 且 hidden=0`;明细**表单页签**会额外渲染 `visible=0` 的字段供录入 —— 两处字段集合不同,别混为一谈。
> 另有面板级宽表列合并/隐藏覆盖(PanelxList),但**列名与相对顺序仍以 `seq` 为准**。

### 1.4 字段 vs 显示字段(ADR-0001:数据键永远中文)

| 概念 | 落在哪 | 说明 |
|---|---|---|
| **字段(数据键)** | `yj_field.label` | 也是前后端 API 的 `dataName`;**永远中文、不随语言变**;本文表格里的"字段"列即是它 |
| **物理列** | `yj_field.col_name` | 落库列名,**可与字段名不同**(如字段「单号」↔ 列 `单据编号`) |
| **显示名(译名)** | `yj_translation(scope='field', ref_key=中文标签, locale)` | 切语言后**只换显示名**,字段名与顺序都不变 |

### 1.5 参照字段的显示来源

参照型字段(`dataType=参照`)按 `ref_panel` 的 `ref_field` 匹配,选中后把 `display_field` 回填本字段。逐字段的实际指向见下文各表「参照」列。

WHERE panel_code IN ('SL_RECV', 'QC_INSP', 'QC_RECV')  -- 2026-09-24 补 QC_RECV(...) AND label = N'供应商' AND place LIKE '%header%'
  AND ISNULL(ref_panel, '') <> 'GFDA';
