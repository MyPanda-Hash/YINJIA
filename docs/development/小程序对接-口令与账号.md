# 小程序对接:口令校验与账号口径

> 起因:要做微信小程序(计划用 C/C++ 写),需要复刻账号口令的哈希。
> 结论:**不用自己写哈希函数** —— 服务端用的是公开标准 BCrypt,且代码在本仓库可见,
> 按本文口径实现(或直接调接口)就能对上。

## 1. 结论先行(实测)

| 问题 | 事实 | 证据 |
|---|---|---|
| 口令存哪 | `HSDZ_MES.yj_user.password_hash`(`nvarchar(400)`) | `AuthController.java:45-46` |
| 什么算法 | **BCrypt `$2a$`,cost 10**,60 字符:`$2a$10$<22位盐><31位摘要>` | `MesApplication.java:18-21`(`new BCryptPasswordEncoder()`),库中 4 个账号全部 `$2a$10$`,长度 60 |
| 能不能反推口令 | **不能**。这是单向哈希,不是"加密"(加密=可解密,哈希=不可逆),所以库被拿走也无法还原口令 | 算法性质 |
| 登录怎么校验 | `encoder.matches(明文, 库里哈希)`;哈希里自带盐,无需另存盐列 | `AuthController.java:47` |
| 建号/改密怎么写入 | `encoder.encode(明文)` | `SysAdminController.java:164/175`;种子账号 `MesApplication.java:29-30` |
| 换算法会怎样 | 自己另写一个哈希函数写进库 ⇒ 服务端 `matches()` 认不出 ⇒ **登录必然失败**(除非同时改服务端做双写/多方案兼容) | 由上面两条推出 |

端到端已实测(`tools/archive/_chk-login-bcrypt-interop.cjs`):把《密码哈希口径-BCrypt.md》里的哈希
直接写进 `yj_user`,再用**明文中文口令**走 `POST /api/auth/login` → 200 且返回 token;错口令 → 409
"用户名或密码错误";超 72 字节口令 → 409(不是 500)。

## 2. 三条路线(推荐 A)

| 路线 | 做法 | 代价 | 评价 |
|---|---|---|---|
| **A. 小程序只调接口(推荐)** | 小程序把明文口令 POST 给 `/api/auth/login`,拿 JWT 后续带 `Authorization: Bearer`;哈希永远留在服务端 | 需要网络;要 HTTPS | 不用在 C 里实现密码学,也没有"客户端算哈希"的暴露面。**能用 A 就别用 B** |
| B. C/C++ 实现标准 bcrypt | 照第 3 节清单写/移植,自测向量在《密码哈希口径-BCrypt.md》 | 需要 C→WASM(微信小程序不能直接跑 .c);实现错了就是"永远登录失败" | 只有"必须离线校验口令"时才需要(例如小程序本地缓存了哈希) |
| C. 换成自己的哈希 | 服务端加新列/新方案(Spring 可用 `DelegatingPasswordEncoder` 存 `{id}` 前缀做多方案共存),再迁移历史口令 | 要迁移 4 个账号 + 改登录代码;迁移期要双写 | 不推荐:BCrypt 是行业基线,换自定义哈希通常更弱,还要动已上线系统 |

> 说明:路线 C 的"换算法"是**服务端工作**,不是小程序单方面能做的 —— 单方面换 = 登录不了。

## 3. 若走路线 B:C 实现清单(照这个写才不会跑偏)

1. **算法族**:OpenBSD bcrypt,版本串 `$2a$`;内核是 Blowfish 的变体(`EksBlowfishSetup`,
   magic 常量 `OrpheanBeholderScryDoubt`,64 轮循环)。**别手写 Blowfish 密钥调度**,
   直接移植成熟小实现(OpenBSD `blf.c`/`bcrypt.c`,或 jBCrypt 的 C 移植),它们都是几十行的公开代码。
2. **盐**:就是哈希串的前 29 个字符(`$2a$10$` + 22 字符),编码表是 bcrypt 专用 base64
   `./A-Za-z0-9`(**不是**标准 base64,不含 `+`/`=`)。
3. **口令字节**:
   - 按 **UTF-8** 取字节(不是 UTF-16、不是本地码页)——中文口令的关键;
   - **不追加 NUL**(jBCrypt 系代码对 `$2a$` 会补 `\0`,Spring 不补;补了哈希就完全不同,
     自测向量里有反例值可对照);
   - **超过 72 字节直接判"口令错误"**,不要截断计算(Spring 侧 `hashpw` 抛异常、
     `matches` 返回 false ⇒ 界面表现就是"用户名或密码错误")。
4. **cost**:哈希第 5-6 字符(本项目恒为 `10`),迭代 `2^cost` 轮。
5. **自测**:用《密码哈希口径-BCrypt.md》里的向量表逐条比对(含中文口令与空口令),
   再用"反例表"确认自己没有补 NUL、没有截断。全对 = 口径一致。
6. **落进小程序**:C 代码要编成 WASM 走 `WXWebAssembly`,或把哈希放在云函数(Node.js 生态
   用 `bcryptjs`);小程序主包不能直接执行 `.c`。
7. **不要**把用户口令写进小程序本地存储/日志;校验失败一律同一句提示(不要区分"用户不存在/口令错")。

## 4. 待决策(与代码无关,是产品口径)

1. **小程序用哪套账号?** (a) 直接用 MES 账号 `yj_user`;(b) 只做微信身份(openid/unionid)绑定;
   (c) 两者绑定(首次微信登录后绑 MES 账号)。
2. **遗留 `users` 表怎么处理?** 库里有这张老表:5 行账号,**口令是明文**,且带 `unionid`/`phoneNo`
   等微信字段(`tools/archive/_chk-legacy-users-pwd.cjs` 已盘)。要点:
   - 现 MES 后端**从不读它**(全仓 `grep "FROM users"` 无命中),它属于上一代微信接入的遗留;
   - 明文口令是安全缺陷:**不要再往这张表写口令**。要复用它就得先把它迁进 `yj_user`
     (转成 BCrypt)或直接废弃。

## 5. 安全提醒(与本次对接直接相关)

- 库里的 `password_hash` 是**可离线爆破的**:cost 10 对 6 位数字口令几乎瞬间可破。
  既然是给小程序做账号,建议口令策略加最小长度/复杂度,或把 cost 提到 12。
- 小程序不要"先本地校验再调接口"以外的任何口令缓存;JWT 按现状带在 `Authorization` 头即可。
- 生产走 HTTPS;接口登录失败信息保持"用户名或密码错误"这一句(现系统已是如此)。

## 7. 路线 A 落地指南(已选方向:小程序只调接口)

核心一句:**口令只经 HTTPS 明文提交给登录接口,哈希永远留在服务端;小程序只保管 token。**

### 7.1 四步时序

1. 登录页:用户输入账号口令 → `wx.request` `POST https://<你的域名>/api/auth/login`,body `{ "userName": "...", "password": "..." }`
2. 成功:取 `data.token` 存本地 —— `wx.setStorageSync('mes_token', data.token)`,**不要存口令**
3. 之后每个业务请求带 `header: { Authorization: 'Bearer ' + token }`
4. 收到 **403** 或 token 过期 → 清 token,回登录页重新登录

### 7.2 实测契约(逐字,来自 `_chk-wx-login-contract.cjs`)

| 场景 | HTTP | 响应 |
|---|---|---|
| 登录成功 | 200 | `{"code":200,"message":"success","data":{"token":"<152 字符 JWT>","user":{"userName":"admin","realName":"系统管理员","roleCode":"admin","isAdmin":true,"visiblePanels":["*"],"approvePanels":["*"]}}}` |
| JWT 内容 | — | 头 `{"alg":"HS384"}`;载荷 `{"sub":"admin","iat":…,"exp":…}`;**有效期 24 小时**(`yinjia.jwt.expire-hours: 24`) |
| 未带/失效 token 访问受保护接口 | **403**(不是 401) | body 为空 ⇒ 小程序按 403 判"需重新登录" |
| 参数为空 | 400 | `用户名和密码不能为空` |
| 口令错误 | 409 | `用户名或密码错误`(统一文案,不区分账号是否存在) |
| 超 72 字节口令 | 409 | 同上(服务端按口令错误处理,不会 500) |

**免鉴权接口只有 4 个**:`/api/auth/login`、`/api/base/factory/list`、`/api/locale/list`、`/api/locale/dict`
(`SecurityConfig.java:31-36`);其余 `/api/**` 一律要 `Authorization: Bearer`。
服务端是 **无状态**(`STATELESS`,无 session/cookie),所以小程序不需要处理 cookie。

### 7.3 小程序侧骨架(以及 C/C++ 在这条路里的位置)

先说清一件事:**微信小程序里网络请求只能由 JS 层 `wx.request` 发出**。WASM 没有 socket 能力,
所以"用 C 写小程序"的现实分工是:

```
界面/网络(JS)  ←→  WASM(C/C++ 只做纯计算:数据整理、校验、格式化、编码)
                        │
                        └─ 不碰口令、不碰 token 的加解密
```

登录相关的 JS 骨架(可直接放进 `pages/login/login.js`):

```js
const BASE = 'https://<你的域名>'          // 生产必须 HTTPS + 已备案域名(见 7.4)
Page({
  data: { userName: '', password: '', err: '' },
  onInput(e) { this.setData({ [e.currentTarget.dataset.k]: e.detail.value }) },
  async onLogin() {
    const { userName, password } = this.data
    wx.request({
      url: BASE + '/api/auth/login',
      method: 'POST',
      header: { 'Content-Type': 'application/json' },
      data: { userName, password },
      success: (res) => {
        if (res.statusCode === 200 && res.data.code === 200) {
          wx.setStorageSync('mes_token', res.data.data.token)      // 只存 token,不存口令
          wx.setStorageSync('mes_user', res.data.data.user)
          wx.reLaunch({ url: '/pages/home/home' })
        } else if (res.statusCode === 409) {
          this.setData({ err: '用户名或密码错误' })                 // 统一提示,不区分账号是否存在
        } else {
          this.setData({ err: (res.data && res.data.message) || '登录失败' })
        }
      },
      fail: () => this.setData({ err: '网络异常' }),
    })
  },
})
```

业务请求封装(带 token + 403 兜底):

```js
function api(path, { method = 'GET', data } = {}) {
  const token = wx.getStorageSync('mes_token')
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE + path, method, data,
      header: { 'Content-Type': 'application/json', ...(token ? { Authorization: 'Bearer ' + token } : {}) },
      success: (res) => {
        if (res.statusCode === 403) { wx.removeStorageSync('mes_token'); wx.reLaunch({ url: '/pages/login/login' }); return reject(new Error('未认证')) }
        if (res.statusCode >= 400) return reject(new Error((res.data && res.data.message) || ('HTTP ' + res.statusCode)))
        resolve(res.data.data)
      },
      fail: reject,
    })
  })
}
```

> 如果你原本说的是"**云函数**"(而不是 C++)也可以:小程序 → 云函数(Node.js)→ MES API,
> token 由云函数保管,客户端完全不接触。代价是云函数出网要能到达 MES(公网域名或内网打通)。
> 两条都能走,差别只在 token 存在谁那儿。

### 7.4 上线硬门槛(现在是 HTTP + IP,小程序真机/发布会被拦)

| 项 | 现状 | 要求 |
|---|---|---|
| 协议 | `http://` | 微信 `wx.request` 只允许 **HTTPS**(`wss` 用于 socket) |
| 地址 | `http://36.140.66.163:8090`(IP + 端口) | 合法域名必须是**域名**且**已完成 ICP 备案**,不能用 IP |
| 端口 | 8090 | 微信侧按域名默认端口校验,建议用 Nginx/Caddy 反代 `443 → 8090`,同时把证书挂上 |

开发/联调期可以先绕:微信开发者工具 → 详情 → 本地设置 → 勾选
「不校验合法域名、web-view(业务域名)、TLS 版本以及 HTTPS 证书」。**发布前必须换 HTTPS 域名。**

CORS 不用动:`SecurityConfig.java:44-52` 已放开 `allowedOriginPatterns("*")`,且小程序请求不受浏览器同源限制。

### 7.5 安全清单

- 小程序端**只存 token**,不存明文口令、不存哈希;退出登录即清 token。
- 传输必须 HTTPS —— 现在是明文 HTTP,口令会以明文过网络,联调可以、上线不行。
- 没有 refresh 接口 ⇒ 过期(24h)就重新登录;不要为了自动重登而在本地存口令。
- 共享设备/外勤场景建议调短 `yinjia.jwt.expire-hours`,或加"退出登录"按钮(清 token 即可)。
- `yinjia.jwt.secret` 上线必须用环境变量 `YINJIA_JWT_SECRET` 注入随机值(默认值是占位串,
  知道它就能伪造任意账号的 token)。已实测默认串长度为 64 字节 ⇒ 算法为 HS384。
