## 1. 命名规范

### 1.1 表

| 前缀 | 含义 | 归属 | 建表要求 |
|---|---|---|---|
| `yj_` | 面板引擎元数据与运行时 | 系统 | 只由引擎读写,业务代码禁止直连 |
| `bs_` | 基础档案(主数据) | 基础设置 | 必须走单单据结构(`archive`),保存全量提交 |
| `bd_` / `bl_` | 业务单据**头表**/**行表**(成对) | 订单/生产/仓库 | 齐备 `asp_user1/2` + `asp_time1/2`;删除=软删 |
| `rd_` | 研发管理单据 | 研发管理 | `*_head` + `*_detail` 成对 |
| `qc_` | 品质管理单据 | 品质管理 | 头行成对 |
| `wo_` | 生产执行(工单/报工/进度) | 生产管理 | 头行成对 |

**硬规矩**

1. 新表**只用上表前缀**;`^[a-z]{2}_[a-z0-9_]+$`,全小写,单词用 `_` 分隔。
2. **禁止新增拼音缩写表**(如 `gxgs`/`plang`/`scjl`/`kucun`)——2026-09-28 前建的进冻结登记,之后禁止。
3. 单据必须 `bd_` 头 + `bl_` 行成对(或 `*_head`/`*_detail`),禁止单表承载头行。
4. **禁止** `RENAME_*` / `*_bak_*` / `tmp_*` / `t1` / `t2` 命名;备份走 `BACKUP DATABASE`,不留在业务库里(现存 65 张见 §7 阶段 1)。
5. 视图统一 `v_` 前缀(现存 103 个里大量 `VIEW_*`/`View_*` 为遗留,冻结不改名)。

### 1.2 列

| 规则 | 说明 |
|---|---|
| **列名 = 中文标签** | 现状口径:`yj_field.col_name` 与 `yj_field.label` 一一对应,数据键是中文(`dataName` 永不翻译,ADR-0001) |
| **禁 `.`** | SQL 会解析成"表.列"→ 语法错误 |
| **禁首尾空格** | 实测存在 `bd_sale_out.[ivc_status ]`(尾部空格),SQL 里必须写成 `t.[ivc_status ]` |
| **`%` `/` `( )` 冻结** | 存量 69 处(`税率%`/`产量/小时`/`工作时间（小时）`/`流速（L/min)样品3` 全半角混用)已登记冻结;**新列禁止**;引用一律 `t.[列名]` |
| **同一物理列只准一个中文标签** | 一个列挂两个标签 = 两个数据键映射一个物理列,保存时互相覆盖(现存 104 组,见 §7 阶段 3) |
| **英文/拼音列名必须写中文注明** | 中文列名本身就是语义,可豁免;`id`/`asp_*` 由规范统一约定,豁免 |

### 1.3 索引与约束命名

`ix_<表>_<列>` / `uq_<表>_<列>` / `ck_<表>_<语义>` / `df_<表>_<列>`;主键 `pk_<表>`。
(存量索引名多为系统生成 `PK__yj_field__3213E83F…`,新建索引按上述命名,存量不强制改名。)

## 2. 结构规范

### 2.1 必备列

| 列 | 类型 | 说明 |
|---|---|---|
| 主键 | `bigint identity`(或业务键唯一索引) | **每张表必须有**;当前 51 张无主键的全是备份表 |
| `asp_user1` / `asp_time1` | `nvarchar(50)` / `datetime2` | 创建人/创建时间 |
| `asp_user2` / `asp_time2` | 同上 | 最后修改人/时间 |
| `asp_cancel` | **`nvarchar(1)`** 取值 `'Y'`/`'N'` | 软删标志;**当前 4 种物理定义并存**(char(1) 274 / varchar(1) 31 / nvarchar(2) 118 / nvarchar(4) 20)——新表一律 `nvarchar(1)`,存量见 §7 阶段 3 |

### 2.2 类型口径

| 语义 | 允许 | 禁止 | 现存问题 |
|---|---|---|---|
| 文本 | `nvarchar(n)` | `char` / `varchar` | char 340 列、varchar 103 列(遗留为主) |
| 状态标志 | `nvarchar(1)` 或 `bit` | `char(1/2)` | `yj_doc_status` 9 个 char(1) 标志 |
| 日期时间 | `datetime2` | `datetime` | 旧 `datetime` 343 列 |
| 数量 | `decimal(18,4)` | `float` | float 1012 列(`bl_dispatch` 4 + `scjl` 1 是数量/金额语义) |
| 金额 | `decimal(18,2)` | `float` / `money` | — |

**定长列的坑**(踩坑台账 D1):`char(n)` 右补空格,`'T'.equals(state)` 永假。存量定长列比较一律 `RTRIM`,新列禁 `char`。

### 2.3 默认值与"影子真源"

- **禁止**把业务状态写成固定默认值:`单据状态 DEFAULT N'草稿'`、`状态 DEFAULT N'启用'`。
  现状:**65 张表**这么写(其中 16 张 `bd_`/`bl_` 单据表),与 `yj_doc_status` 并存 = **两个真源**;
  踩坑台账 D8 的"文档编号被给固定默认值 ⇒ 该面板只能存一张单"就是这一类的后果。
- 合法默认值:审计列(`asp_cancel='N'`、`asp_time1=getdate()`)、计数列(`0`)、单据编号(前缀 + 号池,不用 DEFAULT)。

### 2.4 索引策略(不盲加)

- 业务表当前最大 3.5 万行,且查询以 `LIKE '%x%'` 模糊匹配为主 —— **模糊匹配用不上索引**,因此**不搞"每列都加索引"**。
- 硬规矩:**≥10 万行**的表必须有主键之外的非聚集索引(体检 11 号项);新增大表或新增**等值过滤**列时,在迁移脚本里一并评估并登记理由。
- 反例参考:`tools/migrate-stock-report-perf.sql`(视图层聚合才是性能瓶颈,不是列索引)。

## 3. 元数据规范(`yj_panel` / `yj_field`)

加面板/字段 = **插行不改代码**(§代码规范 B1)。因此元数据本身就是"生产数据",必须当代码管。

| 规则 | 判定 | 现状 |
|---|---|---|
| 字段必须在目标对象里真实存在 | `col_name` ∈ `line_table`/`head_table`(含视图)的列 | 漂移 71 个 → **0**(2026-09-28 清理) |
| 面板指向的对象必须存在 | `OBJECT_ID(line_table)` / `OBJECT_ID(head_table)` 非空 | 3 个 → **0** |
| 同一面板同列同 place 同 seq 只准一行 | 完全重复行 | 1 → **0** |
| 同一物理列只准一个中文标签 | 同面板同 `col_name` 的行 `place` 不得不同(数据键唯一) | 104 组(冻结登记,阶段 3 收敛) |
| `place` 取值收口 | `detail` / `header` / `query` / `query,header` / `query,detail` / `header,detail` / `query,header,detail` | 已符合 |
| 面板 `mode` 取值收口 | `doc` / `archive` / `flat` | 已符合 |
| 新面板/新字段必须有 `en` 译名 | `yj_translation(scope='panel'/'field', locale='en')` | 缺 73 面板 + 1273 字段标签(阶段 2) |

**新增单据面板的固定顺序**:`yj_panel` 插行 → `yj_field` 登记 → `yj_translation` 译名(至少 en)
→ `yj_role_panel` 授权 → 前端 `business/menus.js` 菜单 → 迁移脚本进链 → 两账套执行。

`line_table` 对报表/明细类面板可以指向**视图**(现存 29 个面板如此);视图必须能被 `sp_refreshview` 编译通过,
且改动视图后必须重新登记字段(从 `sys.columns` 自动发现,禁止手工硬编码列名)。

### 3.1 动态字段(备用列池,2026-09-28 起)

业务表预置 `备用1..20`(nvarchar(500) NULL)承载管理员自定义字段,设计真源
`docs/design/动态字段扩展-备用列池-V1.0.md`。本规范的硬口径:

| 规则 | 说明 |
|---|---|
| 一列一标签 | 一个备用列同一时刻只绑一个标签(体检 08 口径;占用=该表该列被**任一面板**的 `yj_field` 引用) |
| **永不 DROP** | 退绑=删 `yj_field` 行,物理列与数据永不动;全系统唯一写业务数据的动作是换绑脏列时的显式清空(G4,需确认) |
| 绑定即注明 | 绑定时 `MS_Description` 更新为 `<标签>(动态字段,绑定<备用N>)`;退绑改 `预留(已停用:原<标签>)` |
| 标签守卫 | 禁 `.` `%` `/` `(` `)` 与空格(§1.2 列名安全同源);面板内唯一;≤60 字符 |
| 类型边界 | 仅 文本/下拉框/日期(ISO 文本,排序正确)/是否;**数值型走正式迁移加物理 decimal 列**(文本排序 `9`>`10`、不进度量列合计) |
| 审计 | 全部 bind/retire/clear 落 `yj_ext_bind_log`(append-only) |
| 权限 | 仅 `is_admin='Y'`(服务端 `requireAdmin` 真闸门;前端入口对非 admin 隐藏) |
| 运行时定位 | 绑定/退绑是运行时元数据(同 saveColumnPrefs 先例),不生成链上脚本;池耗尽走迁移脚本扩池(重跑 `migrate-spare-columns.sql` 同款生成口径) |
| 覆盖范围 | **在册业务表全覆盖**(2026-09-29 起):`migrate-spare-columns.sql`(139 表,前缀+面板引用口径) + `migrate-spare-columns-biz.sql`(45 表,在册业务表补口);`yj_*` 引擎元数据表**不加**(结构由代码与迁移脚本固定)。台账见 [数据库表清单](数据库表清单.md) §0.1 |
| ⚠ 扩展属性谓词 | 查「列级 `MS_Description` 是否已存在」**必须带 `ep.class = 1`**:`sys.extended_properties` 按 class 混装(class 1=列级 / 7=索引级),`major_id` 都是 object_id、`minor_id` 分别放 column_id / **index_id** —— 漏 class 时,只要某索引的 `index_id` 撞上备用列的 `column_id`,就会误判"已有注明"而静默漏写(2026-09-29 实测 `kucun.备用1` 中招,补漏脚本 `migrate-spare-desc-fix.sql`) |

## 4. 变更流程

1. **一切库变更走迁移脚本**:禁止 SSMS 手工改库(踩坑台账多次记录"手工改库未入链"导致的碎片:`migrate-restore-gfda.sql` 就是为修一次手工改库事故写的)。
   **已知例外(已批准,勿再重复争论)**:① 列自定义 `saveColumnPrefs`(运行时 UPDATE `yj_field`);
   ② 动态字段绑定/退绑(`POST /px/extField/*`,运行时 INSERT/DELETE `yj_field` + 更新备用列 `MS_Description`)。
   二者属**运行时元数据写入**,由服务端守卫与审计日志(`yj_ext_bind_log`)约束,不进迁移链;
   但**接口与字段仍须完全遵守 §1.2 列名、§2.2 类型、§3 元数据规范,并通过 §6 体检** ——
   详见 `docs/design/动态字段扩展-备用列池-V1.0.md` §3.1(并附"新增对象无过渡期"的逐条自检表)。
2. **脚本必须幂等**:`IF COL_LENGTH(...) IS NULL` / `IF NOT EXISTS` / `DELETE + INSERT`,可重跑。
3. **写进 `tools/db-migrations.txt`**(唯一权威顺序);清单与 `tools/*.sql` **必须一一对应**:
   - 工具类脚本(备份/清理/部署导出)不进链 —— 现有 **13** 个,清单见体检工具 12 号项的 `allowOffChain`;
     其中一类是**手动回滚/撤回工具**(如 `migrate-wo-process-line-drop.sql`):**有意不进链 —— 一登记
     `DbSync` 就会执行它**。该例原委:2026-10-06 按「不应该预排产」DROP 了 `wo_process_line`,
     2026-10-07 又以「排产时人工逐道选线」的口径**恢复**了该表(`migrate-wo-process-line.sql` 头部
     写明「该脚本不在迁移链里,手动执行」)⇒ 登记它就等于把线上正在用的表删掉。**再遇到这种
     "撤回脚本 + 后来恢复" 的配对,一律加白名单,不要登记**;
   - 一次性**种子/数据脚本不应留在链上**(现存 17 个,如 `_bs_part3_data.sql`/`_doc_part3_data.sql`/`_so_data.sql`)——它们内容一变就被 `DbSync` 重跑,**重跑即重复灌数据**(踩坑台账 D15)。
4. **两个账套都要执行**:先正式 `HSDZ_MES`、后测试 `HSDZ_MES_TEST`;脚本开头用守卫 `IF DB_NAME() = N'master' USE HSDZ_MES;`(**禁止**无条件 `USE`,会把会话切库且不报错)。
5. **执行后必须收口**:`DbSync sync` 跑到「**执行 0、失败 0**」;「已应用但没登记」用 `DbSync baseline`(只登记不执行)。
6. **建表/改表后刷新文档**:`数据库表清单.md`(生成命令见该文末尾)+ 本文档 §7 的目标值。
7. **新增表必须写 `MS_Description`**(表级 100%),关键列(主键/金额/数量/状态/日期/业务单号)与实际为英文名的列必须有列级注明。

## 5. 冻结与豁免登记(`tools/db-legacy-whitelist.txt`)

四类登记(每行一条,`#` 注释):

| 前缀 | 语义 | 体检影响 |
|---|---|---|
| `table:<表名>` | 遗留/拼音表:**禁新增、禁扩展、禁新代码引用**;现有面板引用豁免 | 202 张不计入命名/注明/必备列违规 |
| `panel:<面板码>` | 已下线面板:实体表已不存在,**行保留**(前端配置与回滚需要) | 不计入漂移与对象缺失违规 |
| `col:<表>.<列>` | 特殊字符列名**冻结**:SQL 必须 `t.[列名]`;**新列禁止同类命名** | 备查登记(冻结清单;**暂无自动判定项**) |
| `dupkey:<面板>.<列>` | 同一物理列多标签(数据键不唯一)**待收敛登记** | 告警不阻断 |
| `skiplabel:<中文标签>` | **免译标签**:标签本身即英文/单位/编号(如 `TDS（mg/L）200-500mg/L`、`P-E/kg`、`delivery_type_id`、`asp_cancel`),机翻无意义 | 不计入 09 项 |
| `count:<检查号>=<n>` | **存量债棘轮基线**:实际值只许降不许升 | 等于基线 = WARN,超过 = FAIL,为 0 = PASS |

**它是"冻结登记",不是"许可清单"**:新表**不得**再往 `table:` 里加(除非确属遗留接管);
`col:` 同理 —— 那里列的每一个都是技术债,不是榜样。

重新生成(仅在需要重建快照时):`sqlcmd -S localhost -E -d HSDZ_MES -I -f 65001 -i tools\gen\gen-legacy-whitelist.sql -h -1 -W -u -o %TEMP%\_wl.txt`
(输出为数据行;头部注释与分段由人工维护,勿整文件覆盖。)

## 6. 自动化防线(提交前必跑)

```powershell
cd tools
$env:YINJIA_SQL_PASS='<库口令>'                       # 工具不内置口令(规范:密码不入库)
java -cp lib\mssql-jdbc.jar verify/DbNormAudit.java   # 正式账套 HSDZ_MES
$env:YINJIA_SQL_DB='HSDZ_MES_TEST'; java -cp lib\mssql-jdbc.jar verify/DbNormAudit.java
```

> 体检项 12 依赖 `db-migrations.txt` 与 `tools/*.sql` 的对应关系,因此**必须在 `tools` 目录下运行**
> (与 `DbSync` 同口径);口令也可用 `tools/SqlRunner.java` 那套 `env` 约定统一注入。

| # | 检查 | 级别 | 判定 |
|---|---|---|---|
| 01 | 表命名合规(白名单外) | **FAIL** | 白名单外的表必须用 §1.1 前缀 |
| 02 | 表级中文注明 | **FAIL** | 白名单外每张表必须有 `MS_Description` |
| 03 | 拼音/英文列名的列注明 | 棘轮 | **基线 0(已归零)**;新增无注明列立即 FAIL |
| 04 | 业务表主键与审计四件套 | **FAIL** | `bd_/bl_/bs_/rd_/qc_/wo_` 表必须有主键 + 4 审计列 |
| 05 | 元数据漂移(字段不在**其所在对象**里) | **FAIL** | 按 `place` 判:`header`→头表、`detail`→行表、仅 `query`→头行任一(明细面板只 FROM line_table,那里缺列 = 打开即 500);必须为 0 |
| 06 | 面板指向不存在的表/视图 | **FAIL** | 必须为 0 |
| 07 | 完全重复的字段登记行 | **FAIL** | 必须为 0 |
| 08 | 同一列多标签(数据键不唯一) | 登记豁免 | 未登记的组必须为 0 |
| 09 | 缺 en 译名(面板 + 字段标签) | 棘轮 | **基线 0(已归零)**;免译标签登记见 §5 |
| 10 | 备份/临时表 | 棘轮 | 基线 65,目标 0 |
| 11 | ≥10 万行且无非聚集索引的表 | **FAIL** | 必须为 0 |
| 12 | 迁移链清单 ↔ 文件一致 | **FAIL** | 未登记脚本 / 清单缺文件均为 0 |
| 13 | 面板引用对象缺 `pk_col` / `asp_cancel` | **FAIL** | 引擎统一拼 `SELECT t.<pk_col> … WHERE ISNULL(t.asp_cancel,'N')<>'Y'`,缺任一即该面板打开 500;必须为 0 |

**输出约定**:`[PASS]` / `[WARN]`(收敛指标)/ `[FAIL]`(阻断);末行 `RESULT: PASS` 或 `RESULT: FAIL-n`(**FAIL 非 0 时退出码 1**,可直接用于提交前钩子与 CI)。

**为什么分级**:仓库原则是"能靠工具守住的,不靠自觉;新代码红线优先于历史代码"([代码规范与防臃肿](代码规范与防臃肿.md) 开篇)。
因此**新增对象**一律 FAIL 级;**存量债**用棘轮(WARN + 只许降),既不让工具永远红灯,也不允许它悄悄变坏。

## 8. 违规速查

| 症状 | 根因 | 处置 |
|---|---|---|
| 面板打开报 500「列名/对象名无效」 | `yj_field` 漂移或面板指向的对象不存在 | 体检 05/06 → 修 `col_name` 或重建视图/表 |
| 明细列取值永远为空、保存静默丢值 | 配置里写了 `col_name`,而数据键必须是 `label`(踩坑台账 §F) | 配置改 label;显示差异用 `yj_field.alias` |
| 同一列在界面出现两次、保存互相覆盖 | 同列多标签(数据键不唯一) | 体检 08 → 收敛为一列一标签 |
| 某面板只能存一张单 | 该列被 `DEFAULT` 给了固定值,又挂了唯一性校验(踩坑台账 D8) | 去掉固定默认值(DEFAULT 约束) |
| `DbSync` 报 `[缺失]` 后整链中止 | 清单里有指向不存在文件的条目 | 体检 12 → 补脚本或删除条目 |
| 脚本改了字节就被重跑、数据翻倍 | `DbSync` 按内容哈希判重(踩坑台账 D15) | 一次性种子脚本移出主链;重跑前先看脚本是否幂等 |
| 测试账套改了东西正式账套看不见(或反之) | 元数据/译名缓存按账套隔离已修;仍异常则查是否真的改在不同库 | 一次只问一个账套,或直接查库 |
