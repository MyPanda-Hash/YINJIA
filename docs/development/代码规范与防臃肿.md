# 代码规范与防臃肿(YINJIA-MES)

> 目标:功能持续增加时**不产生**「堆叠复制粘贴、大文件、改一处坏三处、新旧两套并存」的屎山。
> 原则:**能靠工具自动守住的,不靠自觉**;新代码红线优先于历史代码(存量问题进技术债清单逐步清理)。

## A. 分层与边界(强制,自动检测)

| 守则 | 内容 | 防线 |
|---|---|---|
| A1 frontend core 层边界 | `frontend/src/core/**`(面板引擎)禁止 import `business/**` / `views/**` / `stores/**`;通用能力只进 core 或独立 composable | `tools/architecture-audit.mjs` 脚本(light-mes 同款,提交前跑) |
| A2 后端分层 | Controller 只做参数校验与转发;**业务逻辑一律在 service**;SQL 只在 service 内(JdbcTemplate),禁止 controller 拼 SQL、禁止在 Controller 里写业务规则 | 代码评审 + `mvn package` |
| A3 单向依赖 | 面板引擎(panel 包/PanelxList 等)不反向依赖业务(报表/生单/参照业务逻辑通过 `PanelActionHandler`/engine 注入) | architecture-audit |
| A4 响应契约 | 新接口统一 `ApiResult{code,message,data}`;错误用 GlobalExceptionHandler 归一(400/409 HTTP、403/429/503 body-code),禁止自造异常格式 | 评审 |

## B. 契约与数据驱动(防"改需求改到代码")

| 守则 | 内容 |
|---|---|
| B1 加面板/字段=插行不改代码 | 只改 `yj_panel/yj_field`(元数据)+ 幂等迁移脚本进 `db-migrations.txt`;前端/后端**零改动**;若"加面板要改代码"说明违反数据驱动,必须重构回元数据 |
| B2 数据键永远中文 | `dataName/buttonName/单据状态` 存储值不翻译、不缩写(ADR-0001);迁移时严禁改成英文键 |
| B3 px 契约冻结 | `getPanelConfig/getPermMatrix/.../saveColumnPrefs` 等运行时接口变更 = 契约变更,必须同步 `docs/` 与 CHENGXIAO 资产库,并给兼容期 |

## C. 文件与代码组织(防大文件/职责混乱)

| 守则 | 阈值 |
|---|---|
| C1 组件红线 | Vue 组件 ≥ **1200 行**必须拆分(弹窗/子组件/组合式函数抽出);service/controller ≥ **800 行**必须拆领域 |
| C2 单一职责 | 一个 service 一个领域;`*Service` 不允许"什么都能干";通用能力进 core(前端)/公共包(后端) |
| C3 命名一致 | 组件名=文件名;后端类名=职责;`yj_field.label`(中文键)与 `col_name`(列名)一一对应,新增字段同时进两端 |
| C4 弹窗/流程复用 | 参照 RefPickDialog、导入 ImportDialog、审批历史、列调整等**只允许使用已有通用弹窗**,禁止业务组件内再造 |

## D. 反复制粘贴(技术债主要来源)

| 守则 | 内容 |
|---|---|
| D1 三次法则 | 同一逻辑出现 **3 处** → 抽公共(工具函数/composable/Service 方法);新逻辑先查 `CHENGXIAO` 与两项目已有实现再写 |
| D2 禁止平行实现 | 生单/占用/列自定义/参照/翻译等**已有系统级实现**,业务方不得再写一套(选型差异见 CHENGXIAO 09) |
| D3 状态/权限判断 | 单据状态判断只用 `docStatus`/`doc-status.js` 统一判据;权限只用 `panelPerms`/注册表,禁止散落硬编码 |

## E. 可维护性与清理

| 守则 | 内容 |
|---|---|
| E1 无死代码 | 删除功能 = 代码 + 相关表/菜单/翻译**一并清理**(或标注 `@Deprecated` + 迁移脚本),不留僵尸分支 |
| E2 库变更留脚本 | 禁止手工改库(SSMS 直接改);一律写幂等迁移脚本进清单并执行验证 |
| E3 技术债台账 | 存量问题(如 PanelxList 3900 行、历史硬编码文案)记入 `docs/development/技术债清单.md`,每完成一个大版本清理一批;新代码不新增债 |

## F. 自动化防线(提交前必须全绿)

| 脚本 | 作用 |
|---|---|
| 前端 `npm run build` | 语法/打包通过 |
| 后端 `mvn -DskipTests package` | 编译/打包通过 |
| `tools/verify-api.ps1` | 登录→配置→查询→保存→审核→审批→删除 全链路 |
| `tools/audit-panels.ps1` + `audit-conditions.ps1` | 76 面板配置/查询/condition 冒烟(元数据改动后必跑) |
| `tools/architecture-audit`(移植) | core 层依赖边界 |
| `git grep` 敏感词 | 无 AK/密码入库 |
| 多语言走查 | 切 en 后新页面无中文残留(AGENTS.md 多语言规范) |

## G. 演进守则

- 新功能先查 `CHENGXIAO`(通用能力)与两项目已有实现 → 有则复用/增强,无则新增并回写资产库(新增通用能力=向 CHENGXIAO 提交一个 commit)
- 每完成 5 个功能做一次「重复代码/大文件/死代码」扫描(对照本文 C/D/E),结果记入技术债清单

## 检查清单(每次任务收尾 30 秒)

- [ ] 本次改动没碰 core 层依赖边界 / 没在 Controller 写业务
- [ ] 新增面板/字段没改前后端代码(只插元数据+迁移脚本)
- [ ] 新逻辑查过 CHENGXIAO/已有实现,没有平行造轮子
- [ ] 无复制粘贴(出现 3 处逻辑已抽取)
- [ ] 没超文件红线(C1);新文件职责单一
- [ ] 删除的功能代码/表/词条已同步清理(或标注废弃)
- [ ] 库改动有幂等脚本 + 已执行验证
- [ ] 按 Git 提交规范独立提交(单任务单提交)
- [ ] build/审计脚本/多语言走查通过(按 F)
