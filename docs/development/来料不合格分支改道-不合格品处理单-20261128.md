# 来料不合格分支改道：特采单 → 不合格品处理单(来料)（2026-11-28）

> **一句话**：来料不合格不再「退料单勾特采 → 特采单」，而是
> **检验数据记录判「不合格」→ 审批通过自动生成「不合格品处理单(来料)」→ 两级审批通过回填来料检验单明细「特采」
> → 检验单审核按特采分流（是=让步接收进采购入库／否=暂收退料退回供应商）**。

| 后端 | `ButtonService`（`inspRecNgGenerate` / `inspAutoSpecialIn` / `inspRouteDefects` / `tcInApprovedGenerate` 重写）、`QcFlowService`、`FlowBoardService` |
| 前端 | `menus.js`、`docSheetConfigs.js`、`QcInspRecSheet.vue`、`qcFlow.js`、`QcFlowMonitor.vue`、`flowSpec.js`、`i18n/locales/en.js` |

## 一、用户口径（原文）

1. 「先将特采单改为不合格品处理单（来料），放在品质的来料检验里面。」
2. 「现在流程不需要经过退料单了，取消暂收单的特采字段。」
3. 「检验数据记录里面的检验结论选择不合格，审批通过后自动生成和进入不合格处理单，并且检验结论处可以链接进入不合格处理单。」
4. 「进入不合格处理单（来料）都不变。审批通过后，在来料检验单会回填一个特采字段，
   通过这个特采字段，可以判断不合格数量是采购入库还是暂收退料。」
5. （追问：特采是/否 由什么决定）「只要不合格处理单审批通过就回填特采，没用就默认不特采就行」
6. （追问：特采字段放哪）「来料检验单明细行」

## 二、链路对照

```
旧(2026-10-04 ~ 2026-11-27)                       新(2026-11-28 起)
─────────────────────────────────────────────    ─────────────────────────────────────────────
送料暂收单 → 来料检验单 → 合格数量 → 采购入库单    送料暂收单 → 来料检验单 → 合格数量 → 采购入库单
                      └ 不合格数量 → 暂收退回单              ├ 检验数据记录(结论=不合格)
                          └ 退料行勾「特采」                     └─审批通过→ 不合格品处理单(来料) 草稿
                              └ 退料单审批通过 → 特采单            └─两级审批通过→ 回填检验行 特采=1
                                  └ 特采单二级批准 → 采购入库单         └ 检验单审核按特采分流：
                                                                        特采=1 → 采购入库(让步接收)
                                                                        特采=0 → 暂收退回单(退回供应商)
```

**退料单退出中间环节**：它现在只承接「不特采」的那部分不合格数量（发票口径仍转 ERP 采购退货）。

## 三、改了什么

### 3.1 数据库（`migrate-qc-ng-disposal-20261128.sql`，两账套已跑）

| 对象 | 变更 |
|---|---|
| `yj_panel.QC_TC_IN` | `panel_name` 特采单 → **不合格品处理单(来料)**；`module_group` → 品质管理；补 `panel_name_en` |
| `yj_field` QC_INSP | **恢复明细「特采」字段**（是否/只读，seq=105 紧跟不合格数量）。物理列 `qc_insp_detail.特采 bit` 是 2026-09-22~10-04 那代留下的，本次不动 DDL |
| `yj_field` QC_RETURN | **删除明细「特采」字段**（旧发起口下线）；物理列保留留档，并把列注明改成「已停用」 |
| `qc_insp_rec` | 新增 `不合格品处理单号 nvarchar(200)` + 隐藏字段行（seq=149）+ 列中文注明 |
| `yj_translation` | 面板译名键跟着改名（各语言逐 locale 迁移，en 重写为 `Incoming Nonconforming Disposal`）；新增字段译名 `不合格品处理单号` |
| 列注明 | `qc_insp_detail.特采` / `qc_return_detail.特采` / `bl_purchase_in.特采` 三处旧口径注明一并刷新 |

### 3.2 后端生单与联动（`ButtonService`）

| 方法 | 时机 | 行为 |
|---|---|---|
| `inspRecNgGenerate` | 检验数据记录 **审核/审批通过** | 检验结论=「不合格」→ 生成**一张**不合格品处理单（一物料一单），头带 供应商/采购单号（行级优先）/产品名称/总数量（送检数量+单位）/不合格品数量/比例/不良说明（=记录处理意见）/检验单号/检验数据记录单号/批次号/批次键/现存量；回填 `qc_insp_rec.不合格品处理单号` + 写链路 `QC_INSP_REC→QC_TC_IN`；给品质审核发「草稿待补充」消息 |
| `tcInApprovedGenerate` | 处理单 **二级批准通过** | ①回填检验行 `特采=1`（行定位 = 链路记录 → 物料编码，退到「产品名称=物料名称」兜底）②检验单已审核则立刻调分流 |
| `inspRouteDefects` | 检验单 **审核/审批通过** + 处理单 **审批通过/弃审** | 唯一的**分流判据**：`特采=1` → `inspAutoSpecialIn`（采购入库，数量=不合格数量，行 特采=是，来源单据=不合格品处理单(来料)、来源单号=处理单号）；否则 → `inspAutoReturn`（暂收退回单）。检验单没审完直接返回 |
| `inspAutoSpecialIn` | 由上一行驱动 | 一物料一张入库单草稿；链路 `QC_INSP→PURCHASE_IN` 且 `备用1='特采'`、`备用2=处理单号`（分流幂等判据 + 弃审反查） |
| `inspAutoReturn` | 同分流 | 由「整单一个 doc 级幂等闸」改为**逐行筛**：没有不合格数量 / 特采=是 / 已分流 / 处理单在途 → 该行不退料 |
| `inspRecUnauditCascade` | 检验数据记录 **弃审/作废** | 它生成的处理单（草稿）一并作废 + 清回填；处理单已审批则挡弃审 |
| `tcInUnauditCascade` | 处理单 **弃审** | 清 `特采=0` → 作废它生成的入库单草稿（已审核则挡）→ 按「不特采」补生暂收退回单 |
| 删除 | — | `returnAutoSpecialAccept`（退料单勾特采 → 生成特采单）整段删除，两个调用点一并摘掉 |
| 消息收件人 | — | `DRAFT_FILL_ROLES_BY_PANEL`：不合格品处理单的「草稿待补充」发**品质审核(pzsh)**，不再发仓库审核 |

要点：**分流时机可能早于/晚于处理单审批**，两边都调 `inspRouteDefects`，靠 `form_flow_link` 的
`备用1='特采'` / `QC_RETURN` 占用做幂等去重；下游作废时 `voidDoc` 会把链置 RELEASED，可重新分流。

### 3.3 品质监控（`QcFlowService` / `QcFlowMonitor.vue` / `qcFlow.js` / `flowSpec.js`）

- 行字段改名：`特采单号/特采日期/特采数量/特采结果/特采状态` → `不合格品处理单号/不合格品处理日期/
  不合格品处理数量/不合格品处理结果/不合格品处理状态`；新增 `特采`（检验行回填值）；
- 「当前环节」：`特采` → **不合格品处理**；判定顺序改为「不合格品处理单在途 → 退货单在途 → 检验不合格且无分支单 → 入库 → 完成」；
- 汇总：`待特采` → **待不合格品处理**；停留天数按处理单日期算；
- 前端分支泳道顺序改成业务顺序（处理单 → 退回单），行上多一条「特采→采购入库」提示。

### 3.4 纸面与菜单

- 菜单：`QC_TC_IN` 从 **智能供应链 > 采购管理 > 单据** 迁回 **品质管理 > 来料品质**，标题「不合格品处理单(来料)」
  （面板编码/路径/表/前缀/权限行不变；`menus.test.js` 断言已同步翻转）；
- 纸面：`docSheetConfigs.QC_TC_IN` 标题两段式 `不合格品处理单` + `来料`（渲染成「不合格品处理单（来料）」），
  表体一格未动（用户口径「进入不合格处理单（来料）都不变」）；
- 检验数据记录：`检验结论` 格下方新增链接「不合格品处理单 TCI-…」（`QcInspRecSheet.vue` 的
  `ngNo` / `gotoNg`，挂在 v-if/v-else 链**之后**，避免抢走「空值说明」那支）。

## 五、已知遗留 / 需要注意

1. **迁移链被一条历史脚本卡住**：`tools/DbSync.java` 增量同步在
   `migrate-qc-proc-insp-batch-table-20261111.sql`（出货检验功能记录表批次矩阵自检）处 `[SQL FAIL]` 中止，

   `DbSync.java run migrate-qc-ng-disposal-20261128.sql` 单独执行并在 `yj_schema_log` 记账。
   要让增量同步恢复正常，需要先修那条脚本的自检。
2. **`DbNormAudit` 7 项 FAIL 为存量债**（备份表 9 张 / 未登记脚本 18 条 / 缺 en 译名 198 处 / 主键审计 38 处等），
   本次新增对象不在任何失败清单里（无 QC_TC_IN / 不合格品处理单号 / 特采 命中）。
3. **`recordSheetConfigs.livedb.test.js` 红**：活库 `RD_EXTRA_REC_FILE`（2026-11-17 新增的「特殊数据记录表」）
   未写进该测试的 `EXPECTED_LABELS`。与本次改动无关，未顺手改（避免混入无关 diff）。
4. **处理单草稿被删的边界**：若不合格品处理单还是草稿时被删除，那一行不合格数量不会自动退料
   （分流在「检验单审核」与「处理单审批/弃审」两个时机触发）。此时可按检验单选单手工建退料单，
   或把检验单弃审后重审一次 —— 重审即重新分流。
5. **仓位**：`inspAutoSpecialIn` 取仓位用的是物理列 `仓位编码`（标签叫「仓位」，AGENTS §5① 的经典坑）。
   顺手修了 `inspAutoPurchaseIn` 里同款的老 bug（它一直没把该列取回来，导致「先吃上游带下来的仓位」那段恒走预设分支）。
