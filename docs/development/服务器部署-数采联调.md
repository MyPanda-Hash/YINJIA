# 服务器部署 · 数采联调(交付给运维/实施)

> 目的:把 MES 部署到 `36.140.66.163:8090` 并让电子秤经 W111 模块把数据推进去。
> 环境要求:**JDK 25**(`pom.xml` java.version=25)、**SQL Server**(库名 `HSDZ_MES`)、Windows 或 Linux 均可。

## 1. 打包(在有源码的机器上)

```powershell
# 仓库根目录;会先 npm run build 前端→镜像到 backend/src/main/resources/static→mvn package

# 产物:backend\target\app.jar(自检:jar tf app.jar 里应有上百条 BOOT-INF/lib/)
```

> 已有 `backend/target/app.jar` 的可直接拷到服务器,跳过本步。

## 2. 数据库

服务器上的 SQL Server 需先恢复一份 `HSDZ_MES` 备份(与本地同结构),然后执行迁移补齐:

```powershell
cd tools
java -cp "lib\mssql-jdbc.jar" DbSync.java            # 正式账套 HSDZ_MES
$env:YINJIA_SQL_DB="HSDZ_MES_TEST"; java -cp "lib\mssql-jdbc.jar" DbSync.java   # 测试账套(可选)
```

连接串默认 `yinjia / Yinjia@2026 @127.0.0.1:1433`,可用环境变量 `YINJIA_SQL_PASS` 覆盖。
**确认成功**:最后一行是 `=== 同步完成: 执行 N, 跳过 M, 失败 0 ===`,失败必须为 0。

### 2.1 数据备份权限(**必做,要用管理员/`sa` 执行**)

「系统管理平台 → 数据备份」的备份动作是 `BACKUP DATABASE`,应用账号 `yinjia` 必须有
`db_backupoperator`(迁移脚本里那段授权是用 `yinjia` 自己跑的,只要它不是 `db_owner` 就会失败并只打印提示 ——
2026-10-19 本机正式库就是这样:测试库 `yinjia` 是 `db_owner` 能备,正式库不能,自动备份留了一行
`自动/失败 | 在数据库 'HSDZ_MES' 中拒绝了 BACKUP DATABASE 权限`)。

```sql
-- 用 sysadmin(或 sa)在正式库执行,两账套都建议跑
ALTER ROLE db_backupoperator ADD MEMBER [yinjia];
-- 核对应为 1
SELECT IS_ROLEMEMBER('db_backupoperator','yinjia');
```

**确认成功**:管理员的「数据备份」页点「立即备份」,结果为 **成功** 且「备份文件」路径带 `.bak`。
另外备份目录必须是 **SQL Server 服务账号**可写的本机路径(默认 `C:\SQLBackup\YINJIA-MES`)。

## 6. W111 模块配置(现场)

手机/电脑连模块 AP `W111`(密码 `12345678`)→ `http://192.168.4.1`(admin/admin)→「端口1」:

| 字段 | 值 |
|---|---|
| 波特率/数据位/停止位/校验 | `9600 / 8 / 1 / NONE` |
| 模式 | `HTTP Client(SSL)` |
| 服务器地址 / 端口 | `36.140.66.163` / `8090` |
| 请求方式 | `POST` |
| URL | `/api/dc/ingest/text?device=DZ-001` |
| 协议头 | `X-DC-Key: scale-demo-2026\|Content-Type: text/plain` |
| 包头过滤 / 超时 | `OFF` / `6` |

保存后**必须重启模块**(页面提示"点此重启生效")。
模块连的 WiFi 只要能上外网即可,**不需要和 MES 在同一局域网**。

```bash

curl -s -o /dev/null -w "%{http_code}\n" http://36.140.66.163:8090/

# ② 密钥/绑定正确(应返回 code 200,status online)
curl -s -X POST -H "Content-Type: application/json" -H "X-DC-Key: scale-demo-2026" \
     --data '{"deviceCode":"DZ-001"}' http://36.140.66.163:8090/api/dc/heartbeat

# ③ 文本上报口存在(应返回 code 200 且带 weight)
curl -s -H "X-DC-Key: scale-demo-2026" \
```

页面验收:登录后「数采平台 → 数据监控」→ 选「电子秤」:设备显示**在线**,`W01` 有实时值,
下方「最新 10 条数据」每 1 秒左右增长一条(空秤 ≤5g 不记流水,但状态保持在线)。

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 文本口 403 | 服务器跑的是**旧包**(没有 `/api/dc/ingest/text`),重新打包部署即可 |
| heartbeat 报「设备未绑定网关或网关未配置接入密钥」 | 第 5 步没做 / `api_key` 不一致 |
| 页面能开但设备离线 | 模块没推上来:查模块状态页 `A_sta` 是否 `HTTP`、收发字节是否增长 |
| 数据忽有忽无 | 模块 WiFi 断 / 服务器地址写错 / 车间网络出不去 |
| 时间差 8 小时 | 服务器时区应为 Asia/Shanghai(`tzutil /s "China Standard Time"`),程序按本地墙钟下发 |

## 9. 回滚

- 程序:保留上一版 `app.jar`,覆盖回去重启即可;
- 数据:第 5 步只新增网关/设备绑定/采集点,不删业务数据;要撤销就删 `GW-DZ-01` 并把 `DZ-001` 解绑。
