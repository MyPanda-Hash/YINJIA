# 采购订单「金蝶已入库/未入库」冻结在旧值（2026-11-26）

> 客户问：「金蝶不是允许超送吗？」——是。真正挡住转ERP 的不是超送，是**MES 显示的剩余量是旧的**。

## 1. 现象

采购入库单 `PI-2026-11-0169`（供应商 惠州市冠霖实业，批次 20261126，已审核、未转ERP）：

| 操作 | 结果 |
|---|---|
| 转ERP | 金蝶拒绝：`部分数据已经构建了关联关系，无法再构建关联关系。` |
| 删除/弃审 | `冲回将使现存量变为负(物料 YJ-GL-019-1 批 20261126 余额 -500),库存已被消耗,不可冲回` |

## 2. 真实账套实测（只读，2026-11-26）

`CGRK-20261126-03855` **不是** MES 的单（供应商=深圳市陶氏水处理，remark 空）；近 300 张入库单里
**没有** `[MES:PI-2026-11-0169]` ⇒ 上次推送在金蝶**没留下任何单据**（不是"残留草稿"）。

冲突在**源单行**上：

| 采购订单行 | 订单量 | 金蝶 `in_qty`(已入库) | 金蝶 `un_out_qty`(未入库) | 行状态 | 本次要推 |
|---|---|---|---|---|---|
| YJ-20261121-07 行1 · YJ-GL-019-1 | 500 | 0 | 500 | A | 500 ✅ |
| **YJ-20261014-03 行2 · YJ-GL-002** | 1000 | **1000** | **0** | **C 全部入库** | 300 ❌ |
| YJ-20260614-04 行5 · YJ-GL-004 | 2000 | 1900 | 100 | Z 部分 | 300 ⚠️ |

「已经构建了关联关系」= 那一行在金蝶**已经关联满**（行②），再建关联就冲突。

## 3. 为什么 MES 显示的是错的

MES 采购订单行显示 `0 / 1000`（已入库/未入库），金蝶实际 `1000 / 0`；而同一张单的**关闭状态又是 C（全部入库）**
—— MES 自己跟自己矛盾。两层病根都在 `deploy/sync-core.mjs`：

| # | 病根 | 说明 |
|---|---|---|
| ① | **31 天修改窗** | 增量用 `modify_start_time = 近 31 天` 过滤，采购订单一旦超过窗口没被改过就再也不重取。`YJ-20261014-03` 金蝶 `modify_time=2026-10-17`（早已出窗）⇒ 明细冻结在首次同步那一刻 |
| ② | **表头指纹** | 即便补拉进列表，指纹只比表头（状态/关闭/日期/供应商），**行级数量变了指纹不变** ⇒ 整单被判"无变化跳过"，补拉等于白拉（实测：补拉后仍写 0/1000，就是被这层挡住的） |

结果：现场看 MES 说"还能收 1000"，于是又收了一次 300，推到金蝶必然被拒；而库存又因为"未转ERP"被金蝶同步抹平，
弃审又被库存守卫拦住 —— 三件事串成一条死锁。

## 4. 修复（`deploy/sync-core.mjs`）

1. **`pendingPoNos()`**：查出 MES 里「已审核但**还没转ERP**」的采购入库单 / 送料暂收单所引用的采购订单号
   （合单的「订单1、订单2」按分隔符拆开；上限 200 张；缺 `是否已转ERP` 列的旧库自动退化为"已审核全算"）。
2. **每轮强制补拉**：这些订单不在本轮列表里也按单号补一次列表查询，并入本轮（日志：
   `强制补拉 N 张(待转ERP兜底 M) → 命中 K 张`）。
3. **指纹旁路**：补拉进来的单**无条件重取详情**（`autoRefreshNos`），否则只会重复病根②。

## 5. 验证（本地库 HSDZ_MES，真实账套拉数）

| 单 | 修前 | 修后 |
|---|---|---|
| YJ-20261014-03 行2 YJ-GL-002 | 行已执行 0 / 行未执行 1000 / A | **1000 / 0 / C** ✅ |
| YJ-20260614-04 行5 YJ-GL-004 | null | **1900 / 100 / Z** ✅ |

日志：`待转ERP单据引用的 116 张订单将强制补拉` → `强制补拉 118 张(点名 2 + 待转ERP兜底 116) → 命中 118 张`
→ `完成:新增 0,更新 118,失败 0`。

## 6. 生效条件与运维

- 服务器上的计划任务用的是**服务器自己那份 `deploy/`**（`JdySalOrderSync`）⇒ 这个改动要随代码一起部署上去才生效。
- 生效后**下一轮（≤5 分钟）**自动把待转ERP 单涉及的采购订单刷新一遍；也可以单张补：
  `node deploy/sync.mjs --refresh-bill=YJ-20261014-03 --yes`
- 遗留：`回单/删除`侧的死锁已由 `mes.stock.guard.*`（2026-11-26 口径修订）解决。
