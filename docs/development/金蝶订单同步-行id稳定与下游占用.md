# 金蝶订单同步 · 明细行 id 必须稳定(与下游占用的契约)

> 2026-11-16 故障复盘与修复记录。**改动订单同步、订单明细行、行级占用、材料码打印之前,先读这一份。**
> 相关实现:`deploy/sync-core.mjs`(`upsertLines` / `upsertDoc`)、`tools/migrate-erp-linekey-repair-20261116.sql`

## 一、不变量(违反即等于把下游单据和数据一起弄坏)

**金蝶同步写订单明细行时,同一业务行的 `identity id` 必须保持不变。**

MES 的**行级引用**全部是「`{单据编号}#{行id}`」这一种形状,没有任何兜底:

| 用途 | 位置 | 悬空后的表现 |
|---|---|---|
| 采购链已送量(暂收/检验/退回/入库的按量占用) | `form_flow_link.source_line_key` | 已送量归零、可送上限虚高 ⇒ **重复送料**;分批送料弹窗报「送料行不存在或已失效」 |
| 材料码打印记录(= 弹窗下层「已打印隔离行」) | `bl_pu_label.采购订单行id` | 已打印量切不回去、隔离行整片消失 |
| 销售链已转工单量 | `form_flow_link.source_line_key`(SO_ORDER) | 已转量归零 ⇒ 结转列表可重复转工单 |

## 二、2026-11-16 故障

- 现象:采购订单 `YJ-20261111-06` 分批送料弹窗点「确定生单」报
  `送料行不存在或已失效:YJ-20261111-06#11039`。
- 事实(正式库实测):
  - 该单明细行 id 在 **17:47:07** 被整体换掉:`11035…11043` → `11103…11111`(`asp_user1='jdy-sync'`);
  - 17:41:26 刚生成过暂收单 `SL-2026-11-0064`(占用 `#11040`,40000),弹窗里第 6 行还显示着「已送 40000」;
  - 17:47 同步一跑,弹窗手里的 `#11039` 就作废了 ⇒ 后端重算候选行(全成了新 id)查不到 → 报错。
- 存量损伤(当天):采购链占用 422 条、销售链占用 505 条、材料码记录 24 条指向已删行。

## 三、根因

`deploy/sync-core.mjs` 的 `upsertDoc()` 旧实现:|头表 upsert **+ 明细行 `DELETE FROM … WHERE 单据编号=?` + 逐行 INSERT**。
每写一次,该单明细行就拿一批新的 identity id。

而**"写一次"非常频繁**:同步每 5 分钟一轮,列表级指纹(`fingerprintOf`,采购订单为
`bill_status|bill_close_state|bill_date|supplier_name|supplier_number|emp_name|io_status|real_io_status|remark`)
只要变一个字段(审核、到货/入库进度、关闭、改备注…)就重写整单明细 ⇒ 一天之内反复换 id。

## 四、修复(代码)

`deploy/sync-core.mjs` 新增并导出 `upsertLines(doc, tx, mssql, docNo, lines, log)`,`upsertDoc` 改调它:

1. **行键 = 金蝶分录 seq(本表 `行号` 列)**。seq 在 ERP 里就是分录身份(转 ERP 的 `src_seq` 也用它),
   改数量/交期/审核/入库进度都不变;同键 **UPDATE 保 id**(不动 `asp_time1`,只盖 `asp_user1/asp_user2/asp_time2`)。
2. **没有行号的老行**(2026-09-27 之前的销售订单行、本地研发库存量)兜底行键 =
   `物料编码 + 该物料在本单的第几次出现`(`DOCS` 里按表配置 `lineCodeCol`:采购订单 `物料编码`、销售订单 `存货编码`)。
3. ERP 新增行 → INSERT;ERP 已删除的行 → 硬删(与旧行为一致);**若被删行上还挂着 ACTIVE 占用,打 ⚠ 日志留痕**。
4. 两个键都算不出来(无行号且无物料)或库内同键重复 → 退回旧的「整单删插」并**告警**(宁可换 id 也不错配)。
5. 行号比较按**数值**归一:正式库 `bl_pu_order.行号` 是 `nvarchar('6.0000')`、`bl_so_order.行号` 是 `int('6')`,
   接口给的是数字 `6` —— 不归一会每行都被当成新行(退化回整单删插)。

回归:`node deploy/_test-lineupsert-20261116.mjs`(事务 + 回滚,不留痕),覆盖
①原样重写行 id 一个不差 ②改数量不变 id ③幂等 ④ERP 删行 ⑤ERP 加行 ⑥行键算不出来时退回 replace。
两个账套 × 两种单据(采购/销售)各跑一遍全 `[PASS]`。

## 八、金蝶在册核对:金蝶删了/作废了,MES 不能还当"已审核"用(2026-11-16)

**实现**:`deploy/sync-presence.mjs`(`sync.mjs` 每轮最后自动跑一次,`--no-presence` 可跳过)。

【为什么必须补】增量同步只拉 `bill_status='C'(已审核)+ 近 31 天修改` ⇒ 金蝶**删除**、**作废(Z)**、
**反审核回草稿**的单会从列表里"消失";而同步从不删 MES 单据 ⇒ 那张单在 MES 里**永远停在「已审核」**,
分批送料/生单照样能点、能生成暂收/检验/入库,而且不报错、没人看得出来。
(已被拦住的只有:金蝶**手动关闭 H** → 已中止、**自动关单 S** → 已完成,状态推导里本来就有。)

【怎么判、怎么处置】(只碰 `外部数据ID` 非空的金蝶来源单,本地自建单一律不动)

| 金蝶侧 | MES 有下游痕迹(占用/材料码/批次台账) | MES 无任何痕迹 |
|---|---|---|
| 已无此单 | 写 `yj_doc_status.erp_close_state='D'`(状态=**金蝶已删除**)→ 生单闸门自动拒 + 日志点名 | 软删(头/行 `asp_cancel='Y'` + 清 `外部指纹`)→ 面板里消失 |
| 不是 C(作废 Z / 反审核) | 同上,`'Z'`(状态=**金蝶已作废**) | 同上 |

- 两个新状态由 `QueryService.docStatus` 与 `ButtonService.docStatusOf` 推导(两处同改),
  都**不是「已审核」** ⇒ 沿用现有「仅已审核可生单」闸门,**不改生单逻辑**;前端 `tt()` 有译名,
  列表里红/橙显示。生单报错文案会提示「刷新页面或等下一轮同步(≤5 分钟)」。
- **为什么有痕迹的只标记不删**:删了等于把已经发生的收货藏起来(库存/批次/对账全断),只能人工处置。
- **软删的单能自愈**:清 `外部指纹` ⇒ 若金蝶那边其实还在,下一轮同步按"无指纹"重取详情,
  头表 UPDATE 会把 `asp_cancel` 写回 `'N'`,单子自己回来。
- **标记也能自愈**:金蝶侧又变回 C 的单,核对会把 D/Z 清回 NULL。
- 成本控制:每轮只问两个数(总数 / 已审核数),与上轮相同且 24 小时内做过全量 ⇒ 跳过;
  计数一变才全量对差(金蝶全列表 25 页 × 200 条,实测 ~5 s)。
- **安全闸门**:一次命中 > max(20, MES 在册数 × 5%) ⇒ 判定"金蝶列表没取全",**一个都不动**,只留告警。
  这条闸门是防"接口抽风把整库标记成已删除"的最后一道,别删。

### §八·边界(被反复问到的三点,别凭印象改)

1. **"没有下游的"是软删,不是物理删**:只把 头/行 `asp_cancel` 置 `'Y'`(数据、行 id 全保留),
   面板按 `asp_cancel` 过滤后不再出现;`外部数据ID` 仍占着那一行(唯一索引 `ux_bd_pu_order_ext_id`)。
2. **下游单据不做标记、也不阻断**(有意为之):暂收/检验/入库/退回是 MES 自己的凭据,
   货可能已经收了、批次/库存/对账都挂在上面 —— 因为源采购订单在金蝶被删就把它们标废/挡住,
   等于把已经发生的业务弄断。下游照原流程走完;只有"再往上生成新单"这一步被拦(源单不是已审核)。
   真正需要人看的是**转ERP**:采购入库推金蝶时会带采购订单号 + 源单行号,金蝶侧若已删单会在推送时报错
   (失败是响亮的,不是静默)。
3. **软删不会堵住后续同步**(实测:`deploy/_test-presence-revive-20261116.mjs`):软删时清了 `外部指纹`
   ⇒ 下一轮同步必然把它判成"有变化" ⇒ 按 `外部数据ID` 命中**同一行** UPDATE,`asp_cancel` 写回 `'N'`,
   明细行(走 upsertLines 的 UPDATE 分支)同样回 `'N'`;行 id 与已送量**一个不变**。
   因为复活是 UPDATE 而不是 INSERT,也不会撞 `外部数据ID` 唯一索引。
   ⚠ 唯一没法自动收拾的边角:**金蝶删了一张单、又新建了同号新单**(新 外部数据ID)。
   MES 侧 `单据编号` 没有唯一索引 ⇒ 新单会作为**另一条头记录**落库(旧的软删行还在),列表按
   `asp_cancel` 过滤后只显示新那条,功能不受影响,但库里会留一条同号的作废行(要清得人工)。
4. **转ERP 前置校验(2026-11-16,A 方案)**:采购入库单/暂收退料单转ERP 前先查
   `yj_doc_status(panel='PU_ORDER')` 里**该单的来源采购订单**(表头「采购订单号」+ 行级
   「源单编号/采购单号」,合单时的"订单1、订单2"串会拆开);销售出库/销售退货同理查来源销售订单。
   只要有一张被标 `D`/`Z` 就**直接拒绝**:
   > 来源采购订单 X(金蝶已删除) 在金蝶侧已失效,本单不能转ERP:请先在金蝶恢复该采购订单
