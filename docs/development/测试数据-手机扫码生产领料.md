> 生成于 2026-10-30。**只在测试账套 `HSDZ_MES_TEST`**。
> 登录时「登录工厂」要选 **YINJIA-MES·测试库**，否则看到的是正式库（空的）。

## 一、数据怎么来的

| 脚本 | 作用 |
|---|---|
| `tools/seed-mobile-pick-all-stages-20261030.sql` | 造**基底**：50 张工单（6 组）+ 6 张组装工艺清单（BOM） |
| `tools/seed-mobile-pick-all-stages-20261030.mjs` | 用**真实接口**把状态推到各环节（生单 → 领料 → 提交 → 退料） |

为什么不直接 INSERT 单据：领料单 / 材料出库单 / 库存台账 / 退料台账是一整条过账链，
手工塞数据必然与真实过账分叉（库存对不上、工单回写不对、状态推不出来），测出来不可信。

重跑：

```powershell
# 基底（幂等，可反复跑）
cd tools
java -cp lib\mssql-jdbc.jar SqlRunner.java "jdbc:sqlserver://127.0.0.1:1433;databaseName=HSDZ_MES_TEST;encrypt=false" yinjia env seed-mobile-pick-all-stages-20261030.sql

# 推状态（已做过的会跳过）
cd ..
node tools/seed-mobile-pick-all-stages-20261030.mjs --run
```

## 三、逐环节检查清单

### 环节一：生成工单领料/退料单

进入：菜单 **手机扫码 → 生成工单领料/退料单**

- [ ] 「未开单」组有 10 条可开（`GD-STG-A*`）+ 10 条未排产（`GD-STG-B*`，红标签）
- [ ] 「已开单」组有 40 条
- [ ] 扫 `0@GD-STG-A01@1001` → 加入队列 → 生成 → 成功，显示领料单号
- [ ] 扫 `GD-STG-B01` → 生成 → **被拦**，提示「未排产…请先到快速排产」
- [ ] 重复扫同一张 → 提示「已在待生成列表里」
- [ ] 已开单行可点 → 进明细，**只读**（无扫码框、无数量框、无提交按钮）

### 环节二：生产领料（未完成）

进入：菜单 **生产领料**

- [ ] 「未完成」组有 **20** 条
- [ ] `GD-STG-C*` 进度显示 `0/3`；`GD-STG-D*` 显示 `1/5`
- [ ] 顶部查询框输入 `GD-STG-D01` → 查询 → 只剩该单
- [ ] 中间扫码框扫 `0@GD-STG-D01@1001` → 直接打开对应单据

### 环节三：单据详情 · 领料

从 `GD-STG-C01` 进入：

- [ ] 明细行右侧显示 **已领 / 需求**（如 `0 / 3`）
- [ ] **点明细行不再自动带料**，只提示「请扫物料码：XXX」
- [ ] 扫物料码后：数量框出现，**默认值 = 需求用量**
- [ ] 数量上限 = 该物料库存总量；超出自动拆到下一批
- [ ] 写入 → 数量框消失（重新锁定）回到扫码状态
- [ ] 「取消」→ 同样锁定，不写入
- [ ] 未领满时「提交」置灰；全部领满后才亮

### 环节四：单据详情 · 提交

从 `GD-STG-D*` 把剩余领完：

- [ ] 提交 → 二次确认 → 成功
- [ ] 领料单转入「已完成」组
- [ ] 库存减少（可在材料出库单面板核对）

### 环节五：已完成的单 · 退料

从 `GD-STG-E01` 进入：

- [ ] 明细行**不可点**（已过账的单不再能领）
- [ ] 点「开始退料」→ 进退料模式
- [ ] 扫物料 → 数量默认 = 累计可退 → 提交
- [ ] 生成**其他入库单**，单据头有「退料标志 = 生产退料」
- [ ] 抬头出现 **【含退料】** 徽标 + 退料单号
- [ ] 库存增加

### 环节六：再退一次

从 `GD-STG-F01` 进入：

- [ ] 可退数量 = 已领 − 已退（比第一次少）
- [ ] 再退成功后，抬头退料单号**累加**（逗号分隔多个）
- [ ] 退到 0 后再退 → 被拦「可退只剩 0」

## 五、常见问题

**Q：打开是空的？**
A：看顶栏登录工厂是不是「YINJIA-MES·测试库」。正式库没有测试数据。

**Q：改了界面没变化？**
A：打开 `/api/build` 看 `indexChunk`，与 F12 → Network 里实际加载的 `index-*.js` 比对；
不一致就是浏览器缓存，用 `Ctrl+Shift+R` 或无痕窗口。

**Q：想从头再测一遍？**
A：重跑上面两条命令。基底脚本幂等；mjs 会跳过已开单的工单（要彻底重来需先清 `GD-STG-*` 的单据）。
