# 检验报告「检测标准」换行不一致 —— 成因与处置(2026-11-11)

## 一、现象(用户截图)

同一张检验报告(YJ-XH-001),有的行「检测标准」是多行文字,有的挤成一行还被截断;
草稿态与已审核态看到的也不一样,像是"带入时随机会不会换行"。

## 二、成因:两层,叠加在一起

### 1. 数据层:源文本本来就有的有硬换行、有的没有

`frontend/src/core/qc/qcInspReqCarry.js` 带入时**只做 `String(值).trim()`**,不加工文本:

```js
const std = String(row?.[key] ?? '').trim()   // 硬换行原样带过去
```

来料检验要求里,单元格若是 Excel 里 Alt+Enter 的**硬换行**,进库就是 `char(10)`/`char(13)`;
只是一句话的,就没有。带入后前者分多行、后者一行 —— 这是数据差异,不是带入随机。

### 2. 渲染层:同一份数据,可编辑/只读两种画法(主因)

| 状态 | 「检测标准」原来怎么渲染 | 看到的效果 |
|---|---|---|
| 草稿/可编辑 | `el-input` → 单行 `<input>` | 硬换行**根本显示不出来**,超宽直接截断 |
| 已审核/归档 | `<span>`(`white-space: normal`) | 硬换行被折成空格、长文本按列宽折行 |

⇒ 同一张单"草稿看一行、审核后看多行",断行位置还和源表对不上。

### 3. 顺带发现的隐患

编辑态输入框写死 `maxlength="500"`,而 `qc_insp_rec_detail.检测标准` 是 `nvarchar(1000)`:
截图里那种几百字的标准,在草稿态**一编辑就会被截到 500 字**。

## 三、处置(用户选方案 A)

`frontend/src/core/views/QcInspRecSheet.vue`:

1. **编辑态** → 多行 `textarea`(`autosize` 1~6 行),硬换行按原样断行;`maxlength` 500 → **1000**;
2. **只读态** → 加 `.qr-pre { white-space: pre-wrap }`,保留源文本的硬换行;
3. **信息隐藏时给全文**:两态都挂 `el-tooltip`(内容 = 该格全文),提示框限宽 460px、
   `pre-wrap` 换行、深色实底(Element 默认提示不限宽,长文本会拉成一条横贯全屏的长条);
4. 检验项 / 单项判定 / 五个结果格补 `:title`,超宽时悬停同样看得到全文。
