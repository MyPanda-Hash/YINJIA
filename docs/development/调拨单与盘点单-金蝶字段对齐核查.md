# MES 调拨单 / 盘点单 ←→ 金蝶 字段对齐核查(2026-10-18)

> 用户口径:「现在的盘点单和调拨单是否和金蝶的接口字段对齐。如果对齐了,拉取金蝶9.1号后已经审核的这两个单据。
> 并且日期编号相关的信息要和拉取的单据日期对应,相当于补充完整这两个单据在九月份系统的实际操作。」

## 一、结论

**业务字段已对齐,可以做数据拉取**;有 3 类字段 MES 没有对应列,但**都不影响补录九月数据**(详见第三节)。

| 单据 | 业务字段对齐度 | 能否直接拉取 | 结论 |
|---|---|---|---|
| 调拨单 | 表头 8/8、分录 13/13 关键字段 | ✅ 可以 | **拉** |
| 盘点单 | 表头 6/6、分录 7/7 关键字段 | ✅ 可以 | **拉**(见下方⚠) |

⚠ **盘点单有个硬前提**:金蝶 9.1 之后**一张盘点单都没有**(最近一次是 2026-01-06),所以九月能补的只有**调拨单 10 张**。
盘点类要补就得放宽日期窗口,这超出「补九月」的口径 —— 需要你确认后我再拉。

| `bill_date` | 单据日期 | ✅ |

| `material_number` / `material_name` / `material_model` | 存货编码 / 存货名称 / 规格型号 | ✅ |
| `out_stock_number` / `out_stock_name` | 调出仓库编码 / 调出仓库 | ✅ |
| `in_stock_number` / `in_stock_name` | 调入仓库编码 / 调入仓库 | ✅ |
| `out_sp_number` / `in_sp_number` | 调出仓位编码 / 调入仓位编码 | ✅(金蝶实测 0 行有值,可空) |

| `qty` | 数量 | ✅ |

**MES 没有对应列的金蝶字段**(均不影响业务):
`material_id`/`stock_id`/`sp_id`/`unit_id` 等 **ID 族**、`base_unit_*`/`aux_unit_*` **单位族**、
`inv_qty`/`inv_base_qty` **账存数量族**、`coefficient`/`conversion_rate` **换算族**、
`src_bill_*` **源单族**、`custom_entity_field` **自定义字段**、`material_is_*` **商品属性族**。

> 这些是金蝶的**主数据 ID / 多单位 / 折算 / 追溯**信息,MES 侧用「编码」而非「ID」关联,
> 档案在 MES 本地维护 —— 与现有 7 张单据的拉取口径完全一致(采购入库/销售出库也不存这些)。

### 2.2 盘点单

| 金蝶 | MES | 状态 |
|---|---|---|
| `bill_no` / `bill_date` / `remark` | 单据编号 / 单据日期 / 备注 | ✅ |
| `emp_name` | 盘点人 | ✅ |
| `stock_name` | 仓库(表头) | ⚠ MES 仓库在**明细行**,表头无仓库列 → 落到每行 |
| `material_number` | 存货编码 | ✅ |
| `sp_number` | 仓位编码 | ✅(金蝶 13/1664 行有值) |
| `batch_no` | 批号 | ✅ |
| `unit_number` | 计量单位 | ✅ |
| **`inv_qty`(账存)** | **账面数量** | ✅ 语义完全对应 |
| **`qty`(实盘)** | **实盘数量** | ✅ 语义完全对应 |
| `comment` | 明细备注 | ✅ |

**`差异数量` 是 MES 自己算的**(实盘 − 账面),金蝶不存该字段 —— 拉取时按金蝶两列现算,口径一致(审核时会以 kucun 现值重算覆盖)。

**MES 没有对应列的金蝶字段**:同调拨单(ID 族/单位族/换算族/源单族),
外加 `check_time`(盈亏处理时间)/`check_id`(盈亏处理人)/`gain_bill_no` 与 `loss_bill_no`(盘盈/盘亏单号)
—— 这几个是金蝶「盈亏处理」环节的产物,MES 用盘点单自身的审核+流水覆盖,不需要。

## 三、为什么说「已对齐、可以拉」

1. **业务主干字段 100% 有落点**:单号/日期/仓库/物料/批次/单位/数量/仓位/备注,一个不缺;
2. **MES 特有的字段金蝶本来就没有**(账面/差异/单价),这些由 MES 自己算或从 kucun 取;
3. 缺口全是**主数据 ID 与多单位折算**,而 MES 全部用编码关联 —— 与现有采购入库单/销售出库单的拉取口径**完全一致**;
4. 调拨单**唯一真正缺的**是 `转ERP` 回填(ERP单号):拉取时把金蝶单号写进 MES 的「ERP单号」列,即可溯源。

## 四、拉取方案(等确认后执行)

### 4.1 只拉调拨单(九月)

- 范围:金蝶 `inv_tfmove` 中 `bill_date >= 2026-09-01` 且 `bill_status = 'C'(已审核)` → **10 张 / 13 行**
- 单据编号:**沿用金蝶原号**(`YCD-20261014-00001`),写进 MES `单据编号`;
  同时写 `ERP单号 = 金蝶单号`,`是否已转ERP = 是`,`转ERP操作人 = system(金蝶拉取)`
  —— 这样「日期编号与拉取的单据日期对应」:MES 的 `单据编号` 与 `单据日期` 与金蝶**逐字一致**,
  不会出现 MES 自己发号(DB-2026-10-xxxx)与金蝶对不上的问题。
- 落库:头 `bd_transfer` + 行 `bl_transfer`,状态**已审核**(`yj_doc_status.shr = '金蝶同步'`),
  并**过 kucun 双腿账**(与手工审核完全同一套 `applyTransfer`),流水段 9/10。
- 幂等:以金蝶 `bill_no` 为键,**已存在则跳过**(重跑不重复)。

### 4.2 盘点单

按当前口径 **9.1 之后 0 张**,无可拉取。若你确认要补,可选:
- **A. 放宽到 2026-01-01 起**:有 3 张(2026-01-06 的三张 PDD-…),可补;
- **B. 保持不拉**:MES 九月盘点确实是「没做过盘点」这一真实情况。

## 五、风险与待确认

### 🔴 5.1 最要紧的一条:2026-09 **已经月结**,补录会动已关账期间

实测(`q-monthclose.sql` / `q-opening-check.sql`):

| 事实 | 数据 |
|---|---|
| `bd_stock_close` | 期间 `2026-09` = **已月结**(单号 `JZ-202609`,结转日 2026-10-01,操作人 admin) |
| 月结结转流水 | `inh` 里 **2272 行**「月结结转」(单据日期 2026-10-01) |
| 期初结存 | `inh` 里 **1889 行**「期初结存」 |
| MES 9 月其他单据 | 采购入库 332 / 销售出库 415 / 材料出库 487 / 产成品入库 232 / 其他出入库 93 |
| MES 9 月调拨/盘点 | **0 张**(只有 10-18 我建的演示单) |

**问题**:9 月的出入库单据已经齐了、月结也做完了。此时把这 10 张 9 月调拨补进来**并过账**,等于:

- 9 月的 `kucun` 会被**再扣一次**(调出仓 −、调入仓 +);
- 而 **9 月的月结结转(`JZ-202609`)不会自动重算** —— 结转快照是按当时数据打的;
- 结果:9 月期末结存与 10 月期初**对不上**,而系统**没有"已月结期间禁止过账"的拦截**(全仓实测无此守卫),
  所以这件事**会静默成功**,直到有人对账才发现。

**所以补录必须选一种做法,请你定:**

| 方案 | 做法 | 影响 |
|---|---|---|
| **A. 只补单据、不记账**(推荐) | 落 `bd_transfer`/`bl_transfer` 与 `yj_doc_status`(已审核),**不写 kucun/流水**;单据在界面可查可打印,库存以月结结转为准 | 库存不动、账不乱;但「审核了却没动库存」需要在单据上标注(备注写「金蝶历史单据·不参与记账」) |
| **B. 补单据 + 取消月结重做** | 先「取消月结 2026-09」→ 补录并过账 → 重新月结 | 账完全平;但要重跑月结,10 月的期初/成本会随之变化,**影响面大** |
| **C. 补单据 + 过账但不重算月结** | 直接过账 | ❌ **不建议**,会造成 9/10 月结存对不上 |
