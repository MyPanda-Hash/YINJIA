# 送料浮层「关联单据可见性」修复（2026-11-25）

> 客户原话：
> 「下游有单据吗，为什么不能生单」→「这里已经作废了，而且改动到的单据，这里会看到对应变化吗？还有为什么这个记录找不到送料的单」
> →「SL-2026-10-0053 为什么我能查到这个单据」→「**这上面关联的单据不应该都能看到吗**」

## 1. 现象（生产实例 YJ-20260921-10）

采购订单表头「送料」浮层只有两行：

| 批次号 | 日期 | 数量 | 状态 | 去向单号 |
|---|---|---|---|---|
| （空） | 2026-09-28 06:15:57 | 75000 | 待编号 | 已作废（查不到单） |
| 20261114 | 2026-11-14 13:25:00 | 4000 | 有效 | PI-2026-11-0057 |

而同一张订单的「已送」是 **35000 / 39000 / 5000**（剩余 0），真正吃掉这些量的是
**送料暂收单 SL-2026-10-0053**（已审核、75000、单据批次号 `SX-20260921`、批次键 240）——
它在暂收单面板里查得到，**在送料浮层里却完全不存在**。

## 2. 根因：浮层列的是「批次台账」，不是「关联单据」

`PanelxList` 的送料摘要/浮层与分批送料对话框的「已有批次」都取 `/px/batchFlow/lines` →
`BatchService.batches()`，而它只查 `yj_doc_batch` 且 `status IN ('ACTIVE','PENDING')`。
占用（`form_flow_link`，ACTIVE）**不等于**台账行，于是三类单据必然漏显：

| 情况 | 为什么会漏 | 实例 |
|---|---|---|
| 有 ACTIVE 占用、但台账行不在有效态（被释放/丢了/批次键对不上） | 被 `status` 过滤掉 | **本单 SL-2026-10-0053（批次键 240）** |
| 单据由**统一生单 / 选单 / 手工**创建 | `PushGenerateHandler` 那两条路走 `linkBatch(..., batchId=null)`，**只写占用不建台账** | 生产上有这类单（修数脚本实测能扫出来） |
| 台账行指向的单被删/作废 | `resolveEndTarget()` 只沿「它自己那张单」的下游找，不回头找「谁挂着这个批次键」 | 本单 2026-09-28 那行 |

## 3. 改了什么

### 3.1 后端：补「孤儿占用」合成行

`BatchService.batches()` 末尾新增 `appendOrphanRows()`：
凡本来源单 `link_status='ACTIVE'` 的目标单据，若在**已列出的台账行**里找不到同一个目标单号，
就合成一行 —— 批次号取占用上的 `batch_no`、数量 = 该单 Σ`linked_quantity`、日期 = 最早占用时间、
`status='UNREGISTERED'`、去向单号 = 该单（并沿用 `resolveEndTarget()` 走到链路终点）。

- **纯展示语义**：只读、不写库、不参与按量占用/剩余/可填上限/生单校验，也不影响取号
  （`nextBatchNo` 与 `batch_seq` 都不看合成行，`batchSeq` 固定 0）。
- 即使生产库还没跑修数脚本，界面也不会再「有已送、没记录」。

### 3.2 前端：状态文案与去向单号

- 新增纯函数模块 `frontend/src/core/selection/batchStatus.js`：
  - `batchStatusKey(status)` → `有效 / 待编号 / 未登记台账 / 已释放`（未知状态不漏英文码）；
  - `batchTargetDisplay(row)` → 正常行可点；整链作废时**回显首跳单号**（`firstTargetFormNo`）+「已作废」。
- `PanelxList.vue` 浮层的「状态」「去向单号」两列改走这两个函数（原来只显示「已作废」，
  现场连"该去哪张单排查"都无从下手）。

> 顺带说明：摘要里的「已送 N 批」= 上面这个列表的行数，所以合成行出现后这个数字会变得更接近真实；
> 「剩余/可补」一直按 `form_flow_link` 的 ACTIVE 占用实时算，与批次台账无关。

### 3.3 数据：`tools/migrate-batch-ledger-orphan-repair-20261125.sql`

- ① 诊断：列出「有 ACTIVE 占用、没有有效台账行」的组合；
- ② 恢复：台账行被 `RELEASED` 但目标单仍被占用 ⇒ 回 `ACTIVE` 并按占用重算 `batch_qty`；
- ③ 补登：完全没有台账行的占用 ⇒ 插一行（号取占用上的号，其次单据头号；都空 ⇒ `PENDING` 待编号，绝不造号）；
- ④ 复检：孤儿必须 = 0，否则整体回滚（`RAISERROR`）；
- ⑤ 只报告：单据批次号 ≠ 占用批次号（不改）；
- ⑥ **默认关闭**：把台账批次号对齐成单据批次号（见 §4）。
- 只动台账，**不改单据、不改占用量**；幂等（两账套均已执行，复跑 0 行）。

## 4. 单据批次号与占用批次号为什么不一样（全库性，不是某张单被改坏）

`migrate-align-docdate-batch-time-20261016.sql` §1 把有「批号/批次号」列的表里的日期段
统一改成**单据日期**（⇒ SL-2026-10-0053 成了 `SX-20260921`），但 `form_flow_link.batch_no` 与
`yj_doc_batch.batch_no` 不在那次扫描范围 ⇒ 占用侧仍保留生单那天的号（`SX-20261014`）。
于是老单普遍「单据一个号、占用一个号」。

**没有擅自统一**：这个号可能已经印在材料码上（实物流凭证）。现场确认"实物贴的是哪个号"后，
把脚本 §6 的 `@alignLedgerBatchNo` 置 1 重跑即可（幂等）。

### 7.1 卡住整条链的 `migrate-qc-proc-insp-batch-table-20261111.sql`

它的效果**早已就位**，失败的是脚本 §7 的**断言过时**（逐项诊断）：

| 断言 | 现库实际 | 说明 |
|---|---|---|
| 面板名 = `出货检验表观` | `出货检验（表观）`（带全角括号） | 后续脚本统一加了括号，旧断言失效 |
| `处理方式` 字段 `hidden=1` | `hidden=0`（已放开可见） | 后续脚本有意放开 |
| `处理方式` 是下拉框 | OK | — |

⇒ 建议把该脚本这两条断言放宽到「接受现行命名/现行可见性」，再 `DbSync run` 一次把哈希对齐 —— 否则任何新机器上 `DbSync sync` 都会停在这里。**本次没改它**（改历史迁移要单独确认）。
