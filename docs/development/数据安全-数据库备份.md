## 一、面板上有什么

| 区块 | 内容 | 说明 |
|---|---|---|
| 自动备份 | 启用开关 / **每月几号(1~28)** / **备份时间(HH:mm)** / 保留份数 / 备份目录 | 保存即生效,不用重启服务 |
| 立即备份 | 一键**主动备份**一次 | 成败都进「备份记录」,失败原因原文落库 |

  两个账套各备各的,文件名按库名区分 —— 在测试账套里开自动备份,不会替正式账套做决定。
- 顶栏标签会显示当前库名;测试账套额外显示「测试账套」标签。

## 二、怎么备的(为什么是 BACKUP DATABASE)

用 `BACKUP DATABASE [库] TO DISK = N'路径.bak' WITH FORMAT, INIT, CHECKSUM` —— **完整备份**由
数据库引擎自己写盘,事务日志、索引、约束、视图、扩展属性一起保下来,恢复出来是同一个库。

- ❌ 不用「导出表/生成 INSERT 脚本」那种逻辑备份:恢复不回去,数据安全上是假备份;
- ✅ `CHECKSUM` 让备份集带校验和,恢复前可用 `RESTORE VERIFYONLY ... WITH CHECKSUM` 验完整性;
- ⚠ 目录是**SQL Server 服务账号**写的,不是 Java 进程 —— 必须是服务账号可写的本机路径
  (默认 `C:\SQLBackup\YINJIA-MES`,与既有手工备份同盘)。改目录后点一次「立即备份」验证。

### 自动备份的触发规则(**每月一次**)

> 用户 2026-10-19 追加口径:「里面显示的数据库备份记录改为每个月一次」—— 原「每天一次」已改为
> 「每月 `auto_day` 日 `auto_time`」,参数 `db_backup.auto_day`(1~28,默认 1 号)。
> 为什么只给 1~28:29~31 号在 2 月不存在,选 1~28 日期不漂移;程序仍会兜底成"当月最后一天"。

`DbBackupScheduler` 每 60 秒轮询一次(**不是 cron**):日期/时间由面板改,cron 要重启才生效。
判定 = 「已启用」+「现在 ≥ 本月 `auto_day` 日 `auto_time`」+「**本月**还没有成功自动备份」。

- **一个月最多备一次**;万一失败,下一次轮询会重试(该日没开机/服务没起,本月内起来会补一次);
- 调度线程本身没有请求上下文,默认只会落正式库 ⇒ 代码里**显式轮流查两个账套**,
  否则「测试账套里开了自动备份」永远不触发(用户看到的开关是开的、却什么都没备)。

### 保留份数与清理

`保留份数` 为 N(默认 14)时,每次备份成功后按修改时间从新到旧,删除超出 N 的旧文件;
**只删「备份目录里、文件名以本库名开头、后缀 .bak」的文件**,同目录里其它库/其它软件的文件一律不碰;
N = 0 表示不清理。备份记录(yj_backup_log)永远不删。

## 三、接口(全部管理员专属 `requireAdmin`)

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/sys/backup/overview` | 当前库名 + 设置 + 下一次自动备份时间 + 最近 20 条记录 |
| POST | `/api/sys/backup/save` | `{autoEnabled, autoTime:'HH:mm', keepFiles, dir}` |
| POST | `/api/sys/backup/run` | 立即备份(同步返回本次结果:状态/文件/大小/耗时/原因) |
| GET | `/api/sys/backup/logs?limit=` | 备份记录(新的在前) |

参数存在 `yj_app_setting`:`db_backup.auto_enabled` / `db_backup.auto_day` / `db_backup.auto_time` /
`db_backup.keep_files` / `db_backup.dir`;留痕表 `yj_backup_log`。

## 四、部署/运维要点

1. **服务账号权限**:应用账号 `yinjia` 需要 `db_backupoperator`(迁移脚本已幂等补一次,
   失败只打印提示不中断)。服务器上若缺,用管理员执行:
   `ALTER ROLE db_backupoperator ADD MEMBER [yinjia];`
2. **目录权限**:备份目录必须 SQL Server 服务账号可写;建议单独一个盘(如 `D:\SQLBackup\YINJIA-MES`),
   并按保留份数预留空间(实测 71 MB 的测试库备份 ≈ 0.2 秒)。
3. **磁盘**:面板「立即备份」不锁业务查询,但占 IO ⇒ 自动备份默认 02:00,避免与生产高峰重叠。
4. **恢复(灾难恢复)**:应用账号**没有** `CREATE DATABASE` 权限,恢复必须用 sysadmin(或 dbcreator):
   ```sql
   RESTORE VERIFYONLY FROM DISK = N'D:\SQLBackup\YINJIA-MES\HSDZ_MES_auto_20261020-020000.bak' WITH CHECKSUM;  -- 先验
   ALTER DATABASE [HSDZ_MES] SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
   RESTORE DATABASE [HSDZ_MES] FROM DISK = N'…' WITH REPLACE, RECOVERY;
   ALTER DATABASE [HSDZ_MES] SET MULTI_USER;
   ```
   恢复期间 8090 的连接池会被踢断,Hikari 会自愈(应用不用重启)。
5. **别用「全量恢复备份」部署与本功能混淆**:部署走 `deploy/` 的全量覆盖流程,
   本功能是**运行期数据安全**,两者互不替代。

## 六、演示数据(测试账套的「每月一次」备份记录)
