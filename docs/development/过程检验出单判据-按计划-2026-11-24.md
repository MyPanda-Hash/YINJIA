# 过程检验出单判据：按出货检验计划 / 成型工艺清单（2026-11-24）

> 取代 2026-11-14 的 `bs_inv.是否过程检验` 商品开关（该列 2026-11-24 已删除）。

## 用户口径（原话）

1. 「需要自动出单，但是实现方式不一样，需要实现当前产品编码存在对应的出货检验计划就出什么单：
   存在 1PCS 就出功能，存在 1% 出表观，而不是在商品中选择对这个商品选择是或否。」
2. 「首件检验单获取的和出货检验的不同，选取的是成型工艺清单，也是当前存在对应的产品编码就产生。」
3. 「产成品的门禁需要修改，就是存在对应的检验需要完成情况下才需要阻拦……都没有就可以直接入库了。」
4. 入库明细：「应该存在一个生产数量作为接受报工数量的存在，然后实收数量是根据生产数量减去不合格数量自动算出的。」
5. 「直接删除掉这个列吧，否则影响后续的系统判断。」（指 `bs_inv.是否过程检验`）

## 判据（唯一实现：`ProcessInspPlanGate`）

| 单 | 判据（按**产品编码**，取最新一张存活单据） |
|---|---|
| 首件 `QC_FIRST_INSP` | 《成型工艺清单》`rd_mold_proc_head.产品编号` 存在 |
| 出货检验（功能）`QC_PROC_INSP` | 《出货检验计划》最新版明细 `检测频率` 含 `1PCS` |
| 出货检验（表观）`QC_ASM_INSP` | 同一计划明细 `检测频率` 含 `1%`（库里写作「生产量*1%」，按包含判） |

- 频率判定用 `CHARINDEX`（`1%` 里的 `%` 是 LIKE 通配符，不能写 `LIKE '%1%%'`）。
- **出单时机不变**：首件=成型当天首笔报工；功能=成型累计已审报工达该道计划量；表观=进入末道工序。
- 三样都没有 ⇒ 三张单都不自动出（仍可手工「选生产工单」建单）；产成品入库也**不拦**。

## ⚠ 上线前必须知道的数据现状（正式库实测）

改判据后，**自动出单几乎全停**，因为计划/清单覆盖率极低：

- 出货检验计划：**只有 2 个产品**有（1 个含 1PCS、1 个含 1%）；
- 成型工艺清单：**只有 5 个产品**有产品编号；
- 按工单量取前 12 个在用产品实测：**12 个全部「不出单」**（见 `_scratch/insp-plan-recon/InspGateProbe.java` 输出）。

⇒ 要恢复自动出单，须先在《出货检验计划》《成型工艺清单》里补齐对应产品。
在此之前：看板仍会显示「待检验」（按报工量推导），但不会自动出单；入库门禁同样按计划判 ⇒ 不拦。
