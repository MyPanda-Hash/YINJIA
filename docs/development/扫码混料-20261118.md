# 扫码混料(2026-11-18):删掉三个扫码领料入口 + 手机扫码新增「扫码混料」

> 任务来源(用户原话):
> 「把 wms 管理-条码管理里面的扫码领料和扫码领料记录和工单扫码领料删除。然后在手机扫码里面
> 加一个扫码混料的面版。逻辑:扫工单码,带出一级BOM(就是物料清单,之前生产领料的是组装物料清单),
> 逐项扫物料码,自动获取电子秤的数量(我们系统已经有了(之前的工单扫码领料读的就是这个的数据)),
> 提交保存一笔,全部扫完,整单保存。保存后自动打印,并且保留单据,重新扫码后进入可以补打印。
> 前端设计要统一手机扫码的规范」

| 工单扫码领料 | `views/scm/WorkOrderPick.vue` + 路由 `/scm/workOrderPick` + 菜单 `workOrderPick` | 文件删除;路由与菜单项删除;能力由「扫码混料」接替 |

> 通用扫码底座没动:`business/scanPick.js`(`存货编码|批号` 解析)、`nativeScan.js`(App 相机扫码)、

## 二、新增:手机扫码 › 生产扫码登记 › 扫码混料(面板码 `MIX_SCAN`)

### 2.1 作业链路(页面即流程)

> ⚠ **本节是第一版(单页)的口径,已被 §七 第四轮取代**:现在拆成「列表页 + 明细页」两页,
> 扫物料码只解锁、点「确认」才落库,全部确认完毕才可提交。接口对照见 §7.2。

```
扫工单码        GET  /api/px/mix/lines      → 工单行(plang:工单号/行号/产品/产线/排产数量,含 plang.id)
带出一级BOM     GET  /api/px/mix/task       → 《混料物料清单》(MIX_BOM 面板底表 bs_mix_bom)
                                             应投量 = 单件用量 × 排产数量(单件用量 = 单支含量g 换算成存货单位)
         (兼容) GET  /api/px/mix/bom        → 同一份取数的老键名版(子件代码/标准用量…)
逐项扫物料码    (前端解析 `存货编码|批号`)   → 命中清单行 → 读电子秤 /api/dc/monitor(或手输)
提交保存一笔    POST /api/px/mix/scan       → 落 wo_mixing_list 一行(标记 N = 保存前)
全部扫完        POST /api/px/mix/save       → 取混料单号 PL+yyMMdd+4 位 + 标记置 Y(保存后)
保存后自动打印  GET  /api/px/mix/doc        → 打印站点(类型 MIX_SLIP)/ 本机打印兜底
                                          → POST /api/px/mix/printed 累加 asp_print
重扫工单补打印  GET  /api/px/mix/docs       → 该工单已保存的混料单 → 点「补打印」再来一次
```

页面另外两个小接口:**`GET /px/mix/draft`**(重进页面恢复「扫了一半」的草稿 —— 手机熄屏/App 被杀
不该把已投的料丢掉,否则会重复投料)与 **`POST /px/mix/undo`**(撤回本项,只删未保存的行)。

### 2.2 读哪张表:2026-11-18 **二次改口径 → 《混料物料清单》**

| 页面 | 取料表 | 面板 | 说明 |
|---|---|---|---|
| 生产领料(手机扫码) | `bs_asm_bom` | 组装物料清单 `ASM_BOM` | 组装件:炭棒/垫片… |
| **扫码混料(本页)** | **`bs_mix_bom`** | **混料物料清单 `MIX_BOM`** | 投料:炭粉/活性炭… |

🔴 用户 2026-11-18 原话:「扫码混料也是一样,扫工单码查询对应的物料清单,带出需要称重的物料,
**带入的bom从物料清单改为混料物料清单**」—— 上一版读的是遗留表 `mate`(面板 WLBOM《物料清单》),
实测正式库 **0 行**,扫工单永远带不出料。现在取数统一走 `MixBomService`:

- 定位键 = `产品编号` + `烧结类型`;编码先归一(`**TB` / `-tb` 去掉)再匹配;
- 应投量 = `单支含量g × 排产数量`(单支含量g 按存货单位换算:kg ⇒ ÷1000),损耗量恒 0;
- 明细行键沿用旧口径(`物料编号/物料名称/规格型号/单位/标准用量/损耗量/备注`),页面/校验不用改;
- 与「生成工单领料 → 混料领料单」**同源**(`docs/development/混料领料-两张单与物料清单口径.md`);
- 清单没维护/清单被「删除单据」作废时,页面给明确提示(不静默空白)。

⚠ **现状提醒**:`bs_mix_bom` 由「烧结工艺清单 / X烧结工艺清单」**归档**时同步;上线前已归档的老单要先跑
`POST /api/px/procBom/resync`(管理员,幂等)补齐,否则扫工单仍会提示"没有维护用料"。

### 2.3 为什么落 `wo_mixing_list`(混料记录)而不是新开单据表

`wo_mixing_list` 的表注释就是「混料时通过电子称自动获取的实际用量」,现役只读面板
「生产过程 → 混料记录」(`WO_MIXING_LIST`)直连它。字段口径与老系统那 8 行完全同构:

```
单据编号(PL2610210002 这种) / 工单号 / 工单行id / 工单行号 / 序号 /
物料编号 / 物料名称 / 计划用量 / 实际用量 /
标记(N=保存前, Y=保存后) / asp_print(打印次数) / asp_user1 / asp_time1
```

好处:扫完保存的记录**现场立刻能在电脑端「混料记录」查到**,不用再造一份数据、也不用补第二套
面板/权限/译名;「保留单据、重新扫码后补打印」也天然成立(单据就在这张表里)。

**与老系统的一个刻意差别**:老系统每扫一次就插一行(服务器那 8 行里有 6 行是一模一样的同一物料),
现场看不出到底投了几次。本版对「同一工单行 + 同一物料 + 未保存」**累加到同一行**,
并在页面上给「撤回本项」。

### 2.4 前端设计(统一手机扫码规范)

与「其他领料/其他退料/生产领料单」同一套:顶部标题 + 一句说明 → 扫码框(`el-input` + append 按钮)
→ 卡片分区(工单 / 电子秤 / 物料清单 / 已保存单据)→ 底部整单保存大按钮;手机竖屏单列,
电脑宽屏限宽 900。文字一律走 `tt()`,新增词条已写入 `en.js` / `ja.js`。

### 3.1 顺手修的坑:打印代理文件缺 UTF-8 BOM(2026-11-06 起 Windows PowerShell 根本读不了)

`tools/printing/print-agent.ps1` 是 **UTF-8 无 BOM** 的,而本机只有 Windows PowerShell 5.1,
它按 ANSI 读脚本 ⇒ 中文字符串被拆出错字(实测 `powershell -File print-agent.ps1` 直接 39 个
解析错误:`Unexpected token '璁㈠崟鍙?` …),**代理根本起不来**。
这不是本次改动引入的(git 里的上一版同样 39 个错),是 2026-11-06 那次把中文列头写进脚本后
就一直存在的隐患 —— 本批给文件补上 **UTF-8 BOM**(PS 5.1 与 PS 7 都认),`Parser::ParseFile`
解析错误从 39 → **0**,代理实测可启动(`/health` 返回 `mode: Pdf`)。

### 7.5 已知边界

1. 「未完成」的身份是**工单号 + 工单行号**(混料单号要提交才生成),列表里显示「未生成」—— 与生产领料未完成组同一写法;
2. 提交闸门的分母 = 《混料物料清单》行数;清单没维护用料时明细为空、闸门自动放行(否则现场永远提交不了),
   页面在空明细时直接给出「请先在 数据建模 → 生产 → 物料清单 录入」的指引;
3. 「上次混料单」= 该工单行上一锅已保存的号(只作参考,不是本锅单号);
4. 本机没有台车电子秤(读数一直「等待称重」),数量走手输验证;现场秤在线时解锁会**自动填入稳定读数**,
   并按 2026-10-19 的采样教训拦掉负值/过期/跳动读数。
