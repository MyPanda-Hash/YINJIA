## 2. 范围:为什么是"全量"

上一版(`migrate-asm-bom-data-20261030.sql`,2026-10-30)按当时口径只导
「`plang` 在产产品 ∩ Excel 父件」= 236 个产品 / 1085 行;Excel 里另有 581 个产品未进库。
本次按新口径导**全部 827 个 BOM 块**:

| 指标 | 数值 | 说明 |
|---|---|---|
| Excel 数据行 | 3641 | 含末尾 1 行「合计」汇总行(产品名称=`合计`,其余关键列空),丢弃 |
| BOM 块 / 单据 | 827 | 每个块 = 一张单据(单据编号=BOM 编码,如 `A-32-01_V0009`) |
| 父产品 | 817 | 10 个产品各有 2 个版本块 |
| 子件行 | 3640 | 工序全部=组装 |
| 默认BOM='是' | 13 块 | 取数时优先 |
| BOM 级备注非空 | 304 块 | 金蝶第 7 列 `备注`,上一版漏导,本次补上 |
| 行备注非空 | 782 行 | 金蝶第 32 列 |

多版本全部保留,不丢历史版本。代码端(扫码领料 `MobilePickController.latestAsmBom` 与
工序报工 `WorkReportController.asmBomOf`,2026-11-04 起同口径)按
**默认BOM=是 → 版本号 DESC → 单据编号 DESC** 取一张,实测:
`A-48-05` 取 `A-48-05_V0002`(版本号最大)、`B-38-17` 取默认单。

## 4. 脚本设计要点

1. **幂等**:开头 `DELETE FROM dbo.bs_asm_bom WHERE 来源 = N'金蝶BOM引出列表_20261019174847';`
   再全量插入。只动本来源的行,**面板手工新建的 BOM 不动**;可重复执行。
2. **零 DDL**:不建表、不改列、不删表;表/面板/字段元数据沿用 2026-10-30 那套。
3. **计量单位**:先写 Excel `分子单位`,插入后按 `bs_inv.计量单位` 覆盖(存货档案优先;
   档案查不到的保留金蝶分子单位)⇒ 两账套 `missing_unit=0`。
4. **自检**:脚本末尾用 `RAISERROR(severity 16)` 做硬失败 —— 行数/单数/产品数/缺单位/空子件编码/
   行序连续性/标准用量折算/工序/损耗/软删 十个计数,任一不符即 FAIL(DbSync 会判失败并中止)。
5. **与上一版关系**:本脚本是上一版的超集;新环境整链重放时两脚本顺序执行,终态一致。
