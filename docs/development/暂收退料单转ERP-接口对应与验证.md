# 暂收退料单转ERP —— 接口对应与验证(2026-10-19)

> 出自《10.19问题.docx》第 8 条:**「暂收退料单需要转 erp。查看接口文档是否能够对应。并且看测试账套能不能转 erp。」**
> 结论先说:**金蝶侧能对应**(采购退货单 `pur_ret`),**代码已接通**,**测试账套能发出请求并走到金蝶的业务校验**;
> 但当前沙箱**凑不出"可采购原料 + 有库存"的组合**,拿不到一张绿灯单(两轮实推的报错与定性见 §5)。

---

## 一、结论速览

| 问题 | 答案 | 证据 |
|---|---|---|
| 金蝶有对应单据吗? | **有**:采购退货单 `POST /jdy/v2/scm/pur_ret`(单据类型 `pur_bill_outbound`) | `tools/archive/_jdy-doc-catalog.json`:「采购退货单新增及修改」,uniqueId `9e606768712511eda0b32f9e325f49e2`;`GET /jdy/v2/scm/pur_ret` 沙箱可用(0 行) |
| 为什么不用「其他出库单」? | 它**没有 supplier 字段**(资格丢失"退给谁")、且必须写死账套常量 `trans_type_id`,而金蝶无业务类型档案接口 | 同 catalog `inv_other_out` 字段表;`KingdeePushService` 里其他入库/出库那段的注释(2026-10-14 实测) |
| MES 侧字段够吗? | 够,但有 3 处要**反查档案**:供应商(名称→编码)、仓库(名称→编码)、计量单位(名称→id) | `qc_return` 只有 `供应商`/`仓库` 两列**名称**,无编码列;`qc_return_detail.计量单位` 也是名称 |
| 测试账套能转吗? | **能发起、能到金蝶业务校验**,但沙箱数据不满足(库存/商品性质)⇒ 未拿到绿灯单 | 两轮实推:见 §5(金蝶已回单号 `CGTH-20261009-00001` 后以"库存不足"拒单) |
| 推的是哪套金蝶账? | **由 `kingdee.push.*` 凭证决定 = 当前测试沙箱**,与"登录哪个工厂"无关 | `KingdeePushService.assertPushTargetAllowed` + `application.yml` 的 `kingdee.push.allowProd: false`、`deploy/push/config.json` 只有 `sandboxInstanceId` |

## 二、账套口径(最容易被理解错的一条)

「登录哪个工厂」只决定**读/写哪张库**,不决定**推哪套金蝶账**:

| 层 | 真源 | 行为 |
|---|---|---|
| 读/写哪张库 | `DataSourceRouter`(按 JWT 里的工厂声明切库) | 登录「YINJIA-MES」→ `HSDZ_MES`;登录「YINJIA-MES·测试库」→ `HSDZ_MES_TEST` |
| 推哪套金蝶账 | `application.yml` 的 `kingdee.push.*`(运行时也可落 `C:\yinjia\config\application.properties`) | 现值 = **测试沙箱**;真实账套要 `outerInstanceId` 且 `allowProd=true`,否则守卫直接拒绝 |

⇒ 「在测试账套里点转ERP」= 读测试库单据、回写测试库、**推到沙箱**。正式账套同理也推沙箱,这正是 2026-09-20 定下的意图(测试单据绝不写进正式账)。

## 三、字段映射(MES 列 → 金蝶键)

**表头**

| 金蝶键 | 必填 | MES 来源 | 转换规则 |
|---|---|---|---|
| `bill_date` | 建议 | `qc_return.单据日期` | 直传 `yyyy-MM-dd` |
| `supplier_number` | **是** | `qc_return.供应商`(名称) | 先按**编码**直判(`dm_gf.dm`),再按**名称**反查(`dm_gf.mc → dm`);都查不到 **拦截并提示**(不静默推空) |
| `remark` | — | `qc_return.备注` | 追加 `[MES:单据编号]` |
| `outside_pk_id` | — | `qc_return.单据编号` | 直传;金蝶列表可按它过滤,两侧对账用 |
| `return_reason` | — | 头 `退货原因`(实测全空)→ 行 `不良原因` 去重拼接 | 有值才推 |

**明细 `material_entity[]`**

| 金蝶键 | 必填 | MES 来源 | 转换规则 |
|---|---|---|---|
| `material_number` | 是(二选一) | `qc_return_detail.物料编码` | 直传 |
| `material_id` | 是(二选一) | 同上 → `materialMap()` | 解析不到只 warn(不挂源单时 number 够用) |
| `qty` | 是 | `qc_return_detail.退货数量` | 数值 |
| `unit_id` | 是 | `qc_return_detail.计量单位`(名称) | 名称 → `measure_unit` id;解析不到 **硬失败**(沿用其余单据文案) |
| `stock_number` / `stock_id` | 是 | 头 `仓库`(名称)→ `bs_wh.仓库编码` → `storeIds` | 换不到时**回落默认正品仓 CK00001 + 返回消息显式提示**(与其余 7 张单同口径;两个账套 38 张退料单的「仓库」实测全空,硬拦等于功能不可用) |
| `batch_no` | 否 | 行 `批次号` → 头 `批次号` | 仅批次管理商品落库 |
| `price` / `comment` | 否 | 行 `单价` / 行 `备注` | — |

**不推**:`src_bill_no` / `src_seq` / `src_entry_id`(金蝶侧没有对应的采购入库单可挂;硬推会被"源单分录不存在"整单拒绝)、`seq`(该接口字段表无此键)、税金族(MES 行无税率列)。

## 五、测试账套实推记录(2026-10-19)

> 前置:测试库挑一张**已审核**(`yj_doc_status.shr` 非空)的暂收退料单 —— `TH-2026-10-0047`。
> 沙箱档案实况(只读 GET 探测):供应商 86 个(含 `YJ-YFHX` 广东元丰化学试剂有限公司)、单位 26 个(含 kg/支/升/桶)、
> 仓库 21 个;**有库存的只有 `CP-02 成品B仓`(183 行)与 `CK00003`,`CK00001 正品仓 0 行`**。

| 轮次 | 单据改成 | 结果 |
|---|---|---|
| 1 | 供应商=广东元丰化学试剂有限公司、物料 `CL004`(切削液)、单位 `kg`、数量 30、仓库**空** | 金蝶**已受理并生成单号** `CGTH-20261009-00001`,随后以业务规则拒单:<br>`单据[CGTH-20261009-00001]商品[CL004，切削液]在仓库[正品仓]库存扣减后，即时库存不足`<br>⇒ **报文结构/字段/档案解析全部通过**,卡在沙箱无该仓库存 |
| 2 | 供应商同上、物料 `A-32-01`(S阻垢炭棒/滤芯)、单位 `支`、数量 1、仓库 `成品B仓`(沙箱有 2262 支) | 拒单:`基础资料(商品编码)数据不存在或者不符合字段筛选条件：编码"A-32-01"`<br>⇒ 成品不是采购物料,采购退货单不认 |

**定性**:接口与代码链路**已打通**(能过字段校验、能拿到金蝶单号);沙箱当前**没有"可采购原料 + 正品仓有库存"的组合**,故拿不到一张绿灯单。
这不是代码缺陷,是**测试数据缺口**。

**上线/复验步骤**(建议)
1. 在沙箱先做一次**采购入库**(MES 采购入库单「转ERP」即可)把某原料(如 `CL004`)进到 `CK00001`;
2. 再对一张「该原料 + 该仓」的暂收退料单点「转ERP」⇒ 预期 `是否已转ERP=是` + `ERP单号=CGTH-…`;
3. 复核:金蝶 `GET /jdy/v2/scm/pur_ret?bill_no=<ERP单号>` 的供应商/数量/仓库与 MES 一致;
4. 弃审 → 四列被清 → 重审 → 可再转(同其余 7 张单)。

> 两轮实推只改了测试库那**一张**单据的供应商/物料/单位/数量(便于命中沙箱档案),验证后已用
> `tools/archive/_1019-verify/_erp-e2e-restore-test.sql` 还原为原值;正式库(`HSDZ_MES`)**未做过任何写操作**。

## 六、仍未覆盖 / 需业务确认

1. **退货类型**:`qc_return.退货类型` = 退供应商 / 报废 / 让步接收。当前实现**不按类型过滤**(整单推)。
   若"报废 / 让步接收"行不该进采购退货,需要业务给口径再加行级过滤。
2. **仓库全空**:现状 38 张退料单「仓库」全空 ⇒ 一律回落 `CK00001 正品仓` 并在返回消息里提示。
   若要强约束,需业务先定"退料必须选仓",再把默认仓换成硬拦。
3. **`qty` 的 JSON 类型**:本轮被金蝶在**业务规则层**驳回,尚未验证到"类型校验"那一层
   (其余出入库单分两派:数字 / 字符串)。当前按**数字**发送;若首次绿灯单报
   `invalid value for string type`,改成 `plainDecimal(...)` 字符串即可(一行改动)。
