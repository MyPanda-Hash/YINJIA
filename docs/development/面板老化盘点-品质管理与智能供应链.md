## 1 判定口径（为什么不能直接查库）

`yj_panel` **没有 created/updated 时间列**；`config_at` 全库 **141/141 行都是 NULL**（实测）⇒ 库里查不到「这张面板最后一次改是什么时候」。
所以「有没有更新」只能靠**三源证据**拼：

| 源 | 取什么 | 怎么取 |
|---|---|---|
| ① 元数据变更（主证据） | 迁移链里最后一次「改动过含该面板编码的行」的提交 | `git log -G'\bCODE\b'`，路径限定 `tools/*.sql` + `db/`（排除 `tools/archive` 探针、`tools/gen` 台账、`tools/verify`） |
| ② 代码引用 | 前端/后端代码里最后一次提到该面板 | 同上，路径限定 `frontend/src` + `backend/src/main/java` |
| ③ 使用度（旁证） | 业务表/视图行数、角色授权行数、单据状态行数、字段行数 | 动态 SQL 逐面板数（`_q-usage.sql`） |
| ④ 依赖（风险） | 代码引用清单、DB 视图依赖、菜单引用 | 全仓 grep + `sys.sql_expression_dependencies` |

**口径定义**：「9 月后没有修改或更新」= ① 与 ② **都早于 2026-10-01**（含「自初始导入后从未改动」）。

**已知局限（据实声明）**：

- 迁移链是面板变更的唯一正规通道，但**通过界面改权限/列设置**（`yj_role_panel`、`report_column_settings`）不留迁移痕迹，本盘点不计入「面板更新」；
- 极少数**批量脚本按标签/列名改字段、行内不出现面板编码**的情况，pickaxe 可能漏检。已逐个排查 10 月脚本，命中的都是带 `panel_code` 条件的定点脚本（如 `migrate-yjfield-tab-key.sql` 只动 `QC_INSP_REQ`），**未发现漏检**；
- 「0 行数据」**不等于**「没人需要」：报表类面板的空，往往是因为上游单据类型暂时没有业务（见 §3.3）。

## 5 真要下架，按哪条路走

本仓库已有两套先例，选哪套取决于「要不要能回滚」：

| 路线 | 做法 | 先例 | 适用 |
|---|---|---|---|
| **轻：菜单下线，元数据保留** | 只注释 `menus.js` 的入口行，`yj_panel`/`yj_field`/`yj_role_panel` 行原样留着 | `RD_MOLD_FORMULA`、`RD_ASM_BOM`（并入页签）、`WO_ORDER`、`MANU_SCHEDULE`、`STOCK_STATUS`、`PARTNER` | 只是「暂时不想让人看见」；用户说「不需要保存」时不满足 |
| **重：整体下架（含元数据/表/视图/译名）** | 一个幂等迁移脚本：删 `yj_role_panel` → `yj_field` → `yj_panel` → 仅它们使用的 `yj_translation` 词条（必要时连视图/表），脚本头**逐个列出删了什么**，两账套执行，末尾自检「越界数 = 0」 | `migrate-drop-sample-no-panel-2026-09-30.sql`、`migrate-qc-tc-drop.sql`、`migrate-drop-bom-panels.sql`、`migrate-drop-unused-tables.sql`（29 面板 + 244 表） | 用户明确「不要了」 |

重路线落地时必须一起做的（不符合即视为任务未完成）：

1. `menus.js` 入口行注释掉并写明「YYYY-MM-DD 下架 + 恢复办法」；
2. 若面板挂在「业务总览」流程图节点上（`BusinessOverview.vue`）或移动端（`MobileWarehouse.vue`），同步摘除；
3. 后端若有按面板编码特判的服务（`QcDisposalService`、`QueryService`、`PanelConfigService`、`ButtonService`），一并清理；
4. `tools/db-migrations.txt` 登记脚本、`docs/development/数据库表清单.md` 与 `tools/db-inuse-tables.txt` 回写；
5. 两账套（`HSDZ_MES` + `HSDZ_MES_TEST`）都执行并跑到「执行 0、失败 0」。

### 7.1 本轮顺带发现的**预存在**缺陷（不是本次改动引入）

`FINISH_IN_DETAIL`（产成品入库单明细表）与 `FINISH_IN_STATS`（统计表）**打开即 500**：

```
列名 'asp_cancel' 无效  —— SELECT COUNT(*) FROM v_finish_in_detail t WHERE ISNULL(t.asp_cancel,'N')<>'Y'
```

根因：实库 `v_finish_in_detail` / `v_finish_in_stats` 是**初版导入时期的旧定义**（缺报表视图标配的 `id` 与 `asp_cancel` 两列），
