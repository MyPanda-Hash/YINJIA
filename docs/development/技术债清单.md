## 1. 项目实施计划:立项申请 → 实施计划的字段自动带入未实现

**状态**:已定位根因,**暂不修复**(2026-09-10 决定)

**2026-09-11 复核**:仍存在(本轮只改了 RD_PLAN.负责人 只读,refMap 映射容器仍未落地)

**现象**:在项目实施计划里选「文档编号」(参照立项申请)后,只有 3 个通用字段被带回,
业务字段(`测试内容/测试产品打样要求/测试目标/测试条件/测试方法/测试标准`)一个都带不回来。

**根因**:后端 `PanelConfigService.buildRefMap` 只按**同名字段**生成映射。
服务器实测返回的配置是:

```
refMap: [{文件管理人→文件管理人},{密级→密级},{文件使用范围→文件使用范围}]
```

而两边字段名**完全不重叠**:

| 立项申请(RD_APPROVAL) | 实施计划(RD_PLAN) |
|---|---|
| 客户名 / 立项背景 / 机型及应用位置 / **滤芯炭棒规格或结构** / **项目开发目标** / 项目输出 / 开发周期要求 / 其它要求 / 申请立项人 / 申请立项日期 / 文件管理人 / 密级 / 文件使用范围 / 文档编号 | **项目名称** / 项目定级 / **测试内容** / **测试产品打样要求** / **测试目标** / **测试条件** / **测试方法** / **测试标准** / 负责人 / 编制日期 / 文件管理人 / 密级 / 文件使用范围 / 文档编号 |

**已有能力 vs 缺口**:前端 `core/ref/refCarry.js` 的 `applyRefCarry()` 已经支持消费
`ref.map / refMap` 数组;但 **`yj_field` 表里没有存放 refMap 的列** ——
也就是说这套跨面板映射能力目前**无处配置**。

**修复所需**:一张「源字段 → 目标字段」的显式映射表(业务决策,需用户给),
实现上建议在 `buildRefMap` 里加一段针对 RD_PLAN←RD_APPROVAL 的显式映射(不动表结构)。

## 4. RD_INSP_PLAN 产品功能类别:字段的参照取值域 ≠ 自动填充的值域

**状态**:已知,**待业务定见**(2026-09-20 出货检验计划表重排时暴露)

**现象**:本面板 `产品功能类别`(`yj_field` seq 105,`place=header`)是**既有**的
`参照 → RD_PROD_INFO.产品功能类别`;而 `RD_PROD_INFO.产品功能类别` 是下拉框,
字典只有 `除余氯 / VOC / 重金属`(性能功能词)。
但设计纸《出货检验项目控制计划.xlsx》把这一格标为「自动填充规格书」,
`autoFillSpec` 便按设计把它填成**规格书**的 `产品类别`
(20 个品类词:普通炭棒 / 高精度炭棒 / … / 烧结矿化棒)。
**两者取值域不相交** ⇒ 填进去的值落在参照键域之外(能显示、能打印,
但参照弹窗选不中该项,该字段作为参照的一致性被破坏)。

**根因**:设计这一格只有「自动填充规格书」一个来源、**没有手选路径**,
而字段元数据还留着参照 + 弹窗。配置(文本格 + 自动填充)与元数据(参照)两半不一致。

**修复所需**:业务先定这一格的**权威口径** ——

- 若照设计(推荐):该格只由规格书带入 ⇒ 把 `RD_INSP_PLAN.产品功能类别` 的
  `data_type` 改为 `文本`、清空 `ref_panel/ref_field/display_field`,配置一行不动;
- 若要以 `除余氯/VOC/重金属` 为准 ⇒ 规格书侧需先有该口径的列(现无),
  且这一格不再由规格书自动填,需回到手选 —— 与设计原文冲突。

⚠ 该字段是既有共享元数据,**未擅自改**,以免影响本面板通用表单的渲染。

## 6. 实施计划→进度查询:进度单不存在时**静默跳过**,且无人自动建那张单

**状态**:已知,**未修**(2026-09-22 走查项目管理流程时实测)

**现象**:走查时本机库 `rd_progress` **0 行** ⇒ 点「阶段完成」后端照样返回
`{"code":200,"message":"success"}`(还带 `实际完成` 日期),但进度查询里**一行都没有**;
用户完全看不出是"没生效"还是"没数据"。

**根因**(两段,都在后端):

1. `ButtonService.syncPlanToProgress` 取目标单:`SELECT TOP 1 [单据编号] FROM rd_progress
   WHERE ISNULL(asp_cancel,'N') <> 'Y' ORDER BY [单据编号] DESC`,**取不到就
   `logger.warn("...没有可用的项目进度查询单据,跳过导入 项目={}")` 并 `return RES_SKIPPED`**
   (`ButtonService.java:2246-2252`)——调用方(`completeStage`)不看这个返回值,于是前端拿到 200。
2. **没有任何代码会创建那张唯一进度单**(全 backend grep `INTO rd_progress` 无命中)。
   它靠 `tools/seed-rd-progress.sql` 手工种(该脚本在迁移清单里);而 RD_PROGRESS 面板
   **没有「新增」入口**(单单据面板),界面上的路只有「开空单 → 点保存」——
   本次走查就是这么建出 `LXJ-2026-09-0006` 的,但不直观、也没人告诉用户。

**影响**:那张单一旦被删(本机就是这么坏的),整条「实施计划 → 阶段完成 → 进度查询」链
**静默失效**,且进度明细里会留下**孤儿行**(见下条)。

**修复所需**(建议,待定见):① `syncPlanToProgress` 取不到目标单时**自动建一张**
(用号池发号,等同空单保存),或至少把 `RES_SKIPPED` 冒泡成可提示的结果;
② 面板上加一个「还没有进度单,点此创建」的空态引导。

## 8. 「阶段完成」不校验计划内容 ⇒ 进度行显示为空,看起来像同步没生效

**状态**:已知,未定见(2026-09-22 实测)

`syncPlanToProgress` 统计进度时**先看该阶段有没有「阶段N_计划内容」,空则 `continue`**
(`ButtonService.java:2227-2228`),连这一阶段的**实际完成日期也不计入**;
而 UI 的「阶段完成」按钮**只要求单据非草稿**(`DocSheet.vue:480`),
不要求先填计划内容 ⇒ 用户对空阶段点完成,进度行会落成 `状态=已立项`、`里程完成=null`,
看上去像"同步没生效"(本次走查第一遍就是这个现象,补上计划内容后立刻变成 `全部完成(1/1)`)。

**修复所需**:二选一 —— ①「阶段完成」前置校验该阶段计划内容非空(提示更明确);
② 同步改为按「实际完成」独立计入(与计划内容解耦),`totalStages` 另算。
