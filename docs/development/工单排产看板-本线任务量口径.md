# 工单排产看板「本线任务量」口径（2026-11-12 基线）

> 本文件是**工单排产页（`WORK_ORDER_BOARD` / `frontend/src/views/modules/plan/WorkOrderBoard.vue`）**
> 三处数字的唯一口径基线：**左侧每线数字、顶部统计、右侧排产明细**。改这三处之前先读这里。
> 2026-11-19 追加**右下角「未完成数量」框**（勾车间合计，见 §2.5）：它是**成品口径**，
> 与上面三处的工序口径不是同一把尺，别拿它去和左侧/顶部「未完工量」对账。
> 起因：用户报障「左侧边栏显示的数量和当前的生产线排产数量（本线排产数量）和当前工序报工数量
> 没有任何关联」——同一屏三处数字各说各话。全过程与证据：`tools/archive/_wo-line-consistency-20261112/`。

## 1. 页面结构（一行 = 什么）

选中左侧一条线后，右侧「排产明细」的一行 = **一张工单行 × 该线要做的当前工序**。行有两种来源：

| 行来源 | 取数 | 何时出现 |
|---|---|---|
| `当前线` | `plang_pc.scx = 选中线`（工单**当前**线就是这条线） | 工单已排到该线且未完工 |
| `本线工序` | `wo_process_line` 台账归该线、但工单当前线不在该线（「后道可见」） | 台账该道状态 = **已落实**（上一道已有量流下来） |

两种行都带 `本线排产数量`（= 该行当前工序的**台账计划数量**，缺失回落 `排产数量 × 该道换算率`）
和 `当前工序完工量`（= 该道**已审**报工量，行锚定 `scjl.gd_id → plang_pc.plang_id`）。

## 2. 三处数字的唯一定义

```
行级：本线计划 = 该行当前工序的台账计划数量
      本线已报 = 该行当前工序已审报工量
      行未完工 = max(本线计划 − 本线已报, 0)        ← 逐行截断

左栏（每条线）：本线排产数量   = Σ 本线计划      （该线「未完工」页签那批行）
                本线已报完工量 = Σ 本线已报
                本线未完工量   = Σ 行未完工
顶部（选中线）： 本线排产数量   = Σ 本线计划      （当前页签下的行 = 明细表合计）
                已报完工量     = Σ 本线已报
                未完工量       = Σ 行未完工
```

**一致性是构造出来的**，不是人工对账：

- 后端 `ScheduleBoardService` 里 `curOpExpr()` / `planQtyExpr(op)` / `reportedQtyExpr(op)`
  是**唯一**表达式；`scheduled()`（明细）、`today()`（快速排产②）、`linesSummary()`（左栏）
  三处**只拼这三个方法**，禁止再写等价子查询。
- `linesSummary` 的 A 类（当前线）/ B 类（本线工序）过滤条件与 `scheduled` 主查询 / `lineProcessRows`
  逐条对齐；B 类还共用 `(工单行, 工序, 归线)` 的 `ROW_NUMBER` 去重规则。
- 左栏固定按「未完工」页签口径（不随右侧页签切）；右侧顶部统计跟随页签 ——
  **默认「未完工」页签下：左栏该线数字 = 顶部「本线排产数量」**。

## 2.5 右下角「未完成数量」框（2026-11-19 追加；2026-11-20 按反馈修正，成品口径）

用户口径①：「增加一个未完成数量的查看实现。勾选车间查看当前勾选车间的未完成数量在右下方蓝色边框内；
不勾选时右下方显示当前车间未完成量……当前存在的应该是在图中存在一个历史未完成量，
需要修改为右下方的蓝色框内，当前只实现了单个车间当前查看的情况。」
用户口径②（2026-11-20）：「没有完成勾选对应车间，当前实现的是选择的对应**类型**的车间
（成型/切炭/组装）而不是选择车间；但是数量需要区分车间这一点确实没啥问题。」

```
未完成数量（框内）= Σ linesSummary.未交量，只累加「勾选车间」/「当前车间」的产线
未交量（每条线）  = Σ max(排产数量 − 入库数量, 0)   ← 成品口径，与顶部「总未完成量」同一把尺
```

- **勾车间**：勾选位置 = **左侧每条生产线（用户口中的「车间」：1号车间 / 成型1线 / …）**，
  勾几条就合计几条线的 `未交量`；不再按成型/切炭/组装这种「车间类型」勾选。
- **不勾**：当前选中生产线（车间）；**未选线**：全部车间（等价顶部总未完成量）。
- 与 §2 的工序口径（本线排产数量 / 本线未完工量）**不可互相替代**：
  前者是成品还欠多少，后者是当前工序还剩多少没报工。
- 实测（正式库 2026-11-19，开工日 2026-11-19）：30 条线 `Σ未交量 = 29449`
  = `/px/scheduleBoard/stats` 的 `总未完成量`；成型 23239 / 切炭 6200 / 组装 10。
- 原顶部「历史未完成」通栏红条按用户口径**并入该框底部**（处数 + 原计划 − 报工 = 欠产，
  悬停看逐条明细）；历史欠产仍按当前选中线的明细算，不随车间勾选跨线汇总。
- 实现：`WorkOrderBoard.vue` 的 `pickedLines / unfLines / unfQty`（数据源 `linesSummary.未交量`；
  勾选框在左侧 `.wb-line` 每行 `.wb-line-pick`）。

## 3. 数据前置条件（会破坏口径的四件事）

1. **台账权威键 = `工单行id`**，`工单号` 只是兼容/展示列。
   所有读台账的地方用 `(工单行id=? OR (工单行id IS NULL AND 工单号=?))`
   （`ScheduleBoardService.ledgerOfRow`、`ProcessFlow.ledgerPlanQty`、`ProcessTaskService.applyNextProcess`）。
   2026-10-10 之前建的历史台账行存错过工单号 ⇒ 已由
   `tools/migrate-wo-ledger-rowid-align-20261112.sql` 回正 + 按行id 重算（两账套已执行）。
2. **台账状态（计划/已落实/已完工）由 `ProcessFlow` 按量流转口径维护**；状态漂移会让
   「本线工序任务」把已完工的行当成待做活。看板侧另有一道兜底：`lineProcessRows` 对
   **整张工单行已完工/已结案**的行一律不显示（仅未完工/全部页签；已完工页签保留历史）。
3. **`本线未完工量` 必须逐行截断**（`max(计划−已报,0)` 再求和）；先求和再相减会让某行超报抵掉别行缺口。
4. **跨工序不可加**：成型件 + 装箱件的「本线排产数量」不是同一单位。只在同工序/同车间内看合计；
   成品口径（整单还欠多少）看 tooltip 里的 `Σ未交量 = Σmax(排产−入库,0)`。

## 4.5 明细表里「需交付 / 已排 / 未交量」的口径（2026-11-15 追加，别混）

| 列 | 口径 | 算式 / 来源 |
|---|---|---|
| 7天/15天/大于15天**需交付** | **工序口径** | **工序计划量**（排产数量 × 该道换算率）按交期落桶 —— 2026-11-15 起（原来是「需求数量」成品口径；用户口径「这里原来也应该是工序计划量的」） |
| 7天/15天/大于15天**已排** | 工序口径 | 日计划（自动均摊 ∪ 人工指定）按日期落桶，`≤7`/`≤15` 为累计 |
| **未交量** | **成品口径** | `排产数量 − 入库数量`（不足 0 记 0），按工单行；=「当前整个工单剩余的成品数量」（用户 2026-11-15 再次确认） |
| 本线排产数量 / 当前工序计划量 | 工序口径 | 台账计划数量优先，缺失回落 排产 × 该道换算率 |
| 需求数量 / 排产数量 / 入库数量 / 订单数量 | 成品口径 | `plang.xq_sl` / `plang.pl_sl` / `plang.rk_sl` |

> 生产工单页与工单排产页共用 `WorkOrderDayPlanService.data()` 的三桶；改这些列前先读本节
> 与 `docs/development/工单追溯-工序口径数量-20261115.md` §6。
