# 金蝶采购入库单:一张单里能不能混装多张采购订单(2026-11-13 核查)

> 用户问题:「金蝶的采购入库单,能不能做到不同采购订单在同一张入库单里(通过采购订单和采购订单行号来对应和回填采购数据)?查一下真实账套里面有没有出现这样的单据」。
> 本文只记录**只读取证**结论;没有改库、没有改代码、没有改面板字段。

## 一、结论(先看这三条)

1. **金蝶能,而且真实账套里是常态** —— 真实账套(星辰 `clientId 359797`)全量 3647 张采购入库单、
   9102 行,**1146 张(31.4%)含 2 个及以上不同采购订单**,最多一张挂 **12 张订单**
   (`CGRK-20250930-00843`,17 行)。这些单**全部已审核(`bill_status=C`)**,行上的订单行号
   **没有一行缺失**(`src_seq` 空值 0)。
2. **"对应关系"全在行级,表头没有采购订单字段** —— 金蝶 `pur_inbound` 表头无 `src_bill_no`;
   每行各自带 `src_bill_no`(订单号)+ `src_seq`(订单行号)+ `src_bill_type_id/number`(常量
   `pur_bill_order`)+ `src_inter_id`(订单单据 id)+ `src_entry_id`(订单分录 id)。
   于是"回填采购数据"就是**按行 join 订单行**:MES 本地 `bl_pu_order` 已有 `行号`/`基本数量`/
   `行已执行数量`/`行未执行数量`/`行入库状态`(同步自金蝶,目前全隐藏),`(源单编号,源单行号)`
   对得上 `(单据编号,行号)` 即可。
3. **MES 现在做不到,而且连"看得见"都做不到** —— MES 采购入库单的订单是**表头单值**
   (`bd_purchase_in.采购订单号`),转 ERP 时**整单所有行都推同一个订单号**
   (`KingdeePushService`:443 / 624 / 633);行级 `源单编号` 是隐藏字段、**全库 0 行有值**;
   金蝶导进来的 313 张入库单里 **122 张在金蝶侧本来就是多订单混装**,而 MES 侧
   **表头订单号 0/313 有值、行源单编号 0 行有值** —— 多订单信息在导入时就丢了。

## 三、MES 现状(为什么"做不到",以及坏在哪)

| 环节 | 现状 | 证据 |
|---|---|---|
| 数据模型 | 表头 `bd_purchase_in.采购订单号` **单值**;行上 `源单编号`(订单号)/`源单行号`(订单行号)两列**都在**,与金蝶同名同义 | `migrate-po-inbound-fields.sql`、`yj_field` `PURCHASE_IN` |
| 面板 | 表头「采购订单号」可见;**行「源单编号」`visible=0,hidden=1`**;行只显示「采购订单行号」 | `yj_field`:`采购订单号` seq160 header / `源单编号` seq670 hidden / `采购订单行号`(=列 `源单行号`) seq290 |
| 转 ERP | 取**表头**一个 `poNo`,解析一次 `PoRefs`,然后**每一行**都写同一个 `src_bill_no`(注释原文:"同单全部行带同一订单号") | `KingdeePushService` 443-466、624-651 |
| 生单 / 选单 | 一次只认**一张**来源单(头映射取来源单头);批量生单 = 每张来源单各生一张目标单,不合并 | `PushGenerateHandler.generateLines`(入参 `sourceNo` 单数)、`PanelxForm.vue::confirmSelect`(`const first = selectRows[0]` 做 headerMap,明细整表替换) |
| 链路字段 | 采购订单号/行号沿 订单→暂收→检验→入库 逐站下传,但**头只有一个订单号** ⇒ 全链天然"一单一个订单" | `PanelConfigService` FLOW_HEAD_MAPS(`PU_ORDER|QC_RECV`、`QC_RECV|QC_INSP`、`QC_INSP|PURCHASE_IN`) |
| 金蝶导入 | 采购入库单**没有接入 `deploy/sync.mjs`**,313 张是按金蝶号(CGRK-*)落库的存量,`src_*` 族**一个都没映射** | `deploy/sync-core.mjs` 的 DOCS 无 `PURCHASE_IN`;库里实测见下 |

MES 库实测(`HSDZ_MES`,`2026-11-13`):

```
bd_purchase_in      376 张   头「采购订单号」有值 11 张(CGRK-* 的 313 张里 0 张)
bl_purchase_in      979 行   行「源单编号」有值 0 行(「源单行号」23 行)
CGRK-* 313 张 —— 其中 122 张在金蝶侧是多订单混装;MES 里全都看不出订单(头空、行空)
```

> 结论:MES 现在**既不能录、也不能转、也不能查**"一张入库单多个采购订单";
> 且**历史 313 张金蝶入库单的订单关联已永久丢失**(只能按 `单据编号` 回金蝶反查)。

## 四、要做到"一单多订单",需要动的四处(评估用,本次未实施)

1. **行级落点**:放开 `bl_purchase_in.源单编号`(订单号)+ 现有 `源单行号`(订单行号),
   在明细里成对可见;表头「采购订单号」改为派生展示(单订单显示号、多订单显示"多单"或留空)。
2. **转 ERP 按行解析**:`PoRefs` 缓存键从"整单一个 `poNo`"改为 **按行订单号** keyed
   (`src_inter_id` 必须逐行取该订单的 id),否则多订单单会被金蝶判"源单分录不存在"整单拒绝
   (这条坑 `deploy/采购入库单字段接口核对.md` §6 已实测过)。
3. **生单/选单允许跨来源单合并**:头映射改"同来源才带、多来源留空";选单明细要**追加**而不是整表替换
   (`PanelxForm.confirmSelect` 目前是 `detailData[key] = rows`)。
4. **接金蝶入库单同步/导入必须映射 `src_bill_no`/`src_seq`/`src_bill_type_*`/`src_inter_id`/`src_entry_id`**,
   否则重导一次仍然丢订单关联。
5. (回填"采购数据"本身零成本)`(源单编号,源单行号) → bl_pu_order(单据编号,行号)` join 就可取
   `行已执行数量`/`行未执行数量`/`行入库状态`/`基本数量` —— 这些列**已在库里**,只是没有可 join 的行级订单号。
