## 二、必须回答的问题:现在的期初库存「算不算无库存」?

**结论:不算「无库存」。现在是「有库存、但不区分批次」。**

实测(HSDZ_MES,2026-10-19):

| 项 | 实测值 |
|---|---:|
| `kucun` 中 `PC0000`(无批次)行 | **1,442 行** |
| 其中正结存 / 负结存 / 零 | 1,268 / **148** / 26 |
| `PC0000` 行余量合计 | **+3,257,783.37** |
| 全体负结存行 470 行中 `PC0000` | **148 行 / −804,015.16**(占负余量 82%) |
| 其它批号负结存 | 283 行 / −174,235.00 |

**关键判据** —— 含 `PC0000` 行的 1,442 个物料仓库组合按 `(物料, 仓库)` 合计:

| 情形 | 组合数 | 含义 |
|---|---:|---|
| **C 总账为正、PC0000 行也非负** | **1,275** | 正常,库存实打实在 |
| **A 总账为正、但 PC0000 行是负的** | **117** | **假负数**:货在(其它批次上),只是记错了批次 |
| **B 总账本身为负** | **2** | 真缺货 |
| D 其它 | 48 | — |

⇒ **470 行负结存里,真正的缺货只有 2 个组合(缺口合计 −17,447)**。
其余是**批次口径错配**造成的假象 —— 库存并没有丢。

> ### ⚠ 这正是「验收能过」的底气,也是「上线必须重做」的原因
> 现在放行出的每一笔「无批次出库」,都**不落到任何真实批次上**。
> 验收期没问题(总账对得上金蝶);但一旦要求追溯,现在的账里**查不出这批货是哪一批出的**。

## 三、`PC0000` 到底是什么(取证结论)

| 问题 | 结论 |
|---|---|
| 是 MES 编的吗? | **不是**。是**金蝶云·星辰自身的默认批号**;`ButtonService.java:429` 注释明确写「金蝶默认占位 `PC0000`」,MES 只是照搬 |
| 金蝶里占比 | 9–10 月真实收发 5,728 行中 **4,065 行**批号是 `PC0000`(**71%**) |
| 为什么会有 | 金蝶商品档案 3,878 个中,**未启用批次管理 1,472 个**;无批次商品的单据行,金蝶统一填 `PC0000` 而非留空 |
| 语义 | 在金蝶里 **「空批号」≡「PC0000」**,都表示「这一行不做批次管理」 |
| MES 的问题 | MES 把 `PC0000` 当成**真实批号**参与 `kucun` 三键 `(物料, 仓库, 批号)` 分账 ⇒ 拆成 27 行,行行对不上 |
| 数据来历 | MES 材料出库单的 `PC0000` 行**全部** `asp_user1='admin'`、`asp_time1=2026-10-14 21:09:04`(同一秒)⇒ 是 **10-14 批量导库**形成的,不是现场录入 |

按 (物料,仓库) 分类的 453 组里:**212 组有真实入库批号但出库全记 PC0000**(纯错配)、52 组两边都有、189 组入库本身也无真实批号。

## 四、验收期方案(当前执行)

**目标**:让「无批次号」的出库正常通过,先过验收。

| # | 措施 | 状态 |
|---|---|---|
| 1 | 出库校验**改按 `(物料, 仓库)` 汇总**判断,不再要求该 `批号` 行本身有余额 | ✅ 已实施(2026-10-19) |
| 2 | 出库行批号可空 / 可为 `PC0000`,**不强制** | ✅ 已实施(同上) |
| 3 | 扣减顺序:先扣本行批号 → 不够按结存从大到小扣同物料同仓其它批次 → 仍不足则记到本行批号(让其显负) | ✅ 已实施(同上) |
| 4 | 负库存告警 / 库存状况表按 `(物料, 仓库)` 呈现时不再误报 | ⏳ 待做(告警仍按批号行报) |

**代码落点**:`StockLedgerService.LOT_STRICT = false`(2026-10-19)。
设为 `false` 时立即使 `applyOut` 走 `applyOutAggregated()`;上线当天改回 `true` 即恢复按批号核销,
`applyOutAggregated` 不再被调用(**不需要改任何别的代码**)。

⚠ **验收通过 ≠ 可以就这样上线**。措施 1~3 全部是「忽略批次」的权宜之计。

## 五、正式上线当天必须做的事(清单)

### 5.1 重新导入金蝶期初

- 用 `/jdy/v2/scm/inventory?point_date=<上线日的前一天>` 取**上线时点**的金蝶库存(不要用 2026-08-31 那份,那是验收期的);
- 导入前**清空**既有所有期初:`INIT-*`(src=0)、`JZ-*`(月结结转)、`kucun` 表;
- 同时写 `inh` 期初行 + `kucun`,口径见可行性核查文档 §六。

### 5.2 所有出库必填批次号

- **材料出库 / 销售出库 / 其他出库** 三张单的行批号改为**必填**(前端必填 + 后端守卫);
- 扫码带批号(`StockLedgerService.applyOut` 已有「出库行缺少[批号]」守卫,届时**打开**即可,见其 `HIST_BACKFILL` 开关);
- `PC0000` 不再作为合法出库批号(仅可作为历史数据的显示值)。

### 5.3 先进先出:日期在前的先出库

- 出库时按 `入库单据日期` 升序**推荐/强制**取批次(FIFO);
- **允许一张出库单跨多个批次**,按批次分行出库(用户口径:「可以多批出库,但是出库要按批次号来算」);
- 每行出库必须**精确落到某一批次**上,`kucun` 按 `(物料, 仓库, 批号)` 逐行核销。

### 5.4 验收标准(上线前必须逐条通过)

```
① 每键:期初 + 全部流水  ==  金蝶 point_date 现存量        (键 = 物料+仓库+批号)
② kucun 负结存行数 == 0(真缺货除外,且需人工说明)
③ 随机抽 20 张出库单,每一行的批号都能在 kucun 找到对应批次且有足够余额
④ 每批次可反查到 入库单据 → 供应商 → 生产日期(追溯闭环)
```
