## 2. 从 light-mes 同步升级的流程

1. 对比 `frontend/src`(排除 business/menus.js 与既有适配点),复制差异文件。
2. 重新套用 YINJIA 适配清单:menus.js(面板菜单)、engine.js(数据源注释/字段键扩展/refRowCount/refSelectOptions/saveColumnPrefs)、品牌文案(index.html/router/LeftNav/TopBar/PanelxList/PanelxForm)、vite 代理端口、package.json 名称、PanelxList 单据切换按钮对 singleDoc 面板隐藏(singleDocMode)、参照字段双模(refModeMap)、列头点击筛选(colFilterText)、表格列自定义对话框(colPrefVisible)、OrgAdmin 面板授权分组改为后端 modules 驱动。
3. 后端按 light-mes 新架构对齐(panel 包/契约),数据层保持 HSDZ_MES 适配。
4. 同步后运行前端构建 + `tools\verify-api.ps1` 全链路验证。

### 🔴 列名安全规范(2026-08-31 起强制,违反 = 生产报错)

**问题根因**:SQL Server 中列名含 `%`(税率%)、`.`(部门.负责人)、空格等特殊字符时,未加方括号的 `t.列名` 会触发语法错误;后端 `QueryService`/`ButtonService` 的动态 SQL 已统一加 `t.[列名]`,但 **yj_field.col_name 与物理表列名必须一致**,改名时漏同步即报"列名无效"。

| 规则 | 说明 | 违反后果 |
|---|---|---|
| **列名禁止含 `.`** | light-mes 迁入的复合字段名(如 `存货名称.品牌`)必须改为无点形式(如 `品牌`) | SQL 解析为表.列 → 语法错误 |
| **列名含 `%` 必须方括号** | `税率%`、`折扣%` 等在 SQL 中必须写成 `[税率%]` | `%` 被解析为取模 → 语法错误 |
| **改名三处同步** | 物理列名(sp_rename) + yj_field.col_name + 视图定义,三处必须同步更新 | 列名不匹配 → "列名无效" |
| **报表面板字段从视图自动发现** | 视图重建后必须重新注册 yj_field(从 sys.columns 自动发现),不可手工硬编码 | 字段引用不存在的列 → 查询报错 |

**修复流程**(列名出问题时):
```sql
-- 1. 改物理列名
EXEC sp_rename '表.[旧列名]', N'新列名', 'COLUMN';
-- 2. 同步 yj_field
UPDATE yj_field SET col_name=N'新列名', label=N'新列名' WHERE panel_code='XX' AND col_name=N'旧列名';
-- 3. 重建视图(用新列名)
-- 4. 重新注册报表面板字段(从视图列自动发现)
```

### 3.1 多语言开发规范(2026-08-30 起强制,违反=功能未完成)

> 判定标准:**切到英语/日语后,新功能显示目标语言而非中文**。
> AI 开发者由根目录 `AGENTS.md` 自动注入本规范;红线见 `docs/adr/0001`。

| 场景 | 必做动作 | 模板 |
|---|---|---|
| **新增面板** | yj_panel 插行后,同步插入译名(至少 en,鼓励全语言) | `INSERT INTO yj_translation (scope, ref_key, locale, text, source) VALUES ('panel', N'<面板中文名>', 'en', N'<英文>', 'manual')` |
| **新增字段** | yj_field 插行后,同步插入译名;已有译名的标签(数量/备注等)免插 | `('field', N'<字段中文标签>', 'en', N'<英文>', 'manual')` |
| **前端新 UI 文案** | 显示层一律 `tt('中文原文')`(import { tt } from '@/i18n'),译名进 `src/i18n/locales/*.js` 至少 en.js;占位符/tooltip/标题同走 tt() | `{{ tt('保存') }}` |
| **后端新接口文案** | 面板配置/公告等返回内容按 `TranslationService` + `Accept-Language` 供给译名,键保持中文 | 参考 `PanelConfigService.fieldSpec` |
| **新增语言** | yj_locale 插行即可,切换器自动出现,词条机翻初始化 | `INSERT INTO yj_locale VALUES ('ar', N'阿拉伯语', N'العربية', 1, 100)` |

**红线(ADR-0001,永不触碰)**:
- `dataName`/`buttonName`/单据状态存储值等**数据键永远中文**,不随语言变化
- 业务事实数据(客户法定名/单据号/用户输入)**不做翻译**,原样显示
- 机翻仅兜底显示层零星词条,结果缓存进 yj_translation(source='mt'),人工可校对(source='manual' 优先)

**提交前自检**:切 en(或 ja)→ 走查新增页面 → 列头/字段标签/按钮/提示全部目标语言;
`npm run build` 通过;涉及翻译数据变更时 SQL 脚本 UTF-8 无 BOM + `-f 65001` 执行(见 tools/i18n-*.sql 惯例)。

**机翻批量初始化(一次性补齐历史翻译)**:
- 密钥:`backend\.env`(gitignored,不入库)写入 `ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET`;
  `start-project.bat` 启动前自动 source;缺失时翻译/OCR 自动降级,接口返回中文原文。
- 全量触发:`tools\trigger-mt.ps1`——keys 真源 = yj_panel.panel_name + yj_field.label(仅含中文),
  逐语言 POST `/api/locale/dict`(后端阿里云机翻,结果缓存 scope='ui'),
  再按真源表把 ui 结果拷入 scope='field'/'panel'(缺哪补哪,幂等可重跑)。
- 注意:同名字段/面板(如「部门」既是面板名又是字段标签)在 field 已有译名时
  /dict 视为命中、不产生 ui 行,交叉 scope 拷贝(ui+field→panel、ui+panel→field)兜住。
- 验证:`tools\i18n-verify-multi.cjs <locale> <panelCode>`(CDP 无头 Edge,
  断言列头/字段标签/标题为目标语言字符集;ja 判假名、ko 判谚文、其余判无 CJK)。

## 4. 测试与验证

1. 提交前:`tools\verify-api.ps1`(18 步:登录→配置→查询→保存→审核→409→弃审作废→档案全量保存→描述符→dashboard→库存→通知→OCR)。
2. 全量面板回归:`tools\audit-panels.ps1`——76 面板逐个 getPanelConfig + queryFormDataList(暴露视图/列缺失)+ DB 静态校验(表/视图存在性、yj_field 列按 header/detail 分表比对);`tools\audit-conditions.ps1`——带 condition 筛选查询冒烟(暴露参照字段映射错误);`tools\panels-ui-smoke.cjs`——CDP 批量打开代表面板并捕获 console 报错。
3. 前端 `npm run build` 必须通过。
4. 涉及元数据变更时重跑 `setup-db.sql` 后再验证。

## 5. 安全要求

- JWT 密钥、数据库口令、OCR 密钥生产环境一律环境变量注入;代码仓库不落真实凭据。
- 登录失败、权限不足使用中性文案;日志不输出 Token/密码/完整连接串。
- 上传(OCR)限制 10MB 与图片格式;用户级限流(默认 10 次/分钟)。
