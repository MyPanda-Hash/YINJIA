## 2. 从 light-mes 同步升级的流程

1. 对比 `frontend/src`(排除 business/menus.js 与既有适配点),复制差异文件。
2. 重新套用 YINJIA 适配清单:menus.js(面板菜单)、engine.js(数据源注释/字段键扩展/refRowCount/refSelectOptions/saveColumnPrefs)、品牌文案(index.html/router/LeftNav/TopBar/PanelxList/PanelxForm)、vite 代理端口、package.json 名称、PanelxList 单据切换按钮对 singleDoc 面板隐藏(singleDocMode)、参照字段双模(refModeMap)、列头点击筛选(colFilterText)、表格列自定义对话框(colPrefVisible)、OrgAdmin 面板授权分组改为后端 modules 驱动。
3. 后端按 light-mes 新架构对齐(panel 包/契约),数据层保持 HSDZ_MES 适配。
4. 同步后运行前端构建 + `tools/scripts/verify-api.ps1` 全链路验证。

### 🔴 列名安全规范(2026-08-31 起强制,违反 = 生产报错)

**问题根因**:SQL Server 中列名含 `%`(税率%)、`.`(部门.负责人)、空格等特殊字符时,未加方括号的 `t.列名` 会触发语法错误;后端 `QueryService`/`ButtonService` 的动态 SQL 已统一加 `t.[列名]`,但 **yj_field.col_name 与物理表列名必须一致**,改名时漏同步即报"列名无效"。

| 规则 | 说明 | 违反后果 |
|---|---|---|
| **列名禁止含 `.`** | light-mes 迁入的复合字段名(如 `存货名称.品牌`)必须改为无点形式(如 `品牌`) | SQL 解析为表.列 → 语法错误 |
| **列名含 `%` 必须方括号** | `税率%`、`折扣%` 等在 SQL 中必须写成 `[税率%]` | `%` 被解析为取模 → 语法错误 |
| **改名三处同步** | 物理列名(sp_rename) + yj_field.col_name + 视图定义,三处必须同步更新 | 列名不匹配 → "列名无效" |
| **报表面板字段从视图自动发现** | 视图重建后必须重新注册 yj_field(从 sys.columns 自动发现),不可手工硬编码 | 字段引用不存在的列 → 查询报错 |

**修复流程**(列名出问题时):
```sql
-- 1. 改物理列名
EXEC sp_rename '表.[旧列名]', N'新列名', 'COLUMN';
-- 2. 同步 yj_field
UPDATE yj_field SET col_name=N'新列名', label=N'新列名' WHERE panel_code='XX' AND col_name=N'旧列名';
-- 3. 重建视图(用新列名)
-- 4. 重新注册报表面板字段(从视图列自动发现)
```

### 3.1 多语言开发规范(2026-08-30 起强制,违反=功能未完成)

> 判定标准:**切到英语/日语后,新功能显示目标语言而非中文**。
> AI 开发者由根目录 `AGENTS.md` 自动注入本规范;红线见 `docs/adr/0001`。

| 场景 | 必做动作 | 模板 |
|---|---|---|
| **新增面板** | yj_panel 插行后,同步插入译名(至少 en,鼓励全语言) | `INSERT INTO yj_translation (scope, ref_key, locale, text, source) VALUES ('panel', N'<面板中文名>', 'en', N'<英文>', 'manual')` |
| **新增字段** | yj_field 插行后,同步插入译名;已有译名的标签(数量/备注等)免插 | `('field', N'<字段中文标签>', 'en', N'<英文>', 'manual')` |
| **前端新 UI 文案** | 显示层一律 `tt('中文原文')`(import { tt } from '@/i18n'),译名进 `src/i18n/locales/*.js` 至少 en.js;占位符/tooltip/标题同走 tt() | `{{ tt('保存') }}` |
| **后端新接口文案** | 面板配置/公告等返回内容按 `TranslationService` + `Accept-Language` 供给译名,键保持中文 | 参考 `PanelConfigService.fieldSpec` |
| **新增语言** | yj_locale 插行即可,切换器自动出现,词条机翻初始化 | `INSERT INTO yj_locale VALUES ('ar', N'阿拉伯语', N'العربية', 1, 100)` |

**红线(ADR-0001,永不触碰)**:
- `dataName`/`buttonName`/单据状态存储值等**数据键永远中文**,不随语言变化
- 业务事实数据(客户法定名/单据号/用户输入)**不做翻译**,原样显示
- 机翻仅兜底显示层零星词条,结果缓存进 yj_translation(source='mt'),人工可校对(source='manual' 优先)

**提交前自检**:切 en(或 ja)→ 走查新增页面 → 列头/字段标签/按钮/提示全部目标语言;
`npm run build` 通过;涉及翻译数据变更时 SQL 脚本 UTF-8 无 BOM + `-f 65001` 执行(见 tools/i18n-*.sql 惯例)。

**机翻批量初始化(一次性补齐历史翻译)**:
- 密钥:`backend\.env`(gitignored,不入库)写入 `ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET`;
  `start-project.bat` 启动前自动 source;缺失时翻译/OCR 自动降级,接口返回中文原文。
- 全量触发:`tools/scripts/trigger-mt.ps1`——keys 真源 = yj_panel.panel_name + yj_field.label(仅含中文),
  逐语言 POST `/api/locale/dict`(后端阿里云机翻,结果缓存 scope='ui'),
  再按真源表把 ui 结果拷入 scope='field'/'panel'(缺哪补哪,幂等可重跑)。
- 注意:同名字段/面板(如「部门」既是面板名又是字段标签)在 field 已有译名时
  /dict 视为命中、不产生 ui 行,交叉 scope 拷贝(ui+field→panel、ui+panel→field)兜住。
- 验证:`tools/verify/i18n-verify-multi.cjs <locale> <panelCode>`(CDP 无头 Edge,
  断言列头/字段标签/标题为目标语言字符集;ja 判假名、ko 判谚文、其余判无 CJK)。

## 5.5 踩坑台账(2026-09-11 前端导出/探针专项;新代码必须绕开,违者即重复事故)

> 来源:文书面板「导出 PDF/Excel」五轮排障。全部实测复现过,不是理论风险。

### A. 浏览器内 PDF 生成(jsPDF / 截图库)

| # | 坑 | 规范 |
|---|---|---|
| A1 | **jsPDF `unit:'px'` 换算因子与 CSS 96dpi 不一致**——页面虚标 598×980mm 巨页、内容占比缩水、边框缩成发丝不可见 | 页面尺寸一律 **`unit:'mm'` + 自算 `1px=25.4/96mm`**;`format:[宽mm,高mm]`,addImage 同尺寸满铺 |
| A2 | jsPDF 4.x `save()` 走 `anchor.dispatchEvent(new MouseEvent)` 且**即刻 revoke blobURL** | 自动化验证须 hook `URL.createObjectURL` 截 Blob 本体(`fetch(blob:)` 会得空);hook `.click` 拦不到 |
| A3 | html2canvas 的 iframe 克隆机制在真实浏览器报 **"Unable to find element in cloned iframe"**(无头复现不了) | 截图一律 **modern-screenshot(domToPng,SVG foreignObject)**,禁用 html2canvas 截文书纸张 |
| A4 | 纸张根 `max-width:100%` 窄窗被压缩时,**截原元素=克隆树按压缩宽排版**,画布再宽也只排半张(压降/精度 ~1500px 宽表必现) | **离屏克隆+按纸宽强制布局**:clone 挂 `position:fixed;left:-10000px` 容器,`style.width=纸宽px; maxWidth='none'; overflow='visible'`,**双 raf 等重排**后按全宽布局的 scrollHeight 截;宽=`scrollWidth`(非 offsetWidth) |

### B. Vue 组件引用

| # | 坑 | 规范 |
|---|---|---|
| B1 | 组件模板含**多个 append-to-body 弹窗** → 多根 fragment,`ref.$el` 可能是**注释锚点**(dev 必现,prod 偶尔正常→假通过) | `$el` 用前必判 `instanceof HTMLElement && offsetWidth>0`;不满足按纸张根类名 DOM 查询兜底(本工程:`.record-sheet/.approval-sheet/.progress-sheet`) |

### C. PowerShell 工具脚本

| # | 坑 | 规范 |
|---|---|---|
| C1 | PS5.1 经命令通道传 **CJK 哈希键不可靠**(值悄悄变空、查找返回 null,还不报错) | 语言包/locale 批量写入一律 **Node 脚本**(`tools/archive/_i18n-*.cjs` 惯例);PS 只做 ASCII 逻辑 |
| C2 | PS 脚本无 BOM 被按 GBK 解析(中文注释吞掉换行符→语法错);法语弯引号 U+2019 被当字符串定界符 | 写盘一律 **UTF-8 BOM**;弯引号先规范成 ASCII `'`;JS 值内 `'` 转义为 `\'`(不是 SQL 的 `''`) |
| C3 | build-hot-update 只打 service/controller/config 三个包的 class | 并行会话加**新后端依赖**(如 JasperReports)时 javac classpath 缺 jar 必挂 → 前端-only 改动用 `tools/archive/_deploy-static-only.ps1`(仅 vite build + dist→static + jar uf,不碰 Java) |
| C4 | `Invoke-WebRequest` 把 UTF-8 响应当 **Latin-1** 解码 ⇒ 中文串比对**假阴性**(2026-09-21 实测:从 8090 取回的分包里 `配方计算`/`参数库维护` 明明在,却全查不到;同一原因让标准库接口返回的中文显示成乱码) | 核验"某功能在不在产物里"要**显式按 UTF-8 解码**(`New-Object System.Net.WebClient` + `$wc.Encoding=[Text.Encoding]::UTF8`),或**直接查磁盘文件**;别用 `-match`/`-like` 判中文存在性 |

### F. 面板配置的数据键(recordSheetConfigs.js)

> 铁律:**配置里的 `key` 一律写字段的 `label`,不是 `col_name`**。
> 后端 `PanelConfigService.fieldSpec()` 定死了 `dataName = f.label()`,前端行模型 `{ [label]: value }`,
> 保存链 `labelsToCols` 也按 label 反查 —— 写 col_name 的后果是**取不到值(格子空白)且保存时静默丢值,不报错**。
> `col_name` 是物理列名永不动;纸上要显示成别的字,用 `yj_field.alias`(显示层)分流。
> 三处同源铁律的活例:RD_INSP_PLAN 的 序号/控制项目/控制标准及要求/检测频率/控制方法 五个字段
> label 是旧名、alias 才是设计列名,配置全部写 label。
