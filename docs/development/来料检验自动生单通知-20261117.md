# 来料检验单审核 → 自动生单的草稿消息(2026-11-17)

> 用户口径(三轮,逐条对照):
> 1.「从来料检验单审批自动生产采购入库单和暂收退料单能不能消息通知到生产销售和仓库审核两个角色。」
> 2.「都是只要知情,并且告诉我他们在哪里收到消息」
> 3.「**1. 生产销售只用收到暂收退料就行。2. 生成单据的时候就要有消息,这个草稿单是需要他们去补充的,不是待审批的消息。**」
>
> 本文按第 3 条(最新口径)描述;**第 1 版做法已被取代**(当时两张单都发给两个角色、文案写"等待仓库审核"),
> 被取代的 4 条测试消息已在测试库置 `asp_cancel='Y'`。

## 一、结论(先看这里)

**能,已经做完并实测通过。消息在「顶栏右上角的『消息』图标」里收,不在『待办』里。**

| 收件人 | 收哪几张单 | 条数 | 文案(标题 / 正文要点) |
|---|---|---|---|
| **仓库审核** `cksh`(账号 `jxg` 蒋小刚) | 采购入库单 + 暂收退料单 | 2 条 | **已自动生成草稿单:请补充** / 「…已自动生成「采购入库单 PI-…」草稿,**请补充完善后再审核**。」 |
| **生产销售** `scxs`(账号 `Smm` 孙淼淼) | **只有暂收退料单**(采购入库单**不发**) | 1 条 | **已自动生成草稿单(知会)** / 「…已自动生成「暂收退回单 TH-…」草稿(由仓库补充完善),**特此知会**。」 |

| 问题 | 答案 |
|---|---|
| 在哪里收 | 顶栏右上角**「消息」**图标(气泡,带红色未读数)→ 弹出「消息」页签列表 → 点条目看详情 → 点 **「去处理」** 直接跳到那张草稿单 |
| 什么时候发 | **生单那一刻**(审核来料检验单、下游单据落库的同时),不是审批节点 |
| 是"待审批"吗 | **不是**。正文一律说"请补充完善后再审核 / 特此知会",不出现"待审批/等待审核"字样(回归闸钉住) |
| 为什么进不了「待办」 | 待办只认 `pending='Y'`(已提交审批),草稿天然不在里面 ⇒ 这条消息是目前唯一提醒入口 |
| 手机推送/短信 | 没有。本系统只有站内消息(顶栏消息 + 未读数),不接短信/微信/APP 推送 |

## 二、为什么原来收不到(改动前的事实)

| 事实 | 位置 |
|---|---|
| 两个自动生单方法 `inspAutoPurchaseIn` / `inspAutoReturn` 只建草稿,**一条消息都不发** | `ButtonService`(原 2026-09-15 实现) |
| 直审(审核按钮)连「审批结果」消息都没有 | `ButtonService.audit` |
| 生产销售在 `PURCHASE_IN` / `QC_RETURN` 上**没有** `audit` 权限(perms 只有 `view,query,export,print,warn`)⇒ 走「审批人」口径(`approversOf`)永远解析不到它 | 正式库 `yj_role_panel` 实测 |
| 自动生成的是**草稿**,门户「待办」只查 `pending='Y'` | `PortalNotificationService.appendTodos` |

⇒ 改动前:仓库只能"自己想起来"去列表里翻草稿,生产销售更是完全无感知。

## 三、实现落点

| 文件 | 改了什么 |
|---|---|
| `backend/.../service/MessageService.java` | 两个消息码:**`AUTO_DRAFT_TO_FILL`**(草稿要去补充的人)与 **`AUTO_DRAFT_FYI`**(只需知情);新增 `accountsOfRoles(...)`(按 `yj_role.role_code` 取启用账号)、`draftNotifyTargets(panelCode, kind, defaultRoleCodes)`(kind=`fill`/`fyi`,面板配置可按 kind 覆盖);`approvalNotify` 的 JSON 解析抽成私有 `configStringArray` 复用 |

| `frontend/src/layout/NoticeCenter.vue` | `MSG_TPL` 补两个码的模板(否则渲染成通用「业务消息」) |

消息参数:`{docNo: 下游单号, actor: 审核人, sourceNo: 来料检验单号}`,并由 `MessageService.send` 自动补 `panelName`。
消息的 `面板编码`/`单据编号` 挂的是**下游单据**(`PURCHASE_IN` + `PI-…` / `QC_RETURN` + `TH-…`)⇒ 「去处理」落到那张草稿,不是检验单。

## 四、收件人怎么改(不用改代码)

`yj_panel.config` 是 JSON,四个键(都可以不配):

```sql
-- ①「请补充」换个角色(默认 cksh 仓库审核):
UPDATE yj_panel SET config = JSON_MODIFY(config,'$.fillNotifyRoles',JSON_QUERY(N'["ckgl","cksh"]'))
 WHERE panel_code = N'PURCHASE_IN';
-- ②「请补充」点名加人(与角色取并集):
UPDATE yj_panel SET config = JSON_MODIFY(config,'$.fillNotify',JSON_QUERY(N'["jxg"]'))
 WHERE panel_code = N'PURCHASE_IN';
-- ③ 让生产销售也收采购入库单的知会(默认为空 = 不收):
UPDATE yj_panel SET config = JSON_MODIFY(config,'$.fyiNotifyRoles',JSON_QUERY(N'["scxs"]'))
 WHERE panel_code = N'PURCHASE_IN';
-- ④ 取消某条覆盖,回到代码默认:
UPDATE yj_panel SET config = JSON_MODIFY(config,'$.fillNotify',NULL) WHERE panel_code = N'PURCHASE_IN';
```

⚠ 两个账套(`HSDZ_MES` / `HSDZ_MES_TEST`)都要执行;本次**没有新增迁移脚本**(默认口径写在代码里,配置只是可选覆盖)。

## 六、边界与后续

1. **生产销售只有"知情"**:`scxs` 在暂收退料单上仍无 `modify`/`audit` 权限 ⇒ 文案写"由仓库补充完善",不让他去补;要让他能补/能审,那是 `yj_role_panel` 授权的事。
2. **草稿不进门户待办**(只认 `pending='Y'`)。要让仓库在待办里看到"待补草稿",是一条独立的口径变更(会牵动 `PortalNotificationService` 与所有面板),本批没做。
3. **暂收退料单审核 → 特采单草稿** 同样是"自动生成的下游草稿",目前**没有**通知(用户只要到入库单/退料单这两个下游);要兜住在 `returnAutoSpecialAccept` 里加一行 `notifyAutoDraft("QC_TC_IN", …)` 即可。
4. **幂等**:重审时 `form_flow_link` 已有 `ACTIVE` 占用就跳过整段生单,不会重复发消息;操作者本人不收自己的动作消息。
5. 本次构建时 `tools/sync-db.bat` 报的 `migrate-qc-proc-insp-batch-table-20261111.sql` 第 7 节自检失败是**既存问题**(该脚本没进 `yj_schema_log`,与本次改动无关),留待单独处理。
