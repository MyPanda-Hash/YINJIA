# 来料检验单审核 → 自动生单的「知情」消息(2026-11-17)

> 用户口径(逐字):
> 1.「从来料检验单审批自动生产采购入库单和暂收退料单能不能消息通知到生产销售和仓库审核两个角色。」
> 2.「都是只要知情,并且告诉我他们在哪里收到消息」

## 一、结论(先看这里)

**能,已经做完了;消息在「顶栏右上角的『消息』图标」里收,不在『待办』里。**

| 问题 | 答案 |
|---|---|
| 收件人 | **生产销售**角色(`scxs`,账号 `Smm` 孙淼淼)+ **仓库审核**角色(`cksh`,账号 `jxg` 蒋小刚) |
| 收几条 | 每个角色 **2 条**:采购入库单 1 条 + 暂收退回单 1 条(哪张生成了就发哪张;两行都合格/都不良时只有一条) |
| 在哪里收 | 顶栏右上角 **「消息」** 图标(气泡图标,带红色未读数)→ 弹出「消息」页签列表 → 点条目看详情 → 点 **「去处理」** 直接跳到那张草稿单 |
| 收不到的地方 | **「待办」页签不会出现**。待办只认 `pending='Y'`(已提交审批),而自动生成的是**草稿** ⇒ 这条消息目前是唯一提醒入口 |
| 是否需要审批权 | 不需要。这是**知情**消息,收件人按**角色**解析,与「谁能审核」(`yj_role_panel.can_approve`)完全分开 |
| 手机推送/短信 | 没有。本系统只有站内消息(顶栏消息 + 未读数),不接短信/微信/APP 推送 |

## 二、为什么原来收不到(改动前的事实)

| 事实 | 位置 |
|---|---|
| 两个自动生单方法 `inspAutoPurchaseIn` / `inspAutoReturn` 只建草稿,**一条消息都不发** | `ButtonService`(原 2026-09-15 实现) |
| 直审(审核按钮)连「审批结果」消息都没有 —— 全库 `messageService.*` 调用里没有审核路径 | `ButtonService.audit` |
| 生产销售在 `PURCHASE_IN` / `QC_RETURN` 上**没有** `audit` 权限(perms 只有 `view,query,export,print,warn`)⇒ 走「审批人」口径(`approversOf`)永远解析不到它 | 正式库 `yj_role_panel` 实测 |
| 自动生成的是**草稿**,门户「待办」只查 `pending='Y'` ⇒ 也不会出现在待办里 | `PortalNotificationService.appendTodos` |

⇒ 改动前:仓库只能"自己想起来"去列表里翻草稿,生产销售更是完全无感知。

## 三、实现落点

消息参数:`{docNo: 下游单号, actor: 审核人, sourceNo: 来料检验单号}`,并由 `MessageService.send` 自动补 `panelName`。

## 四、收件人怎么改(不用改代码)

`yj_panel.config` 是 JSON,两个键(都可以不配):

```sql
-- 只把「自动生单知情」发给这几个账号(与角色取并集)
UPDATE yj_panel SET config = JSON_MODIFY(config,'$.auditNotify',JSON_QUERY(N'["jxg","Smm"]'))
 WHERE panel_code = N'PURCHASE_IN';
-- 换掉默认角色(scxs=生产销售 / cksh=仓库审核),用别的角色编码
UPDATE yj_panel SET config = JSON_MODIFY(config,'$.auditNotifyRoles',JSON_QUERY(N'["cksh"]'))
 WHERE panel_code = N'QC_RETURN';
-- 取消覆盖,回到代码默认(生产销售 + 仓库审核)
UPDATE yj_panel SET config = JSON_MODIFY(config,'$.auditNotify',NULL) WHERE panel_code = N'PURCHASE_IN';
```

⚠ 两个账套(`HSDZ_MES` / `HSDZ_MES_TEST`)都要执行;本次**没有新增迁移脚本**(默认口径写在代码里,配置是可选覆盖)。

## 六、边界与后续

1. **生产销售只有"知情"**:`scxs` 在两张单上仍无 `audit` 权限,消息里能看、能点开,但不能点审核(工具栏不给)。要改成"能审",那是 `yj_role_panel` 授权的事,与消息无关。
2. **草稿不进门户待办**(只认 `pending='Y'`)。如果将来要让仓库在待办里看到"待审草稿",那是一条独立的口径变更(会牵动 `PortalNotificationService` 与所有面板),本批没做。
3. **暂收退料单审核 → 特采单草稿** 同样是"自动生成的下游草稿",目前**没有**通知(用户本次只要求到入库单/退料单这两个下游)。要一起兜住,在 `returnAutoSpecialAccept` 里照 `notifyAutoDraft("QC_TC_IN", …)` 加一行即可。
4. **幂等**:重审时 `form_flow_link` 已有 `ACTIVE` 占用就跳过整段生单,不会再重复发消息。
5. **操作者本人不收自己的动作消息**(与全库口径一致)。
6. 本次构建时 `tools/sync-db.bat` 报了一条**与本次改动无关**的既存失败:`migrate-qc-proc-insp-batch-table-20261111.sql`
   第 7 节自检 `[SQL失败] 出货检验功能记录表(批次矩阵)迁移自检失败`,该脚本未被登记进 `yj_schema_log`,
   后续脚本因此未执行。本次没有改动该脚本,留待单独处理。
