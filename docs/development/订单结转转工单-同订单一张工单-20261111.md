# 订单结转 → 转工单:同一销售订单一次转单 = 一张工单(2026-11-11)

> 用户报障(2026-11-11 截图):销售订单 `XQ-20261019-01` 的两条订单行在同一次结转里转出,
> 却生成了**两个工单号** `GD-2026-11-0010`(#1)/`GD-2026-11-0011`(#2),
> 用户口径:「同一个销售订单都应该为同一个工单号只是工单行号不同」。

## 一、旧口径(2026-10-31 起)与病根

`QuickScheduleService.createFromOrderLine` 在 2026-10-31 改成「**一次转单 = 一张新工单号**」:
每转出一条订单行就 `formNo.next("GD")` 取一个新号,工单里只有这一行(`pl_xc` = 订单行号)。

- 当时要修的是**同一订单行分两次转单**被塞进同一张工单的问题(行号被 `MAX(pl_xc)+1` 改成 2、
  两张单各带一份整单需求)。修法选成了「一行一张单」,**把「同一销售订单的多条订单行」也一并拆开了**;
- `OrderConvertService.toManu` 也是**逐行**调 `createFromOrderLine`,本身没有「按订单分组」的概念;
- 结果:同一次转单勾了同一订单的 N 行 ⇒ N 个工单号,现场无法按「一个销售订单一张生产工单」核对。

## 二、新口径(2026-11-11 用户拍板,取代 2026-10-31)

**工单号按「转单批次 × 销售订单」发放,不按订单行发。**

| 场景 | 工单号 | 说明 |
|---|---|---|
| 同一次转单里,同一销售订单的多条订单行 | **同一张新工单号** | 每行一条工单行,`pl_xc` 各取自己的**订单行号** ⇒ 工单行号不同、单号相同 |
| 同一销售订单**分多次**转单(数量分批) | **每次另取一张新工单号** | 用户原话:「订单结转可能存在不是一次转单完成的情况,数量可能多次,这个时候对这个订单结转的不同行就需要为不同的工单号」 |
| 同一订单行重复转单(备品/补量) | 落在下一次转单的新工单号里 | 与上一条同构:每次转单 = 一张新单 |
| 一次转单勾了**不同销售订单**的行 | 每张销售订单各一张新工单号 | 分组键 = 订单号,取号顺序 = 勾选顺序 |

用户原话(2026-11-11):「销售订单转单需要通过中间流程订单结转进行,当前订单结转本来同一个销售订单
都应该为同一个工单号只是工单行号不同;而订单结转可能存在不是一次转单完成的情况,数量可能多次,
这个时候对这个订单结转的不同行就需要为不同的工单号。」

### 落库形态

| 列 | 值 | 说明 |
|---|---|---|
| `pl_no` | 本次转单里该订单的第一行取新号,同组后续行复用 | `FormNoService.next("GD")`,号池仍按 前缀+年月 独立序列 |
| `pl_xc`(工单行号) | **订单行号**(`bl_so_order.行号`) | 同一张工单里各行行号不同;撞号时让位(见下) |
| `od_no` | 销售订单号 | 工单列表/追溯显示「订单号」 |
| `od_xc` | **销售订单行 id**(`bl_so_order.id`) | 工单列表/追溯按它 `JOIN` 反查「订单行号」显示(`PlangOrderLine`) |
| `xq_sl`(需求) / `pl_sl`(转单) | **本行本次转单数量** | 不写整条订单行数量(避免 2026-10-30 那次的"需求重复计") |
| `yl`(余量) | 0 | 未排产量由 `pl_sl` 派生 |
| 占用链 | `form_flow_link`,键 `工单号#工单行号` | 同一张工单的多行各挂各的占用,订单结转页「已排产/剩余」口径不变 |

### 行号撞号保护(2026-11-11)

`pl_xc` 同时是占用链/工序台账/领料/报工的定位键。同一张工单内若两行 `pl_xc` 相同,
链路会混成一条。正常一笔转单里每行订单行号唯一,撞号只可能来自「订单行 `行号` 为空/重复」的历史脏数据 ⇒
`QuickScheduleService.reserveLineNo`:优先用订单行号,已被占用时改用 `MAX(pl_xc)+1` 并打
`[订单结转] … 已被占用` 告警日志(不静默混账)。

## 三、代码位置

| 位置 | 改动 |
|---|---|
| `QuickScheduleService.createFromOrderLine(...)` | 新增 6 参重载:`plNo` 空 = 取新号;非空 = 追加进该工单(行号防撞、工序台账按行幂等、占用链按 `工单号#行号`) |
| `QuickScheduleService.generateFromOrder(...)` | SO_ORDER「生成生产工单」按钮:整单一次生成 ⇒ 复用同一张工单号(返回去重号清单) |
| `OrderConvertService.toManu(...)` | **按订单号分组**(LinkedHashMap 保勾选顺序),组内首行取号、其余行追加;回执新增 `生成行数`,`生成张数` = 新工单张数 |
| `frontend/src/views/modules/plan/OrderConvert.vue` | 结果提示按「张数(行数)」展示,勾 3 行只生成 1 张单不再像漏转 |

## 四、存量数据

**不迁移历史工单**(2026-11-11 用户选择「不动历史,只改今后的转单」):

- 历史上「同一订单多个工单号」的单据(如 `GD-2026-11-0010/0011`)保持原样 —— 单号已被领料/报工/
  入库/打印留痕按 `工单号+工单行号` 引用,改号会拆断整条链;
- 新口径只作用于**新的转单**;老工单继续按原行操作(排产/报工/结案均行级,不受影响)。

## 五、展示 / 追溯

- 生产工单列表(`/api/px/workOrderList`)本就逐行展示 `工单号 + 工单行号 + 订单号 + 订单行号`,
  多行工单只是同一工单号出现多行(按 `pl_no, pl_xc` 排序相邻);
- 追溯弹窗(`/api/px/scheduleBoard/trace`)按行取订单行号(`PlangOrderLine`),多行工单逐行正确;
- 打印生产任务单是**逐行**出表(同一工单号多行 = 多行表格),二维码按 `工单号#行号`。

## 七、多行工单审计(2026-11-11,只读)

「一张工单多行」是 2026-09-27~10-30 的既有形态,系统主体按 `工单号#工单行号` 工作(排产/报工/领料/
结案/切单/追溯/台账/占用链均已行级)。本次审计发现**与本次改动无关、但多行成为常态后更容易踩到**
的老口径兜底,按风险记录(不是本次引入,未在本次修改):

| 风险 | 位置 | 说明 |
|---|---|---|
| P0 | `WorkOrderListController.close`(约 :296-315) | 结案用 `queryForMap(comm+pl_no+pl_xc+批次号)`;若同单存在重复 `pl_xc` 且批次号同为 NULL ⇒ `IncorrectResultSizeDataAccessException`(500)。本次 `reserveLineNo` 只防新写入 |
| P0 | `ButtonService.dualOutFinishIn`(约 :4062-4077) | 切炭直销入库的产品/单位/批号取 `TOP 1 ... WHERE pl_no=?`(无 ORDER BY),并回写整单 `lot_no` ⇒ 多行时入库单头可能带错行信息 |
| P0 | `WorkReportController.context`(约 :62-81) | 报工给了行号但匹配不上时**静默退回首行**,多行时会把产量记到行 1 |
| P1 | `ScheduleBoardService`(约 :935-937 / :1027-1029) | 「计划线」按 `pl_no` 聚合,未带 `工单行id` ⇒ 多行工单每行都显示全单各行的工序:线(显示错,旁边 `curOp` 已按行收敛) |
| P1 | `ProcessTaskService.processPlanQty`(约 :870-892) | 兜底路径用 `SUM(pl_sl) WHERE pl_no` + 首行路线 ⇒ 多行时计划量虚高 |
| P1 | `WorkOrderListController.close` 同族 / `wo_pick_doc` 唯一键 | `wo_pick_doc(工单号,工单行号)` 是**唯一会因重复行号硬失败**的约束;`plang` 本身无 `(comm,pl_no,pl_xc)` 唯一键 |

复现/排查口径:`SELECT pl_no, pl_xc, COUNT(*) FROM plang WHERE ISNULL(asp_cancel,'N')<>'Y'
GROUP BY pl_no, pl_xc HAVING COUNT(*)>1`(存量里确有 `GD-2026-10-0023` 这类历史重复行号)。

## 八、验证要点(改这块必须复验)

在测试账套 `HSDZ_MES_TEST` 上,取一张有 ≥2 条订单行的已审核销售订单:

1. 订单结转页勾选**同一订单的 2 行**,一次转工单 ⇒ **只有 1 个新工单号**,工单里 2 行,
   行号 = 各自订单行号,需求/转单数量各自正确,订单号/订单行号可回查;
2. 再勾该订单另一行(或同一行补量)转一次 ⇒ **另一个新工单号**;
3. `form_flow_link` 每行各一条(键 `工单号#行号`),订单结转页「已排产/剩余」汇总正确、转满行消失;
4. 新工单行在排产、报工、领料、结案、切单、打印、追溯上均正常(全部按 `工单号+行号`);
5. 一次勾选**两张不同订单**的行 ⇒ 两张新工单号(各订单一张)。
