# 订单结转 → 转工单:同一个销售订单始终一张工单(2026-11-11)

> 用户报障(2026-11-11 截图):`GD-2026-11-0013`(#2)与 `GD-2026-11-0014`(#4)同属销售订单 `LZW-20261019-02`,
> 只是分两次点「转工单」(13:43、13:44),却拿到两个工单号。用户口径:
> 「当前明明是同一个销售订单的订单结转,生成的生产工单号还是不同,要求同一个销售订单的工单号相同。」

## 一、结论(为什么之前会不同)

工单号的发放口径在一天里走了两版,都不对:

| 版本 | 口径 | 病根 |
|---|---|---|
| 2026-09-27 ~ 10-30 | 同一销售订单共用一张工单,复用号时行号取 `MAX(pl_xc)+1` | 同一订单行第二次转单行号变 2(与订单行号脱钩);`xq_sl` 写整条订单行数量 ⇒ 需求重复计 |
| 2026-10-31 ~ 2026-11-11 上午 | **一次转单 = 一张新工单号**(`formNo.next("GD")` 每行都取) | 把「同一订单的多条订单行」也拆成多张单(2026-11-11 上午报障) |
| 2026-11-11 中午 | 按「转单批次 × 销售订单」发号 | 同一次点击内合并,但**再次点击**(数量分批、换个订单行再转)仍另发新号 ⇒ 本条报障 |

## 二、现行口径(2026-11-11 修订,用户拍板)

**工单号按「销售订单」发,不按转单批次、不按订单行发。**

| 场景 | 工单号 |
|---|---|
| 同一销售订单的不同订单行,**无论分几次点「转工单」** | **同一张工单号** —— 后来的行进已有工单,行号 = 自己的订单行号 |
| 同一订单行**重复转单**(该工单里已经有这一行了:数量分批、备品追加) | **另取新工单号** |
| 该订单的工单已**全部结案**(生产做完)后才出现新的订单行 | 另取新工单号(不往历史单里塞) |
| 一次转单勾了**不同销售订单**的行 | 每张订单各落自己那张工单(没有工单的订单取新号) |

实现单点:`QuickScheduleService.resolveOrderWorkOrderNo`(页面/控制器不得再写第二套判据)。

### 落库形态

| 列 | 值 | 说明 |
|---|---|---|
| `pl_no` | 该销售订单已有的工单号;没有则 `FormNoService.next("GD")` | 号池仍是 前缀+年月 独立序列 |
| `pl_xc`(工单行号) | **订单行号**(`bl_so_order.行号`) | 同一张工单里各行行号不同;撞号时让位(见下) |
| `od_no` | 销售订单号 | 工单列表/追溯显示「订单号」 |
| `od_xc` | **销售订单行 id**(`bl_so_order.id`) | 判重键;工单列表/追溯据此反查「订单行号」(`PlangOrderLine`) |
| `xq_sl`(需求) / `pl_sl`(转单) | 本行本次转单数量 | 不写整条订单行数量(避免 2026-10-30 的需求重复计) |
| `yl`(余量) | 0 | 未排产量由 `pl_sl` 派生 |
| 占用链 | `form_flow_link`,键 `工单号#工单行号` | 同一张工单的多行各挂各的占用,订单结转页「已排产/剩余」口径不变 |

### 判重与让位规则

- **判重**:`plang.od_no = 销售订单号` 且 `CONVERT(bigint, plang.od_xc) = 订单行 id`
  ⇒ 该订单行已经在这张工单里,再转必须开新单(行键 `工单号#行号` 不能重复,否则占用链/工序台账混成一条);
- **候选工单**:未作废、**不是切单子单**(`是否切单 <> 'Y'`)、**还有未结案的行**;按最早创建优先
  (主工单持续累积该订单各行;单独开的「重复行工单」只装它自己那几行);
- **行号让位** `reserveLineNo`:优先 `pl_xc = 订单行号`;若该行号在这张工单里已被别的订单行占用
  (历史脏数据:订单行 行号 为空/重复),改用 `MAX(pl_xc)+1` 并打 `[订单结转] … 已被占用` 告警。

## 七、多行工单审计(2026-11-11,只读)

「一张工单多行」是 2026-09-27~10-30 的既有形态(正式库 `GD-2026-10-0018` 就是 12 行一单,已作废),
系统主体按 `工单号#工单行号` 工作。审计发现的**既有**老兜底(不是本次引入,未在本次修改):

| 风险 | 位置 | 说明 |
