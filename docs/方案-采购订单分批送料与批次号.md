# 方案:采购订单分批送料与批次号贯通

> 目标链路:**采购订单 PU_ORDER → 送料暂收单 SL_RECV → 来料检验单 QC_INSP → 采购入库单 PURCHASE_IN / 暂收退回单 QC_RETURN**
> 状态:**P0 已实现并实测通过(2026-09-20)**;P1/P2 待排期
> 起因:一张采购订单会**分多批**送料暂收,而原来的生单逻辑是"整单生单 + 整行占用",既生不出第二张暂收单,也没有任何"批次"标识可追溯。

## 一、一句话结论

把「整单生单 + 整行占用」改成「**按行分批生单 + 按批次数量占用**」:

1. 给暂收单及其下游单据加 **批次号**(送货批次,单据级,自动取号,如 `YJ-20260915-08-01`);
2. 新增批次台账 **`yj_doc_batch`**,记录每个批次送了多少、去的哪张下游单、是否释放;
3. `form_flow_link` 记录**每批次实际送料量**(现在是整行量),于是"剩余量 = 订单量 − Σ各批次量"可算;
4. 批次号沿 暂收→检验→入库/退回 **全程下传**,一个批次号可一次拉出四张单。

## 二、现状核对(2026-09-20 实测代码与库)

### 2.1 两条生单入口,语义不同

| 入口 | 位置 | 现状行为 |
|---|---|---|
| **推式**「生成送料暂收单」 | 采购订单单据内按钮 → `PushGenerateHandler` | **整单**映射订单全部明细行;**只要该订单已向 SL_RECV 生过一次就整单拒绝**("该单已向目标面板生单(或已选单占用),请先删除下游草稿后重试") |
| **拉式**「选单」 | 送料暂收单内按钮 → `SelectVoucherDialog` + `VoucherFlowService.sources` | 来源列表只列 **已审核** 且 **未完全占用** 的订单行,显示 `已生单数量/剩余数量`;**可只勾选部分明细行**;但生成时**整行数量照搬,不能改量** |

两条路径最后都调用 `VoucherFlowService.link(...)`,而它写入的是:

```java
double qty = qtyOf(src);           // 源行整行数量
... source_quantity = qty, linked_quantity = qty   // ← 送多少都记成"整行送完"
```

→ **部分送料在数据上等于整行送完,剩余量根本算不出来**;推式那条还被"整单仅一次"卡死。这就是你说的问题。

### 2.2 已有的正确范式(可以照搬)

检验 → 入库 / 退回 两跳**已经是行级按量占用**:

- `ButtonService.inspAutoPurchaseIn`:写入 `source_quantity = 数量`、`linked_quantity = 合格数量`(不良部分余量留给退回链);
- `ButtonService.inspAutoReturn`:写入 `linked_quantity = 不良数量`。

本方案就是把这两跳的语义**往前推到 采购订单 → 暂收**,链路口径统一。

### 2.3 现有"批次"相关字段(别混用)

| 位置 | 字段 | 性质 |
|---|---|---|
| `bl_pu_order`(采购订单行) | `批次号`、`商品是否开启批次` | 金蝶带过来的**物料批次**(行级) |
| `qc_insp_detail` / `bl_purchase_in` / `qc_return_detail` | `批号` | 物料存货批号(行级,库存/LOT_TRACE 用) |
| `bd_purchase_in` | `资金批次` | 金蝶同步的资金口径批次 |
| 暂收/检验/入库/退回 **表头** | **无** | ← 本次要补的就是"送货批次号" |

### 2.4 占用现状(库里真实数据)

| 链路 | link 行数 |
|---|---|
| PU_ORDER → SL_RECV | 28 |
| SL_RECV → QC_INSP | 27 |
| QC_INSP → PURCHASE_IN | 14 |
| QC_INSP → QC_RETURN | 3 |

且 `YJ-20260915-06` 一张订单已对应 **6 张**暂收单 —— 说明"分批送料"实际上**已经在发生**,但既没有批次标识,也没按量核减(每张下游单都把整行记成已占用),所以现在**算不出这张订单到底还剩多少可送**。

## 三、设计口径

### 3.1 两种"批次"严格分开

| 名称 | 含义 | 粒度 | 来源 | 用途 |
|---|---|---|---|---|
| **批次号**(新增) | 该采购订单的**第几次送料** | **单据级(表头)** + 行上冗余 | MES 生单时自动取号 | 分批追溯、按批对账、开票/索赔取证 |
| 批号(已有) | 物料的**存货批号** | 行级 | 金蝶/入库取号 | 库存批次、批号追溯 |

**结论**:`批次号` 放表头(一单一批次),同时**冗余写到明细行**(便于行级对账与后续推 ERP);**不复用** `批号`。

### 3.2 批次号编码(已定稿 2026-09-20)

```
<采购订单号>-<3位批次序号>      例:YJ-20260915-08-001 / YJ-20260915-08-002
```

- **序号可回收**(用户口径 2026-09-20):取号 = 该订单 `1..N` 中**第一个未被"有效批次"占用的序号**;
  删除下游**草稿**暂收单 → 该批次台账行随之删除、序号回到可用池,下一次生单优先补空洞。
- **"有效批次" = 暂收单还在的单据**:已审核/已作废的暂收单都仍占号(单据还在,批次号不能重复);
  只有"草稿被删除"(连带释放 `form_flow_link` 占用)才回收序号。已流转到检验/入库/退回的暂收单删不掉
  (现有守卫:必须先弃审 → 草稿 → 删除),所以回收范围天然安全。
- 释放痕迹不丢:`form_flow_link` 保留 `RELEASED` 行 + `release_time`(台账只记有效批次,历史查 link)。
- ⚠️ 复用风险:若单据**已打印/外发给供应商**后再删除,新批次可能拿到同一个号 → 追溯容易混。
  建议流程上约束"打印过的批次不要删"(系统不硬拦)。
- 超长单号:订单号超过 40 字符时截断拼接(批次号最大长度 50)。

### 3.3 数量口径与**超送**(超送口径已定稿 2026-09-20)

- **可送量(按行)** = `订单行.数量` − Σ(该行所有**有效批次**的送料数量) `+ 允许超送额度`;
- **允许超送**:是。额度 = `剩余量 × 超送比例`,比例**可配**:
  - 系统级默认值(面板/系统参数,建议初始 `5%`,可改 0 关闭);
  - 生成暂收单时可在对话框里**按单覆盖**(默认取系统值,权限内可改小/改大);
  - 校验:`0 < 本次送料数量 ≤ 剩余量 × (1 + 比例)`;超出提示"超出允许超送比例"。
- 数量比较**限同单位**:订单行 `单位/计量单位` ↔ 暂收行 `计量单位`,不一致直接拒绝并提示(不做跨单位换算);
- ⚠️ **超送与金蝶的已知冲突(实测)**:推 ERP 时若入库数量 > 订单剩余,金蝶返回「**不允许超额入库**」(本项目 2026-09-20 实测过)。因此超送部分在推送时需要二选一:
  (a) 超送行**不带源单关联**推送(金蝶侧作为无源单入库);
  (b) 或金蝶侧开启超收容差后再带源单推。
  → 归属到 P1,本方案 P0 只在 MES 内允许超送并如实记录,推送策略单独定。
- 只对**已审核**订单可生单(现有守卫保留),已中止/作废/审批中一律不可(现有状态机已具备)。

### 3.4 占用与释放

- **生成**:`form_flow_link` 增列 `batch_no`;每行写
  `source_quantity = 订单行数量`、`linked_quantity = 本次送料数量`、`batch_no = 批次号`;
- **校验**:去掉"整单已生单就拒绝",改为**按行剩余**判断 → 有剩余就能再生一批;
- **释放**:删除下游**草稿** → 该批次 link 置 `RELEASED`(机制已有);下游已**审核**则必须先弃审/作废(沿用现有守卫);
- **台账**:`yj_doc_batch.status` = `ACTIVE / RELEASED / CLOSED`;订单所有行剩余为 0 时可标记该订单"送料完成"。

## 五、生单流程(改造后)

### 5.1 推式:采购订单 →「生成送料暂收单」

1. 点按钮 → 弹**分批送料对话框**(不再直接生成):
   表格列 = `行号 / 物料编码 / 物料名称 / 规格型号 / 订单数量 / 已送 / 剩余 / 本次送料数量(可编辑,默认剩余)`;
   底部 = 合计数量、**批次号(自动生成,只读)**、供应商、单据日期。
2. 校验:勾选行 `0 < 本次 ≤ 剩余`;全为 0 时"确定"禁用;单位不一致行标红。
3. 生成:创建 SL_RECV 草稿
   - 头:供应商 / 供应商代码 / 采购订单号 / **批次号** / 日期(创建当日,沿用现有口径);
   - 行:物料 / **数量 = 本次送料数量** / 单价 / 计量单位 / 采购订单行号 / **批次号**;
   写 `form_flow_link`(带 `batch_no` 与本次数量)+ `yj_doc_batch`,跳转暂收单继续填写。
4. **同订单可反复生单**,直到所有行剩余为 0 → 按钮置灰提示"已全部送料"。

### 5.2 拉式:送料暂收单 →「选单」

- 来源列表语义不变(仅已审核、仅还有剩余行),把 `可生单数量` 明确为**剩余数量合计**;
- 生成对话框加"本次送料数量"列(默认剩余),与推式**共用同一套校验与生成器**;
- **批次号自动取号**(无需用户输入);
- 一次勾选多张订单时**仍一单一张暂收单**(保持现状;跨订单合并见 §七 问题 3)。

### 5.3 下游自动链路(已存在,只补批次号)

| 跳 | 触发 | 补什么 |
|---|---|---|
| SL_RECV → QC_INSP | 暂收单「生成来料检验单」/ 审核钩子 | 头 `批次号` ← 暂收单;行 `批次号` + `采购订单行号` |
| QC_INSP → PURCHASE_IN | 检验单审核(合格数量>0 的行) | 头/行 `批次号`(现有 `inspAutoPurchaseIn` 里补一行) |
| QC_INSP → QC_RETURN | 检验单审核(不良数量>0 的行) | 头/行 `批次号`(现有 `inspAutoReturn` 里补一行) |

→ **同一批次的"入库 + 退回"共用同一批次号** —— 按批次号一次拉出 暂收/检验/入库/退回 四张单,这是本方案最大的价值。

### 5.4 界面呈现

- 暂收/检验/入库/退回 单据头部显示 `批次号`(自动带出,只读);**查询条件加 `批次号`**(支持模糊搜全库,与现有 keyword 一致);
- 采购订单单据界面加「送料批次」页签或左上角汇总:`已送 N 批 / 剩余数量 x`,台账行可点击跳到对应暂收单;
- 左栏「单据选择」中间列:暂收单那一栏可把 `采购订单号` 换成/加上 `批次号`(更直观,待你定)。

| 1 | 批次号编码与取号 | **`<采购订单号>-<3位序号>`**(如 `YJ-20260915-08-001`);**序号可回收** —— 取最小未占用序号,删除草稿序号回到可用池(详见 §3.2) |
| 2 | 超送 | **允许**,额度 = 剩余量 × **可配置比例**(系统默认值 + 生成时按单覆盖);超送与金蝶"不允许超额入库"的冲突见 §3.3,推送策略放 P1 |
| 3 | 一个暂收单装几张采购订单 | **一张暂收单 = 一张采购订单**(保持现状,批次号放表头;行上仍冗余写一份,将来要合并只放开入口) |
| 4 | 退货是否回冲已送量 | **回冲**:退回单审核后把 `退货数量` 加回该行可补送额度;**只影响可送量**(送货量/批次记录/退回单本身不变) |
| 5 | 批次台账要不要独立面板 | **先不做面板**:只建数据表 `yj_doc_batch`;批次信息放进「采购订单」单据里的**「送料批次」页签/汇总**(零新增菜单与权限)。将来要独立面板再加(见 §7.2) |

### 7.2 决策依据(备查)

**问题 3(一单多订单)为什么最终选"一单一订单"**

- 现在的行为:一次选单勾多张订单 → 每张订单各生成**一张**暂收单;推式生单也是一订单一张。
- "能合并"的代价:一张暂收单里装多张订单的行时,**表头批次号失去唯一语义**(一行属于不同订单的不同批次),
  必须整体改为行级口径,入口、列表、台账、追溯都要跟着改(+约 1 天)。
- 结论:按"一单一送"操作即可;**行上照样写批次号**,将来真需要"一车一单"只改入口,不动数据模型。

**问题 4(退货回冲)为什么选"回冲"**

- 场景:订单行 100 → 暂收 100(批次 `-001`)→ 检验判 20 不良 → 退回 20、入库 80。
- 不回冲:该行"已送 100 / 剩余 0",供应商换货补送 20 时**没有额度**(只能靠超送比例硬塞或人工改订单量)。
- 回冲:该行"已送 100 / 可补 20",补货按正常分批流程再生一批(`-002`);最终不补货就用现有**中止/关闭**收口。
- 口径:`可送量 = 订单量 − Σ批次送料量 + Σ退货数量`。

**问题 5(台账面板)为什么先不做**

- 表 `yj_doc_batch` **必须**(取号、按量占用、释放、追溯都靠它),但它是纯数据层,**不是面板**:
  菜单里不会出现,也不占权限配置。
- 做成独立面板要额外一整套元数据:`yj_panel` 注册 + `yj_field` + `yj_translation` 译名 + `yj_role_panel` 授权(约 +1 天)。
- 先用「采购订单」里的送料批次页签满足 95% 的查看需求;要独立台账面板随时可加(建议与 P1 批次追溯报表一起)。

## 八、存量数据兼容(迁移策略)

- 现网已有 28 条 `PU_ORDER→SL_RECV` 占用,无批次号 → 迁移脚本按"**每张暂收单 = 一个批次**"回填:
  `批次号 = 采购订单号-序号`(按暂收单创建时间排序取序号),同时写 `yj_doc_batch`;`linked_quantity` **保持原值**(存量本来就是整行占用);
- 回填后立即自检:**每张订单 Σ批次数量 ≤ 订单数量**,超出者输出清单人工核对(存量里已有手工造的数据,可能不平);
- 旧单据不阻断:没有批次号的存量单照常查看/审核,只是不参与按批次追溯。

## 九、验收标准(实现后按此写探针)

1. 一张订单 3 行 × 各 100,分 3 批各送 100 → 生成 3 张暂收单,批次号 `-001/-002/-003`;第 4 次生单被拒并提示"该订单已无剩余可送"。
2. 删除第 2 批草稿 → 该行剩余回到 200;台账中 `-002` 行删除、序号**回收**,重送生成 **`-002`**(不是 004);`form_flow_link` 里旧 `-002` 状态为 `RELEASED`(留痕)。
3. 每一批的 暂收 → 检验 → 入库 / 退回,四张单 `批次号` 完全一致;按批次号反查能列出四张单。
4. 同一订单两行部分送:剩余**按行**独立核减;超量超过比例 / 负数 / 单位不一致被拒。
5. 检验退回 20 件后,该行"可补送额度" +20(回冲口径);补送 20 走正常分批流程生成 `-003`。
6. 采购订单界面能显示「已送批次数 / 剩余数量 / 可补送额度」。

## 十、分期(P0/P1/P2 是**本方案的施工顺序**,不是另外的方案)

> `P0` = **最小可用闭环**:做完 P0,"一张采购订单分多批送料"这件事就能真正跑通(能生第二批、剩余量算得准、批次号能追)。
> `P1`/`P2` 是**同一个方案**的体验增强与外围(台账页签、金蝶推送策略、报表),不做也不影响 P0 的正确性。
