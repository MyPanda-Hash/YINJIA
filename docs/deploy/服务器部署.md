# YINJIA-MES 服务器部署

| 属性 | 内容 |
|---|---|
| 文档类型 | 部署说明 |
| 适用场景 | 环境搭建与上线 |
| 维护状态 | 生效 |

> **远程登录与远程运维** —— 服务器对外只开了 **3389(RDP)** 与 **8090(应用)** 两个端口,
> 没有命令行直连的路。人工怎么连、AI/脚本怎么隔着 RDP 把活干完(驱动器重定向、按键约束、
> 日志编码、跨服务器还原的孤儿登录坑),全部见 **`deploy/部署说明.md` 第七节
> 「远程登录服务器与自动化远程操作」**。

## 1. 组件与端口

| 组件 | 说明 | 端口 |
|---|---|---|
| SQL Server | HSDZ_MES 数据库(本机 PANDA 为还原副本) | 1433 |
| **JDK 25(必须)** | 后端运行时;**低于 25 一律起不来**,见 §1.1 | — |
| Spring Boot 后端 | yinjia-mes-backend(SQL 账号 yinjia) | 8090 |
| 前端 dev/preview | Vite(代理 /api → 8090) | 5173 / 4173 |

### 1.1 JDK 版本要求(硬性,不可降级)

| 事实 | 值 |
|---|---|
| 项目要求 | `backend\pom.xml` → `<java.version>25</java.version>` |
| 编译工具链 | `backend\build.bat` / `tools\pull-sync.bat` / `build-appjar.ps1` 三者**都只找 `jdk-25*`** |
| 产物字节码 | `MesApplication.class` = **major 69(= Java 25)** |
| 服务器已装 | `C:\Program Files\Eclipse Adoptium\jdk-25.0.4.101-hotspot`(2026-09-21 安装) |
| 服务器 `start-service.bat` | 自动探测 `jdk-25*` 目录,**无需手工配 PATH** |

**⚠ 2026-09-21 实测事故**:服务器上一度只剩 JDK 21,部署后应用启动即崩:

```
java.lang.UnsupportedClassVersionError: com/yinjia/mes/MesApplication has been compiled by
a more recent version of the Java Runtime (class file version 69.0), this version of the
Java Runtime only recognizes class file versions up to 65.0
```

原因是 `app.jar` 的 `MesApplication.class` 来自上一次 Maven 构建(按 `pom.xml` 的 25 编),**降 JDK 无用** —— 只能装 JDK 25。

**安装 JDK 25**(约 111 MB):

```
https://github.com/adoptium/temurin25-binaries/releases/download/jdk-25.0.4.1%2B1/OpenJDK25U-jdk_x64_windows_hotspot_25.0.4.1_1.msi
```

- 版本:Eclipse Temurin **25.0.4.1+1 LTS**;SHA256 = `517b3590be43120c34c3891d09c97a1eddc12da982208c4f5adf1bdc1b5e3f15`
- 图形安装:勾选 **Set JAVA_HOME variable**;静默安装:
  `msiexec /i jdk25.msi /qn ADDLOCAL=FeatureMain,FeatureEnvironment,FeatureJavaHome`
- 验证:`dir /b "C:\Program Files\Eclipse Adoptium"` 应出现 `jdk-25*`
- ⚠ 服务器 **Schannel 已损坏**,`Invoke-WebRequest` 直接下 HTTPS 会报
  「请求被中止: 未能创建 SSL/TLS 安全通道」→ 在开发机下好再拷过去,或先
  `[Net.ServicePointManager]::SecurityProtocol = 'Tls12,Tls13'`

## 2. 数据库准备

1. SQL Server 需开启**混合认证**(LoginMode=2,见 tools/scripts/enable-mixed-auth.ps1,需管理员+重启服务)。
2. 还原 HSDZ_MES 备份:`RESTORE DATABASE HSDZ_MES FROM DISK=... WITH MOVE 'ASPSMT' TO ..., MOVE 'ASPSMT_log' TO ...`。
3. 初始化元数据:`sqlcmd -S localhost -E -i tools\setup-db.sql`(UTF-8 BOM;幂等,含 yj_* 表、登录 yinjia、11 面板字段种子)。
4. 中文 SQL 脚本必须保存为 **UTF-8 with BOM** 再由 sqlcmd 执行。

## 3. 构建与启动

```powershell
backend\build.bat          # Maven(复用 light-mes 工具链) + JDK 25(见 §1.1,勿降级)
start-project.bat          # 后端 8090 + 前端 5173
# 访问 http://localhost:5173  admin/123456(首次启动自动种子)
```

## 4. 配置项

| 配置 | 环境变量 | 默认 |
|---|---|---|
| JWT 密钥 | YINJIA_JWT_SECRET | 开发默认值(生产必须替换) |
| OCR 密钥 | ALIBABA_CLOUD_ACCESS_KEY_ID / SECRET | 空=扫描填单返回"未配置" |
| 数据源 | application.yml(生产改环境变量注入) | localhost/HSDZ_MES/yinjia |

## 5. 验收清单

1. `tools/scripts/verify-api.ps1` 全部通过(登录/面板配置/读写/审核/作废/档案全量保存/库存状况/通知/OCR 路径)。
2. 浏览器过一遍:登录 → 基础资料(单单据内联编辑)→ 单据(新增/保存/审核/弃审)→ 参照弹窗 → 库存状况。
3. SQL Server 侧抽查:新单据行 asp_user1 留痕、s_allno 新号、yj_doc_status 状态正确。

## 6. 连接生产库的切换

application.yml 数据源指向生产 SQL Server(如 172.16.48.17)即可,元数据与代码不变;切换前确认混合认证、防火墙与账号权限,并先用只读方式核对表结构一致。
