### D1 · 2026-09-21 · C6 批次口径：**只用「批次号」，删除「批号」**

**决策**
1. C6 一律按 **「批次号」** 实现，不再保留「批号」这个并行语义。
2. **批次号在「送料暂收单」上产生**（分批送料取号，规则 `<采购订单号>-<3位序号>`），**转来料检验单及其下游时继承**，中间不重新取号。
3. 因此 C6 的链路是：**采购订单 →（分批送料取批次号）→ 送料暂收单 → 来料检验单 →（采购入库单 / 暂收退回单）**，全程只有一个批次标识。

**「批号」删除范围（已定位，共 4 处，全部在品检分流链内）**

### D2 · 2026-09-21 · C7 + C8 检验结论改三态：**合格 / 不合格 / 特采**

**决策**
1. 来料检验单的检验结论改为 **合格 / 不合格 / 特采** 三选一。
   - 现状：`QC_INSP.总结论` = 合格 / 不合格 / **让步接收**（**没有"特采"**）；另有 `处置方式` = 入库 / 退货 / 让步入库（**后端零消费的死字段**）。
2. 后续 **先出实现方案再动代码**（本台账只记录，不实施）。

**实现方案必须覆盖的 5 点**（方案文档待产出）
1. 下拉术语统一（加/改「特采」）+ 多语言词条；
2. **特采闸门**：检验单选「特采」须校验"存在已审批的特采申请单"（C8 ①④）；
3. **特采标记字段**：检验单 / 采购入库单上加标记，转入库单时带下去（C8 ⑤）；
4. 「处置方式」死字段：接线（驱动入库/退货分支）**或**删除，二选一；
5. 转 ERP 时特采单的处理口径。

**前置（不解决就落不了地）**
- C8 ③ 特采单 **Word 固定格式 → PDF** 的落地方式（现报表模板只收 `.jrxml`；前端只能预览外部 docx，不能把面板数据渲染成 Word 版式）→ **需与采购拍板三选一**：重画 jrxml / 新增 docx 模板通道 / 文书式表样 + 浏览器打印。
- 企业侧：特采单最新版格式（`品质资料 2026.09.19.xlsx` 的「特采单」sheet 是**一张内嵌图片**，需人工转写字段）。

**状态**：⏸ 待出方案（优先级由你指定）。
