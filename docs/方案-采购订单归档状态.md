# 方案:采购订单"归档"状态(全量入库后自动锁定)

## 一、目标

采购订单的货物经采购入库单**全部入库**后(允许分批:数量分批 + 不同货物分批),
订单自动进入 **已归档** 状态——列表可见、可查,但**不能再进行任何业务操作**
(选单引用/审核/弃审/删除/修改/中止),入库弃审冲回后自动解除。

## 二、现状盘点(已具备的基础)

| 基础 | 现状 |
|---|---|
| 头级关联 | `bd_purchase_in.采购订单号`(选单时回填)✓ |
| 行级占用 | `form_flow_link` 已有 PU_ORDER→PURCHASE_IN 流(选单写入 source_quantity/linked_quantity)✓ |
| 归档位 | `yj_doc_status.archived`(文件面板已用)✓ |
| 状态显示 | `QueryService` 由状态机组合出 单据状态 文本 ✓ |
| 按钮禁用 | 前端按状态禁用 + 后端 ButtonService 校验 ✓ |

## 三、归档判定口径

**入库完成 = 该订单全部物料行的「已审核入库量」≥「订单量」**

```
对每一张候选订单:
  订单行(bl_pu_order): 物料编码 × SUM(数量)
  入库行(bl_purchase_in JOIN bd_purchase_in):
    WHERE 采购订单号 = 订单号 AND 单据状态='已审核'
    GROUP BY 物料编码 × SUM(实收数量)
  全部物料: 入库量 ≥ 订单量  → 归档
  任一物料不足            → 不归档
```

- 允许**数量分批**(多张入库单累计) ✓
- 允许**货物分批**(先入 A 料后入 B 料,全齐才归档) ✓
- 只算**已审核**入库(草稿/审批中不算) ✓
- 允许超量(超量也归档;超量校验列为可选项,见 §七)

口径取"头关联+物料聚合"而非严格行级 link:实现简单、天然覆盖手工建的
非选单入库单(填了采购订单号即认)。行级 link 作为二期严格化路径。

## 四、触发点(事件驱动 + 兜底重算)

| 时机 | 动作 |
|---|---|
| **入库单审核**通过后 | 取该单 `采购订单号` → 执行归档判定 → 齐则 `yj_doc_status.archived='Y'` + `bd_pu_order.单据状态='已归档'` |
| **入库单弃审**后 | 同一订单重算 → 不齐则解除(archived=NULL,状态回'已审核') |
| 入库单删除/作废后 | 同上重算 |
| 兜底:管理员批量重算 | 一个 SQL/按钮,按全部 PU_ORDER 重算(修数用,平时不需要) |

## 五、归档后的锁定清单

| 操作 | 处理 |
|---|---|
| 采购入库**选单**引用 | 选单来源列表过滤 已归档(不能再对它入库) |
| 审核/弃审(订单自身) | 后端 ButtonService 校验拒绝:"订单已归档" |
| 删除/中止/修改 | 同上拒绝 |
| 前端按钮 | 已归档 → 除 查找/刷新/打印/预览/导出/审批情况 外全部禁用 |
| 显示 | 单据状态列 = **已归档**(shr 非空 && archived='Y' 的组合文本);侧栏状态标签加灰色/紫色"已归档" |

## 六、状态流转图

```
草稿 ──审核──▶ 已审核 ──(入库分批累计)──▶ 已归档
  ▲              │ ▲                        │
  │              │ └── 弃审(未归档时) ──────┘
  └── 弃审 ◀─────┘      入库弃审冲回 → 不齐 → 自动解除归档回 已审核
```

## 七、可选增强(默认不做,确认后才加)

1. **超量阻止/警告**:入库行保存时校验 该订单该物料累计入库 ≤ 订单量(软警告 or 硬阻止)
2. **行级严格对应**:归档判定改走 form_flow_link 行级(阻止"同物料不同行"混算)
3. **部分归档视图**:订单列表加"入库进度%"列(已入/应入)

## 九、测试用例

1. 订单 100 个分两张入库单 60+40 → 第二张审核后订单=已归档
2. 订单两种物料,先入 A 后入 B → B 入完才归档
3. 已归档订单:选单列表不出现;点弃审/删除 → 拒绝提示
4. 弃审其中一张入库单 → 订单自动回 已审核
5. 入库 120(超量) → 归档;(若选增强1则另有提示/阻断)
