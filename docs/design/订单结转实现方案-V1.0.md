# 订单结转 · 实现方案 V1.0

> 2026-09-22 定稿。来源：生产部结转需求讨论 + 参考系统《订单结转》页面截图(页面形态以截图为准)。
> 状态：**已实施（2026-09-22）**——后端 OrderConvertService/Controller + 前端 OrderConvert.vue + 路由菜单(生产计划→订单结转,置首位) + i18n;探针 `tools/archive/_probe-order-convert.cjs` 按 §5 清单全绿(含删草稿占用释放自愈)。

## 1. 要解决的问题

- 销售订单由 ERP 拉入、**拉入即已审核**，MES 侧无法用单据状态区分"已转生产/未转生产"，已转与未转数据混在销售订单面板里。
- 需要一个**发单工作台**：判断每行订单"库存/排产够不够"，然后**转加工单（自制）或转采购单（外购成品）**，处理完的行自动从工作台消失。
- 防重复保证：**行级占用链 `form_flow_link`**（SO→各目标单据，转多少记多少占用）——"剩余数量=需求数量−各通道占用之和"，转满的行自然消失，重复提交被后端剩余量校验拒绝（双保险：列表过滤 + 后端守卫）。**不修改销售订单状态**（ERP 同步真源不可动）。

**定位原则**：结转页只是**发单调度台**（判断+生成单据+跳转），生成的加工单/采购申请是标准面板单据，后续排产/审核/报工/采购审核仍按全系统面板↔面板流转。

## 2. 页面形态（按参考截图，银嘉口径替换）

### 2.1 顶部汇总条（蓝底白字，同参考）

```
未结转订单汇总(总订单笔数: N 总款数: N 总下单数量: N)；
今日结转订单汇总(总订单笔数: N 总款数: N 总下单数量: N)；当前数据(N)笔
```

- 未结转 = 剩余数量>0 的行汇总；款数 = distinct 物料编码；数量 = SUM(需求数量)。
- 今日结转 = `form_flow_link.create_time` 为今日的 SO→(加工单|采购申请) 占用汇总。

### 2.2 工具栏

`查询条件(订单号/客户/物料)` + `刷新` + `【转工单】` + `【转采购单】`（勾选行后点按钮，支持多行批量）。
**无转外包单**（用户 2026-09-22 拍板不做）。

### 2.3 表格列（参考图列 → 银嘉列映射）

| 参考图列 | 银嘉列 | 来源 |
|---|---|---|
| ☑ 复选 | ☑ 复选（批量转单用） | — |
| 图片 | 图片（占位，后续接商品图片） | bs_inv 图片 |
| 订单资料(订单号+物料编码 堆叠) | 订单号 + 物料编码 + 品名 堆叠 | bd/bl_so_order |
| 下单日期 / 交货日期 | 下单日期 / 交货日期(行级优先) | 同上 |
| 客户 | 客户 | bd_so_order.客户 |
| 需求数量 | 需求数量（订单行数量，xq_sl） | bl_so_order.数量 |
| 已排产数量 | **已排产数量** = SUM(SO→MANU_ORDER ACTIVE 占用) | form_flow_link |
| 已外包数量 | **不做**（外包未启用，列不渲染；结构预留） | — |
| 已采购数量 | **已采购数量** = SUM(SO→PU_REQ ACTIVE 占用) | form_flow_link |
| 剩余数量 | **剩余数量** = 需求数量 − 已排产 − 已采购（**必须展示**，用户确认） | 计算 |
| 镀种/面厚/材质（电镀域） | **型号(规格型号) / 重点管控 / 客户订单号**（银嘉口径替换） | bl_so_order |
| — | 客户等级（bs_partner.客户价格等级，可选展示） | bs_partner |

**行为**：剩余=0 的行**不显示**（转满自动消失）；部分转的行保留并实时更新 已排产/已采购/剩余；下游工单/采购申请草稿被删 → 占用释放 → 行**自动回现**（自愈）。

## 3. 动作与判定逻辑

### 3.1 转工单（勾选行，逐行处理）

- 生单数量 = **剩余数量**（默认全额；转出后在加工单上可拆单/改量；同一行可多次转，剩余递减）。
- 复用 `QuickScheduleService.createFromOrderLine(行id, 生单数量)`：生成加工单草稿 + `linkLine(SO→MANU_ORDER, 数量)`（占用守恒已内置，超剩余直接拒绝=防重复）。
- 转满 → 行从列表消失；未转满 → 行保留、已排产/剩余刷新。
- 成功提示含新加工单号，提供"前往加工单"链接（gotoPanel 语义，不强制离页）。

### 3.2 转采购单（勾选行，逐行处理）

- **口径：采购的是订单产品本身**（参考图三通道语义：排产/外包/采购都是"订单交付通道"，已采购数量与已排产并列）。
- 生成 **采购申请 PU_REQ 草稿**：头=请购人/单据日期今日/需求日期=交货日期/销售订单号/来源单据=销售订单/来源单号=订单号/备注"订单结转"；行=**存货编码=产品编码、数量=剩余数量**。
- `linkLine(SO→PU_REQ, 数量)`（**新增占用链**，已采购数量与防重复依赖它）；重复点击因剩余递减自然受限。
- 生成后站内消息推采购（复用 MessageService，收件人=能看 PU_ORDER 的角色 ∪ 管理员）。

### 3.3 与 BOM 齐套的关系（重要口径）

参考页本身不做 BOM 计算，三通道按订单数量分配即可。**BOM 齐套/材料缺口采购属于生产领料链路**（已有 v_wo_kit 齐套表 + 加工单「生成采购申请」按 BOM×排产−库存），与本页**互不替代**。
可选增强（二期）：转工单前若产品有默认 BOM，附带材料齐套提示（提示不阻塞）。

## 4. 技术实现清单

## 5. 验证清单（实施后探针必须全绿）

1. pending 只含 剩余>0 的已审核行；已转满行不出现（占用过滤）。
2. 转工单：生成加工单、已排产数量+剩余联动、占用链正确；**同一行重复转 → 第二次剩余不足自动拒绝/只转剩余**。
3. 转满后行消失；删除加工单草稿 → 占用释放 → 行回现（自愈）。
4. 转采购单：PU_REQ 生成（产品级行，数量=剩余）、来源单据/单号正确、SO→PU_REQ 占用记账、消息送达。
5. 汇总条勾稽：未结转笔数/款数/数量 = 列表聚合；今日结转 = 当日占用聚合。
6. 部分转中间态：需求1212 → 转1000 → 剩余212 的行保留且数字正确（对齐参考图样例）。

## 8. 2026-10-06 增补：左上角日期查询 + 分页（用户报障修复）

> 用户报障原文：「**就是太多了会卡死，不能一次全部显示出来**」；要求「左上角加日期查询，
> 点进来只显示单日数据，然后可以设置成可选择近几日」。同日拍板口径：按**下单日期**过滤、
> 默认单日 = **今天**。
>
> 追加口径（同日第二版，用户原话「当前没数据跳转到最近的数据日期需要**弹窗提示询问**，
> 而不是直接跳转到最近的数据日期」）：当天没有待结转数据时**先问再跳**，不再静默跳到
> 最近有数据的那一天。

### 8.1 页面（`OrderConvert.vue`）

| 件 | 口径 |
|---|---|
| 左上角日期查询 | `档位下拉`（**单日** / 近3天 / 近7天 / 近14天 / 近30天）+ `日期`。单日 = 该日一天；近N天 = **以所选日期为截止日往前数 N 天（含端点）**，此时标签变「截止日期」并回显区间 `2026-09-21 ~ 2026-09-27` |
| 默认值 | 打开即「单日 = **今天**」并直接查（不会一进页面就拉全量历史） |
| 当天没数据的处理 | **弹窗询问**「`<今天>` 没有待结转数据, 跳到最近有数据的一天 `<最近下单日>`?」→ 按钮 `跳转` / `留在本日`。**只在打开页面时问一次**（之后用户自己切日期/刷新不再打扰）；选「留在本日」就停在当天，空表里另给「跳到最近有数据的一天 `<日期>`」近路按钮 |
| 近路兜底 | 空表（任意日期/档位）都显示提示，并在「最近有数据的一天不在当前窗口」时给出跳转近路；单日档另给「看近7天」 |
| 切档即查 | 档位/日期/关键字任一变化 → 回第 1 页并重查（不再需要点两次「查询」） |
| 分页 | 表格改**前端分页**（默认 100/页，可选 50/100/200/500），勾选靠 `row-key + reserve-selection` 跨页保留 —— 这是"不一次全渲染"的兜底 |

### 8.2 后端（`OrderConvertService` / `OrderConvertController`）

- `/pending`、`/stats` 的 body 增加 `dateFrom` / `dateTo`（`yyyy-MM-dd`，**含端点**；
  止日按 `< 次日` 比较，含当日整天时间戳）。缺省不传 = 不限（**老调用方行为不变**）。
  格式非法直接 **400**（不静默变"不限"）。
- `pending()` 的 `FROM…WHERE` 抽成常量 `PENDING_FROM`，与聚合共用，避免两份 SQL 走偏。
- **`stats()` 不再 `pending("")` 拉全表再在内存里数数**（那等于每次开页把整份待结转明细查两遍），
  改成 SQL 聚合 `pendingAgg()`：行数/款数/下单数量 + `MAX(下单日期)`。
- 汇总条口径：**「未结转订单汇总」仍是全量积压**（§2.1 语义不变）；
  **「当前数据笔数」= 当前日期/关键字口径**（与列表逐行对得上）；新增返回 `最新下单日期`
  （无论带不带日期条件都返回全量口径）—— 前端既用它写弹窗文案，也用它做空表近路。
- 踩坑：可选条件用 `? = ''` 哨兵写法时，**日期参数必须传空串而不是 JDBC `null`**
  （null 会让条件求值成 NULL ⇒ 一行都查不出来）。见踩坑台账 D18。

### 8.4 遗留

- **生产环境待确认**：若单日行数本身就上千（比如把 30 天档当默认），前端分页只封住渲染、
  仍会把整窗口数据取回。届时改**服务端分页**（`/pending` 加 `page/pageSize` 返回 `{list,total}`，
  勾选仍靠 row-key 保留）即可，接口参数已按此预留 `dateFrom/dateTo` 语义。
