# 出货检验功能记录表(YJ-QR-154)表样改造 — 实现契约(v1,2026-11-11)

> 用户口径:
> 1.「将当前的组装成品检验修改为出货检验表观」(只改显示名,面板代号/表结构/单据前缀不动)
> 2.「将当前的出货检验列表的格式修改为图2所示的形式。表格内的信息填写按照图中各个表格形式进行」
>
> 图2 = 《出货检验功能记录表》:抬头 3 行(单据编号|检测周期 / 产品编码|工单号 / 产品型号|抽检方案)
> + 「检验明细」矩阵(检验项目|检验方法|检验要求 + **多个内部生产批次**,每批两列:批次号 + 结果判断)
> + 表尾 2 行(检验人|检验结论 / 审核人|处理意见)。

| 项 | 落点 |
|---|---|

| 第1条改名 | `QC_ASM_INSP`(组装成品检验单)→ 显示名 **出货检验表观**;面板代号、`qc_asm_insp_*`、单号前缀 ZJ、历史数据、审批状态**全部不动** |
| 旧单 | 也按新表样显示(无批次数据的旧单 = 单批次列,批次号取头「批次号」,结果取明细「结果判断」) |

## 二、数据模型(设计决策:批次行摊在明细表里,不新建子表)

`qc_proc_insp_detail` 增列 **`内部批次 nvarchar(60)`**;**一行 = (检验项目 × 内部批次)**:

- 同一检验项目的 `检验要求`/`检验方法` 在每个批次行上各存一份(UI 编辑时**写穿**到同项目的所有行);
  `结果判断`(已是下拉框 合格/不合格)= **该批次该项目**的判定。
- 批次清单与顺序存在头表新列 **`内部批次清单 nvarchar(500)`**(英文逗号分隔,如 `261105,261107,261108`)——
  它保证「先加批次、后带入检验项目」也能记住列(行上没数据时列不丢)。
- 旧单:`内部批次清单` 空 + 明细 `内部批次` 空 ⇒ 渲染为**一个**批次列,批次号 = 头 `批次号`(空则「本批」),
  结果 = 该行 `结果判断`;旧单可编辑草稿一旦保存,自动回填 `内部批次清单` 与各行 `内部批次`。
- 为什么摊在明细表:本系统的明细页签 = 单张行表(`PanelDef.lineTable()` 单表),通用保存(`ButtonService.save`)
  只认这一张行表;新建子表要么加自定义保存链路(所有保存入口都要接),要么冒「提交审批时批次数据没落库」的风险。
  摊在行表 = 批量/草稿/提交审批/弃审所有路径天然一致,零后端保存改动。

### 字段清单(新增/修改)

| 表 | 列 | 说明 | yj_field(label/place/hidden) |
|---|---|---|---|
| qc_proc_insp_detail | `内部批次` nvarchar(60) NULL | 该行所属内部生产批次 | `内部批次` / detail / **hidden=0 visible=1**(必须在明细字段集合里,通用保存才会带) |
| qc_proc_insp_head | `内部批次清单` nvarchar(500) NULL | 批次列顺序(逗号分隔) | `内部批次清单` / header / hidden=1 |
| qc_proc_insp_head | `表单审核人` nvarchar(50) NULL | 纸面审核人(默认冯敏、可改) | `表单审核人` / header / hidden=1 |
| (派生) | `检测周期` | 首次保存时间 ~ 末次提交/审核时间,**后端派生只读** | yj_field 不建(虚拟字段,QueryService 下发) |

`总结论`(检验结论)改 `data_type=下拉框` + 选项 合格/不合格;
`处理方式`(处理意见)改 `data_type=下拉框` + 选项 允收/合格/不合格/报废(sheet 允许手工新增)。

## 三、前端表样(QcProcInspSheet.vue)

```
出货检验功能记录表                                   表单编号：YJ-QR-154
┌───────────┬──────────────┬──────────┬──────────────┐
│ 单据编号  │ <编号 ZC-…>  │ 检测周期 │ <派生文本>   │
│ 产品编码  │ <产品编码>   │ 工单号   │ <工单号>     │
│ 产品型号  │ <规格型号>   │ 抽检方案 │ <检验方案>   │
└───────────┴──────────────┴──────────┴──────────────┘
检验明细                        [＋新增检验项] [⧉带入检验项目] [＋添加批次]
┌────────┬────────┬────────┬──────┬──────┬──────┬──────┐
│检验项目│检验方法│检验要求│批次号│结果  │批次号│结果  │…
├────────┼────────┼────────┼──────┼──────┼──────┼──────┤
│ 行(一行一个检验项目,批次列 = 每个内部批次一组「批次号(可改) + 结果判断(下拉)」) │
└────────┴────────┴────────┴──────┴──────┴──────┴──────┘
┌────────┬──────────────┬──────────┬──────────────────┐
│ 检验人 │ <检验员>     │ 检验结论 │ <总结论 下拉>    │
│ 审核人 │ <表单审核人> │ 处理意见 │ <处理方式 可新增>│
└────────┴──────────────┴──────────┴──────────────────┘
```

交互:
- **添加批次**:`内部批次清单` 追加一个空批次名(默认 `新批次N`),给每个检验项目各加一行(结果空);
  批号在表头格内直接改(改 = 同批所有行 `内部批次` + 清单项一起改);**删除批次** = 删清单项 + 该批所有行。
- **新增检验项**:每个批次各加一行(保证矩阵每格都有落点);**删除检验项** = 删该项目的所有批次行。
- **带入检验项目**(QcInspPlanDialog,来源《出货检验计划表》RD_INSP_PLAN):带入的行没有 `内部批次` ⇒
  组件内规范化:按当前批次清单把每行复制成 N 行(每批一行);清单为空则先建一个默认批次。
- 检验要求/检验方法编辑**写穿**同项目所有批次行(避免"改了一个批次、别的批次还是旧值")。
- `el-select` 选项取 `detailFields` 里该字段的下拉选项(yj_field.dict_sql 下发),有 options 才渲染下拉。

① 关联字段放**表头两个参照**(出货检验功能单号 / 出货检验表观单号);

| 「已进入」的三条(任一成立) | — | ① 路线里「组装/装箱」那道的前道已审报工流下来(可加工量折成品 > 0,即台账「已落实」);② 该道自己已有已审报工(兜手机端直写/存量跨序);③ 工单当前线 `plang.scx` 或该道台账**实际**生产线属「组装」车间(装箱归组装;⚠ 只看实际线,不看预排的计划线 —— 排产时每道都预计划线,拿它判会让整批未生产的单在排产那刻就出单) |
| 触发面 | 报工单审核 / 手机端报工吸收 | 不变(同两条钩子),差别只在判据 |
| 工序/报工数量 | 工序=报工工序(组装);报工数量=组装累计已报工 | 工序=**命中的组装环节工序**(组装/装箱);报工数量=`max(该道可加工量, 该道已审报工)`(提前出单那刻「组装累计报工」还是 0,纸面会像空单) |
| 占用链 | `form_flow_link(source=WO_REPORT/SCJL)` —— 弃审报工会级联作废 | 表观单记 `source_panel_code='ASM_ENTRY'`(来源=工单号):切炭报工触发的那张单**不挂**到切炭报工上,否则弃审切炭报工会被表观单挡住/连带作废(业务上无关) |

### 9.2 「选生产工单」入口(手工建单)

- 位置:`QC_ASM_INSP` 工具栏「更多」组,与制程检验单**同一弹窗**(`QcProcInspWoPicker` 增加 `mode='asm'`)。
- 后端新入口 `QcAsmInspController`(`GET /api/qc/asmInsp/woLines`、`POST /api/qc/asmInsp/fromWoLine`):
  - 列表 = 未作废 + 未结案 + 工艺路线含「组装/装箱」的工单行;逐行下发**进入环节/进入量/已审报工量/可开单/已建单号/生产状态**;
  - 准入 = 已进入组装/装箱(同 9.1 判据);未进入的行**照旧列出并置灰** + 原因(门禁不藏行,与制程一致);

- 前端回执话术按目标面板分:首件检验单 / 出货检验表观 / 出货检验单功能(新增 en 词条,切英不露中文)。
