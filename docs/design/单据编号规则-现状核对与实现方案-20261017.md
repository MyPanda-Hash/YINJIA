# 单据编号规则(前缀表)——现状核对、实现方案与风险评估

> 输入:用户 2026-10-17 提供的《单据编号.txt》(68 条「单据 → 两位前缀」规范,已逐字收录于 §1)
> 口径:暂收链 **保持现状**(送料暂收单 SL / 暂收退料单 TH),且**不进 `inh`**(不影响库存)。
> 本文只做设计,不含任何实际操作。文末 §8 给需要用户拍板的 5 件事。

---

## 0. 一句话结论

**当前实现不是这样。** 68 条规范里只有 **5 条**前缀对得上(客户订单 OD / 生产工单 GD / 生产日报 RB / 委外工单 WW / 资产保养 BY,其中 **客户订单 OD 只是名义对上**——真正在跑的销售订单号由金蝶按客户码出)、**3 条**按用户口径保留或属档案不取号(暂收 SL / 暂收退回 TH / 客户 KH),
其余 **60 条**:要么"有面板但前缀不符"(**12 条**),要么"系统里根本没有这张单据"(**48 条**,其中 **7 条**的前缀已被别的面板占走:CH/ZC/ZJ/YC/SK/WL/YF)。

更要紧的是:**6 张库存核算单 + 采购/销售订单的实际单号,现在基本都由金蝶 ERP 出**(如 `CGRK-20260901-03098`、`YJ-20260901-01`),不是 MES 取的号。所以"把采购入库叫 JH"这件事,只改 MES 只能改到**未来 MES 新建草稿**的号,改不到已经/将来从金蝶同步进来的单据——那要改金蝶的编码规则(§4 C1)。

## 2. 现状:MES 的单号到底是谁生成的

### 2.1 MES 自取号:唯一入口 `FormNoService`

`backend/src/main/java/com/yinjia/mes/service/FormNoService.java`

- 格式:**`前缀-yyyy-MM-NNNN`**(如 `PG-2026-09-0001`),2026-09-07「方案 A」定稿;
- 号池:**`s_allno`**,按 `lb=前缀` + `ny=yyyy-MM` 走 `MAX(RIGHT(dh,4))+1`,取号必写池(不回收);
- 预览:`preview()` 不写池(新增表单的默认号);
- 查重:`exists()` = `s_allno.dh` ∪ `inh.单据编号`(2026-09-30 修掉了引用 `inh_no` 的 500);
- ⚠ **没有空前缀守卫**:号池里实测有一条 `lb=''` / `dh='null-2026-10-0001'`(2026-10-05 16:10 / admin)——即 `next(null)` 会把字符串 `null` 拼进单号。这类"脏前缀"恰好是本方案要防的东西,纳入 D5。

**前缀从哪来**:`yj_panel.prefix`(`PanelRegistry.java:223` 加载),面板驱动,零代码成本。

**调用点共 8 处 / 5 个文件**(这就是全部):

| 位置 | 用途 | 前缀 |
|---|---|---|
| `ButtonService.java:401` | 新建空白草稿 | `def.prefix()` |
| `ButtonService.java:449` | 保存(无号时) | `def.prefix()` |
| `ButtonService.java:5364` | 复制单据 | `t.prefix()` |
| `PanelFacade.java:45` | 新增表单预览号 | `def.prefix()` |

> 写死的 3 处(共 4 个前缀)不在 `yj_panel` 里,改前缀时**必须同步改代码**,否则面板显示与实号不符。

> 串号的后果不是 DB 报错(各表 `单据编号` 独立),而是**同一前缀下两个单号序列互相跳号**,人眼与对账都难受。

## 4. 设计前必须承认的 4 个硬约束

**C1 — 库存与订单单据的号,99% 由金蝶生成,MES 无权决定。**
金蝶推送时**不传 `bill_no`**(`KingdeePushService.java:255` 注释:"不传 bill_no → 金蝶自动生成编号")⇒ 金蝶按账套内「单据编码规则」出号(`CGRK-`/`XSCK-`/`SCLL-`/`CPRK-`/`QTRK-`/`QTCK-`)。MES 侧改 `prefix` 只影响"MES 新建草稿"的号,**改不到金蝶号**。
⇒ 若真要"采购入库单号以 JH 开头",必须在**金蝶后台改编码规则**,不在本仓库范围。

**C2 — 采购订单是唯一"MES 号会进 ERP"的单据。**
`KingdeePushService.java:262`:`if (isOrder) body.put("bill_no", docNo);`——直推采购订单时把 MES 单据编号当金蝶单号。改 PO 前缀 = **直接改金蝶里的订单号**(历史 187 单全是 `YJ-yyyyMMdd-NN`)。

**C3 — 订单号是跨系统关联键,不能改花。**
`resolvePoRefs(poNo)`(`:363`)、`resolveSoRefs(soNo)`(`:400`)按**单据编号**去金蝶查源单,查到的号写进 `src_bill_no`;采购订单还有"同号已存在"查重(`:230`)。

**C4 — 暂收不进 `inh` 这件事,现状已经是对的。**
`StockLedgerService.postsStock()` 只认 6 张单:`PURCHASE_IN / FINISH_IN / OTHER_IN / MATERIAL_OUT / SALE_OUT / OTHER_OUT`。`QC_RECV`(送料暂收单)与 `QC_RETURN`(暂收退料单)都不在内 ⇒ 它们**不会**写 `inh`/`kucun`。
⇒ 本方案对暂收链**零改动**(编号与过账都不碰),只是把这条口径写进基线,防止以后有人"顺手"给它加过账。
