# 动态字段扩展(备用列池)设计 V1.0

| 属性 | 内容 |
|---|---|

## 1. 背景与定位

引擎层本就元数据驱动:面板字段 = `yj_field` 行,`加字段=插行不改代码`是既有契约。
当前瓶颈在**物理列**:加字段要走 迁移脚本→进链→两账套 DbSync,必须技术角色参与。
本设计把"插行"升级为**带守卫的管理动作**,承载于**预置备用列池**——运行时零 DDL。

**同类先例**:`saveColumnPrefs` 已在运行时 UPDATE `yj_field` + `registry.reload()`
(`PanelConfigService.java:1287`),本设计是同一模式从 UPDATE 到 INSERT/DELETE 的自然延伸。

## 2. 术语

- **备用列池(spare pool)**:业务表预置的 `备用1..备用20`(nvarchar(500) NULL)。
- **动态字段(dynamic field)**:`col_name` 指向备用列的 `yj_field` 行;对引擎与普通字段无差别。
- **绑定(bind)**:管理员把新标签登记到空闲备用列的动作(纯元数据 INSERT)。
- **退绑(retire)**:删除 `yj_field` 行使字段从界面消失;备用列数据原样保留。

## 3. 备用列池

| 项 | 规格 |
|---|---|
| 列名 | `备用1` … `备用20`(中文,与库内列名口径一致) |
| 类型 | `nvarchar(500) NULL`(NULL 存储成本≈0;满载由 SQL Server 行溢出页自动处理,库内最大表 3.5 万行,无感知) |
| 适用表 | **139 张**(2026-09-28 实测):前缀 `bs_/bd_/bl_/rd_/qc_/wo_` **且**被 `yj_panel.line_table/head_table` 引用的物理表(排除视图/`yj_`/白名单冻结表/未被引用表) |
| 注明 | 建列时 `MS_Description='预留扩展字段(未绑定)'`;绑定时更新为 `<标签>(动态字段,绑定<备用N>)`;退绑时更新为 `预留(已停用:原<标签>)` |
| 落地 | `tools/gen/gen-spare-columns.cjs` 生成幂等迁移 `migrate-spare-columns.sql`(`IF COL_LENGTH` 守卫 + 扩展属性幂等),进链,两账套执行 |
| 池耗尽 | 重跑生成器扩 `备用21..40`(同一安全模式);运行时不做 DDL |

### 3.1 与《数据库规范》的对齐(强制,逐条可验)
备用列池与动态字段**不得绕过** [数据库规范](../development/数据库规范.md);落地时按下表逐条自检:

| 规范条款 | 本设计的落点 | 验收方式 |
|---|---|---|
| §1.2 列名:中文标签即列名,禁 `. % / ( )` 与空格、禁首尾空格 | 列名固定 `备用1..备用20`;绑定后**列名不变**(新名字进 `label`,显示差异走 `alias`) | G1 + 体检 01 |
| §2.1 必备列 | 只加备用列,不动既有主键与审计四件套 | 体检 04 |
| §2.2 类型口径:文本用 `nvarchar` | 统一 `nvarchar(500) NULL`,不引入 `char/varchar/float` | 体检口径(规范 §6) |
| §2.4 列级中文注明 | 建列即写 `MS_Description='预留扩展字段(未绑定)'`,绑定/退绑同步改写 | 体检 03 —— **基线已收到 0:新列无注明 = FAIL(不是 WARN)** |
| §3 元数据:一列一标签 / place 收口 / 新字段必有 en 译名 | G1-G3 守卫 + §4 的 `yj_translation` INSERT + place 规则 | 体检 08 / 09 —— **基线 0:无 en 译名 = FAIL** |
| §4 库变更走幂等脚本 + 两账套执行 | 建池 `migrate-spare-columns.sql`、`yj_ext_bind_log` 建表同 | `DbSync sync` 两账套「执行 0、失败 0」 |
| §4 例外:**运行时元数据写入** | 绑定/退绑按 `saveColumnPrefs` 先例不入链(§11 已声明),但必须 G1-G7 守卫 + `yj_ext_bind_log` 全量审计 | 审计表可回溯;该例外已在规范 §4 登记 |
| §7 阶段 3(一列多标签待收敛) | 动态字段天然一列一标签,不得成为**新的**多标签来源 | 体检 08 不新增未登记组 |

> 即:备用列是"新列",动态字段是"新字段" —— 规范对新增对象一律 FAIL 级判定,**没有过渡期**。

### 3.2 分页签面板的变体:每张表各 20 个扩展位 + 父子字段(2026-10-04 起)

**来料检验要求(QC_INSP_REQ)** 是「一张宽表当多张表用」的档案面板:行靠 `物料类别` 分流到 8 个页签,
每张表各有各的列。用户口径:①自定义列要**单独针对每个表**;②扩展池**每张表 20 个**;
③自定义列支持**父子**(父只做分组表头、无数据格),检验数据记录**只带入子字段**。

| 项 | 口径 | 承载 |
|---|---|---|
| 列属于哪张表 | 每张表各有各的自定义列,互不串;不同表**允许同名**列 | `yj_field.tab_key` = 页签名(= 物料类别 字典值);标签唯一性收窄为「**同页签内**唯一」 |
| 扩展池 | **每张表 20 个**(8 张表 = 160 位),按页签顺序分段:第 i 个页签 = `备用[(i-1)*20+1 .. i*20]` | `tools/migrate-qc-insp-req-tab-pools.sql`(备用1..备用160);绑定只在**本页签段内**找空闲列 |
| 父子字段 | 父 = 分组表头(**没有数据格、不占数据列**),子 = 真正的数据列 | `yj_field.col_group`(其固有语义「父表头分组」,与固定表的 规格/外观 同一套两行表头渲染) |
| 带入检验数据记录 | 列的解析只有一处(`core/qc/qcInspReqCols.js`):固定列 + 该表自定义子列,**父名永不成为检验项** | 渲染与带入同源 ⇒ 不会出现"界面看得到、报告带不进来" |

> 分段顺序必须与 `yj_field.物料类别` 词表顺序(= 前端 `qcInspReqConfig.js` 页签顺序)一致 ——
> **加页签要三处一起改**:词表(`migrate-qc-insp-req-custom-tab.sql` 那类)、页签配置、扩展池分段。

## 4. 绑定机制(数据流)

```
授权用户:面板「更多 ▼」→「字段管理」(2026-10-09 起 = 管理员 ∪ 该面板被授予「自定义字段」的角色)
  表单:中文名* / 英文名* / 类型* / 词表(下拉时) / 位置(doc:表头|明细) / 进查询区 / 列宽 / 必填
        │
        ▼ POST /px/extField/add
守卫(§5 全过) → 取目标表(按 place 定 head_table/line_table)第一个空闲备用列
  INSERT yj_field (col_name=备用N, label, label_en, data_type, dict_sql, place, seq=MAX+10, width, editable=1, required, visible=1, hidden=0)
  INSERT yj_translation (scope='field', ref_key=label, locale='en', text=labelEn, source='manual')
  UPDATE MS_Description → registry.reload()(账套级缓存刷新)
  INSERT yj_ext_bind_log(action='bind')
        │
        ▼
面板刷新 → 列表列/表单格/查询条件/导出列 自动出现新字段
```

**place 规则**:doc 面板 `header`→绑 `head_table` 备用列、`detail`→绑 `line_table` 备用列,
可叠加 `query`;archive 档案面板固定 `detail`(既有"基础档案单单据结构"规矩)。

## 5. 守卫(服务端强制)

| # | 规则 | 违反→ |
|---|---|---|
| G1 | label 非空、≤60 字符、禁 `.` `%` `/` `(` `)` 与空格、禁首尾空格(列名安全规范) | 400 |
| G2 | label 在该面板内唯一(数据键唯一) | 409 |
| G3 | 一列一标签:**占用 = 该表该列被任一面板的 `yj_field` 行引用**(表可跨面板共用,占用判定必须全局面板范围) | 409(池满→提示走正式迁移) |
| G4 | 空闲备用列若含历史数据(COUNT 非 NULL>0)→ 返回行数与告警,须显式 `confirmDirty=true` 才绑;可选 `clearFirst=true` 清空(**全系统唯一写业务数据的动作,仅此一处**) | 409 |
| G5 | 权限:该面板的「自定义字段」授权(词 `field`;管理员恒过)—— 2026-10-09 用户口径「自定义字段需要在组织权限里面能够配置;现在的来料检验要求的自定义字段只要超级管理员能够配置」,闸门由 `requireAdmin` 改为 `PanelPermissionService.requireFieldConfig(panel)` | 403 |
| G6 | 退绑仅允许作用于动态字段(`col_name LIKE '备用%'`);**永不 DROP 物理列** | 400 |
| G7 | INSERT yj_field + yj_translation + MS_Description 同事务 | 原子 |

## 6. 类型口径(第一期)

| data_type | 存储 | 说明 |
|---|---|---|
| 文本 | nvarchar 备用列 | 默认 |
| 下拉框 | nvarchar(存词表值,中文数据键) | 词表由服务端转成引擎既有内联格式 `SELECT v FROM (VALUES (N'词1'),(N'词2')) AS t(v)` 存入 `dict_sql`(`PanelConfigService.dictOptions` 直接执行;单引号转义;生成串 ≤500 字符,超长→400 提示精简词表) |
| 日期 | nvarchar(ISO `yyyy-MM-dd`) | 文本字典序=时间序,排序/筛选正确 |
| 是否 | nvarchar(`是`/`否`) | 引擎既有类型(在用 70 个字段) |
| ~~小数/整数/数值/参照/附件/标准库~~ | — | **不支持**:nvarchar 承载的数值按文本排序(`9`>`10`)、不参与度量列合计;参照配置面大。绑定表单对数值诉求给出指引"需精确合计/排序/索引 → 走正式迁移加物理 decimal 列"(池耗尽同路) |

## 7. 退绑与无损边界

| 动作 | 效果 | 数据 |
|---|---|---|
| 绑定 | 插元数据行 | 不碰业务数据 |
| 退绑 | 删 `yj_field` 行,界面消失 | 备用列数据保留;重绑同名标签到同列即恢复 |
| 重新绑定占用列 | G4 告警+显式确认(+可选清空) | 见守卫 |
| DROP 物理列 | **机制上无此入口** | 数据损失唯一来源被封死 |

## 8. 接口契约(PxController,均经 G5 = 该面板「自定义字段」授权)

1. `GET /px/extFields?panel=<code>` →
   `{ capacity, fields:[{id,label,col,dataType,place}], headPool?, linePool }`
   (`headPool`/`linePool` = 对应表备用列 `[{col,bound|null,dirtyRows}]`,doc 面板两池、archive 仅 linePool;dirtyRows=该列非空行数,前端据此渲染占用与告警)
2. `POST /px/extField/add` body
   `{ panel, label, labelEn, dataType, dictOptions?, place, inQuery, width, required, confirmDirty?, clearFirst? }`
   → `ApiResult<{colName, fieldId}>`
3. `POST /px/extField/retire` body `{ panel, fieldId }` → `ApiResult<Void>`

实现在 `PanelConfigService`(yj_field 写入归属,与 saveColumnPrefs 同层)。

## 9. 审计表

```sql
CREATE TABLE yj_ext_bind_log (
  id         bigint IDENTITY PRIMARY KEY,
  panel_code varchar(40)  NOT NULL,
  label      nvarchar(60) NOT NULL,
  col_name   sysname      NOT NULL,
  action     nvarchar(10) NOT NULL,          -- bind / retire / clear
  op_by      nvarchar(50) NOT NULL,
  op_at      datetime2    NOT NULL DEFAULT GETDATE(),
  detail     nvarchar(500) NULL
);
```
(带 MS_Description 表/列注明;进链两账套执行。)

## 11. 边界(明确不覆盖)

- 文书面板(RecordSheetPanels 纸张复刻 22 面):纸面版式前端配置驱动,动态字段进不了纸面。
- 报表/flat 面板(37 个):字段从视图列自动发现,不适用。
- 参照/附件/标准库控件:二期再议。
- 运行时绑定不生成链上脚本(saveColumnPrefs 先例:运行时元数据);`yj_ext_bind_log` 保有全量审计,需要时可从日志重建。

## 12. 验收口径

1. 绑定后:列表列/表单格/查询条件/导出列出现新字段,可编辑、可保存、重开单据数据在。
2. 切 en:新字段列头显示英文(manual 译名)。
3. 退绑→界面消失→库中数据保留→重绑同名同列→数据恢复显示。
4. G1-G7 各有一项探针断言(非法字符/重名/池满/dirty 告警/无权 403/退绑非动态字段/事务原子);
   权限项口径(2026-10-09):无该面板「自定义字段」授权的角色 403,授权后放行,管理员恒过。
5. `DbNormAudit` 两账套 12 项全绿(备用列有注明、无漂移、无多标签)。⚠ **03/09 棘轮基线已收到 0**:
   新建备用列无 `MS_Description`、或绑定字段无 en 译名 = **直接 FAIL**(不再落在存量 WARN 区间);口径见 §3.1。
6. `DbSync sync` 两账套「执行 0、失败 0」;`数据库表清单.md` 刷新随任务提交。
7. 全程(除 G4 显式清空)不写任何业务表既有行。
