## 0. 一句话

**出厂检验报告 = 一张独立放行单据**：行清单来自《出货检验计划表》（只读视图，不改表），实测值从 首件 / 制程 / 成品 三张检验单按「并集 + 有值优先」取，取不到的留空手填；由**销售出库单勾选货物**触发生成，走正常单据审批，按 YJ-QR-05/A1 版式打印。

       ③重量检查(S-2/5) ④挤压强度(S-1/3) ⑤黑水检查(S-1/3)
       ⑥余氯测试(S-1/1) ⑦碱性寿命测试(S-1/1) ⑧包装检查(II级/50)

## 3. 现状事实（实测，HSDZ_MES）

### 3.1 三张检验单

| 面板 | 名称 | 表 | 前缀 | 单量 |
|---|---|---|---|---|
| `QC_FIRST_INSP` | 首件检验单 | `qc_first_insp_head/_detail` | SJ | 431 |
| `QC_PROC_INSP` | 制程检验单 | `qc_proc_insp_head/_detail` | ZC | 443 |
| `QC_ASM_INSP` | 组装成品检验单 | `qc_asm_insp_head/_detail` | ZJ | 438 |

- 三套**独立头行表，无外键**；跨单可用锚 = `工单号 + 工单行号`（`bs_route GY-CB-STD` 一条工单行串完 成型→切炭→组装）。
- 自动出单：`QcInspAutoService` 成型→[首件, 制程]、组装→[成品]，幂等键 `(工单号, 工单行号) × 面板`。
- **批次号不是批身份**：`plang.批次号` 是完工日生成的日期标签（395 行只有 30 个不同值，27 个值跨多个工单号）。

### 3.2 编码体系（已证实可打通）

**统一主键 = `bs_inv.存货编码`**（`C-95-12` / `B-92-25` 这种），四方同体系：

```
rd_insp_plan_head.产品编号 ┐
rd_prod_info_head.产品编号 ├→ bs_inv.存货编码 ← qc_{first,proc,asm}_insp_head.产品编码
plang.dm                  ┘
```

- 覆盖率：plan→bs_inv 4/4；plang.dm→bs_inv 476/476；qc 三表 262/266（98.5%）。
- `3-01-01-0159` 只是 `bs_inv.助记码`（全表仅 53/3899 行是该格式）⇒ **不能做主键**。
- `qc_asm_insp_head.产品编码` 有 TAB 前缀脏值 ⇒ 取数 SQL 必须清洗 `CHAR(9)/CHAR(10)/CHAR(13)/空格`。

### 3.3 标准层家底（关键约束）

| 事实 | 数字 |
|---|---|
| `rd_insp_plan_head` 9 张 | 仅 4 张有明细；`0009` 与 `0007` 逐字段相同；5 张空壳 |
| 覆盖产品 | **2 个**：`B-92-25`、`C-23-11` |
| 可用列 | 控制项目 / 控制标准及要求 / 控制方法 / 不合格应对措施 / 检测频率 / 序号 |
| 全 NULL 列 | 检验类别、取样方式、检测仪器、检验内容（55/55） |
| 全库 AQL | **无**任何 AQL / Ac-Re / 检验水平列 |

### 3.4 数据漂移

计划表 → 检验单 `检验要求` 逐字一致率 **30/3891 = 0.77%**，其余是"按产品标准""按规格型号，公差±0.5mm"等泛化文本 ⇒ **不能靠文本反推计划，必须靠对齐表**。

### 3.5 出库 → 工单：无路径

`bl_sale_out` 无 `工单号/工单行号/入库单号`；`批号` 1112 行 = `PC0000` 758 / 空 333 / 真实 21；按真实批号回连产成品入库 **0 命中**。

## 4. 总体设计

### 4.1 数据流

```
销售出库单（勾选明细行）
   │  ①点"生成出厂检验报告"
   ▼
OqcReportService.generateFromSaleOut(出库单号, 行号…)
   │  ②每行 → 一张报告草稿（一产品一张）
   │  ③定位检验单：真实批号 → qc_asm_insp_head.批次号
   │              否则 → 该产品最近一张已审核成品检验单（页面标黄提示）
   ▼
qc_oqc_head + qc_oqc_detail（快照）
   │  ④行清单 = 视图 v_oqc_std（按产品编号）∪ 手工加行
   │  ⑤实测值 = 对齐表匹配 三单 同(工单号,工单行号) 的数据，有值优先
   ▼
页面填写/核对 → 提交 → 审核（正常单据审批）→ 打印 YJ-QR-05/A1
```

### 4.2 单据模型

- 面板 `QC_OQC_REPORT` / 出厂检验报告 / `doc` 模式 / 前缀 **`OQC`**（号池未占用）/ 模块 **品质管理**
- 表：`qc_oqc_head` + `qc_oqc_detail`（命名沿 `qc_*_head/_detail` 家族）
- 与三张检验单**同构**：同一套 Panel 引擎、同一套审批、同一个报表机制

### 4.3 行清单来源：只读视图

不改 `rd_insp_plan_*` 任何一列，标准层用视图：

```sql
CREATE VIEW dbo.v_oqc_std AS
SELECT
    h.单据编号            AS 计划单号,
    h.产品编号,
    h.客户项目名称,
    h.版本号,
    TRY_CONVERT(int, d.序号) AS 序号,
    d.控制项目             AS 检验项目,
    d.控制标准及要求        AS 检验要求,
    d.控制方法             AS 检验方法,
    d.检测频率             AS 检查频率,
    d.不合格应对措施,
    CASE WHEN d.检测频率 = N'型式检验' THEN N'型式检验' ELSE N'出厂检验' END AS 检验类别
FROM dbo.rd_insp_plan_head h
JOIN dbo.rd_insp_plan_detail d ON d.单据编号 = h.单据编号
WHERE h.产品编号 IS NOT NULL;
```

- 「出厂检验」行 → 数据取自三单；「型式检验」行 → 数据手工/留空（对应卫生安全/寿命类）。
- 视图**只读**，不改表、不补列；计划表以后怎么改都自动跟随。

### 4.4 项目对齐表（新建，唯一新增的映射）

`qc_oqc_item_map`：把"报告上的项目"映射到"三张单里实际用的项目名"——因为三套词表不同名（`外观检查` vs `炭棒表观状态` / `外观` / `外观`），且**只能按名字匹配**（三张明细表都没有 `项目编码` 列）。

初版 seed（按实测词表）：

| 报告项目 | 源面板 | 源表区/检验类型 | 源项目名 | 优先级 | 取值方式 |
|---|---|---|---|---|---|
| 外观检查 | QC_ASM_INSP | 外观 | 外观 | 1 | 文本 |
| 外观检查 | QC_PROC_INSP | 外观 | 外观 | 2 | 文本 |
| 外观检查 | QC_FIRST_INSP | 首件检验 | 炭棒表观状态 | 3 | 勾选 |
| 外观检查 | QC_FIRST_INSP | 首件检验 | 炭棒脱粉情况 | 3 | 勾选 |
| 尺寸规格检查 | QC_ASM_INSP | 尺寸 | 尺寸 | 1 | 数值×5 |
| 尺寸规格检查 | QC_PROC_INSP | 尺寸 | 尺寸-外径 / 尺寸-长度 | 2 | 数值×5 |
| 尺寸规格检查 | QC_FIRST_INSP | 首件检验 | 炭棒外径 / 炭棒内径 / 炭棒长度 | 3 | 数值×2 |
| 重量检查 | QC_ASM_INSP | 重量 | 重量 | 1 | 数值 |

| 挤压强度检查 | QC_ASM_INSP | 性能 | 抗压强度 | 2 | 文本 |
| 黑水检查 | QC_ASM_INSP | 性能 | 黑水测试（无需无黑） | 1 | 文本 |

| 碱性寿命测试 | —（无源） | — | — | — | 手填 |
| 包装检查 | —（无源） | — | — | — | 手填 |

**取数规则：按优先级顺序找，第一个"有值"的胜出**（不是"第一个存在的单"——例如成品单只有 120/438 张带外观行）。

### 4.5 首件的勾选处理

首件记录表按项目组分样品行：表观及脱粉→`1#/2#`、尺寸及重量→`3#/4#`、强度→`5#/6#`、浊度及压降→`7#/8#`；**其余格子画斜杠，不填**。

报告侧：
- `外观检查` 行的**结果**列显示勾选文本，如 `无粘模（均匀） / 无明显脱粉`；
- **不带任何数值**（尺寸/重量/强度按 4.4 的对齐表从制程/成品取，取不到就空）；
- 备注/来源列附首件单号（`来源：SJ-…`），便于追溯。

### 4.6 手填项与留白

| 列 | 来源 |
|---|---|
| 抽样标准 / 抽检量 / AQL | **手填**（系统无 AQL 数据，也不自动查表）|
| 检验要求 | 视图 `控制标准及要求`；视图无此行则手填 |
| 卫生安全 15 项 | 不做数据；版面印"卫生安全项目见型式检验报告" |
| 检验结论 | 明细判定汇总（全合格→合格），可改 |
| 备注 | 手填（默认带"测试环境：温度 __℃ 湿度 __%"）|

## 6. 取数与生单规则

### 6.1 定位检验单（三段式，兼容批次追溯上线）

```
1) 出库行.批号 有效（非空、非 'PC0000'、能在 qc_asm_insp_head.批次号 里查到）
   → 按批次号匹配；
2) 否则 → 该产品最近一张"已审核"的 QC_ASM_INSP（按审核时间倒序）
   → 页面标黄：「出库未填批次，已按最近一批带入，请核对」；
3) 都无 → 页面提示手选。
```

批次追溯上线（`docs/development/上线前必验-库存批次追溯.md` 要求"所有出库必填批次号"）后，规则 1 自动成为主路径，**代码不用改**。

### 6.2 从成品单回到首件/制程

```
qc_asm_insp_head (工单号, 工单行号)
   → qc_first_insp_head / qc_proc_insp_head 同 (工单号, 工单行号)
```

实测精确配对 425/427。

### 6.3 取值

按 `qc_oqc_item_map` 逐行尝试：
- 数值项：`测量值1..5`（首件/成品）→ 拼成 `44.5/44.6/44.5/44.7/44.6`；不足 5 个有几格填几格；
- 定性项：`检验结果`（asm）/`实测数值`（first/proc）/`产线常规功能性结果`；
- 判定：取该行 `结果判断`；
- 命中即停（**有值优先**），并在 `数据来源` 记录 `面板:单号`。

### 15.2 实现偏差（与本文档前文的差异，以本节为准）

| # | 偏差 | 原因 |
|---|---|---|
| D-1 | **视图按「受控优先 + 版本最新」只取一张计划单** | 实测 `B-92-25` 有 3 张计划（`0007`/`0009`/`0011`，其中 `0009` 与 `0007` 逐字段相同）⇒ 直接 join 会返回 45 行而不是 15 行。规则：`备用1='是'`(受控) 优先 → 单据日期 → 版本号 → 单据编号 |
| D-2 | **报告行 = 计划表的 `控制项目`**，不是 c-95-12 的 8 个受控表单项目 | 计划表项目（`*外观` / `*炭棒尺寸` / …）是客户控制条款；8 项（外观检查/尺寸规格检查/…）是 YJ-QR-05/A1 的用语。两套之间的「计划项目 ↔ 报告项目」映射需要业务确认，v1 先按关键词在代码里转（`KEYWORD_TO_ITEM`），确认后改查表 |
| D-3 | `qc_oqc_head.单据状态` **留空** | 与三张检验单一致（实测 438 张成品检单该列全为 NULL），单据状态由 `yj_doc_status` 提供 |
| D-4 | 验收清单第 3 条的期望值修正 | `B-92-25` 15 行 / `C-23-11` 10 行 ✔（视图按 D-1 取单张计划后成立） |
| D-5 | 定位检验单加第三档：**已审 → 最近一张（不论是否已审）→ 无** | 实测 `B-92-25` 唯一那张 `ZJ-2026-10-0135` **没审核**（`yj_doc_status.shr` 为空）⇒ 只认已审核会一行数据都取不到。退档取到的数据在报告行 `数据来源` 里标出单号，品质在报告上核对，不静默冒充已审数据 |
