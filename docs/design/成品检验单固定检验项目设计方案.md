## 0. 需求拆解:什么叫做"固定"

| 维度 | 问题 | 判定 |
|---|---|---|
| **看得见** | 打开单子,三组(外观/尺寸/出货重量)是否永远在? | 要 |
| **填得进** | 每个固定格能否直接录值? | 要 |
| **读得到** | 填完的值报表/取数能不能拿到? | 要 |
| **不添乱** | 没填的固定项会不会在库里留空行/脏数据? | 要(2026-10-15 口径) |
| **可维护** | 以后加/改固定项要不要改代码? | 不要改代码(改配置) |

**引擎硬约束(不可绕过)**
1. 明细只能以**行**存在:`qc_asm_insp_detail` 一行 = `表区(组) + 检验项目 + 检验结果/测量值1..5/结果判断`;
   报表(`QcAsmInspReportSupport`)与任何取数都按「同组 + 归一化项目名」匹配这些行。
2. **2026-10-15 用户口径:检验单自动生成时不预铺明细行**(`ButtonService.java:2881` 已按此删掉预铺逻辑)——
   指"报工审核建单那一刻不要塞数据";本条与"单子建好后品质录入时默认有固定项"**不是同一件事**,
   但它意味着**自动补行的时机与口径要重新取得你的同意**(见 §2 方案 A/B 的分歧点)。
3. 面板是元数据驱动:明细区由 `yj_field` 列定义渲染成表格;要别的形态(分组成横表)只能用**自定义纸张表组件接管**
   (`isApprovalDoc` 白名单,2026-10-16 试过一版,你回退了)。

## 1. 候选方案

### 方案 A:草稿打开时自动补固定项行(通用明细表,不动形态)
- 配置:`yj_panel.config` 的 `fixedItems`(**已落地**):外观[端盖两头/管身两侧]、尺寸、出货重量 + 组列名。
- 行为:**仅当**单是草稿、且该组还没有行时,由后端 `GET /px/loadDocData`(或保存前)补 3~4 行
  (`表区=组名、检验项目=固定项名`),界面照旧是**现在的通用明细表**,不点任何按钮、默认就有这几行能填。
- 读:天然(落的就是真行)。
- 代价:库里会留下固定项行(哪怕值是空的 ⇒ 需要 §2 的"空行过滤"配套);改动集中在 **1 个后端服务 + 配置**。

### 方案 B:纸张表组件接管(照截图:组分横跨 + 列内格子)
- 2026-10-16 做过一版(`QcAsmInspSheet.vue`),被你以"当前形式不对"回退。
- 优点:**版式就是截图**(组名跨列、外观 3 列、尺寸/出货重量整组一列多格、打开就铺出)。
- 缺点:面板从"表头表单+明细页签"变成"文书纸张",抬头字段也要组件自己渲染;交互(筛选/定位/列宽/汇总页签)全部要重做;与**方案 A 不冲突**(A 管数据、B 管形态)。
- 适用:你要的就是"纸面长这样"。

### 方案 C:固定项进「检验项目/检验方案」标准库(复用既有入口)
- 把 端盖两头/管身两侧(+可选 尺寸/出货重量 组列)建成一条**固定检验方案**,产品上挂它。
- 品质用**现成的两个入口**(「检验项目/检验方案」弹窗勾选 / 「取出货检验计划」)带入 —— 不新增按钮、不改引擎。
- 代价:仍需点一次勾选(不是"默认就在");好处是完全复用既有链路、可维护可停用。

### 方案 D:引擎层"空行占位"(通用明细表 + 配置默认行)
- 给面板配 `defaultItems`,前端在**明细表底部**渲染这几行"待填行"(项目名预置、只读;其余格可填),
  保存时**全空行不入库**。
- 优点:不写脏数据、不用按钮、形态仍是通用表(改动可复用给别的检验单)。
- 代价:要动保存口径(过滤空行),属引擎级改动,影响面需评估。

## 6. 最终实现(2026-10-16,已落地并验证)

### 6.1 选定的路:复用引擎「按表区分区渲染」,不新写纸张表组件

用户口径 ④「按三区实现,没有数据的时候显示和当前截图形式相当即可」+ ②「不要按钮、用组件形式」⇒
实现落在**通用明细区的分区渲染分支**(`PanelxList.vue`),而不是再写一个专用纸张表:

| # | 改动 | 位置 | 要点 |
|---|---|---|---|
| 1 | 分区渲染分支(取回 `fde804ba` 的辅助函数并扩展) | `PanelxList.vue` `isSectioned/archSections/sectionCols/sectorLetter/sectionRowNo/removeSectionRow/addSectionRow` | 每区 = 区标题(A.外观…) + **该区自己的列头** + 该区的行 |
| 2 | 触发条件收敛 | `SECTION_PANELS`(检验单族)+「明细含 表区 字段」 | ⚠ 判据必须用**该页签全部明细字段(含隐藏)**:`表区` 在本单是 `hidden=1/visible=0`,用 `activeTab(b).cols` 判会永远为假 |
| 3 | **固定组永远铺** | `archSections` + `metadata.fixedItems` | 声明过的组哪怕一行数据都没有也出一块(空区给占位行),照"没有数据也显示成截图形式" |
| 4 | **固定项=预置行** | 同上 | 端盖两头/管身两侧**永远可见**:已有真行用真行,没有就铺预置占位行(项目名已填),末尾再给一行空占位行 |
| 5 | 列集稳定 | `sectionCols` | 固定组列 = 检验项目/检验要求/检验方法 + 定性(检验结果/产线常规功能性结果)或定量(测量值1..5)+ 检查频率/不合格数量/处理方式/结果判断;再把本区实际有值的列补上 ⇒ 空区不会"两列"、有数据也不会忽然变十几列 |
| 6 | 0 值不冒出测量值列 | `sectionCols` | `测量值N` 的 0 当"没填"(引擎新建行数值列默认 0)⇒ 外观区不会出现一排全 0 的测量值列(与截图一致) |

### 6.2 数据模型(回答"明细表是不是被顶替了")

**没有被顶替**:库里仍是 `qc_asm_insp_detail` **一行 = 一个检验项目**
(`表区` + `检验项目` + `检验结果` + `测量值1..5` + `结果判断`),分区只是**呈现**。
当年"交叉表"那版(一项一列)也只是把**行画成列**,格值存在同一行的 `测量值N` 里
(证据:现 `QcProcInspSheet.vue` 注释「上一版"一项一列 + 格数"留下的结构化格,纸面已不再渲染(值照存)」),
所以从交叉表改回纵向表时一行数据都没丢。报表/取数/追溯与呈现形状无关。
