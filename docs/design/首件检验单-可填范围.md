# 首件检验单 · 可填范围（2026-10-17 第九轮 · 现行口径）

用户口径（两句话定案）：

> 「让当前各个表格都能填写即可，**前两列保持原样**即可」
> 追问后补充：「**以及后面新增的列也一样**」

## 一、现行规则（唯一真源）

| 列 | 可填样品行 | 输入方式 | 颜色 |
|---|---|---|---|
| **前两列**：炭棒表观状态 / 炭棒脱粉情况 | **只 1#、2#**（保持原样） | 勾选式（无粘模/轻微粘模/严重粘模…） | 1#/2# 淡黄 `#FFF3CA` |
| **其余所有列**：图纸上的 8 列 **+ 表头「＋」新增的列** | **1#..8# 八行全可填** | 文本录入 | 白底 |

- 10 列时：可填格 **68** 个，`/` 占位格只剩 **12** 个（＝前两列 × 3#..8#）。
- 「前两列」按**列名**认（`表观状态`/`表观`/`粘模`/`脱粉`，key 兜底），改名后照样认得出；
  所以"新增一列再改名成炭棒表观状态"也会自动回到"只填 1#/2#"的勾选式行为。

**真源**：`frontend/src/core/qc/firstInspCols.js`

```js
export function isCheckColumn(col)        // 这一列是不是勾选式那两列(按列名认)
export const CHECK_SAMPLE_ROWS = [1, 2]   // 勾选式列的样品范围
export function isFillableCell(sample, col)  // 前两列 → 只 1#/2#;其余列 → 八行全开
```

组件渲染、勾选式判定、底色标记、**Excel 导出**共用这一个判据 —— 别再各写一份样品范围。

## 二、沿革（同一天改了两回，别再照旧版改）

| 版本 | 规则 | 为什么被推翻 |
|---|---|---|
| 第六轮之前 | `SAMPLE_LIMIT = 2`：**每个测试项目都只记 1#/2#** | 尺寸/强度/浊度三组在任何行上都不可录 ⇒ 8 个测试项目**永远填不进去** |
| 第六轮 | 按图纸把四个分组各绑一对样品行（表观→1#/2#、尺寸→3#/4#、强度→5#/6#、浊度→7#/8#），其余格打 `/` | 用户改口：「让当前各个表格都能填写即可，前两列保持原样即可」 |
| **第九轮（现行）** | **只前两列限 1#/2#，其余列（含新增列）八行全开** | — |

随之调整的两处显示层：

- **底色只剩前两列 1#/2#**：原来那四段色带是标"这个分组的可填区"，
  其余列八行全可填之后色带就成了没有含义的装饰，故移除（`.gz-p` 那条 CSS 一并删掉）；
- 不可填格的悬停提示仍在（现在只剩前两列 3#..8# 会用到）：「按相关要求：本组测试只记录 2 支样品（1#、2#）」。

⚠ 相关要求第 1 条纸面原文（"每个分组各记录 2 支样品"）**不随本改动一起改**：它还是印在纸上的原文，
本次是用户对**系统录入范围**的显式口径覆盖。
