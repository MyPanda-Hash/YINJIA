## 1. 业务口径(硬约束)

1. **不新造批次体系**。大批次号 = **生产批次号**(`plang.[批次号]` / `plang_pc.[批次号]` / `scjl.[批次号]`,均为日期形态 `yyyyMMdd`;
   注意 `plang.lot_no` 全库为 NULL,不是批次来源)。**真实批次号在该工单行首次「生产完工」时才生成**
   (`ProcessTaskService.assignProductionBatch`:批次号=完工当天日期)⇒ 录入阶段多数行还没有号:
   卡头先按**工单日期**推定(`批次来源='工单日期'`),等真实批次号出现后由服务端读取时**自动同步**
   (`批次来源='生产批次'`)。卡号/小批次号**不含批次号**,同步不影响卡的身份。
2. **一张卡 = 一个工单行(小批次)**:业务唯一键 = `工单行id`;小批次号 = `<工单号>-<工单行号>`;卡号 `LZK-<小批次号>`(全系统唯一)。
3. **工序行来自现役工序台账** `wo_process_line`(按工艺路线生成,路线口径与《订单结转》一致:工单行 `plang.[工艺路线]` → `bs_inv.[工艺路线]` → `GY-CB-STD`)。卡不重算路线、不写台账;台账缺行时调既有 `ProcessTaskService.ensureLedgerForWorkOrder` 补齐后读取。
4. **完成情况只读现算**,不落冗余完成量(防"两账不合一"):
   - 已报工 = `scjl` 中 `wgzt='Y'` 的数量;待审核 = `wgzt<>'Y'` 的数量;统计口径**完全同** `WorkReportController.row`(行锚 `scjl.gd_id→plang_pc.plang_id`,草稿期 `gd_id=0` 时按 `批次号` 兜底);
   - 工序状态 = 已报工 ≥ 计划数量 → `已完工`;> 0 → `进行中`;否则 `未开始`;
   - 完成时间 = 该工序已审核报工的 `MAX(wgsj)`;操作人 = 最近一笔报工的 `ywman`。
5. **卡状态**:`录入中`(默认)→ `已完成`(人工「确认完成」;前置条件=全部工序已完工且每道工序至少 1 张照片,服务端强校验)。**不引入审核/作废流**,写错可回退 `录入中`(仅确认人/管理员)。
6. **照片口径**:照片挂 `yj_attachment`(`panel_code='PROC_FLOW_CARD'`,`doc_no=卡号`,`field_key='工序照片-<工序序>'`),复用既有上传/删除/下载接口与磁盘存储;**图片只允许 `image/*`**,单张 ≤20MB(全局 multipart 上限),每道工序建议 ≤20 张(前后端软提示)。
7. **权限**:`PROC_FLOW_CARD` 为页面级虚拟面板(不落 `yj_panel`),登记进 `PagePanelRegistry`;动作词 `view/query/entry/confirm`;授权行落 `yj_role_panel`(各角色默认授予,见迁移脚本)。
8. **多语言**:面板名/动作词走 `yj_translation`(en/ja/ko/vi);页面 UI 文案一律 `tt('中文原文')` 并补 `frontend/src/i18n/locales/en.js` 的 biz 段;数据键(批次号/卡号/照片文件名)**永不翻译**(ADR-0001)。

### 2.3 照片

复用 `yj_attachment`(不新建表):`panel_code='PROC_FLOW_CARD'`,`doc_no=卡号`,`field_key='工序照片-<工序序>'`,同时兼容卡级照片 `field_key='卡照片'`。

```json
→ { "工序": ["成型","切炭","组装"], "卡状态": ["录入中","已完成"] }
```

### 3.2 `POST /api/procCard/batches` — 大批次列表
请求:`{ "关键字": "", "日期从": "", "日期到": "" }`(均可空)
> 按**工单行的解析批次号**聚合(不是按已建卡):`plang.[批次号]` → `plang_pc.[批次号]` → `scjl.[批次号]` → 工单日期推定。
> ⚠ 实现取舍(2026-10-29):**不过滤「8 位纯数字」** —— 既有生产批次存在 `20260928-4` 这类带后缀值,且推定值本就是日期,
> 硬过滤会漏行;改为「非空即列」。
```json
→ [ { "批次号":"20261019", "批次来源":"生产批次", "行数":12, "卡数":3, "产品数":5, "计划数量":21600 } ]
```

## 5. 前端页面(单文件 `ProcFlowCard.vue`,≤1200 行;窄屏单列、≥900px 双栏)

**页签① 录入**
- 批次条:大批次下拉(来自 `/batches`,显示 批次号(行数));关键字过滤。
- 小批次表:`/lines` 列表(工单号/行号/产品/规格/计划数量/当前工序/卡号/照片数),点行选中。
- 右侧(窄屏在下方)卡编辑区:头信息 + 工序卡片流(每道工序:计划/已报工/状态/完成时间 + 照片缩略图墙 +「上传照片」`<input type=file accept="image/*" capture="environment" multiple>`)+ 卡备注 +「创建流程卡」/「确认完成」。
- 上传后刷新 `/detail`;照片点击走 `openAttachmentPreview`(core 通用预览)。

**页签② 卡片列表**:产品编码/产品名称/规格型号/工单号/批次号/卡状态/日期范围 → 分页表格(列见 §3.7),行点击打开详情抽屉(复用页签①的卡编辑区组件化展示,只读)。

**页签③ 批次追溯**:批次号输入/下拉 → 汇总卡(卡数/产品数/计划量/各工序完成量)+ 卡片表;选中卡片 → 追溯抽屉:工序进度时间线 + 报工记录 + 照片墙 + 「工单追溯」按钮(展开 `ScheduleBoardService.trace` 的只读结果,不重复实现)。

**通用要求**:所有显示文案 `tt()`;`request` 走 `@/core/request`;加载态/空态/错误态齐备;手机端按钮 ≥40px、照片上传支持拍照。

## 7. 回滚

① 菜单项/路由注释掉 → 入口消失;② 后端新类删除即可(无既有代码依赖);③ 迁移脚本附回滚段(删两表 + 删授权行 + 删译名),执行后 `DbSync` 仍可通过;④ `yj_attachment` 中 `panel_code='PROC_FLOW_CARD'` 的照片行随卡删除(磁盘文件可留)。
