# 生产工单成型配方与混料关联

## 目标与术语

- **生产工单行**：`plang.id` 标识的一行；同工单号可有不同工单行，因此所有配方/混料关联必须携带 `工单号 + 行id`，展示工单行号 `pl_xc`。
- **成型配方**：研发面板 `RD_MOLD_PROC` 的 `表区=配方表` 行；仅已审核/已归档的清单可被生产使用。
- **获取混料配方**：生产工单页对一条工单行选定本次混料数量，从可用研发配方生成一份不可被研发后续改版影响的生产快照。
- **配料比**：只取配方计算保存的「实际添加比例」并归一为小数；不使用「设计添加量」兜底，因为折算料的设计添加量可能表示克/支。

## 方案

1. `plang` 增加成型配方单号/版本/关联人/时间四个可空追溯字段，工单主键、外部写入路径和旧数据保持不变。
2. 新建生产执行域快照头/行 `wo_mixing_head`、`wo_mixing_detail`。头表关联工单行和配方版本，记录数量/单位；行表保存物料、实际比例、单支含量、计划用量及实际用量。
3. 工单列表按单行入口读取匹配产品的最新已审核/已归档 `RD_MOLD_PROC` 配方，服务端校验工单仍存在、配方已发布、明细有效。
4. 现场输入混料数量（支）。计划投料量 = 混料数量 × 配方「单支物料含量」(g/支)；配料比保存为小数，例如实际比例 `7%` 存 `0.07`。实际用量留空给现场后续填报。
5. 确认获取时事务性地软作废同工单行的当前快照、更新 `plang` 配方指针并落新快照。保留历史快照，研发配方后续改版不追溯覆盖生产记录。
6. 端点权限依托 `WORK_ORDER_LIST` 的专属 `recipe` 动作；读接口要求工单页查看权，写接口同时要求「获取混料配方」动作权。

## 边界与校验

- 精确用 `plang.id + pl_no` 查工单行，拒绝缺行ID、已作废行、空产品编号、混料数量非正数。
- 不读 `RD_MOLD_FORMULA` 旧菜单面板或下架 BOM；只读成型工艺清单现行配方表。
- 草稿/审批中/作废研发配方不可作为生产配方；物料行空白不落快照。
- 配料比解析允许小数与百分数文本，但不能从设计添加量推断生产比例。
- SQL 迁移必须幂等、为新表/关键列加中文 `MS_Description`，登记在 `db-inuse-tables.txt`、`db-migrations.txt`；正式库与测试库都需执行并验证。

## 后续可扩展

`wo_mixing_head.混料报工单号` 为混料报工绑定预留锚点；`实际用量` 可在后续混料称重/报工录入时回写。当前功能负责工单获取配方和形成可追溯的数量/比例快照，不自动创建混料报工单，也不把一条配方快照扩展为多批次台账。
