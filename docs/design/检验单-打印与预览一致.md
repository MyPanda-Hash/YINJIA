# 检验单打印/打印预览与单据不一致（2026-10-21）

用户口径：

> 「处理一下当前的报表渲染问题，**打印处的格式应该和当前单据对应**，修改当前打印预览的渲染方式，
> 第一张图为打印预览的格式，第二张为原来的系统内实现的报表。」

第一张图 = 打印预览当前出来的样子（服务端 `.jrxml` 版本）；第二张 = 系统内那张纸（QcProcInspSheet）。
用户要的是**前者对齐后者**。

## 一、病根（两个独立问题）

### ① 制程检验单「打印」出的是**空白页**

全系统的打印开关是 `body.approval-printing` + `@media print`，公共样式（`DocSheet.vue` 的非 scoped 块）先

```css
body.approval-printing .portal { visibility: hidden; }
```

再把**允许打印的纸张根类名**逐个 whitelist 成 `visibility: visible`
（`.approval-sheet` / `.progress-sheet` / `.catalog-sheet` / `.qc-rec-sheet` / `.rsp-sheet`，
首件检验单后来自己补了 `.fi-sheet`）—— **唯独漏了制程检验单的 `.qr-sheet`**。

实测（CDP + `Page.printToPDF`）：

| 面板 | 纸张根 | print 媒体下 visibility | 出纸 |
|---|---|---|---|
| 制程检验单 | `.qr-sheet` | **hidden** | **1.9 KB / 3 页空白** |
| 首件检验单 | `.fi-sheet` | visible | 379 KB / 2 页正常 |

### ② 「打印预览 / 导出 PDF」走的是另一份版式（`.jrxml`）

「导出报表 → 打印预览 / 导出 PDF」走服务端 JasperReports 模板 `reports/qc_proc_insp.jrxml`。
那份模板是 2026-10-17 手工重画的**第二份**版式，与面板纸张表（`QcProcInspSheet.vue`）各改各的：
纸张后来加了「检验结果」分区带、结论区加了「检验人 / 审核人」行，模板没跟上
⇒ 同一张单**纸上是一个样、屏上是另一个样**（正是用户截图对比的那两版）。

## 二、改法

### 2.1 补上打印白名单 + 按纸重排列宽（`QcProcInspSheet.vue`）

新增一段非 scoped 的 `@media print`（与首件检验单同一套写法）：

- `body.approval-printing .qr-sheet { visibility: visible; position: absolute; top/left: 0; width: 100% }`
- `.qr-sheet *` 统一 `print-color-adjust: exact`（蓝底、勾选框要印出来）
- 隐藏 `.approval-side` / `.doc-select-rail` / `.no-print` / 操作列 `.c-op`
- 字号压到 9px、内边距 1px，`@page { size: A4 portrait; margin: 8mm }`

🔴 **顺带修掉「检验要求/检验方法 被压成竖排文字」**：
`.qr-grid` 是 `table-layout: fixed`，`<colgroup>` 把前四列定死 `118/118/104/104`（=444px），
后两列（检验要求 / 检验方法）是**弹性列**。A4 纵向内容宽 ≈ 733px，再减右两列 150+96+操作列 34
⇒ 弹性列各只剩 **0px**，于是每个汉字单独占一行（实测 `cols = 118,118,104,104,0,0,150,96,34`）。
修法：打印时按纸宽重排 —— 客户名称 11% | 产品编码 11% | 型号 9% | 批号 9% |
**检验要求 26% | 检验方法 24%** | 产线结果 7% | 结果判断 7%
（`col { width: auto }` + `th/td:nth-child(n) { width: …% }`，colgroup 的 width 优先级更低）。

### 2.2 检验单的「打印预览 / 导出 PDF」改用纸张（`PanelxList.vue`）

```js
const SHEET_PREVIEW_PANELS = ['QC_PROC_INSP', 'QC_FIRST_INSP']
const sheetPreviewUsesPaper = computed(() => SHEET_PREVIEW_PANELS.includes(String(panelCode.value)))
```

- `previewServerReport()`：这两张单改为 `buildSheetPdfBlob()`（**和「打印」同一份渲染源**：
  把当前纸张元素截成 PDF），其余面板照旧走 `fetchReportBlob('pdf')`。
- `downloadReport('pdf')`：同样走纸张；`xlsx` 不动（那是"报表数据行 + 页眉信息"，与纸张版式不是一件事）。
- 弹窗文案随 `sheetPreviewUsesPaper` 换话术：
  「按当前单据的纸张版式生成（与「打印」同一份渲染，所见即所得）」。

> 为什么不是去改 `.jrxml`：那等于**长期维护两份版式**，而它们已经漂移过一次（这次报障就是）。
> 让打印/预览/导出都读**同一个纸张组件**，从根上不会再有"纸上一个样、屏上另一个样"。

## 四、回滚点

1. `QcProcInspSheet.vue` 末尾那段 `@media print` 删掉 ⇒ 打印又回到空白页。
2. `PanelxList.vue` 的 `SHEET_PREVIEW_PANELS` 清空 ⇒ 打印预览/导出 PDF 回到 `.jrxml`。
3. 列宽那几条 `nth-child` 删掉 ⇒ 检验要求/检验方法 又会被压成竖排。
