# 参考库工单表 `plang`(55 列)——修改底稿

> **用途**:本文档按列级给出参考库(旧 HSDZ 系统,同源 `HSDZ_MES` 实测)的工单表 `plang` 完整结构,
> 供据此修改新系统(YINJIA-MES)的工单/生产加工单实现时对照使用。
> **取证**:`tools/archive/_ref-dump/01-table-structure.txt`(2026-09-22 实测导出);
> 面板口径:工单 = `plang`、排产 = `plang_pc`、报工 = `scjl`(2026-09-22 与需求方确认)。

## 1. 表概览

| 项 | 值 |
|---|---|
| 表名 | `plang`(中文注明:工单) |
| 主键 | `PK_plang_1` = **(comm, id)** 复合主键;`id` 为 IDENTITY 自增;**无二级索引**(参考库风格,查询靠全表扫) |
| 列数 | 55(与孪生表 plang_pc 完全同构,仅 3 列差异,见 §3) |
| 行数 | **0 行**(实际投产走 plang_pc;「生产工单」屏经 View_SCGD 读本表) |
| 工单号格式 | `GD + yyMMdd + 4位流水`(如 GD2608260013,由应用层生成) |
| 消费方 | `View_SCGD`(生产工单屏:`WHERE lb IS NULL`,联 dm_wz/dm_ywy 补名称,按 pl_no 倒序);`View_od_cost3`(订单成本:`scjl.gldh = plang.pl_no` 关联,Σ 工时×工序单价) |
| 删除/结案约定 | 软删 `asp_cancel='Y'`;结案 `ja ∈ ('T','Y')`,结案后退出需求统计(View_pcqty/OD_WLQTY 均排除) |

## 3. 与孪生表 plang_pc(排产主表)的 3 处差异

| 差异点 | plang(工单) | plang_pc(工单排产) |
|---|---|---|
| 已排产数量 | **有 `ypl_sl`**(防超排) | 无 |
| 订单交期 | 无 | **有 `jh_date`**(排产屏交期基准) |
| ll_no 语义 | 领料单号 | **客户PO**(领料单号挪到 ll_no2) |
| od_xc 语义 | 订单项次 | 订单表身ID(order_bs.id) |
| 行数 | 0 | 25(全部结案) |

其余 50 列名称、类型、默认值、注释完全一致;两表主键同为 (comm,id)。

## 5. 修改时的注意点(据盘点结论)

1. **执行回填链是参考库的灵魂**:`rk_no/rk_no→rk_sl→yl→ll_no2→wb_no→ja` 由 完工入库/领料/委外/结案 动作回写;
   新系统 bd_manu_order 已建同语义列但 Java 回写未实现(盘点文档 §4.5 最大缺口)——若按参考库修改,优先补这层。
2. **语义漂移列**:`lb`(注明「类别」实存班次)、`BomId`(注明「完工标记」非布尔)、`plang_pc.ll_no`(注明领料单号实为客户PO)——
   照搬列名前先核对真实语义,不要按注释望文生义。
3. **单号/锚点格式**:工单 GD+yyMMdd+4流水(应用层生成,不入 s_allno);MoDId/BomId 是外部系统锚点,迁移时决定保留或丢弃。
4. **颜色/尺码占位**:color/siz 实测多为 'N',批号 lot_no 才是有效批次键(与 kucun/inh/outh 的批号三元组联动)。
5. **无外键、无二级索引**:关联全靠 应用层 join(pl_no/od_no/od_xc 文本级);若在新系统中加强,需自行补索引与约束。
6. **审计/软删约定**:asp_user1..4+asp_cancel+asp_print 为全库统一尾列;新系统已沿用(见 bd_manu_order)。
