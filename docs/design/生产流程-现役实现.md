> 达标后由 `applyNextProcess` 把**该工单行**切到下一道预排线；末道达标即完工，成品入库不在报工里，
> 而在**组装成品检验单审核**时生成。

### 2.1 工序 → 产线车间口径：**装箱归组装**（2026-10-21 用户口径）

> 用户原话：「当前生产的工单对当前的生产排产只有对应的工序名称才能进入到对应的生产线，
> 当前组装和装箱工序都是同样进入组装生产线才对。」

**唯一口径 = `ProcessShop`（`backend/.../service/ProcessShop.java`，纯函数）**：

| 工序 | 产线车间（`bs_prod_line.生产车间`） | 可进哪些线 |
|---|---|---|
| 成型 | 成型 | 成型车间下的线（1~7 号机/车间、成型 1~5 线、自动线…） |
| 切炭 | 切炭 | 切炭车间下的线 |
| 组装 | 组装 | 组装车间下的线（组装 1/2、组装线…） |
| **装箱** | **组装** | **同一批组装车间下的线**（组装线 + 装箱 1/2、装箱线）——**不为装箱单另开一个车间** |
| 其它（下料/车削/检验…） | 路线登记的车间 | 不猜；路线也没填 ⇒ 不判（不瞎拦） |

- **判据只有一个**：产线的 `生产车间` 必须等于工序的归口车间（`ProcessShop.matches`）；判不出时放行。
  ⚠ **2026-10-28 起改走 `ProcessTaskService.requiredShop`**：只对「认得的工序 + 该车间确有启用线」拦，
  其它工序（含以后新建的）一律放开、弹窗列全部产线 —— 见 §2.2。
  用在：①派工 `ProcessTaskService.assign`；②预排线弹窗 `routeSteps` 的候选线；
  ③排线保存 `preplanManual`；④下一道工序候选线 `nextProcess`；⑤工序任务生成时落 `wo_progress.生产车间`；
  ⑥**自动转序** `applyNextProcess` —— 计划线的车间配不上这道工序时**不切**，只提示重新排线。
- **起因（两个坑互相加剧）**：工艺路线面板的「生产车间」下拉此前写死成
  `熔铸车间/轧制车间/精整车间/测试车间`（钢铁类遗留值），炭棒的 `成型/切炭/组装` 选不出来 ⇒
  路线车间只能留空（实测 `GY-2026-10-0001` 成型→装箱 两条明细全空）；空值 ⇒ 排线没有车间判据 ⇒
  排线弹窗把全部产线都摆出来，**装箱被排到了成型线**（实测 `GD-2026-10-0202` 行6：装箱 → 2号车间）。
- **数据修复**：`tools/migrate-route-workshop-options-20261021.sql` ——
  ①「生产车间」下拉 = 产线档案真实车间 ∪ 路线历史值（遗留路线照旧可维护）；
  ②补齐路线里空着且工序可判归属的车间（装箱→组装）。两账套均已执行。
- **存量脏数据**：`GD-2026-10-0202` 行6 的预排台账仍是「装箱:2号车间」，自动转序会**拦住并提示**
  「计划线属于成型车间，与工序应进的组装车间不一致，请撤销该行排产后重新排线」——
  人工重排一次即回到正确线（不自动改业务台账）。

### 2.2 工序→车间：**只拦"认得的工序"，其余一律放开**（2026-10-28 用户口径）

> 用户原话：「这个工序不是成型→切炭→组装这个工序的话，即使我为现在的工序进行了排产线的处理，
> 也无法实现对应处理……需要最后的工序设置为装箱，我就无法选择到产线，因为现在没有装箱的这个产线类型
> 存在，导致无法填写这个对应的产线就被卡住，这种情况就需要显示出全部的产线来实现选择。」
> 追认口径：**以后新建的任意工序，都必须能选到产线**。

**判据收口成一句**：`ProcessTaskService.requiredShop(op, routeShop)` —— 返回**车间名**才拦，
返回 `null` 就不设限。只有两种情况会拦：

| 情形 | 结果 |
|---|---|
| 工序在 `ProcessShop` 表里（成型/切炭/组装/装箱，装箱归组装）**且**该车间在 `bs_prod_line` 里**有启用线** | 拦截：线必须属于该车间（2026-10-21 口径不变） |
| 工序**不在**表里（下料/车削/检验，以及以后新建的封箱/喷码/包装…） | **不拦**：预排线弹窗列**全部启用产线**，保存/派工/转序全部放行 |
| 工序在表里但该车间**一条启用线都没有**（还没建线、路线写着历史车间名如「熔铸车间」「装箱车间」） | **不拦**：同上，否则弹窗一条线都列不出来、保存必被拒，新工序直接被卡死 |

- **前端同口径**：`routeSteps` 每道工序多回一个 `限定车间` 布尔；弹窗用
  `business/routeDefaults.lineOptions()` 决定下拉内容 —— `限定车间=true` 才按车间筛，
  否则列全部启用线，并在「生产车间」列打 `全部产线` 标签 + 表下提示一句（避免误以为筛选坏了）。
- **服务端同口径**：`preplanManual`（排线保存）、`assign`（派工）、`applyNextProcess`（自动转序）
  全部改走 `requiredShop`，不再直接调 `ProcessShop.matches` —— 只放开前端而服务端仍硬拒，
  就会出现「选得到、存不进去」，正是本轮报障的形态。
- **不做的事**：不替新工序猜车间（`ProcessShop.resolve` 仍返回空串），不改任何已有台账。
- **取证（2026-10-28，测试账套 `HSDZ_MES_TEST`）**：临时路线「成型 → 封箱（车间空/写成不存在的
  「装箱车间」）」——
  ① `routeSteps` 回落 `封箱 · 限定车间=false`；② `preplan` 把封箱排到 `切炭4(X)`（跨车间）**成功**
  （改前必报「应进的装箱车间不一致」）；③ 回归：`成型 → 切炭4(X)` 仍被拒（「属于切炭，与成型应进的
  成型车间不一致」）。探针与清理见 `tools/archive/_newop-line-pick-20261028/`。

### 2.3 订单结转的工艺路线预填：**同物料 > 同品名同规格族 > 档案绑定**（2026-10-29 用户口径）

> 用户原话：「需要放到的是要同规格通品名的产品实现，不然当前只是根据上次的随便一条转工单的
> 工艺路线就没有实际存在的意义实现了。」

**问题**：2026-10-25 的预填只按**物料编码**取「最近一次转单路线」。同一款产品在系统里常按客户/供应商
拆成多个存货编码（如 `S031-1` / `S031-3`、`B-58-07` / `B-58-10`），各编码历史互不相干 ⇒
等于"随便一条以前的转单路线"，同款产品之间还会互相矛盾。实测待结转 226 行 = 144 个
「品名+型号」家庭，其中 **13 个家庭跨多个编码**、**4 个家庭里不同编码的"上次路线"互相矛盾**。

**口径（三档）**：

### 2.4 生产工单·批量排产：**多行排入同一组产线，排产数量逐行算**（2026-10-30 用户口径）

> 用户原话：「排产数量按各行根据各行的算，这样各个工单排产的产线都是相同的，
> 本身当前作为排产的就是实现将多个工单排入相同产线的操作罢了。」

- **入口**：生产工单列表勾 N 行 →「排产」。勾 1 行 = 原内嵌快速排产（`keyword=工单号#行号`）+
  单行排线弹窗 `ProcessRoutePlanDialog`（**逐字不动**）；勾 N 行 = **仍打开内嵌快速排产页**
  （`ScheduleBoard.vue`，不新建页面），①待排产池由前端按勾选的 `行id列表` 收敛并默认全选，
  ②已排产按 `工单号列表` 收敛；点「批量排产」出 `ScheduleBatchDialog.vue`。
- **批量语义**：整批共用**每道工序一条生产线**（选线仍走 `routeDefaults.lineOptions` 的车间口径：
  成型/切炭/组装/装箱 + 其余工序列全部启用线）；排产班组、计划完工日期整批共用
  （完工日期留空 = 各行按自己的交期）。
- **排产数量**：逐行、各行按各行算 —— 默认 = 该行当前排产数量（>0）否则需求数量，可改小，
  `0 < 数量 ≤ 该行需求数量`（前端 `scheduleBatch.validateQty` + 后端 `preplanManual` 双拦）。
- **工序不同 ⇒ 点名排除**：按「工序链」（工序名称 + 顺序，`>` 连接）分组，默认排行数最多的一组；
  其余组/未绑路线的行在弹窗顶部逐条点名（`工单号#行号 —— 工序不同（成型>装箱）`），不参与本批。
- **换算率不同 ⇒ 允许同批、各自换算**：换算率是**工艺路线明细**字段（`bs_route.换算率`），
  同一路线编码各行必然相同 ⇒「同链不同率」= 两条同链不同率的路线。计划量仍 = 本行排产数量 ×
  本行该道换算率（`ProcessTaskService.preplanManual` 落库时按行重算，**不累乘**）；本批每道合计
  = Σ(各行数量 × 各行率)，不是「合计数量 × 某个率」。弹窗对率不同的行标黄、工序列显示「各行不同」。
- **提交**：逐行调用既有 `/px/scheduleBoard/preplan`（同一套守卫/预排台账/留痕），部分失败点名、
  成功的保留（不整批回滚）。
- **实现落点**：`frontend/src/business/scheduleBatch.js`（纯函数，`scheduleBatch.test.js` 12 条断言）
  + `ScheduleBatchDialog.vue`（新弹窗）+ `ScheduleBoard.vue`（新增可选参数 `行id列表/工单号列表`，
  不传时原行为逐字不变）+ `WorkOrderList.vue`（勾 N 行入口，先点名排除已排产/已结案/已完工）。
- **零库变更 / 零后端变更**：不建表、不加列、无迁移；不改 `/preplan`、`assign` 等接口。
- **验证**：两账套 UI 只读验证(勾选→内嵌页收敛→批量弹窗→取消,未写库)PASS；
  测试库(成型换算率=3)计划量链 600·200·200 / 1500·500·500 证明按行换算不串。
  探针、截图与复跑说明见 `tools/archive/_batch-sched-20261030/README.md`。
- **已知边界**：`preplanManual` 按「工序名称」匹配 steps —— 路线里同一工序重复出现时
  （`GY-001/002/003` 每条重复两次）会给两道用同一条线，属既有隐患，本次未改后端；
  正式库工单现均为 `GY-CB-STD`（无重名）。

## 3. 报工审核钩子链（`runWoAuditHooks`，同一事务内按序执行）

```
WO_REPORT 审核 / 审批通过
  ├─ woReport.post            记账：写 wgzt/wgsj、补工单行号、镜像排产到 scjl
  ├─ processTask.onReport     工序任务回写 + 工单完工状态重算
  ├─ applyNextProcess         转序：前道完工 → 切下一道预排线（逐行）
  ├─ woInspGenerate           工序检验单：按 QcInspAutoService 判据出草稿（幂等）
  │    └─ 成型达标 → 首件 QC_FIRST_INSP + 制程 QC_PROC_INSP；组装达标 → QC_ASM_INSP
  ├─ asmInspToStock           组装成品检验审核 → 按合格数量生成 FINISH_IN 草稿
  ├─ dualOutFinishIn          切炭直销数量 → 成品入库单（自动审核）
  ├─ manuWriteback.post       入库回写 rk_sl/rk_no、领料回写 ll_no2
  └─ syncCloseAfterAsmInsp    组装成品检验审核 → 重算结案
```

要点：

1. **一处定义、两个入口**：审核与「审批通过」共用本方法（`ButtonService:1712`），各钩子内部自筛面板，非本面板直接 return。
2. **幂等与对称**：自动出单按「报工单号 + 工序」查存活单去重；报工**弃审**时作废对应自动单据并释放占用，可再次生成。
3. **越权/超量守卫**：组装成品检验表头合格数量在**真正消费它的那一刻**兜底校验（拒绝审核），不靠前端置灰。

### 4.1 「切炭直销入库」是什么（图上 `CUTOUT` 那个节点）

- **业务**：切炭（图面旧称「裁切」）是**双出口** —— 切出的合格炭棒一部分**不继续组装**，直接作为半成品**对外直销 / 入成品仓**，其余继续组装（银嘉MES总流程整理-V1.2 §5.1「裁切双出口」）。
- **载体**：报工单上的 **`直销数量`**（`scjl.直销数量`，银嘉独有列，`decimal(18,4)`，默认 0）—— 它表达「该次报工数量里有多少走了直销出口」，其余即继续组装；报工保存时校验 **`直销数量 ≤ 报工数量`**（`WoReportService:222`）。
- **实现**：切炭报工单**审核/审批通过**时，`ButtonService.dualOutFinishIn` 自动建一张 **`FINISH_IN` 成品入库单并直接审核入账**
  （仓库=成品类启用仓、车间=切炭车间、带工单行号+批次号、单价取 `plang.dj`；`plang.lot_no` 为空则现场取号并回写），
  回执写回报工行 `scjl.post_no`；`form_flow_link`(`WO_REPORT`→`FINISH_IN`) 保证重审幂等（`ButtonService:2875-2962`）。
- **反向**：弃审切炭报工单 → `dualOutRedReverse` 自动补一张**红字（负数量）**入库单并审核，台账 `rkl/yl` 对称扣减，原单保留作审计线索（`ButtonService:4038-4085`）。
- **与组装那条入库的区别**：直销是**报工审核即建单并自动过账**；组装成品检验审核建的 `FINISH_IN` 是**草稿**，要仓库再审核（见 §2、§3）。
- **字段登记**：`yj_field`(WO_REPORT) 里 `直销数量` = `place='query,detail'`、`seq=55`（紧随「报工数量」seq 50）、`visible=1/hidden=0/required=0`
  ⇒ 它是**报工单表格里的可填列**；`WO_REPORT` 的表头字段只登记了「单据编号/单据日期」两项。
- **有没有数据**：正式库**零真实数据** —— `scjl` 3 行报工的 `直销数量` 全为 NULL；`bd_finish_in` 里那张 `FI-2026-09-0001` **不是**直销链生成的
  （它的占用链来源面板是 `MANU_ORDER`「生成产成品入库单」按钮，2026-09-24 的测试草稿，状态=草稿、`inh` 无流水）。
  取证脚本与逐条数据：`tools/archive/_dualout-probe/`（只读探针 + README 结论）。
