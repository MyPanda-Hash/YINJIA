## 1. 逐条判定

### 1.1 【第 1 条】系统管理平台 —— **部分有**

**本系统对应实现**【已验证】

| 能力 | 落点 | 证据 |
|---|---|---|
| 用户管理 | 组织架构页 `/sys/org`（`OrgAdmin.vue`，`requireAdmin`）→ `SysAdminController /api/sys/user/*` | `yj_user` **13 行**；增/改/删/批量分配角色 |
| 角色管理 | 同页「角色与面板权限」 | `yj_role` **4 行**；`yj_role_panel` **262 行**（面板 × 动作级权限矩阵） |
| 权限（功能级） | `PanelPermissionService.readablePanels` + `SysAdminController.PERMISSION_ACTIONS` | 动作矩阵覆盖 可见/新增/修改/删除/审核/审批/生单/打印/导入/自定义字段 等 |
| 权限（数据级） | `yj_user.生产车间` 字段 + 前端按车间收敛 | 用户弹窗「生产车间」；计划组/管理员留空不受限 |
| 组织架构 | 同页「部门」树（多级，`+子`） | `yj_dept` **20 行**；另有 `yj_change_dept`（变更通知部门） |
| 日志 | 「使用权限查看」`/sys/usage`（`UsageLog.vue`）→ `/api/sys/usageLog`、`/usageLog/grouped` | `yj_usage_log` **2753 行**；字段=时间/类型(登录·操作)/面板/动作/单据号/来源IP，可按账号·面板·动作·日期筛选 |
| 单据变更留痕 | `yj_doc_modify_log`、`yj_archive_change_log`、`yj_schema_log` | 表清单在册 |

**缺口具体是什么**【已验证】

1. **菜单不是数据库驱动的** —— 左侧导航 100% 硬编码在 `frontend/src/business/menus.js`，
   `yj_panel` 只有面板注册信息（`module_group`/`category` 是历史碎值，见流程梳理 §1.5），
   **没有任何菜单表**。后果：**改一行菜单必须改前端代码 + 重新构建打包**，甲方无法自助配置菜单/排序/改名。
2. **无可视化「系统参数」维护界面** —— `yj_app_setting` 表存在，但目前只有
   `receive_over_ratio`（收料超送比例）一个键，且是**在生单对话框里顺手改**（`BatchSendDialog.vue:46`），
   没有集中式参数管理页。
3. **无会话/在线用户管理、无强制下线、无密码策略配置**（密码只由 `YjPasswordEncoder` 校验，默认 123456）。
   **【未确认】**：是否在别处有策略配置，代码检索未命中。
4. **无系统日志导出/审计报表**，只有在线查询（超 2000 条只显示最近部分）。

### 1.2 【第 2 条】数据建模管理 —— **部分有**

**本系统对应实现**【已验证】

- **面板引擎 = 元数据驱动**（这就是「数据建模」的运行时实现）：
  `yj_panel` **125 行**（`panel_code`/`panel_name`/`mode`/`head_table`/`line_table`/`pk_col`/`code_col`/`detail_key`/`page_size`）
  + `yj_field`（字段名/标签/数据类型/字典SQL/参照面板/显隐/顺序/宽度/必填/可编辑）
  + `yj_doc_status`（30 列单据状态）+ `form_flow_link`（行级占用链）+ `yj_translation`（多语言）
  → 由 `PanelConfigService` 统一下发，前端 `PanelxList.vue` / `PanelxForm.vue` **通用渲染**，
  **新增一张单据 = 插元数据行 + 建两张表**，不需要写前端页面。
- **接口**：`PanelRegistry`、`PanelRuntimeService`、`PanelConfigService`（按钮组 / 选单流向 `SELECT_FLOWS` / 推式生单 `PUSH_TARGETS`）。
- **部分可视化字段维护（有限）**：
  - 「字段管理（动态字段/备用列池）」弹窗 `core/views/FieldManagerDialog.vue` ——
    可在**备用列池**上绑定/停用自定义字段（增删列），入口按「自定义字段」权限显隐，
    规格见 `docs/design/动态字段扩展-备用列池-V1.0.md`；接口 `/px/extFields`（读任何人、写 `requireAdmin`）。
  - 数据记录表「字段编辑弹窗」可改 `yj_field.alias`（列别名）/`visible`（`DataRecordSheet.vue:494`）。
  - 数据字典维护：`ZDGL` 面板（基础档案 › 数据字典，表 `bs_dict`）。

**缺口具体是什么**【已验证】

1. **没有在线「新建面板 / 新建字段」的建模界面** ——
   `yj_panel` / `yj_field` 的新增与改动**全部靠写 SQL 迁移脚本**（`tools/migrate-*.sql` 里的
   `INSERT INTO yj_panel` / `INSERT INTO yj_field`）。
   也就是说：**能配「已有面板的列」，不能配「新面板」**。
2. **没有「模型设计器」的完整要素**：无字段类型可视化选择（`data_type` 是中文词表）、
   无参照关系图、无字典在线编辑（走 `dict_sql` 写 SQL）、无表单版式设计器（版式在 `recordSheetConfigs.js` 等前端配置里硬编码）。
3. **无元数据版本管理 / 变更审批**：`yj_schema_log` 只登记迁移脚本执行哈希，不是模型版本。
4. **主数据建模缺失**：BOM（`bs_bom` + 面板 `BOM`/`BOM_FWD`/`BOM_REV`）与自建视图 `v_wo_kit`
   已于 2026-10-04 整批下架（流程梳理 §6 I）；现役只剩 `WLBOM`（表 `mate`）。
   **【未确认】**：`WLBOM` 是否在现役业务中被使用。

### 1.6 【第 6 条】数采平台管理 —— **没有**

**为什么这么判（三条独立证据）**【已验证】

1. **后端无任何采集调度**：`grep -r "@Scheduled|EnableScheduling|ScheduledTask" backend/src/main/java` **0 命中**；
   `application*.yml` 无 `scheduling`/`cron` 配置。**全系统没有任何定时任务**（唯一周期任务在系统外的 Node 工具）。
2. **代码库无设备协议/采集实现**：`grep -ri "数采|采集|OPC|PLC|设备联网|实时数据|SCADA|Modbus"` 全仓命中，
   **除研发「水分未采集」文案、探针脚本注释、旧文档外无一处是采集代码**。
3. **无采集相关表**：实库表清单中，设备侧只有
   `bs_equip`（设备档案，**12 行**）、`equip_check`/`equip_check_detail`（点检记录）、
   `maint_plan`/`maint_plan_detail`（保养计划）—— **全是人工录入的表单，无采集任务表 / 实时数据表 / 设备点位表 / 采集日志表**。

**本系统对应实现**：**未找到**。设备数据入口仅为：
基础档案 › 生产 › 设备（`EQUIP`，档案）；生产制造 › 设备维护 › 设备点检记录 / 保养计划（人工填报）。

**缺口具体是什么**：整块能力缺失，差在**从「设备联网」到「数据落库」的全部环节**——
① 无设备联网/协议对接（PLC / OPC UA / Modbus / 串口 / 网关）；
② 无采集任务配置（点位、频率、采集规则）；
③ 无实时数据表 / 时序存储；
④ 无采集数据与业务单据的关联（例如报工数量、设备状态、OEE 自动取数）；
⑤ 无设备状态监控与异常联动的数据基础。
> 目前生产数据（报工数量、合格/不良）**全部靠人工在 `WO_REPORT` 逐单录入**。

**旁证（非判据）**：`tools/archive/_wms-doc-shots/README.md`（2026-10-05 截图任务）
当时已记录「其中「数采平台管理」「可视化管理」本系统**无对应页面**」。
其中**「可视化管理」这句已过期**（见下条，可视化页面现已存在），**「数采」这句经本次独立核验仍然成立**。

**缺口具体是什么**【已验证】

1. **无车间级大屏/电子看板**：无 Andon（安灯）、无工位终端、无大屏适配版式；
   `dashboard` 是**办公桌面**尺寸的自绘图表，不是车间挂屏。
2. **有页面、无入口**：`生产看板` / `返修工作台` / `方案中心` / `业务总览` 四条路由**写进了 `router/index.js`

   ⇒ **现役用户从左侧导航点不到这四页**，只能手工敲 URL。**（本轮首次发现，流程梳理未记录）**
3. **无实时可视**：无 WebSocket / SSE（`grep -r "WebSocket|EventSource"` 前端 0 命中），
