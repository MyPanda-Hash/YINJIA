> 「当前的首件检验单的表格应该是这种实现方式实现的，当前为全部都在最上面两行可被填写，

## 一、病根：把「每组各 2 支」读成了「每个项目都只记 1#/2#」

相关要求第 1 条原文：

> 表观及脱粉项目测试后记录2支样品数据，炭棒尺寸及重量相关项目测试后记录2支样品数据，
> 炭棒强度测试2支样品，浊度及压降测试记录2支样品。

**正解**：四个分组**各自**占一对样品行，四对 = 纸面 1#..8#，一个样品行只服务一个分组：

| 分组 | 可填样品行 | 图片底色 |
|---|---|---|
| 表观及脱粉 | 1#、2# | 淡黄 `#FFF3CA` |
| 尺寸及重量 | 3#、4# | 淡桃 `#FCE4D3` |
| 强度 | 5#、6# | 淡黄 `#FFF3CA` |
| 浊度及压降 | 7#、8# | 淡桃 `#FCE4D3` |

这正是图片版式：每个分组自己那两行**空白可填**（并铺了底色），其余格一律打 `/`。

**旧实现**（`QcFirstInspSheet.vue` 的 `SAMPLE_LIMIT = 2`）按「样品序号 ≤ 2」一刀切 ⇒

- 1#/2# 只有**表观·脱粉**两列能填（勾选式）；
- 尺寸及重量 / 强度 / 浊度及压降 **三组在任何样品行上都不可录**（8 个测试项目永远填不进去）；
- 3#..8# 整片 `/`。

⇒ 用户看到的「全部都在最上面两行可被填写」，且尺寸/强度/浊度实际上**完全没有录入入口**。

## 二、修法（一处真源 + 组件按它判）

### 1. 真源：`frontend/src/core/qc/firstInspCols.js`

```js
export const GROUP_SAMPLES = {
  '表观及脱粉': [1, 2], '尺寸及重量': [3, 4], '强度': [5, 6], '浊度及压降': [7, 8],
}
export function samplesOfGroup(group)   // 某分组用哪两支（未知分组 → 最后一对，自定义列照旧可填）
export function isFillableCell(sample, group)  // 这一格要不要填
```

单测钉死：① 四组 × 2 支 = 1#..8# **不重不漏**；② 每列只在自己分组那一对样品行上可填；
③ 整张纸 10 列共 **20 个可填格 / 60 个 `/` 占位格**；④ 自定义组名兜底到最后一对，不整列变砖。

### 2. 组件：`QcFirstInspSheet.vue`

- 数据区把 `sample <= SAMPLE_LIMIT` 换成 `fillable(sample, c) = isFillableCell(sample, c.group)`
  —— **看本列的分组**认样品，而不是看样品序号大小；
- 不可填格的 `title` 改成「按相关要求：本组测试只记录 2 支样品（3#、4#）」——
  改前只留一片 `/`，用户不知道该去哪填；
- 可填格铺底色（`gz-y` / `gz-p`，色值直接取自用户图片的主色统计）：
  只标本组自己那两行，其余格保持白底；只读态与打印件一样带（纸面本来就有）。

### 3. 多语言

- 删旧词条「按相关要求：每个测试项目只记录 2 支样品（1#、2#）」——口径本身就是错的，改后无引用；
- 加新词条「按相关要求：本组测试只记录 2 支样品（{a}）」，10 个语言包同步
  （`tools/archive/_i18n-first-insp-zones.mjs` 一把写完）。

**后端一分不动**：`FirstInspItems` 本来就是「10 列 × （1 标准行 + 8 样品行）」，可填范围纯属显示层判据。

`_probe-first-insp-zones.mjs` 验的四件事：

1. **可填行**：10 个项目逐个核「可填样品行 = 本组那一对」，其余格是 `/`；
2. **底色**：四处可填区取到的计算色与图片主色一致（`#FFF3CA` / `#FCE4D3`），非本组格白底；
3. **提示**：不可填格的 `title` 把本组那两支样品说出来；
4. **真落库**：走「选生产工单」建一张带工单号的单，四个分组各填一格（表观勾选 2#、外径 4#、
   跌落 6#、浊度 8#）→「保存」成功 → 库里恰好这 4 行有实测数值、`(检验列, 样品序号)` 与分组对得上
   （`appearance@2# / outer@4# / drop@6# / turbidity@8#`），不串行。探针自清场。
