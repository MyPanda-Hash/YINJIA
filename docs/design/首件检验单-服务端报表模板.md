# 首件检验单 · 服务端报表模板（打印样式）落地（2026-10-17 第九轮）

用户口径：

> 「打印样式需要实现就是当前报表的excel表，当前制程检验单已经存在实现。」

## 一、先对齐「打印样式」指的是哪一条路

面板右侧「文档输出」下有**两条**看上去都像"打印"的路，必须分清（走错就是白干）：

| 路径 | 实现 | 制程检验单 | 首件检验单（改前） |
|---|---|---|---|
| 侧栏「打印」按钮 | 浏览器打印（`approval-printing` + `window.print()`） | ⚠ **坏的**（见第四节） | 上一轮已修好 |
| 「导出报表」→ 打印预览 / 导出 PDF / 导出 Excel | **服务端 JasperReports 模板**（`.jrxml`） | ✅ 有 `qc_proc_insp.jrxml` | ❌ **没有** |

用户说的「制程检验单已经存在实现」指的是**第二条**（服务端报表模板）—— 实测三条接口证据：

```
GET /report/templates?panelCode=QC_PROC_INSP => [qc_proc_insp  制程检验记录表]
GET /report/templates?panelCode=QC_ASM_INSP  => [qc_asm_insp   组装成品检验记录表]
GET /report/templates?panelCode=QC_FIRST_INSP=> [generic       首件检验单]      ← 兜底的通用模板
```

`ReportService.templatesOf()` 的口径是「**有专用模板就用专用，没有才回落 generic**」——
所以首件检验单现在拿到的是一张**通用字段流水**，而不是这张纸。

## 二、改前实测（这就是用户说的"不是当前报表的 excel 表"）

对同一张首件检验单（明细 90 行长表）走 `/report/export`：

| 格式 | 改前结果 |
|---|---|
| PDF | **14 页**、119 KB；每页都是「序号 / 检验项目 / 检验要求 / 检验方法」一行行刷下来，纸面矩阵一点没有 |
| xlsx | sheet 名 `report_generic`、**415 行**；首行不是大标题（是公司名），没有两级表头、没有标准行与 1#..8# |

对照 `qc_proc_insp.jrxml` 头部的注释，那里记着**一模一样**的用户口径：

> 「当前这个报表形式需要根据当前页面修改实现导出，形成和当前页面导出形式相同的 excel 形式而不是当前的旧报表形式」

⇒ 本轮就是把同一件事对首件检验单做一遍：**报表模板的版式 = 面板上这张纸（也就是上一轮做的 Excel 出口径）**。

## 三、为什么走「按数据生成 XML」而不是写死 `.jrxml`

首件检验单的列是**动态的**（面板支持「新增测试项目 = 新增一列」），而 **JR 6.x 的
`reportElement` 的 x/y/width/height 只能是整数常量**（写表达式会被 XSD 拒）⇒「一份模板运行期换列」走不通。

本仓已有两个先例，本轮照**组装成品检验单**那套（矩阵 + 动态列）：

- `QcAsmInspReportSupport`（矩阵版式，列来自数据）—— **本轮的主要参照**；
- `GenericReportSupport`（同套路的最初实现）。

做法：**骨架固定 + 表头/明细按数据生成后拼进去再编译**，编译结果按「列签名」缓存
（结构相同只编一次；数据变了不重编，值走参数）。

## 四、顺带记一笔：制程检验单的「打印」按钮是坏的（与本轮无关，未修）

「制程检验单已经存在实现」只对**导出报表那条路**成立。侧栏那个「打印」按钮**打出来是空白页**：

公共打印样式把 `body.approval-printing .portal` 整体 `visibility:hidden`，再逐个白名单纸张根类名
（`.approval-sheet`/`.qc-rec-sheet`/…），**`.qr-sheet` 不在名单里** ⇒ 纸面自己也是 hidden。

实测（`Page.printToPDF` 走真打印管线）：`tools/archive/_tmp-QC_PROC_INSP-print.pdf` = **1149 字节的空白页**，
`getComputedStyle(.qr-sheet).visibility === 'hidden'`。首件检验单上一轮已修好（`.fi-sheet` 补进白名单），
制程检验单这一处**待修**（另开任务，避免与本轮的报表模板工作混在一起）。

## 五、交付物与验证

### 交付物

| 文件 | 作用 |

### ⚠ 没有入库(`yj_report_template`)—— 这是**对的**,不是漏做

报表模板解析 = **DB 优先 → 注册表兜底**。但对**动态生成**的模板,DB 那行的 `jrxml_text` 根本不被读
(渲染走的是 classpath 骨架 + 生成段)。实测台账:

```
yj_report_template 里只有 qc_proc_insp(纵向表,模板正文就是 .jrxml)与 so_order
qc_asm_insp(同样是"骨架 + 生成"的动态模板)→ **没有 DB 行**,纯注册表
⇒ qc_first_insp 与 qc_asm_insp 同路:只进注册表,不插库。
```

`QcFirstInspReportSupport` 的公开面:`CODE` / `FRAME_FILE` / `PAGE_W·PAGE_H·TABLE_W` /
`matrix(rows, head)` / `report(matrix)` / `params(matrix, head)` / `dataRows()` / `describe(matrix)` /
`columnHeadText(label, unit)` / `unitOfLabel(label)` / `text(v)`。

版式取舍:A4 **横向**(842×595,`columnWidth=782`)。行标签列固定 78pt,其余**等分**剩余宽度
(余数补到最后一列,保证合计恰好 782);标准行高度**按每列文字在本列宽度下要折几行算出来**
(写死 20pt 会被裁,实测"跌落高度…"要 3 行)。

### 🔴 途中挖出两个坑(都写进代码注释了)

**① `orientation="Landscape"` 会把页面**换成纵向**,右半张被静静裁掉。**
骨架里按惯例写了 `pageWidth="842" pageHeight="595" orientation="Landscape"`,编译出来却是
**595×842(纵向)** ⇒ 11 列表格在 x≈565 之后全部出界。实测对照:去掉 `orientation` 属性后
`report.getPageWidth()×Height()` = **842×595**,PDF 的 `/MediaBox` 也随之变成 `0 0 842 595`,
原本缺失的「挤压强度 / 浊度NTU / 压降kPa / 检验人 / 打印时间」全部回来。
**规范:在这些 .jrxml 里不要写 `orientation`,只写 `pageWidth`/`pageHeight`。**

**② 同一个坑,制程检验记录表也踩着(尚未修)。**
`reports/qc_proc_insp.jrxml` 同样写着 `orientation="Landscape"`,实测它的导出 PDF 也是
`/MediaBox 0 0 595 842`,而 `columnWidth=758` ⇒ **右侧约 1/3 被裁**。属另一批,未在本轮改动
(它还有一条 `yj_report_template` 库内行要同步,见该文件头部的生成脚本说明)。

**③ JR 的 xlsx 导出把内容放在第 2 列起**(col 0 空)—— 探针按"第 0 列是行标签"去认会全判错(踩过)。

### 回滚点

删 `QcFirstInspReportSupport.java` + `reports/qc_first_insp.jrxml` + ReportService 里那个分支
+ `report-templates.properties` 那三行,重启后端即回到 generic 通用模板。

## 六、2026-10-18 追加：表尾补第三格「审核人」

用户口径：

> 「为当前的首件检验单增加审核功能，审核功能实现参照当前的制程检验单」

首件检验单与制程检验单同批开了**直接审核**（`PanelxList.DIRECT_AUDIT_PANELS`，
详见 `docs/frontend/前端面板设计.md` §6.1）。制程那张纸的表尾是「检验人 | 审核人」
（`QcProcInspSheet.vue` + `qc_proc_insp.jrxml` 的 `$P{审核人}`），首件这张只到「检验人」⇒
审完打印出来看不出谁审的 ⇒ 本轮三处同批补齐（**版式仍同源**）：

| 面 | 改动 |
|---|---|
| 面板纸面 | `QcFirstInspSheet.vue` 表尾加「审核人」格（只读，取虚拟字段 `head['审核人']`；CSS 三组标签各 96px） |
| 客户端 Excel | `firstInspExport.js` 表尾由两段改**三段等分**（`auditorLabel/auditor`），列数不足时顺延不覆盖前段；单测 ⑤ 同步 |
| 服务端报表 | 骨架表尾由两组改三组（`检验结果｜检验人｜审核人`，均分 782 = 每段标签 78 + 值 182/184）；`QcFirstInspReportSupport` 声明并填充 `$P{审核人}` |

取值口径：**不是本表物理列** —— `ReportService.headParams` 下发单据的全部标量字段，
「审核人」由 `QueryService.loadDocs` 对**非两级审批面板**用 `yj_doc_status.shr` 覆盖
（`qc_first_insp_head` 的 `审核人`/`审核时间` 列在 MES 侧恒空，只有金蝶同步单才写列），
未审核时为空串。⚠ 由此，**导出报表的「审核人」只有在该单已审核时才有值**；
验报表时先用一张**已审核**的首件检验单取证（否则看到的是空格，会被误判成"没实现"）。

复验：`node tools/archive/_probe-first-insp-report.mjs <base>`（该探针断言纸面要素齐全；
新增的「审核人」格在 PDF 文本层可直接 `ops_inspect_local_file ... --pdf_mode=text` 抽出来看）。
