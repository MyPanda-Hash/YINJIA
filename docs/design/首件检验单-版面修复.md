# 首件检验单 · 版面三处修复（2026-10-16 第五轮）

用户口径（截图三个框）：

> 「当前这个生产日期的控件不要超出当前框体。还有删除黄框的内容。修复当前红框会因为过多列而挤压的问题，
> 当前实现可以拉滚动条移动。增长当前生产日期框体长度让当前控件不会超出距离。」

## ① 生产日期控件收进框内（并把这一格加宽）

**病根**：抬头四对是 `table-layout: fixed` 的等分表，每格摊到 ≈150px；而 Element Plus 的日期选择器
root 自带 `width: var(--el-date-editor-width)`（默认 **220px**）⇒ 控件顶出格线、压到「组别」上。

**修法**：
- 生产日期那一格给**固定宽 240px**（`:style="f.date ? { width: '240px' } : null"`，其余列照旧平摊）；
- 抬头格子里的控件按 100% 收口（`.fi-head td .fi-cell` + `:deep(.el-date-editor.el-input)`，
  特异性高于组件自带样式）。

实测：格子 `958..1198`（240px）、控件 `964..1191`（227px）⇒ **完全落在格内**。

## ② 删掉黄框那条提示

第三轮按「相关要求第 3 条后半句」加的提示条 `本单同时有浊度与压降两项测试：请先测初始浊度，再进行压降测试。`
（`.fi-tip` + `turbidityPressureTip` computed + 对应 CSS）**整体移除**。
「先测浊度后测压降」的口径不变——它仍由**列序**保证（浊度列本来就排在压降列之前），相关要求第 3 条原文也照旧印在纸面底部。
（语言包里那 1 条词条留着不删：它属于翻译词典，删它要动 10 个共享语言包，收益只是"少一条无用词条"。）

## ③ 列多不再挤压，改成横向滚动

**病根**：`.fi-grid` 是 `width:100%` 的 fixed 布局表 —— 测试项目可以自由新增，列一多每列就被压成一条缝。

**修法**：表格外面套一层滚动容器 `.fi-grid-scroll { overflow-x: auto }`，并给表格挂一个**按列数算的最小宽**：

```
minWidth = 96(行标签) + 120 × 列数 + (可编辑 ? 40(操作列) : 0)
```

容器够宽就照旧 `width:100%` 铺满；不够宽就按最小宽撑开、由外层拉滚动条。实测：
10 列 → 17 列时，列宽稳定在 **120px**（改前会被压扁），表格宽 2176px / 容器 1300px ⇒ 溢出可滚。

打印/导出：`@media print { .fi-grid-scroll { overflow: visible } }` —— 不裁切，交给打印机分页。
