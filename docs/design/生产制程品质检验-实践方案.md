## 0. 一句话结论

**这套东西系统里已经全有了，只差"把标准填进去 + 把明细带出来"。**

用户截图确认了完整闭环（这是本次最关键的理解）：

```
① 出货检验项目控制计划（截图4）      ← 系统已有：RD_INSP_PLAN「出货检验计划表」
   维护「检验项目 / 检验要求 / 检验方法 / 不合格应对措施 / 检查频率」
        │
        │  检查频率 = 1PCS/一个生产批次   ← 与制程检验表 B24 逐字一致！
        ▼
② 制程检验记录表（截图1/2/3）        ← 系统已有：QC_MOLD_INSP 等三张工序检验单
   报工审核时按频率触发 → 带出检验项目 → 品质填实测值 → 判定
```

**所以本任务的实质不是"新建一个检验单"，而是打通「出货检验计划表 → 工序检验单」这条自动带出链路。**

### 🔴 决定性证据：检查频率字典

`检测频率` 的下拉字典实测为：

```sql
SELECT v FROM (VALUES (N'1PCS/一个生产批次'),(N'生产量*1%'),(N'型式检验')) AS t(v)
```

而制程检验表 `B24` 写的是：

> 以下检验项目对应系统上的检查频率，**1PCS/一个生产批次**才进行测试

**两者逐字一致** —— 证明设计意图就是：
**制程检验表里"要检哪些项"，由出货检验计划表的 `检测频率=1PCS/一个生产批次` 的行决定。**

### 现状：这张表**一行数据都没有**

```
rd_insp_plan_head    : 0 行
rd_insp_plan_detail  : 0 行
```

**这是整条链路的断点** —— 标准没建，所以下游无从带出。

### 2.2 🔑 关键发现：「尺寸」「出货重量」各占 **5 列**

这不是随手画的 —— 对照我们刚做完的出厂检验报告 `c-95-12`：

| 检验项 | 抽检量 | 结果 |
|---|---|---|
| 尺寸规格检查 | **5** | 外径 `44.5/44.6/44.5/44.7/44.6`（**5 个值**）<br>内径 `20.9/20.8/21.0/20.7/20.8`<br>长度 `256.2/256.2/256.9/256.4/256.6` |
| 重量检查 | **5** | `234.5/230.8/234.1/225.1/226.1`（**5 个值**） |

**5 列 = 5 个抽样测量值的位置**。所以：

- **外观** → 定性判定（无异常），3 个子列里前 2 个固定、第 3 个动态
- **尺寸** → 定量，一个项目要记 **5 个测量值**
- **出货重量** → 定量，同样 **5 个值**

## 4. 方案设计：三段式映射

### 4.1 整体链路

```
【标准层】研发管理 · 产品文件
  出货检验计划表 RD_INSP_PLAN（截图4）
    头：产品编号 / 客户项目名称 / 产品整体尺寸 / 版本号 / 编写人 / 审核人
    行：序号 | 检验类别 | 控制项目 | 控制标准及要求 | 控制方法 | 检测频率 | 不合格应对措施
         └─ 检测频率 = 「1PCS/一个生产批次」的行 ← ★ 就是制程检验要检的项
                    = 「生产量*1%」/「型式检验」的行 ← 不参与制程检验
              │
              │  ① 按 产品编号 匹配
              ▼
【执行层】生产制造 · 工序检验单（截图1/2/3）
  WO_REPORT 报工审核
     └─ 按 工序 → QC_MOLD_INSP / QC_CUT_INSP / QC_ASM_INSP
          └─ 按 产品编码 → 找出货检验计划表 → 取「1PCS/一个生产批次」的项
               └─ 逐项生成明细行（表区 = 检验类别，检验项目 = 控制项目，
                                标准要求 = 控制标准及要求，检验方法 = 控制方法）
                    └─ 品质填 实测数值 → 判定
                         └─ 头.总结论 = 结果判断
              │
              │  ② 报表输出
              ▼
【输出层】制程检验记录表（截图2/3 的版式）
  用 Jasper 报表按「外观 / 尺寸 / 出货重量」三段渲染（同 c-95-12 那套链路）
```
