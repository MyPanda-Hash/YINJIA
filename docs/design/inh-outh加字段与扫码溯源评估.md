## 10. ⭐ 批号（lot）能不能做溯源键 —— **已查实：直接一跳是断链**

### 10.1 结论

**批号本身不能作溯源键** —— **成品批号与原料批号之间没有任何关联字段或中间表**，全库找不到成品批号↔原料批号的列或表。

**但有一条已存在的间接边**：

```
成品批号 → plang 行 → 领料单行 → 原料批号
           （工单号 + 工单行号）
```

`工单号 + 工单行号` 同时挂在**领料单头**（`bd_material_out.加工单号` + `工单行号`）与**完工入库单头**（`bd_finish_in.加工单号` + `工单行号`），而 `plang` 行带 `lot_no`（成品批号）。

⇒ **现状能做到「单据级」（经工单行两跳），做不到「批次级」**。**且前提是领料单带了加工单号/工单行号**（只有「转领料单」生成的才带）。

**⭐ 关键发现：系统里已经有一个追溯页在跑** —— `ScheduleBoardService.java:846-879` 做的正是"工单号+行号 → 领料单行 → 批号"这条两跳链。

### 10.4 ⚠️ 领料批号是"人工填"的 —— 这是溯源覆盖率的决定因素

- `yj_field` 实测 `MATERIAL_OUT.批号` = `place=query,detail`、`editable=1`、**`required=1`**、`ref_panel=NULL` ⇒ **自由文本，既不参照现存量、也不来自 BOM**
- 领料单**只转单头**，材料行由仓库按实发补：`WorkOrderPickingService:27-33`「**不做"猜材料"的自动展开**」
- **全仓无 FEFO/先进先出/自动选批实现**（"先进先出"只出现在 INV 的「计价方式」字典）；**前端无批次选择 UI**
- 出库守卫：`StockLedgerService:157` **批号为空直接报错**「请扫材料二维码补批号后再审核」

⇒ **"这批成品到底耗了哪几个原料批次"，系统自己不知道，完全取决于仓库当时填/扫了什么。**

### 10.5 完工入库批号与原料批号无关联

- 切炭直销自动生单：`plang.lot_no` 有则用，为空则 `lotSeqService.next()` **新取号**并回写 `plang`（`ButtonService:2531-2548`）
