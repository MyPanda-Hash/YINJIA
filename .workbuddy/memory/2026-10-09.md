## 后端安全与性能审查（对话内报告，未改代码）

范围：Spring Boot 后端重点扫描（认证链/动态查询引擎/权限服务/附件/OCR/报表/SysAdmin）。

### 关键发现（按严重度）
- **P0 停用账号可登录**：`AuthController.login` 的 SQL 不查 `enabled` 字段（enabled 检查只在 ButtonService 审批人校验里），停用账号治理完全失效。修复=登录 SQL 加 `AND ISNULL(enabled,'1')='1'`。
- **P1 voucherFlow/sources 越权读**：`PxController.voucherFlowSources` 仅在 targetPanel 非空时校验 `requirePanelView(targetPanel)`；传空 targetPanel + 任意 sourcePanel 即可读任意面板全量业务数据。且校验对象应是 sourcePanel（读的是它的数据）。
- **P1 单号生成竞态**：`FormNoService.next()` = SELECT MAX → exists 检查 → INSERT，无锁无唯一约束兜底，并发保存会产出重复单号。对照：`LotSeqService` 用 UPDATE...OUTPUT 原子取号是正确示范。
- **P1 AttachmentController 无面板权限校验**：list/upload/delete/download 四端点任何登录用户可操作任意单据附件（含客户图纸下载、头表字段值覆盖）。
- **P1 JWT secret 有公开默认值**：`application.yml` `${YINJIA_JWT_SECRET:CHANGE_ME_...}`，生产忘配环境变量=任何人可伪造 token。建议启动 fail-fast。DB 密码明文入库同文件（内网惯例，但建议一并外置）。
- P2：GlobalExceptionHandler 500 回传原始 e.getMessage()（SQL 细节泄露）；pageSize/pageNo 无上限校验（大页 DoS + 负 OFFSET 报 500）；CORS 全开；/sys/user/list 任意登录用户可枚举全部账号；登录无限流无锁定；rdBoard N+1（每档案面板一条 TOP 5 查询）；权限查询（isAdmin/permsOf/readablePanels）每请求 2-4 次 DB 无缓存；全字段 '%kw%' LIKE 不可走索引（已有 OPTION(RECOMPILE) 缓解 4 张库存报表）。
- P3：X-Forwarded-For 直接信任；rdBoard 字符串拼 SQL（内部注册表来源+已转义，模式风险）。

## 影响分析（"修复会不会影响正常使用"追问，只读探针实测）

- **P0 实测背书**：HSDZ_MES 正式库 13 个账号，仅 1 个 enabled='0'（tester01 测试账号）→ 登录加 enabled 过滤对正常账号零影响。
- **P1-2 单号竞态实测**：s_allno.dh **历史零重复**（竞态是潜伏缺陷、不紧急）；dh 无唯一索引但有 PK(id)+lb/ny 非唯一索引 → 加 dh 唯一索引不会因脏数据失败，可行。
- **pageSize 上限红线**：前端实际最大传 500（dashboard/index.vue、engine.js STOCK_STATUS、RecipeCalcDialog）→ 服务端上限必须 ≥1000，否则功能回归。
- **JWT fail-fast 是唯一需要部署配套的**：必须先给 start-prod.ps1 与服务器部署脚本注入 YINJIA_JWT_SECRET，否则服务起不来；换 secret 后在线用户需重登一次。
- **voucherFlow 改校验 sourcePanel 有低概率回归**：readablePanels 三层放行（可见∪参照∪同模块）大概率覆盖选单链路，但需实测各角色选单功能。
- 分组结论：P0/附件权限/异常脱敏(仅500兜底)/CORS/N+1/权限缓存 = 零影响组；JWT = 配套组；voucherFlow/FormNo 原子化 = 实测组。
