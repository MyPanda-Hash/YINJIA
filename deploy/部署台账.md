## 0. 快速判定：服务器现在是哪一版

三条指纹互相印证，任意两条吻合即可定位版本。

| # | 指纹 | 取值位置 |
|---|---|---|
| ① | **app.jar SHA256** | 服务器 `certutil -hashfile C:\yinjia\app.jar SHA256` |
| ② | **前端入口 chunk** | 浏览器打开 `http://localhost:8090/`（服务器本机）或 `http://36.140.66.163:8090/`，看 `<script src="assets/index-XXXX.js">` |
| ③ | **迁移台账条数** | 服务器 `sqlcmd … SELECT COUNT(*) FROM yj_schema_log` |

判定方法：拿①或②去下面「§1 台账」的**部署后 jar / 部署后入口**列里匹配，命中最上面一行 = 当前版本。
③ 用于判断「库跟没跟上」（条数对不上 = 库比代码落后或超前）。

1. **`MANU_ORDER` / `MANU_SCHEDULE` 仍在**：`migrate-drop-manu-order-20261028` 的闸门①要求两表 0 行，

   （历史字段残留，不影响使用）。

## 3. 服务器取证命令集（只读，随时可跑）

```cmd
rem ① 代码版本
certutil -hashfile C:\yinjia\app.jar SHA256

rem ② 前端版本（同机）
curl -s http://localhost:8090/ | findstr /i "index-" 

rem ③ 库到哪一步了
sqlcmd -S localhost -d HSDZ_MES -E -W -h -1 -Q "SET NOCOUNT ON; SELECT 'ledger='+CAST((SELECT COUNT(*) FROM yj_schema_log) AS varchar(10)) UNION ALL SELECT 'panels='+CAST((SELECT COUNT(*) FROM yj_panel) AS varchar(10)) UNION ALL SELECT 'fields='+CAST((SELECT COUNT(*) FROM yj_field) AS varchar(10))"

rem ④ 最近一次部署日志（RESULT 行）
dir /o-d C:\yj-deploy\pkg-incr-*\logs\deploy-*.log
findstr /c:"RESULT:" C:\yj-deploy\pkg-incr-20261101\logs\deploy-*.log
```

> 迁移台账的完整导出（含 content_hash）见 `deploy/部署说明.md` §二 B 与 pkg README；
> 导出后可与 `tools/db-migrations.txt` 做差集，得出「服务器还缺哪些脚本」。
