## 三、与订单同步的差异(架构上的"档案模式")

| 维度 | 订单(doc) | 基础资料(archive) |
|---|---|---|
| 表 | 头表+行表(1:N) | 单表 |
| 状态镜像 yj_doc_status | ✅ MERGE(shr/stopped) | ❌ **不写**(档案无审核流;删除=MES侧 asp_cancel='Y') |
| 行表 DELETE+INSERT | ✅ | ❌ 无行表 |
| 编码匹配列 | 单据编号 | **每表不同**(dm/存货编码/员工编码...) → 注册表需加 `codeCol` |
| 列表过滤 | bill_status=C + 时间窗 | **无过滤参数** → 全量列表+指纹跳过 |
| enable 处理 | — | enable=0 → 停用位=1(行保留,不删) |
| 增量时间窗 | 31天 modify 窗 | **不用时间窗**(全量指纹,量小:合计约4600条/46页列表) |

## 四、脚本改造细节(对照 sync-core.mjs 现有代码)

### 1. DOCS 注册表扩展

```js
// sync-core.mjs 的 DOCS 数组追加 12 个档案条目(示例 2 个):
{
  code: 'BD_CUSTOMER', label: '客户', archive: true,          // ← 新增 archive 标记
  listPath: '/jdy/v2/bd/customer', detailPath: '/jdy/v2/bd/customer_detail',
  headTable: 'dm_kh', lineTable: null,                         // 档案无行表
  codeCol: 'dm',                                               // ← 新增:编码匹配列
  fingerprintOf: (r) => [r.number, r.name, r.enable, r.group_name, r.remark].join('|'),
  mapHead(d) { return { dm: str(d.number), mc: str(d.name), addr: null /*敏感跳过*/,
    tel: null, bank: str(d.bank), bank_no: null /*敏感*/, sui_no: str(d.sui_no || d.tax),
    khlb: str(d.group_name), khjb: str(d.c_level_name), ywman: str(d.emp_name),
    bz: str(d.remark), comm: '', __停用: d.enable === '0' }; },
  mapLines: null,
}
```

### 2. upsert 拆分:upsertArchive(单表版)

`upsertDoc` 基础上:去掉行表 DELETE/INSERT、去掉 yj_doc_status MERGE;WHERE 改为
`外部数据ID=@extid OR (外部数据ID IS NULL AND [codeCol]=@编码)`。
其余(参数化生成/外部指纹/asp_time1=星辰create_time)复用。

### 3. 增量与初始化的档案策略

- **两模式统一**:档案不做时间窗,每轮全量列表(46页) + 指纹跳过 → 实测成本约 20 秒/轮;
- config.sync.types 加入 12 个档案 code(或加 `groups: ['doc','archive']` 开关);
- 建议顺序:档案先于订单同步(同一轮内 DOCS 数组顺序即执行顺序,档案放前面)。

### 4. 迁移 SQL(每张目标表,幂等)

```sql

IF COL_LENGTH('dbo.dm_kh','外部单据号') IS NULL ALTER TABLE dbo.dm_kh ADD [外部单据号] nvarchar(200) NULL;

IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name='ux_dm_kh_ext_id')
  CREATE UNIQUE INDEX ux_dm_kh_ext_id ON dbo.dm_kh([外部数据ID]) WHERE [外部数据ID] IS NOT NULL;
GO
-- bs_inv / bs_emp / bs_dept / bs_wh / bs_uom / dm_gf 同模板
```

### 5. enable → 停用 映射规则

- 金蝶 `enable`:**字符串**"1"/"0"(注意是 string 不是 number;结算方式/币别是 integer 1/0/-1);
- 有 `停用`(bit) 列的表:`停用 = (enable !== '1')`;
- `状态`(nvarchar NOT NULL) 列:`enable==='1' ? N'启用' : N'停用'`;
- dm_gf(旧表无停用列):`asp_cancel = enable==='1' ? 'N' : 'Y'`;
- **行不物理删除**:金蝶删档 → 列表不再返回 → 本地保留(与订单弃审同理,以金蝶为准)。

### 6. 敏感字段(⚠重要)

官方标注"敏感数据解密"的字段(addr/email/tel/mobile/bank_account 等)返回 **AES 密文**,
密文形如 `bsiV0ZrykeIH/5ZZ65lX5A==`。两种处理:
- **跳过**(推荐起步):映射时置 null,地址/联系方式等从金蝶界面维护;
- **解密**:AES-256-CBC/PKCS7,密钥=应用的 client_secret(32位ASCII),**iv 固定 `5e8y6w45ju8w9jq8`**,
  Base64 解码后解密(官方文档《隐私数据解密》有 Java 示例,Node 用 `crypto.createDecipheriv('aes-256-cbc', clientSecret, iv)`)。

### 7. 分类对照(商品分类等)

`material_detail` 的分类是 `parent_id`(id 引用)。两种取法:
- 先同步"商品分类"面板(id→name 映射存内存/专表),商品落表时 id→name 写 `所属类别`;
- 或详情接口若有 `parent_name` 直接用(部门详情有 parent_name,商品详情需验证)。

### 8. 安全规范自动适用

档案同步走同一 runCore → 备份/超阈值提示/日志轮转/PID 锁**全部自动生效**,无需额外代码;
备份范围=档案全表前像(初始化)或变化行(增量)。

## 六、已知坑(本项目实测)

| 坑 | 说明 |
|---|---|
| 表格解析 | 官方文档 markdown 表格**行尾常缺竖线**、子结构用 `**Data**` 粗体——写解析器时勿用 `split('|').slice(1,-1)` |
| enable 类型 | 档案多为字符串"1"/"0",结算方式/币别是 integer(含 -1 不限) |
| NOT NULL | bs_inv 四个必填(所属类别/状态/是否检验/数据来源)、bs_* 系列 `状态` 均必填;dm_kh.comm/dm 必填 |
| 旧表列名 | dm_kh/dm_gf 是旧系统拼音缩写列(dm=编码/mc=名称/bz=备注/sui_no=税号),别按新表风格猜 |
| 档案接口无时间窗 | 不要套用 modify_start_time(会 500 或被忽略),全量+指纹即可 |
| 面板注册红线 | 若新建面板展示这些数据:AGENTS.md 要求同步交付 yj_field + yj_translation(至少 en),否则功能视为未完成 |
