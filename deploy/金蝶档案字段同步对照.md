> 记录日期:2026-09-15 | 适用范围:12 类基础资料档案(deploy/sync-core.mjs 的 `BD_*` 条目)
> 配套工具:`_probe-archive-fields.mjs`(抓真实接口字段)、`_compare-fields.mjs`(双向自动对照)、`_gen-archive-fields.mjs`(生成迁移)

## 一、本次口径(用户确认后定稿)

1. **字段来源 = 列表接口 ∪ 详情接口**
   实测两者字段集不同:供应商列表有 `bank/rate/invoice_name/group_number` 而详情没有;商品列表有
   `brand_name/stock_name/base_unit_number` 而详情没有;仓库列表有 `group_name/is_allow_neg`;部门列表有 `is_leaf`。
   **商品分类则是详情超集**(列表 7 键,详情 11 键:`parent_id/description/creator_name/modifier_name` 仅详情有——
   `parent_id` 是「上级编码」的来源,漏调详情会导致上级编码永远为空,2026-09-16 已修复为必调详情)。
   运行期用 `mergeListDetail()` 合并(列表打底、详情非空覆盖),避免"只调一侧白丢字段"。
2. **只保留能同步过来的字段**:面板字段 = 映射实际写出、且接口真有该键的字段;其余删除(`migrate-kingdee-archive-prune.sql`
   + `migrate-kingdee-archive-keep-syncable.sql`)。物理列保留(MES 业务逻辑读列),只删面板字段。
3. **敏感字段解密导入**:官方《隐私数据解密》——AES-256-CBC / PKCS7,密钥 = 应用 `clientSecret`(32 位 ASCII),
   IV 固定 `5e8y6w45ju8w9jq8`,密文 Base64。实现见 `kingdee-crypto.mjs`(`setSecret/dec`),失败不阻断同步并计数。
4. **初始化清污**:`init-sync` 每轮先"确认→全量前像备份→删本同步器旧数据→全量重建"(手录行保留)。
5. **测试上限**:`config.sync.maxRecordsPerType`(当前 50)——够数即停,不再翻页。

## 四、自定义字段(商品·来料检验,2026-10-03)

金蝶界面自建的自定义字段走详情接口的 `custom_field` 容器(`{键ID: 值}`),**接口不返回字段显示名**,
所以「哪个键 = 哪个字段」只能实测取证后登记在 `sync-core.mjs` 的 `CF_INSPECTION_KEYS` 里:

| 账套 | 键 ID | 凭据 |
|---|---|---|
| 测试沙箱 Wyaf4sPe | `custom_field__1__62jiaob3z7yj97` | 2026-09-18 定义,CL004 取值「是」全链路通 |
| 真实账套 359797 | `custom_field__1__62tvoyr1j4fa` | 2026-10-03 实测:商品 `custom_field` 共 4 键,前三键为老字段(规格/装箱量,值形如 `57*21*66.5`/`108支/箱`),此键**最新且取值只有「是」**,命中 YJ-XH-001/002、YJ-TJHZ-001/006、YJ-YKRS-007/008/009/014 共 8 个商品 ⇒ 即「来料检验」,落 `bs_inv.来料检验`(INV 面板 detail 列,只读,金蝶维护) |

**为什么必须额外做「自定义字段复核」**(实测踩坑,勿删):

- 商品**列表**接口只回 35 个标准键,**既没有 `custom_field` 也没有 `modify_time`**,而"指纹跳过"用的就是列表行
  ⇒ 自定义字段在商品上**改了什么都看不出来**,不主动重取详情就永远同步不到;
- 列表接口**支持** `modify_start_time/modify_end_time` 过滤(实测近 7 天 16 条 / 31 天 110 条 / 60 天 781 条),
  且自定义字段编辑**会**推进商品 `modify_time`(那 8 个「来料检验=是」的商品正落在近 7 天窗口内);
- 按自定义字段过滤**不支持**(字段名当参数 / `custom_field.` 前缀 / `filter=` 均返回全量 3852 条)。

**取值口径(用户 2026-10-03):「没有填写『是』的,默认为否」** —— 金蝶侧未勾选时接口回**空串**,
故两侧同口径:

- 同步器:`cfInspection()` 从登记键里取不到「是」就写 **否**(不再写 NULL);
- 存量:迁移 `tools/migrate-inv-inspection-default-no.sql` 把 `bs_inv.来料检验` 的空值统一回填「否」
  (已填「是」的不动),并给该列加默认约束 `DF_bs_inv_来料检验`(MES 侧新插入、未带该列的商品行自动落「否」)
  与列注明;
- 实测(2026-10-03,两账套执行后):`HSDZ_MES` 3874 行 = 是 9 / 否 3865 / 空 0 / 其它 0;
  `HSDZ_MES_TEST` 3859 行 = 是 10 / 否 3849 / 空 0 —— 默认约束另在测试库用「事务内插入后回滚」验证:省略该列 → 落「否」。

⇒ 同步器的做法:
1. **常规复核**:每轮把「近 `CF_REFRESH_WINDOW_DAYS`(31)天改动过」的商品圈出来,给它们的指纹追加**当日戳**,
   同一天至多重取一次详情(每天 ≤ 窗内条数,有界),此后指纹一致即跳过 —— 在 5 分钟增量任务里自动生效;
2. **存量补拉**:登记表新增/改动键之后,已有行必须全量重取一次:
   `node sync.mjs --refresh=BD_MATERIAL --yes`(忽略库内指纹,3852 个商品逐个取详情 + upsert)。
