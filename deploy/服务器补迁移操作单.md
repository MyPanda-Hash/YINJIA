# 云服务器补迁移操作单（手机领料缺表）

> 目标：服务器 `36.140.66.163:8090` 上，手机端「生成工单领料/退料单」不再报
> `对象名 'dbo.wo_pick_doc' 无效`。
>
> 一句话结论：**光换 jar 不够，必须让 DbSync 按 `tools/db-migrations.txt` 跑迁移。**

---

## 0. 为什么会缺表

手机领料是 2026-10-30 ~ 11-01 这段新增的功能，用到了 4 张新表：

| 表 | 用途 | 迁移脚本 |
|---|---|---|
| `wo_pick_doc` | 领料台账（报错的就是它） | `migrate-wo-pick-doc-20261030.sql` |
| `wo_pick_return` | 退料台账 | `migrate-wo-pick-return-20261030.sql` |
| `wo_pick_line` | 领料明细 | `migrate-wo-pick-line-20261101.sql` |
| `bs_asm_bom` | 组装物料清单（生单取 BOM 用） | `migrate-asm-bom-20261030.sql` |

这些表**本机有、服务器没有**，因为没有跑过对应的迁移。

⚠️ 特别说明：`migrate-wo-pick-line-20261101.sql` 之前**漏登记在 `db-migrations.txt`** 里
（已在提交 `c7cea084` 补上）。所以同事**必须拉到这个提交之后的代码**，否则
DbSync 不会执行它 → `wo_pick_line` 仍然缺。

## 1. 拉代码：认准这个版本

```bash
git fetch origin
git checkout main
git pull origin main
git rev-parse HEAD
```

**必须 ≥ `880fbac540ef1fb98c6e564f50f7f1a4dbc018d7`**（提交 `880fbac54`，2026-11-03）。

拉到后**立刻自查这两件事**（缺一不可）：

```bash
# ① 迁移清单里必须有 wo-pick-line
grep -n "migrate-wo-pick-line-20261101" tools/db-migrations.txt
# 期望输出：4414:migrate-wo-pick-line-20261101.sql

# ② 脚本文件必须在
ls -l tools/migrate-wo-pick-line-20261101.sql
```

**如果 ① 没有输出 → 代码是旧的，停下，重新拉。**

---

## 2. 要拉的是「整个仓库」，不是只有 jar

部署包里必须包含：

```
tools/db-migrations.txt        ← 唯一权威清单，DbSync 按它跑
tools/*.sql                    ← 全部迁移脚本
tools/lib/mssql-jdbc.jar       ← 数据库驱动
tools/DbSync.java              ← 迁移执行器
backend/target/yinjia-mes-backend-0.1.0.jar   ← 应用
deploy/deploy-production.bat   ← 部署入口
```

**最容易犯的错**：只拷了个 jar 上去，或者用了旧的部署包（里面的
`db-migrations.txt` 还是老的）→ 表依然缺。

---

## 3. 部署：先 CHECK，再 GO

在**服务器上**、解压后的部署包目录里执行：

```cmd
deploy-production.bat            :: 只读体检，不改任何东西
```

先看 CHECK 的报告，确认没异常，再执行：

```cmd
deploy-production.bat GO
```

它会依次做：

```
停应用 → 备份数据库 → 按 db-migrations.txt 跑迁移 → baseline → 同步复核
      → 换 jar → 启动 → 真实登录探针
```

**预期输出里有**：`执行 N 、跳过 M 、失败 0`。

- `失败 0` 才算成功
- 若出现 `RESULT: FAIL-*`，**停下来**，把日志给回我，不要反复重跑

日志位置：`deploy/logs/deploy-<时间戳>.log`

---

## 4. 验证：这四张表都得在

跑完迁移后，在服务器上执行这段 SQL（SSMS 或 sqlcmd）：

```sql
USE HSDZ_MES;
GO
SELECT t.name AS 表名,
       CASE WHEN OBJECT_ID('dbo.'+t.name,'U') IS NULL THEN N'❌ 缺' ELSE N'✅ 有' END AS 状态
FROM (VALUES
    (N'wo_pick_doc'), (N'wo_pick_return'), (N'wo_pick_line'), (N'bs_asm_bom'),
    (N'wo_day_plan'), (N'wo_proc_card_head'), (N'wo_proc_card_detail')
) v(name)
ORDER BY t.name;
GO
-- 组装物料清单要有数据(否则生单时取不到 BOM)
SELECT COUNT(*) AS bs_asm_bom行数 FROM bs_asm_bom;          -- 期望 > 0
SELECT COUNT(DISTINCT 产品编码) AS 产品数 FROM bs_asm_bom;   -- 期望 > 0
GO
```

**`bs_asm_bom` 行数为 0 也是问题**：表建了但没数据，生单会报「未找到组装物料清单」。
数据来自 `migrate-asm-bom-data-20261030.sql`（1085 行 / 236 个产品），确认它跑了。

## 6. 别忘的两件事

### ① 记账

按项目规范，部署完要在 **`deploy/部署台账.md`** 追加一节（append-only），必须写：

- `app.jar` 的 SHA256
- 前端入口 `index-*.js` 文件名
- `yj_schema_log` 行数
- 本次跑了多少条迁移、跳过了多少
- 验收证据（截图或接口返回）

参考格式：`docs/development/部署记录规范.md`

### ② 代理要重装

服务器更新后，客户电脑上的打印代理**不用动**（它是独立进程，只是去服务器拉任务）。

但如果之前装的是**旧包**（没有「自己去服务器拉任务」那个能力），必须换新包：
`deploy/yinjia-print-agent.zip`（21.4 KB，2026-11-03 之后打的）。

旧包在公网部署下会一直显示「代理未连接」，且**真的拉不到任务**。

## 附：出问题时先看这三处

| 现象 | 先查什么 |
|---|---|
| 仍报 `wo_pick_doc 无效` | `tools/db-migrations.txt` 里有没有 `migrate-wo-pick-doc-20261030.sql` |
| 报 `wo_pick_line 无效` | 清单里有没有 `migrate-wo-pick-line-20261101.sql`（这是之前漏登记的那个） |
| 报 `bs_asm_bom 无效` / 生单报「未找到组装物料清单」 | 表在不在 + 行数是不是 0 |
| `deploy-production.bat` 输出 `FAIL-*` | `deploy/logs/deploy-*.log` 里第一条 FAIL 的脚本名 |
