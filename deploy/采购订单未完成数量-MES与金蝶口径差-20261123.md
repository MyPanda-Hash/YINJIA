# 采购订单「未完成数量」MES 与金蝶为什么对不上(2026-11-23 实测)

> 现场:用户报「两个系统采购订单未完成数量没同步 —— MES 显示已完成,ERP 显示都还没完成」,
> 举例单号 `YJ-20260927-02` / `YJ-20261023-05` / `YJ-20261112-10` / `YJ-20261114-03`(同一物料 `YJ-SX-005-2`)。
> 本文只读取证:金蝶真实账套(359797)+ 本机账套快照(`HSDZ_MES`,数据止于 2026-11-13)。

## 一、结论:两边量的是两件不同的事,而且中间没有「同步」

| | MES 生单对话框里的「已生单 / 剩余」 | 金蝶采购订单的「未完成数量」 |
|---|---|---|
| 数据来源 | `form_flow_link`(`link_status='ACTIVE'` 的 `linked_quantity` 求和) | 订单分录 `un_out_qty` = 订单量 − **已审核采购入库量** |
| 含义 | 该订单行**已经生单出去多少**(送料暂收/来料检验/采购入库单被创建即算) | 该订单行**还没入库多少** |
| 代码 | `VoucherFlowService#sources` / `BatchService#sentByLineKey` / `PushGenerateHandler#batchRows` | 金蝶原值,同步落在 `bl_pu_order.行未执行数量`(`EXTRA_LINES` 自动映射) |
| 会不会超 | 会 —— 默认允许超送「数量 ×(1+超送比例,上限 50%)」,`剩余` 用 `Math.max(0, …)` 夹到 0 | 会 —— 超收时是**负数**(实测 −1800 / −1000) |

**两者之间没有任何自动同步:**

- 同步任务(`deploy/sync.mjs`,每 5 分钟)只拉 **采购订单 + 12 类档案 + 库存**,**从不拉采购入库单**;
- MES **不回写**金蝶的订单完成状态,也不回写已入库量;
- MES → 金蝶只有一条单行道:**采购入库单「转ERP」并被金蝶审核**。这一步不做,金蝶的未执行数量一个都不会少。

所以「MES 剩余=0」只说明**这张订单行已经被 MES 内部的下游单据占满了**(不能再送),它**不等于**「货已入库」。

## 三、五个断裂点(按出现频次)

1. **生单 ≠ 入库**。MES 生单只产生送料暂收单,后面还要:暂收审核 → 来料检验 → 采购入库单 → 审核 → 转ERP → **金蝶审核**。
   任何一站没走完,金蝶就没有量。
   实证:`YJ-20260927-02` 8 行全部压在送料暂收单 `SL-2026-10-0072`(2026-09-27 已审核)上,
   之后**没有一张来料检验单、没有一张采购入库单**(MES 侧 0 张;金蝶侧该单的入库行全是 `PC0000`/空批号,
   不是 MES 推的)。
2. **金蝶侧有 MES 不知道的入库**。这些入库单的批次号是金蝶默认批号 `PC0000` 或空,
   而 MES 转ERP 一定带 MES 自己的批次号(`20261116`/`20261117`/`20261120`…):
   ```
   CGRK-20261115-03730 | YJ-20261023-05 seq=1 YJ-SX-005-1 6600 | batch=PC0000    ← 金蝶侧手工
   CGRK-20261105-03632 | YJ-20260927-02 seq=8 YJ-SX-029   2000 | batch=PC0000    ← 金蝶侧手工
   CGRK-20261117-03767 | YJ-20261112-10 seq=5 YJ-SX-005-1 5000 | batch=20261117  ← MES 批次,但 MES 该行已生单=0
   ```
   ⇒ 用户(或别人)直接在金蝶按订单下推/录入了采购入库单,或在 MES 里手工建采购入库单(带订单号但不走「生单」,
   不写 `form_flow_link`)⇒ **金蝶的未执行减少了,MES 的已生单没增加**,MES 剩余虚高。
   (同一现象 2026-11-11 已在 `tools/archive/_erp-closed-segment-20261111/README.md` 记录过。)
3. **超送把两边越拉越远**。MES 允许已生单 > 数量(实测 13000 → 15500、6000 → 7000),
   金蝶超收后 `未执行` 变**负数**,该行既不会「全部入库」也不会自动关闭 ⇒ 整单永远停在「部分入库」。
4. **金蝶的完成是整单判定**。`io_status` 只有**所有行**都全部入库才是 `C`;`bill_close_state` 也只有整单收完
   才自动 `S`。所以哪怕某一个物料收满了,只要这张单还有别的行没入库(或超收成负数),列表里就是「未完成」。
   —— 用户「都还没完成」的感受,主要来自这一条。
5. **金蝶回传的进度字段本身也在「停更」**(重要,决定了第 1 条建议能不能直接用)。
   `deploy/sync-core.mjs:949-953` 按**订单指纹**决定要不要重取详情,而采购订单指纹是
   `bill_status | bill_close_state | bill_date | supplier_name | supplier_number | emp_name | io_status | real_io_status | remark`
   —— **行级 `in_qty / un_out_qty` 不在指纹里**。整单一旦从「未入库 A」变成「部分入库 Z」,
   之后每一次收货都不再触发重拉 ⇒ `bl_pu_order.行已执行数量 / 行未执行数量` 会停在「该单最后一次重同步那一刻」。
   旁证(本机快照,只作参考:本地库 11-13 后已停更,无法证伪):`YJ-20261112-10` 在 MES 里 7 行全是
   「已执行 0 / 未执行 = 订单量」,而金蝶此刻是 行1 已入库 4200、行5 已入库 5000。
   ⇒ 这两列**放出来之前先把判据修好,否则是"看着有数、其实过期"**。

## 四、MES 其实已经握着金蝶的答案,只是「藏着 + 停更」

`bl_pu_order` 里已经有金蝶回传的四个行级字段(同步自动写入):

| 字段 | 金蝶键 | 面板状态(`yj_field`,PU_ORDER) |
|---|---|---|
| 行已执行数量 | `in_qty` | `visible=0, hidden=1`(detail, seq 960) |
| 行未执行数量 | `un_out_qty` | `visible=0, hidden=1` |
| 行入库状态 | `entry_realio_status` | `visible=0, hidden=1` |
| 行执行状态 / 行关闭状态 | `entry_ios_tatus` / `close_state` | `visible=0, hidden=1` |

⇒ 「金蝶未入库数量」这一列**数据已经在库**,只是被藏起来(且只更新到该单最后一次重同步那一刻,见 §三-5);
把它放出来 + 修掉停更,现场一眼就能看出两边差多少。

## 五、建议(按投入产出排序,均未实施)

1. **【先修数据源】** 把「行级执行量」纳入同步判据:采购订单 `fingerprintOf` 增加行级摘要
   (或对 `bill_close_state`/`io_status` 未关闭的单据每次全量重取详情)——
   否则第 2 条放出来的列是比金蝶晚几天的旧数,反而更容易误判。
2. **【最小改动,收益最大】** 采购订单明细放开/新增一列「金蝶未入库数量」(`行未执行数量`)+「行入库状态」,
   并在生单对话框里与「剩余」并排显示;「剩余」标签改为「已生单(未入库)」。
3. **转ERP 推前预检**:`KingdeePushService#resolvePoRefs()` 已在拉订单详情,顺带读 `close_state / in_qty / un_out_qty`,
   命中「分录已关闭」「超出未入库量」就直接给人话提示,而不是把金蝶原文(`不符合条件: 商品分录已关闭,不允许下推`)甩给用户。
   (2026-11-11 提过,仍未实施 —— 见 `_erp-closed-segment-20261111/README.md` 五)
4. **超送口径**:MES 允许超送,但转ERP 时按该行**金蝶未入库量**截断(或禁止超送行挂源单),
   避免在金蝶制造「负数未执行」的死行。
5. **补齐反向同步(治本)**:定时拉金蝶采购入库单(`/jdy/v2/scm/pur_inbound`)回写
   「订单行 × 已入库量」,于是无论谁在金蝶做的单,MES 都能看见;或至少做「订单完成度」双口径只读看板。

## 七、补充:2026-11-23 当天金蝶在「手工补录」这些单(15:00 复核)

用户随后发来金蝶《采购入库单》截图(单号 `CGRK-20261123-03826`,2026-11-23 14:25:06,制单人 蒋小刚,
**审核人/审核时间空白、页面停在编辑态**,三行 `YJ-SX-005-2` 各 3000 / 7000 / 5000,批号全 `PC0000`,
采购订单号分别是 `YJ-20261114-03` / `YJ-20261023-05` / `YJ-20260927-02`)。复核结果:

1. **这个单号在金蝶里不存在** —— `bill_no=CGRK-20261123-03826` 列表命中 0 条。
   同一天 14:25:07 实际落库的是 **`CGRK-20261121-03826`**(单据日期 2026-11-21、已审核 `C`)。
   金蝶单号 = `CGRK-{单据日期}-{流水}`,**改了单据日期单号就跟着变** —— 截图那张单在保存时把日期改成了 11-21。
2. 存下来的那张有 7 行(含 `YJ-20261111-06` 4 行),`YJ-SX-005-2` 只有 **2000**(挂在 `YJ-20261114-03` 行 2);
   截图里的 7000(`YJ-20261023-05`)和 5000(`YJ-20260927-02`)那两行**没有被保存**。
   所以这两张单此刻仍是 0 入库。
3. 当前行级状态(15:00 复核):

   | 单号 | 行 | 数量 | 已入库 | 未完成 |
   |---|---|---|---|---|
   | YJ-20261114-03 | 2 | 6000 | 5000 | 1000 |
   | YJ-20261023-05 | 2 | 7000 | 0 | 7000 |
   | YJ-20260927-02 | 7 | 5000 | 0 | 5000 |

4. ⚠️ **重复入库风险**:`YJ-20261114-03` 行 2 只剩 1000 未完成,截图那行还写 3000
   (那是 14:25 之前的口径,之后 03826 已经补了 2000)。照原样保存会多 2000 ⇒ 要么被金蝶按
   「超出订单行未入库量」拦下,要么进去变成超收 `−2000`、这行再也关不掉。**按 1000 录才对。**
5. 这三行批号都是金蝶默认 `PC0000`、制单人手工建单 ⇒ **MES 全程不知道这些收货**
   (MES 转ERP 会带自己的批次号,当天别的单是 `20261123`),MES 的「剩余」不会因此变化。
   这正是「两边未完成数量不同步」的根:一边在 MES 生单,一边在金蝶手工入库,谁都不通知对方。

## 八、可行性:「采购订单明细里直接显示金蝶未入库数量」要不要改流程?

**不要。数据早就在库里了,这是纯展示层开口子。** 2026-11-23 实测:

| 项 | 现状 | 结论 |
|---|---|---|
| 数据源 | `bl_pu_order` 已有 `行未执行数量`(金蝶 `un_out_qty`)、`行已执行数量`(`in_qty`)、`行入库状态`(`entry_realio_status`)、`行执行状态`、`行关闭状态` | 同步 `EXTRA_LINES` 自动写,**不用新增接口、不用改采购流程** |
| 字段注册 | `yj_field` PU_ORDER / detail:`行未执行数量` id=6494、`行已执行数量` 6487、`行入库状态` 6490、`行执行状态` 6491、`行关闭状态` 6488 —— **全部 `visible=0, hidden=1, seq=960`** | 只需 `visible=1, hidden=0` + 给个 seq/width |
| 译名 | `yj_translation` 已有 en:`Un Out Qty` / `Out Qty` / `Entry Realio Status`(manual) | 多语言不用补 |
| 列类型 | `nvarchar(1000)` | 能显示;要排序/合计最好转 decimal 或前端格式化 |
| 角色视图 | `yj_field_view` 只有 **`cksh`(仓库审核)** 存过 PU_ORDER 显式视图(101 行),其中这 5 个字段 `shown=false` | 全局打开后 `cksh` **仍看不见**;其余角色(含 admin,无显式行)跟随全局,立即可见 |
| 存量填充度 | 全库 **5289 行只有 610 行有值**(11.5%);2025 年 2078 行全空 | 直接放开会大片空白 ⇒ 需要回填一次 |
| 保鲜 | 见 §三-5(指纹不含行级数量,部分入库后停更) | 要让数字可信必须补这一条 |

⇒ 落地就三步,**都不碰业务流程**:

1. **放开显示**(元数据):`yj_field` 5 条 UPDATE(`visible=1, hidden=0, seq=…`)+
   `yj_field_view` 里 `cksh` 那 5 行改成 `shown=true`(或直接删掉让该角色跟随全局);
2. **回填存量**(数据):对采购订单跑一次强制刷新(`sync.mjs --refresh` / `init-sync.mjs`),
   把历史行的 `行未执行数量` 补上;只补近 N 天也行;
3. **保鲜**(同步判据,唯一动到代码的一处):`PU_ORDER.fingerprintOf` 增加行级摘要,
   或对 `bill_close_state` 未关闭的单据每次重取详情 —— 一行改动,不改任何业务流转。

建议先上 1+2(当天就能在明细里看到金蝶未入库),3 紧接着补;否则现场会把「停更的旧数」当准数。
复跑:`node _q-po-uninbound-feasibility-20261123.mjs`、`node _q-po-fieldview-20261123.mjs`。
