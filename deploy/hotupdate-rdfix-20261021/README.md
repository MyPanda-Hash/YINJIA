## 一、这个包修的是什么

**问题**：普通销售账号填写立项申请并提交审批 → 管理员点「审批通过并定级」（选等级）→ 之后侧栏
「定级分发」按钮**永久置灰**，对接人再也发不出去，流程卡死在第一步。

**原因**：审批通过时已把 `项目等级` 写进 `rd_approval`，而「定级分发」的门禁要求「等级必须为空」，
两个既有口径叠成死结；唯一能写 `备用1` 的旧按钮「分发对接人」已在 2026-10-19 下架。

**修复**：
1. 判定改为 `已审核/已归档 ∧ 对接人为空 ∧ 当前人是审批人`（不再要求等级为空）；
2. 等级已存在时**沿用库内等级**，只补写对接人；请求带不同等级仍被拒（改级只能弃审）；
3. 弹窗里等级单选置灰并提示「项目等级已由审批定级，不能在此修改；此处只需选择对接人」；
4. 留痕写「分发对接人(等级沿用 X)」。

**本机已验证**：`canGradeDispatch` false→true；`定级分发` 只传对接人即 200 并落库；重复分发/改级被拒；
UI 断言 4/4；前端测试 855/855。

（前提：服务器上 `C:\yinjia\update.bat` 存在、`C:\yinjia\update\` 目录可写）

**方式 B（手动两步）**：


脚本依次做：**先查包大小**（< 80 MB 直接判 `RESULT: FAILED - app.jar truncated`，绝不用被截断的包覆盖可用的）

`C:\yinjia\update.bat`（停 → 换 → 起）→ 等 40 秒探活 → 打印 `RESULT: OK` / `RESULT: FAILED`。
日志写在同目录 `apply-update-log.txt`（可直接在本机通过重定向盘读）。

`.bat` 用 `pushd` 起头，所以**直接在 `\\tsclient\C\...` 双击也能跑**（`cd /d` 在 UNC 路径上会失败）。

## 四、部署后怎么确认

1. `apply-update-log.txt` 末行是 `RESULT: OK`（`[health] http code = 200`）；
2. 服务器浏览器打开 http://127.0.0.1:8090 → 登录 → 研发管理 → 项目管理 → 立项申请：
   找一张**已归档、已定级、没分发对接人**的单，侧栏「1 定级分发·X级」应**可点**（白底黑字，不是灰的）；
3. 点开 → 弹窗里等级是灰的、下面「对接人」下拉可选 → 「定级并分发」→ 提示「已定级并分发对接人」，
   该对接人收到「您被指定为项目对接人」站内消息；
4. 之后「2 对接人签核」对**该对接人账号**开放（管理员也可代做）。
