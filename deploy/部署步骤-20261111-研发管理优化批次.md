## 2. 本批次要跑的数据库迁移（7 条）

> 🔴 **部署脚本不会自动跑迁移**（`deploy_src.py` 里 `DbSync` 出现次数 = 0）。
> 必须在换 jar **之前**手工执行，否则新代码查不存在的列会 500。

按顺序（均幂等，可重复执行）：

```
tools/migrate-sample-view-all-20261111.sql          # 样品单 view_all 权限
tools/migrate-sample-progress-desc-20261111.sql     # 样品单「进度描述」列
tools/migrate-insp-plan-revision-page-20261111.sql  # 出货检验「表区」列 + 修订记录字段
tools/migrate-prodinfo-approver-cells-20261111.sql  # 产品信息表三格只读
tools/migrate-mold-density-stdlib-20261111.sql      # 烧结「密度管控」标准库
tools/migrate-mold-recipe-design-unit-20261111.sql  # 配方表「设计添加量」单位
tools/migrate-rd-change-approval-sign-20261111.sql  # 产品变更申请表批准人/签字/日期
```

**两个账套都要跑**（先 `HSDZ_MES` 正式，再 `HSDZ_MES_TEST` 测试）：

```bash
cd <repo>/tools

# 正式库
java -cp lib/mssql-jdbc.jar SqlRunner.java \
  "jdbc:sqlserver://36.140.66.163:1433;databaseName=HSDZ_MES;encrypt=false;trustServerCertificate=true;loginTimeout=20" \
  yinjia '<口令>' migrate-XXX.sql

# 测试库
java -cp lib/mssql-jdbc.jar SqlRunner.java \
  "jdbc:sqlserver://36.140.66.163:1433;databaseName=HSDZ_MES_TEST;encrypt=false;trustServerCertificate=true;loginTimeout=20" \
  yinjia '<口令>' migrate-XXX.sql
```

**跑完必须补登记**（否则下次 `DbSync` 会当没跑过而重放）：

```sql
INSERT INTO yj_schema_log (script_name, content_hash, applied_at)
VALUES ('migrate-XXX.sql', 'MANUAL-20261111-<说明>', GETDATE());
```

> 硬规矩（用户 2026-11-06）：「不要把服务器上数据库的数据覆盖了，那些是真实使用的数据」。
> 7 条脚本全部是 `IF NOT EXISTS` / `COL_LENGTH IS NULL` 守卫 + 行数守卫 + 末尾自检，
> **没有** 无 WHERE 的 UPDATE/DELETE、没有 TRUNCATE/RESTORE。

## 3. 部署方法 A（推荐）· macOS WinRM 一键

前置：Python 环境已装 `pywinrm`（本机用 `~/Projects/MA/YINJIA-mac-环境包/.venv`）；
服务器 `administrator` 口令**走环境变量，不落盘**。

```bash
cd ~/Projects/MA/YINJIA-mac-环境包
export YJ_SERVER_PASS='<服务器 administrator 口令>'
export YJ_WINRM_TRANSPORT=basic        # 5985 明文，仅内网/临时

# ① 只读体检（不动任何东西）
.venv/bin/python scripts/deploy_src.py --check

# ② 正式部署：服务器自拉 GitHub 源码 → 本地构建 → 备份库 → 停 → 换 jar → 起 → 验证
.venv/bin/python scripts/deploy_src.py --ref 0234aa5da

# 只换 jar、不备份库不跑迁移（回滚或纯前端修复时用）
.venv/bin/python scripts/deploy_src.py --app-only --ref 0234aa5da
```

脚本内部 8 步：`0 环境体检 → 1 拉源码 → 2 服务器本地构建 → 3 备份数据库 → 4 停应用 →
5 归档旧 jar 并换新 → 6 启动并验证 → 7 验收`。

**为什么是"服务器自拉构建"**：服务器只开 3389/8090，22/445 都不通；WinRM 单条命令有长度上限，
推不了大包；但服务器能上 GitHub（实测 96MB tarball 11.6 秒）。所以 Mac 只管 `git push`。

⚠ 迁移不在脚本里，**§2 要单独先跑**。

## 4. 部署方法 B · RDP 内走 Windows 批处理

若能登录服务器桌面（`36.140.66.163:3389`，主机名 `ECS-38508784`）：

```
deploy\deploy-production.bat CHECK     # 只读体检
deploy\deploy-production.bat GO        # 增量：停应用 → 备份库 → 跑 to-run 迁移 → baseline → 裸 sync 复核 → 换 jar → 起 → 验收
deploy\deploy-production.bat GO APP    # 只换 jar
```

> 只认 `deploy-production.bat`。`deploy-all.bat`（全量整库还原）**不是默认路线**，
> `GO`/`GO DB` 必须带第三个参数 `CONFIRM-FULL-REPLACE`，否则脚本会停在
> `RESULT: FAIL-FULL-REPLACE-NOT-CONFIRMED` 并不动库。
> 这条路线的好处：迁移由脚本按 `to-run` 自动跑，不用手工执行 §2。

RDP 操作注意（历史实测）：
① 远程桌面中文输入法会吃掉敲进去的 ASCII 字母 ⇒ 长命令放剪贴板 Ctrl+V；
② `.ps1` 必须纯 ASCII（PS 5.1 按 ANSI 读无 BOM 的 UTF-8）；
③ 抢前台失败的按键会打到开发机自己窗口，先用 `GetForegroundWindow()` 复核句柄。

## 7. 回滚

```powershell
# 库：用部署时自动备份
RESTORE DATABASE [HSDZ_MES] FROM DISK = N'C:\yinjia\backup\pre-deploy-<时间戳>.bak'
  WITH REPLACE, RECOVERY

# jar：换回归档的旧 jar
schtasks /end /tn "YINJIA-MES"
Copy-Item 'C:\yinjia\backup\app-<时间戳>.jar' 'C:\yinjia\app.jar' -Force
schtasks /run /tn "YINJIA-MES"
```

> 迁移脚本**不做自动回滚**：它们是幂等增量（只加不删），回滚 jar 后旧代码不看新列，通常无需撤库。
> 若必须撤，按脚本里注释的"回滚段"逐条反向执行，并同步删 `yj_schema_log` 对应行。
