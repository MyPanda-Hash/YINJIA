# 金蝶采购订单「现存量」口径(2026-11-12 实测,真实账套 359797)

> 一句话:**有,但它是「这张单上存下来的库存快照」,不是现在的库存。**
> 想要"现在有多少"只能看 `inv_inventory_ims` 同步进 `kucun` 的数(见
> `docs/development/金蝶库存同步-以金蝶为准.md`),**不要**拿采购订单行上的「现存量」当库存用。

## 一、接口层面:字段确实存在

| 项 | 实测 |
|---|---|
| 接口 | `GET /jdy/v2/scm/pur_order_detail`(采购订单详情) |
| 商品分录键总数 | **103** 个 |
| 相关键 | `inv_qty`(库存数量)、`inv_base_qty`(基本库存数量) |
| 列表接口 | `/jdy/v2/scm/pur_order` 列表行只有 18 键、`material_entity` 为空 ⇒ **列表拿不到**,只有详情才给 |
| `inv_base_qty` | 采样 67 行**恒为 0**,不可用 |
| 「现存量说明」 | 接口无实时值(同步映射里硬编码 null,见 `deploy/金蝶档案字段同步对照.md` §二) |

官方字段表登记:`deploy/面板字段对照.md` §三 `MaterialEntity` → `inv_qty | number | 库存数量`。

## 二、数据层面:真实账套里是有值的

- 2026-11-12 抽 20 张已审核采购订单 / 67 行:带 `inv_qty` 键 **67/67**,空值 **0**,0 值 23,正值 44,负值 0。
- MES 已同步全量 `bl_pu_order`:**5030 行,空值 0**(0 值 1677、正 3335、负 18)。
  ⇒ 不是"字段空着没人填",金蝶确实把下单时的库存带到了单上。

## 三、关键结论:是「制单快照」,不是实时现存量

同一物料 `YJ-XH-001` 的 **49 张**采购订单(2025-04 ~ 2026-11,跨 19 个月),在**同一次运行、同一时刻**逐张取详情:

| 单据日期 | 单据编号 | 数量 | MES 库内现存量 | 金蝶现在返回 |
|---|---|---|---|---|
| 2025-05-06 | YJ-20250506-03 | 3000 | 6000 | 6000 |
| 2026-01-02 | YJ-20260102-03 | 3000 | 4000 | 4000 |
| 2026-06-05 | YJ-20260605-01 | 6000 | 700 | 700 |
| 2026-10-05 | YJ-20261005-01 | 5000 | 25 | 25 |
| 2026-11-05 | YJ-20261105-06 | 90000 | 2525 | 2525 |

- 49 张单 → **49 个互不相同的值**(0 / 6000 / 8000 / 10120 / 2495.5 / 14000 …),而"实时库存"对同一物料只可能是一个数 ⇒ **排除"读取时现算"**;
- 49 张单的金蝶返回值与 MES 库内已同步值 **49/49 逐一相同**(MES 是几个月里分批同步进去的)⇒ 值在单据上**冻结**,不随后续出入库变化;
- 同一天的两张单(如 2025-07-28 的 `YJ-20250728-12` / `YJ-20250728-01`)值相同 ⇒ 与"按单据日期取结存"也吻合,但无论按哪种解释,**都不是今天的库存**;
- 与今天的真实库存对比:`YJ-XH-001` 当前 `kucun` 合计 **2025**,而 11-05 的单上写着 2525 ⇒ 差 500,照抄会被当成"现在有 2525"。

**口径**:行上 `仓库` 为空(5030 行里 4980 行为空;有值的 50 行全是 2025-04 老单且值为 0)⇒ 这个数是**全仓合计**,不分仓库、不分批次。

## 四、MES 侧怎么用

- 面板 `PU_ORDER` 明细列表有一列「现存量」(`place=detail`,`visible=1`,`hidden=0`,`seq=130`),没有「现存量说明」;
  同步映射 `deploy/sync-core.mjs` 的 `PU_ORDER.mapLines` 写 `现存量: num(m.inv_qty)`。
- 该列只代表**这张采购订单在金蝶保存那一刻**的库存,业务上只适合做"当时库存参考",**不可用于可用量判断、缺料判断、库存对账**。
- 要"现在的库存":`kucun.yl`(金蝶 `inv_inventory_ims` 现存量,每 5 分钟覆盖一轮);
  要"按仓库/批次":`kucun` 的 `(物料,仓库,批号)` 三键;库存状况表 `v_stock_balance` 仍是流水口径,也不是现存量。

## 六、MES 侧全流程贯通(2026-11-12 实施)

用户口径:「采购订单的现存量字段,MES 里有没有记录?如果有,需要让这个字段从 采购订单 → 送料暂收单 →
采购入库 全流程都有这个信息(中间可能有检验、退料、特采);可以隐藏这个字段,但要保留字段全流程存在。」

### 6.1 落点(每站都是 `现存量` 一列,除特采单外都在**明细行**;特采单一物料一单,只在**表头**)

| 站 | 面板 / 表 | 列 | 面板字段 | 值来源 |
|---|---|---|---|---|
| 采购订单 | `PU_ORDER` / `bl_pu_order` | `现存量`(+`现存量说明`) | 表格可见(seq 130) | 金蝶 `pur_order_detail.inv_qty`(制单快照) |
| 送料暂收单 | `QC_RECV` / `sl_recv_detail` | `现存量` | **表格可见**(2026-11-12 取消隐藏,seq 360,只读) | 选单映射 `现存量→现存量`(采购订单行) |
| 来料检验单 | `QC_INSP` / `qc_insp_detail` | `现存量`(2026-11-12 新增) | **隐藏**(seq 265) | 同名字段映射 + 暂收保存镜像 `ButtonService.syncInspFromSlRecv` |
| 暂收退回单 | `QC_RETURN` / `qc_return_detail` | `现存量`(2026-11-12 新增) | **隐藏**(seq 105) | 选单映射 / 检验审核自动生单 `inspAutoReturn` |
| 特采单 | `QC_TC_IN` / `qc_tc_in`(**表头**) | `现存量`(2026-11-12 新增) | **隐藏**(seq 66) | 退料单审核生特采 `returnAutoSpecialAccept`(取退料行) |
| 采购入库单 | `PURCHASE_IN` / `bl_purchase_in` | `现存量`(+`现存量说明`) | 表格可见(seq 170) | 选单映射 / `inspAutoPurchaseIn` / `tcInApprovedGenerate` |

迁移脚本:`tools/migrate-po-stock-fullchain-20261112.sql`(加列 + 字段登记 + 译名 + 存量回填,两账套已执行)。

### 6.2 映射为什么要显式登记一条同义词

`PanelConfigService` 的行映射是「同名优先,按来源 `seq` 先到先得、**上限 14 条**」。
暂收行的「现存量」seq 360 排在最后,同名映射必被挤掉(实测加字段前 `QC_INSP` 侧 detailMap 里根本没有它),
故在 `FLOW_DETAIL_SYNONYMS` 里加了一条 `{"现存量","现存量"}`(同义词循环不占那 14 条名额)——
一处登记,四单所有含该字段的链路(采购订单→暂收、暂收→检验、检验→退回、检验→入库、暂收→入库)同时生效。

### 6.3 端到端取证(测试账套 `HSDZ_MES_TEST`,探针见 `tools/archive/_po-stock-fullchain-20261112/`)

| 链路 | 造数 | 结果 |
|---|---|---|
| 暂收 → 入库(免检直达) | `SL-2026-09-0021` 审核后生单 | `PI-2026-11-0002` 行 `现存量` = 暂收行值(3500)✅ |
| 暂收 → 检验 | 暂收行置 6666 后生单 | `IJ-2026-11-0001` 行 `现存量` = 6666 ✅ |
| 检验 → 入库 / 退回(审核自动) | 检验行置 8888、不合格 5 | `PI-2026-11-0003` = 8888 ✅ ;`TH-2026-11-0001` = 8888 ✅ |
| 退回 → 特采单 | 退料行勾「特采」后审核 | `TCI-2026-11-0001` 表头 = 8888 ✅ |
| 特采单 → 入库(两级审批后) | 提交审批→审批通过→再审批通过 | `PI-2026-11-0004` 行 = 8888 ✅ |

### 6.4 存量回填(历史单)

脚本按「采购订单号 + 采购订单行号」把历史值补进各站(只填 NULL,不覆盖有值):
正式库 暂收 71→7 空、检验 25 行全满、退回 27 行全满、特采 25 行中 7 行有值(其余因历史链单号缺失无源可填)、
入库 113→105 空(无来源单号的历史入库单留空)。

### 6.5 使用红线

**这一列是采购订单制单那一刻的库存快照,不是实时库存。** 不得用于可用量、缺料、库存对账;
实时库存 = `kucun.yl`(金蝶 `inv_inventory_ims`,每 5 分钟覆盖)。四单字段口径登记见
`docs/development/采购链四单字段与显示字段.md`(2026-11-12 已重跑生成器,§四 12/12 ✅)。
