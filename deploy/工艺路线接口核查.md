# 工艺路线(ROUTE / bs_route)金蝶接口核查

> 核查日期:2026-10-04 | 触发:用户质疑「工艺路线不是从金蝶拉的吧,金蝶是表头+明细」
> 结论:**现状确实不是从金蝶同步的(是本地演示种子);且金蝶云·星辰开放接口里没有「工艺路线/工序」接口** —— 因此「按金蝶接口字段重构并全量拉取」目前无接口可依,需人工定口径。

## 二、金蝶侧可用接口核查(三路证据,均无「工艺路线/工序」)

1. **官方文档目录全量检索**:open.jdy.com 文档目录共 **1228 篇**全量拉取后逐篇抓正文匹配「工艺路线/工序」——
   命中的 12 篇**全部是金蝶KIS云(koas)文档**(见下第 3 条),星辰(jdy/v2)侧命中 **0 篇**。
   探针:`tools/archive/_jdy-doccatalog-all.mjs`(目录)、`tools/archive/_jdy-doccrawl.mjs`(正文),
   产物 `_jdy-doc-catalog.json`、`_jdy-doc-hits.json`。
2. **真实账套路径穷举**:对正式账套(clientId 359797)**66 条**候选路径
   `/jdy/v2/{pm,bd}/{process_route,route,routing,process,procedure,operation,craft,craft_route,
   work_procedure,work_center,workcenter,machine,equipment,team,shift,…}` 全部 **HTTP 519**(= 无此接口,
   与当年 `material_out` 判定同口径,见 `tools/migrate-material-out-erp.sql` 注释)。
   探针:`tools/archive/_route-probe-kd.mjs`、`_route-probe-kd3.mjs`。
3. **在册对象清单**:官方《基础资料及单据类型》**基础资料 18 类 + 单据 40 类 + 系统 1 类里没有工艺路线/工序;
   生产侧只有 `mo_taskbill`(生产任务单)/`subm_workorder`(委外加工单)/`inv_pick`(生产领料单)等,
   其响应字段里与车间/工序相关的只有 `dept_id/dept_name/dept_number`(生产车间),**无工序、无工艺路线**。
   探针:`tools/archive/_jdy-basetypes-probe.mjs`、`_jdy-doc-scan-probe.mjs`。
4. 正式账套生产类接口实测数据量:**mo_taskbill / subm_workorder / mat_issue_order / subm_prodin / bd/bom
   / sys/custom_field 全部 count = 0**(该账套未启用生产模块),`bd/aux_info` 181 条。
   探针:`tools/archive/_route-probe-kd2.mjs`。

## 二补、对照:星辰**有** BOM 接口,而且正是「表头+明细」

| 项 | 实测 |
|---|---|
| 接口 | `GET https://api.kingdee.com/jdy/v2/bd/bom`(《BOM单列表》,官方文档 id `9c2c4958712511eda0b361e90d734914`,已在 `deploy/doc-endpoints.json` 在册) |
| 形态 | **表头 Row + `material_entity` 子料分录** —— 与用户描述的「表头+明细」一致 |
| 表头字段 | `number` 编号、`product_id/name/number` 产品、`product_unit_*` 产品单位、`product_baseunit_*` 基本单位、`product_aux1..5_*` / `product_auxprop_*` 辅助属性、`version` 版本号、`yield` 成品率%、`bom_remark` BOM备注、`isskip` 跳过该层级直接领用下级物料、`status` Z未审核/C已审核、`enable`、`billsource`、`audit_time/auditor_*`、`creator_*/modifier_*/create_time/modify_time`、`id` |
| 明细字段 | `seq` 分录行号、`material_id/number/name` 子料、`material_baseunit_id` 基本单位、`dosage_numerator` 材料用量、`dosage_denominator` 产品产量、`unitqty` 单位用量、`scrap` 损耗率%、`fixed_loss` 固定损耗、`issue_pattern` 发料方式(D直接领料/A倒冲/B不领料)、`iskeypieces` 关键件、`isrepitem` 替代件、`machinepos` **工位**、`stock_*`/`sp_*` 发料仓库与仓位、`material_remark`/`custom_txt1..3`、`custom_entity_field` 自定义字段、`aux1..5_id` |
| 账套数据量 | **0 条**(实测 `count=0`)—— 接口通但该账套没建过 BOM,拉下来是空的 |
| 详情接口 | **不存在**:`/jdy/v2/bd/bom_detail` → HTTP 400、`/jdy/v2/bd/bom_list` → HTTP 519;列表接口自带子料分录 |

⚠️ **BOM ≠ 工艺路线**,别混:①BOM 回答「产品由哪些料、用多少构成」,工艺路线回答「依次经过哪些工序」;
②星辰的生产任务单(列表 59 键 / 详情 278 键)与委外加工单(186 键)里,**只有 `dept_id/name/number`(生产车间)
和 `bom_id/bom_number`,没有任何工序/工艺路线字段**;③金蝶侧唯一把两者挂钩的是 **KIS 云**的模拟BOM
`Head.FRoutingID`(工艺路线**内码**引用)—— 只有内码,没有路线明细可拉。

### MES 侧现状(顺带查明)

| 面板 | 表 | 形态 | 是否接金蝶 |
|---|---|---|---|
| `BOM` 物料清单 | `bs_bom` | `head_table=null` 单表平铺 | ❌ 未接(`DOCS` 无 BOM 类型) |
| `WLBOM` 物料清单 | `mate` | 单表平铺 | ❌ 未接 |
| `RD_ASM_BOM` 组装BOM表 | `rd_asm_bom_head` + `rd_asm_bom_detail` | **表头+明细** | ❌ 未接(研发自建) |
| `ROUTE` 工艺路线 | `bs_route` | 单表平铺 | ❌ 未接 |
| `OP` 工序 / `TEAM` 班组 / `EQUIP` 设备 | `bs_op`/`bs_team`/`bs_equip` | 单表平铺 | ❌ 未接(25/20/24 行,均为种子) |

⇒ 若目标是「让某个面板像商品那样从金蝶全量拉取」,**BOM 是当前唯一有接口、且天然表头+明细的候选**;
工艺路线/工序/班组/设备在星辰侧无接口,只能 MES 本地维护。

## 三、结论与待定

- **能确定的**:①现状非金蝶来源(演示种子);②面板是单表平铺、非表头+明细;③星辰开放接口无工艺路线/工序,
  「与金蝶接口字段一致 + 像商品那样全量拉取」**当前无接口可依**。
- **不能确定的**:用户所指「金蝶真实账套是表头+明细」的字段清单 —— 若来自金蝶**界面**(星辰旗舰版/KIS 的
  生产管理·工艺路线表单),需要按该表单口径人工定字段;若来自某个我们尚未接入的接口(如星空 WebAPI、
  客户自建中间层),需给出接口文档/路径与账套。
- **未动任何代码/数据**:本轮只做取证,`bs_route` 数据、`ROUTE` 面板字段、同步脚本均保持原样。
