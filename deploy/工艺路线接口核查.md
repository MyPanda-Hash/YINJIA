### 「根据产品查询BOM」/`POST /jdy/v2/pm/bom` 到底是什么(字段口径)

它是**「产品 → 有哪些 BOM 单」的索引接口**,不是 BOM 明细接口:

- **请求**:POST,body `{ material_ids: [ { material_id: 产品ID, aux_prop_id: 辅助属性ID(辅助属性商品必录) } ] }`
  —— 可传多个产品,一次批量问"这几个产品各自挂了哪些 BOM"。
- **响应**:`data = { material_id, aux_prop_id, bom_list: [ { id, name } ] }`,每项只有 `id`(BOM 单内码)与
  `name`(BOM 单编号)。⚠ 官方文档把这两列说明写成"BOM集合 / BOM单编号",表述含糊,但响应示例
  `{"bom_list":[{"id":"10","name":"10"}]}` 表明就是「内码 + 编号」。
- **不含明细**:要 BOM 的表头与子料分录,须拿这里的 `id`/`name` 再调
  **`GET /jdy/v2/bd/bom_detail`(`id` 与 `number` 二选一)**。
- **与基础资料那个是同一件事的两个入口**:

  | | 生产管理版 | 基础资料版 |
  |---|---|---|
  | 接口 | `POST /jdy/v2/pm/bom`「根据产品查询BOM」 | `GET /jdy/v2/bd/bom_query`「产品查询BOM」 |
  | 入参 | `material_ids`(批量,可带辅助属性) | `material_id`(必填)+`aux_prop_id`/`page`/`page_size`/`search` |
  | 出参 | `data.bom_list[{id,name}]` | `data.rows[{id,number}]`(分页) |
  | 本账套 | ❌ `errcode=5001 API not found` | ✅ 可用 |

⇒ 两者都只回答"该产品有没有 BOM、编号是什么"。**它们返回 0 条,与 `bd/bom` 列表 0 条互为印证**——
账套里是真没有 BOM 单,而不是"明细读不到"。反过来:只要 `bd/bom_query` 对某个产品返回了编号,
`bd/bom_detail?number=` 就一定能取到明细 —— 这就是终局判定手段。
探针:`tools/archive/_bom-pm-fields.mjs`(拉两个接口的完整字段与响应示例)。

| `GET /jdy/v2/bd/bom`(BOM单列表) | ✅ 接口通,**count=0** | 账套的星辰 BOM单 表是空的(MES「BOM单」面板同步自它,故也是 0 行) |
| `POST /jdy/v2/pm/bom` | ❌ `errcode=5001 API not found` | 生产管理版索引接口在本应用不存在 |
| 34 条工艺路线候选路径(`pm|bd` × routing/process_routing/technics/craft/procedure/operation/work_center/team/equipment… ) | ❌ 全 **HTTP 519**(仅 `pm/mo_taskbill` 存在且 0 条) | 星辰开放接口**没有工艺路线/工序** |
| 生态应用口子 `/koas/app007099|007140|007155|007720/api/*`、`/jdy/v2/apps|sys/apps|sys/modules` | ❌ 全 519 | 本授权下**看不到任何生态应用的接口面** |
| 用 `GYLX-0006`/`GYLX-0022`/`GX-0001` 去 `bd/material`、`bd/aux_info`、`bd/bom` search | 全 0 条 | 编号不在星辰任何基础资料里 |

### 结论:数据在**生态应用**里,不在星辰原生模块

截图左上是 **「轻智造云」= 云蝶轻智造**(金蝶应用市场上架的生态应用/数字工厂 ERP,含轻MES;
市场页 <https://appmarket.kingdee.com/index/productDetail/776069307670073344>)。两条旁证:

1. **字段口径不是星辰原生**:星辰 BOM 只有 `version/yield/bom_remark/isskip/…`;
   界面却有 BOM类型/原配置BOM/默认BOM/审批进度/质量管控点/特殊配方及工艺/工艺路线。
   工艺路线侧 工艺类型=通用工序集/工序组/班组/操作工/计件依据/关键工序/标准合格率% 同理。
2. **同产品的星辰 BOM 查询为 0**,而界面明摆着有 BOM单 ⇒ 该 BOM单 存在**该应用自己的库**里,
   星辰开放接口(jdy/v2)不暴露。

⇒ **「能不能像商品那样全量拉取」的答案:现在不能。** 要能拉,三条路:

| 路 | 做法 | 前置条件 | 覆盖 |
|---|---|---|---|
| A | 走**该应用方的接口/中间库**(像商品那样做全量+增量同步) | 云蝶轻智造 提供 API 文档 + 授权(其 appId/密钥,或只读中间库账号) | BOM ✅ 工艺路线 ✅ |
| B | 把 BOM 维护到**星辰原生 BOM单** | 金蝶侧改维护位置;我方通道已就绪(`sync-core.mjs` 的 `BD_BOM` + MES「BOM单」面板 45 字段) | 只 BOM;工艺路线星辰原生没有 |
| C | 界面**导出 Excel → MES 导入** | 无(最快);工艺路线若要对齐界面的"表头+明细",需先把 ROUTE 从平铺改成两层 | BOM ✅ 工艺路线 ✅(批量) |

探针:`tools/archive/_q-bom-route-live.mjs`(产品→BOM→明细 全链路 + 编号穷举)、
`_q-route-sweep2.mjs`(34 条路径二次穷举 + 生态应用口子)。**本轮只读,未改任何数据。**
