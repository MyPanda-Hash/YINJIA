# 工艺路线(ROUTE / bs_route)金蝶接口核查

> 核查日期:2026-10-04 | 触发:用户质疑「工艺路线不是从金蝶拉的吧,金蝶是表头+明细」
> 结论:**现状确实不是从金蝶同步的(是本地演示种子);且金蝶云·星辰开放接口里没有「工艺路线/工序」接口** —— 因此「按金蝶接口字段重构并全量拉取」目前无接口可依,需人工定口径。

## 一、现状取证(MES 侧)

| 项 | 实测 | 证据 |
|---|---|---|
| 面板 | `yj_panel.panel_code='ROUTE'`:`mode=archive`、`head_table=NULL`、`line_table='bs_route'`、`pk_col=id`、`detail_key=route` | `tools/archive/_route-probe2.sql` |
| 字段 | `yj_field` 共 **17** 个,**全部 `place=detail`**,表头字段(工艺路线编码/名称/停用)与工序行字段(加工顺序/工序编码/工序名称/加工方式/生产车间/工资类型/计件依据/委外供应商/按辅单位计价/辅单位/换算率/默认报工数量/关键工序/标准合格率%)同处一表 | 同上 |
| 数据 | `bs_route` **45 列 / 40 行 / 3 条路线**(GY-001/002/003),`asp_user1='migration'` —— 全部由 `tools/_bs_part3_data.sql` 种入 | `tools/archive/_route-probe1.sql` |
| 同步 | `deploy/sync-core.mjs` 的 `DOCS` 注册表 = 12 类档案(BD_SETTLE/CUSGRP/SUPGRP/MATGRP/CUR/UOM/DEPT/EMP/STORE/MATERIAL/CUSTOMER/SUPPLIER)+ 2 类订单(SO_ORDER/PU_ORDER),**无 ROUTE**;`deploy/kingdee-extra-fields.mjs` 亦无 | `grep -n "ROUTE\|bs_route" deploy/*.mjs` → 0 命中 |

⇒ **一条路线 = 若干行,每行重复一遍表头字段**;这就是「平表当两层用」,与金蝶的主表+子表形式不同 —— 用户判断成立。

## 二、金蝶侧可用接口核查(三路证据,均无「工艺路线/工序」)

1. **官方文档目录全量检索**:open.jdy.com 文档目录共 **1228 篇**全量拉取后逐篇抓正文匹配「工艺路线/工序」——
   命中的 12 篇**全部是金蝶KIS云(koas)文档**(见下第 3 条),星辰(jdy/v2)侧命中 **0 篇**。
   探针:`tools/archive/_jdy-doccatalog-all.mjs`(目录)、`tools/archive/_jdy-doccrawl.mjs`(正文),
   产物 `_jdy-doc-catalog.json`、`_jdy-doc-hits.json`。
2. **真实账套路径穷举**:对正式账套(clientId 359797)**66 条**候选路径
   `/jdy/v2/{pm,bd}/{process_route,route,routing,process,procedure,operation,craft,craft_route,
   work_procedure,work_center,workcenter,machine,equipment,team,shift,…}` 全部 **HTTP 519**(= 无此接口,
   与当年 `material_out` 判定同口径,见 `tools/migrate-material-out-erp.sql` 注释)。
   探针:`tools/archive/_route-probe-kd.mjs`、`_route-probe-kd3.mjs`。
3. **在册对象清单**:官方《基础资料及单据类型》**基础资料 18 类 + 单据 40 类 + 系统 1 类里没有工艺路线/工序;
   生产侧只有 `mo_taskbill`(生产任务单)/`subm_workorder`(委外加工单)/`inv_pick`(生产领料单)等,
   其响应字段里与车间/工序相关的只有 `dept_id/dept_name/dept_number`(生产车间),**无工序、无工艺路线**。
   探针:`tools/archive/_jdy-basetypes-probe.mjs`、`_jdy-doc-scan-probe.mjs`。
4. 正式账套生产类接口实测数据量:**mo_taskbill / subm_workorder / mat_issue_order / subm_prodin / bd/bom
   / sys/custom_field 全部 count = 0**(该账套未启用生产模块),`bd/aux_info` 181 条。
   探针:`tools/archive/_route-probe-kd2.mjs`。

### 金蝶侧确实「有工艺路线概念」的地方(仅作参考,均非可拉取的主数据接口)

| 产品家族 | 接口 | 出现的工艺路线/工序字段 | 说明 |
|---|---|---|---|
| 金蝶KIS云(koas) | `/koas/app007099/api/simulatedbom/{list,getdetail,create,update}` | `Head.FRoutingID` = **工艺路线**(内码) | 只给内码,无工艺路线明细接口 |
| 金蝶KIS云 | `/koas/app007104/api/pickinglist/*` | `Head.FWBINTERID` 工序计划单内码;`Entry.FOperSN` 工序号;`Entry.FOperID` 工序 | 同上,引用而非主数据 |
| 金蝶KIS云 | `/koas/app007140/api/qualitycheck/*` | `Entry.FProcedureCode` 工序代码;`ProcedurePlanNo` 工序计划单号 | 同上 |
| 金蝶KIS云底表清单 | 29 个已发布接口域(APP002112/006992/007020/007099/007104/007140/007155/007455/007720/SVC200000) | **无「工艺路线」主数据 List/GetDetail** | `_koas-endpoints.json`(295 篇 KIS 文档) |

⇒ 即便转去 KIS 家族,也只能拿到 `FRoutingID` 这类**内码**,拿不到工艺路线的编号/名称/工序明细。

## 三、结论与待定

- **能确定的**:①现状非金蝶来源(演示种子);②面板是单表平铺、非表头+明细;③星辰开放接口无工艺路线/工序,
  「与金蝶接口字段一致 + 像商品那样全量拉取」**当前无接口可依**。
- **不能确定的**:用户所指「金蝶真实账套是表头+明细」的字段清单 —— 若来自金蝶**界面**(星辰旗舰版/KIS 的
  生产管理·工艺路线表单),需要按该表单口径人工定字段;若来自某个我们尚未接入的接口(如星空 WebAPI、
  客户自建中间层),需给出接口文档/路径与账套。
- **未动任何代码/数据**:本轮只做取证,`bs_route` 数据、`ROUTE` 面板字段、同步脚本均保持原样。
