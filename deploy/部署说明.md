## 一、首次部署(从零到上线,已完成,仅存档)

### 1. 传输部署包
RDP 远程桌面里直接复制粘贴 zip 到服务器,解压到 `C:\yinjia\`。

### 2. 安装 SQL Server
SQL Server 2019/2022 Express「基本」安装 + SSMS。

### 3. 恢复数据库(自动探测数据目录版)
SSMS 连 localhost(Windows 身份验证),整段执行:

```sql
USE master;
GO
IF DB_ID(N'HSDZ_MES') IS NOT NULL
    EXEC(N'ALTER DATABASE [HSDZ_MES] SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE [HSDZ_MES];');
GO
DECLARE @data NVARCHAR(400) = CAST(SERVERPROPERTY('InstanceDefaultDataPath') AS NVARCHAR(400));
DECLARE @sql NVARCHAR(MAX) = N'RESTORE DATABASE [HSDZ_MES] FROM DISK = N''C:\yinjia\HSDZ_MES.bak'' WITH RECOVERY, '
    + N'MOVE N''ASPSMT''     TO ''' + @data + N'HSDZ_MES.mdf'', '
    + N'MOVE N''ASPSMT_log'' TO ''' + @data + N'HSDZ_MES_log.ldf''';
PRINT N'使用数据目录: ' + @data;
EXEC(@sql);
GO
IF NOT EXISTS (SELECT 1 FROM sys.sql_logins WHERE name = N'yinjia')
    CREATE LOGIN [yinjia] WITH PASSWORD = N'Yinjia@2026', CHECK_POLICY = OFF;
USE [HSDZ_MES];
ALTER USER [yinjia] WITH LOGIN = [yinjia];
EXEC sp_addrolemember N'db_datareader', N'yinjia';
EXEC sp_addrolemember N'db_datawriter', N'yinjia';
EXEC sp_addrolemember N'db_ddladmin',  N'yinjia';
```

> **踩坑**:恢复前必须 `USE master`;MOVE 路径用 SERVERPROPERTY 自动探测,不要手写 MSSQL15/MSSQL16。

### 4. 安装 Java 21
Temurin 21 MSI,默认勾选 Add to PATH。

### 5. 生成启动脚本(PowerShell,防编码坑)
> **踩坑**:bat 含中文注释必须 GBK/ANSI 编码,UTF-8 的 bat 在中文 cmd 里必炸。以下生成纯 ASCII 脚本:

```powershell
@'
@echo off
cd /d "%~dp0"
title YINJIA-MES backend :8090
java -jar app.jar
echo.
echo [EXITED] backend stopped - check errors above
pause
'@ | Set-Content C:\yinjia\start.bat -Encoding ASCII

@'
@echo off
cd /d "%~dp0"
:loop
java -jar app.jar
echo [%date% %time%] exited, restart in 5s...
timeout /t 5 /nobreak >nul
goto loop
'@ | Set-Content C:\yinjia\start-service.bat -Encoding ASCII
```

### 6. 放行外网(两道闸)
```powershell
# ① Windows 防火墙(管理员 PowerShell)
New-NetFirewallRule -DisplayName "YINJIA-MES 8090" -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow -Profile Any
# ② 移动云安全组(控制台→安全组→入方向):TCP 8090 / 0.0.0.0/0
```

### 7. 上线加固
1. 改 admin 密码(默认 123456)
2. 换 JWT 密钥:`start.bat` 里取消注释并填 64 位随机十六进制串,本机生成:
   ```powershell
   -join ((1..32) | ForEach-Object { '{0:x2}' -f (Get-Random -Maximum 256) })
   # 校验:输出为 64 位、匹配 ^[0-9a-f]{64}$
   ```
3. 开机自启:`schtasks /Create /TN "YINJIA-MES" /TR "C:\yinjia\start-service.bat" /SC ONSTART /RU SYSTEM /RL HIGHEST /F`

## 二、数据库与代码同版本发布(含 DDL/数据变更) ★ 最易踩坑 ★

> **硬纪律(2026-09-08 定,不可绕过):热更新换包永不碰数据库;凡是版本含表结构/元数据/数据变更,
> 必须先迁库、再换包,两条流程严格分离。**
>
> 为什么必须成对:新 `app.jar` 的代码会读写新表/新列。服务器库落后一步 → 启动时 SQL 报错
> (`无效的列名` / `对象名无效`)或面板直接 500。**先迁库、后换包,顺序不能反。**

### 先判断走哪条路

| 走法 | 适用 | 代价 |
|---|---|---|
| **A. 全量恢复备份**(实测路径) | 服务器数据可被本机覆盖(一次上线/演示/重装) | 覆盖服务器库 = 丢掉服务器上新产生的数据 |
| **B. 增量迁移脚本**(最小改库) | 服务器已在生产、有真实业务数据 | 需逐条核对脚本、幂等性 |

### A. 全量恢复(已实测走通的流程)

```
本地开发机                                服务器(RDP)
━━━━━━━━━━                                ━━━━━━━━━━
① 出一份最新全量备份
   sqlcmd -S localhost -d HSDZ_MES -E -Q
     "BACKUP DATABASE [HSDZ_MES] TO DISK=
      'C:\INCER\YINJIA-MES\deploy\HSDZ_MES.bak'
      WITH FORMAT, INIT, STATS=10"
   → deploy\HSDZ_MES.bak(约 54 MB)          ② 粘贴 HSDZ_MES.bak 到 C:\yinjia\
                                            ③ SSMS 连 localhost(Windows 身份验证)
                                               跑「一、3」那段自动探测版 RESTORE
                                               (含 DROP 残留 + 建 yinjia 登录 + 授权)
                                            ④ 服务器浏览器 http://localhost:8090
                                               admin 登录 → 抽查一个面板确认数据在
                                            ⑤ 再走「三、热更新」换 app.jar
                                            ⑥ 本机实测 http://36.140.66.163:8090 复核
```

### B. 增量迁移(服务器数据不能动时用这条)

> ℹ️ **现状提示(2026-09-10 实测)**:开发库 `HSDZ_MES` 里**没有 `yj_schema_log` 表**——
> 说明历史迁移全是 `sqlcmd` 手工执行、**从未记录过**。所以**第一次**在开发库或服务器跑
> `DbSync`/全量初始化时,清单里 116 条脚本会被**当新脚本全部执行一遍**(脚本幂等,理论安全)。
> 若不想让它们重跑(库就是当前版本),先按下面第 4 步跑 `baseline` 把它们只标记为已执行。

1. 本机生成/确认本次涉及的迁移脚本(都在 `tools/`,如 `migrate-phase23-forms.sql`);
2. **登记清单**:确认脚本已写进 `tools/db-migrations.txt`(该文件是"唯一权威顺序",
   `DbSync.java` 增量同步与 `DbInit.java` 全量初始化都只认它);
3. 两个执行口径,任选:
   - **服务器上有仓库副本** → 在服务器跑 `tools\pull-sync.bat`:`git pull` + `DbSync` 按清单
     **只执行新增/内容有变化的脚本**(幂等,可重复);
   - **服务器上没有仓库** → SSMS 手工执行:把脚本内容贴进查询窗口,或
     `sqlcmd -f 65001 -S localhost -d HSDZ_MES -E -i "C:\yinjia\tools\migrate-xxx.sql"`
     (`-f 65001` 必须加,否则中文乱码);
4. **已在服务器手工跑过、不想被清单重跑** → 在服务器 `tools\` 目录下用基线模式,把清单里
   尚未记录的脚本**只标记为已执行、不动数据**:
   ```powershell
   cd C:\yinjia\tools     # 必须在此目录执行:DbSync 按"当前目录"解析 db-migrations.txt
   java -cp <mssql-jdbc.jar> DbSync.java baseline
   ```
   DbSync 三个模式:`(默认)` 增量同步 · `baseline` 仅标记 · `run <脚本名>` 无视记录强制执行;
   执行的脚本名 + 内容 SHA-256 记在 `yj_schema_log`,内容一变就会重跑(故脚本必须幂等)。
5. 验证 → 再换 jar(同 A 的 ⑤⑥)。

### 收尾硬规矩

```sql
-- 重大变更前先备份(服务器本地):
BACKUP DATABASE [HSDZ_MES] TO DISK = N'C:\yinjia\backup\pre-update.bak' WITH FORMAT, INIT;
```

> 🔴 **清单禁入名单**:`tools\_doc_part3_cleanup.sql` 是**一次性清库脚本**——它 `DELETE` 掉
> `bl_/bd_` 的 dispatch / manu_order / material_out / outsource_order / pu_order 中
> `asp_user1='migration'` 的**全部业务单据行**。它**不在** `db-migrations.txt` 里,**绝不要登记进去**,
> 也不要随手对服务器库执行。其余 `migrate-*.sql` 均幂等(IF NOT EXISTS / 条件 UPDATE / DELETE+INSERT),
> 库内重跑安全。

## 三、热更新(日常版本升级,不动数据库) ★ 新对话必读 ★

> 本节只解决"换代码"。**若本次版本含数据库变更,先做第二节,再回来做本节。**

### 完整流程(3 步)

```
本地开发机                          服务器(RDP)
━━━━━━━━━━                        ━━━━━━━━━━
① 跑一键打包脚本
   pwsh -File C:\INCER\YINJIA-MES\tools\build-hot-update.ps1
   → 产出 deploy\app.jar
                                    ② 复制 app.jar 到
                                       C:\yinjia\update\app.jar
                                       (RDP 窗口直接粘贴)
                                    ③ 双击 C:\yinjia\update.bat
                                       → 自动停/备/换/启
                                       → Started MesApplication ✓
```

### 本地一键打包脚本

```powershell
pwsh -File C:\INCER\YINJIA-MES\tools\build-hot-update.ps1
```

脚本自动执行(约 30 秒):
1. 前端 `npm run build`
2. 后端全量编译(javac --release 17 -parameters, fat-jar classpath)
3. 同步 dist → static
4. 组装 fat-jar(所有 .class + static)
5. 重启本地开发服务
6. 输出热更新包到 `deploy\app.jar`

> 脚本首次运行会解包 fat-jar 提取 classpath(jar-inspect 目录,后续复用)。

### 服务器热更新

1. RDP 远程桌面,把 `deploy\app.jar` **粘贴到** `C:\yinjia\update\`(覆盖旧的)
2. **双击 `C:\yinjia\update.bat`** → 自动:
   ```
   [1/4] stopping backend...     ← taskkill java
   [2/4] backing up...           → app.jar.bak
   [3/4] installing new jar...   ← update\app.jar → app.jar
   [4/4] starting backend...     ← start.bat
   ```
3. 新窗口出现 `Started MesApplication` + `HikariPool Start completed` = **更新完成**

### 回滚

```cmd
copy /Y C:\yinjia\app.jar.bak C:\yinjia\app.jar
```
然后重启(taskkill java → start.bat)。

### 数据库迁移(如涉及表结构变更)

> 热更新**不动数据库**。本次版本若含表结构/元数据/数据变更,**先做「二、数据库与代码同版本发布」再回来换包**。
> 迁移清单唯一权威顺序:`tools/db-migrations.txt`(`DbSync`/`DbInit` 都按它执行);执行方式见「二、B」。

## 五、排查速查表(实战版)

| 症状 | 处理 |
|---|---|
| `Port 8090 was already in use` | `taskkill /IM java.exe /F` 再启动 |
| bat 报 `'dp0"' 不是内部或外部命令` | bat 是 UTF-8 → 用 PowerShell 重生成 ASCII 版 |
| `'java' 不是内部或外部命令` | JDK 没装/PATH 未生效 → 新开 cmd |
| RESTORE 报"正由此会话使用" | 脚本开头缺 `USE master;` |
| RESTORE 报目录查找失败 | 用自动探测版脚本(不手写路径) |
| **外网打不开(防火墙+安全组都放行了)** | **先核对服务器真实公网 IP**:服务器上 `curl http://ip.3355.cn`,或移动云控制台实例页核对。**IP 抄错时所有放行都"不生效",站长工具也显示关闭**(2026-09-08 实测:一直测的 .136 是错的,.163 才是真身) |
| 外网打不开(IP 已核对) | ① Windows 防火墙规则(netsh 验证) ② 移动云安全组入方向 ③ 移动云部分产品线实例页还有独立**「防火墙」标签**,与安全组是**两道闸** ④ 规则是否加在**该实例实际绑定的**安全组上(加错组是高频坑) ⑤ 源地址别选成"安全组内网",TCP 8090 源 `0.0.0.0/0` |
| 数据库连不上 | SQL Server 服务没起 / yinjia 登录未建 |
| **服务起不来(SQL 报"无效的列名/对象名无效")** | 库落后于代码 → 先按「二」迁库(或恢复新 bak)再换 jar |
| **sqlcmd 执行中文脚本输出乱码** | 加 `-f 65001`:`sqlcmd -f 65001 -S localhost -d HSDZ_MES -E -i tools\migrate-xxx.sql` |
| **某迁移脚本好像"没被部署执行"** | 它没登记进 `tools/db-migrations.txt` → 按「二、B」补登记(`DbSync`/`DbInit` 只认清单) |
| javac 报 ButtonService 找不到 | 缺 import 或 classpath 不含 jar-inspect → 用 build-hot-update.ps1(自动处理) |
| javac 编译的 Controller 端点 400 | 编译缺 `-parameters` 旗标(Spring @PathVariable 需要) |
| jar 更新后行为没变 | 服务器上旧 java 进程没死干净 → taskkill 后再跑 update.bat |
