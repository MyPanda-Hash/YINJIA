# YINJIA-MES 服务器部署说明（Windows · 实战版）

> 本文档由 2026-09-08 首次真实部署全程沉淀（服务器：Windows + SQL Server 2019 + Java 21 + 移动云 ECS）。
> 部署包内容：`HSDZ_MES.bak`（数据库全量备份）、`app.jar`（后端+前端一体）、`start.bat`、`start-service.bat`、`update.bat`、本说明。
>
> **本服务器档案**：公网 IP `36.140.66.163`，系统地址 `http://36.140.66.163:8090`，安装目录 `C:\yinjia\`。

---

## 一、首次部署（从零到上线）

### 1. 传输部署包
RDP 远程桌面里直接复制粘贴 zip 到服务器，解压到 `C:\yinjia\`。

### 2. 安装 SQL Server（已装跳过）
SQL Server 2019/2022 Express，「基本」安装一路默认 + SSMS。SSMS 打开方式：开始菜单敲 `ssms`。

### 3. 恢复数据库（最终验证版脚本，自动探测数据目录）
SSMS 连 `localhost`（Windows 身份验证），Ctrl+N 新建查询，整段执行：

```sql
USE master;
GO
-- 清掉失败残留(全新部署无风险)
IF DB_ID(N'HSDZ_MES') IS NOT NULL
    EXEC(N'ALTER DATABASE [HSDZ_MES] SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE [HSDZ_MES];');
GO
DECLARE @data NVARCHAR(400) = CAST(SERVERPROPERTY('InstanceDefaultDataPath') AS NVARCHAR(400));
DECLARE @sql NVARCHAR(MAX) = N'RESTORE DATABASE [HSDZ_MES] FROM DISK = N''C:\yinjia\HSDZ_MES.bak'' WITH RECOVERY, '
    + N'MOVE N''ASPSMT''     TO ''' + @data + N'HSDZ_MES.mdf'', '
    + N'MOVE N''ASPSMT_log'' TO ''' + @data + N'HSDZ_MES_log.ldf''';
PRINT N'使用数据目录: ' + @data;
EXEC(@sql);
GO
IF NOT EXISTS (SELECT 1 FROM sys.sql_logins WHERE name = N'yinjia')
    CREATE LOGIN [yinjia] WITH PASSWORD = N'Yinjia@2026', CHECK_POLICY = OFF;
USE [HSDZ_MES];
ALTER USER [yinjia] WITH LOGIN = [yinjia];
EXEC sp_addrolemember N'db_datareader', N'yinjia';
EXEC sp_addrolemember N'db_datawriter', N'yinjia';
EXEC sp_addrolemember N'db_ddladmin',  N'yinjia';
```

> **踩坑记录**：
> - 恢复前必须 `USE master`，否则报"正由此会话使用"；
> - `MOVE` 目标目录用 `SERVERPROPERTY('InstanceDefaultDataPath')` 自动探测，**不要手写**（MSSQL15/MSSQL16 等版本目录各不相同）；
> - `FROM DISK` 路径 = 实际解压位置。

### 4. 安装 Java 21
Temurin 21 MSI（https://adoptium.net/temurin/releases/?version=21），默认勾选 Add to PATH。**新开** cmd 验证 `java -version`。

### 5. 生成启动脚本（PowerShell，防编码坑）
> **踩坑记录**：bat 含中文注释时必须 GBK/ANSI 编码，UTF-8 的 bat 在中文 Windows 的 cmd 里必炸（`'dp0"' 不是内部或外部命令`）。以下命令生成纯 ASCII 脚本，已验证：

在 **PowerShell**（提示符 `PS C:\...>`；注意不是 cmd——`@'...'@` 语法 cmd 不认）里执行：

```powershell
@'
@echo off
cd /d "%~dp0"
title YINJIA-MES backend :8090
java -jar app.jar
echo.
echo [EXITED] backend stopped - check errors above
pause
'@ | Set-Content C:\yinjia\start.bat -Encoding ASCII

@'
@echo off
cd /d "%~dp0"
:loop
java -jar app.jar
echo [%date% %time%] exited, restart in 5s...
timeout /t 5 /nobreak >nul
goto loop
'@ | Set-Content C:\yinjia\start-service.bat -Encoding ASCII
```

### 6. 启动
双击 `C:\yinjia\start.bat`。成功的标志：

```
Tomcat started on port 8090
Started MesApplication in x.x seconds
HikariPool-1 - Start completed.
```

> **踩坑记录**：报 `Port 8090 was already in use` = 旧 java 进程没死。管理员 PowerShell 执行 `taskkill /IM java.exe /F` 后重启。

服务器浏览器自检 `http://localhost:8090`。

### 7. 放行外网（两道闸都要开）
**① Windows 防火墙**（管理员 PowerShell；注意验证规则真的建上了）：

```powershell
New-NetFirewallRule -DisplayName "YINJIA-MES 8090" -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow -Profile Any
netsh advfirewall firewall show rule name="YINJIA-MES 8090"   # 必须能列出规则
```

**② 云安全组**（移动云控制台 ecloud.10086.cn → 弹性云主机 → 实例 → 绑定的安全组 → 入方向）：

| 协议 | 端口 | 源 |
|---|---|---|
| TCP | 8090 | 0.0.0.0/0 |

### 8. 验证外网（按顺序，快速定位）
1. 在线探测：`https://tool.chinaz.com/port?host=<公网IP>&port=8090` → 显示「开放」
2. 手机**关 WiFi 走流量**访问 `http://<公网IP>:8090`
3. 任意外网浏览器访问

> **踩坑记录**：务必核对**服务器真实公网 IP**（本机实测 .136 是错误地址、.163 才是真身——IP 抄错时所有放行都"不生效"，站长工具显示关闭）。服务器自身出口 IP 可在 cmd 里 `curl http://ip.3355.cn` 或控制台实例页核对。

### 9. 上线加固（三件事）
1. **改 admin 密码**：登录 → 右上角用户菜单 → 修改密码（默认 123456 绝不可留）
2. **换 JWT 密钥**（PowerShell 生成随机密钥并写入 start.bat）：

```powershell
$secret = -join ((1..64) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })
$bat = "@echo off`r`ncd /d `"%~dp0`"`r`nset YINJIA_JWT_SECRET=$secret`r`ntitle YINJIA-MES backend :8090`r`njava -jar app.jar`r`npause"
Set-Content C:\yinjia\start.bat $bat -Encoding ASCII
```

3. **开机自启**（管理员 PowerShell）：

```powershell
schtasks /Create /TN "YINJIA-MES" /TR "C:\yinjia\start-service.bat" /SC ONSTART /RU SYSTEM /RL HIGHEST /F
```

## 二、热更新（日常版本升级，不动数据库）

> 原则：**只换 app.jar + 重启进程，数据库一律不碰**。前后端都在 jar 里，换包即完成升级。
> 若某次升级含表结构变更，会单独提供**幂等迁移 SQL**（tools/migrate-*.sql），先执行第九节备份命令再跑迁移——不在本流程内。

### 更新步骤（两种方式任选）

**方式 A：用热更新脚本（推荐）**

1. 把新的 `app.jar` 复制到服务器 `C:\yinjia\update\app.jar`（RDP 直接粘贴覆盖）
2. 双击 `C:\yinjia\update.bat` —— 脚本自动：杀旧进程 → 备份旧包为 `app.jar.bak` → 换新包 → 拉起服务
3. 看新窗口出现 `Started MesApplication` = 更新完成（业务数据原封不动）

**方式 B：手动三步**

```powershell
taskkill /IM java.exe /F                 # 1. 停旧进程
copy C:\yinjia\update\app.jar C:\yinjia\app.jar   # 2. 覆盖新包(先放好)
C:\yinjia\start.bat                      # 3. 启动
```

### 回滚
更新后发现问题：`copy /Y C:\yinjia\app.jar.bak C:\yinjia\app.jar` → 重启，即回到上一版。

### 更新前可选保险（数据库快照）
虽然热更新不动数据库，重大版本前可拍一份快照（约 10 秒）：

```sql
BACKUP DATABASE [HSDZ_MES] TO DISK = N'C:\yinjia\backup\HSDZ_MES-更新前.bak' WITH FORMAT, INIT;
```

## 三、排查速查表（实战版）

| 症状 | 原因与处理 |
|---|---|
| `Port 8090 was already in use` | 旧进程残留：`taskkill /IM java.exe /F` 再启动 |
| bat 报 `'dp0"' 不是内部或外部命令` | bat 是 UTF-8 含中文 → 用第五节 PowerShell 重生成 ASCII 版 |
| `'java' 不是内部或外部命令` | JDK 没装/PATH 未生效：重装 MSI 或新开 cmd |
| RESTORE 报"正由此会话使用" | 脚本开头缺 `USE master;`（用第三节的完整版） |
| RESTORE 报目录查找失败 | 手写了 MOVE 路径 → 用自动探测版脚本 |
| 外网打不开但本机正常 | ① Windows 防火墙规则没建上（用 netsh 验证）② 云安全组没放行/加错组 ③ **公网 IP 抄错**（用 chinaz + 手机流量双重核对） |
| 数据库连不上（Hikari 报错） | SQL Server 服务没起 / yinjia 登录未建（第三节后半段） |
