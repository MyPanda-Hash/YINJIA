看回传日志 `pkg-20260921\logs\deploy-*.log`（脚本跑完文件已经在开发机上）。CHECK 会打印：

## 2. 确认无误后跑 GO（会改库、会换包）

```
\\tsclient\C\yj-deploy\deploy-all.bat GO
```

它按顺序做 8 步，任何一道闸不过就**硬停**、不做下一步：

1. 前置检查 2. 现状自查（check-db.sql） 3. **停应用**（结束任务计划 `YINJIA-MES` + 杀掉 java.exe）
4. **备份服务器现有库** → `C:\yinjia\backup\pre-deploy-<时间戳>.bak`（失败就硬停，绝不在没有回滚点的情况下换库）
5. **还原我们的库**（强删 HSDZ_MES → 自动探测数据目录 → RESTORE + MOVE → 修孤儿登录 → 授权）
6. 复核（演示数据条数）+ **用应用账号 `yinjia` 真连一次**（跨服务器还原最容易死在这：库里的用户带着原机器 SID，报“用户 'yinjia' 登录失败”）
7. 换 `app.jar`（旧的先归档到 `C:\yinjia\backup\app-<时间戳>.jar`）
8. 起应用 + **真实验收**：每 5 秒打一次 `POST /api/auth/login`，最多等 150 秒，直到 `RESULT: LOGIN-OK`

**收尾看这几个标记**（日志里 grep `RESULT:`）：

| 标记 | 含义 |
|---|---|
| `RESULT: ALL-OK` + `LOGIN-OK` | 部署成功 |
| `RESULT: BACKUP-GATE-PASSED` | 服务器旧库已备份（回滚点有了） |
| `RESULT: RESTORE-GATE-PASSED` | 库已换成我们的干净账 |
| `RESULT: SQL-LOGIN-GATE-PASSED` | `yinjia` 能真连库（没有 SID 孤儿问题） |
| `RESULT: FAIL-*` | 失败点，日志里紧跟一行 `hint:` 给下一步怎么办 |

只想换其中一样：`deploy-all.bat GO APP`（只换 jar，不动库）· `deploy-all.bat GO DB`（只换库，不动 jar）。

## 6. 两个必须记住的点

1. **健康检查不算验收**：Tomcat 在启动期缓存预热**之前**就开始监听，`curl http://localhost:8090` 拿到 200 是假阳性；只有 `POST /api/auth/login` 拿到 token 才算可用（本包第 8 步就是这么判的）。
2. **`.bat` 必须纯 ASCII**：zh-CN 的 cmd 按 GBK 解析批处理，UTF-8 中文的 `.bat` 会直接崩。所以中文全在 `.sql` 里（sqlcmd `-f i:65001,o:65001` 读），日志回传到开发机再看。
