# 推送(push) vs 同步(sync) 规则对比

## 用户要求
推送脚本的规则必须与同步(读入)脚本完全一致，方向反转(MES → 金蝶)。
不能只是跳过，一个月内有变化的要修改推送，新增的要加入。

## 逐项对比

| # | 规则 | 同步(读入) sync-core.mjs | 当前推送 push.mjs | 差距 |
|---|---|---|---|---|
| 1 | **增量判定** | 指纹比对:拉列表→算指纹→与MES存的`外部指纹`比→不同才调详情写入 | 仅看 `asp_user1 ≠ 'mes-push'`(一次标记永不重推) | ❌ **推送缺指纹**——修改过的单据不会重推 |
| 2 | **时间窗** | 订单:近31天修改/新增(`modify_start_time`时间戳毫秒);档案:全量+指纹跳过 | 无时间窗,无修改检测 | ❌ **推送缺时间窗** |
| 3 | **状态过滤** | 订单:`bill_status=C`(已审核) | `单据状态='已审核'`(等价✓) | ✅ 一致 |
| 4 | **幂等(新增)** | `外部数据ID`锚点:有→UPDATE,无→INSERT | `bill_no`比对:金蝶已有→跳过 | ❌ **推送缺更新能力**——只有跳过,没有更新 |
| 5 | **幂等(更新)** | 指纹变了→调详情→UPDATE全部字段+新指纹 | 无(不更新已推送的) | ❌ **完全缺失** |
| 6 | **修改传播** | MES 列表拉到的 modify_time 变化→指纹变→重写 | MES 单据被用户改了→推送脚本不知道 | ❌ **需要 MES 端指纹(asp_time2 或计算)** |
| 7 | **全量字段** | EXTRA + EXTRA_LINES 全量映射 | EXTRA + EXTRA_LINES 全量映射 | ✅ 一致 |
| 8 | **基础资料** | 12类档案全量同步+指纹跳过 | 6类自动创建(缺则建) | ✅ 基本一致(推送是确保存在,不需要指纹) |
| 9 | **备份** | 写前备份全量前像(backupBeforeWrite) | 无备份 | ❌ **推送缺备份**(写金蝶前应备份MES前像) |
| 10 | **日志** | 逐条日志+完成统计 | 逐条日志+完成统计 | ✅ 一致 |
| 11 | **分页** | page_size + maxPages | 拉全部(200/页×50页) | ✅ 基本一致 |
| 12 | **确认** | 大批量时交互确认(confirmBatch) | 无确认(直接推) | ❌ 可加(沙箱场景非必须) |
| 13 | **单据编号** | 不涉及(MES自动编号) | `bill_no` 保留 MES 编号 | ✅ 已实现 |
| 14 | **渐进降级** | 不需要(金蝶→MES无类型冲突) | 全量→去src→核心 | ✅ 推送特有(合理) |
| 15 | **防重复** | 外部数据ID唯一索引 | 金蝶单号集合+备注标记 | ⚠️ 需要改为指纹驱动 |

## 核心差距:增量/更新机制

### 同步(读入)的增量原理
```
金蝶列表 → fingerprintOf(row) 算指纹(如 "C|S|2026-09-15|惠州双喜|...")
         → 与 MES 存的 外部指纹 比较
         → 不同 → 调详情 → UPDATE MES + 写新指纹
         → 相同 → 跳过(不调详情)
```

### 推送(写入)应有的增量原理(镜像反转)
```
MES 单据 → pushFingerprintOf(row) 算指纹(基于 MES 关键字段)
         → 与 MES 存的 推送指纹 比较(或比对 asp_time2 最后修改时间)
         → 指纹变了(或无推送指纹=新单) → 推到金蝶
             → 金蝶已有该 bill_no → UPDATE(金蝶 save API 可能不支持,需验证)
             → 金蝶没有 → CREATE(POST)
         → 写新推送指纹到 MES
         → 指纹没变 → 跳过
```

### MES 端变更检测方案
| 方案 | 说明 | 优缺点 |
|---|---|---|
| A: asp_time2 | MES 每次修改自动更新 asp_time2 → 推送脚本查 asp_time2 > 上次推送时间 | ✅ 简单可靠(引擎自动维护);❌ 需要记录"上次推送时间" |
| B: 字段指纹 | 对 MES 头+行关键字段算哈希 → 存到某列 → 每轮重算比对 | ✅ 精确;❌ 需要新列存储推送指纹 |
| C: 全量重推 | 每轮把所有已审核单据重推(金蝶幂等去重) | ✅ 最简单;❌ 浪费API额度,大量单据时慢 |

### 推荐:方案 A(asp_time2)
- MES 引擎(ButtonService)在每次保存/修改时自动写 `asp_time2 = GETDATE()`
- 推送脚本记录每轮的 `lastPushTime`
- 查询条件: `asp_time2 > lastPushTime AND 单据状态='已审核'`
- 效果: **新增的推、修改的重推、没变的不推**

3. ~~全量字段 EXTRA~~ ✅ 已有

8. **防重复(改进)**: 不再"推过就永跳",而是"有变化就重推"(金蝶端用 bill_no 去重)
