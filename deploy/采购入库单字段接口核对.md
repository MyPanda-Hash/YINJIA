## 二、关键验证:挂了源单也读不回「订单基本数量」(2026-09-20 实测)

用户口径:**只需把采购订单号推给金蝶,订单信息金蝶自己带**。前半句成立,后半句分两半:

- ✅ **金蝶侧成立**:推出 `src_bill_no` 后,金蝶把入库行挂到采购订单源单上。真实账套实测 123/138 行带源单,关联字段全集为:
  `src_bill_no`(订单号)、`src_bill_type_id` / `src_bill_type_number`(**常量字符串 `pur_bill_order`**)、`src_bill_type_name`=`采购订单`、`src_inter_id`(订单单据id)、`src_seq`(订单行号)、`src_entry_id`(订单分录id)。
- ❌ **接口读回不成立**:逐键比对 138 行(其中 123 行挂了源单)的键集 vs 官方详情接口基线 —— **挂源单行的键集与未挂源单完全相同(83 键,零新增)**。接口里**没有**任何「订单数量 / 源单数量」族键,只有本单的 `qty` / `base_qty` / `inv_qty` / `inv_base_qty` / `aux_qty` / `def_float_qty` / `return_qty`。
  → 金蝶界面会自己显示订单数量,但**不会通过采购入库单接口把「订单基本数量」还给我们**;MES 要用只能自己取(见 §四)。

> 探针:`tools/archive/_q-pi-srckeys.mjs`(键集比对)、`_q-pi-orders.mjs`(取值实测)。

## 三、MES 侧现状(已有什么 / 缺什么)

**落数现状(本地库)**

- 头:63 张(接口可见 57 张)——`采购订单号` 有值 1 张;`客户 / 来源单号 / 来源单据 / 匹配来源单号 / 销售订单号` 全为 0;`ERP单号` 7 张。
- 行:116 行——`源单编号` 4 行、`源单行号` 5 行、`基本数量` 5 行有值;`是否来料检验` 116/116 有值。
- 结论:**采购入库单尚未接入金蝶同步**(`deploy/sync-core.mjs` 的 DOCS 只有 PU_ORDER / SO_ORDER + 12 个基础资料档案),库里的入库单是 MES 自建(送料暂收→来料检验→采购入库链)产生的,所以源单族字段基本为空。

**字段位已备好(只差同步/赋值)**

- 列与面板字段均已建:`bl_purchase_in` 有 `源单编号/源单行号/源单日期/源单分录id/源单类型*/基本数量/是否来料检验`(面板字段多为隐藏);`bd_purchase_in` 有 `采购订单号/客户/客户编码`。
- 映射表已备好但未接线:`deploy/kingdee-extra-fields.mjs` 的 `EXTRA_LINES["PURCHASE_IN"]` 已含 `src_bill_no→源单编号`、`src_seq→源单行号`、`base_qty→基本数量`(文件头注明"PURCHASE_IN/SALE_OUT 条目已备好但 sync-core 尚未接入")。

**推送方向(MES→金蝶,转ERP)的缺口**

- 已推:`src_bill_no` = MES 采购订单号 + `src_bill_type_name`=「采购订单」(`KingdeePushService` 第 182~186 行);实测单据 `TCGRK-PO-001`(订单号 `YJ-20260916-01`)已转ERP成功 → 金蝶单 `CGRK-20260917-00033`。
- **未推:`src_bill_type_id` / `src_bill_type_number`(常量 `pur_bill_order`)与 `src_seq`(源单行号)** → 金蝶侧挂上了订单但认不出对应哪一行;对准金蝶自己的关联写法,建议两者都补(前者是常量,零成本;可选再补 `src_inter_id`/`src_entry_id`,需按订单号查一次 `pur_order` 取)。
- 不推:客户(采购只推 `supplier_number`)、是否来料检验(MES 独有语义)。
- 数据来源瓶颈(**推送能否普遍生效的前提**):63 张入库单里只有 1 张头上有 `采购订单号`;且 `sl_recv`(送料暂收单)、`qc_insp`(来料检验单)表头**没有「采购订单号」列** → 实际链路(采购订单→送料暂收→来料检验→采购入库)会把订单号丢掉,只有「采购订单→采购入库单」直连生单会填(`PanelConfigService.FLOW_HEAD_SYNONYMS` 的 `PU_ORDER|PURCHASE_IN`)。
- 安全性:本地 2137 张采购订单**全部是金蝶样式单号**(`YJ-*`,同步自金蝶),MES 无自建订单号 → 推出去的订单号在金蝶必定存在,不会挂空。

## 四、「订单基本数量」的取数方案(推荐不新增接口)

1. **本地 join(推荐)**:MES 已同步采购订单头+行(`bl_pu_order` 有 `基本数量`、`行号`),入库行已有 `源单编号` + `源单行号` → 直接
   `bl_purchase_in.源单编号/源单行号 = bl_pu_order.单据编号/行号` 取 `基本数量`,零额外金蝶调用。
   先决条件:入库行必须真带上 `源单编号/源单行号`(见上:同步未接入、推送未带行号)。
2. 金蝶回查:按 `src_bill_no + src_seq` 调 `pur_order_detail` 取 `base_qty`(多一次请求,仅在本地订单缺失时需要)。
